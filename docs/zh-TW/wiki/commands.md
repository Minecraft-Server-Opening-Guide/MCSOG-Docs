這一頁把三類指令放在一起查：**Java 版服務端指令**、**基岩版（BDS 與第三方核心）指令**、以及**套在服務端外面的管理層**（MCDR、面板控制台、RCON）。

表裡的「權限」一列寫的是**原版預設**：Java 版按 OP 等級，基岩版按操作員身份與「作弊」開關。裝了權限插件（如 LuckPerms）之後，實際權限由權限節點決定，可能比原版更寬也可能更嚴。

> 指令是否可用、權限等級是多少，**隨遊戲版本與核心類型變化**：同一個名字在不同核心上可能不存在，也可能被核心改寫。下指令前請以你實際執行的服務端與遊戲版本的官方文件為準。

:::note 三句話先記住
- **控制台裡通常不用打 `/`**，遊戲內聊天框裡必須打 `/`。
- **控制台身份等於最高權限**，遊戲內要看你有沒有 OP 或對應權限節點。
- **Java 版與基岩版是兩套指令集**：名字相同不代表行為相同，`save-all` 在基岩版根本沒有對應物。
:::

## 1. 讀表之前：三條規則

| 規則 | 說明 |
| --- | --- |
| 版本相關 | 指令會隨版本增刪（例如 `/tick` 一類新指令只存在於較新版本），老教學裡的寫法不一定還能用 |
| 核心相關 | `plugins`、`version`、`tps`、`restart` 這類指令**不是原版指令**，是 Spigot / Paper 系核心提供的；原版服務端沒有 |
| 插件相關 | 裝了權限插件後，原版權限節點可以被改寫；裝了命令別名插件後，指令名可能被替換 |

判斷一條指令到底存不存在，最快的辦法是**在遊戲內輸入 `/` 後看 Tab 補全列表**，或在控制台輸入前幾個字母看補全。補全裡沒有，就是這條核心沒註冊它。

## 2. Java 版：生命週期與存檔

| 指令 | 作用 | 權限 | 備註 |
| --- | --- | --- | --- |
| `stop` | 安全關閉服務端：先儲存再退出 | OP 4 / 控制台 | **關服只用它**，不要直接叉視窗或殺行程 |
| `save-all` | 立即儲存全部世界資料 | OP 4 / 控制台 | 可加參數 `flush` 強制寫入磁碟 |
| `save-off` | 關閉自動儲存 | OP 4 / 控制台 | 備份前先關，避免備份到寫了一半的存檔 |
| `save-on` | 恢復自動儲存 | OP 4 / 控制台 | 備份結束後記得開回來 |
| `reload` | 過載已啟用資料包中的資料 | OP 2（版本間可能不同） | **不是重啟，也不是過載服務端配置**，見下方警告 |
| `restart` | 重啟服務端 | 視核心而定 | Spigot / Paper 系提供；原版沒有這條指令 |

標準關服順序是 `save-all` → `save-off` → 備份 → `stop`。行程已經退出時不需要再 `save-on`。

:::warn `/reload` 不是"全部過載"，還可能弄壞插件
Java 版的 `/reload` 只過載**當前已啟用資料包裡的資料**。它**不會**：

- 重新讀取 `server.properties`（改埠、改難度這類配置必須重啟才生效）；
- 重啟服務端行程，也不會過載插件程式碼；
- 讓插件的註冊內容回到乾淨狀態。

反過來，它**可能**讓插件狀態錯亂：計分板、監聽器、快取、註冊過的命令都可能殘留成半新半舊的樣子，症狀是"過載完某些功能就怪了"。能用插件自己的 `/插件名 reload`、`/datapack enable`、`/datapack disable` 解決的，就別用原版 `/reload`；改動大或說不清影響時，直接挑維護視窗重啟。

基岩版的同名指令範圍更窄（過載行為包中的函式與腳本），兩版的 `reload` 都**不是**"重新整理服務端配置"的按鈕。
:::

## 3. Java 版：玩家、封禁與白名單

| 指令 | 作用 | 權限 | 備註 |
| --- | --- | --- | --- |
| `list` | 列出當前線上玩家 | 所有人 | 最常用的"服裡有人嗎"指令 |
| `kick <玩家> [原因]` | 踢出玩家 | OP 3 / 控制台 | 被踢的人**還能重新進** |
| `ban <玩家> [原因]` | 封禁玩家 | OP 3 / 控制台 | 不解封就進不來 |
| `pardon <玩家>` | 解封玩家 | OP 3 / 控制台 | 很老的版本里這條叫 `unban` |
| `ban-ip <IP>` | 按 IP 封禁 | OP 3 / 控制台 | **該 IP 下所有人都進不來**，慎用 |
| `pardon-ip <IP>` | 解封 IP | OP 3 / 控制台 | 解封前先確認這個 IP 現在歸誰 |
| `banlist [ips\|players]` | 檢視封禁列表 | OP 3 / 控制台 | 不寫參數時列出玩家 |
| `op <玩家>` | 授予管理員 | OP 3 / 控制台 | 只給需要的人；給 OP 比給權限節點粗放得多 |
| `deop <玩家>` | 撤銷管理員 | OP 3 / 控制台 | 權限插件環境下 OP 仍可能繞過權限組 |
| `whitelist on` | 開啟白名單 | OP 3 / 控制台 | 開啟前先把自己加進去 |
| `whitelist add <玩家>` | 加入白名單 | OP 3 / 控制台 | 寫入 `whitelist.json` |
| `whitelist remove <玩家>` | 移出白名單 | OP 3 / 控制台 | 生效後對方下次連線被拒 |
| `whitelist list` | 檢視白名單 | OP 3 / 控制台 | 與 `whitelist.json` 內容一致 |
| `whitelist reload` | 從檔案重新讀取白名單 | OP 3 / 控制台 | **手工改過 `whitelist.json` 後必須執行它** |

白名單相關檔案是 `whitelist.json`，封禁與 OP 名單分別在 `banned-players.json`、`banned-ips.json`、`ops.json`。用指令改會立即寫檔案；手工改檔案則需要對應的 reload 或重啟。

## 4. Java 版：世界、時間與遊戲規則

| 指令 | 作用 | 權限 | 備註 |
| --- | --- | --- | --- |
| `tp <玩家> <目标>` | 傳送玩家 | OP 2 / 控制台 | 完整寫法是 `teleport`；控制台執行時兩個參數都要寫 |
| `gamemode <模式> [玩家]` | 切換遊戲模式 | OP 2 / 控制台 | 取值 `survival` / `creative` / `adventure` / `spectator` |
| `gamerule <规则> <值>` | 修改遊戲規則 | OP 2 / 控制台 | 規則名隨版本增刪，**用 Tab 補全確認** |
| `time set day` | 設定時間 | OP 2 / 控制台 | 也可用 `noon` / `night` / `midnight` 或具體數值 |
| `time add <数量>` | 推進時間 | OP 2 / 控制台 | 除錯晝夜機制時比 `set` 好用 |
| `weather clear` | 設定天氣 | OP 2 / 控制台 | 取值 `clear` / `rain` / `thunder`，可帶持續時間 |
| `difficulty <难度>` | 設定難度 | OP 2 / 控制台 | 取值 `peaceful` / `easy` / `normal` / `hard` |
| `give <玩家> <物品> [数量]` | 給予物品 | OP 2 / 控制台 | 物品 ID 與元件語法隨版本變化 |
| `seed` | 顯示世界種子 | OP 2 / 控制台 | 與存檔繫結，換世界後數值不同 |
| `say <内容>` | 以服務端身份廣播 | OP 2 / 控制台 | 玩家看到的是伺服器訊息樣式 |
| `tell <玩家> <内容>` | 私聊 | 所有人 | 別名 `msg` / `w` |
| `datapack list` | 列出資料包 | OP 2 / 控制台 | 與 `/reload` 搭配使用 |

`gamerule` 是最容易被誤用的一條：**同名規則在 Java 版與基岩版可能含義不同，在不同版本之間也可能被改名或拆分**。改之前先在補全列表裡確認規則存在，改完觀察日誌與玩家回饋。

## 5. Java 版：狀態與排查

| 指令 | 作用 | 權限 | 備註 |
| --- | --- | --- | --- |
| `tps` | 檢視 TPS | OP | **不是原版指令**：Spigot / Paper 系自帶；裝了 spark 時可能被 spark 接管 |
| `mspt` | 檢視每刻耗時 | OP | Paper 系提供；與 TPS 一起看更有意義 |
| `spark tps` | 用 spark 檢視 TPS | OP | spark 的命令樹比核心自帶指令更細 |
| `spark profiler start` | 開始效能取樣 | OP | 結果預設會上傳並給出連結，注意資料外洩風險 |
| `spark profiler stop` | 結束取樣並檢視結果 | OP | 只想停下不上傳，用 `spark profiler cancel` |
| `plugins` | 列出插件 | OP / 權限節點 | 別名 `pl`；綠色為已載入，紅色為載入失敗 |
| `version <插件>` | 檢視插件版本 | OP / 權限節點 | 報 bug 時對方一定會問這個 |
| `help` | 檢視指令幫助 | 所有人 | 分頁檢視，`/help <指令>` 可看單條 |

原版服務端**沒有** `tps`、`mspt`、`plugins`、`version` 這幾條。原版想看效能只能靠日誌與外部工具，這也是很多人"換了核心就有新指令"的原因。效能排查的完整流程見 [用 spark 分析伺服器效能](/tutorials/ops/spark)。

:::tip 權限節點也能改指令可見性
`plugins`、`version`、`help` 的權限節點預設對所有人開放。想關掉，把 `bukkit.command.plugins`、`bukkit.command.version`、`bukkit.command.help` 設為 `false`。但**關掉指令不等於藏得住**：部分客戶端能通過 Tab 補全的響應推斷出已裝插件。
:::

## 6. 基岩版：同一批指令在 BDS 上是什麼樣

基岩版（BDS 與第三方核心）有自己的一套指令。**可用性同時受兩件事影響**：你是否有操作員身份，以及服務端是否開啟了作弊。

| 指令 | 作用 | 權限 | 備註 |
| --- | --- | --- | --- |
| `stop` | 安全關閉服務端 | 控制台 | 與 Java 版同名同義，是最該記住的一條 |
| `save hold` | 暫停寫入並保持檔案一致 | 控制台 | 基岩版的備份第一步 |
| `save query` | 列出當前需要備份的檔案 | 控制台 | 按它給出的清單複製 |
| `save resume` | 恢復寫入 | 控制台 | 複製完成後執行 |
| `whitelist on` / `off` | 開關白名單 | 操作員 | 對應檔案是 `allowlist.json` |
| `whitelist add` / `remove` / `list` / `reload` | 維護白名單 | 操作員 | 手工改檔案後要 reload |
| `op` / `deop` | 授予 / 撤銷管理員 | 操作員 | 結果寫入 `permissions.json` |
| `permission list` | 檢視當前權限 | 操作員 | 與 `permissions.json` 對應 |
| `permission reload` | 重新讀取權限檔案 | 操作員 | 手工改過 `permissions.json` 後執行 |
| `kick <玩家> [原因]` | 踢出玩家 | 操作員 | 與 Java 版含義相同 |
| `ban` / `pardon` | 封禁 / 解封玩家 | 操作員 | 按玩家（gamertag / XUID）封禁，**沒有按 IP 封禁的等價指令** |
| `tp` / `teleport` | 傳送 | 操作員 | 語法與 Java 版接近但不完全相同 |
| `gamemode` | 切換遊戲模式 | 操作員 | 取值與 Java 版類似 |
| `gamerule` | 修改遊戲規則 | 操作員 | 規則集合與 Java 版**不同**，同名規則含義也可能不同 |
| `time set` / `time add` | 設定 / 推進時間 | 操作員 | 基岩版也可用 `daylock` 一類指令鎖時間 |
| `weather clear` / `rain` / `thunder` | 設定天氣 | 操作員 | 另有 `toggledownfall` |
| `difficulty` | 設定難度 | 操作員 | 與 Java 版同名 |
| `list` | 列出線上玩家 | 操作員 | 部分版本對普通玩家開放，以補全為準 |

表中有一部分指令是**較新版本才加入的**（`ban` / `pardon` 這類尤其明顯），在較舊的基岩版服務端上，補全列表裡可能根本沒有它們。**判斷某條指令在你的版本上存不存在，唯一可靠的辦法是看 Tab 補全與官方文件**，不要照抄別處的版本號。

BDS 的配置裡有一項與指令直接相關：`server.properties` 中的 `allow-cheats`。它關閉時，遊戲內的指令會受到限制；預設值以你本地生成的 `server.properties` 為準，改完必須重啟服務端才生效。**基岩版的很多"指令用不了"，根因是作弊開關或操作員身份，不是指令寫錯了。**

基岩版的備份流程與 Java 版完全不同，可以直接照抄：

```text
save hold
save query
# 按 query 输出的清单复制文件（worlds/ 要整体拷走）
save resume
```

## 7. 基岩版沒有（或語義不同）的指令

| Java 版指令 | 基岩版情況 | 說明 |
| --- | --- | --- |
| `save-all` | 不存在 | 用 `save hold` / `save query` / `save resume` |
| `save-off` / `save-on` | 不存在 | 基岩版沒有"關閉自動儲存"這一對開關 |
| `ban-ip` / `pardon-ip` | 不存在 | 基岩版按玩家封禁，沒有按 IP 封禁的指令 |
| `plugins` / `version <插件>` | 不存在 | 基岩版核心沒有統一的插件列表指令，看控制台輸出 |
| `tps` / `mspt` | 不存在 | 基岩版沒有 TPS 指令；效能只能從日誌與外部觀測判斷 |
| `reload` | 存在但**語義不同** | 基岩版過載的是行為包裡的函式與腳本，**不過載 `server.properties`**，也不是重啟 |
| `gamerule` | 存在但**規則集不同** | 同名規則在兩版可能含義不同，跨版本照抄會踩坑 |
| `difficulty` / `time` / `weather` | 存在 | 這幾條兩版都有，語法接近 |

:::warn "基岩版沒有 /reload" 這個說法要拆開看
社群裡常說的"基岩版沒有 `/reload`"，指的其實是**沒有能過載服務端配置的 reload**——這一點是對的：基岩版改了 `server.properties` 只能重啟服務端（用控制台正常 `stop` 再啟動，別殺行程）。

但基岩版確實有一條名為 `reload` 的指令，它的作用範圍是行為包中的函式與腳本，**和 Java 版過載資料包不是同一件事**，也不會讓服務端重新讀取設定檔。兩版都別把 `reload` 當"萬能重新整理鍵"用；具體可用範圍與行為隨版本變化，以官方文件為準。
:::

## 8. 管理層：MCDR 的 `!!MCDR` 子命令

MCDReforged（MCDR）是**包在服務端外面**的管理器：它託管核心行程、解析控制台輸出，並提供一套 `!!` 字首的指令。這套指令**不是遊戲指令**，由 MCDR 自己處理，不會傳給服務端。

| 指令 | 作用 | 權限 | 備註 |
| --- | --- | --- | --- |
| `!!MCDR` | 主命令，列出可用子命令 | 由 MCDR 權限系統控制 | 字首 `!!` 可在配置裡改 |
| `!!MCDR status` | 檢視 MCDR 狀態 | MCDR 權限 | 排查"管理器還活著嗎" |
| `!!MCDR reload config` | 過載 MCDR 配置 | MCDR 權限 | 有縮寫形式，如 `!!MCDR r cfg` |
| `!!MCDR reload plugin` | 過載插件 | MCDR 權限 | 與過載配置分開 |
| `!!MCDR reload permission` | 過載權限資料 | MCDR 權限 | 改完權限檔案後用 |
| `!!MCDR reload all` | 過載全部 | MCDR 權限 | 出問題時優先用它 |
| `!!MCDR plugin list` | 列出已載入插件 | MCDR 權限 | 與 Java 版 `/plugins` 是兩回事 |
| `!!MCDR plugin load <插件>` | 載入插件 | MCDR 權限 | 參數是插件 id |
| `!!MCDR plugin reload <插件>` | 過載單個插件 | MCDR 權限 | 比整體重啟輕 |
| `!!MCDR plugin unload <插件>` | 解除安裝插件 | MCDR 權限 | 解除安裝不等於刪除檔案 |
| `!!MCDR plugin install <插件>` | 從官方倉庫安裝插件 | MCDR 權限 | 示例：`!!MCDR plugin install ndpr` |
| `!!MCDR permission list` | 檢視權限 | MCDR 權限 | 按玩家與權限組檢視 |
| `!!MCDR permission set` | 設定權限 | MCDR 權限 | 語法以官方文件為準 |
| `!!MCDR permission remove` | 移除權限 | MCDR 權限 | |
| `!!MCDR checkupdate` | 檢查 MCDR 更新 | MCDR 權限 | 是否自動檢查由設定項決定 |

:::warn MCDR 子命令隨版本變化
MCDR 的子命令與縮寫形式在版本之間會調整（`!!MCDR reload config` 這類縮寫尤其容易記錯），**具體寫法以 MCDR 官方文件與你機器上 `!!MCDR` 輸出的幫助為準**。另外，MCDR 的權限是它自己的一套，和遊戲內 OP 等級無關；玩家在聊天框裡能執行哪些 `!!` 指令，取決於 MCDR 的權限配置。
:::

## 9. 管理層：面板控制台與 RCON

面板（如 MCSManager、Pterodactyl）的網頁控制台本質上是一個**遠端標準輸入**：你敲的內容會被原樣送進服務端行程，和你坐在機器前敲控制台沒有區別。

| 渠道 | 要不要打 `/` | 權限 | 備註 |
| --- | --- | --- | --- |
| 本機控制台 | 通常不需要 | 最高權限 | 原版控制台不受 OP 等級限制 |
| 面板網頁控制台 | 多數面板兩種都能接受 | 最高權限 | 有的面板會自動去掉前導 `/`，以面板行為為準 |
| RCON | 通常不需要 | 最高權限 | 需在 `server.properties` 裡開啟並設定口令 |
| 遊戲內聊天框 | 必須打 `/` | 按 OP 等級或權限節點 | 受白名單、封禁、權限插件影響 |

三條實踐建議：

1. **停服永遠用 `stop`（基岩版同樣）**，不要在面板上點"終止行程"。強行終止可能丟資料或損壞存檔。
2. **RCON 不要暴露到公網**。它是一條免登入的"執行任意指令"通道，只監聽迴環或內網位址，口令要長且唯一。
3. **面板控制台裡執行的指令等同於最高權限**，給協管面板帳號之前先想清楚這一點。

## 10. 控制台 vs 遊戲內：差異清單

| 差異 | 控制台 / RCON | 遊戲內聊天框 |
| --- | --- | --- |
| 前導斜槓 | 通常不用寫 | 必須寫 |
| 權限來源 | 行程身份，等於最高權限 | OP 等級或權限節點 |
| 執行者上下文 | **沒有執行者**：`@s`、相對座標、不指定目標的 `tp` 都不能用 | 有執行者，可用選擇器與相對座標 |
| 輸出去向 | 終端與日誌檔案 | 聊天框與動作欄 |
| Tab 補全 | 通常有；部分面板沒有 | 有 |
| 字元編碼 | Windows 控制台內碼表不對時中文會亂碼 | 一般正常 |
| 玩家可見性 | 玩家看不到你敲了什麼 | 部分指令會對玩家廣播 |

最典型的坑是"控制台裡執行 `/tp ~ ~10 ~`"——控制台沒有位置，這條一定失敗。控制台執行傳送類指令時，**玩家與目標都要顯式寫出來**。

## 11. 權限從哪來

| 體系 | 適用 | 怎麼控制 |
| --- | --- | --- |
| OP 等級 | Java 版原版 | `/op` 給到 4 級；等級 1 到 4 對應不同指令組，可用權限節點細化 |
| 權限節點 | Java 版插件服 | 權限插件（如 LuckPerms）按節點與權限組分配，比給 OP 安全 |
| 操作員 + 作弊開關 | 基岩版 | `permissions.json` 決定誰是操作員；`server.properties` 的 `allow-cheats` 決定指令可用性 |
| MCDR 權限 | 裝了 MCDR 的服 | MCDR 自己的權限系統，按玩家與權限組控制 `!!` 指令 |

**給權限的原則**：能只給一條指令的權限，就不要給整個 OP；能給限時權限，就不要給永久權限。OP 是"整台伺服器"級別的信任，權限節點才是最小授權。

## 12. 可以直接抄的組合

維護前的標準流程（Java 版）：

```text
say 服务器将在 5 分钟后进入维护
save-all
save-off
# 此时在外部打包世界目录与插件目录
stop
```

白名單從零到可用（Java 版）：

```text
whitelist add 你的ID
whitelist on
whitelist list
```

基岩版備份與恢復：

```text
save hold
save query
# 复制 query 列出的文件，worlds/ 整体拷走
save resume
```

排查"玩家進不來"時最先敲的幾條：

```text
list
whitelist list
banlist players
plugins
```

## 13. 常見誤用

| 誤用 | 後果 | 正確做法 |
| --- | --- | --- |
| 直接關視窗或點"終止行程" | 存檔可能損壞或回滾 | 控制台執行 `stop` |
| 用 `/reload` 當重啟 | 插件狀態錯亂、配置不生效 | 用插件自己的 reload；必要時重啟 |
| 備份前不 `save-off` | 備份到寫入一半的存檔 | 先 `save-all` 再 `save-off` |
| 在控制台用 `~` 相對座標 | 指令直接失敗 | 顯式寫出玩家與座標 |
| 把 RCON 埠開到公網 | 等於把伺服器交給掃描器 | 只監聽迴環或內網，配強口令 |
| 改完 `whitelist.json` 不 reload | 改動不生效 | 執行 `whitelist reload` |
| 用基岩版的 `gamerule` 名去 Java 版 | 規則不存在或含義不同 | 用 Tab 補全確認規則名 |
| 以為基岩版有 `save-all` | 指令不存在 | 用 `save hold` / `save query` / `save resume` |
