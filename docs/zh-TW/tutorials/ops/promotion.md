前面講的是"伺服器能不能跑起來"。這一篇講的是另一件事：**伺服器跑起來了，玩家憑什麼知道它存在，又憑什麼留下來**。

這是一篇非技術文件。它和 [[JAVA] 經營管理](/tutorials/ops/management-java) 是配套關係：那一篇講開服需要什麼、團隊怎麼分工、資金與玩家管理怎麼做；這一篇只聚焦其中兩塊——**宣傳引流**和**社群運營**。它不涉及任何命令、配置或插件選型；需要插件清單時看 [插件入門](/tutorials/java/plugins) 與 [常用前置插件](/tutorials/java/plugin-deps)。

:::note 先擺正預期
宣傳不是一個"發一條帖子就完事"的動作，而是一件**持續幾個月、由內容驅動**的日常工作。如果你期待"發一次宣傳帖就有幾十人常駐"，那這篇會讓你失望——但失望得越早，伺服器活得越久。
:::

## 1. "開服了就有人來"是假的

很多新服主的心智模型是：我把服務端跑起來，公網能連上，把 IP 發出去，玩家自然就會來。現實是：**沒有人有義務發現你**。

你面對的是典型的**冷啟動問題**，而且它自帶一個負回饋迴圈：

1. 你的伺服器線上 0 人；
2. 玩家在伺服器列表站或群裡看到"0/20"，第一反應是"這個服已經死了"，直接跳過；
3. 因為沒人點進來，列表站給你的曝光更低；
4. 於是你依然 0 人。

這個迴圈裡最關鍵的一點是：**"0 人線上"本身就是一個勸退訊號**。玩家不是不願意當第一個，而是不願意把時間押在一個看起來沒人維護的地方。所以宣傳的真正目標不是"發出去"，而是**在有人來看的那一刻，讓伺服器看起來值得留下**。

幾個必須接受的事實：

| 常見想法 | 現實 |
| --- | --- |
| 伺服器好玩，玩家自然會來 | 好玩是留存的必要條件，不是曝光的充分條件。沒人知道你，就沒人能評價你好不好玩 |
| 我有技術，所以我能開服 | 技術只解決"能跑"。宣傳和運營是另外兩門手藝 |
| 先開著，等人多了再想宣傳 | 等人多了再想，通常等不到。宣傳素材要在開服前就準備好 |
| 花錢買廣告位就夠了 | 廣告位能買到點選，買不到留存。首日體驗差，流量越大死得越快 |

:::warn 不要在別人的群裡刷廣告
**在與你無關的 QQ 群、Discord 伺服器、貼吧、論壇裡反覆貼上伺服器 IP，是最快被踢、被拉黑、被公開點名的方式之一**，而且會連累你的伺服器名聲——玩家會記住"那個到處刷屏的服"，並把這份反感遷移到你身上。想進別人的社群宣傳，先看群規、先徵得管理員同意、先做一個願意聊天的人。**規則允許的渠道才叫渠道，不允許的渠道叫騷擾。**
:::

## 2. 用一句話定義你的伺服器是什麼

在寫任何宣傳文案之前，先完成這個填空：

```
这是一个给 ______（谁）玩的 ______（什么玩法）服务器，
和同类服务器相比，它的差别是 ______。
```

三個空都必須填出**具體**的東西。填不出來，說明定位還沒想清楚，此時做宣傳只是把"沒想清楚"放大給更多人看。

### 2.1 常見的定位類型

| 定位 | 面向的人群 | 這個定位會強制你做的決定 |
| --- | --- | --- |
| 生電 / 技術服 | 喜歡紅石、刷怪塔、機制研究的玩家 | 原版機制不能被插件改壞；對 TPS 與區塊載入極敏感 |
| 原版生存服 | 想長期經營一個世界的玩家 | 世界不能頻繁重置；經濟與領地系統要剋制 |
| 小遊戲服 | 想隨時玩一局的玩家 | 需要穩定的對局人數與匹配節奏；大廳體驗決定一切 |
| RP / 角色扮演服 | 想演故事、做設定的玩家 | 需要劇本、審核與管理人力，投入遠高於普通服 |
| 基岩版 / 跨端服 | 手機、主機玩家 | 版本與跨端方案決定可用插件範圍 |
| 模組服 | 想玩整合包的玩家 | 客戶端要裝同樣的模組；宣傳必須寫清整合包與版本 |

### 2.2 為什麼沒有定位就沒人來

- **玩家在 3 秒內做判斷**。他看到的不是你的世界，而是一行標題。定位模糊的標題等於沒有標題。
- **沒有定位，宣傳只能堆形容詞**。"好玩、刺激、福利多、不氪金"這些詞對所有人都不構成資訊。
- **招來的人會互相沖突**。想安靜建家的玩家和想隨時開打的玩家放在一起，兩邊都不滿意，兩邊都走。
- **運營沒有取捨標準**。有人提議加 PVP、有人提議加科技模組，你沒有判斷依據，最後加成"什麼都有一點"的四不像。

:::tip 定位是一份取捨清單
寫定位的時候，把"我們不做什麼"也寫下來。例如"不做 PVP 競技""不做付費強度""不重置主世界"。**明確拒絕掉一部分玩家，是讓另一部分玩家安心的前提。**
:::

## 3. 中文 MC 玩家實際在哪裡

下面按**類別**描述，不點名具體網站。原因很簡單：**這類平台會興衰、會改版、會換規則**，今天有效的渠道明年可能已經關閉或禁止宣傳。你真正需要掌握的是"去哪一類地方找人"和"進這類地方之前先確認什麼"。

| 類別 | 典型形態 | 適合做什麼 | 發帖前必須先確認 |
| --- | --- | --- | --- |
| 綜合論壇 / 社群類 | 以 MCBBS 為代表的玩家論壇，含伺服器版塊與招人版塊 | 長文宣傳、招管理、招建築師 | 是否仍在運營、是否允許伺服器宣傳、發在哪個版塊、是否有格式模板 |
| 影片與專欄類 | Bilibili 等平台的影片、專欄、動態 | 展示真實玩法、建立"這服有人在認真做"的印象 | 是否允許在簡介或評論區留 IP、是否算商業推廣、是否需要標註 |
| 貼吧類 | 各類 MC 相關貼吧 | 小範圍觸達、提問式互動 | 吧規是否禁止宣傳、是否只允許集中樓 |
| 即時通訊社群類 | QQ 群、Discord 伺服器 | 長期陪伴、活動通知、客服 | 群規、是否允許外鏈、能否先和管理員溝通 |
| 伺服器列表 / 導航站類 | 包括本站在內的伺服器列表與導航站 | 被動流量、按版本與玩法被篩選到 | 收錄要求、標籤規範、是否需要互鏈、置頂是否收費 |
| 熟人 / 主播 / 校園社群 | 朋友、同學、小主播的觀眾群 | 最早期的那幾個真實玩家 | 對方的意願；不要預設別人會幫你推 |

幾條實操原則：

- **先潛水，再說話**。進任何一個社群，先看它平時怎麼交流、管理員什麼態度、有沒有人因為發廣告被處理。
- **一稿一改**。同一篇宣傳稿直接貼上到所有平台，通常會在格式上翻車（圖片掛了、排版亂了、連結被吞）。
- **記錄渠道效果**。同一個渠道發過三次都沒帶來任何一次有效進服，就該放棄它，而不是加大頻率。
- **不要偽造人氣**。掛假人、刷線上數、買點選，短期能騙過列表站的排序，長期一定會被玩家發現，而"這服刷資料"的標籤洗不掉。

## 4. 一份合格的伺服器宣傳帖應該包含什麼

宣傳帖的任務不是"描述你的伺服器有多好"，而是**讓玩家在 10 秒內回答四個問題**：這是什麼？適合我嗎？現在能玩嗎？怎麼進？

| 要素 | 為什麼必須有 | 常見錯誤 |
| --- | --- | --- |
| 一句話定位 | 決定玩家是否繼續往下看 | 只寫"最好的伺服器" |
| 支援的版本 | 玩家客戶端版本不匹配就進不來 | 寫"全版本"，實際只支援一兩個 |
| 正版 / 離線 | 決定玩家能不能進、以及是否願意進 | 不寫，或者含糊其辭 |
| 玩法特色 | 說明和別人的差別 | 羅列幾十個插件名，玩家看不懂 |
| 硬體與穩定性說明 | 玩家關心卡不卡、會不會突然關服 | 吹"永不卡頓"，進服就掉幀 |
| 加入方式 | 降低進入門檻 | 只有群號，沒有 IP 或域名 |
| 截圖或影片 | 唯一能證明"真的有人在玩"的東西 | 用創造模式擺拍的宣傳圖，進服落差巨大 |
| 規則連結 | 提前篩掉不合適的人 | 規則只寫在群裡，新人看不到 |
| 聯絡方式 | 出事能找到人 | 留一個長期不看的信箱 |
| 線上時間與開服時間 | 讓玩家判斷"是不是新服、什麼時候人多" | 不寫，玩家以為是殭屍服 |

### 4.1 填空模板

```
【服务器名称】______
【一句话定位】这是一个给 ______ 玩的 ______ 服务器，差别是 ______
【支持版本】Java ______ 版本；是否支持基岩版：______
【账号要求】正版 / 离线（如支持混合登录请写清）
【玩法特色】1. ______  2. ______  3. ______
【硬件与稳定性】托管位置：______；日常在线峰值：______；近一个月可用性：______
【加入方式】IP 或域名：______；端口：______；加群方式：______
【开服时间】______（新服请直接写"新服"，不要装作老服）
【规则】______（链接）
【联系方式】______
【截图或视频】______
```

### 4.2 常見減分項

- 全篇沒有一張真實遊戲截圖，只有伺服器 logo 和宣傳圖。
- 用"史上最好""絕對不卡""永不關服"這類無法驗證的承諾。
- 把插件列表當成玩法介紹，寫了幾十個插件名。
- 版式花哨到看不清 IP。
- 留了聯絡方式，但三天不回一條訊息。

## 5. 影片與短影片策略

影片是**目前價效比最高的展示方式**，因為它同時證明了三件事：真的有人在玩、畫面長什麼樣、伺服器卡不卡。

### 5.1 三十秒鉤子

前 3 秒決定觀眾是否划走。有效的開頭通常直接給畫面結果，而不是給片頭：

- 直接展示一個視覺衝擊強的場景（大型建築、紅石機器運轉、活動混戰）。
- 用一句話說明"這是什麼、為什麼值得看"，例如"這是全服第一台自動分類機建成的那一晚"。
- 不要放 5 秒以上的 logo 動畫、不要放"某某伺服器宣傳片"的標題卡。

### 5.2 展示真實玩法，而不是 logo

觀眾能分辨擺拍和實機。**把鏡頭放在玩家視角的連續遊玩上**：挖礦、建家、交易、打怪、參加活動。如果伺服器最吸引人的地方是"社群氛圍"，就拍聊天欄裡的互動、一起蓋房子的過程、活動開始前的集合。

### 5.3 為什麼穩定 TPS 會影響你的宣傳效果

**卡頓在影片裡是看得見的**：實體抽搐、方塊回彈、玩家瞬移、方塊破壞延遲、掉落物堆積。觀眾未必知道 TPS 是什麼，但一定能感覺到"這服卡"。

所以拍宣傳片之前，先確認伺服器狀態：

- 錄製時段避開備份、地圖渲染、大規模世界生成。
- 用 [用 spark 分析伺服器效能](/tutorials/ops/spark) 確認 TPS 與 MSPT 正常，不要在卡頓期硬錄。
- 拍完自己回看一遍，重點看實體移動和方塊互動是否順滑。
- 如果確實有效能短板，寧可縮小拍攝範圍，也不要用剪輯掩蓋。

:::tip 素材是一次性投入，可以複用
一次錄製可以剪出：一條 30 秒短影片、一條 3 分鐘長影片、若干張截圖、一段活動回顧。**先想好素材要複用在哪裡，再決定拍什麼**，比每次臨時找素材省力得多。
:::

## 6. 伺服器列表站與導航站的投稿

列表站的價值在於**被動流量**：玩家按版本、玩法、線上人數篩選時可能撞見你。它不會帶來爆發式增長，但它是"長期掛在那裡"的基礎曝光。

典型收錄要求（不同網站差異很大，投稿前逐條核對）：

| 要求 | 說明 |
| --- | --- |
| 準確的版本與玩法標籤 | 標錯版本會讓玩家進來發現進不去，直接流失並可能被差評 |
| IP / 域名與埠 | 必須是玩家能直接連的位址，不能只給一個群號 |
| 正版 / 離線說明 | 與列表站的篩選條件對應 |
| 截圖 | 通常要求真實遊戲內截圖 |
| 簡介文案 | 有字數上限，考驗你的一句話定位 |
| 收錄條件 | 有的要求互鏈、有的要求達到最低線上人數、有的有置頂付費位 |
| 資訊維護 | 版本更新、IP 變更後要主動改，否則玩家連不上 |

需要說清楚的兩點：

- **置頂和廣告位買得到流量，買不到留存。** 花錢把人引進來，首日體驗差，人還是走，而且錢花完了流量就斷了。
- **排序往往和線上人數、點選率有關。** 這意味著"宣傳"和"留存"是同一件事的兩面：留不住人，排名會自己掉下去。

## 7. 社群運營

宣傳解決"來"，運營解決"留"。一個沒有運營的伺服器，宣傳效果會以天為單位衰減。

### 7.1 規則

- **少而清楚**。十條能執行的規則，好過五十條沒人記得的規則。
- **公開可見**。規則要在玩家不需要問人就能看到的地方，參考 [社群規範](/rules)。
- **處罰有梯度**。提醒、警告、臨時限制、永久封禁，每一級都要寫清楚觸發條件。
- **管理自己也要守規則**。管理濫用權限的指控一旦出現，比任何作弊都更傷玩家信任。

### 7.2 新手引導與首日體驗

新玩家進服的第一個五分鐘，決定他會不會有第二個五分鐘。設計目標只有一個：**讓他在 10 分鐘內做成一件事**。

- 出生點要有明確的視覺引導：路牌、地標建築、NPC 或告示，告訴他"往哪走、先做什麼"。
- 提供一條最短的成長路徑：例如"先領新手工具，再去 A 區挖礦，回到出生點交任務，最後拿到第一筆啟動資金"。
- 新手福利可以有，但**不要破壞經濟**。給太多錢和物資，等於讓新人跳過整個遊戲前期，也讓他體會不到成長。
- 不要在出生點堆滿告示牌和傳送選單，資訊過載等於沒有資訊。

### 7.3 迎新

- **真人打招呼**比自動歡迎語有用一百倍。有人在公屏叫出新人的名字，他留下來的機率會明顯提高。
- 安排一個"值班"概念：至少保證某個時段有人能回答問題。
- 不要用機器人刷屏式歡迎，那隻會讓新人覺得這裡沒人。

### 7.4 活動與排期

- **固定排期**優於隨機辦活動。例如"每週六 20:00 建築賽""每週日 21:00 尋寶"，玩家可以形成預期。
- 提前公告，並在活動開始前 10 分鐘再提醒一次。
- 活動規模要匹配你的人力。承諾了做不到的活動，比不辦活動更傷。
- 保留活動記錄（截圖、集錦、結果公告），它們既是宣傳素材，也是社群記憶。

### 7.5 回饋渠道

- 只留**一個**明確的回饋入口，不要讓玩家在五個群裡分別喊話。
- 公開處理結果：已收到、已修、不修（並說明原因）。玩家不怕被拒絕，怕的是沒有迴音。

## 8. 留存：玩家為什麼在最初 10 分鐘離開

絕大多數流失發生在**進服後的前十分鐘**，而且原因通常和"玩法不夠多"無關。

| 流失原因 | 玩家的真實感受 | 可以怎麼改 |
| --- | --- | --- |
| 出生點看不懂 | "我不知道該幹什麼" | 明確指引與最短成長路徑 |
| 卡頓、掉線 | "這服是不是快關了" | 先解決效能，再談宣傳 |
| 沒有人說話 | "這裡沒人，是死服" | 真人迎新、保證有人值班 |
| 找不到目標 | "蓋個房子然後呢" | 清晰的成長與目標體系 |
| 被老玩家碾壓 | "我永遠追不上" | 控制資源差距、限制掠奪 |
| 規則不清被處罰 | "莫名其妙就被封了" | 規則公開、處罰留痕 |
| 感覺隨時會關服 | "不想投入時間" | 公開開服計劃與穩定性說明 |
| 付費強度 | "不花錢玩不下去" | 見下 |

### 8.1 不要做 pay-to-win

付費可以賣**外觀、便利、支持者標識**，不能賣**強度**。原因不是道德說教，而是它直接摧毀留存：

- 付費變強會讓免費玩家認定"這服不是給我做的"，離開是理性選擇。
- 一旦玩家相信"錢能解決一切"，你的所有玩法設計都失去意義。
- 信任破裂後極難修復，而伺服器口碑在玩家社群裡傳播得非常快。

### 8.2 成長路徑要看得見

給玩家一條能自己回答"下一步做什麼"的路徑：短期目標（今天能完成）、中期目標（這週能完成）、長期目標（這個月甚至更久）。路徑不需要複雜，但必須**寫在玩家能看到的地方**。

## 9. 社群層面的管理與衝突處理

技術上的防破壞見 [反作弊與防破壞](/tutorials/java/anticheat) 與 [[JAVA] 安全插件](/tutorials/ops/security-java)；這裡講的是**人和人之間**的部分。

- **處理要留痕**。封禁、回檔、處罰都留下記錄，避免"管理濫用權限"的指控。記錄插件能提供證據。
- **流程固定下來**：私下提醒、公開警告、臨時處罰、永久處罰，逐級遞進。跳級處罰會引發爭議。
- **不在情緒裡做決定**。玩家辱罵你，和他是否違反規則是兩件事。
- **爭議公開處理**。把規則依據和處理結果公開，比在群裡吵一百句更有用。
- **團隊內部也要有規則**。管理不能給自己的朋友開綠燈；這是社群崩壞最常見的原因。

更多關於團隊分工、資金與玩家管理的討論，見 [[JAVA] 經營管理](/tutorials/ops/management-java)。

## 10. 值得盯的資料

不需要複雜的資料平台，一張表就夠。**看趨勢，不要看單點。**

| 指標 | 怎麼理解 | 說明 |
| --- | --- | --- |
| 次日留存 | 今天來的新人，明天還來嗎 | 最能反映首日體驗的指標 |
| 7 日留存 | 一週後還在嗎 | 反映成長路徑與社群氛圍 |
| 峰值線上人數 | 一天裡同時線上最多多少人 | 伺服器承載與列表站排序都看它 |
| 平均線上時長 | 玩家一次進來待多久 | 短而頻繁說明內容不足；長而穩定說明有粘性 |
| 首日流失率 | 進服後很快退出的比例 | 配合出生點與引導一起看 |
| 渠道來源 | 玩家從哪知道你的 | 決定下次把精力放在哪 |
| 聊天活躍度 | 有多少人在說話 | 沉默的伺服器看起來像死服 |

兩點提醒：

- **小樣本不要過度解讀。** 一天來了 5 個人，走了 3 個，這不構成任何結論。至少看兩週趨勢。
- **資料要能對應到動作。** 留存差就去看出生點和引導，不是去多發幾條廣告。**宣傳放大的是體驗，不是彌補體驗。**

## 11. 上線周清單

開服前一週到開服後一週，按下表逐項確認。

- [ ] 一句話定位已經寫好，並且能用它篩掉不合適的玩家
- [ ] 支援版本、正版 / 離線、是否跨端已經確定並寫進所有文案
- [ ] 伺服器在開服前連續穩定運行了足夠長時間，沒有頻繁崩潰
- [ ] 效能已確認（TPS、MSPT、記憶體、磁碟寫入），錄屏時段避開了備份與渲染
- [ ] 出生點有明確指引，新人在 10 分鐘內能做成一件事
- [ ] 規則已成文並可公開訪問
- [ ] 至少有一位真人能在開服時段值班答疑
- [ ] 宣傳帖素材齊備：定位、版本、帳號要求、玩法特色、穩定性說明、加入方式、截圖或影片、規則連結、聯絡方式
- [ ] 目標渠道已逐個確認規則，並取得管理員同意（如需要）
- [ ] 伺服器列表 / 導航站的資訊已提交併核對無誤
- [ ] 至少一條 30 秒影片或一組真實截圖已準備好
- [ ] 活動排期已定，並在開服前公佈
- [ ] 回饋入口唯一且有人看
- [ ] 付費內容清單已檢查：只賣外觀與便利，不賣強度
- [ ] 資料記錄表已建好，約定好每週固定時間復盤一次
