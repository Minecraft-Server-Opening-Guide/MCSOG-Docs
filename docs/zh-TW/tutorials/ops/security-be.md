基岩版的安全模型和 Java 版**不一樣**：正版驗證走 **Xbox Live**，官方服務端 BDS **沒有插件系統**。所以這一篇分兩部分：**BDS 自帶的機制**（可靠、必用）與**第三方核心的插件體系**（靈活、但要自己承擔）。

## 一、BDS 自帶的三個機制（先用好它們）

### 1. 白名單：`allowlist.json`

- 在 `server.properties` 裡開啟白名單後，名單本身由服務端目錄下的 **`allowlist.json`** 管理。
- 這是基岩版**最有效**的一道門檻：基岩版玩家群體流動大、小號成本低，**把麻煩擋在門外**遠比事後封禁省事。
- 修改名單後按官方說明讓服務端重新讀取（或重啟）使其生效。

### 2. 管理員權限：`permissions.json`

- BDS 的管理員（OP）與權限定義在 **`permissions.json`**（含玩家 UUID、名稱與權限項）。
- 建議：**只給確實需要的人**，並在人員變動後及時回收。

### 3. 正版驗證：`online-mode`

- BDS 的 `server.properties` 有 `online-mode` 開關：開啟時玩家需通過 **Xbox Live 帳號驗證**。
- **公開服不建議關閉**：關閉後任何人都能冒用他人遊戲名進入，封禁也可換個名字繞過。

:::warn 基岩版沒有"Java 那樣成熟的登入插件生態"
Java 版離線服可以靠 AuthMe 這類插件補一道密碼門；基岩版**沒有同等地位、同等普及的官方/社群方案**。所以基岩版的正確姿勢是：**保持正版驗證 + 用白名單做門檻**，而不是指望"裝個登入插件就安全了"。
:::

## 二、第三方核心的插件體系

BDS 本身不能裝插件，要擴充只能換核心或加社群載入器（見「BDS 服務端」與「第三方核心」）：

| 路線 | 說明 |
| --- | --- |
| **BDS + 社群載入器** | LeviLamina / EndStone / BDSX 提供插件能力，可做登入、權限、管理等 |
| **Nukkit 系**（含 PowerNukkitX） | Java 編寫、有原生插件系統，生態與 Java 版插件端思路相近 |
| **PocketMine-MP** | PHP 編寫，插件數量最多，登入、權限、管理等類別都有 |

:::warn 本篇不點名具體第三方插件
基岩版第三方插件的**生態分散、命名混亂、活躍度差異極大**，很多插件缺乏可長期核實的官方來源。為避免推薦到已經停更或來源不明的插件，本篇**只說明路線與類別**，具體插件請在其官方平台按"最近更新時間 + 下載量 + 是否開源"自行甄別。
:::

### 選插件時的四個檢查

1. **是否還在更新**：基岩版協議每隔若干版本就變，停更的插件遇到新版必崩。
2. **來源是否官方**：優先作者倉庫或官方插件平台，避免二手轉發的壓縮包。
3. **是否開源 / 可審**：安全類插件（登入、權限）尤其要看得到實現。
4. **是否與你的核心版本匹配**：載入器與插件都強繫結版本區間（見「BDS 服務端」）。

## 三、跨端（Geyser / Floodgate）帶來的安全注意點

如果你用 Geyser 讓基岩版玩家進 Java 服，安全上要額外注意：

- **Floodgate 玩家名會帶字首**（預設 `.`），**白名單、封禁、指令裡寫名字時要帶上它**，否則會漏判或誤判。
- Floodgate 讓基岩版玩家**無需 Java 帳號**即可進入，等於放寬了一道驗證，**必須配合白名單或審核**。
- Geyser 裝在 **Java 服一側**，反向（Java 玩家進基岩版服）**沒有官方方案**。

## 四、通用原則（與 Java 版一致）

1. **門檻前置**：白名單 / 進服審核能擋掉絕大部分破壞與作弊。
2. **規則寫短**：基岩版玩家以手機為主，規則要直白、可執行。
3. **管理留痕**：誰封了誰、誰動了權限，都要可查。
4. **備份是最後防線**：見「備份與恢復」——注意 BDS 的存檔全在 `worlds/`，要整個目錄備。
5. **別強行清記憶體**：BDS 記憶體會緩慢增長，強行清理會導致玩家下載材質包/Addon 卡條，只能重啟解決（見「BDS 服務端」）。
