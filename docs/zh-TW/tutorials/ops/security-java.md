伺服器一公開，安全就分三層：**誰是誰**（身份）、**出事了能不能查**（記錄與回滾）、**誰能幹什麼**（權限）。這三層各有成熟插件，下面只介紹**有官方倉庫可查**的幾個。

## 一、身份驗證：AuthMe

**AuthMeReloaded** 是 Bukkit / Spigot 系的身份驗證插件（作者自己的定位就是"面向 Bukkit/Spigot API 的驗證插件"）。

- 倉庫：<https://github.com/AuthMe/AuthMeReloaded>
- **什麼時候需要它**：只有**離線模式**（`online-mode=false`）才需要。正版服裡帳號由 Mojang 校驗，不需要額外登入。
- **它解決什麼**：離線模式下"ID 可以被任何人冒用"，AuthMe 用**註冊 + 密碼登入**把 ID 和密碼繫結起來，冒用者進不去。
- **它解決不了什麼**：離線模式的根本問題（封禁可換 ID 繞過、皮膚與 UUID 無法繫結）依舊存在。**公開服仍建議開正版驗證**。

:::warn 離線模式的代價不會因為裝了登入插件而消失
登入插件只是"給離線模式補一道門"，不是把離線服變成正版服。帳號安全、皮膚、封禁效力都還是打折的。
:::

## 二、記錄與回滾：CoreProtect

**CoreProtect** 是資料記錄與防破壞工具（官方定位：*blazing fast data logging and anti-griefing tool*）。

- 倉庫：<https://github.com/PlayPro/CoreProtect>
- **它記錄什麼**：方塊放置/破壞、容器存取、實體與指令等操作，寫進資料庫。
- **它能做什麼**：查"這塊地是誰在什麼時候拆的"、查某個玩家最近幹了什麼、按時間或按玩家**批量回滾**，把被破壞的區域恢復原狀。
- **為什麼它是第一優先順序**：沒有記錄，你連"是誰幹的"都不知道，封禁和回滾都無從談起。

:::tip 越早裝越好
CoreProtect 只能記錄**裝上之後**發生的事。等被破壞了才裝，之前的一概查不到。
:::

## 三、權限：LuckPerms

**LuckPerms** 是 Minecraft 伺服器的權限插件（官方定位：*A permissions plugin for Minecraft servers.*）。

- 倉庫：<https://github.com/LuckPerms/LuckPerms>
- **它解決什麼**：原版只有"給不給 OP"，而 OP 權限極大。LuckPerms 用**權限組 + 權限節點**做精細控制，誰能用哪條指令、能碰哪些方塊，都能單獨配。
- **安全意義**：把"管理員"拆成多個角色（客服、建築師、活動主持），**每個人只拿到自己需要的那點權限**，避免一個人拿到全權後出事。
- **配套習慣**：定期審查權限組與 OP 名單。

## 四、反作弊：Grim

**Grim** 是一個**開源、非同步多執行緒、預測式**的反作弊（作者定位裡還標註了支援的版本範圍 1.8–1.21，具體以倉庫當前說明為準）。

- 倉庫：<https://github.com/GrimAnticheat/Grim>
- **思路**：不等玩家真的違規，而是**預測**玩家本應在什麼位置/狀態，偏離即判定，因此對傳統"改包"類作弊較敏感。
- **開源的好處**：判定邏輯可查、可審，不必盲信黑盒。

:::warn 反作弊的誤判比漏判更傷玩家
無論用哪個反作弊，**先跑"只記錄不處罰"模式觀察一段時間**，確認沒有誤傷再開處罰。正常玩家被踢、被回彈甚至被封，會直接流失。
:::

## 五、按類別選，而不是按名氣選

| 類別 | 代表 | 優先順序 |
| --- | --- | --- |
| **記錄與回滾** | CoreProtect | 必備（第一優先順序） |
| **權限** | LuckPerms | 必備 |
| **身份驗證** | AuthMe（僅離線模式需要） | 離線服必備，正版服不需要 |
| **反作弊** | Grim 一類 | 加分項，需謹慎配置 |
| **進服門檻** | 白名單 / 進服審核 | 小規模高質量服強烈建議 |

## 六、通用原則

1. **只從官方渠道下載**：插件是以服務端權限執行的第三方程式碼，論壇、群檔案裡轉手的 jar 風險最高（可能被塞後門）。
2. **先在測試服試**：別在主力服直接裝來路不明的插件。
3. **權限最小化**：能不給 OP 就不給，用權限節點替代。
4. **備份是最後防線**：反作弊與記錄都攔不住"最壞情況"，異地備份仍然不可省（見「備份與恢復」）。
5. **管理操作要留痕**：誰封了誰、誰給了什麼，都應可查，避免"管理濫用權限"的指控。
