反作弊在普通生存服上是加分項，在生電服上卻常常是負收益。原因不是"反作弊不好用"，而是**生電玩家的正常玩法本身就會持續觸發反作弊判定**。

還有一個更直接的事實：官方 Carpet 自己就提供了 `antiCheatDisabled` 這條規則（作用是防止玩家因移動過快被回拉）。官方在規則系統裡給出這個開關，說明生電服真正需要的是**關掉原版那套針對快速移動的回拉檢測**，而不是再加一層判定。

這篇只談結論與替代方案：為什麼衝突、誤判從哪來、以及不加反作弊的話你該做什麼。[反作弊與防破壞](/tutorials/java/anticheat) 講的是通用的兩層防護與配置方法，本篇不重複那些內容。

## 一、官方給的反向訊號

先把最有說服力的一條事實擺出來。

| 規則 | 含義 |
| --- | --- |
| `antiCheatDisabled` | 關掉它，玩家因移動過快被回拉的現象就不再發生 |

這條規則值得逐句讀：

- 它處理的是"**移動過快被回拉**"這一件事，也就是原版針對快速移動的檢測。這裡說的"檢測"指原版自身的行為，不是第三方反作弊。
- 它的存在說明：**生電服真正需要的是關掉原版這一層回拉檢測**，而不是在它之上再加一層判定。

## 二、正常玩法為什麼會觸發判定

生電玩家的日常操作，在判定邏輯眼裡幾乎全是異常訊號：

| 生電玩法 | 在判定邏輯眼裡像什麼 |
| --- | --- |
| 高速移動（鞘翅、冰道、礦車、活塞彈射一類位移手段） | 超速移動、位置不連續 |
| 大量實體（刷怪塔、TNT 陣列、掉落物與經驗球堆積） | 異常實體行為與異常密度 |
| 機器與自動化（飛行器、連發裝置、無人值守的長時執行） | 高頻、重複、與人手操作不一致的動作 |

關鍵在"持續"兩個字：這不是偶爾撞上一次判定，而是**玩法本身長期貼著判定的邊界走**。結果是兩類損失：

1. **誤判直接打斷機器與測試**：被回拉、被取消動作、被踢出，一次測試可能就白跑了。
2. **誤判不可復現**：機器壞掉的原因通常很難查，如果還疊加一層會隨機干預移動與操作的判定，排查成本會成倍上升。

:::warn 本篇不討論任何具體判定閾值
不同反作弊的實現與閾值各不相同，這裡不列舉、不比較，也不點評任何具體產品。要判斷的是**邏輯上的衝突**：一套以"人類正常操作"為基準的判定，遇上以"突破人類操作上限"為目標的玩法，衝突是必然的。
:::

## 三、裝在哪一側，代價是什麼

反作弊通常要求裝在**插件端或最佳化端**上。問題在於，最佳化端本身就會改原版行為，而這兩件事與生電目標直接衝突：

| 衝突點 | 說明 |
| --- | --- |
| 平台衝突 | 反作弊主要面向插件端生態，而生電工具鏈（Carpet 及其附屬包）在 Fabric 上 |
| 行為衝突 | 最佳化端的預設配置本身就偏離原版行為，機器可能不工作或產出不穩定 |
| 目標衝突 | 反作弊要"限制異常"，生電要"利用異常"，兩者的方向相反 |

核心選型與最佳化端的取捨，見 [服務端選擇](/tutorials/java/core)；插件端為什麼要逐項調回原版行為，見 [生電與紅石](/tutorials/java/redstone)。本篇只給一句結論：**方向相反的元件，裝上去只會互相抵消。**

## 四、不加反作弊，那裝什麼

反過來問更有用：**你到底想防什麼？**把這個問題拆開，每一類都有比反作弊更穩的手段：

| 想防的事 | 該用的手段 | 說明 |
| --- | --- | --- |
| 陌生人亂來 | 白名單與權限 | 把門檻放在進服之前，比事後判定便宜得多 |
| 破壞與偷竊 | `ledger` 記錄與回溯 | 它是服務端側的記錄 mod，對標插件端的 CoreProtect |
| 最壞情況 | 定期與異地備份 | 出事能整體回檔，這是最後一道防線 |
| 人肉盾構機、自動破基岩一類 | `playerOperationLimiter` | 每 gt 玩家可以放置 2 個方塊，秒破 1 個方塊，這兩個操作每 gt 只能做一種，用於防人肉盾構機和玩家自動破基岩 mod |

幾點補充：

- **白名單與權限**：生電服通常是熟人圈子，把"誰能進來"控制住，比在服內做即時判定有效得多。權限分開配置的思路見 [領地與保護](/tutorials/java/protection)。
- **記錄與回溯**：`ledger`（對標插件端的 CoreProtect）屬於記錄類工具，它不做即時攔截，但**能回答"是誰、什麼時候、動了什麼"**。沒有記錄，你連處理依據都沒有。
- **備份**：定期備份與異地備份解決的是"前面都失效了"的情況，完整的策略與恢復流程見 [存檔保護](/tutorials/java/sd-backup)。
- **`playerOperationLimiter`**：請注意它是**服務端側的限制手段**，作用在服務端自身，不需要玩家裝任何東西。它限制的是每 gt 的放置與破壞操作，針對的是自動化濫用，而不是給正常玩家打分。它屬於某個 Carpet 附屬專案提供的規則，**裝之前先按你的遊戲版本與 mod 組合確認可用**。

## 五、該怎麼做：一張正向清單

與其反覆論證"不要裝反作弊"，不如直接照著做：

1. **先進服門檻**：白名單或進服審核，把來源控制住。
2. **再做權限分級**：普通玩家、技術組、管理權限分開，不輕易給 OP；誰能動機器、誰能用高風險操作，事先寫清楚。
3. **裝記錄工具**：`ledger` 一類記錄 mod 越早裝越好，它只記錄裝上之後發生的事。
4. **配好備份**：定期備份加異地備份，並**實際演練一次恢復流程**——沒驗證過的備份不算備份。
5. **用服務端側限制替代即時判定**：例如 `playerOperationLimiter` 這種在服務端自身生效、不依賴玩家客戶端的手段。
6. **規則寫明白**：允許什麼、禁止什麼、怎麼處理，寫在玩家看得到的地方。
7. **需要原版回拉檢測時，用 `antiCheatDisabled` 關掉它**：這是官方規則系統給出的開關，比裝第三方元件更可控，也更容易向玩家解釋。

## 六、本篇的底線

```
1. 官方自己就提供 antiCheatDisabled —— 生电服要的是关掉原版回拉，不是再加一层
2. 生电的正常玩法会持续触发判定，误判是必然的，不是偶发
3. 反作弊要装在插件端/优化端，与生电目标方向相反
4. 替代方案：白名单与权限 + ledger 记录 + 定期异地备份 + 服务端侧限制
```
