生電玩法繞不開原理圖：別人設計的世吞、刷怪塔、切門機器，你不可能憑記憶照抄，得靠投影一層層對著搭。單人存檔裡這很簡單，裝上客戶端投影 mod 就行；一旦到了多人伺服器，原理圖就散落在每個人自己的電腦上，誰想照著搭，都得先向原作者要一份檔案。

`syncmatica` 解決的正是這件事。它是給 Litematica 做同步的配套，讓原理圖和放置能被方便地共享。

這一篇只講三件事：為什麼需要它、它裝在哪一側、版本怎麼對齊。**具體怎麼上傳、誰有權限、用什麼命令，請以 mod 官方說明為準，本篇不復述操作步驟**——那部分每個版本都可能變，照著過期教學走反而更容易出錯。

## 一、多人伺服器上原理圖卡在哪

單人存檔裡，原理圖檔案和投影都在你自己的客戶端上，不存在"共享"問題。多人伺服器上則有三層麻煩：

| 麻煩 | 具體表現 |
| --- | --- |
| 檔案在個人電腦上 | 每來一個新玩家，原作者都要重新發一次檔案 |
| 位置對不上 | 投影需要知道"這份原理圖放在世界的哪個座標"，口頭報座標很容易傳錯 |
| 版本與來源混雜 | 傳著傳著就分不清誰手裡那份是不是最新的 |

`syncmatica` 要處理的就是前兩層：把原理圖與它的放置變成"可以方便地共享"的東西。它做的是同步與共享這一層，而不是替你做投影顯示——投影顯示仍然是 Litematica 的活。

> 想先了解投影在生電工具鏈裡的位置，可以回看 [生電與紅石](/tutorials/java/redstone) 裡的客戶端 mod 表，以及 [生電與紅石進階](/tutorials/java/redstone-advanced) 裡對 MiniHUD、Litematica 一類工具的說明。

## 二、兩側各裝什麼

這是本篇最需要記住的一張表。共享原理圖不是"裝一個 mod 就完事"，而是**服務端和客戶端都要裝 Syncmatica，客戶端還要額外裝 Litematica**。

| 位置 | 需要裝 | 說明 |
| --- | --- | --- |
| 服務端 | `syncmatica` | 同步的服務端一半。只裝客戶端是共享不起來的 |
| 客戶端 | `syncmatica` | 同步的客戶端一半，和 Litematica 配合工作 |
| 客戶端 | `litematica` | 真正負責投影顯示的 mod。`syncmatica` 是為它做同步的配套 |

三條容易踩的坑：

1. **只給玩家裝了 Syncmatica**，服務端沒裝，同步無從發生。
2. **服務端裝了 Syncmatica 卻沒讓玩家裝 Litematica**，共享出來的原理圖沒有東西去顯示它。
3. **兩邊版本不一致**，這是最常見的問題，第三節單獨講。

## 三、三個 mod 的載入器與版本區間

下面的資料來自 Modrinth 官方條目，寫作時核對過。把它當作選版本的起點，實際下載前再核對一次專案頁。

| mod | loaders | 支援版本 | 下載量（約） |
| --- | --- | --- | --- |
| `syncmatica` | fabric、quilt | 1.16–26.3 | 83.9 萬 |
| `litematica` | fabric、forge、liteloader、ornithe | 1.12–26.3 | 2644 萬 |
| `servux` | fabric | 1.14.4–26.3 | 98.4 萬 |

幾點補充：

- 三個 mod 的版本區間都很寬，從 1.12 / 1.14 / 1.16 一直覆蓋到 26.x 一類的近期版本。**區間寬不代表隨便挑一版就能用**，真正要對齊的是"遊戲版本一致、兩側的 Syncmatica 同屬一個版本區間"。
- 還有一個常被一起提到的 mod：`servux`。它是**服務端 mod**，為部分客戶端 mod 提供額外支援與功能。它不是共享原理圖的必需品，但它解決的是同一類問題——"客戶端 mod 想要更多資料，得服務端配合"。
- `litematica` 的 loaders 裡有 forge 與 liteloader、ornithe，說明它本身不止 Fabric 一條路；但 `syncmatica` 只有 fabric 與 quilt，**這一側的同步能力是把選擇面收窄的那一環**。

## 四、版本對齊：這一側最容易錯

共享原理圖是兩側配合的機制，所以"對齊"不是一句口號，而是四個必須同時成立的版本關係：

| 要核對的東西 | 要求 |
| --- | --- |
| 遊戲版本 | 客戶端與服務端必須是同一個遊戲版本 |
| `syncmatica`（服務端） | 落在該遊戲版本的支援區間內 |
| `syncmatica`（客戶端） | 與上面同一個版本區間，兩邊不要混用 |
| `litematica`（客戶端） | 與該遊戲版本匹配 |

現實裡最常見的翻車方式有兩種：一是**只更新了一側**（比如只換了客戶端的 mod，服務端還停在舊版），二是**為了讓某個 mod 跑起來把遊戲版本往回退**，結果另一側的 mod 又對不上了。

給一個穩妥的操作順序：

1. 先定遊戲版本，再按第三節的表把三個 mod 都挑好。
2. 服務端與客戶端的 `syncmatica` 用同一版本區間的檔案。
3. 裝完先確認能正常進服、投影能顯示，再談共享。
4. 出問題時的第一判據永遠是**版本**，而不是配置。

## 五、為什麼本篇只講"裝在哪一側"

共享原理圖是一套**跨兩側協作**的機制，任何一步錯位都不會報出清晰的錯誤，只會表現為"共享沒反應"。而具體的操作方式——怎麼把原理圖放上去、誰可以放、用什麼命令管理——屬於 mod 自身的功能面，會隨版本變化。

所以本篇的口徑是：

1. **原理講清楚**：為什麼需要它、資料在哪兩側之間流動。
2. **位置說清楚**：服務端裝什麼、客戶端裝什麼，一個都不能少。
3. **版本對齊說清楚**：三份東西的版本關係。
4. **操作交給官方**：mod 官方說明裡怎麼寫，就怎麼做。

這樣寫不是偷懶，而是避免把某一版的介面和命令寫死在這裡，等 mod 更新之後誤導你。

## 六、它和 Carpet 是什麼關係

**同屬生電工具箱，但解決的是不同問題**。

| | Carpet | Syncmatica |
| --- | --- | --- |
| 解決什麼 | 用規則開關原版細節行為 | 讓原理圖與放置能被方便地共享 |
| 形態 | Fabric 服務端 mod，提供規則系統 | 同步 mod，服務端與客戶端各一半 |
| 典型用法 | `/carpet <规则名> <值>` | 與 Litematica 配合共享原理圖 |

兩者的共同點是都以 Fabric 為主：Carpet 及其全部附屬包都是 Fabric，`syncmatica` 的 loaders 也是 fabric 與 quilt。這也是 [服務端選擇](/tutorials/java/sd-server) 裡推薦 Fabric 服務端 + MCDR 的原因之一——工具鏈在同一側，不用做橋接。

Carpet 本體的定位與規則用法，見 [Carpet 及其附屬包](/tutorials/java/sd-carpet)。

## 七、和世吞、切門怎麼配合

投影最典型的用途就是搭大機器：世吞是 TNT 陣列加飛行器、成片清空區域的機器，尺寸大、結構重複、對位置精度要求高，靠人腦記是不可能搭對的。正常流程是：**先有原理圖，再用投影照著搭**。

共享原理圖在這個流程裡解決的是協作問題：一台世吞往往不是一個人搭完的，需要幾個人分片施工；投影一致，幾個人的方塊才能拼得上。

而一旦機器開始運轉，重點就不再是投影，而是風險控制：[世吞與切門](/tutorials/java/sd-machine) 講的是機器越猛，越要"備份 + 權限 + 防崩規則"三件套，以及新版本上更新抑制（社群俗稱"切門"）要靠社群 mod 恢復這些事實。搭機器之前先把那篇讀完。

## 八、底線清單

```
服务端装 Syncmatica + 客户端装 Syncmatica + 客户端装 Litematica
再把三份版本对齐 —— 缺一项，共享就不成立
```

- **服務端側別忘了**：只配客戶端是新手最常見的錯。
- **操作照官方**：不要在沒核對 mod 官方說明的情況下照抄別人的步驟。
- **先對齊版本再裝**：版本區間見第三節的表，裝之前核對專案頁。
