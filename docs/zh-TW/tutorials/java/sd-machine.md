世吞（world eater）是 TNT 陣列加飛行器的機器，用來成片清空一塊區域；"切門"則是社群對更新抑制（update suppression）這一類操作的俗稱。這兩樣東西是生電服上最容易把服務端直接搞掛的玩法。

**本篇只講風險控制，不講怎麼造。**造法不在已核實範圍內，網上流傳的圖紙與步驟也不保證在你的版本上成立，這裡不寫、也不復述。

先把邊界說清楚：與世吞直接相關的官方 Carpet 規則只有三條，其中兩條會改變原版行為，正式開服不要開。真正需要你提前配好的是防崩規則，而且要**先進規則、後動機器**。

## 一、世吞是什麼，風險在哪

世吞的做法是用 TNT 陣列持續爆破，再靠飛行器把整個結構平移過去，一路把地形清空。它的產出是"一片被挖空的區域"，它的成本則是伺服器最貴的幾樣東西：海量 TNT 實體、成片的爆炸計算、被摧毀方塊帶來的巨量方塊更新，以及始終在執行的飛行器。

| 風險 | 來源 |
| --- | --- |
| TPS 被拖垮 | 同一時刻存在大量 TNT 實體與爆炸計算 |
| 存檔與頻寬壓力 | 一次執行就改掉大片區域，方塊更新量巨大 |
| 無人值守下失控 | 機器靠飛行器自行推進，出問題時不一定有人在場 |
| 操作本身越界 | 更新抑制（"切門"）會把鄰居更新棧填滿，進而可能讓服務端崩潰 |

換一個角度看，同一台機器對玩家和服主的含義是相反的：

| 角色 | 世吞意味著什麼 |
| --- | --- |
| 玩家 | 一條高效獲取大片空區的產線，產出歸自己 |
| 服主 | 一片區域的全量方塊改動 + 一段持續的高負載 + 一份崩潰風險 |

所以世吞不是"能不能造出來"的問題，而是"出事之後你能不能收場"的問題。

## 二、與世吞直接相關的官方規則

Carpet 用 `/carpet <规则名> <值>` 開關原版細節行為。與世吞直接相關的只有下面三條：

| 規則 | 對原版行為的影響 |
| --- | --- |
| `optimizedTNT` | 不改變爆炸效果本身，只是讓同位置與液體中的爆炸更省資源 |
| `tntDoNotUpdate` | **改變原版行為**：TNT 靠著電源放置時不再被更新 |
| `explosionNoBlockDamage` | **改變原版行為**：爆炸不再破壞方塊 |

使用口徑：

- `optimizedTNT` 描述的是**同位置、液體中**爆炸的卡頓更小，對世吞這種"同一片區域反覆爆"的場景有意義；它最佳化的是開銷，不是效果。
- `tntDoNotUpdate` 與 `explosionNoBlockDamage` **會改變原版行為**，只在測試或特定場景使用。正式開服不要開——`tntDoNotUpdate` 會讓"靠著電源放 TNT"這套玩法失效，`explosionNoBlockDamage` 則直接取消爆炸的破壞力，機器清空區域的能力就沒了。

:::warn 兩條改變原版行為的規則只屬於測試環境
`tntDoNotUpdate` 與 `explosionNoBlockDamage` 適合在測試服裡驗證結構、做無害演示，**不適合正式開服**。開著它們測出來的機器行為，和真正上線後的行為是兩回事。
:::

## 三、"切門"的準確定義

**"切門"是社群對"更新抑制（update suppression）"這一類操作的俗稱。**它指的不是某個方塊、某個機器，而是一整類利用更新抑制現象的技巧。

官方 Carpet 給了它一個可控入口，規則名是 `updateSuppressionBlock`：**在屏障方塊上放啟用鐵軌，鐵軌轉向時會填滿鄰居更新棧。**

這裡有兩個必須記住的點：

1. 它是**官方提供的可控入口**，也就是說這件事本身不需要額外的 mod 才能在服務端側被開關。
2. 它的後果寫在"填滿鄰居更新棧"這句裡——鄰居更新棧被填滿，正是崩潰風險的來源。

## 四、為什麼必須先開防崩

更新抑制的機制是**把鄰居更新棧填滿**。填滿之後發生的事情不受你的機器控制：**它進而可能讓服務端崩潰**。

這就是順序問題的答案。很多人是"先動機器，崩了再找規則"，但崩潰不是每次都能溫柔收場——服務端掛掉的那一刻，正在寫入的區塊和正在執行的機器狀態都不一定完整。所以正確順序是：

```
1. 先进防崩规则（本节）
2. 再进机器、再让玩家开工
```

已經核實到的防崩規則如下，按來源分兩組。規則名與可選值在 [Carpet 及其附屬包](/tutorials/java/sd-carpet) 裡已作為清單列過一遍，**這裡要補的是使用順序**：

| 來源 | 規則 | 可選值 |
| --- | --- | --- |
| Carpet AMS Addition | `amsUpdateSuppressionCrashFix` | `false` / `true` / `silence` |
| Carpet AMS Addition | `customBlockUpdateSuppressor` | `none` / `minecraft:bone_block` / `minecraft:diamond_ore` / `minecraft:magma_block` |
| Carpet TIS Addition | `yeetUpdateSuppressionCrash` | 見對應版本的 mod 說明 |
| Carpet TIS Addition | `updateSuppressionSimulator` | 見對應版本的 mod 說明 |

幾點說明：

- `amsUpdateSuppressionCrashFix` 是一個**三態開關**：`false` 與 `true` 是常見的關與開，`silence` 是第三檔處理方式。三檔各自的確切語義以 mod 官方說明為準，這裡不替它下定義。
- `customBlockUpdateSuppressor` 的作用是**把指定方塊變成更新抑制方塊**，可選值就是上表那幾個方塊。
- Carpet TIS Addition 的 `yeetUpdateSuppressionCrash` 與 `updateSuppressionSimulator` 覆蓋的是**另外兩個方向**：一個對應崩潰處理，一個對應模擬。兩者的具體行為與可用值以對應版本的 mod 說明為準。

:::tip 先確認規則真的生效，再動機器
防崩規則不是"裝上就永遠安全"，它是一層兜底。做法是：**配置完先自己觸發一次更新抑制看錶現**，確認規則確實按預期攔住了，再讓玩家開始動機器。
:::

## 五、版本差異：新版本要靠社群 mod 恢復

這是一個必須照寫的事實：**官方版本已修復更新抑制**。也就是說，在新版本上要做同類操作，需要社群提供的恢復或輔助 mod，而它們各自覆蓋的版本區間不同：

| mod | loaders | 覆蓋版本區間 |
| --- | --- | --- |
| `update-depression` | fabric、quilt | 1.19.4–1.21.1 |
| `better-update-suppression` | fabric | 1.21.10–26.2 |
| `suppressed` | fabric | 26.1.1–26.2 |
| `lithonate` | fabric | 僅 1.16.5 |

讀這張表的正確方式：

- 這不是一張"隨便挑一個"的清單，而是**四個各不相同、且互不重疊的版本區間**。你要先定遊戲版本，再看那個版本落在誰的區間裡。
- `suppressed` 與 `better-update-suppression` 的區間都在 26.x 一帶，`update-depression` 覆蓋的是較老的 1.19.4 到 1.21.1，`lithonate` 只覆蓋 1.16.5。
- **一旦換版本，這套選擇就要重做。**機器能不能跑、要裝哪個 mod，都以版本為前提，不要指望"升級後照舊能用"。

## 六、三件套：備份、權限、防崩規則

機器越猛，這三件事越不能省。它們分別對應本站的三篇：

| 事項 | 作用 | 詳見 |
| --- | --- | --- |
| **備份** | 崩服、誤操作、機器失控之後能回到上一個可用狀態 | [存檔保護](/tutorials/java/sd-backup) |
| **權限** | 決定誰能動機器、誰能用更新抑制這類高風險操作 | [領地與保護](/tutorials/java/protection) |
| **防崩規則** | 把更新抑制這類操作從"可能搞掛服務端"壓回可控範圍 | 本篇第四節 |

補充一條與機器行為直接相關的閱讀：機器為什麼壞、為什麼慢，取決於 tick 模型與同一刻內的更新順序，見 [生電與紅石進階](/tutorials/java/redstone-advanced)。

## 七、本篇的底線

```
1. 官方规则只认三条：`optimizedTNT` 可留，另外两条改动原版，正式服不开
2. 切门 = 更新抑制的社区俗称，官方可控入口是 `updateSuppressionBlock`
3. 先进防崩规则，再动机器 —— 顺序反了就等于拿存档赌
4. 新版本上做同类操作，先按版本选恢复/辅助 mod
```
