玩家進不來，提示"版本不相容"或者"過舊的客戶端"，是開服時最常見的求助之一。原因很簡單：服務端和客戶端說的是同一套協議的不同版本，雙方對不上話。跨版本插件做的事，就是在中間當翻譯。

這一篇講清楚 Via 系列各自負責什麼方向、裝在哪裡、誰依賴誰，以及它們做不到什麼。前置知識見 [插件入門](/tutorials/java/plugins)。

## 1. 為什麼玩家進不來

Minecraft 的 Java 版客戶端和服務端通過一套二進位制協議通訊。每個遊戲版本都會改動這套協議：加了新資料包、改了欄位順序、換了數值含義。協議版本對不上，握手階段就會失敗，玩家看到的通常是一句版本不匹配的提示。

服務端只認自己那個版本（以及少量相容版本）的客戶端。於是：

- 服務端是 1.20.4，玩家用 1.21 客戶端：進不來。
- 服務端是 1.21，玩家用 1.8 客戶端：同樣進不來。

跨版本插件的工作方式，是在服務端這一側接收玩家的資料包，把它們翻譯成服務端能理解的形式，再把服務端的回應翻譯回玩家的協議版本。**玩家客戶端不需要裝任何東西。**

:::warn 跨版本不是萬能方案
它翻譯的是協議，不是玩法。跨的版本越大，能對上的東西越少，體驗下降越明顯，詳見第 5 節。
:::

## 2. Via 三件套各管什麼

Via 系列是一個家族，三個插件分別負責不同的方向。方向記法：**"向上"指讓更新的客戶端進來，"向下"指讓更舊的客戶端進來。**

| 插件 | 方向 | 作用 | 依賴 |
| --- | --- | --- | --- |
| **ViaVersion** | 向上相容 | 讓比服務端更新的客戶端進服 | 無，是核心 |
| **ViaBackwards** | 向下相容 | 讓比服務端更舊的客戶端進服 | 需要 ViaVersion |
| **ViaRewind** | 向下相容更老的版本 | 支援 1.7.x 與 1.8.x 客戶端 | 需要 ViaVersion，通常與 ViaBackwards 一起裝 |

舉例說明覆蓋範圍：

- 服務端 1.9.x，只裝 ViaVersion：允許 1.9.x 到最新版的客戶端進服。
- 服務端 1.21.x，裝上 ViaVersion + ViaBackwards：允許 1.9.x 到 1.20.x 的客戶端進服。
- 再加上 ViaRewind：覆蓋到 1.7.x 與 1.8.x。

三者疊加後，插件版 Via 大致覆蓋 1.7 到最新版這一整段。

### 下載渠道

| 插件 | 發佈頁 |
| --- | --- |
| ViaVersion | SpigotMC 資源 19254、Hangar、Modrinth、GitHub |
| ViaBackwards | SpigotMC 資源 27448、Hangar、Modrinth、GitHub |
| ViaRewind | SpigotMC 資源 52109、Hangar、Modrinth、GitHub |

官方構建站是 `ci.viaversion.com`，需要最新構建時從這裡取。

:::note Java 8 支援
新版本的 Via 系列已經去掉了對 Java 8 的支援，因此在很老的服務端上無法直接使用。如果你要讓 1.8 到 1.21 的服務端都能用，需要從構建站上取專門的 Java 8 分支版本。
:::

:::tip 版本要對齊
同時安裝 ViaVersion 與 ViaBackwards 時，儘量選同一時期的版本。更新過代理端之後，也要記得把 Via 系列一起升到最新，否則會出現"裝了跨版本卻仍然提示版本不支援"的情況。即使不用代理端，也建議至少每月更新一次。
:::

## 3. 裝在哪裡：服務端還是代理端

Via 系列在 BungeeCord、Velocity 和各種 Minecraft 服務端上都能裝，但裝的位置不同，效果和坑也不同。

| 安裝位置 | 優點 | 代價 |
| --- | --- | --- |
| 後端服務端 | 後端拿到的是玩家**真實的客戶端版本**，反作弊與資料包類插件工作正常 | 每台後端都要裝一套，配置要各自維護 |
| 代理端 | 只需裝一次，玩家在進入任何後端之前就完成翻譯 | 後端服務端看到的玩家版本是**代理端的版本**，不是玩家客戶端的真實版本 |

如果你用了反作弊、反假人這類對資料包做大量處理的插件，把 Via 裝在代理端容易引起相容性問題，需要謹慎。反過來，如果你只有一個後端，或者希望玩家在選服之前就完成翻譯，裝在代理端會更省事。

:::warn 跨版本與模組端
跨版本方案不適合模組服。模組會改動協議與登錄檔內容，跨版本插件無法翻譯這些自定義部分，混在一起用會出很多問題。
:::

## 4. 安裝順序與相互關係

三個插件的關係是層層依賴的：

1. **先裝 ViaVersion**。它是核心，單獨裝它就已經具備向上相容能力。
2. **需要向下相容時再加 ViaBackwards**。它把新版本協議回退成舊版本能理解的形式。
3. **需要支援 1.7 與 1.8 時再加 ViaRewind**。它需要配合 ViaRewind Legacy Support 才能發揮完整的相容能力。

載入順序上，讓 ViaVersion 先載入、ViaBackwards 與 ViaRewind 後載入即可，通常由服務端按依賴關係自動處理，不需要手動干預。裝完後重啟服務端，在控制台確認三個插件都載入成功。

## 5. 能做到什麼、做不到什麼

這是最容易產生誤解的部分：**Via 翻譯協議，不新增內容。**

| 玩家會遇到的現象 | 原因 |
| --- | --- |
| 高版本客戶端進低版本服務端，用不了高版本物品的功能 | 服務端根本沒有這些物品的邏輯，只能用材質相近的低版本物品代替顯示 |
| 低版本客戶端看不到高版本物品的材質 | 客戶端沒有對應的模型與貼圖資源，官方插件不處理；1.16 以上有繞過手段，但不是官方能力 |
| 1.17 以下的客戶端看不到 y=0 以下的方塊 | 舊客戶端的協議與渲染不支援負高度，官方明確表示不會修復 |
| 進服後行為怪怪的：回彈、動作不同步、介面錯位 | 跨的版本太大，雙方能對上的概念太少 |
| 提示傳送資料包過多被踢出 | 觸發了兩側的 pps 限制，見下 |

跨版本越大，體驗下降越明顯。除非你有能力讓低版本玩家也獲得不錯的體驗，否則不要盲目追求"全版本通吃"。

### 常見設定項

| 設定項 | 用途 |
| --- | --- |
| `serverside-blockconnections` | 方塊材質或連線紋理顯示不對時，改為 `true` 試試 |
| `max-pps` | 玩家因傳送資料包過多被踢出時調整；使用 Paper 分支時可直接設為 `-1`，再單獨調整 Paper 自身的 pps 限制 |
| `fix-1_13-face-player` | 為 1.12 玩家轉換 1.13 的皮膚資料包，需要額外的快取 |
| `handle-pings-as-inv-acknowledgements` | 對 1.17 以下客戶端傳送物品欄確認資料包來替代 ping，對反作弊相容性有幫助 |
| `replace-adventure` | ViaRewind 的選項，控制 1.9 的粒子是否被替換為 1.8 及更低版本的近似粒子 |

:::warn 不要直接關掉 pps 限制
把資料包限制調高是為了讓正常玩家不被誤踢，但完全停用會讓惡意玩家有機會用資料包攻擊卡服。調到"正常玩家不會觸發"的水準即可。
:::

## 6. 獨立版：ViaProxy

如果你連服務端核心都不方便改，還有一個獨立方案：**ViaProxy**。它是一個獨立的代理程式，支援任意客戶端版本連線任意服務端版本，不需要在服務端裡裝插件。

它的覆蓋範圍比插件版寬得多，包括遠古的 Alpha、Beta 與 Classic 版本、愚人節快照、戰鬥測試快照，甚至可以通過 Geyser 讓基岩版玩家接入。下載在 ViaVersion 的 GitHub Releases 與官方構建站上。

:::note 什麼時候用它
當你想讓現代客戶端進入十年前的舊服務端，或者只想臨時驗證某個版本的相容性，ViaProxy 比改造服務端省事得多。但它是獨立行程，多了一層轉發，也意味著多一處要維護和排障的地方。
:::

## 7. 排障速查

| 現象 | 先查什麼 |
| --- | --- |
| 裝完仍提示版本不支援 | Via 系列是否為最新；代理端升級後是否同步升級了 Via |
| 部分玩家進不來，其他人正常 | 這些玩家的客戶端版本是否超出了當前插件的覆蓋範圍 |
| 材質或紋理顯示異常 | `serverside-blockconnections`；低版本看不到高版本材質屬於預期行為 |
| 玩家被踢，提示資料包過多 | `max-pps` 與 Paper 的 pps 限制 |
| 反作弊誤報或行為異常 | Via 是否裝在代理端；後端拿到的是代理端版本而非玩家真實版本 |
| 低版本玩家在 y=0 以下瘋狂回彈 | 已知限制，不會修復 |
