伺服器一公開，就會遇到兩類問題：**有人破壞/偷東西**，以及**有人用作弊客戶端**。這兩類要用不同的手段應對。

## 一、先分清兩層防護

| 層次 | 目標 | 手段 | 優先順序 |
| --- | --- | --- | --- |
| **記錄與回溯** | 出事能查、能回滾 | CoreProtect / Prism 一類記錄插件 |  **必備** |
| **即時反作弊** | 當場攔住作弊行為 | 反作弊插件（檢測移動、戰鬥、發包） | 加分項 |
| **權限與審計** | 防"管理濫用" | 權限組 + 操作留痕 |  必備 |
| **進服門檻** | 減少麻煩來源 | 白名單 / 進服審核 | 視規模 |

**順序很重要**：先把"記錄與回溯"做好，再考慮反作弊。因為**沒有記錄，你連"是誰幹的"都不知道**；而反作弊再強也有漏網的。

## 二、記錄與回溯（防破壞）

這類插件的原理是**把方塊、容器、實體、指令等操作全部記進資料庫**，之後可以：

- 查某個方塊**被誰在什麼時候**破壞/放置過；
- 查某個玩家**最近都幹了什麼**；
- 按時間或按玩家**批次回滾**（把被破壞的區域恢復原狀）；
- 查容器（箱子）的存取記錄，判斷是否偷竊。

推薦做法：

- **CoreProtect**：最主流的方塊記錄插件，配合它的查詢指令與回滾指令使用。
- 也可以搭配 **InvSee** 類插件檢視玩家背包（排查贓物）。
- **Prism** 一類是同類替代方案。

:::tip 記錄插件要早裝
它只能記錄**裝上之後**發生的事。等被破壞了才裝，之前的事一概查不到。
:::

## 三、即時反作弊

主流方案是**服務端反作弊插件**，通過分析玩家發包行為判斷異常（如超速移動、瞬移、攻擊距離超限、自動瞄準等）。常見的有 Grim、Matrix、Vulcan、Spartan 一類。

選擇與配置時注意：

- **先跑記錄模式**：絕大多數反作弊支援"只記錄不處罰"，**先觀察一段時間**再開啟處罰。
- **誤判比漏判更傷玩家**：正常玩家被踢、被回彈、甚至被封，會直接流失並留下差評。**寧可漏一點，也不要大規模誤傷**。
- **離線模式下反作弊意義有限**：換個 ID 就能重來，帳號封禁的威懾力大打折扣。
- **客戶端反作弊**：少數伺服器要求玩家安裝專用客戶端做校驗，防護更強但**門檻極高**，適合競技向的封閉伺服器。
- **插件衝突**：反作弊插件對協議的介入較深，和某些插件（尤其是修改移動/戰鬥邏輯的）容易衝突，**裝完要觀察日誌**。

## 四、權限與內部管理

外部防住了，內部翻車同樣致命：

- **不要隨便給 OP**：原版 OP 權限極大。用權限插件（LuckPerms）按**權限節點**精細授權，比給 OP 安全得多。
- **管理操作要留痕**：誰執行了封禁、誰給了物品、誰改了世界，都應可查。
- **避免單人獨裁**：管理權限集中在一個人手上，一旦此人出問題或跑路，伺服器會很被動。
- **定期審查**：檢查 OP 名單、權限組、白名單是否有不該在的人。

## 五、把門檻前置

比"事後處理"更省事的是**少讓麻煩進來**：

- **白名單 / 進服審核**：小規模、高品質伺服器常用；能擋掉絕大部分破壞與作弊。
- **規則明確**：寫清楚禁止事項與處罰方式，處理時才站得住腳。
- **新玩家觀察期**：新號限制部分權限（如暫時不能使用某些容器），降低一次性破壞的風險。

## 六、一個現實結論

**沒有任何反作弊能 100% 攔住作弊**，也沒有任何保護能 100% 防住破壞。所以真正可靠的是三件事的組合：

```
早裝記錄插件（能查、能回滾）
   + 謹慎配置反作弊（別誤傷）
   + 定期異地備份（最壞情況能整體回檔）
```

這三件裡，**備份是最後一道防線**（見「備份與恢復」）。
