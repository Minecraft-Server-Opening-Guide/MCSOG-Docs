MCDReforged（簡稱 **MCDR**）是開服圈裡非常流行的一個**服務端管理器**。它不替代你的服務端核心，而是**包在核心外面**：由它來啟動和管理核心行程，讀取控制台輸出，從而在**不改動服務端本體**的前提下擴充功能。

## 一、它解決什麼問題

原版 / Paper 服務端能擴充的只有"插件"，而 MCDR 提供的是**另一層**能力：

| 能力 | 說明 |
| --- | --- |
| **插件生態** | 用 **Python** 寫插件，能做很多 Java 插件不方便做的事（跨服轉發、外部 API 對接、自動化維運） |
| **事件驅動** | 解析服務端輸出並分發事件（玩家進出、聊天、死亡、指令……），插件訂閱即可 |
| **熱過載** | 插件通常能過載，不必重啟整個服務端 |
| **權限系統** | 自帶一套按玩家/按群的權限控制，配合 `!!` 字首指令使用 |
| **看門狗** | 核心崩潰後可自動重啟 |
| **跨服** | 一套 MCDR 可以管理多個服務端實例 |

## 二、它是怎麼工作的

MCDR 啟動後會**託管服務端行程**：它把服務端的控制台輸出讀進來解析成事件，同時把你在聊天框裡輸入的 `!!xxx` 指令攔下來交給插件處理，而不是丟給原版服務端。

所以：

- 服務端**本身**還是原來的核心，行為不變；
- 你多了一層"外殼"，**故障排查時要多看一層日誌**（MCDR 自己的日誌 + 服務端日誌）。

## 三、安裝

MCDR 用 **Python 3** 編寫，依賴 Python 與 pip：

| MCDR 版本 | 需要的 Python |
| --- | --- |
| < 2.10 | ≥ 3.6 |
| ≥ 2.10 | ≥ 3.8 |
| ≥ 2.15 | **≥ 3.9** |

裝最新版就用 **pip** 安裝：

```bash
pip install mcdreforged
```

:::warn 不要下載原始碼 zip 來執行
網上不少教學讓你去 GitHub 下載壓縮包解壓使用——**那是過時做法**。MCDR 從 1.0（2021 年初）起就不再以原始碼方式安裝。除非你是開發者且清楚在做什麼，否則請用 pip 安裝。
:::

## 四、啟動流程

1. **初始化**：執行一次初始化指令，MCDR 會生成自己的設定檔與目錄結構。
2. **配置**：在 MCDR 的配置裡填好**服務端的啟動指令**與**工作目錄**（也就是「開啟服務端」裡那個啟動腳本乾的事，現在交給 MCDR 來做）。
3. **啟動**：執行 MCDR，它會拉起服務端，並接管控制台。
4. **確認服務端類型**：MCDR 通過**服務端處理器**適配不同類型的核心（原版 / Paper 系 / 模組端等），選錯會導致事件解析異常。

:::tip 命令列子指令以官方文件為準
MCDR 的命令列介面（全域參數、子指令）在各版本間有調整，**具體寫法請對照官方 CLI 文件**，不要照抄舊教學。
:::

## 五、指令與權限

MCDR 的指令統一用 `!!` 字首（在遊戲內聊天框輸入即可）：

| 指令 | 作用 |
| --- | --- |
| `!!MCDR` | 主指令，管理 MCDR 自身（狀態、插件、過載、權限等） |
| `!!help` | 檢視已註冊的指令幫助 |

- 指令的執行權限由 MCDR 的**權限系統**控制，可按玩家或權限組授予。
- 未授權的玩家執行會收到拒絕提示，不會影響到服務端本體。

## 六、插件

- 插件放進 MCDR 的 `plugins/` 目錄，通過 `!!MCDR` 相關子指令載入 / 過載。
- 官方有一個**插件倉庫**，可以在裡面找現成插件；也可以自己寫（單檔案插件、多檔案插件、資料夾插件等幾種形式）。
- 插件開發的核心是**元資料 + 事件監聽 + 指令樹**：聲明插件資訊，註冊感興趣的事件，構建自己的 `!!` 指令。

## 七、什麼時候該用 MCDR

**適合**：想要自動化維運（定時重啟、崩潰拉起、備份聯動）、想把服務端狀態對接到外部平台（QQ 群、Discord、網站）、或需要寫 Python 插件做定製邏輯。

**不一定需要**：只是開個小型插件服，用核心自帶的插件 + systemd 託管就夠了。**多一層就多一層維護成本**，別為了用而用。
