服務端能在本機跑通，只是第一步。**讓別人也能連上**，才叫真正開服。這一步的難點幾乎全在網路，不在 Minecraft 本身。

## 一、三條路線，先選一條

| 方案 | 適合 | 優點 | 代價 |
| --- | --- | --- | --- |
| **雲伺服器** | 想長期 24 小時線上 | 有公網 IP、穩定、不怕停電斷網 | 要花錢，配置越好越貴 |
| **自家電腦 + 公網 IP** | 家裡有公網 IPv4 | 不額外花錢，效能可控 | 電費/噪音/斷電斷網，且**多數家寬沒有公網 IPv4** |
| **內網穿透（frp 等）** | 家裡沒有公網 IP | 不用換寬頻也能開 | 多一層轉發，延遲與穩定性取決於穿透服務 |

:::warn 先確認你有沒有公網 IPv4
IPv4 位址稀缺，**很多家庭寬頻拿到的是運營商大內網位址**，此時無論怎麼配路由器埠對映都沒用。判斷方法：路由器 WAN 口 IP 與"我的公網 IP"查詢結果**不一致**，就說明沒有公網 IPv4。

沒有公網時的選擇：向運營商申請（部分地區免費、部分收費、部分不給）、改用雲伺服器、或用內網穿透。
:::

## 二、雲伺服器路線

1. **買機器**：按「開服協議與配置推薦」選，重點看**單核頻率**；系統選 Ubuntu / Debian 的 Server 版。
2. **裝環境**：按「環境準備（Windows 與 Linux）」裝對應版本 Java、建專用使用者、建目錄。
3. **放行埠**：安全組放行 `TCP 25565`，系統防火牆（ufw / firewalld）也要放行，**兩處都要**。
4. **上傳服務端**：用 SFTP 或 `scp` 把整個服務端目錄傳上去。
5. **啟動並常駐**：用 systemd 託管，做到開機自啟、崩潰重啟（見「環境準備」第五步）。
6. **驗證**：從**另一台機器**連 `你的公网IP:25565`。

## 三、自家電腦路線

1. **申請/確認公網 IPv4**（見上）。
2. **路由器埠對映**：把外網 `25565` 轉發到內網那台機器的 `25565`（TCP）。
3. **固定內網 IP**：給這台機器在路由器裡繫結靜態 IP，避免重啟後 IP 變了對映失效。
4. **系統防火牆**放行 `25565`。
5. **保證不掉線**：電源選項設為**從不睡眠**，並考慮斷電與斷網風險。

## 四、內網穿透路線（frp）

原理：你在**有公網 IP 的機器**（frps 服務端）上開一個埠，把流量轉發回你家內網機器（frpc 客戶端）。常見做法是租一台最便宜的雲伺服器當 frps。

```ini
# frps.ini（放在有公網的伺服器上）
[common]
bind_port = 7000
```

```ini
# frpc.ini（放在你家內網機器上）
[common]
server_addr = 你的公網伺服器IP
server_port = 7000

[minecraft]
type = tcp
local_ip = 127.0.0.1
local_port = 25565
remote_port = 25565
```

啟動順序：先跑 `frps`，再跑 `frpc`，之後玩家連**公網伺服器的 IP:25565** 即可。

:::tip 也可以用現成的穿透服務
不想自己維護節點，可以用商用的內網穿透服務，省事但通常有流量/頻寬限制，且**品質參差**——選擇時先看是否支援 **TCP**（UDP 通常要額外付費，基岩版或跨端才需要）。
:::

## 五、網域（可選但推薦）

有網域後玩家不用記 IP：

- **A 記錄**：`mc.your-domain.com` → 伺服器公網 IPv4。
- **SRV 記錄**：想省掉玩家輸入埠，可用 SRV 把 `_minecraft._tcp` 指向你的實際埠。這樣玩家只填網域就能進。

注意：**國內伺服器解析網域通常需要備案**，海外伺服器則不需要。

## DNS 與 SRV 記錄

上一節說到「有網域後玩家不用記 IP」，真正落地靠的是 DNS 記錄。這一節把開服會用到的記錄類型、SRV 的準確寫法和排查方法一次講清楚。

### 開服會用到的幾種記錄

| 記錄類型 | 作用 | 例子 | 注意事項 |
| --- | --- | --- | --- |
| `A` | 網域 → IPv4 位址 | `mc.example.com` → `203.0.113.10` | 最基礎的一條；同一個名字可以有多條 A 記錄 |
| `AAAA` | 網域 → IPv6 位址 | `mc.example.com` → `2001:db8::10` | 伺服器有 IPv6 時才需要；玩家用 IPv6 連不上先查這裡 |
| `CNAME` | 別名，指向另一個網域 | `mc.example.com` → `node1.example.net` | **同一個名字上不能與其他記錄共存**：有了 CNAME 就不能再有 A / AAAA / TXT 等；根網域通常也不允許 |
| `SRV` | 聲明某項服務在哪個主機、哪個埠 | `_minecraft._tcp.example.com` | Java 版專用，見下文 |
| `TXT` | 文本記錄，常用於驗證與聲明 | `_acme-challenge.example.com` 的驗證值 | 網域所有權驗證、郵件配置常用；對開服本身不直接影響 |

**TTL** 是每條記錄的快取時間，單位秒，決定「改完記錄之後全世界要多久才看到新值」。日常可以設大一些（如 `3600`）；**計劃遷移前先把 TTL 調小**（如 `300`），等舊 TTL 過期後再切換，出問題時才能快速切回。遷移的完整流程見 [伺服器遷移](/tutorials/ops/server-migration)。

### SRV 記錄是幹什麼的

Minecraft 的預設埠是 `25565`。如果服務跑在別的埠，或者根本在另一台機器上，玩家就得輸入 `mc.example.com:25566` 這種帶埠的位址。**SRV 記錄就是用來省掉埠的**：它告訴客戶端「這個網域對應的 Minecraft 服務其實在哪個主機、哪個埠」，玩家只填網域就能進。

Java 版的 SRV 查詢名稱是固定的 `_minecraft._tcp.<your-domain>`。寫在區域檔案裡長這樣：

```dns
; 玩家輸入 mc.example.com，服務實際跑在 node1.example.com 的 25566 埠
_minecraft._tcp.example.com.  3600  IN  SRV  10 5 25566 node1.example.com.
node1.example.com.            3600  IN  A    203.0.113.10
```

四個數值欄位的含義：

| 欄位 | 示例 | 含義 |
| --- | --- | --- |
| `priority` | `10` | 優先順序，**數值最小者優先**；只有優先順序相同的記錄之間才會互相分擔 |
| `weight` | `5` | 權重，僅在優先順序相同時生效，按比例分配，數值越大被選中的機率越高 |
| `port` | `25566` | **服務真正監聽的埠**，不是 25565 |
| `target` | `node1.example.com.` | 服務真正所在的主機名，它**必須自己能被解析** |

關於 `target` 有兩條硬性要求：它必須是主機名，且通常應指向一條 `A` / `AAAA` 記錄；不要讓它指向一條 CNAME，更不要讓 CNAME 再指向 CNAME。

:::warn target 不能寫成 IP 字面量
把 `target` 填成 IP（例如 `SRV 10 5 25566 203.0.113.10.`）在協議上是**無效**的，客戶端不會使用這條記錄，即使某些面板允許你把它填進去。正確做法是給目標主機建一條 `A` / `AAAA` 記錄，再讓 `target` 指向那個主機名。
:::

:::warn 最常見的錯誤：target 末尾漏了點
在多數 DNS 服務商的控制台裡，`target` 必須寫成**帶末尾點**的完整網域（`node1.example.com.`）。漏掉這個點，控制台會把它當成「相對於當前區域」的名字，於是變成 `node1.example.com.example.com.`——記錄等於白寫，而且**不會有任何報錯**。
:::

### 基岩版不支援 SRV

這一點必須說清楚：

- **Java 版客戶端會查詢 `_minecraft._tcp` 的 SRV 記錄**，所以 Java 玩家只填網域就能進。
- **基岩版客戶端不使用 SRV 記錄**。基岩版玩家必須輸入 `主机:端口`（例如 `mc.example.com:19132`），或者用一個直接解析到正確位址、埠也一致的網域。

所以 SRV 是 **Java 版專屬的便利**。伺服器同時服務兩個版本時，別指望一條 SRV 解決所有玩家——基岩版那邊該寫埠還是要寫。

### 怎麼驗證記錄真的生效了

```bash
# 查 SRV 記錄（Linux / macOS）
dig +short SRV _minecraft._tcp.example.com

# 查 SRV 記錄（Windows 或沒裝 dig 的機器）
nslookup -type=SRV _minecraft._tcp.example.com

# 查 A 記錄
dig +short A example.com
```

- `dig +short SRV` 正常會返回 `10 5 25566 node1.example.com.` 這樣的四段內容；返回空說明記錄沒生效、名字寫錯，或者你查的不是權威伺服器。
- 再用 `dig +short A node1.example.com` 確認 **target 本身能解析**——這一步最容易被漏掉。
- 最後做**客戶端實測**：在遊戲裡新增伺服器，只填網域，看客戶端能不能自己補上埠並連上。

DNS 修改不是立刻生效的，要等舊 TTL 過期。排查時可以先用 `dig @ns1.example.com ...` 直接問權威伺服器，確認記錄已經寫對，再等快取過期。**SRV 寫錯最陰的地方在於「不報錯」**：客戶端只會表現為連不上，而不會提示你 SRV 有問題。

### 常見故障對照表

| 現象 | 原因 | 檢查方法 |
| --- | --- | --- |
| 用 IP 能連，用網域連不上 | SRV 的 `target` 解析不了，或 `port` 填錯 | `dig +short SRV _minecraft._tcp.your-domain`，再 `dig +short A` 查 target |
| 能連上，但進的是另一個伺服器 | 記錄是舊的，或改完還沒等 TTL 過期 | 對比 `dig` 結果與實際 IP / 埠；必要時先降 TTL 再改 |
| 基岩版玩家用短位址進不來 | 基岩版不支援 SRV | 讓玩家改填 `主机:端口`，或另備一條直連網域 |
| 記錄加了但毫無變化 | TTL 還沒過期，或改錯了區域（比如改的是 `example.com`，玩家查的卻是 `mc.example.com`） | 直接查權威伺服器；確認記錄加在正確的 zone 下 |
| 網域解析正常但連不上 | DNS 沒問題，是防火牆或安全組沒放行 | 從外部機器用 `telnet <domain> <port>` 或 `nc -vz <domain> <port>` 測試 |

### 代理與面板的額外記錄

- 前面掛了 **Velocity / BungeeCord 代理**時，SRV 的 `target` 應該指向**代理**的位址，`port` 填代理的監聽埠，而不是某個後端子服。
- 用了**面板**（MCSManager、Pterodactyl 等）時，面板的訪問位址是另一回事：它通常需要獨立的子網域（如 `panel.example.com`）配合反向代理，**與遊戲用的 SRV 記錄互不影響**，不要混在同一條記錄裡。
- 部分服務商或機房還會要求額外的驗證記錄（`TXT`、`CNAME`），按他們給的說明加即可。

## 六、上線前的安全檢查清單

- [ ] `online-mode` 保持 `true`（除非明確知道風險）
- [ ] 控制台/RCON 埠（如 `25575`）**絕不暴露到公網**
- [ ] Linux 下**不要用 root 跑服務端**，用專用使用者
- [ ] 已配置白名單或進服審核（公開前先小範圍測試）
- [ ] 已開啟**自動備份**（見「備份與恢復」）
- [ ] 已裝**防破壞/記錄類插件**（見「插件」與「反作弊」）
- [ ] 已用外部機器驗證過埠可達
