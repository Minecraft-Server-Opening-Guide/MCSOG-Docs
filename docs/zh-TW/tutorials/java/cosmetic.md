前面幾篇講的是"伺服器能不能跑起來"和"能不能防住破壞"。這一篇講的是另一類插件：它們不改玩法規則，但直接決定玩家**看到的介面**——聊天框、箱子選單、伺服器列表裡的那兩行字，以及主城上空飄著的浮空字。

這類插件裝錯了通常不會崩服，只是"看起來不對勁"，所以最容易被忽視。但它們恰好是玩家進入伺服器後最先接觸的東西。

## 一、聊天插件：不只是好看

聊天插件的作用是**接管玩家發出的聊天資訊**，再按規則重新組裝後廣播出去。

最直觀的能力是格式：給訊息加上字首、字尾、稱號，或者把純文本換成帶顏色的內容。但真正讓聊天插件成為**管理工具**的，是下面這幾類功能：

| 能力 | 解決什麼問題 |
| --- | --- |
| 多頻道 | 常規、全域、私聊、管理頻道分開；管理員說話可以和普通玩家區分 |
| 敏感詞過濾 | 自動攔截髒話與廣告，**不限於聊天**，木牌、鐵砧命名等輸入口一併覆蓋 |
| 聊天冷卻 | 限制發言間隔，防刷屏 |
| 提及提醒（@） | 玩家被點名時用音效、標題提醒，避免漏看 |
| 私聊監聽 | 管理員可切換監聽模式，排查私聊中的騷擾與交易糾紛 |
| 顏色權限 | 誰能用哪種顏色程式碼由權限控制，而不是人人可用的"彩虹刷屏" |
| 物品展示 | 在聊天裡展示手中物品、背包甚至末影箱，交易和求助時省掉大量描述 |
| 變數支援 | 接入 PlaceholderAPI 後，聊天裡可顯示餘額、線上人數等即時資料 |

**聊天插件是伺服器裡最便宜的審核手段**。沒有它，你只能靠人盯著螢幕；有了它，規則由配置執行。

### 常見聊天插件對比

| 插件 | 定位 | 值得注意的地方 |
| --- | --- | --- |
| **TrChat** | 功能最全的高階聊天系統 | 多頻道、雲端敏感詞庫、物品展示、@ 提及、跨服（Bukkit / BungeeCord / Velocity）、正則替換、PlaceholderAPI；版本覆蓋 1.8 到最新 |
| **Carbon** | 設計現代的聊天插件 | 結構清晰、可擴充性好，適合想要"乾淨實現"而不是"功能堆疊"的場景 |
| **InteractiveChat** | 聊天**增強**，通常配合別的格式插件使用 | 核心是互動：`[item]`、`[inv]`、`[ender]` 等關鍵詞、自定義懸停與點選、玩家名互動、跨服提醒、RGB 顏色 |
| **HuskChat** | 跨服聊天 | 已停止開發，新專案不建議作為首選 |
:::tip 先想清楚要什麼
如果你只是想讓聊天"有字首、有顏色"，其實**基礎插件**（EssentialsX / CMI 一類）就能做到，不必額外裝聊天插件。真正需要獨立聊天插件的是這三種需求：**多頻道**、**內容過濾**、**跨服**。
:::
:::warn 前置別忘了
聊天插件幾乎都會用到變數。要在格式裡寫"餘額""線上人數"這類內容，先裝 **PlaceholderAPI** 並安裝對應擴充，否則佔位符會原樣顯示成一段文字。詳見 [插件前置與依賴](/tutorials/java/plugin-deps)。
:::

## 二、選單插件：把指令變成箱子介面

選單插件（也叫 GUI 選單、箱子選單）做的事情是：**用設定檔描述一個箱子介面**，裡面的每個格子是一個圖示，點一下執行一條動作。

它解決的問題很實際——玩家記不住指令。與其讓新人背 `/warp shop`、`/kit starter`，不如給他一個箱子，點圖示就行。

典型用途：

- **伺服器導航**：主選單點進商店、傳送、活動、規則
- **商店與兌換**：以物易物、扣錢發貨、限購
- **禮包與簽到**：按權限或冷卻發放物品
- **玩家資訊面板**：顯示自己的統計、餘額、稱號

### 選單插件對比

NitWikit 把選單插件按功能強弱排成一條線：**ChestCommands < DeluxeMenus < TrMenu**。

| 插件 | 強度 | 說明 |
| --- | --- | --- |
| **ChestCommands** | 入門級 | 年代很早，基本只適合 1.7 / 1.8 的老服務端；在高版本上功能明顯不夠用 |
| **DeluxeMenus** | 主力級 | 配置驅動、文件完善，絕大多數伺服器的"夠用"選擇 |
| **TrMenu** | 高階 | 功能與效能都很強，支援條件判斷、子圖示、Kether 腳本；v2 已停更，**用社群維護的 v3** |
| **Invero** | 視覺向 | 提供滾動視窗、逐幀動畫、互動槽等效果，適合做"看起來不像原版箱子"的介面 |
:::note 關於視覺化編輯器
選單插件**沒有**視覺化編輯器，也不需要。用文字編輯器照著文件寫設定檔就行。所謂"選單編輯器"要麼是生成 YAML 的輔助工具，要麼會給你埋下看不懂的配置。
:::
:::tip 選單插件依賴變數與權限
選單裡的"顯示餘額""僅 VIP 可見"這類效果，靠的是 **PlaceholderAPI** 和權限插件。裝選單插件前先把這兩個基礎打好，否則選單能開啟但內容全是死的。
:::

## 三、MOTD：伺服器列表裡的第一印象

玩家還沒進服，先看到的是**多人遊戲列表**裡你伺服器的那一條：圖示、名稱、兩行描述文字、線上人數。這幾樣合起來就是 **MOTD**。

原版 `server.properties` 只能寫兩行純文本，顏色也受限。MOTD 插件補上的正是這部分：

- **漸變與彩色文字**，以及粗體、斜體等樣式
- **多行內容**與自動輪換
- **隨機輪換**：每次重新整理列表顯示不同的一條 MOTD，用來輪流展示公告
- **偽造線上人數**：讓列表裡的數字顯示成別的值
- **按條件顯示**：不同玩家、不同狀態看到不同內容

| 插件 | 說明 |
| --- | --- |
| **MiniMOTD** | 支援範圍廣的 MOTD 插件，Bukkit / Spigot / Paper 系與代理端都能用，隨機輪換是它的常見用法 |
:::warn 不要只改名稱
MOTD 是**玩家判斷"這個服還活著嗎"的最快依據**。兩行空著、寫著"未命名伺服器"、或者人數顯示為 0 的服，即使內容做得再好，也很少有人點進去。花十分鐘寫一條清楚的 MOTD（**伺服器類型 + 特色 + 聯絡方式**）是價效比最高的改動之一。
:::

## 四、全息圖：可選的點綴

全息圖（浮空字）指的是固定在某個位置、始終朝向玩家的懸浮文本，也可以包含展示用的實體和物品。

它屬於**錦上添花**的一類，常見用法：

- 主城出生點的歡迎語與規則摘要
- 商店招牌上直接標價，省掉一個告示牌
- 排行榜、活動倒計時
- 傳送點與地標的標註

| 插件 | 說明 |
| --- | --- |
| **DecentHolograms** | 輕量但功能完整，設定項多，另有傷害顯示、回血顯示等可選特性；**當前首選** |
| **HolographicDisplays** | 老牌全息圖插件，倉庫已歸檔、不再有新提交；舊服可能還在用，新專案建議直接選 DecentHolograms |
:::note 有些限制來自遊戲本身
全息圖的幾個"毛病"不是插件的問題，而是 Minecraft 的限制：文本**始終朝向玩家**，無法單獨調整字號與字型；部分實體（例如浮空物品圖示）會自行旋轉與上下浮動，還會發出聲音。插件層面解決不了，只能用資源包做自定義字型等繞行方案。
:::

## 五、裝之前先排個順序

這幾類插件之間有依賴關係，建議按下面的順序裝：

1. **前置**：PlaceholderAPI、權限插件、經濟插件（見 [插件前置與依賴](/tutorials/java/plugin-deps)）
2. **基礎插件**：提供 warp、kit 這些被選單呼叫的指令
3. **聊天插件**：確定聊天格式，並留出變數位置
4. **選單插件**：把指令包裝成介面
5. **MOTD 插件**：最後調整對外展示
6. **全息圖**：等世界和商店位置定下來再做，否則改一次搬一次
:::tip 一次只裝一個
這類插件都會改玩家可見的文本。同時裝三個再除錯，你分不清是哪個插件在輸出。裝一個、重啟、看效果，再裝下一個。
:::
