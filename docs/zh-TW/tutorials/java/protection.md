伺服器一旦對公眾開放，幾乎必然會遇到同一類麻煩：**有人拆別人的建築、有人翻別人的箱子、有人守在出生點追殺新人**。這些事靠事後講道理很難收場，需要在規則和技術兩個層面同時設防。本文只講技術層面的**領地與保護**。

## 1. 為什麼需要領地保護

公開服裡最常見的問題可以歸成三類：

| 問題類型 | 典型表現 | 保護插件的作用 | 記錄插件的作用 |
| --- | --- | --- | --- |
| 破壞 | 拆建築、燒森林、倒岩漿、剷平別人的農田 | 攔住非成員對方塊的改動 | 查出是誰做的、把區域回滾 |
| 偷竊 | 翻箱子、拿熔爐和漏斗裡的物品、牽走牲畜 | 禁止非成員開啟容器與取用實體 | 查容器的存取記錄 |
| 糾紛 | 搶怪、堵門、在別人家門口 PvP | 在區域內停用 PvP 與部分互動 | 還原現場，作為處罰依據 |
:::note 保護是預防，記錄是追溯
兩者解決的不是同一個問題。保護插件負責**讓破壞根本發生不了**，記錄插件負責**事後查清並恢復**。真正穩妥的伺服器兩樣都會裝，原因見第 5 節。
:::

## 2. 兩條路線：玩家自助圈地與管理端劃區

領地類插件可以分成思路完全不同的兩類。先分清這個，後面選插件才不會亂：

| | 玩家自助圈地 | 管理端區域保護 |
| --- | --- | --- |
| 誰劃線 | **玩家自己**，用指令或工具圈 | **管理員**，用選區工具劃 |
| 典型插件 | Residence、Dominion、GriefDefender | WorldGuard |
| 玩家要學指令嗎 | 要，而且要理解圈地規則 | 基本不用 |
| 保護粒度 | 按玩家、按領地 | 按區域、按世界 |
| 適合的場景 | 生存服、允許自由建家的服 | 出生點、商店、活動場地、公共設施 |
| 管理成本 | 低，玩家自己管自己 | 高，每個區域都要管理員維護 |

**自助圈地是給每個玩家一把鎖，管理端劃區是給公共區域裝圍欄**。兩者並不衝突，規模大一點的伺服器通常同時使用。

## 3. 玩家自助領地插件

### Residence

老牌領地插件，開發歷史超過十三年，最初由 bekvon 維護，後來由 Zrips 團隊接手，並轉為**開源付費**的運營模式。

- **前置**：需要 CMIlib 才能執行。
- **版本**：支援 1.8 以上的服務端，覆蓋面很廣。
- **安全**：為避免被已知漏洞利用，**不要使用 5.1.4.2 以下的版本**。
- 免費版本仍可從 SpigotMC 或 Zrips 官網獲取。

它最大的優勢是**知名度**：大量伺服器用過，玩家對它的指令邏輯比較熟悉，老玩家上手成本低；生態相容性也經過長期驗證，與其他插件衝突的機率相對小。

### Dominion

由國內開發者開發的**完全開源、免費**的領地插件，從一開始就面向高版本設計。

- **版本要求**：僅支援 1.20.1 及以上（Bukkit / Spigot / Paper / Folia），**1.20 以下的服務端用不了**。
- **執行環境**：需要 Java 21。
- 雖然相容 Spigot，但作者強烈建議使用 Paper 或其分支核心（如 Purpur）以獲得更好的效能體驗。
- 支援匯入 Residence 的絕大部分資料，遷移成本較低。
- 專案目前仍標記為 beta，因此版本更新非常頻繁：好處是問題修得快，代價是升級節奏也快。

### GriefDefender

同樣是一款領地保護插件，提供英文與中文文件。需要注意的是，它的**開原始碼停留在 2021 年**，此後沒有繼續公開，長期維護狀態需要自行評估。

## 4. 管理端區域保護：WorldGuard

WorldGuard 的定位與上面三個不同：它不面向玩家自助圈地，而是讓**管理員劃定區域並設定規則**。

- **前置**：必須安裝 WorldEdit 或 FastAsyncWorldEdit。
- **預設狀態**：所有功能預設關閉，只啟用你真正需要的那部分。

它能做的事大致分成兩類。

**區域保護**

- 阻止玩家在指定區域內放置與破壞方塊；
- 只允許特定的人在某個區域內建造；
- 在區域內停用 PvP、TNT、怪物傷害等功能。

**世界規則調整**

- 阻止爬行者與凋靈造成的方塊破壞，以及墜落傷害等；
- 關閉火焰蔓延、岩漿引燃、結冰、末影人搬走方塊等機制；
- 把某些物品或方塊加入黑名單，使其無法使用；
- 在使用特定物品或方塊時向管理員發出警告；
- 防範一些利用遊戲機制的刷物品漏洞；
- 提供"立即停止所有火焰蔓延"一類的實用管理指令。

WorldGuard 是**運營方的工具**，不是玩家的工具。它適合用在出生點、商店街、活動場地，以及需要統一規則的世界，例如資源世界禁止 PvP、禁止放置方塊。

## 5. 領地與記錄回溯插件的關係

不少人以為裝了領地插件就不用管記錄了，這是個常見誤解：

- **領地只保護被圈起來的地方**。荒野、公共區域、還沒圈地的空地都沒有保護。
- **領地保護不了內部作案**。如果玩家把權限給了不靠譜的隊友，或者把領地共享出去，插件不會阻止對方搬空箱子。
- **領地插件通常不提供回滾**。它攔得住的行為攔住了，沒攔住的（爆炸、領地外的破壞、權限誤配）依然需要記錄插件來恢復。

所以標準組合是：**領地插件負責預防，CoreProtect 一類的記錄插件負責追溯與回滾**。兩者的分工與配置細節見 [反作弊與防破壞](/tutorials/java/anticheat)。
:::warn 記錄插件要早裝
它只能記錄**安裝之後**發生的事。等被破壞了才裝，之前的記錄一概沒有。
:::

## 6. 對比表

| 插件 | 誰圈地 | 上手難度 | 版本要求 | 典型用途 |
| --- | --- | --- | --- | --- |
| **Residence** | 玩家自助 | 低，老牌且教學多 | 1.8+ | 生存服自由建家；玩家基數大的老服 |
| **Dominion** | 玩家自助 | 低到中 | 1.20.1+，需 Java 21 | 新開的高版本生存服，希望用開源方案 |
| **GriefDefender** | 玩家自助 | 中 | 視版本而定 | 需要較細權限分級的領地管理 |
| **WorldGuard** | 管理員 | 中到高，要學選區與 flag | 跟隨 WorldEdit / FAWE | 出生點、商店、活動場地、世界級規則 |

## 7. 怎麼選

可以按下面的順序判斷：

1. **服務端版本在 1.20.1 以上嗎？**
   - 是：Residence 與 Dominion 都可以考慮。想要開源、更新活躍就選 Dominion；想要玩家熟悉、相容性穩妥就選 Residence。
   - 否：Dominion 直接排除，在 Residence 與 GriefDefender 之間挑。
2. **玩家以老玩家為主還是新人為主？**
   - 老玩家多：Residence 的既有認知能省下大量答疑成本。
   - 全新玩家群體：Dominion 的指令設計更貼近高版本的使用習慣。
3. **需要給公共區域定規則嗎？**
   - 需要：無論選了哪個領地插件，都再裝一個 WorldGuard。
4. **有跨版本或特殊核心需求嗎？**
   - 有：優先選相容面更廣、資料更全的方案，並先在測試服驗證。
:::tip 不要同時裝兩個自助領地插件
Residence、Dominion、GriefDefender 解決的是同一個問題。同時裝兩個，玩家會不知道該用哪個，兩個插件的選區邏輯還容易互相干擾。**選一個就好**；WorldGuard 屬於另一層，可以和它們並存。
:::

## 8. 落地時的常見坑

- **圈地額度沒限制**：給玩家的領地大小與數量要配好，否則一個人能把出生點周圍全圈走。多數插件支援按權限組給不同額度。
- **權限節點沒配**：領地插件的指令都要權限節點控制。沒配好，要麼玩家用不了，要麼人人都是管理員。
- **領地重疊與相鄰**：先確認插件對重疊、緊貼的領地如何處理，並把結論寫進伺服器規則。
- **領地傳送被濫用**：領地傳送是常見功能，但要限制頻率與冷卻，防止被當成免費的跨圖交通。
- **只在主世界生效**：很多領地插件的保護是按世界配置的。開了多世界之後，記得檢查資源世界、創造世界是否也有保護，或者是否**故意**不設保護——資源世界通常就是讓人隨便挖的。
