**備份是開服裡唯一不能省的事。** 硬體會壞、服務商會跑路、玩家會破壞、插件會寫壞存檔——真出事了，別的都能重來，存檔沒了就是真的沒了。

## 一、要備份什麼

| 必要性 | 內容 |
| --- | --- |
| 必須 | `world/`、`world_nether/`、`world_the_end/`（**存檔本體，最重要**） |
| 必須 | `plugins/`（插件本體與配置）、`mods/`（模組端） |
| 必須 | `server.properties`、`ops.json`、`whitelist.json`、`banned-*.json` |
| 必須 | 核心自己的配置（`bukkit.yml` / `spigot.yml` / `paper-*.yml` / 對應核心的 yml） |
| 可選 | `logs/`、`crash-reports/`（可選，排查問題有用） |
| 不必 | `libraries/`、`versions/`、`cache/`（可自動重建，不用備） |

## 二、最重要的原則：備份要"一致"

**不要在伺服器正在寫存檔時直接複製**——可能拷到寫了一半的區塊檔案，恢復後存檔損壞。

正確姿勢（兩種）：

**方式 A：熱備份（不停服）**

```
save-all        先把資料刷到磁碟
save-off        關閉自動儲存（避免備份過程中繼續寫入）
（此時執行復制/打包）
save-on         備份完恢復自動儲存
```

**方式 B：停服備份（最穩）**

```
stop            安全關服
（復制/打包整個目錄）
（重新啟動）
```

:::tip 定時備份腳本建議用方式 A
配合定時任務，在低峰期執行"`save-all` → `save-off` → 打包 → `save-on`"，玩家幾乎無感。
:::

## 三、自動化

**Linux（cron）**：寫一個備份腳本（打包 + 按日期命名 + 清理舊包），用 `crontab -e` 定時執行。

**Windows（任務計劃程式）**：把啟動腳本改造成"備份腳本"，在任務計劃裡設定每天固定時間執行。

**插件方案**：也有專門的備份插件，能按間隔自動備份並保留若干份歷史，省去自己寫腳本。**注意**：插件備份同樣要保證一致性，且**備份檔案別放在同一塊盤上**。

## 四、保留策略

- **多留幾個版本**：只留最新一份，遇到"存檔已經壞了但還沒發現"時就沒救了。建議保留**若干天每日 + 若干週每週**。
- **注意磁碟**：世界檔案會持續增長，**定期清理舊備份**，別把盤寫滿（盤滿會導致服務端寫存檔失敗，後果嚴重）。
- **異地一份**：本機磁碟壞了，本地備份也一起沒了。

:::warn 服務商會跑路，機房會出事
把全部資料只放在一台你租來的機器上，是把命交給別人。**至少定期把備份下載到自己的電腦或另一處儲存**。
:::

## 五、恢復（回檔）流程

1. **停服**（務必先 `stop`）。
2. **把當前存檔改名留底**（例如 `world_broken_20261004`），**不要直接刪**——萬一新備份也有問題還能回退。
3. 解壓備份，把 `world*` 放回服務端目錄。
4. 啟動服務端，檢查日誌有無存檔相關報錯。
5. 讓玩家確認關鍵建築與物品是否正常。

## 六、最後一個提醒

> **沒有驗證過恢復的備份，不算備份。**

定期（比如每月一次）拿一份備份**在測試環境裡真的恢復一遍**。很多人是在真出事那天才發現：備份腳本早就因為權限/路徑問題失敗了，或者打包出來的檔案是空的。
