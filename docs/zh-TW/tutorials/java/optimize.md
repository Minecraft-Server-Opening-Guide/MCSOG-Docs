"伺服器卡"是最常見的問題，但**最佳化是有優先順序的**。按下面的順序做，價效比最高；順序反了，容易花大力氣收效甚微。

## 一、優先順序順序

```
1. 硬件（单核性能）        ← 收益最大，花钱也最多
2. 服务端配置（视距/模拟距离）  ← 几乎免费，立竿见影
3. 核心选择（Paper 系 vs 原版）
4. 插件/模组质量（劣质插件是重灾区）
5. JVM 参数
```

**先說結論**：如果你的機器單核很弱，**換配置和調參數都救不回來**，因為主執行緒只有一個。

## 二、配置最佳化（價效比最高）

### 視距與模擬距離

| 選項 | 影響 |
| --- | --- |
| `view-distance` | 玩家能看多遠。調低省 CPU 與頻寬，代價是遠處發霧 |
| `simulation-distance` | 多遠的區塊還在**真實運算**（刷怪、紅石、作物）。**調低它比調低視距省得多，且不影響觀感** |

對多數小服，把 `simulation-distance` 從 10 降到 6 左右就能明顯緩解卡頓。

### Spigot 層的實體控制

`spigot.yml` 裡有幾組與實體相關的關鍵項（不同版本名稱略有差異）：

- **實體啟用範圍**：控制生物在多遠才被 tick，調小能省大量 CPU。
- **刷怪範圍**：控制刷怪的距離。
- **實體/物品合併半徑**：調大能減少實體數量（如掉落物、經驗球），**但會改變原版行為**（生電慎用）。
- **每 tick 最大實體 tick 數**：給實體運算設上限，防止爆量卡服。

### Paper 層的世界配置

`config/paper-world-defaults.yml` 裡可調：實體碰撞上限、自動儲存的區塊數、區塊解除安裝延遲等。

:::warn 最佳化與"原版行為"是此消彼長的
上面很多開關**預設值就是被最佳化過的**，調得越激進，離原版越遠。**生電服請反過來——把影響原版行為的項調回原版**（見「生電與紅石」）。
:::

## 三、先找到"卡在哪"，再動手

**不要憑感覺最佳化**。先測量：

| 工具 | 用途 |
| --- | --- |
| **spark** | 目前最主流的效能分析插件/命令，能生成火焰圖，直接指出哪個插件/實體/區塊在吃 CPU |
| `/tps` 類命令 | 看當前 TPS（低於 20 就是掉刻了） |
| **timings**（舊版 Paper） | 老版本上的效能報告 |

用 spark 跑一段時間的取樣，**看火焰圖裡最寬的那條**，再針對性處理。常見元兇：

- 某個劣質插件在迴圈裡做重活；
- 大量實體堆積（刷怪塔沒做好收集、掉落物沒清理）；
- 漏斗/紅石裝置過多（漏斗是經典的效能殺手）；
- 玩家跑圖導致大量新區塊生成（見下）。

## 四、世界預生成

**玩家邊跑圖邊生成新區塊**是卡頓的重要來源：新區塊生成是 CPU 密集操作，會讓 TPS 瞬間掉下去。

解決辦法是**預生成**：用 `Chunky` 一類插件提前把一定範圍的地圖生成好。玩家再到那片區域時，只是載入已有區塊，不觸發生成。

對**長期開放的生存服**，預生成幾乎是必做項。

## 五、JVM 參數

- **記憶體**：`-Xmx` 給足但別過量（過大反而讓 GC 停頓變長）。專用機器上可讓 `-Xms` 與 `-Xmx` 相等，減少堆伸縮。
- **GC 參數**：社群有成熟的推薦組合（如 **Aikar's Flags**），在 Paper 官方文件裡有專門的啟動參數生成工具與說明。**不要盲目抄網上互相矛盾的"玄學參數"**。
- 參數只在**記憶體/GC 層面**有幫助，**救不了單核瓶頸**。

## 六、其他實用手段

- **定期清理實體**：給掉落物、經驗球設定合理存活時間；有插件可做定時清理。
- **限制 TNT / 高頻紅石**：對公開服，限制爆炸與高頻紅石能顯著減少惡意卡服。
- **限制跑圖**：用世界邊界（world border）約束活動範圍，避免無限生成。
- **定期重啟**：不是"最佳化"，但能清掉部分插件記憶體洩漏，作為**臨時緩解**手段可用（治標不治本）。
- **升級硬體**：如果 spark 顯示 CPU 被主執行緒吃滿且配置已調優，那就是**該換單核更強的機器**了。

## 七、最佳化的底線

```
优化不能以牺牲"原版行为"为代价 —— 除非你明确不需要原版行为
```

對生電服：**寧可卡一點，也要保證機器能工作**。
對普通生存服：**可以適度激進**，優先保證線上體驗。

## 結語

到這裡，Java 版開服的完整鏈路就走完了：

```
协议与配置 → 操作系统 → 环境准备 → 服务端选择 → 开启服务端
   → 服务端结构 → 配置服务端 → 部署 → 常用指令
   → MCDR → 插件 → 生电
   → 经营管理 → 跨服端 → 手机玩家 → 备份 → 反作弊 → 性能优化
```
