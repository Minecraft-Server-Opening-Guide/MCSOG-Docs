官方 **BDS** 是基岩版最穩的選擇，但它**本身不支援插件**。這一篇講清它的目錄結構，以及怎麼用社群載入器補上插件能力。

## 一、目錄結構

BDS 解壓後就是一套"綠色"目錄，認識這幾個就夠：

| 檔案 / 目錄 | 作用 | 能不能動 |
| --- | --- | --- |
| `bedrock_server.exe` | **服務端啟動程式**（Linux 下無 `.exe`） | 可以改名，但**不建議**——改名後啟動腳本/面板裡的啟動路徑都要同步改，容易出錯 |
| `server.properties` | 伺服器配置（埠、難度、模式等） | 常改 |
| `allowlist.json` | **白名單**名單（`server.properties` 裡開白名單後在此管理） | 可改 |
| `permissions.json` | **管理員（OP）**資料（UUID、名稱、權限） | 可改 |
| `valid_known_packs.json` | 已知附加包列表（行為包 / 資源包），伺服器據此校驗 |  一般不用動 |
| `worlds/` | **世界存檔**（每個世界一個子資料夾） | 只整體備份 |
| `bedrock_server.pdb` | 除錯用程式資料庫檔案 | 別動 |
| `bedrock_server_how_to.html` | 官方使用說明 |  可讀 |
| `release-notes.txt` | 版本更新日誌 |  可讀 |

### 世界資料夾裡有什麼

`worlds/<世界名>/` 下：

| 檔案 / 目錄 | 內容 |
| --- | --- |
| `db/` | **存檔資料**（世界的資料庫檔案，體積最大） |
| `level.dat` | 世界基本設定與屬性（遊戲規則、時間、天氣等） |
| `level.dat_old` | 舊版存檔設定（更新或備份時使用） |
| `level_name.txt` | 世界名稱 |

:::warn 備份就備 `worlds/`
BDS 的存檔全在 `worlds/` 裡，**整個目錄一起備份**。別隻拷 `db/`，否則設定會丟。
:::

## 二、給 BDS 加插件：三個主流載入器

官方 BDS 沒有插件系統，社群做了載入器來補。目前主流三個：

### LeviLamina（別名 LLL / LLv3）——**最推薦**

- 作者：LiteLDev（前身就是 **LiteLoaderBDS**）
- 定位：輕量、模組化、多功能的 BDS 插件載入器
- **推薦度：非常推薦** —— 插件生態最好，延續了 LiteLoader 時代的巔峰
- 支援版本：1.20.61 – 1.21.3（保持更新）

### EndStone —— 有潛力

- 作者：EndStoneMC
- 定位：提供**類似 Bukkit 的友好 API**，可用 **C++ 或 Python** 寫插件
- **推薦度：比較推薦** —— 目前插件生態極少，但社群有參與開發的聲音，後續可能追平 LeviLamina
- 支援版本：1.20.71 – 1.21.2（保持更新）

### BDSX —— 老牌穩定

- 定位：支援 **Node.js** 的 BDS 修改版，基於官方 BDS，保留原版全部特性，並支援 Hook 函式與網路資料包
- **推薦度：較為推薦** —— 國內插件不算多，但使用者不少，作者從 2019 年維護至今
- 支援版本：1.12 – 最新（保持更新）

> 除這三個外，官方也提供**腳本載入器**（基於官方腳本 API），能力比第三方載入器弱，但勝在官方支援。

### 怎麼選

| 你的情況 | 建議 |
| --- | --- |
| 想要現成插件、生態優先 | **LeviLamina** |
| 會 C++ / Python，想自己寫 | **EndStone** |
| 熟悉 Node.js / 需要 Hook 底層 | **BDSX** |
| 只想用官方能力、不加第三方 | 官方腳本載入器 |

:::warn 載入器與遊戲版本強繫結
載入器只支援**特定版本區間**。**先確認你的服務端版本在支援列表裡**再裝，否則會載入失敗甚至起不來。升級遊戲版本前也要先確認載入器是否已跟進。
:::

## 三、BDS 的兩個已知坑

1. **單核瓶頸**：生物運算單執行緒 → 流暢度取決於**單核效能**，地圖越大越卡。
2. **記憶體緩慢增長**：佔用會慢慢漲。注意 **不要強行清理記憶體**——會導致玩家下載材質包/Addon 時進度條卡住，**只能重啟服務端**解決。
