تجمع هذه الصفحة ثلاثة أنواع من الأوامر للرجوع إليها: **أوامر خادم إصدار Java**، و**أوامر إصدار Bedrock (BDS ونوى الأطراف الثالثة)**، و**طبقة الإدارة المحيطة بالخادم** (MCDR ووحدة تحكم اللوحة وRCON).

وعمود «الصلاحية» في الجداول يصف **الوضع الأصلي الافتراضي**: في إصدار Java بحسب مستوى OP، وفي إصدار Bedrock بحسب صفة المشغّل ومفتاح «الغش». وبعد تثبيت ملحق صلاحيات (مثل LuckPerms) تحدد عُقد الصلاحيات الصلاحية الفعلية، وقد تكون أوسع من الأصلية أو أضيق.

> توافر الأوامر ومستويات صلاحياتها **يتغير بحسب إصدار اللعبة ونوع النواة**: فالاسم نفسه قد لا يوجد على نواة أخرى، وقد تعيد النواة كتابته. وقبل إصدار أمر، اعتمد الوثائق الرسمية للخادم وإصدار اللعبة اللذين تشغّلهما فعلًا.

:::note احفظ ثلاث جمل أولًا
- **في وحدة التحكم لا يُكتب `/` عادةً**، أما في مربع الدردشة داخل اللعبة فيجب كتابته.
- **صفة وحدة التحكم تعني أعلى صلاحية**، أما داخل اللعبة فالأمر يتوقف على امتلاكك OP أو عقدة الصلاحية المقابلة.
- **إصدار Java وإصدار Bedrock مجموعتا أوامر منفصلتان**: تشابه الأسماء لا يعني تشابه السلوك، و`save-all` لا مقابل له في إصدار Bedrock إطلاقًا.
:::

## 1. قبل قراءة الجداول: ثلاث قواعد

| القاعدة | الشرح |
| --- | --- |
| مرتبطة بالإصدار | تُضاف الأوامر وتُحذف مع الإصدارات (فأوامر جديدة مثل `/tick` لا توجد إلا في إصدارات أحدث)، ولا يلزم أن تظل الصيغة الواردة في الدروس القديمة صالحة |
| مرتبطة بالنواة | أوامر مثل `plugins` و`version` و`tps` و`restart` **ليست أوامر أصلية**، بل تقدمها نوى عائلة Spigot / Paper؛ والخادم الأصلي لا يملكها |
| مرتبطة بالملحقات | بعد تثبيت ملحق صلاحيات يمكن إعادة كتابة عقد الصلاحيات الأصلية؛ وبعد تثبيت ملحق أسماء بديلة قد تُستبدل أسماء الأوامر |

وأسرع طريقة للحكم على وجود أمر ما هي **كتابة `/` داخل اللعبة والنظر إلى قائمة الإكمال التلقائي**، أو كتابة الأحرف الأولى في وحدة التحكم والنظر إلى الإكمال. وما لا يظهر في الإكمال لم تسجّله هذه النواة.

## 2. إصدار Java: دورة الحياة والحفظ

| الأمر | الوظيفة | الصلاحية | ملاحظات |
| --- | --- | --- | --- |
| `stop` | إغلاق الخادم بأمان: يحفظ ثم يخرج | OP 4 / وحدة التحكم | **استخدمه وحده لإغلاق الخادم**، ولا تغلق النافذة أو تقتل العملية مباشرة |
| `save-all` | حفظ كل بيانات العالم فورًا | OP 4 / وحدة التحكم | يمكن إضافة المعامل `flush` لفرض الكتابة على القرص |
| `save-off` | إيقاف الحفظ التلقائي | OP 4 / وحدة التحكم | أوقفه قبل النسخ الاحتياطي لتجنّب نسخ حفظ نصف مكتوب |
| `save-on` | استعادة الحفظ التلقائي | OP 4 / وحدة التحكم | أعده بعد انتهاء النسخ الاحتياطي |
| `reload` | إعادة تحميل البيانات في حزم البيانات المفعّلة | OP 2 (قد يختلف بين الإصدارات) | **ليس إعادة تشغيل، وليس إعادة تحميل إعدادات الخادم**، راجع التحذير أدناه |
| `restart` | إعادة تشغيل الخادم | بحسب النواة | تقدمه عائلة Spigot / Paper؛ ولا يوجد في النسخة الأصلية |

ترتيب إغلاق الخادم القياسي هو `save-all` ثم `save-off` ثم النسخ الاحتياطي ثم `stop`. وإذا كانت العملية قد خرجت بالفعل فلا حاجة إلى `save-on`.

:::warn `/reload` ليست «إعادة تحميل لكل شيء»، وقد تُفسد الملحقات
`/reload` في إصدار Java يعيد تحميل **البيانات الموجودة في حزم البيانات المفعّلة حاليًا** فقط. وهو **لا**:

- يعيد قراءة `server.properties` (فتغيير المنفذ أو الصعوبة يحتاج إعادة تشغيل ليُعمل)؛
- يعيد تشغيل عملية الخادم، ولا يعيد تحميل شيفرة الملحقات؛
- يعيد محتوى تسجيل الملحقات إلى حالة نظيفة.

وفي المقابل **قد** يخلط حالة الملحقات: فلوحات النقاط والمستمعات والذاكرة المؤقتة والأوامر المسجّلة قد تبقى نصف جديدة ونصف قديمة، والعرَض أن «بعض الوظائف تصبح غريبة بعد إعادة التحميل». وما يمكن حله بأمر الملحق الخاص `/اسم-الملحق reload` أو `/datapack enable` أو `/datapack disable` فلا تستخدم معه `/reload` الأصلي؛ وإن كان التغيير كبيرًا أو أثره غير واضح فاختر نافذة صيانة وأعد التشغيل.

والأمر نفسه في إصدار Bedrock أضيق نطاقًا (يعيد تحميل الدوال والنصوص في حزم السلوك)، و`reload` في الإصدارين **ليس** زر «تحديث إعدادات الخادم».
:::

## 3. إصدار Java: اللاعبون والحجب والقائمة البيضاء

| الأمر | الوظيفة | الصلاحية | ملاحظات |
| --- | --- | --- | --- |
| `list` | سرد اللاعبين المتصلين حاليًا | الجميع | الأمر الأكثر استخدامًا لسؤال «هل في الخادم أحد» |
| `kick <玩家> [原因]` | طرد لاعب | OP 3 / وحدة التحكم | المطرود **يستطيع الدخول مجددًا** |
| `ban <玩家> [原因]` | حجب لاعب | OP 3 / وحدة التحكم | لا يدخل ما لم يُرفع الحجب |
| `pardon <玩家>` | رفع الحجب عن لاعب | OP 3 / وحدة التحكم | في الإصدارات القديمة جدًا كان اسمه `unban` |
| `ban-ip <IP>` | الحجب بحسب IP | OP 3 / وحدة التحكم | **كل من على هذا IP لا يدخل**، فاستخدمه بحذر |
| `pardon-ip <IP>` | رفع الحجب عن IP | OP 3 / وحدة التحكم | تأكد قبل الرفع ممن يملك هذا IP الآن |
| `banlist [ips\|players]` | عرض قائمة الحجب | OP 3 / وحدة التحكم | بدون معامل يسرد اللاعبين |
| `op <玩家>` | منح صفة المسؤول | OP 3 / وحدة التحكم | امنحه لمن يحتاجه فقط؛ فمنح OP أخشن بكثير من منح عقدة صلاحية |
| `deop <玩家>` | سحب صفة المسؤول | OP 3 / وحدة التحكم | مع ملحق الصلاحيات قد يتجاوز OP مجموعات الصلاحيات |
| `whitelist on` | تشغيل القائمة البيضاء | OP 3 / وحدة التحكم | أضف نفسك إليها قبل التشغيل |
| `whitelist add <玩家>` | إضافة إلى القائمة البيضاء | OP 3 / وحدة التحكم | يُكتب في `whitelist.json` |
| `whitelist remove <玩家>` | إزالة من القائمة البيضاء | OP 3 / وحدة التحكم | يُرفض اتصال اللاعب في المرة التالية |
| `whitelist list` | عرض القائمة البيضاء | OP 3 / وحدة التحكم | مطابق لمحتوى `whitelist.json` |
| `whitelist reload` | إعادة قراءة القائمة من الملف | OP 3 / وحدة التحكم | **يجب تنفيذه بعد تعديل `whitelist.json` يدويًا** |

ملفات القائمة البيضاء هي `whitelist.json`، وقوائم الحجب وOP في `banned-players.json` و`banned-ips.json` و`ops.json`. والتغيير بالأوامر يُكتب في الملف فورًا؛ والتغيير اليدوي للملف يحتاج reload المقابل أو إعادة تشغيل.

## 4. إصدار Java: العالم والوقت وقواعد اللعبة

| الأمر | الوظيفة | الصلاحية | ملاحظات |
| --- | --- | --- | --- |
| `tp <玩家> <目标>` | نقل لاعب | OP 2 / وحدة التحكم | الصيغة الكاملة `teleport`؛ وعند التنفيذ من وحدة التحكم يُكتب المعاملان معًا |
| `gamemode <模式> [玩家]` | تبديل نمط اللعب | OP 2 / وحدة التحكم | القيم `survival` / `creative` / `adventure` / `spectator` |
| `gamerule <规则> <值>` | تعديل قواعد اللعبة | OP 2 / وحدة التحكم | أسماء القواعد تتغير بين الإصدارات، **تأكد بالإكمال التلقائي** |
| `time set day` | ضبط الوقت | OP 2 / وحدة التحكم | يمكن استخدام `noon` / `night` / `midnight` أو قيمة رقمية |
| `time add <数量>` | تقديم الوقت | OP 2 / وحدة التحكم | أفضل من `set` عند اختبار آلية الليل والنهار |
| `weather clear` | ضبط الطقس | OP 2 / وحدة التحكم | القيم `clear` / `rain` / `thunder`، ويمكن إضافة مدة |
| `difficulty <难度>` | ضبط الصعوبة | OP 2 / وحدة التحكم | القيم `peaceful` / `easy` / `normal` / `hard` |
| `give <玩家> <物品> [数量]` | إعطاء عناصر | OP 2 / وحدة التحكم | معرّف العنصر وصيغة المكوّنات تتغير بين الإصدارات |
| `seed` | عرض بذرة العالم | OP 2 / وحدة التحكم | مرتبطة بالحفظ، وتختلف باختلاف العالم |
| `say <内容>` | بثّ باسم الخادم | OP 2 / وحدة التحكم | يرى اللاعبون رسالة بنمط رسائل الخادم |
| `tell <玩家> <内容>` | محادثة خاصة | الجميع | الأسماء البديلة `msg` / `w` |
| `datapack list` | سرد حزم البيانات | OP 2 / وحدة التحكم | يُستخدم مع `/reload` |

`gamerule` هو الأمر الأكثر عرضة لسوء الاستخدام: **القاعدة نفسها قد تختلف دلالتها بين إصدار Java وإصدار Bedrock، وقد تُعاد تسميتها أو تُقسَّم بين الإصدارات**. تأكد قبل التغيير من وجود القاعدة في قائمة الإكمال، وراقب السجع وملاحظات اللاعبين بعده.

## 5. إصدار Java: الحالة والتشخيص

| الأمر | الوظيفة | الصلاحية | ملاحظات |
| --- | --- | --- | --- |
| `tps` | عرض TPS | OP | **ليس أمرًا أصليًا**: تأتي به نوى Spigot / Paper؛ وعند تثبيت spark قد يتولاه spark |
| `mspt` | عرض زمن التكة | OP | تقدمه نوى Paper؛ وقراءته مع TPS أنفع |
| `spark tps` | عرض TPS عبر spark | OP | شجرة أوامر spark أدق من أوامر النواة المدمجة |
| `spark profiler start` | بدء تحليل الأداء | OP | تُرفع النتيجة افتراضيًا ويُعطى رابط، فانتبه لخطر تسريب البيانات |
| `spark profiler stop` | إنهاء التحليل وعرض النتيجة | OP | لإنهاء دون رفع استخدم `spark profiler cancel` |
| `plugins` | سرد الملحقات | OP / عقدة صلاحية | الاسم البديل `pl`؛ الأخضر محمّل والأحمر فشل تحميله |
| `version <插件>` | عرض إصدار الملحق | OP / عقدة صلاحية | سيسألونك عنه حتمًا عند الإبلاغ عن خطأ |
| `help` | عرض مساعدة الأوامر | الجميع | مقسّمة على صفحات، و`/help <指令>` يعرض أمرًا واحدًا |

الخادم الأصلي **لا يملك** `tps` و`mspt` و`plugins` و`version`. ولمن يريد مراقبة الأداء في النسخة الأصلية فلا سبيل إلا السجلات والأدوات الخارجية، وهذا سبب قول كثيرين «تغيّرت النواة فظهرت أوامر جديدة». وعملية تشخيص الأداء الكاملة في [تحليل أداء الخادم بـ spark](/tutorials/ops/spark).

:::tip عُقد الصلاحيات تغيّر ظهور الأوامر أيضًا
عقد صلاحيات `plugins` و`version` و`help` مفتوحة للجميع افتراضيًا. لإغلاقها اضبط `bukkit.command.plugins` و`bukkit.command.version` و`bukkit.command.help` على `false`. لكن **إغلاق الأمر لا يعني إخفاءه**: فبعض العملاء يستنتجون الملحقات المثبّتة من استجابة الإكمال التلقائي.
:::

## 6. إصدار Bedrock: كيف تبدو هذه الأوامر على BDS

لإصدار Bedrock (BDS ونوى الأطراف الثالثة) مجموعة أوامر خاصة. و**التوافر يتأثر بأمرين معًا**: صفتك كمشغّل، وهل فعّل الخادم الغش أو لا.

| الأمر | الوظيفة | الصلاحية | ملاحظات |
| --- | --- | --- | --- |
| `stop` | إغلاق الخادم بأمان | وحدة التحكم | بالاسم والمعنى نفسه في إصدار Java، وهو الأجدر بالحفظ |
| `save hold` | إيقاف الكتابة والحفاظ على اتساق الملفات | وحدة التحكم | أول خطوة في نسخ Bedrock الاحتياطي |
| `save query` | سرد الملفات التي يجب نسخها الآن | وحدة التحكم | انسخ بحسب القائمة التي يعطيها |
| `save resume` | استعادة الكتابة | وحدة التحكم | يُنفَّذ بعد انتهاء النسخ |
| `whitelist on` / `off` | تشغيل وإيقاف القائمة البيضاء | المشغّل | الملف المقابل `allowlist.json` |
| `whitelist add` / `remove` / `list` / `reload` | صيانة القائمة البيضاء | المشغّل | بعد التعديل اليدوي للملف نفّذ reload |
| `op` / `deop` | منح وسحب صفة المسؤول | المشغّل | النتيجة تُكتب في `permissions.json` |
| `permission list` | عرض الصلاحيات الحالية | المشغّل | تقابل `permissions.json` |
| `permission reload` | إعادة قراءة ملف الصلاحيات | المشغّل | يُنفَّذ بعد التعديل اليدوي لـ `permissions.json` |
| `kick <玩家> [原因]` | طرد لاعب | المشغّل | بالمعنى نفسه في إصدار Java |
| `ban` / `pardon` | حجب ورفع حجب لاعب | المشغّل | الحجب بحسب اللاعب (gamertag / XUID)، **ولا أمر مكافئ للحجب بحسب IP** |
| `tp` / `teleport` | النقل | المشغّل | الصيغة قريبة من إصدار Java دون تطابق تام |
| `gamemode` | تبديل نمط اللعب | المشغّل | القيم مشابهة لإصدار Java |
| `gamerule` | تعديل قواعد اللعبة | المشغّل | مجموعة القواعد **مختلفة** عن إصدار Java، ودلالة الاسم نفسه قد تختلف |
| `time set` / `time add` | ضبط وتقديم الوقت | المشغّل | في Bedrock يمكن أيضًا استخدام أوامر مثل `daylock` لتثبيت الوقت |
| `weather clear` / `rain` / `thunder` | ضبط الطقس | المشغّل | وهناك أيضًا `toggledownfall` |
| `difficulty` | ضبط الصعوبة | المشغّل | بالاسم نفسه في إصدار Java |
| `list` | سرد اللاعبين المتصلين | المشغّل | بعض الإصدارات تتيحه للاعبين العاديين، والإكمال هو المرجع |

وبعض أوامر الجدول **أُضيفت في إصدارات أحدث** (وهذا أوضح في `ban` / `pardon`)، ففي خوادم Bedrock الأقدم قد لا توجد في قائمة الإكمال أصلًا. **والطريقة الوحيدة الموثوقة للحكم على وجود أمر في إصدارك هي الإكمال التلقائي والوثائق الرسمية**، لا نسخ أرقام الإصدارات من مصادر أخرى.

وفي إعدادات BDS بند مرتبط بالأوامر مباشرة: `allow-cheats` في `server.properties`. وعند إغلاقه تُقيَّد الأوامر داخل اللعبة؛ والقيمة الافتراضية بحسب `server.properties` المولَّد عندك، وأي تغيير يحتاج إعادة تشغيل الخادم. **كثير من حالات «لا تعمل الأوامر» في Bedrock سببها مفتاح الغش أو صفة المشغّل، لا كتابة الأمر.**

وعملية النسخ الاحتياطي في Bedrock مختلفة تمامًا عن إصدار Java، ويمكن نسخها مباشرة:

```text
save hold
save query
# 按 query 输出的清单复制文件（worlds/ 要整体拷走）
save resume
```

## 7. أوامر غير موجودة في Bedrock (أو بدلالة مختلفة)

| أمر إصدار Java | الوضع في Bedrock | الشرح |
| --- | --- | --- |
| `save-all` | غير موجود | استخدم `save hold` / `save query` / `save resume` |
| `save-off` / `save-on` | غير موجود | لا وجود لزوج «إيقاف الحفظ التلقائي» في Bedrock |
| `ban-ip` / `pardon-ip` | غير موجود | Bedrock يحجب بحسب اللاعب، ولا أمر للحجب بحسب IP |
| `plugins` / `version <插件>` | غير موجود | نوى Bedrock لا تملك أمرًا موحدًا لقائمة الملحقات، فراقب مخرجات وحدة التحكم |
| `tps` / `mspt` | غير موجود | لا أمر TPS في Bedrock؛ والأداء يُقدَّر من السجلات والمراقبة الخارجية |
| `reload` | موجود لكن **بدلالة مختلفة** | يعيد Bedrock تحميل الدوال والنصوص في حزم السلوك، و**لا يعيد تحميل `server.properties`**، وليس إعادة تشغيل |
| `gamerule` | موجود لكن **مجموعة القواعد مختلفة** | الاسم نفسه قد يختلف معناه بين الإصدارين، ونسخه بين الإصدارات يوقع في الأخطاء |
| `difficulty` / `time` / `weather` | موجود | هذه الأوامر في الإصدارين، وصيغتها متقاربة |

:::warn عبارة «لا يوجد /reload في Bedrock» تحتاج تفصيلًا
ما يقصده المجتمع عادةً بعبارة «لا يوجد `/reload` في Bedrock» هو **عدم وجود reload يعيد تحميل إعدادات الخادم**، وهذا صحيح: فبعد تعديل `server.properties` في Bedrock لا سبيل إلا إعادة تشغيل الخادم (بـ `stop` سليم من وحدة التحكم ثم التشغيل، دون قتل العملية).

لكن Bedrock يملك فعلًا أمرًا اسمه `reload`، ونطاقه الدوال والنصوص في حزم السلوك، و**هو ليس إعادة تحميل حزم البيانات كما في إصدار Java**، ولا يجعل الخادم يعيد قراءة ملف الإعدادات. وفي الإصدارين لا تستخدم `reload` كمفتاح «تحديث لكل شيء»؛ والنطاق والسلوك يتغيران بحسب الإصدار، والمرجع الوثائق الرسمية.
:::

## 8. طبقة الإدارة: أوامر `!!MCDR` الفرعية

MCDReforged (MCDR) مدير **يلتف حول الخادم من الخارج**: يتولى عملية النواة، ويفسّر مخرجات وحدة التحكم، ويقدّم مجموعة أوامر بسابقة `!!`. وهذه الأوامر **ليست أوامر لعبة**، بل يعالجها MCDR نفسه ولا يمررها إلى الخادم.

| الأمر | الوظيفة | الصلاحية | ملاحظات |
| --- | --- | --- | --- |
| `!!MCDR` | الأمر الرئيسي، يسرد الأوامر الفرعية المتاحة | يتحكم بها نظام صلاحيات MCDR | يمكن تغيير السابقة `!!` في الإعدادات |
| `!!MCDR status` | عرض حالة MCDR | صلاحية MCDR | لتشخيص «هل المدير ما زال حيًّا» |
| `!!MCDR reload config` | إعادة تحميل إعدادات MCDR | صلاحية MCDR | له صيغ مختصرة مثل `!!MCDR r cfg` |
| `!!MCDR reload plugin` | إعادة تحميل الملحقات | صلاحية MCDR | منفصل عن إعادة تحميل الإعدادات |
| `!!MCDR reload permission` | إعادة تحميل بيانات الصلاحيات | صلاحية MCDR | بعد تعديل ملف الصلاحيات |
| `!!MCDR reload all` | إعادة تحميل الكل | صلاحية MCDR | استخدمه أولًا عند حدوث مشكلة |
| `!!MCDR plugin list` | سرد الملحقات المحمّلة | صلاحية MCDR | مختلف تمامًا عن `/plugins` في إصدار Java |
| `!!MCDR plugin load <插件>` | تحميل ملحق | صلاحية MCDR | المعامل معرّف الملحق |
| `!!MCDR plugin reload <插件>` | إعادة تحميل ملحق واحد | صلاحية MCDR | أخف من إعادة التشغيل الكاملة |
| `!!MCDR plugin unload <插件>` | إلغاء تحميل ملحق | صلاحية MCDR | إلغاء التحميل لا يعني حذف الملف |
| `!!MCDR plugin install <插件>` | تثبيت ملحق من المستودع الرسمي | صلاحية MCDR | مثال: `!!MCDR plugin install ndpr` |
| `!!MCDR permission list` | عرض الصلاحيات | صلاحية MCDR | بحسب اللاعب ومجموعة الصلاحيات |
| `!!MCDR permission set` | ضبط صلاحية | صلاحية MCDR | الصيغة بحسب الوثائق الرسمية |
| `!!MCDR permission remove` | إزالة صلاحية | صلاحية MCDR | |
| `!!MCDR checkupdate` | التحقق من تحديث MCDR | صلاحية MCDR | فحص التحديث التلقائي يحدده بند إعدادات |

:::warn أوامر MCDR الفرعية تتغير مع الإصدارات
تتغير أوامر MCDR الفرعية وصيغها المختصرة بين الإصدارات (والصيغ المختصرة مثل `!!MCDR reload config` أكثر ما يُنسى)، و**الصيغة الدقيقة بحسب وثائق MCDR الرسمية ومساعدة `!!MCDR` على جهازك**. كذلك صلاحيات MCDR نظام خاص به لا علاقة له بمستوى OP في اللعبة؛ وما يستطيع اللاعب تنفيذه من أوامر `!!` في الدردشة يحدده إعداد صلاحيات MCDR.
:::

## 9. طبقة الإدارة: وحدة تحكم اللوحة وRCON

وحدة التحكم في اللوحة (مثل MCSManager أو Pterodactyl) هي في جوهرها **إدخال قياسي عن بُعد**: ما تكتبه يُرسَل كما هو إلى عملية الخادم، تمامًا كما لو كنت تكتب في وحدة التحكم أمام الجهاز.

| القناة | هل تُكتب `/` | الصلاحية | ملاحظات |
| --- | --- | --- | --- |
| وحدة التحكم المحلية | لا يُحتاج إليها عادةً | أعلى صلاحية | وحدة التحكم الأصلية غير مقيدة بمستوى OP |
| وحدة تحكم اللوحة على الويب | معظم اللوحات تقبل الاثنين | أعلى صلاحية | بعض اللوحات تحذف `/` البادئة تلقائيًا، والمرجع سلوك اللوحة |
| RCON | لا يُحتاج إليها عادةً | أعلى صلاحية | يجب تفعيلها وضبط كلمة مرورها في `server.properties` |
| مربع الدردشة داخل اللعبة | يجب كتابتها | بحسب مستوى OP أو عقدة الصلاحية | تتأثر بالقائمة البيضاء والحجب وملحق الصلاحيات |

وثلاث نصائح عملية:

1. **أغلق الخادم دائمًا بـ `stop` (وكذلك في Bedrock)**، ولا تنقر «إنهاء العملية» في اللوحة. فالإنهاء القسري قد يفقد بيانات أو يفسد الحفظ.
2. **لا تعرّض RCON إلى الإنترنت العام**. إنها قناة «تنفيذ أي أمر» دون تسجيل دخول، فاجعلها تستمع على العناوين المحلية فقط، وكلمة المرور طويلة وفريدة.
3. **الأوامر المنفَّذة في وحدة تحكم اللوحة تعادل أعلى صلاحية**، ففكّر في ذلك جيدًا قبل منح حساب لوحة لمشرف مساعد.

## 10. وحدة التحكم مقابل داخل اللعبة: قائمة الفروق

| الفرق | وحدة التحكم / RCON | مربع الدردشة داخل اللعبة |
| --- | --- | --- |
| الشرطة المائلة البادئة | لا تُكتب عادةً | يجب كتابتها |
| مصدر الصلاحية | صفة العملية، أي أعلى صلاحية | مستوى OP أو عقدة الصلاحية |
| سياق المنفّذ | **لا منفّذ**: لا يمكن استخدام `@s` أو الإحداثيات النسبية أو `tp` دون تحديد هدف | يوجد منفّذ، ويمكن استخدام المحددات والإحداثيات النسبية |
| اتجاه الخرج | الطرفية وملفات السجل | الدردشة وشريط الإجراءات |
| الإكمال التلقائي | يوجد عادةً؛ وبعض اللوحات لا توفره | يوجد |
| ترميز الأحرف | يظهر الصيني مشوّهًا إذا كانت صفحة ترميز وحدة تحكم Windows خاطئة | سليم عادةً |
| ظهور اللاعبين | لا يرى اللاعبون ما تكتبه | بعض الأوامر تُبثّ للاعبين |

وأكثر الأخطاء شيوعًا هو تنفيذ `/tp ~ ~10 ~` في وحدة التحكم: فوحدة التحكم لا موضع لها، وهذا يفشل حتمًا. وعند تنفيذ أوامر النقل من وحدة التحكم، **اكتب اللاعب والهدف صراحةً معًا**.

## 11. من أين تأتي الصلاحية

| النظام | نطاقه | كيف يُضبط |
| --- | --- | --- |
| مستوى OP | إصدار Java الأصلية | `/op` يمنح المستوى 4؛ والمستويات 1 إلى 4 تقابل مجموعات أوامر مختلفة، ويمكن تفصيلها بعُقد الصلاحيات |
| عُقد الصلاحيات | خوادم ملحقات إصدار Java | ملحق صلاحيات (مثل LuckPerms) يوزعها بالعقد والمجموعات، وهي أأمن من منح OP |
| المشغّل + مفتاح الغش | إصدار Bedrock | `permissions.json` يحدد من يكون مشغّلًا؛ و`allow-cheats` في `server.properties` يحدد توافر الأوامر |
| صلاحيات MCDR | الخوادم التي تعمل بـ MCDR | نظام صلاحيات MCDR نفسه، يتحكم بأوامر `!!` بحسب اللاعب والمجموعة |

**مبدأ منح الصلاحية**: إن أمكن منح صلاحية أمر واحد فلا تمنح OP كاملًا، وإن أمكن منح صلاحية مؤقتة فلا تمنحها دائمة. فـ OP ثقة على مستوى «الخادم كله»، وعُقد الصلاحيات هي التخويل الأدنى.

## 12. تركيبات قابلة للنسخ المباشر

الإجراء القياسي قبل الصيانة (إصدار Java):

```text
say 服务器将在 5 分钟后进入维护
save-all
save-off
# 此时在外部打包世界目录与插件目录
stop
```

القائمة البيضاء من الصفر إلى الجاهزية (إصدار Java):

```text
whitelist add 你的ID
whitelist on
whitelist list
```

النسخ الاحتياطي والاستعادة في Bedrock:

```text
save hold
save query
# 复制 query 列出的文件，worlds/ 整体拷走
save resume
```

أول الأوامر تنفيذًا عند تشخيص «اللاعب لا يستطيع الدخول»:

```text
list
whitelist list
banlist players
plugins
```

## 13. أخطاء استخدام شائعة

| الخطأ | النتيجة | الصواب |
| --- | --- | --- |
| إغلاق النافذة أو النقر على «إنهاء العملية» | قد يتلف الحفظ أو يتراجع | نفّذ `stop` في وحدة التحكم |
| استخدام `/reload` كإعادة تشغيل | اضطراب حالة الملحقات وعدم سريان الإعدادات | استخدم reload الخاص بالملحق؛ وأعد التشغيل عند الحاجة |
| عدم `save-off` قبل النسخ الاحتياطي | نسخ حفظ نصف مكتوب | نفّذ `save-all` ثم `save-off` |
| استخدام الإحداثيات النسبية `~` في وحدة التحكم | يفشل الأمر مباشرة | اكتب اللاعب والإحداثيات صراحةً |
| تعريض منفذ RCON للإنترنت | تسليم الخادم لفاحصي المنافذ | اسمع على العنوان المحلي فقط، وكلمة مرور قوية |
| تعديل `whitelist.json` دون reload | لا يسري التغيير | نفّذ `whitelist reload` |
| استخدام اسم `gamerule` من Bedrock في إصدار Java | القاعدة غير موجودة أو بدلالة مختلفة | تأكد من الاسم بالإكمال التلقائي |
| الظن أن Bedrock يملك `save-all` | الأمر غير موجود | استخدم `save hold` / `save query` / `save resume` |
