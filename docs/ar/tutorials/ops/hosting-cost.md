«كم يكلّف فتح خادم» سؤال بلا جواب معياري، لكن **طريقة طرحه الخطأ** شائعة. فالسؤال الصحيح ثلاثة أسئلة: **ما حجمي؟ وما البنود في ميزانيتي التي تُدفع مرة واحدة والتي تُدفع شهريًا؟ وكم من وقتي مستعدّ أن أستثمر؟**

وردّ فعل كثيرين الأول هو المقارنة السعرية: يسردون أسعار باقات عدة مزوّدين ويختارون الأرخص. وهذا التصرف يكلّفهم أكثر بعد نصف سنة — لا لأنهم اشتروا باهظًا، بل لأنهم **اشتروا الشيء الخطأ**، ثم يردّون المال الموفَّر دفعةً واحدة عند الترحيل أو ضياع الأرشيف أو التعرّض لهجوم.

تتناول هذه المقالة كيف تصرف المال في المواضع التي تحدّد التجربة فعلًا. وتقوية مستوى المضيف في [تقوية أمان النظام](/tutorials/ops/system-security)، وكلفة الانتقال في [ترحيل الخادم](/tutorials/ops/server-migration)، وواقع التعرّض للهجوم في [أنواع الهجمات الشبكية الشائعة والدفاع المتخصص لـ Minecraft](/tutorials/ops/attack-defense).

:::warn الأسعار والباقات تتبع الصفحات الرسمية للمزوّد
كُتبت هذه المقالة في حالة يتعذّر فيها التحقّق عبر الشبكة، **فكل المبالغ والوحدات وأشكال الباقات أدناه «مؤشرات رتبة مقدار» فقط، وليست عروض أسعار**. فالأسعار وطرق الفوترة وسياسات الاسترداد وسعر تجاوز النطاق، وهل حماية DDoS مجانية، **تختلف بين مزوّد وآخر، وتتغيّر في أي وقت**. تحقّق من صفحة الأسعار الرسمية وشروط العقد قبل الشروع.
:::

## 1. فكّك كلمة «التكلفة» أولًا

الكلفة الكلية لفتح خادم تتكوّن من أربعة أنواع، طبيعتها مختلفة تمامًا:

| الفئة | أمثلة | السمة |
| --- | --- | --- |
| **مصروف لمرة واحدة** | العتاد، والسنة الأولى للنطاق، وأجرة يد الترحيل، والإعداد الأولي | يُدفع مرة عند البداية أو عند تغيير كبير، ويسهل إغفاله |
| **مصروف شهري ثابت** | رسم المضيف الشهري، وحزمة النطاق الترددي، وتخزين النسخ الاحتياطي، ولوحة التحكّم | يُدفع كل شهر، و**يحدّد عبئك على المدى الطويل** |
| **مصروف متغيّر** | رسوم تجاوز النطاق، وتخزين اللقطات، ورسوم الحماية المتقدّمة، والفوترة بالاستخدام | لا يظهر عادةً، ثم يتضخّم فجأة عند وقوع حادث أو حدوث نمو |
| **كلفة الوقت** | التحديثات، والتحقق من النسخ، وإدارة اللاعبين، ومعالجة الحوادث | **الأغلى والأكثر حسابًا بصفر** |

**وبحساب هذه الفئات الأربع منفصلةً يتّضح نصف قرار الاختيار.** فكثير من الحلول «التي تبدو رخيصة» رخيص فيها النوع الثاني، والثمن مخفيّ في النوعين الثالث والرابع.

:::note معيار حكم واحد
إن كان الفارق الشهري بين حلّين صغيرًا، **فاختر الذي يسهّل عليك الانتقال لاحقًا، وإضافة النسخ الاحتياطي، وتغيير الإعداد**. ففي فتح الخادم تكون «قابلية الترحيل» و«قابلية المراقبة» أعلى قيمة عادةً من بضع عشرات من الريالات الموفَّرة.
:::

## 2. العوامل التي تحرّك التكلفة فعلًا

### 2.1 أداء النواة الواحدة للمعالج (الأكثر إغفالًا)

**المنطق الرئيسي في Minecraft (حلقة tick) يعمل أساسًا على خيط واحد**. وهذا يعني:

- **كثرة الأنوية لا تعني سلاسة.** فمضيف بـ 8 أنوية لكن نواته الواحدة ضعيفة، يشغّل خادمًا أصليًا لـ 20 لاعبًا، قد يكون أسوأ من مضيف بنواتين لكن نواته الواحدة قوية.
- **السبب المباشر لهبوط TPS هو امتلاء النواة الواحدة غالبًا**، وقد يكون استهلاك المعالج للجهاز كله 15% فقط.
- وتوليد العالم، وتحميل المناطق، وحساب الكيانات وRedstone، كلها تزيد الضغط على النواة الواحدة.

لذا عند اختيار المضيف، **أولوية أداء النواة الواحدة أعلى من عدد الأنوية**. وهذا مهم خصوصًا في الباقات الرخيصة: فعلى مضيف مفرط البيع، ما تحصل عليه من «3.0 GHz» مشترك.

### 2.2 الذاكرة

الذاكرة تحدّد «كم يمكن أن يكبر، وكم يمكن أن يستوعب»:

- خادم أصلي/Paper: الأحجام الصغيرة (من بضعة إلى نحو عشرة لاعبين) تعمل عادةً بكومة من بضعة GB، **لكن الأرقام المحدّدة تختلف اختلافًا هائلًا بحسب النسخة ومسافة العرض والملحقات ونمط اللعب**.
- خوادم المودات والحزم المتكاملة: حاجة الذاكرة عادةً أضعاف الأصلية، **واعتمد بيان مؤلّف الحزمة والمحمّل الرسمي**.
- ولوحة التحكّم وخريطة الويب وقاعدة البيانات والوكيل كلها تستهلك ذاكرة إضافية، **فلا تحسب الذاكرة للخادم وحده**.
- وإعطاء ذاكرة أكثر من اللازم له ثمن أيضًا: فالكومة الكبيرة جدًا تطيل توقّف GC الواحد. **«الذاكرة الأكبر أفضل» خطأ**، والتصرف الصحيح إعطاء ما يكفي ومراقبة GC وMSPT.

### 2.3 القرص: SSD وIOPS

حفظ العالم وتحميل المناطق وضغط النسخ الاحتياطي كلها تستهلك القرص. **وعندما يكون القرص بطيئًا يبدو المعالج شبه عاطل**، وهذا أصعب أنواع التقطيع في التشخيص.

- **SSD واجب.** فالقرص الميكانيكي بتجربة خدمة حديثة سيئة جدًا، خصوصًا في تحميل المناطق.
- والأهم من «هل هو SSD» هو **قدرة القراءة والكتابة العشوائية (IOPS)** و**هل هو مشترك مع مستأجرين آخرين**.
- **وامتلاء القرص يتلف البيانات**، لذا اترك هامشًا للمساحة المتاحة (النسخ والسجلات وملفات تفريغ الذاكرة كلها تستهلك مساحة).

### 2.4 النطاق الترددي

- **الصاعد (اتجاه الخروج) هو عنق الزجاجة**: فتحميل اللاعبين للمناطق وتنزيلهم لحزم الموارد يمرّ بالصاعد لديك.
- **نطاق المنزل غير متماثل عادةً**، وصاعده صغير؛ أما خطوط مراكز البيانات فمتماثلة عادةً.
- **والفوترة بالترافيك والفوترة بالنطاق نمطان مختلفان**، الأول يُحسب بالـ GB والثاني بذروة Mbps، ومخاطر الفاتورة مختلفة تمامًا.

### 2.5 حماية DDoS

بالنسبة إلى Minecraft فالحماية ليست «خيارًا متقدّمًا»:

- إصدار Java يعمل على TCP (افتراضيًا 25565)، وإصدار Bedrock على **UDP** (افتراضيًا 19132)، و**إغراق UDP هو أكثر أشكال الهجوم شيوعًا على Bedrock**.
- والباقات الرخيصة **لا تتضمّن** حماية فعّالة عادةً، أو تمنح طبقة تنقية رقيقة جدًا فقط.
- **والحماية المتقدّمة رسم شهري إضافي عادةً، وسعرها مرتبط بنطاق الحماية**؛ والشكل المحدّد والسعر بحسب المزوّد.

ومبادئ الحماية وأنواع الهجمات في [أنواع الهجمات الشبكية الشائعة والدفاع المتخصص لـ Minecraft](/tutorials/ops/attack-defense).

### 2.6 مساحة النسخ الاحتياطي

**المساحة التي تشغلها النسخ الاحتياطية تساوي عالمك عادةً، وتحتاج إلى عدة نُسخ.** والخطأ الشائع أن «يشتري المضيف باقتصاد، فلا يبقى مكان للنسخ»، فيفشل سكربت النسخ بصمت شهورًا — إلى اليوم الذي تحتاجه فيه.

- يجب أن تكون النسخة **خارج المضيف الذي تستأجره** (خارج الموقع / تخزين كائني)، انظر [النسخ الاحتياطي خارج الموقع](/tutorials/ops/offsite-backup).
- و**ترافيك الاسترجاع (النازل) في التخزين الكائني يُفوتر منفصلًا عادةً**، وتجربة الاستعادة نفسها تكلّف.
- وسياسة الاحتفاظ (كم نسخة تُبقى، وكم مدة) تحدّد التكلفة مباشرةً.

### 2.7 وقتك أنت

هذا البند الوحيد الذي **يحسبه الجميع تقريبًا بصفر**، وهو عادةً أكبر بند:

- التحديثات الأسبوعية، وفحص توافق الملحقات، والتحقق من النسخ.
- إدارة اللاعبين: القائمة البيضاء، والاستئنافات، والنزاعات، والمشاغبين.
- معالجة الحوادث: التعرّض لهجوم، وانهيار الخادم، وضياع الأرشيف، والاختراق.

**وإن كان وقتك بلا قيمة فذلك لأنك لم تُدخله في الحساب بعد.** فحلّ يطلب منك 5 ساعات أسبوعيًا، وحلّ أغلى بـ 50 يوانًا شهريًا لكنه يوفّر 3 ساعات، الثاني أوفر غالبًا.

### 2.8 الخط والزمن التأخيري

رقم النطاق يحدّد «كم يستوعب»، و**الخط والزمن التأخيري يحدّدان «هل الإحساس جيد»**. ولا يُغني أحدهما عن الآخر:

- **الزمن التأخيري ذهابًا وعودة (RTT)** بين اللاعب والخادم يؤثر مباشرةً في إحساس التعدين والهجوم والحركة؛ وعند ارتفاع الزمن التأخيري لا ينفع نطاق كبير.
- **وموقع مركز البيانات وجودة الخط** أهم من النطاق غالبًا: فـ 100 Mbps نفسها قد تختلف تجربتها الفعلية للاعبين المحليين اختلافًا كبيرًا بحسب الخط.
- **والوصول عبر مشغّلين مختلفين مأزق شائع**: فلاعبو أحد المشغّلين سريعون، ولاعبو آخر يظلّون يهبط زمنهم التأخيري.
- والقياس يكون **بعميل حقيقي من شبكة اللاعب**، لا بـ`ping` إلى البوابة من الخادم: فـ`mtr` و`traceroute` يُظهران في أي قفزة يحدث فقد الحزم.

### 2.9 دورة الفوترة والاسترداد والعقد

هذه الشروط لا تؤثر في الأداء، لكنها **تحدّد كم تكلّفك «الشراء الخاطئ»**:

- **الفوترة بالساعة/بالاستخدام** تصلح للتجربة، لكن سعر الوحدة أعلى عادةً؛ و**الدفع الشهري** نقطة التوازن لأغلب الخوادم الشخصية؛ و**الدفع السنوي** أكبر خصم وأعمق ارتباط.
- **راجع سياسة الاسترداد بوضوح**: بعض المزوّدين «يسترد في أي وقت»، وبعضهم خلال أيام محدّدة بعد الشراء الأول فقط، وبعضهم يحسب بحسب مدة الاستخدام.
- **وقد يكون سعر التجديد أعلى من سعر الشراء الأول**، وهذا هيكل ترويجي شائع، فانظر إلى سعر التجديد عند حساب التكلفة الطويلة.

:::note أسرع طريقة للحكم على «هل يمكن التجربة»
اسأل قبل الطلب: **إن اكتشفت بعد ثلاثة أيام أن الأداء غير كافٍ، فكم أستعيد؟** فإن كان الجواب غامضًا، فحوّل «الدفع السنوي» إلى «شهري» ثم قرّر.
:::

## 3. مقارنة سبعة خيارات

الجدول التالي **مقارنة نوعية**، لا يتناول أسعارًا محدّدة. وركّز عند القراءة على العمودين الأخيرين: **التكلفة المخفية** و**متى لا تختره**.

| الخيار | الحجم المناسب | الميزات | العيوب | التكلفة المخفية | متى لا تختره |
| --- | --- | --- | --- | --- | --- |
| حاسوب منزلي / نطاق منزلي | خادم أصدقاء صغير، وتجارب، وفتح مؤقت | استثمار لمرة واحدة، والبيانات في يدك، والتجربة ممكنة في أي وقت | الصاعد صغير، وقد لا يوجد IP عام، والانقطاع الكهربائي وانقطاع الشبكة يوقفان الخادم، وهجوم على شبكة المنزل يضرّ الأسرة كلها | فاتورة الكهرباء، والضوضاء والحرارة، واستهلاك العتاد، وضرورة صيانة UPS والموجّه بنفسك، وأعلى كلفة وقت | إن كان موجّهًا للإنترنت العام، ويحتاج استقرار 7x24، ويحتاج مقاومة هجوم، أو تجاوز عدد اللاعبين عشرة |
| استضافة مشتركة (Shared Hosting) | مواقع ثابتة، ومواقع PHP | رخيصة وجاهزة | **لا تشغّل عمليات طويلة الأمد عادةً، ولا تفتح منافذ مخصّصة**، وحدود الموارد صارمة | لا مسار للترقية، وكلفة ترحيل | **لا تصلح لخادم Minecraft في معظم الحالات**، إلا إن كان المزوّد يبيع خادم ألعاب صراحةً |
| VPS | الأحجام الصغيرة والمتوسطة، والخوادم الشخصية، والوكيل | سعر معتدل، وصلاحية root، واختيار النظام والنواة | الموارد مشتركة مع الجيران، والباقات الرخيصة مفرطة البيع عمومًا، والحماية رقيقة عادةً | النطاق «مشترك» أو مفوتر بالترافيك في الأغلب، واللقطات برسم إضافي، وقد يُوقف عند التعرّض لهجوم | إن كنت تحتاج حزمة مودات بذاكرة كبيرة، أو حماية قوية، أو أداءً فيزيائيًا حصريًا |
| خادم مستقل (Dedicated) | الأحجام الكبيرة والمتوسطة، وحزم المودات، ونسخ متعددة | حصرية فيزيائية، وأداء مستقر قابل للتوقّع، واختيار العتاد | الرسم الشهري مرتفع، والتسليم بطيء، وأعطال العتاد تنتظر معالجة مركز البيانات | النطاق والحماية يُسعّران منفصلين غالبًا، ورسم IP والموقع، والصيانة وقطع الغيار | إن كان اللاعبون قلائل، أو الميزانية حساسة، أو كنت لا تنوي القيام بالتشغيل بنفسك |
| خوادم بلوحة تحكّم / مزوّدو خوادم الألعاب | خوادم صغيرة ومتوسطة تريد تقليل العناء | لوحة ونسخ ومهام مجدولة جاهزة، والبيع بالذاكرة أو بالخانات | لا تستطيع إلا بيئتهم، والتخصيص محدود، وفرط البيع شائع | زيادات على الذاكرة الإضافية والنسخ الإضافية، والترحيل محدود بأدوات المزوّد، وحدود المعالج لا تُكتب في الإعلان | إن كنت تحتاج نظامًا أو نواة مخصّصة، أو بيئة مودات خاصة، أو حجمًا كبيرًا بتكلفة منخفضة على المدى الطويل |
| خادم سحابي بالاستخدام | الأحجام المتقلّبة، والفعاليات القصيرة، والتجارب | مرونة، وتشغيل وإيقاف حسب الحاجة، ونظام بيئي متكامل (لقطات وصور ومراقبة) | **فاتورة غير قابلة للتوقّع**، والإعداد الافتراضي أغلى عادةً، ويجب أن تبني كل شيء بنفسك | فوترة منفصلة لـ IP العام وتخزين اللقطات والصور والسجلات وترافيك الخروج؛ ونسيان الإيقاف يحرق المال باستمرار | إن كان الحِمل مستقرًا طويل الأمد (الدفع السنوي أو الشهري أوفر عادةً)، أو كان الفريق لا يضبط تنبيهات ميزانية |
| الاستضافة المُدارة / colocation | عتاد خاص، وحجم كبير، ومتطلبات امتثال | استقلال العتاد، وقد تكون كلفة الوحدة أقل على المدى الطويل | تحتاج عتادًا خاصًا وتعاقدًا، والأعطال تعالجها بنفسك | رسم الموقع، ورسم الكهرباء، ورسم النطاق، وأجرة اليد عن بُعد (remote hands)، ووقت الحضور | إن كان لديك جهاز واحد، وبلا قطع غيار، وبلا قدرة تشغيل |

### 3.1 حاسوب منزلي / نطاق منزلي

تموضعه واضح: **أقل تكلفة، وأعلى تحكّم، وأدنى موثوقية**. ويصلح لخادم صغير بين الأصدقاء. وللحكم على صلاحيته، تحقّق من ثلاثة أمور أولًا: **هل يوجد IP عام** (فكثير من خطوط المنازل خلف CGNAT، فلا يوجد أصلًا)، و**كم يبلغ الصاعد**، و**هل تسمح شروط المشغّل بتقديم خدمة للخارج على المدى الطويل**. والتفاصيل والمزالق في [فتح الخادم على حاسوب منزلي وصيانته](/tutorials/ops/home-hosting).

### 3.2 الاستضافة المشتركة

**ليست خيارًا لـ Minecraft.** فالاستضافة المشتركة تبيع «بيئة تشغيل موقع»: بلا عمليات مقيمة طويلة، وبلا استماع إلى منافذ عشوائية، وحدود صارمة للمعالج والذاكرة. وقليل من المزوّدين يدرج «خادم الألعاب» تحت هذه الكلمة، وهو في الحقيقة خادم بلوحة تحكّم أو حاوية، فاحكم عليه حسب 3.5.

### 3.3 VPS

الحل الأكثر استخدامًا للأفراد والفرق الصغيرة. والنقاط المهمة: **«عدد الأنوية» في الباقات الرخيصة قليل القيمة المرجعية، والمهم أداء النواة الواحدة وIOPS القرص**؛ وانظر في النطاق: هل هو «حصري» أم «مشترك»، وهل هو «بلا حدّ للترافيك لكن بسرعة محدودة» أم «مفوتر بالترافيك».

### 3.4 الخادم المستقل

حين تحشر الحزم المتكاملة أو النسخ المتعددة أو حجم اللاعبين الـ VPS في الزاوية، يكون الخادم المستقل الخطوة الطبيعية. وقيمته أنه **قابل للتوقّع**: أنوية فيزيائية، وأقراص فيزيائية، ونطاق فيزيائي. والثمن أن **الرسم الشهري ومسؤولية التشغيل يرتفعان معًا**.

### 3.5 خوادم بلوحة تحكّم / مزوّدو خوادم الألعاب

تصلح لمن يقول «لا أريد لمس Linux». ومالها يُصرف أساسًا في **توفير الوقت**، فمعيار الحكم: **هل الوقت الموفَّر في التشغيل أكبر من علاوة سعرها**. ولاحظ أمرين: **طراز المعالج في الإعلان لا يساوي الأداء الذي تحصل عليه فعلًا غالبًا**؛ و**أدوات الترحيل تنقل صيغتها هي فقط عادةً**، فتأكّد قبل الرحيل من إمكانية أخذ أرشيفك وإعدادك كاملين.

### 3.6 الخادم السحابي بالاستخدام

ميزة الاستخدام هي المرونة، وعيبه **عدم قابلية الفاتورة للتوقّع**. تشغيل جهاز للتجربة ممتع، ونسيان إيقافه شهرًا «ممتع» أيضًا. وإن أردت استخدامه فافعل ثلاثة أمور أولًا: اضبط **تنبيه ميزانية**، واضبط **إيقافًا تلقائيًا أو تذكيرًا بانتهاء المدة**، وافهم **طريقة فوترة IP العام واللقطات**.

### 3.7 الاستضافة المُدارة / colocation

هذا جواب من يقول «لديّ العتاد، ولديّ قدرة التشغيل». وكلفة الوحدة تنخفض مع الحجم، لكن **العتبة والمسؤولية ترتفعان مع الحجم**: فعند عطل العتاد لا يوجد مزوّد يستبدل القرص عنك، بل أنت (أو remote hands مدفوعة).

## 4. بنود التكلفة التي يسهل إغفالها

| البند | لماذا يسهل إغفاله | كيف تتجنّبه |
| --- | --- | --- |
| IP العام / IP المرن | بعض المزوّدين يسعّرون الـ IP منفصلًا، وقد يُفوترون على IP عاطل | تحقّق في صفحة الأسعار قبل الطلب: هل الـ IP مشمول، وهل العاطل مفوتر |
| فوترة تجاوز الترافيك | «ترافيك بلا حدّ» يأتي غالبًا مع شروط استخدام عادل أو تحديد سرعة | افهم: هل هو تحديد سرعة أم فوترة، وكم سعر وحدة التجاوز |
| تخزين النسخ الاحتياطي | النسخ لا تشغل مساحة المضيف، لكنها تكلّف في التخزين الكائني | احسب حجم العالم × عدد النسخ، ثم اختر سياسة الاحتفاظ |
| اللقطات (Snapshots) | اللقطة ليست نسخة احتياطية، وتُفوتر بالحجم | استخدم النسخ الاحتياطي بدل اللقطات كوسيلة لحفظ البيانات (انظر القسم 8) |
| حماية DDoS المتقدّمة | كلما زاد نطاق الحماية زاد السعر، وهي بند شهري إضافي عادةً | حدّد ما تستطيع «الحماية الأساسية» تحمّله، ثم قرّر شراء الإضافية |
| النطاق والشهادة | النطاق يُجدَّد سنويًا، ونسيان التجديد يعني فقدان التحليل مباشرةً | فعّل التجديد التلقائي؛ والشهادة في [شهادة HTTPS والتجديد التلقائي](/tutorials/ops/https) |
| الكهرباء والضوضاء (حلّ النطاق المنزلي) | الحاسوب يعمل 7x24، وعدّاد الكهرباء والأذن يعرفان ذلك | قدّر بحسب تعريفة الكهرباء المحلية (انظر المثال أدناه)، وخذ التبريد والضوضاء في الحساب |
| كلفة الوقت | لا أحد يدخلها في جدول الميزانية | سجّل مرة أسبوعيًا ما تُنفقه فعلًا، وستغيّر رأيك بعد شهور |
| كلفة الترحيل | الانتقال ليس نسخ ملفات، بل **نافذة صيانة** | انظر [ترحيل الخادم](/tutorials/ops/server-migration) |

:::tip مثال حسابي لفاتورة الكهرباء
جهاز يستهلك نحو 60 W وسطًا يعمل 7x24: 60 W x 24 h = 1.44 كيلوواط-ساعة/يوم، أي نحو 43 كيلوواط-ساعة شهريًا. وبحساب 0.6 يوان لكل كيلوواط-ساعة يكون الناتج نحو **26 يوانًا شهريًا**. وهذا مثال حسابي فقط: **أعد الحساب باستخدام أرقامك أنت للاستهلاك والتعريفة**، وتُحسب الشاشة والموجّه وUPS والتكييف بشكل منفصل.
:::

## 5. تقدير الحجم بصدق

### 5.1 تقدير خشن من عدد اللاعبين إلى الموارد

الجدول التالي **مرجع رتبة مقدار، لا ورقة مواصفات**. فالحاجة الفعلية تتأثر بشدة بالنسخة والنواة ومسافة العرض والملحقات وحجم العالم ونمط اللعب.

| الحجم | المعالج | الذاكرة (كومة الخادم) | النطاق الترددي | ملاحظة |
| --- | --- | --- | --- | --- |
| 2 - 5 لاعبين، خادم أصدقاء | نواتان مع نواة واحدة قوية تكفي | من رتبة 2 - 4 GB | صاعد النطاق المنزلي يكفي عادةً | الحاسوب المنزلي يكفي غالبًا |
| 10 - 20 لاعبًا، أصلي/ملحقات خفيفة | أداء نواة واحدة عالٍ، و2 - 4 أنوية | من رتبة 4 - 8 GB | من رتبة بضعة Mbps | مسافة العرض وعدد الكيانات يؤثران تأثيرًا هائلًا |
| 30 - 50 لاعبًا، خادم ملحقات | نواة واحدة عالية + مساعدة الأنوية | من رتبة 8 - 16 GB | من رتبة عشرة Mbps | يحتاج SSD حقيقيًا وخطًا مستقرًا |
| مودات / حزم متكاملة | أولوية لأداء النواة الواحدة العالي | أضعاف الأصلية عادةً | يتوقف على حجم المزامنة | **اعتمد بيان الحزمة الرسمي** |
| نسخ متعددة / خادم مجمّع | كثرة الأنوية تصبح ذات معنى | مجموع النسخ + الوكيل وقاعدة البيانات | متراكم | انظر [وكيل الخوادم](/tutorials/java/proxy) |

**وتقدير النطاق الخشن**: في الحالة المستقرة يشغل اللاعب عادةً **رتبة عشرات KB/s** (نحو 0.2 - 1 Mbit/s)، لكنه يرتفع بوضوح عند كبر مسافة العرض وكثرة الكيانات وطيران اللاعب لتحميل مناطق جديدة، و**التدفّق المفاجئ عند إرسال المناطق لحظة الدخول أكبر بكثير من الحالة المستقرة**. وهذه الأرقام تعتمد اعتمادًا كبيرًا على النسخة ونمط اللعب، **فاعتمد قياسك أنت** (`vnstat` أو `nload` أو مخطط الترافيك في اللوحة، كلها تصلح).

### 5.2 فرط البيع هو الحالة الطبيعية للباقات الرخيصة

«مشترك»، «انتفاضي»، «استخدام عادل» — هذه الكلمات تعني أمرًا واحدًا عادةً: **أنت تشتري حصة، لا نواة حصرية**. وهذا ليس خداعًا بحدّ ذاته، بل هو سبب وجود الباقات الرخيصة؛ والمشكلة أنه **يجعل «الشراء بالنظر إلى المواصفات» غير موثوق**.

وتوصيات تطبيقية:

- اجعل **أداء النواة الواحدة** المؤشر الأول، لا عدد الأنوية ولا رقم التردد.
- كن متحفظًا في توقّع «الحِمل العالي الطويل»: الحصة الانتفاضية تصلح للذروات لا للامتلاء 7x24.
- **اشترِ دورة قصيرة للتحقق أولًا**، ثم قرّر بعد التشغيل إن كنت تريد المدى الطويل.

### 5.3 لا تنظر إلى سعر الوحدة فقط، بل احسب كلفة الوحدة

عند مقارنة حلّين، حوّلهما إلى المقياس نفسه: **إجمالي المصروف الشهري ÷ عدد اللاعبين الذين يستطيع دعمهم بثبات**. وبهذا الحساب يصبح الحلّ «الأغلى 30% لكنه يحمل ضعف اللاعبين» أوفر فورًا غالبًا.

### 5.4 اشترِ صغيرًا أولًا، ثم كبّر

استراتيجية تخالف الحدس لكنها عملية جدًا: **اشترِ الفئة الأصغر بوضوح أولًا، وتحقق من عنق الزجاجة الحقيقي، ثم أضف مالًا بحسب عنق الزجاجة.**

والسبب أن **أكثر الناس يبالغون في تقدير حجمهم**. فقبل الفتح يفكّرون في «سيكون لدينا 50 لاعبًا لاحقًا»، والواقع أن متوسط المتصلين في الأشهر الثلاثة الأولى 3 لاعبين. وإن اشتريت لـ 50 من البداية فستدفع مدة طويلة لأجل لاعبين غير موجودين.

والتطبيق:

1. اشترِ أصغر فئة صالحة بحسب «الحجم الحالي + هامش قليل».
2. سجّل بـ[المراقبة والتنبيهات](/tutorials/ops/monitoring) المنحنيات الحقيقية لاستهلاك النواة الواحدة والذاكرة وقرص I/O والنطاق.
3. رقِّ بعد أن تتكلّم البيانات: **فالترقية أسهل من التخفيض عادةً**، وكثير من المزوّدين يدعمون الترقية أثناء العمل (**وهل يدعمونها، وهل تحتاج إعادة تشغيل، يتبع توثيق المزوّد**).
4. إن كان عنق الزجاجة قرص I/O أو أداء النواة الواحدة، **فزيادة الذاكرة لا تنفع** — وهنا فكّر في تغيير المزوّد لا في ترقية الباقة.

## 6. كيف تختبر قبل الشراء

### 6.1 أداء النواة الواحدة أهم من عدد الأنوية

يمكن أن يكون تقييم الأداء من طرف ثالث (مثل تقييم الخيط الواحد الشائع) **فرزًا خشنًا** لاستبعاد الأجهزة السيئة بوضوح، لكنه **لا يقيس فرط البيع ولا تشويش الجيران ولا اختناق القرص**. لذا استخدمه لتضييق النطاق فقط، والحكم النهائي بالاختبار الفعلي.

### 6.2 اطلب تجربة، أو اشترِ أقصر دورة أولًا

- فضّل المزوّدين **الذين يوفّرون تجربة أو فوترة بالساعة**، وشغّل حِملًا حقيقيًا ثم قرّر.
- وإن لم توجد تجربة، **فاشترِ أقصر دورة** (شهريًا أو حتى يوميًا)، ولا تبدأ بالدفع السنوي.
- **واختبر «سيناريوك الحقيقي» إلزاميًا**: انقل الخادم والملحقات والأرشيف، وأدخل بضعة أشخاص للعب مرة، فهذا أقوى من أي تقييم أداء.

### 6.3 اختبار قرص I/O

القرص هو أسهل موضع للغش في الباقات الرخيصة. وطريقتان شائعتان:

```bash
# اختبار كتابة متتابعة: أنشئ ملفًا مؤقتًا على نظام الملفات الهدف، واحذفه بعد الاختبار
dd if=/dev/zero of=./io-test.bin bs=1M count=1024 conv=fdatasync status=progress
rm -f ./io-test.bin

# اختبار قراءة عشوائية (يحتاج تثبيت fio؛ ومعاني الوسائط تتبع توثيق fio الرسمي)
fio --name=randread --rw=randread --bs=4k --iodepth=32 \
    --size=1G --numjobs=1 --time_based --runtime=30s --group_reporting
```

ولاحظ عند قراءة النتائج: أرقام الكتابة المتتابعة في `dd` **تميل إلى التفاؤل** (بسبب التخزين المؤقت ونظام الملفات)، وIOPS القراءة العشوائية أقرب إلى الضغط الحقيقي لتحميل المناطق وكتابة الأرشيف. **والاختبار يُنتج كتابة كثيفة على القرص، فنفّذه في دليل مؤقت، واحذف النتيجة بعده، ولا تفعله في دليل بيانات الخادم.**

| المأزق | أين الرخص | أين الغلاء | كيف تتجنّبه |
| --- | --- | --- | --- |
| إغفال كلفة الترحيل | اخترت أرخص جهاز | الانتقال يتطلّب توقفًا، ثم معالجة DNS والقائمة البيضاء والنسخ والمراقبة | اختر من البداية حلًّا **يسمح بتصدير البيانات كاملة**، واعتبر الانتقال حدثًا حتميًا؛ انظر [ترحيل الخادم](/tutorials/ops/server-migration) |
| لا مساحة للنسخ الاحتياطي | اشتريت المضيف فقط، لا التخزين | ضياع الأرشيف مرة واحدة يعني كل التقدّم | ضع النسخ خارج المضيف من البداية؛ انظر [النسخ الاحتياطي خارج الموقع](/tutorials/ops/offsite-backup) |
| لا حماية DDoS | وفّرت الرسم الشهري للحماية | عند الهجوم: انقطاع، وإيقاف من المزوّد، وتسرّب لاعبين | تحقّق على الأقل من حدود قدرة الحماية الأساسية؛ انظر [أنواع الهجمات الشبكية الشائعة والدفاع المتخصص لـ Minecraft](/tutorials/ops/attack-defense) |
| فاتورة تجاوز الترافيك | سعر الوحدة في الفوترة بالاستخدام يبدو منخفضًا | هجوم واحد أو توزيع حزمة موارد واحدة يحرق ميزانية شهر | اضبط تنبيه ميزانية، وفضّل تحديد السرعة على الفوترة، وضع حزم الموارد في التخزين الكائني |
| ارتباط الدفع السنوي | خصم الدفع السنوي مغري | هروب المزوّد، أو عدم بلوغ الأداء، أو عدم القدرة على التغيير | ادفع شهريًا في السنة الأولى، وفكّر في المدى الطويل بعد الاستقرار |
| حساب الوقت بصفر | العمل بيدك «بلا مال» | استثمار متواصل عدة ساعات أسبوعيًا | أدخل الوقت في جدول الميزانية، وراجعه دوريًا |

## 8. تخفيض التكلفة بشكل مشروع

هذه التصرفات **لا تضحّي بالموثوقية**، بل تضع الموارد في موضعها الصحيح:

- **تقليل مسافة العرض (view-distance)**: وهو أنجع تحسين منفرد، يقلّل إرسال المناطق ومعالجة الكيانات مباشرةً.
- **تقليل العوالم المقيمة**: فكل بُعد/عالم إضافي يستهلك الذاكرة وقرص I/O؛ فأوقف غير المستخدم أولًا.
- **إعادة التشغيل المجدولة**: تخفّف النمو البطيء للذاكرة وتسريب المقابض (**لكنها ليست إصلاحًا بل تغطية**؛ ابحث عن السبب الجذري في الوقت نفسه).
- **النسخ الاحتياطي بدل اللقطات**: اللقطات تُفوتر بالحجم ولا تعدل نسخة قابلة للاستعادة؛ والحفظ الصحيح للبيانات في [النسخ الاحتياطي والاستعادة](/tutorials/java/backup).
- **التوليد المسبق للعالم**: انقل كلفة توليد المناطق إلى ما قبل الفتح، فتقليل ذروة النواة الواحدة أثناء التشغيل.
- **تشغيل اللوحة بنفسك**: خوادم اللوحات توفّر الوقت؛ فإن كنت تعرف Linux أصلًا فبناء اللوحة بنفسك يوفّر العلاوة (والثمن مكوّن إضافي تحتاج إلى صيانته، انظر [استخدام أدوات إدارة اللوحات وأمانها](/tutorials/ops/panels)).
- **إيقاف الخدمات غير المستخدمة**: خريطة الويب، والنسخ الإضافية، وخادم الاختبار، كلها تستهلك موارد باستمرار.
- **دمج أوقات الهدوء**: حين يتركّز اللاعبون في المساء، يمكن تشغيل النسخة عالية المواصفات في تلك الفترة فقط.

:::warn خطّان أحمران في تخفيض التكلفة
**لا توفّر في النسخ الاحتياطي، ولا في الحماية.** فالمال الموفَّر في هذين البندين يعود مع الفائدة عادةً عند أول حادث. يمكنك تخفيض المواصفات وتغيير الجهاز إلى أرخص، لكن **البيانات القابلة للاستعادة** و**الهجمات القابلة للصمود** هما الحدّ الأدنى.
:::

## 9. ورقة عمل تخطيط الميزانية

انسخ الجدول التالي إلى دفترك، واملأه بحسب حالتك. **واكتب الأساس في عمود «ملاحظة»، لتفهم بعد شهور لماذا اخترت هكذا.**

| البند | لمرة واحدة | شهريًا | ملاحظة |
| --- | --- | --- | --- |
| المضيف / الخادم |  |  | المواصفات، وأداء النواة الواحدة، وهل يوجد فرط بيع |
| IP العام والنطاق |  |  | حصري أم مشترك، وتحديد سرعة أم فوترة |
| حماية DDoS |  |  | ما تصمد له الحماية الأساسية، وهل المتقدّمة ضرورية |
| تخزين النسخ الاحتياطي |  |  | حجم العالم × عدد النسخ المحفوظة، وهل خارج الموقع |
| النطاق (الدومين) |  |  | يُجدَّد سنويًا، ولا تنسَ تفعيل التجديد التلقائي |
| الشهادة |  |  | شهادات ACME المجانية عادةً صفر، انظر [شهادة HTTPS والتجديد التلقائي](/tutorials/ops/https) |
| اللوحة / أدوات الإدارة |  |  | البناء الذاتي يوفّر الرسم الشهري ويكلّف وقتًا |
| الكهرباء (حلّ النطاق المنزلي) |  |  | الاستهلاك × التعريفة، انظر مثال القسم 4 |
| العتاد وقطع الغيار |  |  | القرص والذاكرة وUPS والكابلات |
| الترحيل ونوافذ الصيانة |  |  | أثر التوقف، والإعلان، والعمل اليدوي |
| الوقت المستثمر |  |  | عدة ساعات أسبوعيًا، محوّلة إلى مال |
| هامش احتياطي (10% - 20%) |  |  | الحوادث، والترقية، وتجاوز الترافيك |

## 10. خلاصة

- **قدّر الحجم أولًا، ثم اختر الحل.** فعدد اللاعبين، وهل هناك مودات، وهل هو مفتوح للعامة، تحدّد الخيارات التي لا تحتاج إلى التفكير فيها أصلًا.
- **أداء النواة الواحدة > عدد الأنوية**، و**IOPS القرص > سعة القرص** (بشرط الكفاية).
- **احسب فئات التكلفة الأربع — لمرة واحدة، والشهرية، والمتغيّرة، والوقت — منفصلةً**، فمعظم التكلفة المخفية في الثالثة والرابعة.
- **أفضل حلّ للخادم الصغير بسيط عادةً**: اللعب بين الأصدقاء يكفيه حاسوب منزلي أو أرخص VPS كافٍ، والمهم هو **النسخ الاحتياطي**.
- **الخادم العام أمر آخر**: فبمجرد الفتح للإنترنت، **تصبح الحماية الحقيقية والنسخ الاحتياطي الحقيقي خارج الموقع غير اختيارية**، وتُحدَّد ميزانية المضيف على هذا الأساس.
- **تأكّد من قدرة الانتقال عند الشراء**، لا عند لحظة الحاجة إلى الانتقال.
