**NDPReforged (NDPR)** منظومة **حجب موحّد لخوادم Minecraft** عابرة للمنصات: عدة خوادم تتشارك قاعدة بيانات حجب واحدة، فيتحقق **الحجب الموحّد والمزامنة اللحظية**. وهي مبنية على RESTful API، وتوثيقها الرسمي في <https://ndpreforged.com/wiki.php>، والموقع ولوحة المالك في <https://ndpreforged.com/>.

وهذه المقالة مرتّبة وفق التوثيق الرسمي (الإصدار الحالي **2.1.0**، وآخر تحديث للتوثيق 2026-08-16)، وكل بنود الإعداد وقيمها الافتراضية مرجعها التوثيق الرسمي.

## أولًا: ما المشكلة التي يحلّها

مشكلة الحجب المنفرد: تحجب مخرّبًا في خادم A فيلعب في خادم B كما يشاء؛ ولا يبقى بين المالكين إلا الصور والتبليغ الشفهي. وNDPR يضع بيانات الحجب في السحابة، فتتشارك كل الخوادم المنضمّة **القائمة نفسها**.

والخصائص الأساسية بحسب الموقع الرسمي:

| الخصيصة | الوصف |
| --- | --- |
| المصادقة الآمنة | مصادقة Token + ضبط الصلاحيات |
| دعم عابر للمنصات | MCDR، وBukkit/Paper، والمودات (Fabric/Forge/NeoForge)، وVelocity/BungeeCord، ونسخة Bedrock |
| المزامنة اللحظية | مزامنة فورية لبيانات الحجب بين عدة خوادم |
| التحقق بجهاز HWID | جمع بصمة المتصفح، والتحقق الآلي من الأجهزة في مكافحة الغش |
| مراجعة الحجب | تقديم طلب حجب، وتتم المزامنة بعد المراجعة السحابية |
| إحصاءات البيانات | وظيفة إحصاء كامل للاعتراضات |
| توافق النسخة القديمة | متوافق مع بروتوكول NDP القديم |

وتنقسم البنية إلى أربع طبقات: **لوحة الإدارة (Web) ← طبقة خدمة API (مصادقة Token / إدارة الحجب / إدارة المستخدمين / دفع البيانات / التحقق بجهاز HWID / المراجعة) ← طبقة البيانات (MySQL)**.

## ثانيًا: مصفوفة الدعم

| الخادم | حالة الدعم |
| --- | --- |
| MCDR 2.8+ | مدعوم |
| Java: Spigot / Bukkit / Paper / Folia | مدعوم |
| Fabric / Forge / NeoForge (Mod) | مدعوم |
| Velocity / BungeeCord (جهة الوسيط) | مدعوم |
| Bedrock: LeviLamina / BDSX / BDSpyrunner / gomint / Allay / Nukkit | مدعوم |

ثبّته مرة واحدة على **Velocity أو BungeeCord**، و**تحصل كل الخوادم الفرعية التابعة على الحماية من الحجب تلقائيًا**، بلا تثبيت عميل على كل خادم فرعي.
:::

## ثالثًا: التثبيت

### 1. MCDR (نسخة Java)

المتطلبات: **MCDR 2.8+**، و**Python 3.8+**.

```bash
!!MCDR plugin install ndpr
```

ويمكن أيضًا التنزيل اليدوي من صفحة إصدارات GitHub، ووضع الملف في دليل ملحقات MCDR.

### 2. جهة الملحقات (Bukkit / Spigot / Paper / Folia)

المتطلبات: **MC 1.20.1+**، و**Java 17+**.

1. ضع `NDPR-Bukkit-2.1.0.jar` في دليل `plugins/` بالخادم
2. شغّل الخادم، فيولّد الملحق ملف الإعداد تلقائيًا

**jar واحد يعمل على Bukkit / Spigot / Paper / Folia.**

### 3. Mod (Fabric / Forge / NeoForge)

الإصدارات المدعومة: **1.20.4 / 1.20.6 / 1.21.1 / 1.21.4 / 1.21.6 / 1.21.9 / 1.21.11 / 26.2**.

ضع `NDPR-MOD-2.1.0.jar` في دليل `mods/`، وشغّل اللعبة أو الخادم. **والـ jar نفسه يدعم المحمّلات الثلاثة.**

### 4. جهة الوسيط (Velocity / BungeeCord)

المتطلبات: **Velocity 3.x** أو **BungeeCord (MC 1.20.1+)**، و**Java 17+**.

ضع `ndpr-proxy.jar` في دليل `plugins/` في الوسيط، وأعد تشغيل الوسيط.

### 5. نسخة Bedrock

| المنصة | طريقة التثبيت |
| --- | --- |
| BDSpyrunner | ضع `ndpr.py` في دليل `plugins/` |
| BDSX | ضع حزمة npm في دليل `plugins/ndpr/` |
| LeviLamina | `plugins/ndpr/` (dll + `manifest.json`) |
| Nukkit / Allay / gomint | ضع `ndpr.jar` في دليل `plugins/` |

## رابعًا: الإعداد (خمس خطوات)

### الخطوة 1: الحصول على UUID

**جهة MCDR**، بطريقتين:

الطريقة الأولى، من سجل الإقلاع:

```text
[MCDR] [20:21:33] [TaskExecutor/INFO] [ndpr]: نوع الخادم: xx
[MCDR] [20:21:33] [TaskExecutor/INFO] [ndpr]: UUID: xxxx-xxxx-xxxx-xxxx-xxxx-xxxx-xxxx-xxxx
[MCDR] [20:21:34] [TaskExecutor/INFO] [ndpr]: تم تحميل ملحق NDPR
```

والطريقة الثانية، قراءته من ملف الإعداد بعد التشغيل الثاني، والدليل `MCDR root\config\ndpr\config.toml`:

```toml
uuid = "xxxx-xxxx-xxxx-xxxx-xxxx-xxxx-xxxx-xxxx"
```

**وسائر المنصات** (جهة الملحقات / Mod / جهة الوسيط / Bedrock) **تحصل على UUID تلقائيًا عند التشغيل الأول وتكتبه في ملف الإعداد**، بلا تعبئة يدوية. وإن احتجت التأكد يدويًا فابحث وفق الجدول:

| المنصة | موضع ملف الإعداد | الحقل |
| --- | --- | --- |
| Bukkit/Paper | `plugins/NDPR-Bukkit/config.yml` | `uuid` |
| Mod | `.minecraft/config/ndpr.json` | `uuid` |
| Velocity | `plugins/ndpr/config.toml` | `uuid` |
| BungeeCord | `plugins/NDPReforged-Proxy/config.toml` | `uuid` |
| Bedrock (BDSpyrunner/BDSX/LeviLamina/Nukkit/Allay/gomint) | `plugins/ndpr/config.json` | `uuid` |

### الخطوة 2: الحصول على Token

1. افتح الموقع <https://ndpreforged.com/>، وانقر **إدارة المالك** في الأعلى أو أعلى اليسار
2. سجّل الدخول أو أنشئ حسابًا (وتمرير التحقق بالسحب أبطأ قليلًا يسهّل النجاح)
3. انقر **إدارة Token** على اليسار
4. في «إنشاء Token جديد» املأ UUID من الخطوة السابقة، وولّد الـ Token
5. اختياري: انقر **صلاحية الرفع** على اليسار، واطلب صلاحية الرفع بجانب الـ Token وانتظر المراجعة

### الخطوة 3: ضبط Token

**جهة MCDR** (`MCDR root\config\ndpr\config.toml`):

```toml
token = "xxxxxxxxxxxxxxxxxxxx"
```

وموضع الحقل في المنصات الأخرى:

| المنصة | ملف الإعداد | الحقل |
| --- | --- | --- |
| Bukkit/Paper | `plugins/NDPR-Bukkit/config.yml` | `token` |
| Mod | `.minecraft/config/ndpr.json` | `token` |
| Velocity / BungeeCord | `plugins/ndpr/config.toml` | `token` |
| Bedrock | `plugins/ndpr/config.json` | `token` |

:::warn Token غير مملوء يعني تثبيتًا بلا فائدة
**الـ Token يفعّل وظيفة الحجب، وبدون ضبطه لا ينفّذ الملحق فحص الحجب.** فتثبيت الملحق بلا Token يعني حماية فارغة.
:::

### الخطوة 4: ضبط نوع الخادم

**جهة MCDR**:

```toml
onlinemode = true   # true = خادم أصلي، false = خادم دون اتصال
```

| المنصة | ملف الإعداد | الحقل |
| --- | --- | --- |
| Bukkit/Paper | `plugins/NDPR-Bukkit/config.yml` | `onlinemode` (إلزامي) |
| Mod | `.minecraft/config/ndpr.json` | `onlinemode` (إلزامي) |
| Velocity / BungeeCord | `plugins/ndpr/config.toml` | `onlinemode` (اتركه فارغًا لاستخدام نمط الوسيط نفسه) |
| Bedrock | `plugins/ndpr/config.json` | `onlinemode` (Bedrock يوحّد دخول Xbox، ويُمرَّر) |

:::warn نسخة Java يجب أن تملأ onlinemode
**حقل `onlinemode` إلزامي في كل منصات نسخة Java، وإلا لم يُحمَّل الملحق طبيعيًا.**
:::

### الخطوة 5: بقية بنود الإعداد

| بند الإعداد | الوصف | القيمة الافتراضية |
| --- | --- | --- |
| `api_url` | عنوان API | `https://api.ndpreforged.com` |
| `language` | اللغة (`zh_CN` / `en_us`) | `zh_CN` |
| `download_interval` | فاصل التحديث التلقائي لقاعدة الحجب (ثانية)، و`0` = تعطيل | `900` |
| `check_hwid` | تفعيل التحقق بجهاز HWID | `false` |
| `check_interval` | أيام الإعفاء من الفحص بعد النجاح | `3` |
| `fail_closed` | رفض الدخول عند غياب قاعدة الحجب (الأمان أولًا) | `false` |
| `verify_timeout` | مهلة التحقق بـ HWID (ثانية، 30~600) | `60` |
| `freeze_interval` | فاصل تثبيت الإحداثيات أثناء التحقق (ثانية، 1~60) | `1` |

**مثال كامل لجهة MCDR** (`MCDR root\config\ndpr\config.toml`):

```toml
uuid = "xxxx-xxxx-xxxx-xxxx-xxxx-xxxx-xxxx-xxxx"
token = "xxxxxxxxxxxxxxxxxxxx"
onlinemode = true
api_url = "https://api.ndpreforged.com"
language = "zh_CN"
download_interval = 900
check_hwid = false
check_interval = 3
fail_closed = false
verify_timeout = 60
freeze_interval = 1
```

## خامسًا: الأوامر

### جهة MCDR

الأمر الرئيسي `!!NDPR` أو `!!ndpr`.

| الأمر | الوصف |
| --- | --- |
| `ban <ID> <السبب>` | حجب لاعب |
| `check <ID>` | فحص حالة حجب اللاعب |
| `download` / `d` | تحديث بيانات الحجب |
| `checkupdate` / `cu` | فحص التحديثات |
| `help` | عرض معلومات المساعدة |
| `reload` | إعادة تحميل ملف الإعداد |
| `auth <اللاعب>` | إجبار بدء التحقق بجهاز اللاعب |

### المنصات الأخرى (جهة الملحقات / Mod / جهة الوسيط / Bedrock)

بادئة الأوامر موحّدة `/ndpr` (وجهة الوسيط وBedrock لا تملك أوامر بادئتها `!!`).

| الأمر | الوصف | الصلاحية |
| --- | --- | --- |
| `/ndpr`، `/ndpr help` | معلومات المساعدة | الجميع |
| `/ndpr d`، `/ndpr download` | تنزيل قاعدة بيانات الحجب يدويًا | `ndpr.admin` |
| `/ndpr ban <اللاعب> <السبب>` | تقديم طلب حجب للمراجعة | `ndpr.admin` |
| `/ndpr check <ID/IP/UUID>` | فحص حالة الحجب (ويعطي اقتراحات تقريبية عند عدم المطابقة) | الجميع |
| `/ndpr reload` | إعادة تحميل الإعداد وتنزيل قاعدة الحجب من جديد | `ndpr.admin` |
| `/ndpr cu`، `/ndpr checkupdate` | فحص تحديثات الملحق | `ndpr.admin` |
| `/ndpr auth <اللاعب>` | إجبار بدء التحقق بجهاز اللاعب | `ndpr.admin` |

و`ndpr.admin` تُمنح **OP** افتراضيًا (وفي MCDR مستوى الصلاحية 2).

## سادسًا: نقاط تحتاج موازنتها بنفسك

1. **`fail_closed`: الأمان مقابل التوافر**. الافتراضي `false` — أي **السماح** عند تعذّر جلب قاعدة الحجب السحابية، فيعمل الخادم كالمعتاد؛ وتحويله إلى `true` يعني **رفض الدخول**، والأمان أولًا، لكن اللاعبين يُمنعون عند عطل سحابي. وقد يختلف اختيار الخادم العام عن خادم الأصدقاء.
2. **`check_hwid`: مكافحة الغش مقابل الخصوصية**. عند تفعيله يُستخدم **جمع بصمة المتصفح** للتحقق من الجهاز (مع `verify_timeout` لمهلة التحقق، و`freeze_interval` لفاصل تثبيت الإحداثيات أثناء التحقق، و`check_interval` لأيام الإعفاء). وهذا **أقوى وسيلة تعريف من IP**، لكنه يتضمن جمع معلومات جهاز اللاعب — وقد أوضح التوثيق الرسمي غرضه، **وعليك بيانه للاعبين في قواعد الخادم** قبل تفعيله.
3. **`download_interval`**: الافتراضي 900 ثانية (15 دقيقة) للمزامنة. وتصغيره يزيد معدل الطلبات، وتكبيره يؤخّر سريان الحجب؛ و`0` يعني تعطيل التحديث التلقائي (ولا يبقى إلا السحب اليدوي بـ `/ndpr d`).
4. **جهة الوسيط أولًا**: إن كانت البنية Velocity/BungeeCord، فالتثبيت مرة واحدة على الوسيط يغطي كل الخوادم الفرعية، وأقل عرضةً للنسيان من التثبيت على كل خادم فرعي.

## سابعًا: مرجع سريع للتشخيص

| العَرَض | افحص أولًا |
| --- | --- |
| الملحق محمّل لكن بلا أي اعتراض | **هل مُلئ Token** (بدونه = بلا فحص) |
| الملحق لا يُحمَّل / لا يعمل | هل مُلئ **`onlinemode`** في نسخة Java (إلزامي) |
| تعذّر جلب قاعدة الحجب | هل `api_url` صحيح (الافتراضي `https://api.ndpreforged.com`)، وهل `download_interval` يساوي `0`، وهل المضيف يصل إلى الإنترنت |
| اللاعب المحجوب ما زال يدخل | هل التثبيت على **جهة الوسيط**، وهل الخوادم الفرعية تتجاوز الوسيط باتصال مباشر، وهل قاعدة الحجب مزامنة |
| تريد تحديث القائمة يدويًا | `/ndpr d` (وفي MCDR `!!ndpr d`) |
| تريد سريان تعديل الإعداد فورًا | `/ndpr reload` (يعيد تحميل الإعداد وينزّل قاعدة الحجب من جديد) |
