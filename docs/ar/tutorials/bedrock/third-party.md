BDS الرسمي مستقر لكنه صعب التوسيع. وإن أردت الملحقات وتعدد الأنوية والتخصيص فلا بد من نواة طرف ثالث. وتوضّح هذه المقالة **مسار البدء** في ثلاث نوى شائعة من طرف ثالث.

## أولًا: عائلة Nukkit

Nukkit هو «Bukkit نسخة Bedrock»: **مكتوب بـ Java**، وله منظومة ملحقات أصلية، وإعداده بسيط. وقد تفرّع إلى فروع كثيرة، وعند الاستخدام الفعلي **قدّم الفرع النشط**:

| الفرع | الوصف |
| --- | --- |
| **Nukkit (الأصلية)** | أقدم أصل، وصار غير نشط، ولا يُنصح به للمشاريع الجديدة |
| **PowerNukkitX (PNX)** | الفرع الرئيسي الحديث، **يدعم أحدث بروتوكول + تحسين تعدد الأنوية**، وهو الخيار الأول |
| **NukkitX** | فرع تاريخي |
| **NukkitMot** | فرع تاريخي |
| **PM1E** | فرع تاريخي مرتبط بـ PocketMine (وللمجتمع خلاف حول تاريخه) |
| **PNX** | اختصار PowerNukkitX |

**التحضير**: عائلة Nukkit برامج Java، **فتحتاج تثبيت Java** (كما في نسخة Java، انظر فصل Java في «تجهيز البيئة (Windows وLinux)»).

**البدء**: نزّل jar النواة ← ضعه في الدليل ← اكتب سكربت تشغيل (`java -jar <core-name>.jar`) ← يولّد التشغيل الأول ملفات الإعداد ← ثبّت الملحقات في `plugins/`.

### لماذا يستحق PowerNukkitX الاختيار

- **تحسين تعدد الأنوية** —— وهذه أكبر ميزة له على BDS، فحساب BDS يقع أساسًا على نواة واحدة؛
- **يدعم أحدث بروتوكول Bedrock**، بلا انتظار طويل؛
- **ارتفاع عالم 384 كتلة**، ومولّد تضاريس **Terra** مدمج؛
- **مفتوح المصدر بالكامل وAPI مفتوح**، ويمكن كتابة الملحقات بـ Java / Kotlin / Scala / Python / JavaScript / Lua؛
- **متوافق مع كثير من ملحقات منظومة Nukkit**.

والكلفة: ملحقات كثيرة وبنود إعداد كثيرة، **فمنحنى تعلّم المبتدئ حاد نسبيًا**؛ وقد يتأثر إيقاع التطوير بتغيّرات فريق الأصل.

## ثانيًا: PocketMine-MP (PMMP)

خادم Bedrock مكتوب بـ **PHP**، وله **أكبر منظومة ملحقات**.

**التحضير**: يحتاج **بيئة تشغيل PHP** (لا Java). ويُستحسن تثبيت إصدار PHP المقابل وفق التوثيق الرسمي وضبط الإضافات ذات الصلة.

**البدء**: نزّل PMMP (عادةً ملف `.phar`) ← شغّله بـ PHP (`php PocketMine-MP.phar`) ← يولّد الإعداد والأدلة ← ضع الملحقات في `plugins/`.

**المزايا**: ملحقات كثيرة جدًا، وعابر للمنصات، و**من يعرف PHP يكتب الملحقات**، ومجتمع نشط، ودرجة تخصيص عالية.

**العيوب**: **عنق أداء عند الحمل العالي** (إدارة الذاكرة وكفاءة المعالج)؛ وتأخّر التحديثات؛ وتراجع الاستقرار مع كثرة الملحقات؛ و**استهلاك موارد أوضح** لأن PHP لغة تفسيرية.

:::tip عائلة Nukkit أم PMMP؟
- إن كنت **تعرف Java** وتريد **أداء أفضل** ← **PowerNukkitX**
- إن كنت **تعرف PHP** وتريد **أكثر الملحقات الجاهزة** ← **PocketMine-MP**
- وإن لم تكن تعرف أيًّا منهما ← شغّل **BDS** أولًا، ثم فكّر في طرف ثالث
:::

## ثالثًا: خوادم أخرى

إلى جانب ما سبق، في المجتمع نوى صغيرة أو لأغراض خاصة:

| النواة | التصنيف |
| --- | --- |
| **Allay** | خادم Bedrock طوّره المجتمع |
| **Dragonfly** | خادم Bedrock مكتوب بـ Go، موجّه للأداء |
| **MCPEServer** | خادم Bedrock مبكّر |
| **WaterDogPE** | **خادم وسيط** (مقابل Velocity / BungeeCord في نسخة Java)، لربط عدة خوادم فرعية |

> **منظومة الملحقات والتوثيق في النوى الصغيرة رقيقة عادةً**، ويصعب طلب المساعدة عند المشكلات. وما لم يكن لديك سبب واضح، **لا يُنصح المبتدئ باختيارها**.

### WaterDogPE: لا يُحتاج إليه إلا مع عدة خوادم فرعية

كما في نسخة Java، لـ Bedrock **خادم وسيط** أيضًا: لا يشغّل عالمًا بنفسه، بل يمرّر اللاعبين إلى الخوادم الفرعية الخلفية. ويناسب بنية متعددة الخوادم مثل «ردهة + بقاء + ألعاب صغيرة». **والخادم الواحد لا يحتاجه**، فكل طبقة إضافية نقطة عطل إضافية.

## رابعًا: توصيات عامة

1. **محاذاة الإصدارات**: يجب محاذاة إصدار النواة والبروتوكول والملحقات، وBedrock في هذا أشدّ صرامةً بكثير من نسخة Java.
2. **الصغير أولًا**: شغّل أصغر خادم صالح، ثم أضف الملحقات تدريجيًا.
3. **انظر النشاط**: قدّم النوى والملحقات **التي ما زالت تُحدَّث حديثًا**، فما طال توقفه يُخطئ حتمًا مع الإصدار الجديد.
4. **النسخ الاحتياطي أولًا**: توافق حفظ النوى من طرف ثالث أقل من الرسمي، **فانسخ احتياطيًا دائمًا قبل الترقية/تبديل النواة** (انظر «النسخ الاحتياطي والاستعادة»).
