**BDS** الرسمي أثبت خيارات Bedrock، لكنه **لا يدعم الملحقات بنفسه**. وتوضّح هذه المقالة بنية أدلته، وكيف تُكمَل قدرة الملحقات بمحمّل مجتمعي.

## أولًا: بنية الأدلة

BDS بعد فك الضغط مجموعة أدلة «محمولة»، ويكفي معرفة هذه:

| الملف / الدليل | الوظيفة | هل يمكن تحريكه |
| --- | --- | --- |
| `bedrock_server.exe` | **برنامج تشغيل الخادم** (وبلا `.exe` على Linux) | يمكن إعادة تسميته، لكنه **غير مُستحسن** — فبعد التسمية يجب تحديث مسار التشغيل في السكربت/اللوحة، ويسهل الخطأ |
| `server.properties` | إعداد الخادم (المنفذ والصعوبة والنمط وغيرها) | يُعدّل كثيرًا |
| `allowlist.json` | قائمة **القائمة البيضاء** (تُدار هنا بعد تفعيلها في `server.properties`) | قابل للتعديل |
| `permissions.json` | بيانات **المشرف (OP)** (UUID والاسم والصلاحيات) | قابل للتعديل |
| `valid_known_packs.json` | قائمة الحزم الإضافية المعروفة (حزم السلوك / حزم الموارد)، ويتحقق منها الخادم |   لا يُعدّل عادةً |
| `worlds/` | **حفظ العالم** (مجلد فرعي لكل عالم) | يُنسخ كاملًا فقط |
| `bedrock_server.pdb` | ملف قاعدة بيانات البرنامج للتنقيح | لا تمسّه |
| `bedrock_server_how_to.html` | شرح الاستخدام الرسمي |   للقراءة |
| `release-notes.txt` | سجل تحديثات الإصدار |   للقراءة |

### ماذا في مجلد العالم

تحت `worlds/<اسم-العالم>/`:

| الملف / الدليل | المحتوى |
| --- | --- |
| `db/` | **بيانات الحفظ** (ملفات قاعدة بيانات العالم، وهي الأكبر حجمًا) |
| `level.dat` | إعدادات العالم وخصائصه الأساسية (قواعد اللعب والوقت والطقس وغيرها) |
| `level.dat_old` | إعدادات الحفظ القديمة (تُستخدم عند التحديث أو النسخ الاحتياطي) |
| `level_name.txt` | اسم العالم |

:::warn النسخ الاحتياطي يعني نسخ `worlds/`
حفظ BDS كله داخل `worlds/`، **فانسخ الدليل كاملًا**. ولا تنسخ `db/` وحدها، وإلا ضاعت الإعدادات.
:::

## ثانيًا: إضافة الملحقات إلى BDS: ثلاثة محمّلات شائعة

لا يملك BDS الرسمي منظومة ملحقات، فصنع المجتمع محمّلات تكملها. وأشهرها ثلاثة الآن:

### LeviLamina (ويُعرف أيضًا LLL / LLv3) —— **الأكثر توصية**

- المؤلف: LiteLDev (وسلفه **LiteLoaderBDS**)
- التصنيف: محمّل ملحقات BDS خفيف ومعياري ومتعدد الوظائف
- **درجة التوصية: موصى به بشدة** —— أفضل منظومة ملحقات، واستمرار لقمة عصر LiteLoader
- الإصدارات المدعومة: 1.20.61 – 1.21.3 (ويُحدَّث باستمرار)

### EndStone —— ذو إمكانات

- المؤلف: EndStoneMC
- التصنيف: يوفّر **واجهة ودّية شبيهة بـ Bukkit**، ويمكن كتابة الملحقات بـ **C++ أو Python**
- **درجة التوصية: موصى به نسبيًا** —— منظومة ملحقاته قليلة جدًا حاليًا، لكن في المجتمع من يشارك في تطويره، وقد يلحق بـ LeviLamina لاحقًا
- الإصدارات المدعومة: 1.20.71 – 1.21.2 (ويُحدَّث باستمرار)

### BDSX —— عريق ومستقر

- التصنيف: نسخة معدّلة من BDS تدعم **Node.js**، مبنية على BDS الرسمي، تحفظ كل خصائص النسخة الأصلية، وتدعم خطّافات الدوال وحزم بيانات الشبكة
- **درجة التوصية: موصى به إلى حدٍّ ما** —— ملحقاته المحلية ليست كثيرة، لكن مستخدميه كثر، ويصونه المؤلف من 2019 حتى اليوم
- الإصدارات المدعومة: 1.12 – الأحدث (ويُحدَّث باستمرار)

> وإلى جانب هذه الثلاثة يوفّر المسؤولون **محمّل سكربتات** (مبني على واجهة السكربتات الرسمية)، وقدرته أضعف من محمّلات الطرف الثالث، لكن ميزته أنه رسمي.

### كيف تختار

| حالتك | التوصية |
| --- | --- |
| تريد ملحقات جاهزة، والمنظومة أولوية | **LeviLamina** |
| تتقن C++ / Python وتريد الكتابة بنفسك | **EndStone** |
| تعرف Node.js / تحتاج خطّافات منخفضة المستوى | **BDSX** |
| تريد قدرات رسمية فقط بلا طرف ثالث | محمّل السكربتات الرسمي |

:::warn المحمّل مرتبط بإصدار اللعبة ارتباطًا صارمًا
المحمّل يدعم **مدى إصدارات محددًا فقط**. **تأكد أولًا أن إصدار خادمك داخل قائمة الدعم** ثم ثبّته، وإلا فشل التحميل بل قد لا يبدأ. وقبل ترقية إصدار اللعبة تأكد كذلك هل لحق المحمّل الترقية.
:::

## ثالثًا: مزلقتان معروفتان في BDS

1. **عنق النواة الواحدة**: حساب الكائنات أحادي الخيط ← والسلاسة تعتمد على **أداء النواة الواحدة**، وكلما كبرت الخريطة زاد التقطيع.
2. **نمو الذاكرة البطيء**: الاستهلاك يزيد تدريجيًا. وانتبه إلى **عدم إجبار تنظيف الذاكرة** — فذلك يوقف شريط تقدّم تنزيل اللاعبين لحزم المواد/الإضافات، **ولا يبقى إلا إعادة تشغيل الخادم**.
