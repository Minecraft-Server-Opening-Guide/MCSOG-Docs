تناولت مقالة [النوى من طرف ثالث (Nukkit / PNX / PMMP)](/tutorials/bedrock/third-party) «أي واحدة تختار». وهذه تتناول «كيف تشغّلها بعد الاختيار»: ما تجهّزه، وكيف تبدو الأدلة، وكيف يُكتب سكربت التشغيل، وأين تُوضع الملحقات، وأكثر خطوة إخفاقًا — **عدم تطابق بناء النواة مع إصدار بروتوكول Bedrock**.

## أولًا: قبل البدء: تأكد ثلاثة أمور

| ما يجب تأكيده | الوصف |
| --- | --- |
| **عائلة النواة** | عائلة Nukkit برامج **Java**، وPocketMine-MP برنامج **PHP**. فاختيار العائلة الخطأ يعني إعادة كل بيئة التشغيل لاحقًا |
| **بيئة التشغيل** | عائلة Nukkit تثبّت **Java**؛ وPMMP تثبّت **PHP**. ولا تُغني إحداهما عن الأخرى |
| **محاذاة الإصدار** | بناء النواة يجب أن **يطابق إصدار بروتوكول Bedrock الذي ستتصل به**، وإلا لم يتصل العميل مباشرةً |

### بيئة Java (عائلة Nukkit)

عائلة Nukkit برامج Java كخادم نسخة Java، فثبّتها بمنطق نسخة Java، انظر [تجهيز البيئة (Windows وLinux)](/tutorials/java/environment).

ونقطتان:

- **الإصدار كافٍ**: الفروع الجديدة تطلب عادةً Java أحدث (الشائع Java 17 وما فوق)، وتثبيت إصدار قديم جدًا يفشل الإقلاع مباشرةً، ورسالة الخطأ توضّح المتطلب عادةً.
- **عدد البتّات صحيح**: نظام 64 بت مع Java 64 بت. وتثبيت 32 بت ينهار عند الإقلاع أو في منتصف التشغيل بسبب سقف الذاكرة.

### بيئة PHP (PocketMine-MP)

يحتاج PMMP **PHP**، لا Java.

:::tip استخدم PHP المحزومة مع PMMP، ولا تجمع البيئة بنفسك
موقع PHP يوفّر **نسخة نقية** لا تحمل الإضافات التي يحتاجها PMMP افتراضيًا؛ وإكمال الاعتماديات واحدةً واحدة متعب جدًا، ويسهل الاختلاط مع كثرة الإصدارات. **ويُوصى بتنزيل وقت تشغيل PHP الذي يحزمه PMMP رسميًا لكل نظام** (من GitHub Releases بحسب نظامك)، فاستخراجه يكفي.
:::

:::warn لا تستخدم PHP المدمجة في النظام
إصدار PHP في مستودعات توزيعات Linux قديم عادةً، وفي Windows قد يكون هناك PHP خلفته برامج أخرى. تحقق أولًا من خرج `php -v`، وتأكد أن ما تشغّل به الخادم هو **الذي تقصده**.
:::

## ثانيًا: بنية الأدلة: عائلة Nukkit مقابل PocketMine-MP

### عائلة Nukkit

بعد التشغيل الأول يكون الدليل الجذري تقريبًا هكذا (وتختلف الفروع قليلًا):

| الملف / الدليل | الوظيفة |
| --- | --- |
| `nukkit-1.0-SNAPSHOT.jar` وأمثاله | **برنامج النواة نفسه**، وهو ما يُشغَّل |
| `start.bat` / `start.sh` / `start.command` | سكربت التشغيل، لـ Windows / Linux / macOS على الترتيب |
| `server.properties` | ملف الإعداد الرئيسي: اسم الخادم والمنفذ وأقصى عدد لاعبين ونمط اللعب وغيرها |
| `permissions.yml` | تعريف الصلاحيات |
| `ops.txt` | قائمة المشرفين (OP) |
| `whitelist.txt` | قائمة القائمة البيضاء (لا تسري إلا بعد تفعيلها في `server.properties`) |
| `banned-players.txt` / `banned-ips.txt` | اللاعبون وعناوين IP المحجوبون |
| `rcon_password.txt` | كلمة مرور التحكم البعيد RCON |
| `worlds/` | **الدليل العام لحفظ العوالم**، بمجلد فرعي لكل عالم |
| `plugins/` | **دليل الملحقات**، وفيه توضع `.jar` |
| `logs/` | سجلات التشغيل |

وداخل دليل العالم `worlds/<اسم-العالم>/`:

| الملف / الدليل | المحتوى |
| --- | --- |
| `level.dat` | إعدادات العالم الأساسية |
| `region/` | **بيانات القطع** (التضاريس والمباني، وهي الأكبر) |
| `entities/` | بيانات الكائنات |

:::warn النسخ الاحتياطي يعني نسخ `worlds/`
كما في BDS، حفظ Bedrock **وحدة واحدة**. فانسخ `worlds/` كاملًا عند النسخ الاحتياطي، ولا تنتقِ `region/` وحدها.
:::

### PocketMine-MP

فكرة أدلة PMMP مشابهة، لكن شكل الملفات مختلف:

| الملف / الدليل | الوظيفة |
| --- | --- |
| `PocketMine-MP.phar` | **برنامج النواة نفسه** (و`.phar` صيغة حزم PHP) |
| وقت تشغيل PHP | المشغّل وملف `php` التنفيذي؛ وفي النسخة المحزومة الرسمية يكونان في الدليل نفسه |
| `start.bat` / `start.sh` | سكربت التشغيل |
| `server.properties` | ملف الإعداد الرئيسي |
| `pocketmine.yml` | إعداد PMMP نفسه |
| `plugins/` | **دليل الملحقات**، وفيه توضع `.phar` |
| `worlds/` | الدليل العام لحفظ العوالم |
| `players/` | بيانات اللاعبين |
| `logs/` | سجلات التشغيل |

### مقارنة الجانبين

| | عائلة Nukkit | PocketMine-MP |
| --- | --- | --- |
| ملف النواة | `.jar` | `.phar` |
| بيئة التشغيل | Java | PHP |
| لاحقة الملحق | `.jar` | `.phar` |
| دليل الملحقات | `plugins/` | `plugins/` |
| دليل العالم | `worlds/` | `worlds/` |
| الإعداد الرئيسي | `server.properties` | `server.properties` |
| قائمة المشرفين | `ops.txt` | يديرها إعداد النواة والأوامر |
| البنية الداخلية للعالم | `level.dat` + `region/` + `entities/` | `level.dat` + `region/` + `entities/` |

:::note مزلق مشترك: بلا محارف غير لاتينية ولا مسافات في المسار
أيًّا كانت النواة، يُستحسن وضع دليل الخادم في مسار **إنجليزي صرف بلا مسافات**. فالمسارات غير اللاتينية تُفشل قراءة العالم أو الملحقات في بعض الفروع واللوحات، ورسائل الخطأ غالبًا عصيّة على الفهم.
:::

## ثالثًا: تشغيل الخادم

### عائلة Nukkit

أصغر أمر تشغيل صالح هو `java -jar` واحد:

```bat
@echo off
java -Xms1G -Xmx4G -jar nukkit-1.0-SNAPSHOT.jar
pause
```

والكتابة المكافئة على Linux / macOS:

```sh
#!/bin/sh
java -Xms1G -Xmx4G -jar nukkit-1.0-SNAPSHOT.jar
```

وتوضيح:

- `-Xms` كومة البداية، و`-Xmx` أقصى كومة؛ **ويُستحسن ضبطهما على القيمة نفسها**، لتجنّب توسيع متكرر أثناء التشغيل.
- ولا تتجاوز `-Xmx` الذاكرة الفعلية للجهاز، وإلا بدأ النظام يستخدم قسم المبادلة، فيزيد التقطيع.
- وفي Windows أضف `pause` في آخر `.bat`، فلا تختفي النافذة فورًا بعد الانهيار، وتبقى لك فرصة رؤية الخطأ.

### PocketMine-MP

```bat
@echo off
php PocketMine-MP.phar
pause
```

وعلى Linux / macOS:

```sh
#!/bin/sh
./bin/php7/bin/php PocketMine-MP.phar
```

وتوضيح:

- المسار المحدد يعتمد على استخدام PHP المحزومة رسميًا أم بيئة مثبَّتة بنفسك. **تأكد أولًا بـ `php -v` أنك تصل إليه**، ثم اكتبه في السكربت.
- وسقف الذاكرة لا يُضبط بمعاملات سطر الأوامر، بل في `pocketmine.yml` و`server.properties`.

:::tip ماذا تنظر إليه عند التشغيل الأول
يولّد التشغيل الأول ملفات الإعداد والعالم. وبعد اكتماله انتبه إلى أمرين: **هل في الكونسول أخطاء**، و**هل ظهر فعلًا `plugins/` و`worlds/` في الدليل**. فإن لم تُولَّد الأدلة فالنواة لم تعمل، فلا تستعجل تثبيت الملحقات.
:::

:::warn لا تمنح الذاكرة كلها مرة واحدة
الخادم الجديد بلا لاعبين، فاضبط `-Xmx` صغيرًا أولًا (مثل 2G)، ثم عدّله بعد إقبال اللاعبين. فمنح سقف الذاكرة الفعلية كله يجعل النظام والنواة يتنازعان الذاكرة.
:::

## رابعًا: أين توضع الملحقات وكيف تُحمَّل

1. نزّل الملف المقابل من صفحة إصدار الملحق: عائلة Nukkit تريد `.jar`، وPMMP تريد `.phar`.
2. ضعه في `plugins/` في جذر الخادم.
3. **أعد تشغيل الخادم**.
4. راقب خرج الكونسول، وتأكد من تحميل الملحق وخلوّه من الأخطاء.
5. وبعض الملحقات تولّد دليل إعدادها `plugins/<plugin-name>/` بعد التحميل الأول، فعدّل الإعداد ثم أعد التشغيل مرة.

وعن إعادة التحميل:

- معظم الملحقات تدعم أمر إعادة تحميل، لكن **إعادة التحميل لا تساوي إعادة التشغيل**. فعند تعديل إعداد النواة أو تبديل إصدار ملحق أو تسجيل أحداث متبادل بين الملحقات، تُبقي إعادة التحميل حالات قديمة غالبًا، فيظهر «عدّلت ولم يعمل» أو خطأ مباشر.
- والخلاصة: **الإعداد يمكن إعادة تحميله، وتثبيت الملحق/حذفه/تبديله يعني إعادة تشغيل دائمًا**.

:::warn لا تُدخل ملحقات نسخة Java هنا
ملفات `.jar` في عائلة Nukkit وملفات `.jar` في نسخة Java (Paper / Spigot) شيئان مختلفان تمامًا، و**لا يعمل أحدهما محل الآخر**. فتحقق قبل التنزيل من منصة الملحقات هل الوسم Nukkit / PNX أم Paper، فالتثبيت على النواة الخطأ يعطي عادةً رسالة واحدة: «ملف ملحق غير صالح».
:::

## خامسًا: أكثر خطوة إخفاقًا: محاذاة الإصدار

هذه النقطة أشدّ صرامةً في Bedrock منها في نسخة Java، ولذلك تُفرد هنا.

عميل Bedrock **يتحدّث تلقائيًا**، ولا يستطيع اللاعب البقاء على إصدار قديم كما في نسخة Java. لذلك:

- بناء نواك يجب أن **يدعم إصدار بروتوكول Bedrock الحالي**، وإلا رأى اللاعب رسالة من نوع «خادم قديم جدًا»، ولم يتصل مباشرةً.
- وإن صحّ إصدار النواة فالملحقات تحتاج كذلك: فهي تسير وفق واجهة النواة، و**بمجرد ترقية النواة قد يبطل الملحق القديم فورًا**.
- لذلك ترقية النوى من طرف ثالث **طقم واحد**: النواة + الملحقات + الإعداد تُبدَّل معًا، ولا يُبدَّل أحدها وحده.

وترتيب تشخيص تعذّر الاتصال:

| العَرَض | افحص أولًا |
| --- | --- |
| رسالة أن إصدار الخادم قديم | هل بناء النواة يدعم بروتوكول Bedrock الحالي |
| العميل يتوقف عند «جارٍ الاتصال» | هل المنفذ مفتوح، وهل منفذ `server.properties` يطابق التحويل |
| الدخول يعمل والملحقات لا تتفاعل | هل حُمّلت الملحقات، وهل إصدارها يطابق النواة |
| طرد فور الدخول | هل القائمة البيضاء مفعّلة، وهل هناك سجل في `banned-*` |

:::tip انسخ احتياطيًا قبل الترقية
**توافق حفظ النوى من طرف ثالث أقل من BDS الرسمي**. وقبل تبديل النواة أو ترقية رئيسية، انسخ `worlds/` كله وإعدادات `plugins/`، انظر [النسخ الاحتياطي والاستعادة](/tutorials/java/backup).
:::

## سادسًا: قائمة فحص البدء

- [ ] بيئة التشغيل مثبَّتة وقابلة للاستدعاء من سطر الأوامر (`java -version` / `php -v`)
- [ ] بناء النواة مطابق لإصدار بروتوكول Bedrock الهدف
- [ ] مسار الدليل إنجليزي صرف بلا مسافات
- [ ] معاملات الذاكرة في سكربت التشغيل معقولة
- [ ] التشغيل الأول يولّد `plugins/` و`worlds/`، والكونسول بلا أخطاء
- [ ] لاحقة الملحق تطابق عائلة النواة
- [ ] `worlds/` مُدرَج في خطة النسخ الاحتياطي
