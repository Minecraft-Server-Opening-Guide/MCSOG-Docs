إلقاء الملحق في `plugins/` هو مجرد إتمام التثبيت، أما ما يحدّد فعلًا «سلاسة» الخادم فهو عشرات ملفات `config.yml` التي تليه. فالإعداد الصحيح وظيفة، وخطأ مسافة واحدة قد يجعل مقطعًا كاملًا غير قابل للقراءة.

وتشرح هذه المقالة ثلاثة أمور: **كيف تكتب YAML، وكيف تستخدم رموز الألوان، وكيف تتجنّب تشويه الترميز**، ثم تقدّم مسارًا ثابتًا لتعديل الإعدادات.

## 1. أين تُوضع إعدادات الملحق

تضع الغالبية العظمى من الملحقات ملفاتها تحت `plugins/اسم-الملحق/`، وهذه أنواعها الشائعة:

| الملف / الدليل | الوظيفة |
| --- | --- |
| `config.yml` | الإعداد الرئيسي، ويوجد في كل ملحق تقريبًا |
| `messages.yml` و`lang/` | نصوص الرسائل، وتعديلها يعني تغيير الصياغة أو التعريب |
| `menus/` و`kits.yml` وغيرها | إعدادات وحدات فرعية يولّدها الملحق عند التشغيل |
| `data/` و`playerdata/` و`*.db` | بيانات تشغيل يصونها الملحق بنفسه |

:::warn لا تعدّل ملفات البيانات يدويًا
محتوى `data/` و`playerdata/` و`*.db` يكتبه الملحق أثناء تشغيله. والتعديل اليدوي يُستبدل في أفضل الأحوال، ويُفسد بيانات اللاعبين في أسوئها. فعدّل الإعدادات، ولا تمسّ البيانات.
:::

## 2. القواعد الثلاث الحديدية في YAML

تسعة أعشار حالات «الإعداد غير قابل للقراءة» تعود إلى القواعد الثلاث التالية.

### الإزاحة بالمسافات فقط، لا بـ Tab

YAML تنصّ صراحةً على أن الإزاحة لا تستخدم محارف الجدولة. والـ Tab يبدو في المحرر مطابقًا لعدة مسافات، ويصعب تمييزه بالعين:

```yaml
# صحيح: بمسافات
options:
    enable: true

# خطأ: بداية هذا السطر Tab
options:
	enable: true
```

معظم المحررات تعرض الـ Tab سهمًا أو خطًا منقّطًا، وفي أسفل يمين VS Code يظهر `Tab Size` وطريقة الإزاحة. **وإن كان الإعداد قد اختلط فيه الـ Tab، فلا تحذفه يدويًا سطرًا سطرًا**، بل استخدم وظيفة «تحويل الإزاحة إلى مسافات» في المحرر لتوحيدها.

### يجب أن تكون هناك مسافة بعد النقطتين

```yaml
enabled: true      # صحيح: مسافة واحدة بعد النقطتين
enabled:true       # خطأ: السطر كله يُعدّ نصًا واحدًا
```

`key:value` في YAML ليست زوج مفتاح وقيمة، بل نص عادي. وحين لا يجد الملحق المفتاح `enabled` يعود إلى القيمة الافتراضية، وغالبًا يظهر ذلك كـ«عدّلتُه ولم يعمل».

### يجب أن تتساوى الإزاحة في المستوى نفسه

```yaml
options:
    enable: true
    check: false
    drop-block: true
    other:
        money: 10
        welcome: "أهلًا بك"
guide:
    show: true
```

`options` و`guide` في المستوى نفسه، و`enable` و`check` و`drop-block` و`other` في المستوى نفسه، و`money` تحت `other` أخفض بدرجة. و**لا يُسمح بتكرار المفتاح** في المستوى نفسه:

```yaml
options:
  enable: true
  enable: false     # خطأ: مفتاح مكرر في المستوى نفسه
  check: false
```

والمحررات التي تدعم صيغة YAML تلوّن هذا الخطأ بالأحمر؛ وحتى إن لم تُنبّه، فالملحق يُخطئ عند القراءة.

## 3. الكائنات والمصفوفات والتداخل

لا تملك YAML إلا بنيتين أساسيتين: **أزواج المفتاح والقيمة (الكائنات)** و**القوائم (المصفوفات)**، وما عداهما نتيجة تداخلهما.

### الكائنات

```yaml
options:
  enable: true
  check: false
  money: 10
```

ويمكن كتابتها في صيغة سطرية، وهي مناسبة للإعدادات القصيرة:

```yaml
options: {enable: true, check: false}
```

### القوائم

الأسطر التي تبدأ بـ `-` تشكّل قائمة، وعناصرها مرتبة:

```yaml
worlds:
  - world
  - world_nether
  - world_the_end
```

وبالصيغة السطرية:

```yaml
worlds: [world, world_nether, world_the_end]
```

### كائنات داخل قائمة

هذه أكثر بنية شيوعًا في إعدادات الملحقات وأكثرها عرضةً للخطأ — **المفتاح الأول لكل عنصر يأتي بعد `-`، وبقية مفاتيح العنصر نفسه تُحاذى معه**:

```yaml
kits:
  - name: starter
    price: 0
    items:
      - STONE_SWORD
      - BREAD
  - name: vip
    price: 500
    items:
      - DIAMOND_SWORD
```

لاحظ أن `name` و`price` و`items` مفاتيح ثلاثة لعنصر واحد، فيجب أن تتساوى إزاحتها؛ وأن `- STONE_SWORD` مستوى أدنى من `items`.

### أنواع القيم

القيم الشائعة في إعدادات الملحقات عدة أنواع، وانتبه إلى صياغتها:

```yaml
boolean: true          # true / false، وحالة الأحرف غير مؤثرة
integer: 10
float: 3.14
text: "hello"          # ضع علامات تنصيص إن حوى محارف خاصة
null_value: ~          # ~ تعني قيمة فارغة
```

:::tip متى يجب وضع علامات التنصيص
إذا ظهر في القيمة أحد الرموز `: ` أو `#` أو `{` أو `}` أو `[` أو `]` أو `&` أو `*` أو `!` أو `|` أو `>`، أو بدأت القيمة بأحدها، فأأمن طريقة أن تضعها بين علامتي تنصيص مفردتين أو مزدوجتين. فمثلًا نص يحوي رمز لون مثل `&aمرحبًا` يُكتب `"&aمرحبًا"` فلا يُحلَّل خطأً.
:::

## 4. أخطاء YAML الشائعة وأسبابها

| العَرَض | السبب الحقيقي | المعالجة |
| --- | --- | --- |
| الملحق يخطئ فور الإقلاع بـ `while parsing` أو `mapping values are not allowed here` | لا مسافة بعد النقطتين، أو ظهر `: ` في القيمة بلا تنصيص | أضف المسافة، أو ضع القيمة بين تنصيصين |
| `found character '\t' that cannot start any token` | اختلط Tab في الإزاحة | وحّد الإزاحة إلى مسافات |
| `duplicate key` | كتبت مفتاحين متطابقين في المستوى نفسه | احذف الزائد |
| عدّلت الإعداد بلا أي أثر | اسم المفتاح خطأ، أو المستوى خطأ، أو الملحق لا يقرأ هذا الملف أصلًا | قارن بندًا بندًا مع إعداد الملحق الافتراضي |
| بند واحد فقط في القائمة لا يعمل | إزاحة مفاتيح العنصر غير متساوية | اجعل مفاتيح العنصر نفسه على محاذاة واحدة |
| الملف كله غير قابل للقراءة، والخطأ في السطر الأول | الملف يحمل BOM أو ترميزه ليس UTF-8 | احفظه UTF-8 بلا BOM |
| الخطأ `expected <block end>` | سطر بإزاحة ناقصة أو زائدة | افحص عرض الإزاحة مستوى بمستوى |

:::tip دع المحرر يفحص عنك
تثبيت إضافة YAML في VS Code، أو فتح `.yml` في Notepad++، يعرض مشكلات الإزاحة والصيغة فورًا. **فانظر قبل الحفظ هل هناك خط متموّج أحمر**، فهو أسرع بكثير من تفتيش السجل لاحقًا.
:::

## 5. رموز الألوان والتنسيق

نصوص الخادم (MOTD والدردشة ورسائل الملحقات وأسماء القوائم) تتلوّن بـ**رموز التنسيق**. والنسخة الأصلية تستخدم رمز القسم `§`، لكن معظم الملحقات تسمح تسهيلًا بكتابة `&` في الإعداد وتحوّله بنفسها.

### الألوان

```
&0 أسود &1 أزرق داكن &2 أخضر داكن &3 سماوي داكن
&4 أحمر داكن &5 بنفسجي داكن &6 ذهبي &7 رمادي
&8 رمادي داكن &9 أزرق &a أخضر &b سماوي
&c أحمر &d وردي &e أصفر &f أبيض
```

### التنسيق

```
&l عريض     &o مائل     &n تحته خط   &m يتوسطه خط
&k محارف عشوائية &r إعادة الضبط
```

ويمكن الجمع بينها، مثل:

```yaml
prefix: "&8[&aالخادم&8] &r"
message: "&aمرحبًا &e%player_name% &aبعودتك إلى الخادم"
warning: "&c&lتحذير&r &7الرجاء عدم البناء هنا"
```

و`&r` يمسح التنسيق **الذي بعده** فقط، فإذا أردت إعادة مقطع نصي إلى النمط الافتراضي فاكتب `&r` هناك.

### بعض القيود

- **`&` ليست سحرية**: فهي تحتاج إلى تحويل من الملحق. وقليل من المواضع (`motd` في `server.properties` الأصلية، وبعض الأوامر الأصلية) لا تعرف إلا الرمز الحقيقي `§`، فتظهر `&` كما هي.
- **16 لونًا فقط**: رموز `&` آلية قديمة بلا ألوان حقيقية. وإن أردت تدرّجًا أو قيمة لونية دقيقة فاستخدم MiniMessage المذكور أدناه.
- **ماذا لو تعذّر إدخال `§`**: لا يستطيع العميل العادي إدخال هذا الرمز مباشرةً، ويمكنك الضغط على `Alt` ثم إدخال `167` من لوحة الأرقام بالترتيب، أو النسخ واللصق.
- **نطاق الرموز المدعومة يحدّده الملحق**: فرموز `&l` نفسها قد تعمل في عنوان قائمة عند ملحق، وتُهمل في موضع آخر.

### MiniMessage (للمعرفة فقط)

تعتمد MiniMessage المبنية على مكتبة Adventure على وسوم لوصف الأنماط، وتدعم الألوان الحقيقية والتدرّجات وأحداث التحويم والنقر:

```xml
<yellow>مرحبًا <blue><bold>بالعالم</bold></blue>!</yellow>
<gradient:#f6d365:#fda085>نص متدرّج اللون</gradient>
<rainbow>نص بألوان قوس قزح</rainbow>
```

لكن انتبه: **الدعم الأصلي في المنصة لا يعني دعم الملحق**. فـ Paper وتوابعه تضم Adventure أصلًا، لذا تستطيع ملحقات Paper غالبًا استخدام MiniMessage؛ أما الملحقات المبنية على Bukkit (مثل EssentialsX) فلا تدعمها افتراضيًا، إلا إذا أدخلت المكتبة بنفسها (مثل PlaceholderAPI).

:::note لا تُسقطها على كل ملحق
رؤيتك لغيرك يستخدم MiniMessage بنتيجة جيدة لا تعني أن ملحقك يعرفها. فاقرأ توثيق الملحق قبل الكتابة، وتأكد هل يدعم رموز `&` أو وسوم MiniMessage أو كليهما.
:::

## 6. ترميز الملفات والتشويه

ظهور نص عربي في الإعداد على شكل `???` أو `鍑虹幇` أو `æ¬¢è¿` يعود دائمًا تقريبًا إلى **ترميز خطأ**، لا إلى عدم دعم الملحق للعربية.

| العَرَض | السبب |
| --- | --- |
| يتحول النص إلى علامات استفهام أو مربعات | حُفظ الملف بترميز ANSI / GBK، والخادم يقرأ UTF-8 |
| يتحول النص إلى سلسلة رموز غريبة | الملف UTF-8 لكنه يُقرأ GBK (أو العكس) |
| اسم المفتاح في السطر الأول غير قابل للقراءة | الملف يبدأ بـ BOM، وبعض المحللات تعدّ BOM جزءًا من اسم المفتاح |

والمعالجة:

1. افتح الملف بمحرر مثل VS Code أو Notepad++.
2. اختر **UTF-8** عند الحفظ (وفي VS Code اختر `Save with Encoding` من موضع الترميز أسفل اليمين).
3. تأكد من عدم وجود BOM. ودفتر ملاحظات Windows في إصداراته القديمة يحفظ افتراضيًا «UTF-8 مع BOM»، وهو أكثر المزالق شيوعًا.
4. بعد الحفظ أعد تحميل الملحق، وراقب الكونسول والنصوص داخل اللعبة.

:::warn الحفظ مرة واحدة بدفتر الملاحظات عملية خطرة
فتح `.yml` بدفتر ملاحظات Windows ثم الضغط على Ctrl+S بلا تفكير قد يحوّل ملف UTF-8 سليمًا إلى ANSI. **ويُستحسن أن تبدأ بمحرر يدعم YAML ويعرض الترميز**، وأن تنسخ احتياطيًا قبل التعديل.
:::

## 7. تعديل الإعدادات بأمان: مسار ثابت

اتبع هذا الترتيب، فاحتمال المشكلات أقل بكثير.

1. **انسخ احتياطيًا أولًا**. انسخ `config.yml` إلى `config.yml.bak`، لتستعيده فورًا إن أفسدت شيئًا.
2. **عدّل أثناء إيقاف الخادم أو في وقت الذروة المنخفضة**. فبعض الملحقات تكتب حالة ذاكرتها إلى الملف عند الإغلاق، وقد يُستبدل ما عدّلته أثناء التشغيل.
3. **استخدم محررًا يدعم YAML**، واحتفظ بالتعليقات والبنية الأصلية، ولا تنسّق الملف كله بلا داعٍ.
4. **عدّل موضعًا واحدًا في المرة**، وتحقّق فورًا بعد التعديل. فتعديل عشرين سطرًا دفعةً يجعل تحديد السطر المخطئ مستحيلًا.
5. **أعد التحميل**. قدّم أمر الملحق نفسه:

| الطريقة | الوصف |
| --- | --- |
| `/اسم-الملحق reload` | تدعمها معظم الملحقات، **وهي المفضلة** (مثل `/tab reload` و`/papi reload`) |
| إعادة تشغيل الخادم | الأضمن، ولا مفرّ منها للملحقات التي لا تدعم إعادة التحميل الحيّة |
| `/reload` (الأمر الأصلي) | **غير موصى به**، فقد يُفسد حالة الملحقات |

6. **راقب الكونسول و`logs/latest.log`**. وفشل تحليل الإعداد يطبع عادةً اسم الملف ورقم السطر عند التحميل، فرجوعك إلى رقم السطر يكشف السبب بنظرة.
7. **إن لم تكن متأكدًا فاختبر على خادم اختبار أولًا**. تعديل إعدادات الملحق أأمن من تثبيته، لكنه قد يؤثر في الحفظ أو بيانات اللاعبين.

:::tip كيف تستخدم رقم السطر في الخطأ
عند ظهور تنبيه مثل `config.yml: 42` في السجل، **لا تحدّق في السطر 42 وحده**. فأخطاء تحليل YAML سببها غالبًا إزاحة السطر السابق أو علامة تنصيص غير مغلقة، فانظر سطرين أو ثلاثة إلى الأعلى.
:::

## 8. مرجع سريع

| المشكلة | افحص أولًا |
| --- | --- |
| الإعداد لم يعمل | كتابة اسم المفتاح، وموضعه الهرمي، وهل نفّذت reload |
| خطأ تحليل عند إقلاع الملحق | المسافة بعد النقطتين، وإزاحة Tab، وتكرار المفتاح في المستوى |
| تشويه النص | هل الملف UTF-8 بلا BOM |
| رموز الألوان تظهر كما هي | هل الموضع يدعم `&`، أو يحتاج وسوم MiniMessage |
| يعود كما كان بعد التعديل | هل يعيد الملحق كتابة الإعداد عند إغلاق الخادم |
