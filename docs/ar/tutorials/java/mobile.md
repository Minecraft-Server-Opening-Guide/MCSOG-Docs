كثير من اللاعبين يلعبون Minecraft على **الهاتف / الجهاز اللوحي / أجهزة الألعاب** فقط، وهذا هو **إصدار Bedrock**. وافتراضيًا **لا يستطيع لاعبو Bedrock الدخول إلى خوادم إصدار Java** — فبروتوكولا الإصدارين مختلفان تمامًا.

وباستخدام **Geyser** يمكن فتح هذا الطريق، ليتمكن لاعبو الهواتف من الانضمام إلى خادم إصدار Java.

## أولًا: Geyser أحادي الاتجاه (وهذا ما يجب فهمه أولًا)

الأسئلة الشائعة الرسمية لـ Geyser تنص بوضوح:

> **هل يمكن استخدام Geyser ليتصل لاعبو Java بخادم إصدار Bedrock الخاص بي؟**
> **لا. إنه أداة تحويل يتصل بها لاعبو Bedrock بخادم إصدار Java، والعكس غير ممكن.**

لذلك:

| الاتجاه | هل هو ممكن | الحل |
| --- | --- | --- |
| لاعبو Bedrock ← **خادم Java** | ممكن | **Geyser** (+ Floodgate) |
| لاعبو Java ← خادم Bedrock | لا حل رسمي | غير موجود |

**يُثبَّت Geyser على جهة خادم Java**؛ وخادم Bedrock الرسمي (BDS) **لا يقبل تثبيت Geyser**.

## ثانيًا: أين يُثبَّت وكيف

لـ Geyser أشكال عدة، اختر بحسب نوع خادم Java:

- **شكل ملحق**: خوادم الملحقات Spigot / Paper / Purpur وغيرها (الأكثر شيوعًا)
- **شكل وسيط**: Velocity / BungeeCord (في بنية تعدد الخوادم يُثبَّت على الوسيط)
- **شكل مود**: Fabric / NeoForge
- **شكل مستقل (standalone)**: لا يعتمد على المنصات السابقة، ويعمل وحده

وبعد التثبيت أعد تشغيل الخادم، فيولّد Geyser ملف إعداداته.

## ثالثًا: النقطة المهمة: فتح منفذ UDP

وهذه أكثر خطوة يُغفل عنها:

| المنفذ | البروتوكول | الاستخدام |
| --- | --- | --- |
| `25565` | **TCP** | اتصال لاعبي Java |
| `19132` | **UDP** | **اتصال لاعبي Bedrock (حيث يستمع Geyser)** |
| `19133` | UDP | المنفذ الافتراضي لإصدار Bedrock على IPv6 |

:::warn السماح بـ TCP وحده هو السبب الأول في تعذر اتصال لاعبي الهواتف
يجب السماح بـ **UDP 19132** في **موضعين**: مجموعة الأمان في الخادم السحابي، وجدار حماية النظام. وكثيرون يفتحون TCP 25565 فقط ثم يتساءلون: «لماذا لا يتصل الهاتف».
:::

وفي «إضافة خادم» يُدخل لاعب الهاتف: **العنوان = IP الخاص بك أو اسم النطاق، والمنفذ = 19132**.

## رابعًا: Floodgate: ليدخل لاعبو الهواتف دون حساب Java

افتراضيًا، خادم Java مفعّل فيه التحقق من النسخ الأصلية، ولاعبو Bedrock **لا يملكون حساب Java**، فيُرفضون.

و**Floodgate** يحل هذه المشكلة: فهو يتيح للاعبي Bedrock **الدخول بحساب Xbox مباشرة** دون شراء إصدار Java.

والنقاط المهمة:

- يُثبَّت Floodgate مع Geyser عادةً؛
- يحمل اسم لاعب Bedrock **سابقة** (افتراضيًا `.`) للتمييز عن لاعبي Java؛
- لذلك عند كتابة الأسماء في **القائمة البيضاء والحجب والأوامر** انتبه لهذه السابقة، واستخدم علامات التنصيص عند الحاجة؛
- ويمكن أيضًا استخدام خاصية ربط الحسابات في Floodgate لربط حساب Bedrock بحساب Java قائم.

## خامسًا: قيود معروفة (أبلغ اللاعبين مسبقًا)

- **قيود منصات الأجهزة**: لاعبو Xbox / PlayStation / Switch **لا يستطيعون إدخال IP للانضمام مباشرة**، وغالبًا لا يتصلون إلا عبر **DNS مخصص** أو **شبكة محلية**.
- **اضطراب بصري على المسافات البعيدة**: عميل Bedrock بنية 32 بت وJava بنية 64 بت، وعلى المسافات البعيدة قد تظهر مشكلات غريبة في الموضع أو العرض (وللمجتمع حلول غير رسمية للتخفيف).
- **بعض الملحقات غير متوافقة**: Geyser يحاكي عميل Java، ومعظم الملحقات تعمل، لكن قلة تتدخل في الدخول أو البروتوكول وقد تتعارض.
- **حزم الموارد تحتاج تحويلًا**: لا يقرأ Bedrock حزم موارد Java، ويجب تحويلها إلى صيغة Bedrock لتُستخدم مع Geyser.
- **قيود خوادم المودات**: إذا كان الخادم يشترط تثبيت المودات على العميل للدخول، فلا يستطيع Geyser ذلك («العميل الأصلي يمكنه الدخول، وعندها يستطيع Geyser»).

## سادسًا: هل تفتح اللعب بين الإصدارين

**مناسب للفتح**: عند الرغبة في توسيع مصادر اللاعبين، ووجود جمهور هواتف، وأسلوب لعب يميل إلى البقاء والبناء (غير حساس لدقة الريدستون).

**افتحه بحذر**: **خوادم الآلات التقنية**. فسلوك الريدستون في Bedrock وJava مختلف أصلًا، ويرى لاعبو اللعب بين الإصدارين آليات غير متسقة، ما يثير الخلاف.
