لا يزداد عدد الملحقات على الخادم إلا كثرةً. فإلقاء jar في `plugins/` أمر سهل، والمشكلة فيما بعده: ملحق يريد الترقية، وملحق تعطّل فتريد إيقافه مؤقتًا، وjar يبدو مريبًا. وتتناول هذه المقالة ثلاثة أمور: مسار التثبيت والإزالة المنظّم، وحدود قدرة أدوات إعادة التحميل الحيّة، وكيف تحكم على ملحق هل عُبث به.

وإن لم تكن ثبّتت ملحقات بعد، فابدأ بـ [مدخل الملحقات](/tutorials/java/plugins).

## 1. المسار المنظّم للتثبيت والتحديث والإزالة

### التثبيت

1. تأكد من موثوقية المصدر (انظر القسم 5)، وسجّل رقم الإصدار وعنوان التنزيل في الطريق.
2. **أوقف الخادم**. فمعظم الملحقات لا تدعم التحميل الحيّ عند أول تحميل.
3. انسخ دليل `plugins/` احتياطيًا، انظر [النسخ الاحتياطي والاستعادة](/tutorials/java/backup).
4. ضع ملف `.jar` في `plugins/`.
5. شغّل الخادم وراقب الكونسول، فمعلومات نجاح التحميل وفشله تُطبع هنا.
6. تأكد من حالة التحميل بأمر `plugins`.
7. ثم عدّل الإعدادات، وبعد التعديل قدّم الأمر الفرعي `reload` الخاص بالملحق، لا `/reload` الأصلي في الخادم.

### التحديث

التحديث أكثر عرضةً للمشكلات من التثبيت، لأن بنية إعداد الإصدار الجديد قد تكون تغيّرت.

| الخطوة | النقطة المهمة |
| --- | --- |
| اقرأ سجل التحديث | تأكد هل تغيّرت صيغة الإعداد، وهل هناك بيانات تحتاج ترحيلًا يدويًا |
| انسخ احتياطيًا | انسخ `plugins/<اسم-الملحق>/` على الأقل، وما يتصل بقاعدة بيانات انسخ قاعدتها كذلك |
| أبقِ الـ jar القديم | أعد تسمية الإصدار القديم إلى `.jar.bak` واحتفظ به، واحذفه بعد التأكد من سلامة الجديد |
| استبدل مع إيقاف الخادم | لا تستبدل jar قيد الاستخدام وهو يعمل |
| أعد التشغيل وتحقّق | راقب الكونسول، ثم تأكد الحالة بأمر `plugins` |
| القفز بين إصدارات رئيسية | عند الانتقال بين رئيسيين (مثل 1.20 إلى 1.21) قد يحتاج الملحق إلى إصدار وسيط أولًا |

### الإزالة

الإزالة ليست «حذف الـ jar» فقط.

1. أوقف الخادم.
2. أزل الـ jar.
3. **لا تحذف دليل البيانات فورًا**، بل أعد تسميته إلى `<اسم-الملحق>.bak` وراقبه فترة.
4. تحقق هل يعتمد عليه ملحق آخر كمتطلب مسبق، وعالج ذلك معه.
5. نظّف عُقد الصلاحيات التي تركها في ملحق الصلاحيات.
6. نظّف المهام المجدولة والأوامر المخصصة وبنود لوحة النقاط التي سجّلها.
7. انتبه إلى العناصر أو الكتل المخصصة التي تركها في العالم، فقد تُخطئ عند غياب الملحق.

:::warn الإزالة ليست تنظيفًا
حذف الـ jar يحلّ خطوة «التحميل» فقط. أما دليل البيانات وعُقد الصلاحيات وجداول قاعدة البيانات واعتماد الملحقات الأخرى عليه، فكلها باقية في مكانها.
:::

## 2. أدوات إعادة التحميل الحيّة: PlugManX وServerUtils

تُسمى هذه الأدوات عادةً **ملحقات إدارة الملحقات**: تستطيع تحميل ملحقات أخرى وإزالتها وإعادة تحميلها والخادم يعمل.

### PlugManX

أداة إدارة ملحقات عريقة، سلفها PlugMan، والآن يواصل PlugManX الذي يصونه المجتمع تطويرها.

| البند | المعلومات |
| --- | --- |
| صفحة الإصدار | مورد SpigotMC 88135 |
| الكود المصدري | Test-Account666/PlugManX على GitHub (والنسخة القديمة ryan-clancy/PlugMan) |
| الأوامر الفرعية الشائعة | `load` و`unload` و`reload` و`list` و`info` و`check` |
| الاستخدام النموذجي | `/plugman <الأمر-الفرعي> <اسم-الملحق>` |

أسماء الأوامر الفرعية ومعاملاتها تتغيّر مع الإصدارات، فالمرجع هو معلومات المساعدة التي يوفّرها الملحق.

### ServerUtils

| البند | المعلومات |
| --- | --- |
| صفحة الإصدار | مورد SpigotMC 79599، وModrinth |
| الكود المصدري | frankheijden/serverutils على GitHub |
| المنصات المدعومة | Spigot وBungeeCord وVelocity |

وإلى جانب إدارة الملحقات، يضم أدوات لعرض حالة الخادم. ولأنه يدعم خادم الوسيط أيضًا، تستطيع الخوادم الجماعية إدارة ملحقاتها من طبقة الوسيط، بلا تثبيت طقم على كل خادم خلفي.

### الحدود الحقيقية لإعادة التحميل الحيّة

إعادة التحميل الحيّة ليست «بلا إعادة تشغيل»، فلها أمور لا تستطيعها بوضوح:

| الحالة | هل تحلّها إعادة التحميل الحيّة |
| --- | --- |
| تعديل الإعدادات فقط | يكفي `reload` الخاص بالملحق |
| تعطيل ملحق مشكّل مؤقتًا | نعم، وهذه أنفع استخداماتها |
| تبديل إصدار الملحق (تبديل الـ jar) | غير مُستحسن، بل استبدله مع إيقاف الخادم |
| ملحق سجّل أوامر وصلاحيات ومستمعين ووصفات ومولّد عوالم وتقدّمًا | تبقى بقايا بعد الإزالة، وإعادة التحميل تُخطئ غالبًا |
| ملحق يعدّل تنفيذ الخادم الداخلي (NMS أو الانعكاس) | لا يستطيعها أساسًا |
| ملحق يحتفظ باتصال قاعدة بيانات أو مجموعة خيوط أو ذاكرة مؤقتة ساكنة كثيرة | لا تُحرَّر الموارد عادةً بعد الإزالة |
| تحميل وإزالة الملحق نفسه مرارًا | لا يمكن استرجاع محمّل الأصناف، فتستمر الذاكرة في الارتفاع حتى OOM |
| خادم هجين أو خادم مودات | مدير الملحقات لا يدير المودات |
| `/reload` الأصلي في الخادم | غير موصى به، فقد يُفسد حالة الملحقات |

:::warn لا تعتمد على إعادة التحميل الحيّة وحدها في خادم الإنتاج
إعادة التحميل الحيّة تناسب «إيقاف ملحق مؤقتًا لترى هل تختفي المشكلة» واختبار الإعداد سريعًا. أما تحديث الإصدارات رسميًا وتغيير الاعتماديات، فيجب أن يمضي في مسار الإيقاف وإعادة التشغيل.
:::

:::tip الاستخدام الصحيح في التشخيص
استخدم مدير الملحقات لتنفيذ `unload` على أحدث ملحق ثبّتته، وراقب هل اختفت الظاهرة؛ وبعد التأكد أنه هو، عالجه رسميًا بإيقاف الخادم. فهذا أسرع بكثير من قراءة السجل كله.
:::

## 3. السمات الشائعة للملحقات ذات الأبواب الخلفية

الملحق كود طرف ثالث يعمل بصلاحيات الخادم، فإذا زُرع فيه باب خلفي فكأنك سلّمت الخادم لغيرك. وهذه الإشارات تستحق الحذر.

| الإشارة | التجلّي المحدد |
| --- | --- |
| صلاحيات وأوامر شاذة | `plugin.yml` يعلن أوامر عالية الخطورة لا علاقة لها بالوظيفة، كمنح نفسه OP أو تنفيذ أي أمر أو قراءة وكتابة أي ملف |
| كود مشوّش | أسماء أصناف بلا معنى من حرف واحد أو بنية `a/b/c`؛ أو الحزمة كلها مشفّرة، أو تُفكّ وتُحمَّل وقت التشغيل بمحمّل أصناف مخصص |
| استدعاءات وقت تشغيل مريبة | إنشاء عملية فرعية (`ProcessBuilder` و`Runtime.exec`)، واتصال خارجي استباقي (`URL.openConnection` وطلبات HTTP)، وتعديل `ops.json` مباشرةً، وتحميل أصناف بعيدة بالانعكاس |
| تنكّر في صورة «محدّث» | يدّعي التحديث التلقائي، وفي الحقيقة ينزّل ملفات من خادم المؤلف ويستبدل نفسه |
| مصدر مجهول | jar يُعاد توجيهه في مرفقات المنتديات أو أقراص التخزين أو ملفات المجموعات |
| «ملحق متقدم مجاني» | ملحق مدفوع مكسور ومعاد تجميعه، والكاسر يضيف عادةً شيئًا |
| مخالفة الأصل | الاسم ورقم الإصدار متطابقان، لكن حجم الملف أو التجزئة لا يتطابقان، وقد غُيّر المؤلف والموقع في `plugin.yml` |
| خيارات خفيّة بلا ضرر ظاهر | خيارات مفعّلة افتراضيًا مثل `metrics` و`telemetry` و`update-check`، وهي في الحقيقة ترسل بيانات إلى الخارج |

:::warn لا تنظر إلى اسم الملحق وحده
الملحقات ذات الأبواب الخلفية كثيرًا ما تنتحل اسم ملحق معروف ورقم إصداره. فالمعيار هو مصدر الملف ومحتواه الفعلي، لا اسم الملف.
:::

## 4. مصادر التنزيل الآمنة

| القناة | الخطر |
| --- | --- |
| منصات الإصدار الرئيسية مثل SpigotMC وModrinth وHangar وBukkit Dev | منخفض، وهي المفضلة |
| GitHub Releases الخاصة بالمؤلف | منخفض، وتأكد من مالك المستودع |
| صفحة الشراء الرسمية للملحقات المدفوعة | منخفض، واحذر أن تشتري من «وسيط» |
| مواقع التنزيل المجمّعة والمرايا | متوسط، فقد تُعاد التعبئة، ويُستحسن مطابقة تجزئة الملف |
| مرفقات المنتديات وأقراص التخزين وملفات المجموعات | مرتفع |
| «ملحقات متقدمة مجانية» في منصات البيع المستعمل | مرتفع جدًا، وهي منطقة الكوارث |

والمعيار في الحقيقة بسيط: **هل يمكن تتبّع الملف إلى ما نشره المؤلف نفسه ويصحّ مطابقته**. فظهور ملحق في مواقع كثيرة لا يعني أنه آمن.

:::tip ثبّت ما تحتاجه فقط
كلما قلّ عدد الملحقات صغر سطح الهجوم وسهل التشخيص. ويكفي واحد من الملحقات المتداخلة الوظائف.
:::

## 5. مسار التشخيص عند الشك في ملحق

1. **سجّل الظاهرة**: متى بدأت، وماذا يخطئ الكونسول، وهل أبلغ لاعبون عن شذوذ.
2. **انسخ احتياطيًا أولًا**: أنجز نسخة كاملة قبل أن تمسّ أي شيء، بما فيها `plugins/` وبيانات العالم.
3. **اكتب قائمة المشتبه بهم**: الملحقات التي أُضيفت أو حُدّثت في آخر 24 إلى 72 ساعة.
4. **حدّد بالتنصيف**: أوقف الخادم، وعطّل نصف المشتبه بهم، وأعد التشغيل وراقب؛ فإن اختفت الظاهرة فهي في النصف المعطّل، وإلا ففي النصف الآخر.
5. **أعد الإنتاج منفردًا**: بعد الوصول إلى ملحق واحد، نفّذ `unload` عليه وحده بمدير الملحقات وتأكد هل تتكرر الظاهرة.
6. **افحص ساكنًا**: افحص الـ jar بطريقة القسم 6.
7. **راجع `plugin.yml` يدويًا**: طابق `author` و`website` و`main` و`commands` و`permissions` مع النسخة الرسمية.
8. **انظر قائمة ملفات الأصناف**: فُكّ الـ jar، وانتبه إلى أسماء الأصناف بلا معنى وإلى الاستدعاءات المريبة في الجدول أعلاه.
9. **طابق التجزئة**: قارن الحجم والتجزئة مع الملف الرسمي المنزَّل.
10. **بعد تأكيد الخبث ابدأ مسار الطوارئ**.

قائمة معالجة الطوارئ:

- تحقق هل عُدّل `ops.json` و`whitelist.json`، وهل حصل حساب غريب على OP.
- تحقق من وجود سجلات دخول شاذة وملفات بيانات لاعبين غريبة.
- بدّل كل بيانات الاعتماد: كلمة مرور RCON، وكلمة مرور اللوحة، وكلمة مرور قاعدة البيانات، ومفاتيح SSH.
- تحقق هل زُرع jar آخر في `plugins/`، وهل استُبدل jar نواة الخادم وسكربت التشغيل.
- تحقق من المهام المجدولة على مستوى النظام، وتأكد من عدم إضافة بند إقلاع تلقائي.
- اقرأ سجل الكونسول وسجل الملحق كاملين، وحدّد أول لحظة نشط فيها الباب الخلفي.
- أبلغ اللاعبين وأعد الحفظ إلى نسخة سابقة حسب الحالة، واحتفظ بالأثر للتحليل قبل الإرجاع.

## 6. الفحص الساكن بـ McGuard

McGuard (ويُختصر MCG) أداة فحص ساكن من طرف ثالث، ومؤلفها huzpsb. تفحص كل ملفات jar تحت `plugins/` **بلا تشغيل الخادم**، وتكشف الملفات المريبة.

### نمط الكونسول

ضع jar الخاص بـ MCG في جذر الخادم، ثم نفّذ في ذلك الدليل:

```
java -Xmx1G -jar MCG.jar
```

وبعد الإقلاع يطلب اختيار النمط، ويكفي عادةً اختيار `0` (النمط القياسي)، وهناك أيضًا نمط الخبير ونمط المطوّر.

وشكل نتيجة الفحص:

| الحالة | الخرج |
| --- | --- |
| لا شذوذ | يطبع عملية الفحص فقط، بلا كتلة نتيجة |
| شذوذ مكتشف | يطبع كتلة نتيجة، ويعطي لكل بند درجة خطورة ووصفًا للسبب |

ووصف السبب يذكر صنف السلوك المطابق، مثل «قد يحصل على OP بضبط بتّات الصلاحيات» أو «قد ينفّذ أمرًا بعيدًا بإطلاق عملية فرعية».

:::warn MCG يُبلّغ ولا يعالج
فهو لا يعدّل أي ملحق ولا يحذفه، وعليك التنظيف يدويًا. وانتبه أيضًا إلى أن نمط الخبير يطابق ببصمات شيفرة خبيثة معروفة ويحلّل نية الكود، فيغطي معظم العينات التي لا تتهرّب من الفحص عمدًا، لكن الإنذارات الكاذبة تبقى واردة.
:::

### نمط الملحق

يمكن تثبيت MCG كملحق Bukkit/Spigot للحماية المستمرة أثناء تشغيل الخادم. ووصف الموقع الرسمي لحدوده: هذه الحماية نسبية، وقلة نادرة من الملحقات الخبيثة قد تتجاوز ضبط السلوك؛ **ولا تشغّل خادمًا تعرف أنه يحوي ملحقات خبيثة لمجرد أنك ثبّتت MCG**.

:::warn الفحص آخر خط دفاع فقط
لا تستطيع أي أداة فحص إزالة كل المخاطر، والصحيح أن تحصل على الملحقات من قنوات نظامية. وإن أردت تشغيل نواة خادم مجهولة المصدر، فافحصها أولًا بنمط الكونسول، ثم جرّبها في بيئة معزولة مثل Sandboxie.
:::

## 7. توصيات الصيانة اليومية

- افحص تحديثات الملحقات مرة كل شهر على الأقل، وخصوصًا ما يتصل بالأمان مباشرةً كالتوافق بين الإصدارات ومكافحة الغش.
- احتفظ بقائمة ملحقات تسجّل الاسم والإصدار والمصدر وعنوان التنزيل، لتستطيع التتبّع السريع عند المشكلات.
- افصل خادم الإنتاج عن خادم الاختبار، وشغّل الملحقات الجديدة على الاختبار فترة أولًا.
- لا تشغّل عملية الخادم بحساب root أو Administrator، بل امنح الخادم حسابًا مخصصًا بأقل صلاحية لازمة.
- تابع الـ issues والإعلانات في مستودع المؤلف، فسمّ الملحق يُناقش عادةً في المجتمع قبل وقوعه.
