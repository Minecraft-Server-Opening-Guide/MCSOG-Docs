MCDReforged (ويُختصر **MCDR**) هو **مدير خادم** شائع جدًا في مجتمع تشغيل الخوادم. وهو لا يحل محل نواة خادمك، بل **يلتف حول النواة من الخارج**: يبدأ عملية النواة ويديرها، ويقرأ مخرجات وحدة التحكم، فيوسّع الوظائف **دون تعديل الخادم نفسه**.

## أولًا: أي مشكلة يحل

ما يمكن توسيعه في الخادم الأصلي / Paper هو «الملحقات» فقط، أما MCDR فيقدم قدرة **من طبقة أخرى**:

| القدرة | الشرح |
| --- | --- |
| **منظومة ملحقات** | كتابة ملحقات بلغة **Python**، وهي تتيح أمورًا يصعب على ملحقات Java (التمرير بين الخوادم، والربط بواجهات API خارجية، والتشغيل الآلي) |
| **مدفوع بالأحداث** | يفسّر مخرجات الخادم ويوزّع الأحداث (دخول اللاعبين وخروجهم، الدردشة، الموت، الأوامر...)، ويكفي أن يشترك الملحق فيها |
| **إعادة تحميل ساخنة** | الملحقات تُعاد تحميلها عادةً، فلا حاجة لإعادة تشغيل الخادم كله |
| **نظام صلاحيات** | نظام تحكم بالصلاحيات بحسب اللاعب أو المجموعة، يعمل مع أوامر السابقة `!!` |
| **مراقب (watchdog)** | إعادة تشغيل تلقائية بعد انهيار النواة |
| **تعدد الخوادم** | نسخة MCDR واحدة يمكنها إدارة عدة نسخ خادم |

## ثانيًا: كيف يعمل

بعد تشغيل MCDR **يتولى عملية الخادم**: يقرأ مخرجات وحدة تحكم الخادم ويفسّرها أحداثًا، ويعترض أوامر `!!xxx` التي تكتبها في الدردشة ويسلّمها للملحقات بدلًا من تمريرها إلى الخادم الأصلي.

ولذلك:

- الخادم **نفسه** يبقى النواة نفسها، وسلوكه لا يتغير؛
- صار لديك «قشرة» إضافية، و**عند التشخيص راجع طبقة سجلات إضافية** (سجل MCDR نفسه + سجل الخادم).

## ثالثًا: التثبيت

MCDR مكتوب بلغة **Python 3**، ويعتمد على Python وpip:

| إصدار MCDR | Python المطلوبة |
| --- | --- |
| < 2.10 | ≥ 3.6 |
| ≥ 2.10 | ≥ 3.8 |
| ≥ 2.15 | **≥ 3.9** |

ولتثبيت أحدث إصدار استخدم **pip**:

```bash
pip install mcdreforged
```

:::warn لا تنزّل شيفرة المصدر كملف مضغوط لتشغيلها
كثير من الدروس في الشبكة تطلب تنزيل ملف مضغوط من GitHub وفك ضغطه واستخدامه — **وهذه طريقة قديمة**. فمنذ الإصدار 1.0 (أوائل 2021) لم يعد MCDR يُثبَّت بهذه الطريقة. إلا إذا كنت مطوّرًا وتعرف ما تفعله، فاستخدم pip.
:::

## رابعًا: مراحل التشغيل

1. **التهيئة**: نفّذ أمر التهيئة مرة واحدة، فيولّد MCDR ملف إعداداته وبنية دلائله.
2. **الإعداد**: املأ في إعداد MCDR **أمر تشغيل الخادم** و**دليل العمل** (وهو ما كان يقوم به سكربت التشغيل في «تشغيل الخادم»، والآن يتولاه MCDR).
3. **التشغيل**: شغّل MCDR، فيُقلع الخادم ويتولى هو وحدة التحكم.
4. **تأكيد نوع الخادم**: يهيّئ MCDR أنواع النوى المختلفة عبر **معالج الخادم** (النسخة الأصلية / عائلة Paper / خادم المودات وغيرها)، واختيار الخطأ يفسد تفسير الأحداث.

:::tip أوامر سطر الأوامر الفرعية بحسب الوثائق الرسمية
واجهة MCDR في سطر الأوامر (المعاملات العامة والأوامر الفرعية) تتغير بين الإصدارات، و**الصيغة الدقيقة تراجع في وثائق CLI الرسمية**، لا تُنسخ من الدروس القديمة.
:::

## خامسًا: الأوامر والصلاحيات

أوامر MCDR كلها بسابقة `!!` (تُكتب في مربع الدردشة داخل اللعبة):

| الأمر | الوظيفة |
| --- | --- |
| `!!MCDR` | الأمر الرئيسي، يدير MCDR نفسه (الحالة، الملحقات، إعادة التحميل، الصلاحيات وغيرها) |
| `!!help` | عرض مساعدة الأوامر المسجّلة |

- صلاحية تنفيذ الأوامر يتحكم بها **نظام الصلاحيات** في MCDR، ويُمنح بحسب اللاعب أو مجموعة الصلاحيات.
- من ينفّذها دون تخويل يستقبل رسالة رفض، ولا يتأثر الخادم نفسه.

## سادسًا: الملحقات

- توضع الملحقات في دليل `plugins/` الخاص بـ MCDR، وتُحمَّل وتُعاد تحميلها بأوامر `!!MCDR` الفرعية.
- وللبرنامج **مستودع ملحقات** رسمي يمكن البحث فيه عن ملحقات جاهزة؛ ويمكن كتابة ملحقات خاصة أيضًا (ملحق ملف واحد، أو ملفات متعددة، أو مجلد).
- وأساس تطوير الملحقات هو **البيانات الوصفية + الاستماع للأحداث + شجرة الأوامر**: تُعلن معلومات الملحق، وتشترك في الأحداث التي تهمك، وتبني أوامرك `!!`.

## سابعًا: متى تحتاج إلى MCDR

**مناسب**: عند الرغبة في التشغيل الآلي (إعادة تشغيل مجدولة، إقلاع بعد الانهيار، ربط النسخ الاحتياطي)، أو ربط حالة الخادم بمنصات خارجية (مجموعة QQ، Discord، موقع)، أو كتابة ملحقات Python بمنطق مخصص.

**غير ضروري**: إذا كان الأمر مجرد خادم ملحقات صغير، فملحقات النواة المدمجة مع إدارة systemd تكفي. **فكل طبقة إضافية كلفة صيانة إضافية**، فلا تستخدمه لمجرد الاستخدام.
