**Хронология версий** нашего сайта ([/wiki/versions](/wiki/versions)) перечисляет официальные версии Java Edition и Bedrock Edition в обратном хронологическом порядке. Это первая точка поиска для вопросов вроде «какую версию открывать, когда обновляться, почему игрок не может зайти».

Но сама хронология даёт только **номер версии, дату и одну строку описания**. Эта страница объясняет, что означает каждое поле, какие интуитивные догадки неверны и как превратить это в конкретное решение об обновлении.

> Правила нумерации версий, версии протокола и ритм выпусков определяются официально и могут меняться в любое время. Здесь объясняется только **как читать хронологию нашего сайта**; что поддерживает и требует конкретная версия — по официальным примечаниям к выпуску.
:::note Эта страница отвечает на четыре вопроса
- что означает каждое поле строки в хронологии;
- как разбирать номера версий Java Edition и Bedrock Edition;
- что означают метки LTS / CROSS-PLAY и чего они не означают;
- почему «дата выпуска» не отвечает на вопрос «зайдёт ли мой клиент».
:::

## 1. Где находится хронология и из чего состоит её строка

| Страница | Содержимое |
| --- | --- |
| [/wiki/versions](/wiki/versions) | По умолчанию открывается хронология Java Edition |
| [/wiki/versions/java](/wiki/versions/java) | Хронология Java Edition |
| [/wiki/versions/bedrock](/wiki/versions/bedrock) | Хронология Bedrock Edition |

Хронологии двух изданий **раздельные** и переключаются на странице двумя вкладками. Структура каждой строки постоянна:

| Поле | Пояснение |
| --- | --- |
| Номер версии | Официальный номер, который отображается в игре |
| Метки | Появляются, только если у записи есть отметка (например, LTS, CROSS-PLAY), есть не у каждой строки |
| Дата | Дата выпуска версии |
| Строка описания | Что это за версия (у крупных обновлений указано название, у мелких обычно исправления и улучшения стабильности) |

Несколько фактов о чтении:

- **Новые версии сверху**: хронология упорядочена по убыванию даты, первая строка — самая новая версия, ниже — всё более старые.
- **Только релизы**: снапшоты (Snapshot), предварительные версии (Preview) и бета-версии в хронологию не входят, поэтому «в хронологии нет» не означает «официально не выпускалось».
- **Количество записей у изданий очень разное**: Java Edition идёт от 1.0 до актуальных 26.x; у Bedrock Edition частота выпуска исправлений гораздо выше, записей почти в три раза больше, поэтому хронология Bedrock Edition при прокрутке заметно длиннее.
- **У записей Bedrock Edition есть дополнительное поле**: сервер Bedrock Edition (BDS) имеет собственный номер сборки, он дополнительно хранится в данных хронологии для сопоставления «версии клиента» и «сборки сервера».

## 2. Как читать номер версии Java Edition

Java Edition долго использует форму `1.x.y`:

| Позиция | Значение | Пример |
| --- | --- | --- |
| `1.x` | Основная версия, определяет изменения содержимого и геймплея | 1.21 |
| `.y` | Исправление в рамках этой основной версии | 1.21.9, 1.21.10, 1.21.11 |

**Здесь и возникает самое частое ошибочное прочтение**: `1.21.10` **новее**, чем `1.21.9`, потому что `.10` — это число десять, а не «один-точка-десять». **Сравнивайте числа, а не строки**: сортировка по строкам поставит `1.21.10` перед `1.21.9`, что выглядит как более старая версия, хотя на самом деле наоборот.

### 2.1 Новое именование: 26.x

В хронологии видно, что у Java Edition после 2026 года появились номера версий формы `26.x` (в нашей хронологии 26.1 отмечена 2026-03-24, 26.2 — 2026-06-16, 26.3 — 2026-09-15).

Это **официальное изменение способа именования версий**, а не «26-е исправление для 1.21», и по интуиции `1.x.y` нельзя судить о соотношении его размера со старыми номерами. Встретив непривычную форму номера, правильно **смотреть на дату, а не угадывать числа**:

- Хотите узнать, что новее: сравнивайте даты.
- Хотите узнать, можно ли поставить плагин: смотрите список поддерживаемых версий плагина, а не форму номера.
- Хотите узнать, совместимы ли протоколы: смотрите версию протокола, а не номер версии.

### 2.2 Разница между исправлением и основной версией

| Тип | Масштаб изменений | Риск обновления |
| --- | --- | --- |
| Исправление (например, 1.21.9 → 1.21.11) | Обычно только исправление ошибок и стабильность | Низкий; но плагины всё равно могут пострадать, резервная копия всё равно нужна |
| Основная версия (например, 1.21 → 26.1) | Могут меняться содержимое, механика и формат данных | Высокий; формат мира по сути односторонний, откат обходится очень дорого |

## 3. Как читать номер версии Bedrock Edition

`1.x.y` в Bedrock Edition **похож на Java Edition по форме, но не по сути**: третий сегмент означает не «какое по счёту исправление», а увеличивается по собственному ритму Bedrock Edition.

| Форма | Значение | Пример |
| --- | --- | --- |
| `1.x.y` | Релиз Bedrock Edition | 1.20.10, 1.21.100 |
| `1.x.y.z` (четыре сегмента) | Номер сборки BDS, используется на сервере | BDS 1.20.62.03 |

Три момента:

1. **`1.20.1` и `1.20.10` — не одно и то же**, и это не «изменение одной цифры». Третий сегмент Bedrock Edition часто прыгает сразу на десяток (ритм вроде 1.20.10, 1.20.20 в хронологии встречается очень часто), поэтому `1.21.100` не стоит считать опечаткой.
2. **Номер сборки BDS состоит из четырёх сегментов**: например, `BDS 1.20.62.03`. Это собственный номер сборки сервера, он **не та же строка**, что номер версии на клиенте, но в рамках одного выпуска они соответствуют друг другу.
3. **Если сборка не найдена, остаётся заполнитель**: в наших данных записи Bedrock Edition, для которых точный номер сборки не найден, записываются в форме `BDS <версия>.w` (где `w` — заполнитель номера сборки), что означает «номер сборки этого выпуска не подтверждён», а не «у этой версии нет сервера».

### 3.1 26.x в Bedrock Edition

Bedrock Edition тоже перешёл к именованию `26.x` (в нашей хронологии 26.0 отмечена 2026-02-10). Как и в Java Edition, **не сравнивайте числа между разными системами именования**, смотрите даты.

### 3.2 Клиент и сервер выходят в один день

В описаниях хронологии Bedrock Edition часто встречается формулировка «выпущено в один день с клиентом», что отражает реальный ритм Bedrock Edition: **обновление клиента и сборка сервера обычно продвигаются синхронно**. Отсюда два следствия:

- если сервер отстаёт, игроки (особенно с автообновлением) не могут зайти;
- игроки на iOS **могут установить только последнюю версию из магазина** и не могут откатиться к заданной версии, поэтому «зафиксировать сервер на старой версии» здесь гораздо дороже, чем в Java Edition.

## 4. Что означают метки LTS и CROSS-PLAY

Метки в хронологии — **подсказки, добавленные нашим сайтом**, а не официальная классификация, и никаких официальных обещаний за ними нет. Они показываются только там, где у записи стоит отметка.

| Метка | Что означает у нас | Чего она **не** означает |
| --- | --- | --- |
| LTS | Версия, на которой, по нашему мнению, стоит задержаться надолго и удобно использовать её как стабильную базу | Что официально будет долго её обновлять; и не означает, что она «самая безопасная» |
| CROSS-PLAY | Подсказка о версии, связанной с кроссплатформенной игрой | Что с ней Java и Bedrock будут совместимы; и не гарантирует входа со всех платформ |

Что обязательно нужно различать:

- **LTS — не официальный термин Minecraft**. Официально «версии с долгой поддержкой» не существует, любая версия может перестать получать исправления после следующего обновления.
- **CROSS-PLAY тоже не равен кроссплатформенной совместимости**. Совместимость между платформами Bedrock Edition — её собственная возможность; **совместимость Java Edition и Bedrock Edition обязательно требует инструментов вроде Geyser** и не зависит от версии сервера (см. [Различия Java Edition и Bedrock Edition](/wiki/editions)).
- **Метки меняются**. Сайт может в любой момент поставить или снять отметку, поэтому «у версии есть LTS» — это наше суждение, а не твёрдый факт. Ориентируйтесь на текущее отображение страницы.

## 5. Дата выпуска не равна «можно ли зайти»

Это самое частое неправильное применение хронологии. Дата отвечает только на «когда вышла эта версия» и **совсем не отвечает** на «может ли ваш клиент зайти на этот сервер».

Зайти или нет определяет **версия протокола**: клиент и сервер обмениваются номерами протокола на этапе рукопожатия, и при несовпадении вход невозможен — независимо от номера версии, даты выпуска и содержимого обновления.

| Явление | Настоящая причина | Где смотреть |
| --- | --- | --- |
| Игроку пишет «несовместимая версия» (Java) | Протокол клиента не совпадает с сервером | [Совместимость версий](/tutorials/java/via) |
| Игроку пишет, что нужно обновиться до последней версии (Bedrock) | Протокол клиента не совпадает со сборкой сервера | [Версии протокола и выбор версии](/tutorials/bedrock/protocol) |
| В хронологии вчерашняя новая версия, а игрок не может зайти | Вы ещё не обновили сервер или игрок уже автоматически обновился на более новую версию | Сначала уточните версии обеих сторон, потом решайте, догонять ли |
| В хронологии версия очень старая, но игрок заходит | Эта версия клиента всё ещё в пределах совместимости, принимаемой сервером | Не выводите совместимость протоколов из «заходит» |

### 5.1 Конкретный пример

Сервер работает на 1.21.11, игрок сообщает клиент 1.21.9:

| Вопрос | Ответ |
| --- | --- |
| Как смотреть хронологию | Обе строки есть, 1.21.11 новее 1.21.9 (по числам: 10, 11 больше 9) |
| Почему игрок не может зайти | Это не объяснить словами «версия слишком старая»: нужно смотреть, принимает ли сервер 1.21.11 протокол 1.21.9 |
| Что делать | Сначала посмотрите ошибку рукопожатия в журнале сервера; установка семейства Via позволяет заходить более старым клиентам, см. [Совместимость версий](/tutorials/java/via) |
| Может ли ответить хронология | Нет. Она лишь сообщает, какая из двух версий вышла раньше |

**Хронология отвечает «что новее», протокол отвечает «можно ли подключиться»** — это нужно проверять раздельно.

## 6. Почему версия протокола важнее маркетингового номера версии

«Маркетинговый номер версии» — это отображаемые на странице номера вроде `1.21.x`, `26.x`; **версия протокола** — номер, фактически используемый при обмене данными. Это не одно и то же:

- в рамках одного маркетингового номера протокол мог меняться несколько раз (в Bedrock Edition это особенно заметно);
- официально протокол иногда меняют между исправлениями, а иногда **не меняют**;
- совместимость плагинов, загрузчиков и инструментов кросс-версий в большинстве случаев определяется протоколом и внутренней версией, а не цифрой на странице.

**В Bedrock Edition всё жёстче**: протокол клиента должен совпадать со сборкой сервера, несовпадение на один номер протокола — и подключения нет. **В Java Edition есть слой перевода**: плагины семейства Via умеют транслировать протокол на стороне сервера и пускать более старые или более новые клиенты, но чем больше разрыв, тем меньше совпадающих вещей и тем заметнее падение качества.

Вывод: **определяя «можно ли зайти», всегда сначала смотрите протокол, потом номер версии; номер версии — это лишь имя для людей.** Полное описание обоих путей — в разделах [Версии протокола и выбор версии](/tutorials/bedrock/protocol) и [Совместимость версий](/tutorials/java/via).

### 6.1 Отношение двух изданий к протоколу различается

| Параметр | Java Edition | Bedrock Edition |
| --- | --- | --- |
| При несовпадении протокола | Рукопожатие не удаётся, сообщение о несовместимой версии | Рукопожатие не удаётся, сообщение о необходимости обновиться до последней версии |
| Есть ли слой перевода | Есть: семейство Via транслирует протокол на стороне сервера | В основном нет: экосистема кросс-версийных плагинов очень мала |
| Автообновление клиента | Только в официальном лаунчере, игрок может зафиксировать версию | Магазин приложений по умолчанию обновляет автоматически, игрок часто «обновляется пассивно» |
| Цена фиксации старой версии | Относительно контролируемая | Очень высокая: игроки на iOS могут ставить только последнюю версию |
| Отсюда стратегия по умолчанию | Можно решать, когда обновляться, по экосистеме плагинов | **По умолчанию догонять последнюю версию** |

## 7. Как с помощью хронологии решить, когда обновляться

Хронология даёт **даты и порядок**, а решение об обновлении требует ещё и понимания «что сейчас работает на вашем сервере». Рекомендуемый порядок:

1. **Сначала проверьте диапазон поддержки, потом новую версию**. До какой версии поддерживают ваше ядро, плагины и загрузчик модов? Запишите пересечение — это верхняя граница, до которой можно обновиться. Ограничения версий загрузчиков и ядер — в разделе [Сравнение ядер серверов](/wiki/compare#mcsog-h-%E6%A0%B8%E5%BF%83%E5%AF%B9%E7%85%A7).
2. **Посмотрите, сколько исправлений вышло после целевой версии**. Только что вышедшая основная версия часто ещё допиливается; подождать одно-два исправления заметно снижает риск.
3. **Посмотрите, докуда дошла ваша экосистема плагинов**. Поддержка новой версии ядром не означает поддержки плагинами.
4. **Сделайте резервную копию и проверьте её**. Обновление формата мира по сути одностороннее, откат «только ядро, мир тот же» невозможен.
5. **Проверьте на отдельном экземпляре**. Запустите на копии мира, не экспериментируйте на рабочем экземпляре.
6. **Выберите окно обслуживания и объявите заранее**.

| Ситуация | Рекомендация |
| --- | --- |
| Исправление с одними багфиксами, и ядро с плагинами уже поддерживают | Можно догонять, но резервную копию всё равно сделать |
| Только что вышедшая основная версия | Подождать первое или второе исправление |
| Среди ваших плагинов есть поддерживающие только старую версию | Остаться на старой версии или сначала найти замену плагину |
| Bedrock Edition | По умолчанию догонять последнюю версию; фиксация на старой версии = отказ от игроков на iOS |
| Не уверены | Не трогать. Цена остаться на текущей версии обычно ниже, чем у неудачного обновления |

Полный процесс обновления, риски понижения версии и способы отката — в разделе [Обновление и обслуживание сервера, плагинов и MCDR](/tutorials/ops/updates).

## 8. Порядок диагностики «не могу зайти»

| Порядок | Что проверять | Как проверять |
| --- | --- | --- |
| 1 | Версия клиента | Попросите игрока сообщить точный номер версии (см. следующий раздел) |
| 2 | Версия и протокол сервера | Журнал сервера, вывод версии ядра |
| 3 | Порт и протокол | В Java Edition TCP 25565; в Bedrock Edition UDP 19132 (для IPv6 — 19133) |
| 4 | Белый список и блокировки | `whitelist list`, `banlist players` (в Bedrock Edition смотрите `allowlist.json`) |
| 5 | Проверка лицензии и способ входа | Настройка вроде `online-mode` напрямую меняет «можно ли зайти» |
| 6 | Плагины кросс-версий | Если Via установлен, а версия всё равно не поддерживается, сначала обновите сам плагин |

Первые два шага уже требуют номера версии, поэтому **сначала спросите версию, потом всё остальное** — это сэкономит большую часть переписки.

## 9. Сначала уточните версию клиента
:::tip Когда игрок говорит «не могу зайти», первым делом нужен номер версии
Попросите игрока сообщить **точный номер версии клиента** (скриншот проще всего), затем сверьтесь с хронологией и протоколом. Без этого шага вся дальнейшая диагностика — догадки.

- **Java Edition**: номер версии показан в левом нижнем углу главного меню; в лаунчере тоже видно версию установки; в игре нажмите `F3`, номер отображается в верхней части отладочного экрана.
- **Bedrock Edition**: номер версии виден на странице вроде «О программе» в настройках (расположение на разных платформах разное, особенно отличается на мобильных и консолях).

Получив номер версии, сопоставьте версию игрока и версию сервера в хронологии по датам и порядку — и вы поймёте, «сервер слишком старый» это или «клиент слишком новый».
:::

## 10. Частые ошибки чтения хронологии

| Ошибочное представление | Как на самом деле |
| --- | --- |
| Сравнивать номера версий как строки | `1.21.10` новее `1.21.9`; а между системами именования (1.x и 26.x) числа сравнивать нельзя вообще, только даты |
| Считать, что в хронологии есть снапшоты | Только релизы; снапшотов и предварительных версий там нет |
| Считать, что «дата выпуска недавняя» значит «обязательно обновляться» | Ритм выпусков и ваша экосистема плагинов — разные вещи |
| Считать, что с LTS всё всегда безопасно | LTS — метка нашего сайта, а не официальное обещание |
| Считать, что `1.20.1` и `1.20.10` в Bedrock Edition различаются на один минор | Третий сегмент Bedrock Edition прыгает по своему ритму, это разные выпуски |
| Считать, что в один день выходит только одна версия | Несколько версий с одной датой в хронологии — нормальное явление |
| Считать, что «самое новое — самое подходящее» | Последняя версия дружелюбна к новым плагинам и недружелюбна к старым; смотрите, что у вас фактически установлено |

### 10.1 Вопросы, на которые хронология не отвечает

| Ваш вопрос | Может ли ответить хронология | Куда идти |
| --- | --- | --- |
| Когда вышла эта версия | Да | Сама хронология |
| Может ли зайти мой клиент | Нет | Версия протокола: см. [Версии протокола и выбор версии](/tutorials/bedrock/protocol) |
| Поддерживают ли мои плагины | Нет | Список поддержки на странице выпуска плагина |
| Догнало ли моё ядро | Нет | Официальная страница загрузки и официальный репозиторий ядра |
| Что изменилось в этой версии | Частично | Строка описания в хронологии; детали — в официальном списке изменений |
| Где скачать сервер | Нет | Раздел загрузок нашего сайта и официальная страница загрузки |

## 11. Краткая шпаргалка

```text
Открываю новый сервер
  -> выберите последний релиз, затем убедитесь, что его поддерживают и ядро, и плагины

Игрок говорит, что не может зайти
  -> сначала узнайте версию клиента -> сравните протоколы -> затем порты, белый список, проверка лицензии

Хочу обновиться
  -> посмотрите пересечение поддержки ядра/плагинов/загрузчика -> дождитесь ревизии -> сделайте резервную копию и проверьте
  -> пробный запуск на отдельном экземпляре -> выберите окно обслуживания -> объявите

Вижу незнакомый номер версии
  -> смотрите на дату, а не на величину числа
```

## 12. Используйте хронологию как архив версий

Помимо «посмотреть последнюю версию», у хронологии есть три более практичных применения.

### 12.1 Узнать, к какой основной версии относится историческая версия

Чтобы понять, «к какой крупной версии относится 1.20.4 и какие исправления вышли после неё», найдите эту строку в хронологии и **читайте вверх**: исправления одной основной версии обычно идут подряд. Когда нужно «откатиться к известной рабочей версии», это действие гораздо быстрее поиска материалов.

### 12.2 Понять, будет ли обновляться старая основная версия

Порядок в хронологии даёт интуицию: если после какой-то основной версии уже появилась новая основная версия, старая обычно получает исправления только при необходимости. **Это лишь наблюдение, а не официальное обещание**; будет ли обновление дальше — по официальным примечаниям к выпуску.

### 12.3 Сопоставить клиент и сервер в Bedrock Edition

Записи Bedrock Edition хранят и версию клиента, и номер сборки BDS, поэтому, получив версию клиента от игрока, можно сразу найти соответствующую строку в хронологии и посмотреть, какая сборка сервера ей соответствует. Это самый быстрый шаг в диагностике «клиент обновился, а сервер отстал».
