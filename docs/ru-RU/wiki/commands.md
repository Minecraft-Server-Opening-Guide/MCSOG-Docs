Эта страница собирает для справки три группы команд: **команды сервера Java Edition**, **команды Bedrock Edition (BDS и сторонних ядер)** и **уровень управления поверх сервера** (MCDR, консоль панели, RCON).

В столбце «права» указаны **ванильные значения по умолчанию**: в Java Edition по уровню OP, в Bedrock Edition по статусу оператора и переключателю «читы». После установки плагина прав (например, LuckPerms) фактические права определяются узлами прав и могут быть как шире, так и уже ванильных.

> Доступность команды и уровень прав **зависят от версии игры и типа ядра**: одно и то же имя на разных ядрах может отсутствовать или вести себя иначе. Перед вводом команды ориентируйтесь на официальную документацию вашего сервера и вашей версии игры.

:::note Запомните три вещи
- **В консоли обычно не нужен `/`**, в игровом чате `/` обязателен.
- **Консоль действует с максимальными правами**, в игре всё зависит от того, есть ли у вас OP или соответствующие узлы прав.
- **Java Edition и Bedrock Edition — два разных набора команд**: одинаковое имя не означает одинаковое поведение, у `save-all` в Bedrock Edition вообще нет аналога.
:::

## 1. Перед чтением таблиц: три правила

| Правило | Пояснение |
| --- | --- |
| Зависимость от версии | Команды добавляются и удаляются вместе с версиями (например, новые команды вроде `/tick` есть только в относительно новых версиях), старые руководства могут уже не работать |
| Зависимость от ядра | Команды `plugins`, `version`, `tps`, `restart` **не являются ванильными**, их предоставляют ядра семейства Spigot / Paper; в ванильном сервере их нет |
| Зависимость от плагинов | После установки плагина прав ванильные узлы прав можно переписать; после установки плагина псевдонимов имена команд могут заменяться |

Самый быстрый способ проверить, существует ли команда, — **ввести в игре `/` и посмотреть список автодополнения** либо набрать первые буквы в консоли и посмотреть подсказку. Если в автодополнении её нет, значит это ядро её не зарегистрировало.

## 2. Java Edition: жизненный цикл и сохранения

| Команда | Действие | Права | Примечание |
| --- | --- | --- | --- |
| `stop` | Безопасно остановить сервер: сначала сохранение, затем выход | OP 4 / консоль | **Только так и останавливать сервер**, не закрывайте окно и не убивайте процесс |
| `save-all` | Немедленно сохранить все данные мира | OP 4 / консоль | Можно добавить параметр `flush` для принудительной записи на диск |
| `save-off` | Отключить автосохранение | OP 4 / консоль | Отключайте до резервного копирования, чтобы не копировать наполовину записанный мир |
| `save-on` | Вернуть автосохранение | OP 4 / консоль | После резервного копирования не забудьте включить обратно |
| `reload` | Перечитать данные из включённых датапаков | OP 2 (в разных версиях может отличаться) | **Это не перезапуск и не перечитывание конфигурации сервера**, см. предупреждение ниже |
| `restart` | Перезапустить сервер | Зависит от ядра | Есть в семействе Spigot / Paper; в ванилле её нет |

Стандартный порядок остановки: `save-all` → `save-off` → резервная копия → `stop`. Если процесс уже завершён, `save-on` не нужен.

:::warn `/reload` — это не «перезагрузить всё», он ещё и может сломать плагины
В Java Edition `/reload` перечитывает только **данные включённых в данный момент датапаков**. Он **не**:

- перечитывает `server.properties` (изменения порта, сложности и подобные вступают в силу только после перезапуска);
- перезапускает процесс сервера и не перезагружает код плагинов;
- возвращает зарегистрированное плагинами содержимое в чистое состояние.

Зато он **может** рассинхронизировать состояние плагинов: таблицы счёта, слушатели, кэши, зарегистрированные команды могут остаться в полуобновлённом виде, симптом — «после перезагрузки что-то работает странно». Если задачу решает собственный `/имяплагина reload`, `/datapack enable` или `/datapack disable`, не используйте ванильный `/reload`; при крупных изменениях или неясных последствиях просто перезапустите сервер в окно обслуживания.

У одноимённой команды в Bedrock Edition область действия уже (перечитывание функций и скриптов в пакетах поведения), `reload` в обеих версиях **не** является кнопкой «обновить конфигурацию сервера».
:::

## 3. Java Edition: игроки, блокировки и белый список

| Команда | Действие | Права | Примечание |
| --- | --- | --- | --- |
| `list` | Показать игроков онлайн | Все | Самая частая команда «кто-нибудь есть на сервере» |
| `kick <игрок> [причина]` | Выгнать игрока | OP 3 / консоль | Выгнанный **может зайти снова** |
| `ban <игрок> [причина]` | Заблокировать игрока | OP 3 / консоль | Без разблокировки зайти не сможет |
| `pardon <игрок>` | Разблокировать игрока | OP 3 / консоль | В очень старых версиях называлась `unban` |
| `ban-ip <IP>` | Блокировка по IP | OP 3 / консоль | **Все игроки с этого IP не смогут зайти**, применяйте осторожно |
| `pardon-ip <IP>` | Разблокировать IP | OP 3 / консоль | Перед разблокировкой выясните, кому теперь принадлежит этот IP |
| `banlist [ips\|players]` | Показать список блокировок | OP 3 / консоль | Без параметра выводит игроков |
| `op <игрок>` | Выдать права администратора | OP 3 / консоль | Выдавайте только тем, кому нужно; OP гораздо грубее узлов прав |
| `deop <игрок>` | Снять права администратора | OP 3 / консоль | При использовании плагина прав OP всё равно может обходить группы прав |
| `whitelist on` | Включить белый список | OP 3 / консоль | Перед включением добавьте себя |
| `whitelist add <игрок>` | Добавить в белый список | OP 3 / консоль | Записывается в `whitelist.json` |
| `whitelist remove <игрок>` | Убрать из белого списка | OP 3 / консоль | После вступления в силу следующее подключение будет отклонено |
| `whitelist list` | Показать белый список | OP 3 / консоль | Совпадает с содержимым `whitelist.json` |
| `whitelist reload` | Перечитать белый список из файла | OP 3 / консоль | **После ручного редактирования `whitelist.json` выполнять обязательно** |

Файл белого списка — `whitelist.json`, блокировки и список OP находятся в `banned-players.json`, `banned-ips.json`, `ops.json`. Команды сразу записывают файлы; после ручного редактирования нужен соответствующий reload или перезапуск.

## 4. Java Edition: мир, время и игровые правила

| Команда | Действие | Права | Примечание |
| --- | --- | --- | --- |
| `tp <игрок> <цель>` | Телепортировать игрока | OP 2 / консоль | Полное написание — `teleport`; в консоли нужно указывать оба параметра |
| `gamemode <режим> [игрок]` | Сменить режим игры | OP 2 / консоль | Значения `survival` / `creative` / `adventure` / `spectator` |
| `gamerule <правило> <значение>` | Изменить игровое правило | OP 2 / консоль | Набор правил меняется от версии к версии, **проверяйте автодополнением** |
| `time set day` | Задать время | OP 2 / консоль | Можно также `noon` / `night` / `midnight` или числовое значение |
| `time add <количество>` | Продвинуть время | OP 2 / консоль | Удобнее `set` при отладке цикла дня и ночи |
| `weather clear` | Задать погоду | OP 2 / консоль | Значения `clear` / `rain` / `thunder`, можно указать длительность |
| `difficulty <сложность>` | Задать сложность | OP 2 / консоль | Значения `peaceful` / `easy` / `normal` / `hard` |
| `give <игрок> <предмет> [количество]` | Выдать предмет | OP 2 / консоль | Синтаксис ID предметов и компонентов меняется между версиями |
| `seed` | Показать сид мира | OP 2 / консоль | Привязан к сохранению, при другом мире значение иное |
| `say <текст>` | Объявление от имени сервера | OP 2 / консоль | Игроки видят его в стиле сообщения сервера |
| `tell <игрок> <текст>` | Личное сообщение | Все | Псевдонимы `msg` / `w` |
| `datapack list` | Показать датапаки | OP 2 / консоль | Используется вместе с `/reload` |

`gamerule` чаще всего применяют неправильно: **одноимённые правила в Java Edition и Bedrock Edition могут означать разное, а между версиями их могут переименовывать и разделять**. Перед изменением убедитесь через автодополнение, что правило существует, а после изменения наблюдайте журнал и отзывы игроков.

## 5. Java Edition: состояние и диагностика

| Команда | Действие | Права | Примечание |
| --- | --- | --- | --- |
| `tps` | Показать TPS | OP | **Не ванильная**: есть в семействе Spigot / Paper; при установленном spark может перехватываться spark |
| `mspt` | Показать время на тик | OP | Есть в семействе Paper; информативнее вместе с TPS |
| `spark tps` | Показать TPS через spark | OP | Дерево команд spark подробнее встроенных команд ядра |
| `spark profiler start` | Начать профилирование | OP | По умолчанию результат загружается и выдаётся ссылка, учитывайте риск утечки данных |
| `spark profiler stop` | Завершить профилирование и посмотреть результат | OP | Если нужно только остановить без загрузки, используйте `spark profiler cancel` |
| `plugins` | Показать плагины | OP / узел прав | Псевдоним `pl`; зелёный — загружен, красный — ошибка загрузки |
| `version <плагин>` | Показать версию плагина | OP / узел прав | При сообщении об ошибке об этом спросят обязательно |
| `help` | Справка по командам | Все | Постранично, `/help <команда>` показывает одну команду |

В ванильном сервере **нет** команд `tps`, `mspt`, `plugins`, `version`. В ванилле производительность можно оценить только по журналам и внешним инструментам — отсюда и впечатление «сменил ядро, появились новые команды». Полный процесс диагностики производительности — в разделе [Анализ производительности сервера с spark](/tutorials/ops/spark).

:::tip Узлы прав тоже управляют видимостью команд
Узлы прав для `plugins`, `version`, `help` по умолчанию открыты всем. Чтобы закрыть, установите `bukkit.command.plugins`, `bukkit.command.version`, `bukkit.command.help` в `false`. Но **отключить команду не значит скрыть плагин**: некоторые клиенты могут по ответу автодополнения определить установленные плагины.
:::

## 6. Bedrock Edition: как те же команды выглядят на BDS

У Bedrock Edition (BDS и сторонние ядра) свой набор команд. **Доступность зависит сразу от двух вещей**: есть ли у вас статус оператора и включены ли на сервере читы.

| Команда | Действие | Права | Примечание |
| --- | --- | --- | --- |
| `stop` | Безопасно остановить сервер | Консоль | То же имя и смысл, что в Java Edition; запомнить обязательно |
| `save hold` | Приостановить запись и сохранить согласованность файлов | Консоль | Первый шаг резервного копирования в Bedrock Edition |
| `save query` | Показать файлы, которые нужно скопировать | Консоль | Копируйте по выданному списку |
| `save resume` | Возобновить запись | Консоль | Выполняется после копирования |
| `whitelist on` / `off` | Включить / выключить белый список | Оператор | Соответствующий файл — `allowlist.json` |
| `whitelist add` / `remove` / `list` / `reload` | Обслуживание белого списка | Оператор | После ручного редактирования файла нужен reload |
| `op` / `deop` | Выдать / снять права администратора | Оператор | Результат записывается в `permissions.json` |
| `permission list` | Показать текущие права | Оператор | Соответствует `permissions.json` |
| `permission reload` | Перечитать файл прав | Оператор | Выполняется после ручного редактирования `permissions.json` |
| `kick <игрок> [причина]` | Выгнать игрока | Оператор | Смысл тот же, что в Java Edition |
| `ban` / `pardon` | Заблокировать / разблокировать игрока | Оператор | Блокировка по игроку (gamertag / XUID), **эквивалента блокировки по IP нет** |
| `tp` / `teleport` | Телепортация | Оператор | Синтаксис близок к Java Edition, но не совпадает полностью |
| `gamemode` | Сменить режим игры | Оператор | Значения похожи на Java Edition |
| `gamerule` | Изменить игровое правило | Оператор | Набор правил **отличается** от Java Edition, одноимённые правила могут означать другое |
| `time set` / `time add` | Задать / продвинуть время | Оператор | В Bedrock Edition есть также команды вроде `daylock` для фиксации времени |
| `weather clear` / `rain` / `thunder` | Задать погоду | Оператор | Есть также `toggledownfall` |
| `difficulty` | Задать сложность | Оператор | То же имя, что в Java Edition |
| `list` | Показать игроков онлайн | Оператор | В некоторых версиях доступна обычным игрокам, проверяйте автодополнением |

Часть команд в таблице **появилась только в сравнительно новых версиях** (`ban` / `pardon` особенно заметно): в более старых серверах Bedrock Edition их может не быть в автодополнении вовсе. **Единственный надёжный способ проверить наличие команды в вашей версии — автодополнение и официальная документация**, не копируйте номера версий из чужих материалов.

В конфигурации BDS есть пункт, напрямую связанный с командами: `allow-cheats` в `server.properties`. Когда он выключен, команды в игре ограничены; значение по умолчанию смотрите в локально созданном `server.properties`, а после изменения сервер нужно перезапустить. **Множество случаев «команды не работают» в Bedrock Edition вызвано переключателем читов или статусом оператора, а не ошибкой в команде.**

Процесс резервного копирования в Bedrock Edition полностью отличается от Java Edition, его можно копировать как есть:

```text
save hold
save query
# 按 query 输出的清单复制文件（worlds/ 要整体拷走）
save resume
```

## 7. Команды, которых в Bedrock Edition нет (или с другим смыслом)

| Команда Java Edition | Ситуация в Bedrock Edition | Пояснение |
| --- | --- | --- |
| `save-all` | Не существует | Используйте `save hold` / `save query` / `save resume` |
| `save-off` / `save-on` | Не существует | В Bedrock Edition нет пары переключателей «выключить автосохранение» |
| `ban-ip` / `pardon-ip` | Не существует | В Bedrock Edition блокировка по игроку, команды блокировки по IP нет |
| `plugins` / `version <плагин>` | Не существует | У ядер Bedrock Edition нет единой команды списка плагинов, смотрите вывод консоли |
| `tps` / `mspt` | Не существует | В Bedrock Edition нет команды TPS; производительность оценивается по журналам и внешним наблюдениям |
| `reload` | Существует, но **смысл другой** | В Bedrock Edition перечитываются функции и скрипты в пакетах поведения, **`server.properties` не перечитывается**, и это не перезапуск |
| `gamerule` | Существует, но **набор правил другой** | Одноимённые правила в двух изданиях могут означать разное, копирование между версиями приведёт к ошибкам |
| `difficulty` / `time` / `weather` | Существуют | Эти команды есть в обоих изданиях, синтаксис близок |

:::warn Утверждение «в Bedrock Edition нет /reload» нужно разбирать по частям
Частое в сообществе «в Bedrock Edition нет `/reload`» на самом деле означает **отсутствие reload, перечитывающего конфигурацию сервера**, — и это верно: изменив `server.properties` в Bedrock Edition, сервер можно только перезапустить (нормальный `stop` из консоли и запуск заново, не убивайте процесс).

Но команда с именем `reload` в Bedrock Edition действительно есть, её область действия — функции и скрипты в пакетах поведения, **это не то же самое, что перечитывание датапаков в Java Edition**, и конфигурационные файлы сервер заново не читает. В обоих изданиях не стоит использовать `reload` как «универсальную кнопку обновления»; конкретная область действия и поведение меняются от версии к версии, ориентируйтесь на официальную документацию.
:::

## 8. Уровень управления: подкоманды `!!MCDR`

MCDReforged (MCDR) — менеджер, **обёрнутый вокруг сервера**: он держит процесс ядра, разбирает вывод консоли и предоставляет набор команд с префиксом `!!`. Эти команды **не являются игровыми**, их обрабатывает сам MCDR и не передаёт серверу.

| Команда | Действие | Права | Примечание |
| --- | --- | --- | --- |
| `!!MCDR` | Основная команда, список доступных подкоманд | Управляется системой прав MCDR | Префикс `!!` можно изменить в конфигурации |
| `!!MCDR status` | Показать состояние MCDR | Права MCDR | Проверка «менеджер ещё жив» |
| `!!MCDR reload config` | Перечитать конфигурацию MCDR | Права MCDR | Есть сокращения вида `!!MCDR r cfg` |
| `!!MCDR reload plugin` | Перечитать плагины | Права MCDR | Отдельно от перечитывания конфигурации |
| `!!MCDR reload permission` | Перечитать данные прав | Права MCDR | Используется после изменения файла прав |
| `!!MCDR reload all` | Перечитать всё | Права MCDR | При проблемах начинайте с него |
| `!!MCDR plugin list` | Показать загруженные плагины | Права MCDR | Это не то же самое, что `/plugins` в Java Edition |
| `!!MCDR plugin load <плагин>` | Загрузить плагин | Права MCDR | Параметр — id плагина |
| `!!MCDR plugin reload <плагин>` | Перечитать один плагин | Права MCDR | Легче полного перезапуска |
| `!!MCDR plugin unload <плагин>` | Выгрузить плагин | Права MCDR | Выгрузка не равна удалению файла |
| `!!MCDR plugin install <плагин>` | Установить плагин из официального репозитория | Права MCDR | Пример: `!!MCDR plugin install ndpr` |
| `!!MCDR permission list` | Показать права | Права MCDR | Просмотр по игрокам и группам прав |
| `!!MCDR permission set` | Задать права | Права MCDR | Синтаксис — по официальной документации |
| `!!MCDR permission remove` | Удалить права | Права MCDR | |
| `!!MCDR checkupdate` | Проверить обновления MCDR | Права MCDR | Автоматическая проверка задаётся конфигурацией |

:::warn Подкоманды MCDR меняются между версиями
Подкоманды и их сокращения в MCDR меняются от версии к версии (сокращения вроде `!!MCDR reload config` особенно легко запомнить неверно), **точное написание — по официальной документации MCDR и справке, которую выдаёт `!!MCDR` на вашей машине**. Кроме того, права MCDR — собственная система, не связанная с уровнем OP в игре; какие команды `!!` игрок может выполнить в чате, определяется конфигурацией прав MCDR.
:::

## 9. Уровень управления: консоль панели и RCON

Веб-консоль панели (например, MCSManager, Pterodactyl) по сути является **удалённым стандартным вводом**: введённое вами передаётся процессу сервера как есть, разницы с консолью перед машиной нет.

| Канал | Нужен ли `/` | Права | Примечание |
| --- | --- | --- | --- |
| Локальная консоль | Обычно нет | Максимальные права | Ванильная консоль не ограничена уровнем OP |
| Веб-консоль панели | Большинство панелей принимает оба варианта | Максимальные права | Некоторые панели сами убирают ведущий `/`, ориентируйтесь на поведение панели |
| RCON | Обычно нет | Максимальные права | Нужно включить в `server.properties` и задать пароль |
| Игровой чат | `/` обязателен | По уровню OP или узлам прав | Подчиняется белому списку, блокировкам и плагину прав |

Три практических совета:

1. **Останавливайте сервер всегда через `stop` (в Bedrock Edition так же)**, не нажимайте в панели «завершить процесс». Принудительное завершение может привести к потере данных или повреждению мира.
2. **Не выставляйте RCON в интернет**. Это канал «выполнить любую команду» без аутентификации, слушайте только loopback или внутренний адрес, пароль должен быть длинным и уникальным.
3. **Команды в консоли панели выполняются с максимальными правами**, подумайте об этом, прежде чем дать доступ к панели помощнику.

## 10. Консоль и игра: список различий

| Различие | Консоль / RCON | Игровой чат |
| --- | --- | --- |
| Ведущая косая черта | Обычно не нужна | Обязательна |
| Источник прав | Идентичность процесса, то есть максимальные права | Уровень OP или узлы прав |
| Контекст исполнителя | **Исполнителя нет**: `@s`, относительные координаты и `tp` без указания цели невозможны | Исполнитель есть, доступны селекторы и относительные координаты |
| Куда идёт вывод | Терминал и файл журнала | Чат и панель действий |
| Автодополнение | Обычно есть; в некоторых панелях нет | Есть |
| Кодировка | При неверной кодовой странице консоли Windows кириллица и китайский превращаются в мусор | Обычно нормально |
| Видимость для игроков | Игроки не видят, что вы ввели | Часть команд транслируется игрокам |

Самая типичная ошибка — выполнить в консоли `/tp ~ ~10 ~`: у консоли нет позиции, такая команда обязательно провалится. При выполнении команд телепортации из консоли **и игрока, и цель нужно указывать явно**.

## 11. Откуда берутся права

| Система | Где применяется | Как управлять |
| --- | --- | --- |
| Уровень OP | Java Edition, ванилла | `/op` даёт 4-й уровень; уровни с 1 по 4 соответствуют разным наборам команд, детализация возможна узлами прав |
| Узлы прав | Java Edition, сервер с плагинами | Плагин прав (например, LuckPerms) распределяет по узлам и группам, это безопаснее выдачи OP |
| Оператор + переключатель читов | Bedrock Edition | `permissions.json` определяет, кто оператор; `allow-cheats` в `server.properties` определяет доступность команд |
| Права MCDR | Сервер с MCDR | Собственная система прав MCDR, управляет командами `!!` по игрокам и группам |

**Принцип выдачи прав**: если можно дать право только на одну команду — не давайте целый OP; если можно дать ограниченное по времени право — не давайте постоянное. OP — это доверие уровня «всего сервера», минимальным делегированием являются узлы прав.

## 12. Готовые комбинации

Стандартный процесс перед обслуживанием (Java Edition):

```text
say 服务器将在 5 分钟后进入维护
save-all
save-off
# 此时在外部打包世界目录与插件目录
stop
```

Белый список с нуля до рабочего состояния (Java Edition):

```text
whitelist add 你的ID
whitelist on
whitelist list
```

Резервное копирование и восстановление в Bedrock Edition:

```text
save hold
save query
# 复制 query 列出的文件，worlds/ 整体拷走
save resume
```

Команды, которые стоит ввести первыми при диагностике «игрок не может зайти»:

```text
list
whitelist list
banlist players
plugins
```

## 13. Частые ошибки

| Ошибка | Последствие | Правильное действие |
| --- | --- | --- |
| Закрыть окно или нажать «завершить процесс» | Мир может повредиться или откатиться | Выполнить в консоли `stop` |
| Использовать `/reload` вместо перезапуска | Рассинхронизация плагинов, конфигурация не применяется | Использовать собственный reload плагина; при необходимости перезапустить |
| Не выполнить `save-off` перед резервным копированием | Копия наполовину записанного мира | Сначала `save-all`, затем `save-off` |
| Использовать в консоли относительные координаты `~` | Команда сразу провалится | Явно указать игрока и координаты |
| Открыть порт RCON в интернет | Фактически отдать сервер сканерам | Слушать только loopback или внутреннюю сеть, задать надёжный пароль |
| Не выполнить reload после правки `whitelist.json` | Изменения не применяются | Выполнить `whitelist reload` |
| Использовать имена `gamerule` из Bedrock Edition в Java Edition | Правила нет или она означает другое | Проверить имя правила автодополнением |
| Считать, что в Bedrock Edition есть `save-all` | Такой команды нет | Использовать `save hold` / `save query` / `save resume` |
