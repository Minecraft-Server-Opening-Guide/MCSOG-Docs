Логика управления сервером Bedrock **та же**, что и в Java Edition (см. [JAVA] Управление сервером), но аудитория игроков и формат клиента добавляют несколько пунктов, которые **нужно учитывать отдельно**. Эта статья только о различиях.

## 1. Три особенности аудитории Bedrock

| Особенность | Влияние на управление |
| --- | --- |
| **Высокая доля мобильных устройств** | Широкий возрастной разброс, **много юных игроков**: правила нужно писать прямее, а поддержке быть терпеливее |
| **Версию клиента не контролировать** | Магазины приложений обновляют автоматически → **протокол сменился, и зайти нельзя** (см. «Версии протокола и выбор версии») |
| **Платформы раздроблены** | Android / iOS / Windows / консоли, **на каждой платформе свои проблемы** |

## 2. Управление игроками: барьер на входе нужнее, чем в Java Edition

Текучесть игроков в Bedrock выше, а стоимость второго аккаунта ниже (особенно на Android), поэтому **разбираться по факту очень тяжело**:

- **Белый список / модерация на входе**: настоятельно рекомендуется включить. В Bedrock нет такой зрелой экосистемы античита, как в Java, и **не пустить проблему за порог** гораздо эффективнее, чем блокировать постфактум;
- **Правила должны быть короткими**: мобильные игроки не читают длинные тексты, достаточно нескольких жёстких красных линий;
- **Объявления картинками**: чат в Bedrock маленький, важные объявления эффективнее делать картинкой и отправлять в чат;
- **Администрация должна быть онлайн**: у юных игроков много конфликтов, и **дежурство в одни и те же часы** — ключ к удержанию игроков.

## 3. Раздача клиента: специфическая проблема Bedrock

В Java Edition достаточно официального лаунчера, а в Bedrock часто приходится **раздавать установочные пакеты клиента**:

- **Android**: можно раздавать `.apk`, но следите за **законностью источника** (не распространяйте взломанные версии);
- **Windows**: установка `.appx` / `.msix` для новичков очень сложна, **нужна пошаговая инструкция с картинками**;
- **iOS**: учтите, что **конкретную версию установить нельзя**, доступна только последняя из магазина → **это жёсткое ограничение, которое не обойти** (см. ниже).

:::warn Игроки iOS следуют за версией
Если вы фиксируете старую версию, **все игроки на iOS не смогут зайти**. Поэтому, если вы явно не отказываетесь от аудитории iOS, **держать сервер на последней версии** — единственный реалистичный выбор.
:::

## 4. Различия платформ и техническая поддержка

| Платформа | Частые проблемы |
| --- | --- |
| **Android** | В некоторых версиях есть **серьёзные подтормаживания** (сообщество долго не находит решения); источники установочных пакетов запутаны |
| **iOS** | Можно поставить только последнюю версию; откат невозможен |
| **Windows** | После внедрения Render Dragon **традиционные шейдеры недоступны** (с 1.18.30); установка appx сложна |
| **Консоли (Xbox/PS/Switch)** | **Нельзя подключиться по прямому IP**, обычно только через **свой DNS или локальную сеть** |

⇒ Нагрузка на поддержку большая, заранее напишите **пошаговые инструкции с картинками под каждую платформу** и отсеките повторяющиеся вопросы.

## 5. Финансы и команда

Как и в Java Edition (см. [JAVA] Управление сервером), плюс две особенности Bedrock:

- **Ниже потребление ресурсов**: при том же числе игроков Bedrock обычно требует меньше от железа, **на малом масштабе можно сэкономить**;
- **Но выбор ядра влияет на расходы**: BDS упирается в одно ядро → для большего числа игроков может понадобиться **более сильное ядро**; сторонние ядра (например, PowerNukkitX) используют несколько ядер, но за плагины и стабильность отвечаете вы.

## 6. Время: по-прежнему главный барьер

Этот пункт полностью совпадает с Java Edition и для Bedrock **ещё серьёзнее**:

- Игроки в основном с телефонов → **время в сети более раздроблено**, проблемы возникают в любой момент;
- Много различий платформ → одну и ту же проблему приходится разбирать для четырёх видов клиентов;
- Много юных игроков → больше времени уходит на урегулирование конфликтов.

**Сначала честно оцените, сколько часов в неделю вы можете стабильно уделять серверу**, и только потом решайте про масштаб.
