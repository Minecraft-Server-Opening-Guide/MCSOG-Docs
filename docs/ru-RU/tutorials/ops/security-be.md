Модель безопасности Bedrock **отличается** от Java Edition: проверка лицензии идёт через **Xbox Live**, а официальный сервер BDS **не имеет системы плагинов**. Поэтому статья делится на две части: **встроенные механизмы BDS** (надёжные, обязательные) и **система плагинов сторонних ядер** (гибкая, но отвечать придётся самому).

## 1. Три встроенных механизма BDS (сначала освойте их)

### 1. Белый список: `allowlist.json`

- После включения белого списка в `server.properties` сам список ведётся в **`allowlist.json`** в каталоге сервера.
- Это **самый эффективный** барьер в Bedrock: аудитория игроков текуча, второй аккаунт стоит дёшево, поэтому **не пустить проблему за порог** куда проще, чем блокировать постфактум.
- После изменения списка заставьте сервер перечитать его (или перезапустите), как указано в официальной инструкции.

### 2. Права администратора: `permissions.json`

- Администраторы (OP) и определение прав в BDS задаются в **`permissions.json`** (там UUID игрока, имя и пункты прав).
- Рекомендация: **давайте только тем, кому действительно нужно**, и вовремя отзывайте при изменениях в составе людей.

### 3. Проверка лицензии: `online-mode`

- В `server.properties` BDS есть переключатель `online-mode`: когда он включён, игрок должен пройти **проверку аккаунта Xbox Live**.
- **На публичном сервере отключать не рекомендуется**: после отключения любой может войти под чужим игровым именем, а блокировку можно обойти другим именем.

:::warn В Bedrock нет «такой зрелой экосистемы плагинов входа, как в Java»
В офлайн-сервере Java Edition можно поставить парольный барьер плагином вроде AuthMe; в Bedrock **нет равного по статусу и распространённости официального или общественного решения**. Поэтому правильная позиция для Bedrock: **сохранять проверку лицензии + использовать белый список как барьер**, а не надеяться, что «поставил плагин входа и всё безопасно».
:::

## 2. Система плагинов сторонних ядер

Сам BDS плагины ставить не умеет: чтобы расширить возможности, нужно менять ядро или добавлять загрузчик от сообщества (см. «Сервер BDS» и «Сторонние ядра»):

| Путь | Описание |
| --- | --- |
| **BDS + загрузчик от сообщества** | LeviLamina / EndStone / BDSX дают возможности плагинов: вход, права, управление и т. п. |
| **Семейство Nukkit** (включая PowerNukkitX) | Написано на Java, есть родная система плагинов, подход близок к плагинным серверам Java Edition |
| **PocketMine-MP** | Написано на PHP, больше всего плагинов, есть категории входа, прав, управления и другие |

:::warn В этой статье конкретные сторонние плагины не называются
**Экосистема сторонних плагинов Bedrock раздроблена, названия запутаны, активность крайне разная**, и у многих плагинов нет официального источника, который можно долго проверять. Чтобы не рекомендовать заброшенные или сомнительные плагины, статья **описывает только пути и категории**; конкретный плагин выбирайте на его официальной платформе самостоятельно по признакам «дата последнего обновления + число скачиваний + открытый исходный код».
:::

### Четыре проверки при выборе плагина

1. **Обновляется ли он**: протокол Bedrock меняется каждые несколько версий, и заброшенный плагин на новой версии обязательно упадёт.
2. **Официальный ли источник**: предпочитайте репозиторий автора или официальную платформу плагинов, избегайте архивов, перезалитых третьими лицами.
3. **Открыт ли исходный код / можно ли проверить**: плагины безопасности (вход, права) особенно важно видеть в реализации.
4. **Совпадает ли с версией вашего ядра**: и загрузчик, и плагины жёстко привязаны к диапазону версий (см. «Сервер BDS»).

## 3. Вопросы безопасности, которые приносит кросс-платформа (Geyser / Floodgate)

Если вы используете Geyser, чтобы игроки Bedrock заходили на сервер Java, обратите дополнительное внимание на безопасность:

- **Имена игроков Floodgate имеют префикс** (по умолчанию `.`), и **в белом списке, блокировках и командах имя нужно писать с ним**, иначе будут пропуски или ложные срабатывания.
- Floodgate позволяет игрокам Bedrock входить **без аккаунта Java**, то есть ослабляет один слой проверки, — **обязательно сочетайте с белым списком или модерацией**.
- Geyser ставится **на стороне сервера Java**, обратного направления (игрок Java на сервер Bedrock) **официального решения нет**.

## 4. Общие принципы (совпадают с Java Edition)

1. **Барьер на входе**: белый список / модерация отсекают абсолютное большинство разрушений и читов.
2. **Правила коротко**: игроки Bedrock в основном с телефонов, правила должны быть прямыми и выполнимыми.
3. **Действия администрации фиксируются**: кто кого заблокировал и кто менял права — всё должно быть проверяемо.
4. **Резервная копия — последняя линия обороны**: см. «Резервное копирование и восстановление» — учтите, что все сохранения BDS в `worlds/`, копировать нужно весь каталог.
5. **Не освобождайте память принудительно**: память BDS медленно растёт, принудительная очистка приводит к зависанию полосы загрузки у игроков, скачивающих паки ресурсов/аддоны, и помогает только перезапуск (см. «Сервер BDS»).
