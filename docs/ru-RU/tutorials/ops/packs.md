Названия «ресурспак» и «датапак» очень похожи, но действие у них полностью противоположное: **ресурспак меняет то, что игрок видит и слышит, а датапак меняет поведение самой игры**. Если перепутать эти понятия, появляются вопросы вроде «я поставил набор текстур, почему не изменились рецепты» или «почему датапак не меняет текстуры».

Эта статья про ресурспаки и датапаки Java Edition: что умеет каждый, как их ставить, как сервер раздаёт ресурспак и как искать причины несовместимости форматов. В Bedrock механизм другой (ресурспаки + паки поведения + аддоны), см. [Начало работы со сторонними ядрами Bedrock](/tutorials/bedrock/third-party-setup).

## 1. Что это такое

| Аспект | Ресурспак (Resource Pack) | Датапак (Datapack) |
| --- | --- | --- |
| Где действует | **Клиент**: текстуры, модели, звуки, языковые файлы, шрифты, GUI | **Сервер / сохранение**: рецепты, таблицы добычи, достижения, функции, структуры, теги |
| Кто видит результат | Только игроки, у которых пак установлен (или роздан) | Все игроки (данные лежат в мире/на сервере, независимо от клиента) |
| Куда ставится | Клиентский `resourcepacks/` либо раздаётся сервером | `datapacks/` в каталоге сохранения |
| Может ли сервер заставить | Может раздать и обязать (`require-resource-pack`) | Раздавать не нужно, он и так на сервере |
| Меняет ли геймплей | **Нет**. Меняется внешний вид и звук | **Да**. Может менять рецепты, дроп, генерацию мира, выполнять команды |
| Может ли выполнять код | **Нет**. Только ресурсы и конфигурационные файлы | **Да**. В функции лежит цепочка команд, равная выполнению команд сервером |
| Типичное применение | Текстуры, UI, звуки, локализация, шрифты, модели | Свои рецепты, дроп, достижения, логика мини-игр, генерация мира |
| Связь с версией | Номер формата в `pack.mcmeta` должен совпадать с версией клиента | Номер формата в `pack.mcmeta` должен совпадать с версией сервера |

Запомнить одной фразой: **ресурспак меняет «шкуру», датапак меняет «правила».**

### Сравнение структуры каталогов

```text
Ресурспак/
  pack.mcmeta                 <- обязателен, обозначает, что это пак
  pack.png                    <- необязателен, иконка в меню выбора
  assets/
    <пространство имён>/
      textures/               <- текстуры .png
      models/                 <- модели .json
      sounds/                 <- звуки .ogg
      lang/                   <- перевод <код языка>.json
      font/  blockstates/  gui/ ...

Датапак/
  pack.mcmeta                 <- обязателен
  pack.png                    <- необязателен
  data/
    <пространство имён>/
      function/               <- функции команд .mcfunction
      recipe/                 <- рецепты .json
      loot_table/             <- таблицы добычи .json
      advancement/            <- достижения .json
      structure/              <- структуры .nbt
      tags/                   <- теги (например, function/tick.json)
      predicate/  item_modifier/  worldgen/ ...
```

`pack.mcmeta` — **единственный обязательный файл**, именно по нему игра определяет, является ли каталог или zip «паком».

## 2. Чего каждый из них не может

| Что хочется сделать | Ресурспак | Датапак |
| --- | --- | --- |
| Поменять текстуру блока, звук, шрифт и язык | Можно | **Нельзя** (датапак не трогает клиентские ресурсы) |
| Добавить рецепт крафта, изменить дроп | **Нельзя** | Можно |
| Менять логику игры, добавлять правила мини-игр, выполнять команды по расписанию | **Нельзя** (не выполняет код) | Можно |
| Добавить новый блок / новый предмет | **Нельзя** (можно менять ресурсы только существующего контента) | **Нельзя** (для этого нужен мод) |
| Сделать так, чтобы все игроки видели одно и то же | Нужно раздать ресурспак, игрок всё равно может отказаться | Действует для всех игроков по своей природе |
| Повлиять на производительность сервера | Почти не влияет на сервер | **Влияет**: функция каждый тик может замедлять сервер |

:::note Почему «датапак не может добавить новый блок»
Датапак может определять **данные**: рецепты, дроп, достижения, генерацию мира, но регистрация блоков и предметов жёстко зашита в игру. Чтобы добавить на сервер действительно новый блок или предмет, нужен мод (или пак поведения в Bedrock). **Руководства «датапак добавляет новую руду» чаще всего используют внешний вид и материалы уже существующих блоков.**
:::

## 3. Как сервер раздаёт ресурспак клиенту Java

Ванильный сервер **отправляет** ресурспак клиенту через несколько ключей в `server.properties`. **Имена ключей должны совпадать буква в букву** (это одна из самых частых причин неудачи):

```properties
resource-pack=https://cdn.example.com/packs/survival-2026-10-04.zip
resource-pack-sha1=<40-символьный SHA-1 в нижнем регистре>
require-resource-pack=false
resource-pack-prompt={"text":"На этом сервере используются свои текстуры, рекомендуется включить.","color":"yellow"}
```

| Ключ | Тип | Значение по умолчанию | Значение |
| --- | --- | --- | --- |
| `resource-pack` | Строка (URL) | Пусто | Адрес скачивания ресурспака. Пусто означает, что ресурспак не раздаётся; при входе игрок сам решает, скачивать ли. **Предельный размер пака — 250 MiB** |
| `resource-pack-sha1` | Строка | Пусто | SHA-1 ресурспака, **нижний регистр шестнадцатеричных**. Используется клиентом для проверки целостности, **настоятельно рекомендуется заполнять** |
| `require-resource-pack` | Логический | `false` | При `true` **игрока, отказавшегося от ресурспака, выкинет с сервера** |
| `resource-pack-prompt` | Строка | Пусто | Свой текст подсказки, показываемый при обязательном ресурспаке. Использует синтаксис компонента чата (JSON-текст), может быть многострочным; пусто означает стандартную подсказку |
| `resource-pack-id` | UUID | Пусто | Необязательно, задаёт идентификатор ресурспака; **ключ есть только в более новых версиях**, в старых он не действует |

### Несколько деталей, которые нужно знать

- **Это должен быть HTTPS-адрес, доступный клиенту напрямую.** На практике ванильный клиент принимает только HTTPS-ссылки; открытый HTTP или адрес с проблемным сертификатом приводит к сбою загрузки (проверки на стороне клиента меняются от версии к версии, ориентируйтесь на официальную документацию).
- **Успех или неудача загрузки пишется только в журнал клиента, сервер их не видит.** Поэтому «на сервере ошибок нет» не значит, что игрок получил пак — при диагностике обязательно смотрите клиентский `logs/latest.log`.
- Сервер **не** хостит этот файл за вас. Его нужно разместить там, откуда есть доступ из интернета (объектное хранилище, CDN, статический каталог nginx и т. п.), и убедиться, что **нет защиты от хотлинка, нет авторизации и нет редиректа на HTML-страницу**.
- При запуске сервер перезаписывает `server.properties`: он дописывает отсутствующие ключи, возвращает недопустимые значения к значениям по умолчанию и **экранирует некоторые специальные символы** (например, `:`). Поэтому вручную писать JSON в `resource-pack-prompt` можно, но не считайте ошибкой появившиеся в файле обратные слэши.
- После изменения этих ключей **нужен перезапуск сервера** (`server.properties` не перечитывается через `/reload`).

:::warn Обязательный ресурспак — обоюдоострый инструмент
`require-resource-pack=true` означает, что **игрок, отказавшийся от загрузки, просто не войдёт**. Если ресурспак размещён на вашей небольшой машине с ограниченной полосой, одно обновление может заставить всех игроков качать одновременно, забить полосу и даже выглядеть как «сервер недоступен». **Перед включением обязательности проверьте полосу и доступность хостинга и сохраняйте возможность в любой момент отключить обязательность.**
:::

## 4. Как правильно посчитать SHA-1

Хеш должен быть SHA-1 от **содержимого файла**, в нижнем регистре шестнадцатеричных, ровно 40 символов.

```bash
# Linux / macOS
sha1sum survival-2026-10-04.zip
```

```powershell
# Windows PowerShell: Get-FileHash по умолчанию выводит верхний регистр, переведите в нижний и заполняйте
(Get-FileHash -Algorithm SHA1 .\survival-2026-10-04.zip).Hash.ToLower()
```

### Что будет, если хеш неверный

| Ситуация | Последствие |
| --- | --- |
| Хеш не соответствует файлу | После загрузки проверка на клиенте не проходит, **ресурспак не применяется**; ошибка есть только в журнале клиента, сервер о ней не знает |
| Хеш не является 40-символьной шестнадцатеричной строкой | По документации протокола клиент не использует его для проверки, **полоса на загрузку потрачена впустую** |
| При запуске сервер пишет `Invalid sha1 for resource-pack-sha1` | Значение в конфигурации не соответствует пакету (или формат недопустим), в консоли появится жёлтое предупреждение |
| Пак заменён, а хеш не обновлён | Игроки качают снова и снова терпят неудачу; у старых игроков может остаться старый пак |

:::tip Три самые частые ловушки
1. **Переупаковка меняет хеш**: даже при том же содержимом повторное сжатие (другие отметки времени, другой уровень сжатия) даёт другой zip и другой хеш. **Сохраняйте тот самый zip, для которого считали хеш, не перепаковывайте.**
2. **Файл может измениться при загрузке**: некоторые платформы автоматически сжимают, добавляют водяные знаки или переписывают содержимое, поэтому после загрузки **скачайте файл заново** и сверьте хеш с локальным.
3. **Регистр**: `ABC...` может не распознаваться как допустимый хеш, используйте единообразно нижний регистр.
:::

## 5. Куда класть датапак и как его ставить

Датапак кладётся в `datapacks/` внутри **каталога сохранения**. Каталог сохранения сервера определяется `level-name` в `server.properties` (по умолчанию `world`):

```text
/opt/mcserver/
  server.properties          <- level-name=world
  world/
    datapacks/
      my-tweaks/             <- датапак в виде каталога
      economy.zip            <- датапак в виде zip
    level.dat
    region/
```

Порядок установки:

1. Скачайте датапак (собранные у нас — в [Загрузках датапаков](/downloads/datapacks)) и убедитесь, что это **`.zip` или каталог**.
2. Положите его в `<level-name>/datapacks/`. **Внутри zip должен сразу лежать `pack.mcmeta`, без лишней вложенной папки** — при сжатии «правой кнопкой по папке» лишний уровень появляется чаще всего.
3. Если сервер уже работает: выполните `/reload` или включите пак через `/datapack enable <имя>` (часть содержимого требует перезапуска, см. раздел 6).
4. Проверьте, загрузился ли он:

```text
/datapack list             вывести все датапаки
/datapack list enabled     вывести только включённые
/datapack list available   вывести только доступные, но не включённые
```

В выводе должно быть имя вашего пака (в виде zip оно отображается как `file/<имя файла>`). При наведении мыши на элемент списка видно `description` из `pack.mcmeta`.

### Включение, отключение и порядок

```text
/datapack enable <имя>
/datapack disable <имя>
/datapack enable <имя> first        поставить в самый низкий приоритет
/datapack enable <имя> last         поставить в самый высокий приоритет
/datapack enable <имя> before <существующий пак>
/datapack enable <имя> after  <существующий пак>
```

- **Порядок важен**: файлы с одинаковыми именами **перекрываются: позже загруженный пак перекрывает загруженный раньше**; файлы тегов по умолчанию объединяются, если не указано `"replace": true`.
- Уровень прав: `list` / `enable` / `disable` требуют уровень прав 2; `create` — уровень 4.
- Список включённых паков хранится **в сохранении** (`level.dat`), поэтому **смена сохранения или откат меняет и то, какие датапаки включены**.

:::note Пути в одиночной игре и на сервере различаются
Сохранения одиночной игры лежат в `.minecraft/saves/<имя сохранения>/datapacks/`; на сервере — в `<level-name>/datapacks/` **в рабочем каталоге**. Неправильное размещение — самая частая причина «датапак не работает».
:::

## 6. Что именно перезагружает `/reload`

В Java Edition `/reload` **заново загружает данные из текущих включённых датапаков**. Он **не** всемогущ и не равен перезапуску:

| Содержимое | Действует ли `/reload` |
| --- | --- |
| Теги реестра (tags) | Перезагружаются |
| Таблицы добычи (loot table) | Перезагружаются |
| Рецепты (recipe) | Перезагружаются |
| Достижения (advancement) | Перезагружаются |
| Модификаторы предметов, предикаты | Перезагружаются |
| Функции (function, `.mcfunction`) | Перезагружаются |
| Шаблоны структур (structure) | Перезагружаются |
| Части с динамическим реестром / экспериментальным контентом (например, измерения, биомы, генерация мира, зачарования — точный объём зависит от версии) | **Нет**, нужен перезапуск сервера (в одиночной игре — выйти и зайти в мир) |
| Основная конфигурация вроде `server.properties` | **Нет**, нужен перезапуск |
| Процесс сервера, состояние плагинов | **Нет**, и `/reload` может их испортить |

Два поведения, которые нужно запомнить:

1. **При наличии недопустимых данных в датапаке изменения не применяются**, игра продолжает использовать предыдущие данные. Поэтому «я сделал `/reload`, а ничего не изменилось» иногда означает, что ошибка в самом паке, а не в перезагрузке.
2. **На сервере с плагинами используйте `/reload` осторожно.** Он может перепутать состояние плагинов (например, счётные табло, слушатели, кэш). Если можно решить через `/datapack enable` / `/datapack disable` или просто перезапуском — предпочитайте последнее.

## 7. Формат пака: `pack.mcmeta` и `pack_format`

`pack.mcmeta` — файл метаданных пака, его используют и ресурспаки, и датапаки, но **требуемые номера формата у них разные**.

```json
{
  "pack": {
    "pack_format": <целое число, требуемое этой версией>,
    "description": "Пример датапака"
  }
}
```

:::warn `<целое число, требуемое этой версией>` выше — это заполнитель, а не готовый JSON
**Не копируйте номер формата из любых руководств**, включая это. Значение `pack_format` меняется с каждой версией Minecraft, и для ресурспаков и датапаков оно своё; при ошибке появится сообщение «формат несовместим», и пак не загрузится.
:::

### Как узнать, что вписать для вашей версии

| Источник | Описание |
| --- | --- |
| Официальная документация / таблица форматов паков на Minecraft Wiki | В таблице перечислены номера форматов ресурспаков и датапаков по версиям, **ориентируйтесь на неё** |
| Документация вашего серверного ядра | Некоторые ядра указывают в документации формат для текущей версии |
| Сообщение игры | При ошибке загрузки обычно указывается и «формат, заявленный паком», и «ожидаемый текущей версией» (текст зависит от версии) |
| Обратный вывод из официального пака текущей версии | Посмотрите, что написано в `pack.mcmeta` официального ресурспака/встроенного датапака |

### Другие поля, связанные с версией

В `pack.mcmeta` есть не только `pack_format`, и **сами поля тоже развиваются от версии к версии**:

| Поле | Назначение | Замечание |
| --- | --- | --- |
| `pack.pack_format` | Основной номер формата пака | В новых версиях стал необязательным; в старых обязателен |
| `pack.supported_formats` | Заявляет диапазон форматов (например, `[42, 45]`) | Введено в 1.20.2; **в более новых версиях удалено**, оставляют только для совместимости со старыми версиями |
| `pack.min_format` / `pack.max_format` | Введённые в новых версиях минимальный/максимальный поддерживаемый формат (можно с минорной версией) | Заменили роль `supported_formats` |
| `pack.description` | Текст, показываемый при наведении, поддерживает текстовые компоненты | Используется и ресурспаками, и датапаками |
| `pack.filter` | Отфильтровывает файлы из паков с более низким приоритетом (регулярное выражение) | Введено в 1.19 |
| `pack.overlays` | Накладывает подкаталоги по диапазону версий | Введено в 1.20.2 |
| `features.enabled` | Включает флаги экспериментальных возможностей | Нужен соответствующий экспериментальный переключатель |

**Имена полей, их обязательность и значения номеров формата определяются официальной документацией**, а не этой статьёй или любым сторонним руководством.

## 8. Производительность и безопасность

### Датапак — это «серверный код»

В функции лежит цепочка команд, **выполняемых сервером**, поэтому:

- **Устанавливайте только датапаки из доверенных источников.** Функция может сделать всё, что умеет команда: выдать предметы, телепортировать, изменить мир, очистить контейнеры и даже сбросить игрока в пустоту.
- Перед установкой **откройте zip и посмотрите**: нет ли в `data/<пространство имён>/function/` команд, которые вы не хотите выполнять; соответствует ли `description` в `pack.mcmeta` фактическому содержимому.
- Уровень прав функций задаётся `function-permission-level` в `server.properties` (по умолчанию 2), и он определяет, насколько «продвинутые» команды могут выполняться в функциях.

### Функции, выполняемые каждый тик, замедляют сервер

- Функция, на которую ссылается тег функций `minecraft:tick`, **выполняется каждый тик (20 раз в секунду)**. Один проход по нескольким сотням сущностей или установка/разрушение блоков каждый тик стабильно съедают MSPT.
- Функция, на которую ссылается `minecraft:load`, выполняется один раз при (пере)загрузке и стоит гораздо дешевле.
- При «опросах» через `/schedule`, `execute if` и подобные механизмы обязательно считайте, **сколько раз в секунду это реально выполняется**.
- При появлении лагов сначала измерьте, потом меняйте: см. [Профилирование производительности spark](/tutorials/ops/spark).

```text
# Проверить, есть ли у пака вход на каждый тик: посмотрите, есть ли этот файл
data/<пространство имён>/tags/function/tick.json
```

### Что учесть с ресурспаками

- Ресурспак на клиенте выполняет **замену ресурсов** и не исполняет код, поэтому с точки зрения «безопасности» риск низкий; но **стоимость скачивания и хранения** реальна: предел пака 250 MiB, и каждое обновление игроки качают заново.
- Большой пак заметно удлиняет вход игрока, и игроки со слабой сетью могут просто отказаться. **Если можно решить несколькими MB, не берите десятки MB.**
- Ресурспак может заменить любую текстуру, поэтому **его можно использовать и для введения игроков в заблуждение** (например, нарисовать обычную руду как алмазную). На многопользовательском сервере это вопрос честности, а не только техники.
- Раздача ресурспака сервером **не означает**, что игрок обязательно его использует: если `require-resource-pack=true` не задано, игрок может отказаться; к тому же порядок ресурспаков на клиенте игрока может перекрыть розданный вами пак.

## 9. Таблица диагностики

| Симптом | Частая причина | Как проверить |
| --- | --- | --- |
| Ресурспак вообще не раздаётся | `resource-pack` пуст или с ошибкой; URL недоступен; после правки сервер не перезапущен | Проверьте написание ключей и URL в `server.properties`; через браузер/`curl -I` убедитесь, что zip скачивается напрямую |
| При входе игрок получает ошибку загрузки | Не HTTPS, недействительный сертификат, нужна авторизация, защита от хотлинка, возвращается HTML вместо zip | **Смотрите журнал клиента** (сервер не записывает сбой загрузки) |
| Проверка хеша не проходит, пак качается повторно | `resource-pack-sha1` не соответствует файлу; пак перепакован без обновления хеша; хеш в верхнем регистре или неверной длины | Пересчитайте по методу раздела 4 и убедитесь, что скачивается тот же файл |
| В консоли сервера `Invalid sha1 for resource-pack-sha1` | Значение ключа не соответствует пакету или недопустимый формат | Пересчитайте и обновите; если не уверены, оставьте пустым (потеряете проверку) |
| После отказа игрок не может войти | `require-resource-pack=true` | Смените на `false` и перезапустите; либо сначала исправьте загрузку, потом включайте обязательность |
| Текстуры не изменились | Неверный путь или пространство имён в паке; `pack.mcmeta` отсутствует или неверный формат; пак перекрыт паком с более высоким приоритетом; перекрыт клиентским паком игрока | Убедитесь, что путь `assets/<пространство имён>/textures/...` верен; поставьте пак в начало списка ресурспаков; проверьте на чистом клиенте |
| Действует только у части игроков | Игрок отказался от загрузки или использует свой ресурспак | Если нужна одинаковость на всём сервере, включите `require-resource-pack` и сначала решите вопрос с полосой хостинга |
| Датапак не появляется в `/datapack list` | Неверный каталог (нужен `<level-name>/datapacks/`); лишняя вложенная папка в zip; это не `.zip` и не каталог | Убедитесь, что `pack.mcmeta` лежит в корне пака; посмотрите структуру через `unzip -l` |
| Датапак появился, но не действует | Не включён; функция не упомянута в теге `tick` / `load`; неверное пространство имён или путь; содержимое требует перезапуска | `/datapack list enabled` подтвердит включение; после `/reload` смотрите ошибки в журнале; при необходимости перезапустите |
| Сообщение «формат несовместим» | `pack_format` не соответствует текущей версии (у ресурспаков и датапаков номера разные, не перепутайте) | Сверьтесь с официальной таблицей форматов по разделу 7; обновите до верного номера |
| После `/reload` конфигурация не изменилась | Содержимое относится к требующему перезапуска; либо недопустимые данные в паке отбросили все изменения | Посмотрите в журнале сервера, нет ли ошибок загрузки; проверьте прямым перезапуском |
| После установки датапака явные лаги | Есть функция на `minecraft:tick` с большой нагрузкой на каждый тик | Проверьте `tags/function/tick.json`; локализуйте через [spark](/tutorials/ops/spark) |

## 10. Итог

- **Ресурспак меняет внешний вид, датапак меняет правила**; один на клиенте, другой на сервере.
- **Сервер раздаёт ресурспак четырьмя ключами** `server.properties`: `resource-pack`, `resource-pack-sha1`, `require-resource-pack`, `resource-pack-prompt` (в новых версиях ещё `resource-pack-id`), после правки нужен перезапуск.
- **Хеш должен соответствовать фактическому файлу и быть 40-символьной шестнадцатеричной строкой в нижнем регистре**; после расчёта не перепаковывайте, после загрузки сверяйте заново.
- **Датапак кладётся в `<level-name>/datapacks/`**, проверяется через `/datapack list`; `/reload` перезагружает только часть содержимого, динамический реестр и основная конфигурация требуют перезапуска.
- **Номер формата меняется от версии к версии**, всегда сверяйтесь с официальной таблицей, не копируйте из руководств.
- **Датапак — это серверный код**: ставьте только из доверенных источников; функция на `tick` постоянно расходует производительность.
