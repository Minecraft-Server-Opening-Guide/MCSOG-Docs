Предыдущие статьи были про «использование чужого»: установка плагинов, датапаков, настройка сервера. Эта статья — про **собственную разработку**.

Она для двух категорий: для владельцев серверов, которым нужен свой рецепт или своя команда, и для игроков, которые хотят с нуля освоить разработку плагинов Bukkit / Paper. Цель — не написать законченный продукт, а **понять, какие есть пути, что нужно подготовить на каждом и как выглядит минимальный каркас, который впервые запускается**.

Принцип на всю статью: **имена классов, методов, формат пакетов и имена каталогов меняются от версии к версии, и официальная документация всегда важнее любого руководства, включая это.** Здесь не выдумано ни одного конкретного имени API или номера формата.

## 1. Сначала выберите инструмент: датапак / плагин / мод

Эти три пути принципиально разные; сначала таблица сравнения.

| Критерий | Датапак (datapack) | Плагин (plugin) | Мод (mod) |
| --- | --- | --- | --- |
| Нужно писать код | Нет (JSON + mcfunction) | Да, Java | Да, Java |
| Инструменты сборки | Не нужны | Maven или Gradle | Инструментарий загрузчика |
| Работает на ванильном сервере | Да | Нет | Нет |
| Работает на семействе Paper | Да | Да | Нет (нужен мост) |
| Что можно менять | Данные, которые игра уже предоставляет: рецепты, таблицы добычи, достижения, функции, теги, часть данных генерации мира | Всё, что предоставляет API: команды, события, сущности, блоки, GUI, сеть | Сам код игры: новые блоки, новые мобы, новые измерения |
| Как тестировать | `/reload` + `/datapack list` | Перезапуск сервера | Перезапуск клиента и сервера |
| Цена обновления версии | Низкая (поменять номер формата и имена каталогов) | Средняя (API в целом стабилен, но прямое использование внутренних классов всё сломает) | Высокая (нужно ждать обновления загрузчика и каждого мода) |
| Типичное применение | Изменение правил, рецепты, команды, лёгкая логика | Экономика, регионы, меню, связка серверов, полноценные игровые системы | Новый контент, крупные сборки |

Рекомендуемый порядок: **если задача решается датапаком — делайте датапак; если датапак не может — пишите плагин; мод нужен только когда требуется менять саму игру.** Критерии:

- то, что вы хотите изменить, **игра уже отдаёт как данные** (рецепты, дроп, достижения, функции, теги) → датапак.
- то, что вы хотите сделать, **требует обработки событий или взаимодействия с игроком** (свои команды, GUI, экономика, права) → плагин.
- то, что вы хотите добавить, **изначально не существует в игре** (новые блоки, новые мобы) → мод.

## 2. Путь датапака

Датапак — самый низкий порог из трёх: **без инструментов сборки, без зависимостей, без компиляции**; достаточно нескольких JSON и текстовых файлов.

### 2.1 Структура каталогов

Серверные датапаки лежат в `datapacks/` внутри **каталога сохранения**; имя каталога сохранения задаётся параметром `level-name` в `server.properties` (по умолчанию `world`):

```text
world/
  datapacks/
    my_pack/
      pack.mcmeta
      data/
        my_pack/
          function/
            tick.mcfunction
            hello.mcfunction
          advancement/
          loot_table/
          tags/
            function/
              tick.json
              load.json
```

Имя каталога пространства имён (в примере выше `my_pack`) — это префикс, которым вы ссылаетесь на содержимое, например `my_pack:hello`. **Для пространства имён рекомендуется использовать только строчные буквы, цифры и подчёркивания.**

Датапак может быть и `.zip`, но **внутри zip сразу должен лежать `pack.mcmeta`**, без лишней вложенной папки. При сжатии папки через контекстное меню лишний уровень появляется чаще всего.

### 2.2 `pack.mcmeta` и `pack_format`

```json
{
  "pack": {
    "pack_format": 0,
    "description": "My first datapack"
  }
}
```

Про `pack_format` нужно запомнить одно правило:

:::warn Не копируйте номер формата из руководств
Значение `pack_format` **меняется с каждой версией игры**, и у датапаков и ресурспаков своя нумерация. При ошибке появляется сообщение «формат несовместим», и пакет не загружается.

**Сверяйтесь с таблицей форматов официальной wiki для нужной версии**, а не с цифрами из руководств (включая это). `0` в примере выше — заглушка, а не рабочее значение.

Кроме того, сами поля `pack.mcmeta` тоже развиваются: более новые версии позволяют объявить поддерживаемый диапазон форматов (например, поле вроде `supported_formats`). Набор полей меняется от версии к версии — ориентируйтесь на страницу `pack.mcmeta` официальной wiki.
:::

### 2.3 Единственное и множественное число в именах каталогов меняется от версии

Это самая частая ловушка новичков и при этом реже всего упоминаемая в руководствах:

| Тип содержимого | Старые версии (1.20.x и раньше) | С 1.21 |
| --- | --- | --- |
| Функции | `data/<ns>/functions/` | `data/<ns>/function/` |
| Достижения | `data/<ns>/advancements/` | `data/<ns>/advancement/` |
| Таблицы добычи | `data/<ns>/loot_tables/` | `data/<ns>/loot_table/` |
| Рецепты | `data/<ns>/recipes/` | `data/<ns>/recipe/` |
| Предикаты | `data/<ns>/predicates/` | `data/<ns>/predicate/` |
| Теги функций | `data/minecraft/tags/functions/` | `data/minecraft/tags/function/` |

То есть **начиная с 1.21 эти каталоги стали единственного числа**. Множественное число верно для старых версий, а в новых означает «контент не работает и явной ошибки нет». Ориентируйтесь на официальную wiki нужной версии.

### 2.4 Функции (`.mcfunction`)

- Функция — текстовый файл, где **на строку приходится одна команда**, **без `/` в начале**; строки, начинающиеся с `#`, — комментарии.
- Функцию можно вызвать командой: `/function my_pack:hello`.
- Более новые версии поддерживают **макросы функций**: заглушка `$(имя)`, параметры передаются через `function <функция> with <источник данных>`. Макросы зависят от версии — перед использованием убедитесь, что ваша версия их поддерживает.

```text
# дать игрокам в радиусе 16 блоков немного визуального эффекта
# внимание: обязательно добавьте фильтр, не перебирайте все сущности без фильтра
execute as @a[distance=..16] at @s run particle minecraft:flame ~ ~1 ~ 0 0 0 0 1
```

### 2.5 Теги (tags)

Теги «подвешивают» контент на хуки игры. Два самых используемых тега функций:

```json
{
  "values": [
    "my_pack:tick"
  ]
}
```

Если файл лежит в `data/minecraft/tags/function/tick.json` (до 1.21 — `functions/`), функции из него **выполняются каждый игровой такт**; если в `load.json` — **один раз при загрузке и при `/reload`**. Это стандартный способ «заставить датапак работать постоянно», и одновременно самый частый источник проблем с производительностью.

### 2.6 Достижения и таблицы добычи

Достижения (advancement) часто используют как «пользовательский триггер»: берут условие, которое нельзя выполнить естественно, и выдают его функцией вручную; `rewards.function` задаёт вызываемую функцию. Таблицы добычи (loot table) управляют дропом блоков, мобов или сундуков:

```json
{
  "type": "minecraft:generic",
  "pools": [
    {
      "rolls": 1,
      "entries": [
        { "type": "minecraft:item", "name": "minecraft:diamond" }
      ]
    }
  ]
}
```

Конкретные доступные `type`, условия и имена функций — по соответствующим страницам официальной wiki; они **дополняются и меняются в каждой версии**.

### 2.7 Тестирование: `/reload` и `/datapack list`

```bash
/datapack list
/datapack enable "file/my_pack"
/reload
/function my_pack:hello
```

Главное:

- `/datapack list` — первая диагностическая команда на тему «распознан ли пакет вообще»;
- `/reload` перезагружает **данные включённых датапаков** (функции, теги, достижения, таблицы добычи, рецепты и т. д.), **это не перезапуск**;
- генерация мира, типы измерений и часть содержимого реестров вступают в силу только после **перезапуска сервера**;
- на больших серверах `/reload` сам по себе не бесплатен — не жмите его постоянно как кнопку горячего обновления;
- подробнее о форматах пакетов, размещении и диагностике — в [Ресурспаки и датапаки](/tutorials/ops/packs).

### 2.8 Предупреждение о производительности: функция на tick — это «стоимость каждого такта»

:::warn Каждый такт = 20 раз в секунду
Подвесить функцию на тег `tick` — значит заставить её **выполняться 20 раз в секунду**. Каждая лишняя команда и каждый нефильтрованный перебор сущностей умножают стоимость на 20.

Частые ошибки производительности:

- `execute as @e` без фильтров селектора — перебор всех сущностей сервера;
- масса запросов блоков или `data get` в функции, выполняемой каждый такт;
- «опросная» логика на функциях там, где можно обойтись событиями или тегами.

Инструменты вроде `/spark` помогают найти тормоза от функций. **Сначала сделайте правильно, потом оптимизируйте**: то, что можно положить в `load`, не кладите в `tick`, а фильтры не пропускайте.
:::

Стоит знать ещё два игровых правила, связанных с масштабом команд: `maxCommandChainLength`, ограничивающее длину цепочки/рекурсии команд, и `commandModificationBlockLimit`, ограничивающее число блоков, которое может изменить одна команда. Их значения по умолчанию меняются от версии к версии — проверьте перед написанием больших функций.

## 3. Путь плагина

Плагин намного мощнее датапака, но требует **JDK, инструментов сборки и тестового сервера**.

### 3.1 Что нужно подготовить

| Нужно | Описание |
| --- | --- |
| JDK | Версия должна совпадать с требуемой версией Java для сервера |
| Инструменты сборки | Maven или Gradle — достаточно одного |
| API целевой платформы | Для семейства Paper — Paper API; используется при компиляции и **не попадает в ваш jar** |
| Тестовый сервер | Отдельный каталог, отдельный порт, отдельная копия мира |

Требования к Java **меняются вместе с версией игры**, а разные ветки ядер могут отличаться. Примерное соответствие (**ориентируйтесь на официальную документацию Paper, не копируйте**):

| Версия Minecraft | Требуемая Java |
| --- | --- |
| 1.16.5 и раньше | Java 8 |
| 1.17.x | Java 16 |
| 1.18.x - 1.20.4 | Java 17 |
| 1.20.5 и позже | Java 21 |

Версия Java сервера и версия `release` при компиляции **должны совпадать**, иначе запуск упадёт с ошибкой вроде `UnsupportedClassVersionError`.

### 3.2 Maven: `pom.xml`

```xml
<project xmlns="http://maven.apache.org/POM/4.0.0">
  <modelVersion>4.0.0</modelVersion>
  <groupId>com.example</groupId>
  <artifactId>myplugin</artifactId>
  <version>1.0.0</version>
  <packaging>jar</packaging>
  <properties>
    <maven.compiler.release>21</maven.compiler.release>
    <project.build.sourceEncoding>UTF-8</project.build.sourceEncoding>
  </properties>
  <repositories>
    <repository>
      <id>papermc</id>
      <url>https://repo.papermc.io/repository/maven-public/</url>
    </repository>
  </repositories>
  <dependencies>
    <dependency>
      <groupId>io.papermc.paper</groupId>
      <artifactId>paper-api</artifactId>
      <version>PUT-THE-VERSION-HERE</version>
      <scope>provided</scope>
    </dependency>
  </dependencies>
</project>
```

Три момента:

- `<scope>provided</scope>` означает «сервер уже предоставляет эту библиотеку, не кладите её в мой jar». **Эту строку писать обязательно**, иначе вы упакуете в плагин весь API.
- `<version>` записывается примерно как `<версия Minecraft>-R0.1-SNAPSHOT`; **конкретное значение меняется от версии к версии** — смотрите актуальное в официальной документации или репозитории, не копируйте.
- Если сторонние библиотеки не используются, **не подключайте shade**. Упаковка чужих библиотек создаёт конфликты и легко приводит к проблемам с лицензиями.

### 3.3 Gradle: `build.gradle`

```groovy
plugins {
    id 'java'
}
group = 'com.example'
version = '1.0.0'
repositories {
    mavenCentral()
    maven {
        name = 'papermc'
        url = 'https://repo.papermc.io/repository/maven-public/'
    }
}
dependencies {
    compileOnly 'io.papermc.paper:paper-api:PUT-THE-VERSION-HERE'
}
java {
    toolchain {
        languageVersion = JavaLanguageVersion.of(21)
    }
}
tasks.withType(JavaCompile).configureEach {
    options.encoding = 'UTF-8'
}
```

`compileOnly` — это `provided` в Gradle: **видно при компиляции, не включается в пакет**. Результат сборки — в `build/libs/`.

### 3.4 `plugin.yml` и `api-version`

```yaml
name: MyPlugin
version: 1.0.0
main: com.example.myplugin.MyPlugin
api-version: '1.21'
author: YourName
description: An example plugin.
commands:
  hello:
    description: Says hello.
    usage: /hello
    permission: myplugin.hello
permissions:
  myplugin.hello:
    description: Allows the use of /hello
    default: op
```

| Поле | Назначение |
| --- | --- |
| `name` | Имя плагина, используется как префикс логов и имя папки данных; без пробелов |
| `main` | **Полное имя класса** главного класса (с пакетом); класс должен наследовать `JavaPlugin` |
| `version` | Версия плагина, видна в логах и `/plugins` |
| `api-version` | Объявляет, под какую версию API написан плагин |

**Почему `api-version` важен**: по нему сервер решает, в каком режиме загружать плагин. Официальная документация говорит: **если версия сервера ниже объявленной в плагине версии API, загрузка будет отклонена**; а **если поле не указано, плагин загружается в старом (legacy) режиме и печатает предупреждение**. Оно также влияет на некоторые преобразования совместимости, поэтому в новых плагинах его следует указывать явно.

Это **не** гарантия версии: указанный `api-version` лишь объявляет целевую версию — он не значит, что код точно будет работать на новой версии. Более новые Paper поддерживают другой файл манифеста (`paper-plugin.yml`) и иную модель загрузки плагинов; конкретный синтаксис — по официальной документации соответствующей версии.

### 3.5 Жизненный цикл: `onEnable` и `onDisable`

```text
package com.example.myplugin;

import org.bukkit.plugin.java.JavaPlugin;

public final class MyPlugin extends JavaPlugin {
    @Override
    public void onEnable() {
        saveDefaultConfig();
        getServer().getPluginManager().registerEvents(new PlayerJoinListener(this), this);
        getLogger().info("MyPlugin enabled.");
    }
    @Override
    public void onDisable() {
        getLogger().info("MyPlugin disabled.");
    }
}
```

- `onEnable()` вызывается при включении плагина. При старте сервера это происходит после инициализации самого сервера и до того, как игроки смогут зайти.
- **Не выполняйте в `onEnable()` долгие блокирующие операции** (скачивание файлов, подключение к удалённым сервисам, обход всего мира) — это напрямую замедлит запуск сервера.
- В `onDisable()` следует сохранить конфигурацию, отменить свои запланированные задачи и закрыть открытые ресурсы.
- При отключении плагина сервер **сам снимает слушатели и отменяет задачи, запланированные плагином**, но **не** сохраняет за вас данные и не закрывает открытые вами файлы и соединения.

### 3.6 Регистрация команд и слушателей

Исполнитель команд:

```text
package com.example.myplugin;

import org.bukkit.command.Command;
import org.bukkit.command.CommandExecutor;
import org.bukkit.command.CommandSender;

public final class HelloCommand implements CommandExecutor {
    private final MyPlugin plugin;
    public HelloCommand(MyPlugin plugin) {
        this.plugin = plugin;
    }
    @Override
    public boolean onCommand(CommandSender sender, Command command, String label, String[] args) {
        sender.sendMessage("Hello, " + sender.getName() + "!");
        return true;
    }
}
```

- Возвращаемое значение означает, «обработана ли команда правильно»: при `false` сервер печатает `usage` этой команды.
- Не забывайте проверять `args.length`, иначе при пропущенном аргументе будет выход за границы массива.
- Для автодополнения реализуйте `TabCompleter` и зарегистрируйте через `setTabCompleter(...)`.

Слушатель событий:

```text
package com.example.myplugin;

import org.bukkit.entity.Player;
import org.bukkit.event.EventHandler;
import org.bukkit.event.Listener;
import org.bukkit.event.player.PlayerJoinEvent;

public final class PlayerJoinListener implements Listener {
    private final MyPlugin plugin;
    public PlayerJoinListener(MyPlugin plugin) {
        this.plugin = plugin;
    }
    @EventHandler
    public void onPlayerJoin(PlayerJoinEvent event) {
        Player player = event.getPlayer();
        player.sendMessage("Welcome to the server!");
    }
}
```

Для регистрации слушателя **обязательно** вызвать `registerEvents(listener, plugin)`; реализовать `Listener` недостаточно. При привязке команды в `onEnable()` не забудьте проверку на null:

```text
if (getCommand("hello") == null) {
    getLogger().severe("Command 'hello' is missing from plugin.yml!");
    return;
}
getCommand("hello").setExecutor(new HelloCommand(this));
```

**`getCommand()` вернёт `null`, если команда не записана в `plugin.yml`**; прямой вызов `setExecutor` — и сервер падает при старте. Это первый краш, с которым сталкивается новичок. Более новые версии Paper предоставляют регистрацию команд на основе Brigadier (через события жизненного цикла), что удобнее для сложных команд; это платформенный API, его синтаксис меняется от версии к версии — ориентируйтесь на официальную документацию.

### 3.7 Логи: `getLogger()`

```text
getLogger().info("Loaded " + count + " entries.");
getLogger().warning("Config value is missing, using the default.");
getLogger().log(java.util.logging.Level.WARNING, "Failed to save data", exception);
```

- `getLogger()` возвращает логгер с префиксом имени плагина; записи попадают в консоль сервера и файлы логов.
- **Не глотайте исключения**: после перехвата как минимум залогируйте их вместе с объектом исключения, иначе при диагностике останется только «что-то сломалось».
- Не используйте `System.out.println`: он обходит систему логирования, теряет имя плагина и уровень и не фильтруется инструментами логов. Более новые Paper предоставляют логгер в стиле SLF4J; синтаксис — по официальной документации.

### 3.8 Сборка и развёртывание

```bash
mvn -q package          # Maven, результат в target/
gradle build            # Gradle, результат в build/libs/
```

Шаги развёртывания:

```bash
stop                                              # выполнить в консоли тестового сервера
cp target/myplugin-1.0.0.jar /path/to/testserver/plugins/
java -Xms2G -Xmx2G -jar paper.jar --nogui         # после перезапуска смотрите логи onEnable и состояние /plugins
```

Два замечания:

- Если вы использовали shade и подобное, jar с префиксом `original-` — **не** тот файл, который нужно разворачивать.
- **Не используйте `/reload` для горячего обновления плагинов.** Горячая перезагрузка плагинов не поддерживается: легко остаются хвосты состояния, утекают загрузчики классов, и в итоге появляются самые странные проблемы. На этапе разработки просто перезапускайте тестовый сервер.

## 4. Где учить API

Это раздел, который хочется подчеркнуть сильнее всего: **не пишите имена методов по памяти.**

| Ресурс | Назначение |
| --- | --- |
| Официальный сайт документации Paper | Вводные руководства, рекомендуемые способы работы с событиями и командами, описание возможностей платформы |
| Официальный Javadoc Paper | **Единственный авторитет по именам методов и классов**; можно смотреть для целевой версии |
| Javadoc Bukkit / Spigot | Справка по базовому API; большая часть API Paper с ним совместима |
| Официальный репозиторий и документация вашего ядра | Понять, поведение Paper-специфично или общее для Bukkit |

Как делать:

1. Сначала определите, **под какую версию Minecraft** вы разрабатываете, и выберите соответствующую версию в Javadoc.
2. Собираясь использовать возможность, **сначала найдите класс в Javadoc**, проверьте сигнатуру метода и только потом пишите код.
3. **Имена классов, событий и значения перечислений меняются от версии к версии**; записи из блогов и старых руководств часто уже не работают.
4. **Различайте API и внутреннюю реализацию**: `org.bukkit.*`, `io.papermc.paper.*` — API с обещанием совместимости; внутренние классы сервера (обычно называемые NMS) **никаких гарантий совместимости не дают**, и их использование привязывает плагин к одной версии.
5. При ошибке компиляции «метод не существует» сначала подозревайте неверную версию, а не ищите замену, которая просто скомпилируется.

## 5. Дисциплина тестирования

Самая частая авария при разработке плагинов — не «не получилось написать», а **испытания на рабочем сервере**.

| Правило | Описание |
| --- | --- |
| Отдельный тестовый сервер | Отдельный каталог, отдельный порт, копия мира; **никогда не используйте основной сервер как полигон** |
| Согласуйте окружение | **Версия ядра, номер сборки, версия Java** тестового сервера должны совпадать с рабочими, иначе вы тестируете не то окружение |
| Сначала копия мира | Плагин меняет данные; при проблеме копия — единственный путь назад, см. [Резервное копирование и восстановление](/tutorials/java/backup) |
| Меняйте по одной вещи | Если одновременно менять плагин, конфигурацию и версию ядра, локализовать проблему невозможно |
| Читайте стек в консоли | При краше смотрите **первую строку + цепочку `Caused by` + строку с вашим пакетом**; методика — в [Частых ошибках и крашах Java Edition](/tutorials/faq/errors) |
| Проверьте обычным игроком | Ошибки, связанные с правами, видны только на аккаунте без OP |
| Перед публикацией — постепенно | Сначала включите на маленьком сервере или в непиковые часы, наблюдайте TPS и логи |

## 6. Напоминание о безопасности

**Плагин — не песочница.** Он работает в том же JVM, что и сервер, и имеет все права сервера: читает и пишет файлы, открывает сетевые соединения, выполняет системные команды, обращается к данным в памяти. Платформа его не ограничивает.

Отсюда три вывода:

- **Бэкдор в чужом плагине — бэкдор на вашей машине.** Берите плагины только из официальных каналов выпуска и остерегайтесь пересобранных, переименованных и упакованных версий.
- **С датапаками то же самое.** Функция может делать всё, что умеет команда: выдавать предметы, телепортировать игроков, очищать контейнеры, отправлять игроков в пустоту. Ставьте пакеты только из доверенных источников.
- **И в своём плагине не доверяйте вводу игрока.** Проверяйте аргументы команд, не подставляйте строки от игрока прямо в пути файлов, не исполняйте строки из конфигурации как код и экранируйте текст, отправляемый игрокам.

Порядок установки, аудита и очистки плагинов — в [Управлении плагинами и очистке](/tutorials/java/plugin-manage).

## 7. Итог

- **Сначала выберите инструмент**: датапак → плагин → мод; если хватает простого, не берите сложное.
- У датапака **самый низкий порог**: номер формата в `pack.mcmeta` нужно сверять с официальной таблицей, а единственное/множественное число в именах каталогов зависит от версии.
- Плагину нужны **JDK + инструменты сборки + тестовый сервер**; API подключается через `provided` / `compileOnly`, **не упаковывайте API**.
- В `plugin.yml` **`api-version` определяет режим загрузки**; без него плагин считается старым и выдаёт предупреждение; команда должна быть записана в `plugin.yml`, иначе `getCommand()` вернёт `null`.
- **В `onEnable` не делайте долгих операций**, в `onDisable` сохраняйте состояние и освобождайте ресурсы.
- **Имена методов — по официальному Javadoc**; имена классов и событий меняются от версии к версии.
- **Разработка — всегда на тестовом сервере**, по одной правке за раз, при краше сначала читайте стек.
- **Плагин имеет все права сервера**: плагин неизвестного происхождения — бэкдор неизвестного происхождения.

:::tip Самый быстрый способ учиться: читать готовый открытый плагин
Думать с нуля «какой метод мне вызвать» — самый медленный путь. Быстрее найти **открытый плагин с похожей функцией**, прочитать его `plugin.yml`, главный класс, один класс команды и один класс слушателя, скопировать минимальный каркас и переделать под свою задачу. За полчаса вы узнаете больше, чем из десяти руководств.

Читайте с тремя вопросами: **что и на каком этапе жизненного цикла он регистрирует, как обрабатывает ввод игрока и где хранит данные.** Разберётесь с этими тремя пунктами — и дверь в разработку плагинов открыта.
:::
