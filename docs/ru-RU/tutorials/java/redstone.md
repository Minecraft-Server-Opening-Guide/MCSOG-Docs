«Технический Minecraft» — это **выживание** плюс **схемы**: техническое выживание, в центре геймплея которого редстоун-машины, фермы мобов и точное поведение блоков. Главное отличие от обычного выживательного сервера: **он крайне чувствителен к тому, изменено ли «ванильное поведение»**.

Один оптимизированный порядок обновления блоков или одно исправленное свойство дублирования — и целая машина выходит из строя.

## 1. Плагинное ядро не даёт 100 % ванили

Официальная документация Paper говорит прямо:

> *Unfortunately, it currently is not possible to get a 100% Vanilla experience in Paper.*

То есть **запускать технический Minecraft на Paper / Purpur — заведомо идти на компромисс**. Поэтому сначала выберите правильное ядро, а потом говорите о конфигурации.

| Ваша цель | Рекомендуемое ядро |
| --- | --- |
| **Чистый технический Minecraft** | **Fabric** (ближе всего к ванили без оптимизационных модов), **Leaves** (ветка Paper, специально исправляющая испорченные ванильные особенности) |
| Проверка ванильного поведения / минимализм | **Vanilla** (официальный ванильный сервер) |
| **Умеренный технический Minecraft** с плагинами | Семейство Paper + настройка из раздела ниже |

> Почему `Leaves` стоит упомянуть отдельно: его позиционирование — «исправление ванильных особенностей»; он сохраняет экосистему Paper (плагины, производительность) и возвращает изменённое поведение. Это реалистичный выбор, когда нужны «и плагины, и технический Minecraft».

## 2. Настройка ванильных особенностей на плагинном ядре

Если вы решили делать **умеренный технический Minecraft** на семействе Paper, настройте в первую очередь следующее (файл: `config/paper-world-defaults.yml`).

### Задержка выгрузки чанков

```yaml
chunks:
  delay-chunk-unloads-by: 0s
```

По умолчанию есть некоторая задержка. Только `0s` позволяет нормально работать устройствам вроде **возврата эндер-жемчуга через удержание**, которые зависят от «своевременной выгрузки чанков».

### Столкновения сущностей

```yaml
collisions:
  allow-player-cramming-damage: true
  max-entity-collisions: 2147483647
```

- `allow-player-cramming-damage`: получает ли игрок урон от сдавливания при избытке сущностей; для совпадения с ванилью установите `true`.
- `max-entity-collisions`: при превышении этого числа сервер **перестаёт обрабатывать столкновения сущностей**. Устройствам с плотными сущностями (например, крупным фермам мобов) нужно очень большое значение, **цена — падение производительности**.

### Поведение сущностей

```yaml
entities:
  behavior:
    # время неудачного выхода пчёл из улья, связано с ванильным поведением
```

Paper ради производительности добавил к части поведения сущностей «кулдауны» и ограничения; в технических сценариях их нужно проверять по пунктам и отключать.

### Реализация редстоуна

Paper позволяет переключать **реализацию редстоуна**. **Оставьте реализацию vanilla** — другая (оптимизированная) изменит поведение обновлений редстоуна, и машины сразу перестанут работать.
:::warn Перед правкой конфигурации сделайте копию
Ошибка в файлах `config/` приведёт к сбою запуска сервера. **Скопируйте перед правкой** и сразу восстанавливайте при проблеме.
:::

## 3. Частые моды технического Minecraft (модовое ядро)

Игроки технического Minecraft обычно ставят набор клиентских модов; на серверной стороне нужна соответствующая поддержка:

| Мод | Назначение |
| --- | --- |
| **Carpet** | Управление правилами на сервере; для технического сервера почти обязателен (включает и выключает массу деталей ванильного поведения) |
| **MiniHUD** | HUD с координатами, биомом, освещением и т. п. |
| **Litematica** | Проекция схематик, сборка машин по образцу |
| **Tweakeroo** | Набор удобных настроек |
| **Servux** | Обеспечивает работу отображения структур MiniHUD и вставки схематик на сервере |
| **Syncmatica** | Загружает схематики на сервер и делится ими с другими игроками |
| **BBOR** | Показывает границы естественных структур, 3D-границы биомов и слайм-чанки |
| **Jade / JEI (или REI)** | Просмотр информации о блоках / рецептов крафта |
| **Xaero's Minimap / World Map** | Миникарта и карта мира |
| **AppleSkin** | Показывает голод и восстановление сытости |
| **EasyAuth** | Серверный мод входа |
| **Fuji** | Многофункциональный административный мод |

> Часть функций многих модов **требует установки на сервере** для корректного отображения значений (например, точная сытость в AppleSkin); при запуске технического сервера согласуйте версии с игроками.

## 4. Специализированные редстоун-серверы

Если важна только **сама редстоун-схема** (например, большие вычислители, проверка таймингов машин), есть специализированные ядра для редстоуна (вроде **MCHPRS**): они убирают нагрузку, связанную с выживанием, и разгоняют вычисления редстоуна до очень высокого уровня.

Цена — **это не нормальный выживательный сервер**, многие ванильные механики неполны. Подходит для **тестирования машин**, но не для игры с игроками.

## 5. Итог по выбору

```
Нужен настоящий технический Minecraft (машины должны быть точными)
   → Fabric / Leaves / Vanilla
   → плагинное ядро при любой настройке не даст 100 % ванили

Нужен умеренный технический Minecraft + плагины
   → семейство Paper + настройка из раздела 2
   → примите, что «часть машин всё равно может не работать»

Нужно только тестировать редстоун-схемы
   → специализированное ядро вроде MCHPRS
```
