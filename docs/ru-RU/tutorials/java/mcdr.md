MCDReforged (сокращённо **MCDR**) — очень популярный в сообществе **менеджер сервера**. Он не заменяет ваше серверное ядро, а **оборачивает его снаружи**: запускает и управляет процессом ядра, читает вывод консоли и тем самым расширяет возможности, **не изменяя сам сервер**.

## 1. Какие задачи он решает

Ванильный / Paper сервер расширяется только «плагинами», а MCDR даёт **другой уровень** возможностей:

| Возможность | Описание |
| --- | --- |
| **Экосистема плагинов** | Плагины пишутся на **Python** и умеют то, что неудобно делать Java-плагинами (пересылка между серверами, интеграция с внешними API, автоматизация эксплуатации) |
| **Событийная модель** | Разбирает вывод сервера и рассылает события (вход/выход игроков, чат, смерть, команды…); плагину достаточно подписаться |
| **Горячая перезагрузка** | Плагины обычно перезагружаются без перезапуска всего сервера |
| **Система прав** | Собственный контроль прав по игрокам/группам, используется с командами с префиксом `!!` |
| **Сторожевой таймер** | Автоматически перезапускает ядро после краша |
| **Несколько серверов** | Один MCDR может управлять несколькими экземплярами сервера |

## 2. Как он работает

После запуска MCDR **берёт на себя процесс сервера**: читает вывод консоли и превращает его в события, а команды `!!xxx`, введённые в чате, перехватывает и передаёт плагинам, а не отправляет ванильному серверу.

Поэтому:

- сервер **сам по себе** остаётся прежним ядром, поведение не меняется;
- появляется дополнительная «оболочка», и **при диагностике нужно смотреть на один слой логов больше** (логи самого MCDR + логи сервера).

## 3. Установка

MCDR написан на **Python 3** и требует Python и pip:

| Версия MCDR | Требуемый Python |
| --- | --- |
| < 2.10 | ≥ 3.6 |
| ≥ 2.10 | ≥ 3.8 |
| ≥ 2.15 | **≥ 3.9** |

Чтобы поставить последнюю версию, используйте **pip**:

```bash
pip install mcdreforged
```

:::warn Не скачивайте zip с исходниками
Многие руководства в интернете советуют скачать архив с GitHub и распаковать его — **это устаревший способ**. Начиная с 1.0 (начало 2021 года) MCDR не устанавливается из исходников. Если вы не разработчик и не понимаете, что делаете, ставьте через pip.
:::

## 4. Порядок запуска

1. **Инициализация**: выполните команду инициализации один раз — MCDR создаст свои конфигурационные файлы и структуру каталогов.
2. **Настройка**: в конфигурации MCDR укажите **команду запуска сервера** и **рабочий каталог** (то, что делает скрипт запуска из «Запуска сервера», теперь выполняет MCDR).
3. **Запуск**: запустите MCDR — он поднимет сервер и перехватит консоль.
4. **Укажите тип сервера**: MCDR адаптируется к разным типам ядер через **обработчик сервера** (ваниль / семейство Paper / модовые и т. п.); ошибка приведёт к неверному разбору событий.

:::tip Подкоманды CLI — по официальной документации
Интерфейс командной строки MCDR (глобальные параметры, подкоманды) меняется между версиями; **сверяйтесь с официальной документацией CLI**, не копируйте старые руководства.
:::

## 5. Команды и права

Команды MCDR используют префикс `!!` (вводятся в чате в игре):

| Команда | Назначение |
| --- | --- |
| `!!MCDR` | Главная команда, управляет самим MCDR (состояние, плагины, перезагрузка, права и т. д.) |
| `!!help` | Справка по зарегистрированным командам |

- Права на выполнение команд контролируются **системой прав** MCDR и выдаются игроку или группе прав.
- Неавторизованный игрок получит отказ, и это не затронет сам сервер.

## 6. Плагины

- Плагины кладутся в каталог `plugins/` MCDR и загружаются / перезагружаются соответствующими подкомандами `!!MCDR`.
- У проекта есть **репозиторий плагинов**, где можно найти готовые; можно писать и свои (однофайловые, многофайловые, в виде каталога — несколько форм).
- В основе разработки плагина — **метаданные + обработчики событий + дерево команд**: объявить сведения о плагине, подписаться на нужные события и построить свои команды `!!`.

## 7. Когда стоит использовать MCDR

**Подходит**: если нужна автоматизация эксплуатации (перезапуск по расписанию, подъём после краша, связка с резервным копированием), интеграция состояния сервера с внешними платформами (группы QQ, Discord, сайт) или собственные Python-плагины с нестандартной логикой.

**Не обязательно**: для небольшого плагинного сервера достаточно плагинов самого ядра и управления через systemd. **Каждый слой добавляет расходы на обслуживание** — не используйте ради использования.
