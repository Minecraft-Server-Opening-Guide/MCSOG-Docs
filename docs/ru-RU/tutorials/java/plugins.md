Плагины — главная ценность **плагинных ядер** (Paper / Purpur / Spigot и т. п.): можно добавлять функции серверу, не меняя клиент и ничего не устанавливая игрокам.

## 1. Сначала разделите плагин и мод

| | Плагин | Мод |
| --- | --- | --- |
| Куда ставится | Серверный `plugins/` | Клиент + серверный `mods/` |
| Нужно ли что-то ставить игроку | **Нет** | Обычно да |
| Для каких ядер | Плагинные ядра | Модовые ядра (Fabric / Forge / NeoForge) |
| Можно ли смешивать | **Нет**: плагинное ядро не загрузит моды, модовое не загрузит плагины (если только не гибридное ядро или мост) |

## 2. Стандартный порядок установки плагина

1. Скачайте `.jar` плагина.
2. Положите его в папку `plugins/` в корне сервера.
3. **Перезапустите сервер** (большинство плагинов не поддерживают первую горячую загрузку).
4. Посмотрите в консоль: при запуске плагин обычно печатает своё имя и версию; ошибки тоже здесь.
5. Проверьте состояние командой `plugins` (см. ниже).

### Как по `plugins` понять состояние загрузки

```
plugins          (сокращённо pl)
```

- **Зелёный**: загружен — да (учтите: это значит только, что **он загрузился в этот раз**, а не что при работе не будет ошибок)
- **Красный**: ошибка загрузки — нет (сервер его распознал, но загрузить не смог; смотрите ошибку в консоли)
- **Его вообще нет**: сервер **не распознал** его как плагин → проверьте, действительно ли файл лежит в `plugins/`, правильное ли расширение `.jar` и не скачан ли не тот тип (например, мод установлен как плагин)

## 3. Плагины-зависимости

Многие плагины сами ничего не делают, а лишь предоставляют общие возможности; **их нужно ставить заранее**, иначе целевой плагин не загрузится:

| Зависимость | Что предоставляет |
| --- | --- |
| **Vault** | Единый интерфейс к экономике / правам / чату; от него зависит множество плагинов |
| **PlaceholderAPI** (PAPI) | Заглушки переменных (например, баланс игрока, число онлайн); общий способ обмена данными между плагинами |
| **ProtocolLib** | Низкоуровневая работа с протоколом; зависимость многих продвинутых плагинов |
| **LuckPerms** | Управление правами, тонкий контроль того, кому доступны какие команды |

## 4. Конфигурация и YAML

Конфигурация плагинов обычно лежит в `plugins/<plugin-name>/`, чаще всего `config.yml`. Самые частые ловушки при написании YAML:

- **Отступы только пробелами, не Tab** (главный источник ошибок YAML).
- После двоеточия нужен пробел, например `enabled: true`.
- Иерархия выражается отступами; отступы одного уровня должны совпадать.

:::warn Кракозябры вместо текста
Если не-ASCII текст в конфигурации отображается кракозябрами, скорее всего **файл не в UTF-8** (Блокнот Windows при «Сохранить как» легко делает ANSI/GBK). Используйте редактор вроде VS Code и сохраните в **UTF-8**.
:::

### Цветовые коды

Серверный текст (MOTD, чат, сообщения плагинов) использует `&` с буквой для цвета и стиля, например:

```
&aзелёный  &cкрасный  &lжирный  &oкурсив  &rсброс
```

Конкретный набор зависит от версии сервера и плагина.

## 5. Как применить изменения конфигурации

| Способ | Описание |
| --- | --- |
| `/<plugin-name> reload` или `/<сокращение> reload` | Поддерживают большинство плагинов, **предпочтительно** (например, `/tab reload`) |
| Перезапуск сервера | Самый надёжный; для плагинов без горячей перезагрузки — единственный вариант |
| `/reload` (ванильная команда) | **Не рекомендуется**, легко рассинхронизирует состояние плагинов |

## 6. Выбор плагинов по задачам

| Задача | Частые варианты |
| --- | --- |
| Права | LuckPerms |
| Базовые функции (дом, телепорт, наборы) | EssentialsX, CMI |
| **Защита от разрушений и откат** | CoreProtect (журнал блоков: после инцидента можно узнать, кто это сделал) |
| Защита территорий | Residence, Dominion, GriefDefender |
| Редактирование мира | WorldEdit (создатель миров), WorldGuard (защита регионов) |
| Несколько миров | Multiverse-Core |
| Формат чата | TrChat, Carbon |
| Меню / GUI | DeluxeMenus, TrMenu |
| MOTD и список серверов | MiniMOTD |
| Скины (обязательно в офлайн-режиме) | SkinsRestorer |
| Вход (офлайн-режим) | AuthMe, LibreLogin |
| Совместимость версий | ViaVersion + ViaBackwards |
| Горячее управление плагинами | PlugManX |

Типичный стартовый набор: **LuckPerms + EssentialsX + CoreProtect + WorldEdit/WorldGuard + Vault + PlaceholderAPI**, дальше — по геймплею.

## 7. Безопасность: у плагинов тоже бывает «яд»

Плагин — **сторонний код, работающий с правами сервера**; ошибка при установке обходится дорого:

- **Скачивайте только из доверенных источников**: официальные каналы (SpigotMC, Modrinth, Hangar) или репозиторий автора. Jar, пересланный на форуме или в файлах группы, — самый высокий риск.
- **Остерегайтесь бэкдоров**: нормальный плагин пересобирают и вставляют код, выполняющий произвольные команды, выдающий OP конкретным игрокам или загружающий файлы.
- **Следите за поддержкой**: плагин без обновлений, автор которого ушёл, на новой версии может просто уронить сервер.
- **Если не уверены — сначала тестовый сервер**: не ставьте плагин неизвестного происхождения сразу на основной сервер.

:::tip При проблеме сначала подозревайте плагин
Если сервер внезапно залагал или выдаёт странные ошибки, **сначала отключите недавно установленные плагины**, затем включайте по одному — это гораздо быстрее чтения логов.
:::
