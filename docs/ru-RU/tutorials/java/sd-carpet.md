На техническом сервере каждый день приходится иметь дело с **Carpet**: он превращает массу жёстко заданных деталей ванильного поведения в **правила, которые можно включать и выключать командами**. Здесь — как пользоваться системой правил, что добавляет каждое из четырёх основных дополнений и несколько **проверенных правил защиты от крашей**.

## 1. Что такое Carpet

`Carpet` — **серверный мод Fabric**, предоставляющий **систему правил**: `/carpet <имя-правила> <значение>` включает и выключает то, что в ванили было жёстко задано.

Несколько фактов:

- поддерживаемые версии — от `1.14.4` до `26.3`, всего 179 записей версий, около 11,25 млн загрузок;
- в официальном исходнике `CarpetSettings.java` — **91 правило с аннотацией `@Rule`**.

То есть он умеет менять очень многое, и **«можно включить» не значит «стоит включать»**: базовое правило технического сервера — включать только те правила, чьи последствия вы понимаете.

## 2. Как пользоваться `/carpet`

Взаимодействие с системой правил очень простое:

```
/carpet <имя-правила> <значение>        # изменить одно правило
```

На практике рекомендуется три вещи:

1. **Меняйте по одному правилу**, после изменения понаблюдайте за машинами и только потом трогайте следующее;
2. **Записывайте изменённые правила** (в правила сервера или заметки по эксплуатации) и проверяйте их по пунктам при смене ядра и обновлении версии;
3. все правила, **меняющие ванильное поведение**, на рабочем сервере по умолчанию выключены и включаются только для одиночных тестов или особых сценариев.

Имена правил ниже взяты из официального исходного кода Carpet; к каждому дано пояснение.

## 3. Примеры правил

### Производительность и сущности

| Правило | Пояснение |
| --- | --- |
| `optimizedTNT` | Взрывы TNT в одной точке и в жидкости вызывают меньше лагов |
| `maxEntityCollisions` | Свой лимит столкновений сущностей; 0 — без ограничения |
| `lagFreeSpawning` | Спавн требует гораздо меньше CPU и памяти |
| `fastRedstoneDust` | Оптимизация лагов от редстоун-пыли |
| `movableBlockEntities` | Поршни могут двигать блок-сущности, например воронки и сундуки |

### Меняющие поведение (на рабочем сервере по умолчанию не включать)

| Правило | Пояснение |
| --- | --- |
| `tntDoNotUpdate` | TNT, поставленный у источника питания, не обновляется |
| `explosionNoBlockDamage` | Взрывы не разрушают блоки |
| `antiCheatDisabled` | Не даёт отбрасывать игрока назад из-за слишком быстрого движения |
| `updateSuppressionBlock` | Активированные рельсы на барьерном блоке: при повороте рельсы заполняют стек обновлений соседей |
| `stackableShulkerBoxes` | Пустые шалкеровые ящики на земле складываются в стопку |

`updateSuppressionBlock` — официальная управляемая точка входа для подавления обновлений (в сообществе это называют «резка порталов»); правила защиты от крашей для него — в разделе 6.

### Подсчёт и отладка

| Правило | Пояснение |
| --- | --- |
| `hopperCounters` | Воронка, направленная на шерсть, считает проходящие предметы |
| `commandTick` | Включает команду `/tick` для управления игровыми часами |

### Есть имена, но без описания

Эти правила действительно существуют, но здесь приведены только имена; конкретное поведение — по исходникам вашей версии или выводу `/carpet` в игре:

`creativeNoClip`, `renewableSponges`, `persistentParrots`, `flippinCactus`, `xpNoCooldown`, `smoothClientAnimations`, `tntPrimerMomentumRemoved`, `commandPlayer`.

## 4. Четыре основных дополнения

Сам Carpet содержит только основной набор правил; расширения функций — в дополнениях. Адреса репозиториев, поддерживаемые версии и число записей ниже — официальные данные Modrinth.

| Название | Репозиторий | Поддерживаемые версии | Число записей версий | Позиционирование |
| --- | --- | --- | --- | --- |
| Carpet Extra | `gnembon/carpet-extra` | 1.14.4–26.2 | 87 | Новое поведение раздатчиков, новые способы получения и т. п. |
| Carpet TIS Addition | `TISUnion/Carpet-TIS-Addition` | 1.14.4–26.3 | 141 | Пакет расширений Fabric Carpet |
| Carpet AMS Addition | `Minecraft-AMS/Carpet-AMS-Addition` | 1.16.4–26.3 | 49 | Официальный сайт `https://carpet.mcams.club` |
| Carpet Org Addition | `fcsailboat/Carpet-Org-Addition` | 1.19.4–26.3 | 34 | Пакет расширений Carpet |

Как выбирать:

- **Carpet Extra** и **TIS Addition** покрывают самые старые версии, часто встречаются в старых сборках;
- **AMS Addition** и **Org Addition** начинаются с более новых версий (1.16.4 и 1.19.4), но обе дошли до 26.3;
- ставьте то дополнение, в котором есть **нужные вам правила**, не обязательно все.

:::warn Дополнения работают только при совпадении основной версии Carpet
Напоминание из разряда очевидных: дополнения зависят от интерфейсов самого Carpet; **при другой версии игры или другой основной версии Carpet дополнение может вообще не загрузиться или часть правил перестанет работать**. Перед установкой убедитесь, что диапазон версий дополнения покрывает вашу версию сервера, после установки посмотрите через `/carpet` в игре, появились ли правила; при обновлении Carpet обновляйте и дополнения. Конкретика — по описаниям версий каждого дополнения.
:::

## 5. Проверенные правила защиты от крашей

Пожиратели мира и подавление обновлений намеренно создают **экстремальные обновления блоков и переполнение стека**; для сервера прямое следствие — краш. Ниже правила, проверенные для этой задачи — удержать такие риски.

### Carpet TIS Addition

| Правило | Направление действия |
| --- | --- |
| `yeetUpdateSuppressionCrash` | Обрабатывает краши, вызванные подавлением обновлений |
| `updateSuppressionSimulator` | Симуляция подавления обновлений |
| `deobfuscateCrashReportStackTrace` | Деобфусцирует стек вызовов в отчёте о краше, чтобы лог был читаемым |

### Carpet AMS Addition

| Правило | Допустимые значения |
| --- | --- |
| `amsUpdateSuppressionCrashFix` | `false` / `true` / `silence` |
| `customBlockUpdateSuppressor` | `none` / `minecraft:bone_block` / `minecraft:diamond_ore` / `minecraft:magma_block` |

`customBlockUpdateSuppressor` превращает указанный блок в **блок подавления обновлений** — иными словами, вы сами выбираете, какой блок играет роль «заполнения стека обновлений соседей», а не только `updateSuppressionBlock` из основного Carpet.

Отдельно: в Carpet Org Addition **не найдено правил, связанных с подавлением или крашами**, поэтому их имена здесь не приводятся.

## 6. Как это сочетается с пожирателями мира и резкой порталов

- **«Резка порталов» — обиходное название операций «подавления обновлений» (update suppression)** в сообществе, а не официальный термин игры;
- официальная управляемая точка входа в Carpet — `updateSuppressionBlock`; `customBlockUpdateSuppressor` из AMS позволяет заменить блок;
- риск краша страхуют `yeetUpdateSuppressionCrash`, `updateSuppressionSimulator`, `deobfuscateCrashReportStackTrace` из TIS и `amsUpdateSuppressionCrashFix` из AMS;
- эти три уровня соотносятся как «**управляемый вход + заменяемые параметры + страховка от краша**»; без любого из них диагностика усложняется.

Как именно включать машины и контролировать риски — в статье [Пожиратели мира и резка порталов](/tutorials/java/sd-machine). Вывод там такой: чем мощнее машины, тем важнее связка «копии + права + правила защиты от крашей», и **правила защиты от крашей — это как раз правила из этого раздела**.

## 7. Три нижние границы этой статьи

```
1. Включайте только правила, чьи последствия понимаете — каждое изменение записывайте
2. Дополнение должно совпадать с основной версией — после установки проверьте через /carpet, что правила на месте
3. Сначала правила защиты от крашей — до пожирателей мира и подавления обновлений подстрахуйте краши
```
