Сервер, работающий на локальной машине, — лишь первый шаг. Настоящий запуск — это когда **к нему могут подключиться другие**. На этом этапе почти все сложности связаны с сетью, а не с самим Minecraft.

## 1. Три пути, выберите один

| Вариант | Кому подходит | Плюсы | Цена |
| --- | --- | --- | --- |
| **Облачный сервер** | Нужен круглосуточный онлайн | Публичный IP, стабильность, не страшны отключения электричества и интернета | Платно, чем мощнее конфигурация, тем дороже |
| **Домашний компьютер + публичный IP** | Дома есть публичный IPv4 | Без дополнительных расходов, контролируемая производительность | Электричество/шум/отключения, и **у большинства домашних подключений нет публичного IPv4** |
| **Туннель через NAT (frp и т. п.)** | Дома нет публичного IP | Можно запустить без смены провайдера | Лишний слой пересылки; задержка и стабильность зависят от туннельного сервиса |

:::warn Сначала проверьте, есть ли у вас публичный IPv4
Адреса IPv4 дефицитны, и **многие домашние подключения получают адрес из большой внутренней сети провайдера**; в этом случае проброс портов на роутере не поможет. Как проверить: если IP на WAN-порту роутера **не совпадает** с результатом запроса «мой публичный IP», публичного IPv4 нет.

Если публичного IP нет: запросить у провайдера (где-то бесплатно, где-то платно, где-то не дают), перейти на облачный сервер или использовать туннель.
:::

## 2. Путь с облачным сервером

1. **Купите машину**: выбирайте по «Соглашению о запуске и рекомендациям по конфигурации», главное — **частота одного ядра**; система — Ubuntu / Debian Server.
2. **Подготовьте среду**: по «Подготовке среды (Windows и Linux)» установите нужную версию Java, создайте отдельного пользователя и каталоги.
3. **Откройте порт**: разрешите `TCP 25565` в security group и в системном firewall (ufw / firewalld) — **в обоих местах**.
4. **Загрузите сервер**: перенесите весь каталог сервера через SFTP или `scp`.
5. **Запустите и закрепите**: поручите systemd, настройте автозапуск при загрузке и перезапуск при краше (см. шаг 5 «Подготовки среды»).
6. **Проверьте**: подключитесь с **другой машины** к `<публичный IP>:25565`.

## 3. Путь с домашним компьютером

1. **Запросите/подтвердите публичный IPv4** (см. выше).
2. **Проброс портов на роутере**: перенаправьте внешний `25565` на `25565` (TCP) внутренней машины.
3. **Зафиксируйте внутренний IP**: привяжите статический IP в роутере, чтобы после перезагрузки адрес не сменился и проброс не сломался.
4. Разрешите `25565` в **системном firewall**.
5. **Обеспечьте непрерывность**: установите в настройках питания **никогда не засыпать** и учитывайте риски отключения электричества и интернета.

## 4. Путь с туннелем (frp)

Принцип: на **машине с публичным IP** (frps-сервер) открывается порт, и трафик перенаправляется на вашу домашнюю машину (frpc-клиент). Обычно берут самый дешёвый облачный сервер под frps.

```ini
# frps.ini (на сервере с публичным IP)
[common]
bind_port = 7000
```

```ini
# frpc.ini (на машине в домашней сети)
[common]
server_addr = <ip-вашего-публичного-сервера>
server_port = 7000

[minecraft]
type = tcp
local_ip = 127.0.0.1
local_port = 25565
remote_port = 25565
```

Порядок запуска: сначала `frps`, затем `frpc`; после этого игроки подключаются к **IP публичного сервера:25565**.

:::tip Можно использовать готовый туннельный сервис
Если не хочется обслуживать свой узел, можно взять коммерческий туннельный сервис: проще, но обычно с лимитами трафика/пропускной способности и **очень разным качеством**. При выборе сначала проверьте поддержку **TCP** (UDP обычно платный и нужен только для Bedrock Edition или кроссплатформенной игры).
:::

## 5. Домен (необязательно, но рекомендуется)

С доменом игрокам не нужно запоминать IP:

- **Запись A**: `mc.<ваш-домен>.com` → публичный IPv4 сервера.
- **Запись SRV**: чтобы игрокам не нужно было вводить порт, SRV указывает `_minecraft._tcp` на ваш реальный порт. Тогда игроку достаточно ввести домен.

Учтите: **для серверов в Китае домен обычно требует ICP-регистрации**, для зарубежных серверов — нет.

## DNS и записи SRV

В предыдущем разделе говорилось, что «с доменом игрокам не нужно запоминать IP»; на практике это обеспечивают записи DNS. Здесь разом разобраны типы записей, точный синтаксис SRV и способы диагностики.

### Записи, которые понадобятся при запуске

| Тип записи | Назначение | Пример | Замечания |
| --- | --- | --- | --- |
| `A` | Домен → адрес IPv4 | `mc.example.com` → `203.0.113.10` | Самая базовая; у одного имени может быть несколько записей A |
| `AAAA` | Домен → адрес IPv6 | `mc.example.com` → `2001:db8::10` | Нужна, только если у сервера есть IPv6; если игрок не подключается по IPv6, проверяйте в первую очередь её |
| `CNAME` | Псевдоним, указывающий на другой домен | `mc.example.com` → `node1.example.net` | **Не может сосуществовать с другими записями на одном имени**: при наличии CNAME нельзя иметь A / AAAA / TXT и т. п.; на корневом домене обычно тоже не разрешается |
| `SRV` | Объявляет, на каком хосте и порту работает сервис | `_minecraft._tcp.example.com` | Только для Java Edition, см. ниже |
| `TXT` | Текстовая запись, часто для подтверждений и объявлений | проверочное значение `_acme-challenge.example.com` | Часто используется для подтверждения владения доменом и настройки почты; на сам запуск сервера напрямую не влияет |

**TTL** — время кэширования каждой записи в секундах; оно определяет, «через сколько весь мир увидит новое значение после правки». В обычное время можно ставить больше (например, `3600`); **перед запланированной миграцией сначала уменьшите TTL** (например, до `300`), дождитесь истечения старого TTL и только потом переключайтесь — так при проблеме можно быстро вернуться. Полный порядок миграции — в [Переносе сервера](/tutorials/ops/server-migration).

### Зачем нужна запись SRV

Порт Minecraft по умолчанию — `25565`. Если сервис работает на другом порту или вообще на другой машине, игроку придётся вводить адрес с портом, например `mc.example.com:25566`. **Запись SRV как раз избавляет от порта**: она сообщает клиенту, «на каком хосте и порту на самом деле работает Minecraft-сервис для этого домена», и игроку достаточно ввести домен.

Имя SRV-запроса в Java Edition фиксировано: `_minecraft._tcp.<ваш-домен>`. В файле зоны это выглядит так:

```dns
; игрок вводит mc.example.com, а сервис работает на node1.example.com:25566
_minecraft._tcp.example.com.  3600  IN  SRV  10 5 25566 node1.example.com.
node1.example.com.            3600  IN  A    203.0.113.10
```

Значение четырёх числовых полей:

| Поле | Пример | Значение |
| --- | --- | --- |
| `priority` | `10` | Приоритет, **побеждает наименьшее значение**; распределение нагрузки идёт только между записями с одинаковым приоритетом |
| `weight` | `5` | Вес, действует только при одинаковом приоритете; распределение пропорционально, чем больше значение, тем выше вероятность выбора |
| `port` | `25566` | **Реальный порт прослушивания сервиса**, не 25565 |
| `target` | `node1.example.com.` | Реальное имя хоста сервиса; оно **само должно разрешаться** |

К `target` предъявляются два жёстких требования: это должно быть имя хоста, и обычно оно должно указывать на запись `A` / `AAAA`; не направляйте его на CNAME и тем более не делайте цепочку CNAME → CNAME.

:::warn target нельзя записывать IP-литералом
Указать в `target` IP (например, `SRV 10 5 25566 203.0.113.10.`) **недопустимо** по протоколу: клиент не будет использовать такую запись, даже если какая-то панель позволяет её ввести. Правильно — создать для целевого хоста запись `A` / `AAAA` и направить `target` на это имя.
:::

:::warn Самая частая ошибка: забытая точка в конце target
В консолях большинства DNS-провайдеров `target` нужно записывать как полное имя **с точкой в конце** (`node1.example.com.`). Без точки консоль воспримет его как имя «относительно текущей зоны» и получится `node1.example.com.example.com.` — запись бесполезна, и **никакой ошибки не будет**.
:::

### Bedrock Edition не поддерживает SRV

Это нужно проговорить отдельно:

- **Клиент Java Edition запрашивает SRV-запись для `_minecraft._tcp`**, поэтому игрокам Java достаточно домена.
- **Клиент Bedrock Edition не использует SRV**. Игрокам Bedrock нужно вводить `хост:порт` (например, `mc.example.com:19132`) или использовать домен, который напрямую разрешается в нужный адрес с совпадающим портом.

Итак, SRV — **удобство, доступное только Java Edition**. Если сервер обслуживает обе версии, не рассчитывайте, что одна SRV решит всё за всех: на стороне Bedrock порт всё равно придётся указывать.

### Как проверить, что записи действительно работают

```bash
# проверить SRV-запись (Linux / macOS)
dig +short SRV _minecraft._tcp.example.com

# проверить SRV-запись (Windows или машина без dig)
nslookup -type=SRV _minecraft._tcp.example.com

# проверить A-запись
dig +short A example.com
```

- `dig +short SRV` обычно возвращает четыре части вроде `10 5 25566 node1.example.com.`; пустой ответ означает, что запись не действует, имя написано неверно или вы спрашиваете не авторитетный сервер.
- Затем `dig +short A node1.example.com` подтвердит, что **сам target разрешается** — этот шаг чаще всего забывают.
- И наконец **проверка клиентом**: добавьте сервер в игре, укажите только домен и посмотрите, подставит ли клиент порт сам и подключится ли.

Изменения DNS вступают в силу не сразу — нужно дождаться истечения старого TTL. При диагностике сначала спросите авторитетный сервер напрямую: `dig @ns1.example.com ...`, убедитесь, что запись написана верно, и только потом ждите истечения кэша. **Самое коварное в ошибке SRV — отсутствие ошибки**: клиент просто не подключается и не сообщает, что с SRV что-то не так.

### Таблица частых неполадок

| Симптом | Причина | Как проверить |
| --- | --- | --- |
| По IP подключается, по домену нет | `target` в SRV не разрешается или неверно указан `port` | `dig +short SRV _minecraft._tcp.<ваш-домен>`, затем `dig +short A` для target |
| Подключается, но попадает на другой сервер | Запись старая или TTL после правки ещё не истёк | Сравните результат `dig` с фактическим IP / портом; при необходимости сначала уменьшите TTL, потом правьте |
| Игроки Bedrock не заходят по короткому адресу | Bedrock не поддерживает SRV | Попросите указывать `хост:порт` или заведите отдельный домен с прямым подключением |
| Запись добавлена, но ничего не меняется | TTL ещё не истёк или правилась не та зона (например, меняли `example.com`, а игрок запрашивает `mc.example.com`) | Спросите авторитетный сервер напрямую; убедитесь, что запись добавлена в правильную зону |
| Домен разрешается, но подключения нет | С DNS всё в порядке, порт не открыт в firewall или security group | Проверьте с внешней машины: `telnet <домен> <порт>` или `nc -vz <домен> <порт>` |

### Дополнительные записи для прокси и панелей

- Если перед сервером стоит **прокси Velocity / BungeeCord**, `target` в SRV должен указывать на адрес **прокси**, а `port` — на порт прослушивания прокси, а не какого-то дочернего сервера.
- При использовании **панели** (MCSManager, Pterodactyl и т. п.) адрес панели — отдельная история: обычно ей нужен собственный поддомен (например, `panel.example.com`) и обратный прокси; **на игровую SRV-запись это не влияет**, не смешивайте их в одной записи.
- Некоторые провайдеры или дата-центры требуют дополнительные проверочные записи (`TXT`, `CNAME`) — добавляйте по их инструкции.

## 6. Чек-лист безопасности перед публикацией

- [ ] `online-mode` оставлен `true` (если только вы не понимаете риски)
- [ ] Порт консоли/RCON (например, `25575`) **ни в коем случае не открыт в интернет**
- [ ] На Linux сервер **не запускается от root**, используется отдельный пользователь
- [ ] Настроен белый список или проверка заявок (перед публикацией протестируйте в узком кругу)
- [ ] Включено **автоматическое резервное копирование** (см. «Резервное копирование и восстановление»)
- [ ] Установлены **плагины защиты/логирования** (см. «Плагины» и «Античит»)
- [ ] Доступность порта проверена с внешней машины
