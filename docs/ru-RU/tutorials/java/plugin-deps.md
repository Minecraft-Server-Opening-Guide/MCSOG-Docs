Самая частая ошибка при установке плагинов — не неверная версия, а **забытая зависимость**: плагин лежит в `plugins/`, а в `/plugins` он красный, или установлен, но часть функций отсутствует.

Эта статья объясняет, что такое зависимость, что будет без неё и чем занимаются четыре самых зависимых плагина: Vault, PlaceholderAPI, ProtocolLib и LuckPerms.

## 1. Что такое плагин-зависимость

Плагины могут зависеть друг от друга. Если автор не хочет изобретать велосипед, он объявляет «мне нужна возможность, которую предоставляет другой плагин»; нужный плагин и есть **зависимость (dependency)**.

Зависимости записываются в `plugin.yml` внутри jar плагина и бывают двух видов:

| Объявление | Значение | Что будет без неё |
| --- | --- | --- |
| `depend` (жёсткая зависимость) | Без неё работать нельзя | Плагин **не загружается**, в `/plugins` отображается красным |
| `softdepend` (мягкая зависимость) | С ней включаются дополнительные функции, без неё тоже работает | Плагин загружается нормально, **соответствующие функции тихо отключаются** |

При запуске сервер сначала загружает зависимости, а затем зависящие от них плагины — поэтому «зависимость нужно ставить раньше».

:::note Любой плагин может быть зависимостью
Зависимость — не особый класс плагинов. Теоретически любой плагин может быть объявлен зависимостью другим; просто перечисленные ниже зависят так часто, что за ними закрепилось общее название «плагины-зависимости».
:::

## 2. Что будет без зависимости

Симптомы не всегда выглядят как «ошибка»; зная эти проявления, сэкономите много времени:

| Симптом | Описание |
| --- | --- |
| В `/plugins` отображается красным | Сервер распознал плагин, но загрузить не смог; причина точно есть в консоли |
| В консоли `Unknown dependency` | Самый однозначный случай: жёсткая зависимость из `plugin.yml` отсутствует в `plugins/` |
| В консоли `ClassNotFoundException` / `NoClassDefFoundError` | Код ссылается на класс, предоставляемый зависимостью, но этого класса нет |
| Плагин установлен, но какая-то функция «не реагирует» | Чаще всего не хватает мягкой зависимости, и функция отключена автоматически |
| Переменная отображается как `%player_name%` | Не установлен PlaceholderAPI или не скачано соответствующее расширение |
| Команды экономики сообщают, что экономическая система не найдена | Vault установлен, но нет плагина, реально предоставляющего экономику |

:::warn Сначала консоль, потом догадки
Причина сбоя загрузки плагина обязательно записана в логах запуска. **Откройте `logs/latest.log` и найдите имя плагина** — это гораздо быстрее, чем описывать в чате «мой плагин красный».
:::

## 3. Как понять, что плагину нужна зависимость

По убыванию надёжности:

1. **Страница выпуска плагина**. В описании на SpigotMC, Modrinth, Hangar, GitHub обычно есть раздел `Requires`, `Dependencies` или «зависимости».
2. **`plugin.yml` внутри jar**. Откройте jar архиватором, найдите `plugin.yml`: строки `depend` и `softdepend` — самый авторитетный ответ.
3. **Ошибки в консоли**. Если при запуске пишут, чего не хватает, — добавьте это.
4. **Цвет в `/plugins`**. Для красной записи сначала подозревайте зависимость, потом несовпадение версий.
5. **Документация плагина или раздел issue**. Авторы обычно ясно указывают зависимости и требования к версиям.

## 4. Vault

**Что это**: Vault — **библиотека абстракции** для серверов семейства Bukkit. Она сама не выполняет конкретных функций, а определяет набор интерфейсов, позволяя «плагинам, которым нужны экономика/права/чат» и «плагинам, которые реально это реализуют» понимать друг друга.

**Это не плагин экономики**. Здесь чаще всего ошибаются: Vault сам не создаёт никакой валюты, это лишь единый интерфейс. Чтобы экономика действительно была, нужно поставить плагин экономики (например, XConomy, экономический модуль EssentialsX, CMI), который регистрирует сервис в Vault, а другие плагины через Vault читают и меняют баланс.

| Интерфейс Vault | Кто реализует | Кто вызывает |
| --- | --- | --- |
| Экономика (Economy) | Плагин экономики | Магазины, ежедневные награды, розыгрыши и т. п. |
| Права (Permission) | Плагин прав (например, LuckPerms) | Плагины, которым нужно проверять права игрока |
| Чат (Chat) | Плагин чата | Плагины, которым нужно отправлять/форматировать чат |

**Кому нужен**: если в списке плагинов есть запись «зависит от Vault», ставьте его. Владельцу сервера не нужно ничего настраивать в Vault — достаточно установить.

:::tip Метку версии можно игнорировать
Vault поддерживает и старые, и новые версии Minecraft, поэтому не обращайте внимания на версии, указанные на странице SpigotMC.
:::

## 5. PlaceholderAPI

**Что это**: PlaceholderAPI (сокращённо PAPI) — система заглушек-переменных. Текст вида `%расширение_параметр%` заменяется информацией, которую предоставляют другие плагины.

```
%player_name%        имя игрока
%player_level%       уровень игрока
%vault_eco_balance%  баланс игрока
%server_online%      число игроков онлайн
```

На примере `%player_name%`: `player` — имя расширения, `name` — параметр, вместе — «взять имя игрока».

**Расширения переменных**: сам PAPI почти не предоставляет переменных — их дают отдельные **расширения**. Расширения скачиваются в игре из eCloud; сейчас их сотни, они покрывают EssentialsX, LuckPerms, Vault и множество других плагинов.

```
/papi ecloud download Player     скачать расширение Player
/papi list                       посмотреть установленные расширения
/papi info <имя-расширения>      посмотреть, какие переменные даёт расширение
/papi reload                     перезагрузить PAPI и расширения
```

**Отладка**: проверив переменную в игре сразу после написания, не ждите, пока игроки сообщат об ошибке.

```
/papi parse me %player_name%
```

Команда сразу возвращает результат разбора; `me` означает контекст самого себя.

**Вложенность переменных**: когда результат разбора одной переменной подставляется в параметр другой, внутренний уровень записывается в `{}` вместо `%%`:

```
%math_2_{player_health}%
```

В примере нужно расширение math; оно оставляет здоровье игрока с двумя знаками после запятой.

**Что ещё умеют**: некоторые расширения дают больше, чем «получение значения»: Math (математика), CheckItem (проверка предметов игрока), JavaScript (выполнение скриптов), Progress (генерация полосы прогресса).

**Кому нужен**: плагины TAB, счётные таблицы, голограммы, меню, формат чата, MOTD — всё, что «показывает данные других плагинов», — в основном опирается на PAPI. Это один из плагинов, которые стоит поставить заранее.

## 6. ProtocolLib

**Что это**: ProtocolLib даёт низкоуровневый доступ к сетевому протоколу Minecraft (пакетам), позволяя плагинам перехватывать, изменять или отправлять пакеты и делать то, что Bukkit API не предоставляет.

**Кому нужен**: он **для разработчиков плагинов**. Владельцу сервера настраивать ничего не нужно — если какой-то плагин требует ProtocolLib, просто поставьте его.

| Пункт | Описание |
| --- | --- |
| Нужна ли настройка | Нет, работает сразу после установки |
| Выбор версии | Для 1.8–1.19.4 используется 5.0.0; для более новых — последняя версия |
| Частая настройка | В `plugins/ProtocolLib/config.yml` можно поставить `auto updater.notify` в `false`, чтобы отключить уведомления об обновлениях |

:::warn Версии должны совпадать
ProtocolLib работает напрямую с внутренней реализацией сервера, и **при несовпадении версий может ругаться или падать весь сервер**, а не отдельный плагин. Обновляя ядро сервера, не забудьте проверить и его.
:::

## 7. LuckPerms

**Что это**: LuckPerms — самый распространённый **плагин прав**; он управляет тем, «кому доступны какие команды, кто может войти в какой мир, какой префикс отображается». Поддерживает Bukkit/Spigot/Paper, BungeeCord, Velocity, Sponge, Fabric и другие платформы.

**Ключевые понятия**:

| Понятие | Назначение |
| --- | --- |
| Узел прав (permission) | Минимальная единица вида `essentials.fly`; `true` — разрешено, `false` — запрещено |
| Группа (group) | Набор прав, например `default`, `vip`, `admin` |
| Наследование (inheritance) | Группа может наследовать другую; если `admin` наследует `vip`, не нужно дублировать настройку |
| Контекст (context) | Права действуют только в определённом мире, на сервере или в режиме |
| Префикс / суффикс (meta) | Отображаемая информация для плагинов чата, TAB и т. п. |

**Частые команды**:

```
/lp user <игрок> permission set <узел> true
/lp group <группа> permission set <узел> true
/lp group <группа> parent add <родительская-группа>
/lp user <игрок> parent add <группа>
/lp editor
```

`/lp editor` создаёт ссылку на веб-редактор: менять права графически гораздо нагляднее, чем вводить команды; после сохранения изменения вступают в силу.

**Хранение**: по умолчанию используется файловое хранилище (H2/SQLite), данные лежат в `plugins/LuckPerms/`. **Если несколько серверов используют один набор прав, обязательно перейдите на базу данных вроде MySQL/MariaDB**, иначе каждый сервер будет вести свои права.

**Связь с Vault**: LuckPerms регистрирует в Vault сервис прав, поэтому плагины, которые «проверяют права через Vault», после установки LuckPerms работают нормально без дополнительной настройки.

:::note Кто показывает префикс
LuckPerms только хранит префикс, но **не показывает его**. Префикс появляется в чате или TAB благодаря плагину чата (например, TrChat, Carbon) или плагину TAB, которые читают meta-информацию из LuckPerms.
:::

## 8. Порядок установки и сочетания

Зависимости нужно **ставить и перезапускать первыми**, а затем ставить зависящие от них плагины. Типичный стартовый порядок:

| Порядок | Плагин | Причина |
| --- | --- | --- |
| 1 | LuckPerms | Права — основа, по которой другие плагины решают, «можно ли использовать» |
| 2 | Плагин экономики (XConomy / EssentialsX / CMI) | Даёт Vault настоящую реализацию экономики |
| 3 | Vault | Даёт единый интерфейс к экономике, правам и чату |
| 4 | PlaceholderAPI | После установки скачайте нужные расширения переменных |
| 5 | ProtocolLib | Ставьте только когда его явно требует какой-то плагин |
| 6 | Остальные функциональные плагины | Магазины, меню, титулы, TAB и т. д. |

:::tip Проверяйте после каждой установки
Перезапускайте после установки каждой зависимости и убеждайтесь, что в `/plugins` она зелёная. Если сразу закинуть десяток плагинов, при проблеме стоимость диагностики вырастет в разы.
:::

## 9. Чек-лист диагностики

| Что проверить | Как убедиться |
| --- | --- |
| Зависимость действительно в `plugins/` | Проверьте имя файла и расширение `.jar` |
| Не хватает жёсткой зависимости | Поищите в консоли `Unknown dependency` |
| Не хватает мягкой зависимости | Функция не реагирует, но плагин зелёный — проверьте в документации, от кого он зависит |
| Версии совпадают | Сверьте с версией сервера и зависимостей, указанными на странице выпуска |
| Переменные не разбираются | Убедитесь, что PAPI установлен и расширение скачано, затем проверьте через `/papi parse me` |
| Экономика недоступна | Убедитесь, что установлены Vault **и** настоящий плагин экономики |
| Права не действуют | Проверьте результат через `/lp user <игрок> permission check <узел>` |
| Изменения не применились | Используйте команду reload самого плагина или перезапустите |
