В повседневном управлении сервером используется один и тот же набор команд. **В консоли сервера их выполняют без `/`**, а в чате в игре — с `/`.

## 1. Запуск, остановка и сохранение

| Команда | Назначение |
| --- | --- |
| `stop` | **Безопасно выключает** сервер (сначала сохраняет, потом выходит). **Всегда закрывайте сервер этой командой, не закрывайте окно крестиком** |
| `save-all` | Немедленно сохраняет данные всех миров |
| `save-off` / `save-on` | Отключает / включает автосохранение (**перед копированием** отключите, чтобы не копировать недописанное сохранение) |
| `reload` | Перезагружает датапаки и часть конфигурации. **Осторожно**: может рассинхронизировать состояние плагинов; если у плагина есть своя `reload`, используйте её |
| `restart` | Перезапускает сервер (поддерживается некоторыми ядрами) |

:::tip Стандартный порядок остановки
`save-all` → `save-off` → резервная копия → `stop`. Если просто закрыть окно, можно повредить сохранение или потерять данные.
:::

## 2. Управление игроками

| Команда | Назначение |
| --- | --- |
| `list` | Показывает **игроков онлайн** |
| `kick <игрок> [причина]` | Выгоняет игрока; **он может зайти снова** |
| `ban <игрок> [причина]` | Блокирует игрока; **без разблокировки он не зайдёт** |
| `pardon <игрок>` | Разблокирует игрока (в старых версиях могла называться `unban`) |
| `ban-ip <IP>` | Блокировка по IP (**все, кто за этим IP, не смогут зайти**, применяйте осторожно) |
| `pardon-ip <IP>` | Разблокировка IP |
| `op <игрок>` | Выдать права OP (администратора) |
| `deop <игрок>` | Снять OP |

### Белый список

```
whitelist on                  включить белый список
whitelist add <игрок>         добавить
whitelist remove <игрок>      удалить
whitelist list                показать список
whitelist reload              перечитать из whitelist.json
```

После изменения командами список записывается в `whitelist.json`; если вы **редактировали этот файл напрямую**, не забудьте выполнить `whitelist reload`, чтобы изменения вступили в силу.

## 3. Плагины и диагностика

| Команда | Назначение |
| --- | --- |
| `plugins` (сокращённо `pl`) | Список плагинов. **Зелёный = загружен**, **красный = ошибка загрузки** (смотрите ошибку в консоли) |
| `version <плагин>` | Показать версию плагина |
| `help` | Справка |

Если плагина **нет даже в красном списке**, сервер вообще не распознал его как плагин — обычно файл не лежит в `plugins/`, неверное расширение или несовместимый тип ядра.

### Как скрыть список плагинов от игроков

Права на команды `plugins`, `version` и `help` по умолчанию открыты, их может выполнить любой. Чтобы закрыть, установите следующие узлы прав в `false`:

```
bukkit.command.plugins
bukkit.command.version
bukkit.command.help
```

:::warn Отключить команду не значит скрыть плагин
Некоторые читерские клиенты по ответам **автодополнения (Tab)** определяют установленные плагины. Если это действительно важно, нужен отдельный плагин сокрытия (например, PluginHide).
:::

## 4. Частые административные команды в игре

| Команда | Назначение |
| --- | --- |
| `gamemode <режим> [игрок]` | Сменить режим игры |
| `tp <игрок> <цель>` | Телепортация |
| `give <игрок> <предмет> [количество]` | Выдать предмет |
| `time set day` / `weather clear` | Время / погода |
| `difficulty <сложность>` | Изменить сложность |
| `gamerule <правило> <значение>` | Изменить игровое правило |
| `say <содержимое>` | Объявление от имени сервера |
| `whitelist` / `op` и т. п. | То же, что выше (в игре нужен OP) |

## 5. Права и автодополнение (Tab)

- В ванильном сервере права управляются **уровнем OP**; после установки плагина прав (например, LuckPerms) используется точечное управление через **узлы прав + группы прав**, что гораздо безопаснее выдачи OP.
- **Автодополнение (Tab)** подсказывает команды и параметры — это самый быстрый способ проверить, существует ли команда; игроки также могут по нему узнать, какие плагины стоят на сервере (см. выше).
