Положить плагин в `plugins/` — лишь завершить установку; по-настоящему удобство сервера определяют те десятки `config.yml`, которые идут следом. Правильная настройка — это функции, а ошибка в одном пробеле может сделать нечитаемым целый блок.

Здесь три темы: **как писать YAML, как использовать цветовые коды, как не получить кракозябры из-за кодировки**, а в конце — фиксированный порядок изменения конфигурации.

## 1. Где лежит конфигурация плагина

Подавляющее большинство плагинов хранит свои файлы в `plugins/<plugin-name>/`; обычные типы:

| Файл / каталог | Назначение |
| --- | --- |
| `config.yml` | Основная конфигурация, есть почти у каждого плагина |
| `messages.yml`, `lang/` | Тексты сообщений; правка здесь меняет формулировки или язык |
| `menus/`, `kits.yml` и т. п. | Конфигурации отдельных модулей, создаются плагином при запуске |
| `data/`, `playerdata/`, `*.db` | Рабочие данные, которые ведёт сам плагин |

:::warn Не редактируйте файлы данных вручную
Содержимое `data/`, `playerdata/`, `*.db` пишет сам плагин во время работы. Ручная правка в лучшем случае будет перезаписана, в худшем приведёт к порче данных игроков. Меняйте конфигурацию, а не данные.
:::

## 2. Три железных правила YAML

Девять из десяти случаев «конфигурация не читается» — из-за трёх вещей ниже.

### Отступы только пробелами, не Tab

YAML явно запрещает использовать табуляцию для отступов. А Tab в редакторе выглядит точно как несколько пробелов, и заметить его глазами трудно:

```yaml
# правильно: пробелами
options:
    enable: true

# неправильно: эта строка начинается с Tab
options:
	enable: true
```

Большинство редакторов показывают Tab стрелкой или пунктиром; в VS Code справа внизу видно `Tab Size` и способ отступа. **Если в конфигурации уже перемешаны Tab, не удаляйте их вручную по одному** — используйте функцию редактора «преобразовать отступы в пробелы».

### После двоеточия обязателен пробел

```yaml
enabled: true      # правильно: пробел после двоеточия
enabled:true       # неправильно: вся строка считается строкой
```

`key:value` в YAML — не пара «ключ-значение», а обычная строка. Плагин не находит ключ `enabled` и откатывается к значению по умолчанию; на практике это выглядит как «я же изменил, а не работает».

### Отступы одного уровня должны совпадать

```yaml
options:
    enable: true
    check: false
    drop-block: true
    other:
        money: 10
        welcome: "Добро пожаловать"
guide:
    show: true
```

`options` и `guide` на одном уровне, `enable`, `check`, `drop-block` и `other` — на одном уровне, а `money` под `other` — на уровень ниже. В пределах одного уровня **повторять ключи нельзя**:

```yaml
options:
  enable: true
  enable: false     # неправильно: повтор ключа на одном уровне
  check: false
```

Редактор с поддержкой YAML подсветит такую запись красным; даже если редактор молчит, плагин при чтении выдаст ошибку.

## 3. Объекты, массивы и вложенность

В YAML есть только две базовые структуры: **пары «ключ-значение» (объект)** и **списки (массивы)**; всё остальное — их комбинации.

### Объект

```yaml
options:
  enable: true
  check: false
  money: 10
```

Можно записать и в строку — удобно для коротких конфигураций:

```yaml
options: {enable: true, check: false}
```

### Список

Строки, начинающиеся с `-`, образуют список; элементы идут по порядку:

```yaml
worlds:
  - world
  - world_nether
  - world_the_end
```

Запись в строку:

```yaml
worlds: [world, world_nether, world_the_end]
```

### Объекты внутри списка

Самая частая и самая ломкая структура в конфигурациях плагинов: **первый ключ каждого элемента идёт после `-`, остальные ключи элемента выравниваются по нему**:

```yaml
kits:
  - name: starter
    price: 0
    items:
      - STONE_SWORD
      - BREAD
  - name: vip
    price: 500
    items:
      - DIAMOND_SWORD
```

Обратите внимание: `name`, `price` и `items` — три ключа одного элемента, их отступы должны совпадать; а `- STONE_SWORD` — уже следующий уровень внутри `items`.

### Типы значений

В конфигурациях плагинов встречаются такие типы значений; в записи есть нюансы:

```yaml
boolean: true          # true / false, регистр не важен
integer: 10
float: 3.14
text: "hello"          # при спецсимволах заключайте в кавычки
null_value: ~          # ~ означает пустое значение
```

:::tip Когда кавычки обязательны
Если в значении есть символы `: `, `#`, `{`, `}`, `[`, `]`, `&`, `*`, `!`, `|`, `>`, или значение начинается с них, надёжнее заключить его в одинарные или двойные кавычки. Например, текст с цветовым кодом вроде `&aПривет` в виде `"&aПривет"` не будет разобран неверно.
:::

## 4. Частые ошибки YAML и их причины

| Симптом | Настоящая причина | Что делать |
| --- | --- | --- |
| Плагин при запуске пишет `while parsing`, `mapping values are not allowed here` | Нет пробела после двоеточия или в значении есть `: ` без кавычек | Добавьте пробел или заключите значение в кавычки |
| `found character '\t' that cannot start any token` | В отступах есть Tab | Преобразуйте отступы в пробелы |
| `duplicate key` | На одном уровне два одинаковых ключа | Удалите лишний |
| Конфигурация изменена, эффекта нет | Опечатка в ключе, неверный уровень или плагин вообще не читает этот файл | Сверьте по пунктам с конфигурацией плагина по умолчанию |
| Не работает только один элемент списка | Отступы ключей внутри элемента не выровнены | Выровняйте ключи одного элемента |
| Файл не читается целиком, ошибка в первой строке | Файл с BOM или не в UTF-8 | Сохраните в UTF-8 без BOM |
| Ошибка `expected <block end>` | В какой-то строке отступ меньше или больше нужного | Проверьте ширину отступов по уровням |

:::tip Пусть редактор проверяет за вас
VS Code с расширением YAML и Notepad++ при открытии `.yml` в реальном времени показывают проблемы отступов и синтаксиса. **Перед сохранением проверьте, нет ли красных волнистых линий** — это гораздо быстрее, чем потом копаться в логах.
:::

## 5. Цветовые и форматные коды

Серверный текст (MOTD, чат, сообщения плагинов, названия меню) окрашивается **форматными кодами**. В ванили используется символ раздела `§`, но большинство плагинов для удобства разрешают писать в конфигурации `&`, который они сами преобразуют.

### Цвета

```
&0 чёрный &1 тёмно-синий &2 тёмно-зелёный &3 тёмно-бирюзовый
&4 тёмно-красный &5 тёмно-фиолетовый &6 золотой &7 серый
&8 тёмно-серый &9 синий &a зелёный &b бирюзовый
&c красный &d розовый &e жёлтый &f белый
```

### Форматирование

```
&l жирный     &o курсив     &n подчёркнутый   &m зачёркнутый
&k случайные символы &r сброс
```

Их можно комбинировать, например:

```yaml
prefix: "&8[&aсервер&8] &r"
message: "&aДобро пожаловать, &e%player_name% &aснова на сервере"
warning: "&c&lВнимание&r &7Не стройте здесь"
```

`&r` сбрасывает форматирование только **после** себя, поэтому чтобы вернуть тексту стиль по умолчанию, пишите `&r` в нужном месте.

### Несколько ограничений

- **`&` — не универсальный**: плагин должен его преобразовывать. В некоторых местах (ванильный `motd` в `server.properties`, часть ванильных команд) принимается только настоящий `§`, а `&` отображается как есть.
- **Всего 16 цветов**: коды `&` — старая механика без true color. Для градиентов и точных значений нужен MiniMessage, о котором ниже.
- **Что делать, если `§` не набирается**: обычный клиент не позволяет ввести этот символ напрямую; зажмите `Alt` и наберите на цифровой клавиатуре `167` либо просто скопируйте и вставьте.
- **Набор поддерживаемых кодов определяет плагин**: один и тот же `&l` в одном плагине работает в заголовках меню, а в других местах игнорируется.

### MiniMessage (для общего понимания)

MiniMessage на основе библиотеки Adventure описывает стиль тегами и поддерживает true color, градиенты, подсказки при наведении и события клика:

```xml
<yellow>Привет <blue><bold>мир</bold></blue>!</yellow>
<gradient:#f6d365:#fda085>текст с градиентом</gradient>
<rainbow>радужный текст</rainbow>
```

Важно: **встроенная поддержка платформы не значит поддержка плагином**. Paper и его производные содержат Adventure, поэтому плагины, написанные под Paper, чаще всего понимают MiniMessage; плагины под Bukkit (например, EssentialsX) по умолчанию её не поддерживают, если сами не подключили эту библиотеку (как PlaceholderAPI).

:::note Не применяйте вслепую
То, что у других MiniMessage выглядит хорошо, не значит, что ваш плагин её понимает. Перед использованием загляните в документацию плагина и выясните, что он поддерживает: коды `&`, теги MiniMessage или и то и другое.
:::

## 6. Кодировка файлов и кракозябры

Если не-ASCII текст в конфигурации отображается как `???`, `ÐŸÑ€Ð¸Ð²ÐµÑ‚` или `æ¬¢è¿` и подобное, почти всегда дело в **неверной кодировке**, а не в том, что плагин не поддерживает язык.

| Симптом | Причина |
| --- | --- |
| Текст превращается в вопросительные знаки или квадраты | Файл сохранён в ANSI / GBK, а сервер читает как UTF-8 |
| Текст превращается в странные символы | Файл в UTF-8, но прочитан как GBK (или наоборот) |
| Ключ в первой строке не читается | В начале файла BOM; некоторые парсеры считают его частью ключа |

Что делать:

1. Откройте файл в редакторе вроде VS Code или Notepad++.
2. При сохранении выберите **UTF-8** (в VS Code — `Save with Encoding` в правом нижнем углу).
3. Убедитесь, что BOM нет. Старый Блокнот Windows по умолчанию сохраняет «UTF-8 с BOM» — самая частая ловушка.
4. После сохранения перезагрузите плагин и посмотрите на консоль и текст в игре.

:::warn Сохранение в Блокноте — рискованная операция
Если открыть `.yml` в Блокноте Windows и машинально нажать Ctrl+S, нормальный UTF-8-файл легко превращается в ANSI. **С самого начала используйте редактор с поддержкой YAML и отображением кодировки** и делайте копию перед правкой.
:::

## 7. Безопасное изменение конфигурации: фиксированный порядок

Следуя этому порядку, вы сильно снизите вероятность проблем.

1. **Сначала копия**. Скопируйте `config.yml` в `config.yml.bak`, чтобы при поломке сразу вернуть.
2. **Меняйте по возможности на остановленном сервере или в непиковые часы**. Некоторые плагины при остановке записывают своё состояние из памяти обратно в файл, и правки, сделанные на ходу, могут быть перезаписаны.
3. **Используйте редактор с поддержкой YAML**, сохраняйте комментарии и структуру, не форматируйте файл целиком «на автомате».
4. **Меняйте по одному месту** и сразу проверяйте. Если изменить двадцать строк разом, при проблеме не поймёте, какая из них виновата.
5. **Перезагрузите**. Предпочтительна собственная команда плагина:

| Способ | Описание |
| --- | --- |
| `/<plugin-name> reload` | Поддерживают большинство плагинов, **предпочтительно** (например, `/tab reload`, `/papi reload`) |
| Перезапуск сервера | Самый надёжный; для плагинов без горячей перезагрузки — единственный вариант |
| `/reload` (ванильная команда) | **Не рекомендуется**, легко рассинхронизирует состояние плагинов |

6. **Смотрите консоль и `logs/latest.log`**. При ошибке разбора конфигурации обычно печатаются имя файла и номер строки — по номеру нужное место находится сразу.
7. **Если не уверены — сначала тестовый сервер**. Правка конфигурации плагина безопаснее установки, но всё равно может затронуть сохранение или данные игроков.

:::tip Как пользоваться номером строки из ошибки
Когда в логе появляется `config.yml: 42`, **не смотрите только на строку 42**. Ошибка разбора YAML часто вызвана отступом или незакрытой кавычкой в предыдущей строке — проверьте две-три строки выше.
:::

## 8. Краткий справочник

| Проблема | Что проверить |
| --- | --- |
| Конфигурация не применилась | Написание ключа, уровень вложенности, выполнен ли reload |
| Плагин при запуске выдаёт ошибку разбора | Пробел после двоеточия, Tab в отступах, повтор ключа на одном уровне |
| Кракозябры | Файл в UTF-8 без BOM? |
| Цветовые коды отображаются как есть | Поддерживает ли это место `&` или нужны теги MiniMessage |
| Изменения откатываются | Не перезаписывает ли плагин конфигурацию при остановке |
