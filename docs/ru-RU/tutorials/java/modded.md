Плагинный и модовый серверы — два разных мира. Плагины «навешивают» функции снаружи сервера, и игрок заходит с ванильным клиентом; моды напрямую меняют код игры, и **подавляющее большинство контентных модов требуют одинакового набора на сервере и клиенте** — без него игрок не зайдёт.

Эта статья проводит модовый сервер от нуля до запуска: выбор загрузчика, установка сервера, согласование клиента, размещение модов, поиск несовпадений, а также особенности производительности, копирования и обновления модовых серверов. Если вы всё ещё выбираете между плагинным и модовым сервером, сначала посмотрите [Выбор серверного ядра](/tutorials/java/core).

## 1. Чем отличаются плагинный и модовый серверы

| Критерий | Плагинный сервер (Paper / Purpur и т. п.) | Модовый сервер (Fabric / NeoForge и т. п.) |
| --- | --- | --- |
| Способ расширения | Плагин вызывает API, предоставляемый сервером, не меняя саму игру | Мод напрямую меняет код игры |
| Нужно ли игроку что-то ставить | Нет, достаточно ванильного клиента | В большинстве случаев нужен **тот же загрузчик + тот же набор модов** |
| Типичный контент | Администрирование, мини-игры, экономика, защита территорий | Новые блоки, предметы, мобы, машины, измерения |
| Скорость обновления | Ядра обновляются быстро, плагины успевают | Медленно, зависит от автора каждого мода |
| Настраиваемые параметры | Очень богатые: конфигурация ядра + конфигурация плагинов | Мало; в основном сам мод и JVM |
| Диагностика при проблеме | Смотреть список плагинов и их конфигурацию | Смотреть, **совпадает ли список модов полностью**, и логи крашей |

**Нужен контент для геймплея — берите моды, нужны функции управления — берите плагины.** Смешанные решения (гибридные ядра) существуют, но совместимость и стоимость обслуживания там выше; новичкам не стоит начинать с них.

### 1.1 Три класса модов: только клиент / только сервер / обязателен на обеих сторонах

Мод — не «поставил и уже работает»; сначала определите его класс, иначе точно наступите на грабли:

| Класс | Типичные примеры | Куда ставить | Что будет при ошибке |
| --- | --- | --- | --- |
| **Только клиент (client-only)** | Рендеринг (Sodium и т. п.), миникарты, шейдеры, улучшения интерфейса | Только клиент | На сервере обычно сразу ошибка или краш; большинство загрузчиков откажутся его загружать |
| **Только сервер (server-only)** | Логические/оптимизационные моды, работающие лишь на сервере; часть административных | Только сервер (некоторые можно ставить на обе стороны, но на клиенте они бессмысленны) | На клиенте обычно не падает, но сервер может отклонить рукопожатие; без него на сервере функции просто нет |
| **Обязателен на обеих сторонах (both-required)** | Контентные моды: новые блоки, предметы, мобы, измерения, механики | И клиент, и сервер | Без любой из сторон: отказ в подключении или ошибка из-за несовпадения реестров |

Есть ещё промежуточный класс: **можно ставить на обе стороны, но не обязательно** (например, оптимизация памяти или сети). На странице выпуска таких модов явно указано «необязательно».

### 1.2 Как узнать класс мода

Ориентируйтесь на **страницу выпуска и описание самого мода**, по убыванию приоритета:

| Источник | Что смотреть |
| --- | --- |
| Страница выпуска (Modrinth / CurseForge) | Метка окружения. Modrinth теперь использует поле `environment` (например, `client_only`, `server_only`, `client_and_server`), у старых `client_side` / `server_side` значения `required` / `optional` / `unsupported` |
| README мода / объявления автора | Авторы часто прямо пишут «server-side only», «client-side only», «required on both sides» |
| Моды Fabric | Поле `environment` в `fabric.mod.json`: `"*"` (по умолчанию, обе стороны), `"client"` (клиент), `"server"` (отдельный сервер, без встроенного в одиночную игру) |
| Моды NeoForge | Метаданные `META-INF/neoforge.mods.toml`, а также точки входа, помеченные как клиентские (например, `dist = Dist.CLIENT`) |

:::warn Не переносите опыт плагинного сервера на модовый
- `spigot.yml`, `paper-world-defaults.yml` и весь набор плагинов Bukkit на модовом сервере **не существуют**; настраивать модовый сервер по руководствам для плагинного — пустая трата времени.
- На модовый сервер по умолчанию **нельзя ставить плагины Bukkit** (для этого нужно гибридное ядро — отдельная схема).
- Параметры JVM, оптимизационные плагины и привычку к горячей перезагрузке с плагинного сервера копировать нельзя (см. раздел 10).
- И наоборот: опыт модового сервера не переносите на плагинный.
:::

## 2. Выбор загрузчика: Fabric / NeoForge / Forge

| Загрузчик | Позиционирование | Кому подходит |
| --- | --- | --- |
| **Fabric** | Лёгкий, быстро запускается, быстро догоняет новые версии; сам загрузчик отделён от API | Для тех, кому важны производительность и быстрые обновления, а моды — в основном оптимизационные плюс немного контентных |
| **NeoForge** | Продолжение линии Forge в современных версиях, более полный функциональный API | Крупные контентные сборки современных версий, машины/технологичный геймплей |
| **Forge** | Старый загрузчик; исторические сборки и старые версии всё ещё широко используются | Нужно запустить старую сборку или мод, поддерживаемый только на Forge |

**Разберитесь в раскладе версий**: список поддерживаемых версий Minecraft у загрузчиков меняется со временем; здесь не приводятся конкретные цифры, только способ разобраться:

- Fabric: на официальной странице загрузки можно выбрать и версию игры, и версию загрузчика; там же даны команды загрузки и запуска. В официальной документации Fabric указано, что поддерживаются все стабильные версии начиная с 1.14 (а также снапшоты после 18w43b).
- NeoForge: на главной странице сайта по версии Minecraft указан соответствующий файл инсталлятора; в официальной документации есть шаги установки сервера.
- Forge: официальная страница загрузки перечисляет сборки latest / recommended по версиям и до сих пор выпускает их для нескольких версий (включая сравнительно новые); но значительная часть экосистемы модов новых версий уже перешла на NeoForge.

> **На сайте можно скачать напрямую** — ядра загрузчиков (Fabric / NeoForge / Forge) см. в **[Загрузках · Серверные ядра](/downloads/core)**; сами моды — в **[Загрузках · Моды](/downloads/mods)**; если в итоге решите идти путём плагинного сервера, плагины — в **[Загрузках · Плагины](/downloads/plugins)**. Во всех трёх местах собраны ссылки из официальных и общественных источников; нажмите «Скачать» и войдите по подсказке, **сайт не хранит никаких файлов**.

:::note Загрузчики почти несовместимы между собой
Один мод обычно поддерживает только один загрузчик. Мод Fabric нельзя положить на сервер NeoForge и наоборот. Поэтому **выбор загрузчика — это по сути выбор того, «на какой стороне находятся нужные вам моды»**: сначала проверьте на странице выпуска, какой загрузчик и какая версия игры поддерживаются, и только потом решайте, что ставить.
:::

Рекомендуемый порядок:

```
Сначала определите геймплей (какие моды нужны) → проверьте поддерживаемые этими модами загрузчики и версии игры
  → выберите загрузчик + версию игры с наибольшим пересечением → затем ставьте сервер
```

## 3. Установка загрузчика на сервер

Интерфейс инсталлятора и имена файлов меняются от версии к версии, поэтому ниже — только **общий порядок**; точные действия на каждом шаге — по официальной документации загрузчика.

### 3.1 Сначала проверьте версию Java

| Версия Minecraft | Требуемая Java |
| --- | --- |
| 1.16.5 и раньше | 8 |
| 1.17.2 | 16 |
| 1.18.2 – 1.20.4 | 17 |
| 1.20.5 и новее | 21 |

Неверная версия Java — самая частая причина «инсталлятор не открывается / сервер не запускается»; исключите её в первую очередь.

### 3.2 Общий порядок

1. Создайте пустой каталог как корень сервера.
2. На официальной странице загрузки загрузчика выберите версию Minecraft и версию загрузчика, скачайте инсталлятор (`.jar`).
3. Запустите инсталлятор и выберите установку **сервера (Server)**. В командной строке обычно добавляется параметр `--installServer`.
4. Инсталлятор создаст **скрипт запуска или jar-запускатор** (а также каталог библиотек для работы).
5. **Сначала запустите один раз**. Первый запуск создаст `eula.txt`, `server.properties`, `mods/`, `config/`, `logs/` и т. д., а затем завершится из-за непринятой EULA.
6. Откройте `eula.txt` и замените `eula=false` на `eula=true` (это подтверждает принятие Minecraft EULA).
7. **Запустите снова** и убедитесь, что сервер поднимается нормально и в консоли нет ошибок.
8. Только теперь кладите моды в `mods/` и перезапускайте.

### 3.3 Fabric

- На официальной странице загрузки сервера (страница server на fabricmc.net) можно выбрать версию; там же даны команды загрузки и запуска — выполняйте **имена файлов и команды запуска**, показанные на странице.
- В инсталляторе есть вкладка Server для локальной генерации запускатора сервера.
- Подавляющему большинству модов Fabric нужен **Fabric API**; это тоже мод, положите его в `mods/`.

```bash
# официальная страница покажет примерно такие команды загрузки и запуска; ориентируйтесь на то, что там написано
# 1) скачать запускатор сервера
# 2) первый запуск
java -jar <имя-файла-запускателя-сервера> nogui
```

### 3.4 NeoForge

Порядок из официальной документации NeoForge (на примере серии 21.x):

```bash
# 1) скачать инсталлятор (номер версии — по официальному сайту)
wget https://maven.neoforged.net/releases/net/neoforged/neoforge/<версия>/neoforge-<версия>-installer.jar

# 2) установить сервер
java -jar neoforge-<версия>-installer.jar --installServer

# 3) первый запуск (завершится из-за EULA)
./run.sh        # Windows: run.bat
```

Главное:

- После установки создаются `run.sh` / `run.bat` и **`user_jvm_args.txt`**. **Меняйте память в `user_jvm_args.txt`, не правьте `run.sh` вручную**.
- После первого запуска появляется папка `mods` — моды кладутся туда.
- Для обновления NeoForge достаточно прогнать те же команды новым инсталлятором; официально напоминают: **перед обновлением сделайте копию мира**.

### 3.5 Forge (старые версии / старые сборки)

```bash
java -jar forge-<версия>-installer.jar --installServer
```

- Новые Forge похожи на NeoForge: создают `run.sh` / `run.bat` и `user_jvm_args.txt`.
- Более старые версии создают готовый к запуску `forge-<версия>.jar`, запускаемый через `java -jar`.
- Моды старых версий часто поддерживаются только на Forge, и выбора почти не остаётся.
:::tip Если не запускается, сначала смотрите логи
Ошибки установки загрузчика и краши модов — в `logs/latest.log`, `logs/debug.log` и `crash-reports/`. Методика поиска — в [Частых ошибках и крашах](/tutorials/faq/errors).
:::

## 4. Сторона клиента: игрок должен поставить тот же набор

«Не могу зайти» на модовом сервере в подавляющем большинстве случаев не проблема сети, а **несовпадение списков модов клиента и сервера**.

Что должен сделать игрок:

1. Поставить **тот же загрузчик** и **ту же версию Minecraft**.
2. Поставить **тот же набор модов** (со всеми зависимостями, например Fabric API).
3. Версии модов тоже должны совпадать (см. раздел 6).

### 4.1 Почему при несовпадении списка не пускают

При входе клиент и сервер выполняют «рукопожатие»: обмениваются сведениями о загрузчике, списком модов и частью содержимого реестров. Любой из случаев ниже ведёт к отказу или ошибке:

- **обязательный на обеих сторонах** мод есть на сервере, но не у клиента;
- мод того же класса есть у клиента, но не на сервере;
- **версии одного мода различаются**;
- отсутствует мод-зависимость.

### 4.2 Что увидит игрок

| Загрузчик | Проявление |
| --- | --- |
| NeoForge / Forge | Соединение отклонено, появляется **экран со списком отклонённых модов** (в сообществе называют «mod rejections» / экран несовместимых модов), где по пунктам указана причина, например «на сервере нет этого мода», «несовпадение версий». Тексты и вёрстка зависят от версии |
| Fabric | При отсутствии зависимости на этапе загрузки загрузчик показывает экран ошибки вроде «Incompatible mod set!» и перечисляет в логах отсутствующие/конфликтующие моды; в официальной документации Fabric есть отдельные страницы о краш-репортах и переопределении зависимостей |

:::tip Как избавить игроков от лишних проблем
- упакуйте клиентский `mods/` в архив и раздайте игрокам либо опубликуйте клиентскую и серверную сборки на платформе сборок;
- укажите в объявлении группы: загрузчик, версию Minecraft, версию загрузчика, версии модов;
- после обновления модов на сервере **сразу обновляйте клиентскую сборку**, иначе старые клиенты перестанут заходить.
:::

## 5. Куда класть моды

> **Где искать моды** — на сайте собраны записи модов Modrinth, см. **[Загрузки · Моды](/downloads/mods)**, с фильтром по загрузчику (Fabric / Forge / NeoForge / Quilt) и версии игры; нажмите «Скачать» и войдите по подсказке, чтобы получить официальную ссылку. Перед установкой обязательно определите класс: «только клиент / только сервер / обязателен на обеих сторонах» (см. [1.1](#11-%E4%B8%89%E7%B1%BB%E6%A8%A1%E7%BB%84%E4%BB%85%E5%AE%A2%E6%88%B7%E7%AB%AF--%E4%BB%85%E6%9C%8D%E5%8A%A1%E7%AB%AF--%E5%8F%8C%E7%AB%AF%E5%BF%85%E9%9C%80)).

| Расположение | Описание |
| --- | --- |
| Серверный `mods/` | Все моды, загружаемые сервером (`.jar`) |
| Клиентский `.minecraft/mods/` | Все моды, загружаемые клиентом игрока |
| `config/` | Собственные конфигурации модов; большинство создаётся **после первого запуска** и лежит не в `mods/` |
| `defaultconfigs/` | Каталог, который некоторые загрузчики/сборки используют для «конфигурации новых миров по умолчанию» |

:::warn Клиентские моды не ставьте на сервер, и наоборот
Это одна из самых частых причин крашей модового сервера:

- если положить **клиентский** мод для рендера/интерфейса в серверный `mods/`, сервер при запуске выдаст ошибку или даже упадёт (в сервере нет клиентских классов);
- если дать клиенту **серверный** мод, в лучшем случае он бесполезен, в худшем клиент упадёт из-за отсутствующих классов;
- если поставить **обязательный на обеих сторонах** мод только с одной стороны, игрок не подключится.

Способ определить — в разделе 1.2: ориентируйтесь на метку окружения на странице выпуска и пояснения автора.
:::

## 6. Правило совпадения трёх сторон

Модовый сервер работает, только когда совпадают сразу три вещи:

| Что совпадает | Требование |
| --- | --- |
| Версия игры | Сервер, клиент и каждый мод должны поддерживать одну и ту же версию Minecraft |
| Версия загрузчика | Клиент и сервер используют один загрузчик; версии загрузчика по возможности совпадают (как минимум попадают в требования модов) |
| Версия мода | Один и тот же мод на обеих сторонах должен быть **одной версии**; моды-зависимости должны присутствовать и удовлетворять диапазону версий |

### 6.1 Диагностика несовпадений по логам

| Симптом/подсказка в логах | Значение | Что делать |
| --- | --- | --- |
| Краш при запуске, в отчёте указан мод | Мод несовместим с текущей версией игры/загрузчиком или не хватает зависимости | Смените версию или добавьте зависимость |
| В логах «missing dependency» / не удалось разрешить зависимости | Заявленная модом зависимость не установлена или неверной версии | Добавьте зависимости по логам |
| В логах ошибка загрузки мода, класс не найден | Обычно клиентский мод поставлен на сервер (или наоборот) | Уберите с неправильной стороны |
| Игроку отказано в подключении, на экране список модов | Списки/версии на сторонах не совпадают | Приведите моды к одному набору |
| В отчёте `Is Modded: Definitely; ... brand changed to 'fabric'/'neoforge'` | Просто означает, что среда модовая, само по себе не ошибка | Смотрите дальше настоящий стек исключения |

Семантика зависимостей (по спецификации Fabric, в NeoForge аналогично):

| Объявление | Значение |
| --- | --- |
| `depends` | Жёсткая зависимость, без неё сразу отказ |
| `recommends` | Мягкая зависимость, без неё только предупреждение |
| `conflicts` / `breaks` | Конфликт: при совпадении ошибка |

### 6.2 Не удаётся найти виновника среди модов

Используйте **метод деления пополам** (рекомендован официальной документацией NeoForge):

1. Уберите половину модов из `mods/` (следите за целостностью зависимостей).
2. Запустите и посмотрите, осталась ли проблема.
3. Осталась — делите пополам текущую половину; нет — верните вторую половину и попробуйте снова.
4. Повторяйте, пока не найдёте конкретный мод.

## 7. Моды производительности (по категориям)

Оптимизация модового сервера — это в основном «правильно поставленные моды», а не правка конфигурации. Ниже — моды, существование и широкое использование которых подтверждены (поддержка загрузчиков взята с их страниц и меняется от версии к версии — проверьте ещё раз перед установкой):

| Категория | Мод | Назначение | Загрузчик | Замечания |
| --- | --- | --- | --- | --- |
| Оптимизация игровой логики | **Lithium** | Оптимизирует производительность игровой логики (спавн, ИИ, поведение блоков), стараясь не менять поведение | Fabric, NeoForge, Quilt | Можно ставить на обе стороны, на сервере выгода заметна |
| Потребление памяти | **FerriteCore** | Снижает потребление памяти (структуры данных вроде состояний блоков) | Fabric, Forge, NeoForge, Quilt | Очень полезен модовым серверам с нехваткой памяти |
| Оптимизация сети | **Krypton** | Оптимизирует сетевой стек, снижая трафик и нагрузку CPU | Fabric | В основном для сервера и сетевой игры |
| Движок освещения | **Starlight** | Переписывает движок освещения, исправляет производительность и ошибки освещения | Fabric | Проект заархивирован, поддерживает максимум 1.20.4; в описании указано, что на 1.20 разница с ванилью уже мала. **На новые версии не ставьте силой** |
| Предгенерация чанков | **Chunky** | Заранее генерирует чанки, уменьшая лаги при исследовании мира | Fabric, Forge, NeoForge, а также Paper/Spigot и др. | Для долго работающего сервера почти обязателен |
| Клиентский рендеринг | **Sodium** | Оптимизация рендеринга на клиенте (повышает FPS) | Fabric, NeoForge, Quilt | **Только клиент**, на сервер не ставить |

:::note Два правила насчёт «оптимизационных модов»
- **Не ставьте одновременно несколько оптимизационных модов с пересекающимися функциями** (например, две переписанные системы освещения) — вероятность конфликта очень высока.
- Оптимизационные моды меняют внутреннее поведение игры; **на техническом сервере / сервере точных машин будьте осторожны**: лучше медленнее, но машины должны работать.
:::

## 8. Совместимость мира и данных: удаление модов необратимо

Блоки, предметы, сущности, измерения и биомы, добавленные модами, записываются в сохранение мира. **После удаления мода данные этих объектов остаются в сохранении, но игра их уже не знает**:

- в лучшем случае появляются «отсутствующие блоки / пустые сущности» — выглядят как воздух, но данные на месте;
- в худшем чанки загружаются с ошибкой, а сохранение может вовсе не открыться;
- если вернуть **тот же мод совместимой версии**, обычно всё восстанавливается.

:::warn Сначала копия, потом моды
- перед любым «добавить мод, удалить мод, сменить загрузчик, сменить версию игры» **сделайте полную копию каталога мира** (способ — в [Резервном копировании и восстановлении](/tutorials/java/backup));
- сохранение модового сервера **нельзя просто понизить**: открывать мир модового сервера в ванили или старой версии крайне рискованно;
- хотите «поставить мод и посмотреть»? Пробуйте на **копии**, а не на рабочем сохранении.
:::

## 9. Безопасное обновление модового сервера / сервера сборки

Рекомендуемый порядок (не пропускайте шаги):

1. **Копия**: мир + `config/` + список модов.
2. **Заморозьте изменения**: сначала остановите сервер или работайте в окно обслуживания.
3. **Сначала обновите загрузчик** и запустите один раз, чтобы убедиться, что сам сервер в порядке (старые моды могут ругаться — это нормально).
4. **Обновляйте моды по одному**, не меняйте всё сразу. Поэтапное обновление позволяет найти проблемный мод.
5. **Приведите в соответствие клиентскую сборку**: перепакуйте и опубликуйте обновлённый `mods/` (клиентскую сторону).
6. **Наблюдайте**: после запуска проверьте `logs/latest.log` на аномалии, дайте поработать и посмотрите TPS и ошибки (методы — в [Оптимизации производительности](/tutorials/java/optimize)).
7. **Сохраните пакет для отката**: оставьте предыдущую версию каталога сервера и клиентскую сборку, чтобы при проблеме сразу вернуться.

## 10. Память и параметры JVM

У модового и плагинного серверов разные характеристики памяти:

| Пункт | Плагинный сервер | Модовый сервер |
| --- | --- | --- |
| Потребность в куче | Относительно низкая | **Заметно выше**: реестры модов, модели, рецепты, данные машин едят память |
| Время запуска | Короткое | Долгое (с сотнями модов несколько минут — обычное дело) |
| Основное узкое место | Главный поток + качество плагинов | Главный поток + качество модов + память/GC |
| Источник параметров | Рекомендации официальной документации ядра | **Описание в файлах запуска самого загрузчика** |

Практические советы:

- **Давайте памяти достаточно, но не чрезмерно**. Слишком большая куча удлиняет паузы GC; начните с разумного значения под число игроков и масштаб модов (например, небольшой модовый сервер — от 4–8 ГБ), потом корректируйте по наблюдениям.
- NeoForge / новые Forge: меняйте `user_jvm_args.txt` (создаётся при установке, внутри есть пояснения), не правьте `run.sh` вручную.
- Другие способы запуска: задайте память через `-Xms` / `-Xmx` в скрипте запуска.
- **Не копируйте наборы параметров с плагинного сервера**. Наборы для Paper/Spigot рассчитаны на другую нагрузку и поведение GC; для модового сервера ориентируйтесь на официальную документацию загрузчика и пояснения авторов модов.
- Параметры решают только вопросы памяти/GC и **не спасают от узкого места в одном ядре**, как и от очень плохо написанных модов.

```bash
# пример: параметры памяти записываются в скрипт запуска или user_jvm_args.txt
# конкретные значения подбирайте под масштаб модов и число игроков
-Xms4G
-Xmx8G
```

## 11. Быстрая таблица диагностики

| Симптом | Частая причина | Что делать |
| --- | --- | --- |
| Сервер падает при запуске, в логах назван мод | Версия мода не соответствует игре/загрузчику или не хватает зависимости | Смените версию, добавьте зависимости |
| Экран/логи сообщают «Incompatible mod set!» или перечисляют отклонённые моды | Списки модов или версии на сторонах не совпадают | Приведите моды и версии к одному набору |
| После удаления мода в мире появились отсутствующие блоки/сущности | Данные мода остались, игра их не знает | Верните совместимую версию; **сначала копия**, не продолжайте писать в сохранение |
| Игрок не заходит, на сервере явных ошибок нет | У клиента нет мода/зависимости или другая версия | Дайте игроку ту же клиентскую сборку |
| Сервер запускается, но лагает | Моды сами по себе медленные, слишком много сущностей/машин, не хватает памяти | Найдите причину профайлером (см. [Анализ производительности сервера с spark](/tutorials/ops/spark)) и действуйте точечно |
| Запуск долго висит на загрузке модов | Много модов, первая генерация конфигурации, медленный диск | Это нормально; используйте SSD и подождите |
| Клиентский мод поставлен на сервер | В сервере нет клиентских классов | Уберите из серверного `mods/` |

## Заключение

Сложность модового сервера проистекает из железного правила «обе стороны должны совпадать»: **сначала определите геймплей и версию, затем поставьте загрузчик и только потом добавляйте моды**. Запускайте сервер после каждого добавленного мода и делайте копию перед каждым изменением модов — это сэкономит массу времени на переделках.
