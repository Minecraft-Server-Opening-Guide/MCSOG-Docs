После первого запуска сервера в корневом каталоге создаётся `server.properties`. **Изменения вступают в силу только после перезапуска сервера** (он не перезагружается на лету).

Откройте его в текстовом редакторе; ниже — самые часто изменяемые параметры.

## 1. Самые частые параметры

| Параметр | По умолчанию | Описание |
| --- | --- | --- |
| `server-port` | `25565` | Порт прослушивания сервера; при изменении синхронно поправьте firewall / security group |
| `online-mode` | `true` | **Проверка лицензии**. При `true` клиенты без лицензии не смогут зайти; `false` — офлайн-режим |
| `max-players` | `20` | Максимум игроков одновременно |
| `motd` | — | Строка, отображаемая в списке серверов (поддерживает цветовые коды) |
| `difficulty` | `easy` | `peaceful`/`easy`/`normal`/`hard` (также принимает `0`–`3`) |
| `gamemode` | `survival` | Режим по умолчанию для новых игроков: `survival`/`creative`/`adventure`/`spectator` |
| `force-gamemode` | `false` | При `true` игроку при каждом входе принудительно возвращается режим по умолчанию |
| `pvp` | `true` | Разрешены ли атаки игроков друг на друга |
| `allow-flight` | `false` | Разрешён ли полёт в режиме выживания (при плагинах полёта рекомендуется включить) |
| `spawn-protection` | `16` | Радиус защиты точки появления: только OP может ломать/ставить в этих пределах; `0` — выключено |
| `allow-nether` | `true` | Разрешён ли переход в Нижний мир (`false` отключает Нижний мир) |
| `generate-structures` | `true` | Генерировать ли в новых чанках структуры вроде деревень |
| `level-seed` | пусто | Сид мира; пустое значение — случайный |
| `enable-command-block` | `false` | Включать ли командные блоки; **обычно включать не рекомендуется** (см. ниже) |
| `white-list` | `false` | Включать ли белый список |
| `view-distance` | `10` | **Дальность прорисовки**, один из самых влияющих на производительность параметров |
| `simulation-distance` | `10` | **Дальность симуляции**: в каком радиусе сущности и редстоун ещё обсчитываются |

### О дальности прорисовки и дальности симуляции

Это **два самых дорогих по производительности регулятора**, и эффект от них заметнее, чем от смены ядра:

- `view-distance` определяет, насколько далеко игрок «видит»; снижение заметно экономит трафик и CPU, но вдали появляется туман.
- `simulation-distance` определяет, в каких чанках ещё идёт **реальный обсчёт** (спавн мобов, редстоун, рост растений). Снижать его выгоднее, чем дальность прорисовки, и это не влияет на картинку.

:::tip Сначала подкрутите эти два, потом думайте об апгрейде железа
Во многих случаях «сервер лагает» заметно лечится снижением `simulation-distance` с 10 до 6.
:::

### О командных блоках

`enable-command-block` по умолчанию выключен, и **в большинстве случаев включать его не стоит**: командные блоки на сервере реализованы неэффективно, а почти всё их функции можно сделать плагином эффективнее (плюс плагины дают контроль прав и аудит). Включайте, только если действительно нужен ванильный геймплей с командными блоками.

## 2. Проверка лицензии и офлайн-режим

- `online-mode=true` (по умолчанию): аккаунт проверяется у Mojang, клиенты без лицензии не заходят.
- `online-mode=false`: может зайти любой, но **любой может выдать себя за произвольный ID**, а лицензионные скины и привязка UUID недоступны.

Если по особым причинам офлайн-режим необходим, обычно дополнительно ставят плагин скинов вроде `SkinsRestorer`, чтобы вернуть отображение скинов.

:::warn Цена офлайн-режима
В офлайн-режиме аккаунт ничем не защищён: бан обходится сменой ID, а права администратора проще присвоить. **На публичном сервере не рекомендуется отключать проверку лицензии.**
:::

## 3. Игровые правила (gamerule)

Сложность, защита точки появления и подобное меняются в `server.properties`; а **игровые правила задаются командами**:

```
/gamerule keepInventory true        не терять предметы при смерти
/gamerule doDaylightCycle false     отключить смену дня и ночи
/gamerule mobGriefing false         криперы не ломают блоки
/gamerule announceAdvancements false не объявлять о достижениях
```

Выполняйте в консоли или в игре (нужен OP) — **действует сразу и сохраняется**.

## 4. Общий порядок изменения конфигурации

1. **Сначала остановите сервер**, затем правьте `server.properties` (особенно при изменении настроек мира — чтобы не было конфликта записи сохранения).
2. Перед правкой **сделайте копию исходного файла**, чтобы при проблеме сразу вернуть.
3. После перезапуска проверьте `logs/latest.log` — не должно быть ошибок конфигурации.
4. Конфигурация плагинов лежит в `plugins/<plugin-name>/config.yml`, большинство поддерживает горячую перезагрузку командой `/<plugin-name> reload` — но **конфигурация самого сервера так не перезагружается**.
