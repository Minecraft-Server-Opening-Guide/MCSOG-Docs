Эта статья о том, **как читать ошибки и как локализовать несовместимость**. Она не пытается перечислить все исключения, а даёт порядок рассуждений: сначала разделить «плагин выбросил исключение, но сервер жив» и «сервер просто упал», затем по стеку найти корневую причину и в конце подтвердить минимальным тестом.

Несовместимость — самый трудоёмкий класс сбоев на серверах Java Edition, потому что он часто **не даёт внятной подсказки** либо называет класс, никак не связанный с настоящей причиной. Везде, где статья не уверена, написано «по официальной документации», а не придумано правдоподобное объяснение.

## 1. Как читать ошибку

### 1.1 Где лежат журналы

| Расположение | Содержимое | Когда смотреть |
| --- | --- | --- |
| `logs/latest.log` | Полный вывод консоли текущего или последнего запуска | **Первая точка**. Сервер перезаписывает его при каждом перезапуске, для доказательств сначала скопируйте |
| `logs/2026-10-04-1.log.gz` | Исторические журналы, ротация по дням и размеру со сжатием | Проблема была несколько дней назад, а `latest.log` уже перезаписан |
| `crash-reports/crash-...-server.txt` | Отчёт о падении: полный стек, описание, окружение на тот момент | При **аварийном завершении** сервера смотрите в первую очередь |
| Само окно консоли | Вывод в реальном времени, прокручивается быстро | Смотреть по ходу работы; содержимое перед падением легко вымывается, сначала скопируйте |

Структура каталогов и роли файлов — см. [Структура сервера](/tutorials/java/structure).

:::tip Сначала копия, потом перезапуск
`logs/latest.log` будет перезаписан при следующем запуске. **До перезапуска сервера** скопируйте `logs/latest.log` и свежий файл из `crash-reports/` в другое место, иначе доказательства для разбора пропадут.
:::

Быстрый поиск по ключевым словам (Linux):

```bash
grep -nE "ERROR|Exception|Caused by" logs/latest.log | tail -40
ls -lt crash-reports/ | head
```

Windows PowerShell:

```powershell
Select-String -Path logs\latest.log -Pattern "ERROR|Exception|Caused by" | Select-Object -Last 40
Get-ChildItem crash-reports | Sort-Object LastWriteTime -Descending | Select-Object -First 5
```

### 1.2 Разница между исключением плагина и фатальным падением

Их нужно разбирать по отдельности, иначе легко заблудиться в куче посторонних красных строк.

| | Исключение плагина (чаще всего) | Фатальное падение |
| --- | --- | --- |
| Состояние сервера | Продолжает работу, игроки онлайн | Процесс завершился, окно закрылось или служба systemd остановлена |
| Конец журнала | После исключения идёт нормальный вывод тиков | В конце `This crash report has been saved to: ...` |
| Типичные маркеры | `Could not pass event ... to X`, `... has failed to load`, `... was disabled` | `Encountered an unexpected exception`, `Exception in server tick loop`, `Watching Server thread` |
| Область влияния | Один плагин или одна функция | Весь сервер |
| Что делать | Исправить плагин, обновить или временно отключить | Сначала поднять сервер, потом читать отчёт о падении |

Ниже — **иллюстративный** (для объяснения структуры, а не из реального журнала) пример исключения плагина, при котором сервер продолжает работу:

```text
[12:00:01 ERROR]: Could not pass event PlayerJoinEvent to MyPlugin v1.2.3
java.lang.NullPointerException: Cannot invoke "java.lang.String.toLowerCase()" because "name" is null
        at com.example.myplugin.JoinListener.onJoin(JoinListener.java:42) ~[MyPlugin-1.2.3.jar:?]
        at org.bukkit.plugin.java.JavaPluginLoader$1.execute(JavaPluginLoader.java:315) ~[paper-api.jar:?]
        at org.bukkit.plugin.RegisteredListener.callEvent(RegisteredListener.java:70) ~[paper-api.jar:?]
        ... 20 more
[12:00:02 INFO]: Player Steve joined the game
```

Ключевая здесь последняя строка: **после исключения сервер как обычно обработал следующее событие**, значит ошибка уровня плагина была перехвачена фреймворком.

### 1.3 Как читать стек Java

**Иллюстративный** стек с цепочкой `Caused by`:

```text
[12:00:05 ERROR]: Encountered an unexpected exception
java.lang.RuntimeException: Failed to load plugin data
        at com.example.core.DataLoader.load(DataLoader.java:88) ~[?:?]
        at com.example.core.CorePlugin.onEnable(CorePlugin.java:31) ~[?:?]
        at org.bukkit.plugin.java.JavaPlugin.setEnabled(JavaPlugin.java:280) ~[paper-api.jar:?]
        ... 18 more
Caused by: java.lang.NoSuchMethodError: 'void org.bukkit.configuration.file.FileConfiguration.setDefaults(org.bukkit.configuration.file.FileConfiguration)'
        at com.example.core.DataLoader.load(DataLoader.java:71) ~[?:?]
        ... 18 more
Caused by: java.lang.ClassNotFoundException: com.example.lib.RequiredLib
        at java.net.URLClassLoader.findClass(URLClassLoader.java:445) ~[?:?]
        ... 21 more
```

Разберём построчно:

- `[12:00:05 ERROR]:` — префикс журнала (время и уровень), а не сам текст ошибки.
- `java.lang.RuntimeException: Failed to load plugin data` — **внешнее исключение**. Часто это лишь обёртка, настоящая информация ниже.
- `at пакет.класс.метод(файл.java:строка)` — цепочка вызовов. **Самая верхняя строка — место, где выброшено исключение, чем ниже, тем ближе к вызвавшему его верхнему фреймворку**.
- `Caused by:` — цепочка корневых причин, слоёв может быть несколько. **Последний `Caused by` — самая нижняя исходная причина**.
- `... 18 more` означает, что опущены кадры стека, полностью совпадающие с предыдущим слоем, а не то, что журнал обрезан.
- `~[MyPlugin-1.2.3.jar:?]` — маркер источника, показывает, из какого jar этот кадр; `~[?:?]` означает неизвестный источник.

:::tip Смотреть только две строки
В стеке реально полезны **строка заголовка первого исключения** и **строка заголовка последнего `Caused by`**. Десятки строк `at` посередине — в основном цепочка вызовов самого фреймворка. Найдя эти две строки, вернитесь и найдите **первый `at`, где встречается имя пакета вашего плагина** — обычно это и есть место проблемного кода.
:::

Номера строк нужны автору для локализации кода: если ошибка в вашем плагине, по номеру строки можно смотреть исходники; если в стороннем, номер строки поможет лишь понять, «какая функция сломалась», и не более.

Кроме того, префикс `[MyPlugin]` в журнале печатает сам плагин. **Искать в журнале по имени плагина** намного быстрее, чем читать его целиком.

### 1.4 Как выглядят ошибки Mixin и ремаппинга

Mixin — фреймворк внедрения байт-кода от SpongePowered, его используют Fabric, Forge, NeoForge, Sponge и часть гибридных серверов; некоторые плагины тоже «хукают» игровую логику через Mixin или прямое обращение к внутренней реализации сервера.

Типичный вид таких ошибок:

```text
org.spongepowered.asm.mixin.transformer.throwables.MixinTransformerError: An unexpected critical error was encountered
Caused by: org.spongepowered.asm.mixin.throwables.MixinApplyError: Mixin [mymod.mixins.json:PlayerMixin] from mod [mymod] FAILED during APPLY
```

Типичный вид при обращении к внутренней реализации сервера (NMS):

```text
java.lang.NoClassDefFoundError: net/minecraft/server/v1_20_R1/MinecraftServer
        at com.example.nmsplugin.NmsHook.<clinit>(NmsHook.java:17) ~[?:?]
Caused by: java.lang.ClassNotFoundException: net.minecraft.server.v1_20_R1.MinecraftServer
```

**Достаточно распознать эти два признака**:

1. В ошибке встречаются слова `mixin`, `MixinApplyError`, `InvalidMixinException`, `MixinTransformerError`, `mixin config`;
2. В ошибке встречаются имена пакетов вида `net.minecraft.server.v1_xx_Rx`, `org.bukkit.craftbukkit...` — **с номером версии или указывающие на внутренности сервера**.

Сами эти имена говорят: код написан **под конкретную версию и конкретный загрузчик**, а окружение, в котором он сейчас работает, не то, под которое он сделан. **Почти всегда это несовпадение версий, а не ошибка в вашей конфигурации.**

:::warn На таких ошибках не подозревайте сначала конфигурацию
Увидев классы, связанные с Mixin или NMS, сначала сверьте версии (версию игры, версию ядра или загрузчика, версию плагина или мода), а не правьте `config.yml`. Точные формулировки ошибок и поддерживаемые диапазоны — **по официальной документации соответствующего загрузчика и плагина**.
:::

## 2. Несовместимость плагинов

### 2.1 Таблица симптомов

| Ошибка или симптом | Смысл | Частая причина |
| --- | --- | --- |
| `NoClassDefFoundError: com/example/lib/Foo` | Класс не найден во время работы | Нет жёсткой зависимости (не выполнено `depend`); плагин скомпилирован под **другое ядро**; класс из внутренней реализации сервера |
| `ClassNotFoundException: ...` | То же, обычно при явной загрузке класса | Нет зависимости; плагин состоит из нескольких jar, а вы положили не все; скачанный файл повреждён |
| `NoSuchMethodError: 'void a.b.C.d(...)'` | Класс найден, но **сигнатура метода не совпадает** | Версия API, под которую компилировался плагин, отличается от текущего сервера или зависимости (чаще плагин новее сервера либо зависимость слишком старая) |
| `AbstractMethodError` | В интерфейсе появился новый метод, а в реализации его нет | Плагин скомпилирован под **более старый** API, а сервер или зависимость уже изменили интерфейс |
| `UnsupportedClassVersionError ... class file version 65.0` | Плагин скомпилирован **более новой Java** | Ваша Java старше требуемой плагином (65 = Java 21); смените Java или версию плагина |
| `MixinApplyError` / `InvalidMixinException` / `MixinTransformerError` | Не удалось внедрить Mixin | Плагин хукает внутренности, под которые никогда не писался; несовпадение версий |
| Плагин загрузился, но его команды не реагируют | Функциональность тихо отключена | Не выполнена мягкая зависимость (`softdepend`); не установлено соответствующее расширение или модуль |
| Плагин отключает себя при запуске | Автор сделал проверку версии | Текущая версия вне поддерживаемого диапазона, плагин отказывается загружаться, в журнале обычно указано, какие версии поддерживаются |

:::note NoClassDefFoundError иногда «последствие»
Если в журнале перед этим есть `ExceptionInInitializerError`, то `NoClassDefFoundError` — лишь последствие сбоя статической инициализации, **настоящая причина в предыдущей строке журнала**.
:::

### 2.2 Порядок исправления

Делайте в этом порядке, на каждом шаге меняя только одну переменную:

1. **Сначала подтвердите три версии**: версия игры (1.20.4 / 1.21.x и т. п.), серверное ПО (Paper / Purpur / Spigot / Fabric / Forge / NeoForge), версия Java. Соответствие Java и версии игры — см. [Подготовка среды (Windows и Linux)](/tutorials/java/environment).
2. **Проверьте поддерживаемые версии плагина**: Supported Versions на странице релиза, README, а также `api-version` в `plugin.yml` внутри jar.
3. **Доставьте зависимости**: Vault, PlaceholderAPI, ProtocolLib, LuckPerms и подобные самые часто требуемые плагины, см. [Частые плагины-зависимости](/tutorials/java/plugin-deps).
4. **Обновите или понизьте версию плагина**: приоритет — согласовать плагин с версией ядра. Многие плагины поддерживают несколько веток или несколько jar, **сначала возьмите правильную ветку**, а потом говорите о номере версии.
5. **Замените заброшенный плагин**: если последняя поддерживаемая версия заметно ниже вашего ядра, не упирайтесь, ищите поддерживаемую замену.
6. **Локализация методом деления пополам**: если после всех шагов не помогло, сузьте круг до одного плагина способом ниже.

### 2.3 Деление пополам: сузить проблему до одного плагина

```text
1. Остановить сервер, скопировать весь каталог plugins/ для страховки
2. Оставить только необходимые зависимости и подозреваемого, остальное убрать из plugins/
3. Запустить, попробовать воспроизвести проблему
   Ошибка осталась -> проблема среди этих, продолжаем делить пополам
   Ошибки нет -> проблема среди убранных, вернуть половину, повторить
4. Каждый раунд начинать с «убрать всё, вернуть половину», максимум log2(N) раундов
5. Локализовав один плагин, пробовать разные его версии, а не только последнюю
```

:::tip Не меняйте всё сразу
«Обновить все плагины до последних версий» превращает одну переменную в N, и потом локализация начинается с нуля. **Меняйте по одной переменной за раз.**
:::

### 2.4 Цвета `/plugins` и консоль

В серверах семейства Paper / Spigot команда `/plugins` различает состояния цветом: **зелёный — включён, красный — сбой загрузки или отключён**. Она говорит только, сколько красных, и **не говорит почему**.

Причина обязательно печатается в консоли и в `logs/latest.log`, типичный вид (иллюстрация):

```text
[12:00:02 WARN]: [MyPlugin] Could not load 'plugins/MyPlugin.jar' in folder 'plugins'
org.bukkit.plugin.UnknownDependencyException: Unknown/missing dependency plugins: [Vault]. Please download and install these plugins.
        at org.bukkit.plugin.java.JavaPluginLoader.loadPlugin(JavaPluginLoader.java:155) ~[paper-api.jar:?]
        ...
[12:00:02 WARN]: [MyPlugin] Disabling MyPlugin v1.2.3
```

Ищите в журнале по имени плагина — обычно причина видна за несколько секунд. О зависимостях — см. [Частые плагины-зависимости](/tutorials/java/plugin-deps), основы установки и загрузки плагинов — см. [Введение в плагины](/tutorials/java/plugins).

## 3. Несовместимость ядра

### 3.1 Семейство API: Bukkit — одна линия

Bukkit, Spigot, Paper, Purpur, Leaves, Leaf и Folia принадлежат одному семейству API и связаны отношениями **совместимости сверху вниз**: плагин, написанный под верхний уровень, обычно работает на нижнем, обратное неверно.

| API, под который компилировался плагин | Spigot | Paper / Purpur | Folia |
| --- | --- | --- | --- |
| Bukkit / Spigot API | Да | Да | Нужно, чтобы плагин заявил поддержку Folia |
| Paper API | Обычно нет (не хватает классов или методов) | Да | Нужна адаптация плагина |
| NMS или API конкретной ветки | Только соответствующая версия | Только соответствующая версия | Обычно нет |

:::note «Да» в таблице — только суждение на уровне API
Оно не означает, что плагин действительно будет работать правильно. **Работает ли плагин на вашем ядре — по официальному описанию плагина.**
:::

Folia — особый случай: она делит мир на регионы и тикает их параллельно, поэтому **требует, чтобы плагин явно заявил поддержку Folia в `plugin.yml`**, иначе он будет сразу отклонён при загрузке. Конкретные поля и ограничения — по официальной документации Folia.

### 3.2 Почему плагины на NMS ломаются при каждом обновлении

NMS означает `net.minecraft.server`, то есть **внутреннюю реализацию** сервера. Mojang никогда не обещал её стабильность: имена классов, методов и полей могут меняться между версиями.

- Плагины, использующие только **публичный API** Bukkit / Paper, обычно переживают обновление между минорными версиями.
- Плагины, обращающиеся к NMS, **требуют адаптации автором под каждую версию игры**, пропуск промежуточных версий почти гарантированно ломает их.
- Во времена Spigot внутренняя реализация через ремаппинг попадала в пакеты **с номером версии** вроде `v1_20_R1`, поэтому при смене версии плагин сразу не находит класс.
- Paper с 1.20.5 перешёл на официальные маппинги Mojang, и способ написания NMS-плагинов отличается от прежнего, **конкретные изменения — по официальным объявлениям Paper**.

Признаки ошибок единообразны: `NoClassDefFoundError`, `NoSuchMethodError`, `NoSuchFieldError`, причём в имени класса есть `net.minecraft` или `org.bukkit.craftbukkit`.

### 3.3 Плагинное и модовое ядра не взаимозаменяемы

| Ваше ядро | Может загружать плагины | Может загружать моды |
| --- | --- | --- |
| Paper / Purpur / Spigot | Да | Нет |
| Fabric / Forge / NeoForge | Нет (нужен мост) | Да |
| Гибридные (Arclight, Mohist, Youer и др.) | Обычно и то, и другое | Обычно и то, и другое |

- **Моды для Fabric / Forge / NeoForge плагинное ядро не загрузит**; и наоборот, плагин нельзя просто положить в модовое ядро.
- Гибридные ядра загружают обе стороны, но **совместимость поддерживает само гибридное ядро**, и проблемы возможны в обеих экосистемах. При ошибках плагинов на гибридном ядре сначала уточните по его официальной документации, какие плагины и моды оно поддерживает.
- Прокси (Velocity, BungeeCord) — **третье семейство API**: плагины Bukkit нельзя положить в Velocity, а плагины Velocity — в Paper. Подробнее — см. [Прокси](/tutorials/java/proxy).

Детали и компромиссы — см. [Введение в плагины](/tutorials/java/plugins) и [Выбор ядра сервера](/tutorials/java/core).

### 3.4 Согласование трёх сторон на модовом сервере

На модовом сервере нужно одновременно согласовать три вещи: **версию игры + версию загрузчика + каждый мод**. Не согласуете одну — загрузчик откажется запускаться и перечислит проблемные моды.

Типичный вид для Fabric (иллюстрация, точные формулировки — по официальной документации Fabric):

```text
Incompatible mod set!
net.fabricmc.loader.impl.FormattedException: Mod resolution encountered an incompatible mod set!
A potential solution has been determined:
         - Replace mod 'Sodium' (sodium) 0.5.8 with a version that supports minecraft 1.20.1
```

Типичный вид для Forge / NeoForge (иллюстрация):

```text
Missing or unsupported mandatory dependencies:
        Mod ID: 'create', Requested by: 'mymod', Expected range: '[0.5.1,)', Actual version: '0.5.0'
```

Моды заявляют зависимости в метаданных: Fabric — в `depends` в `fabric.mod.json`, Forge / NeoForge — в `[[dependencies]]` в `mods.toml`. Кроме того, нужно различать моды **только для клиента**, **только для сервера** и **общие для обеих сторон**: если положить клиентский мод в `mods/` сервера, тоже будет ошибка.

### 3.5 Как диагностировать несовместимость ядра

1. **Прочитайте в консоли первую ошибку, где упоминается класс, пакет или ID мода**. Последующие ошибки чаще всего её последствия.
2. **Посмотрите `api-version` в `plugin.yml`** (для плагинов Paper / Spigot). Это **подсказка**: автор заявил целевой API, но она **не гарантирует** нормальной работы на вашем ядре. Если поле отсутствует, сервер обычно считает плагин «старым» и выдаёт предупреждение, конкретное поведение — по официальной документации сервера.
3. **Воспроизведите на чистом тестовом сервере**: то же ядро, только этот плагин (плюс необходимые зависимости), новый мир. Если ошибка повторяется, проблема в плагине, ядре или версии, а не в вашей конфигурации.
4. **Сверьтесь с официальной матрицей поддержки**: страница релиза плагина, официальная документация ядра, страница мода — посмотрите все три.
5. **Проверьте, не смешаны ли вещи из разных семейств**: моды в каталоге плагинов, плагины прокси в подсервере — всё это даёт непонятные ошибки.

### 3.6 Стратегия обновления и понижения

- **Перед обновлением сделайте копию**: как минимум каталоги `world`, конфигурацию плагинов, `server.properties`, и **запишите текущие версии всех плагинов и модов**.
- **Сохраните предыдущий jar ядра**: при проблеме просто вернуть его намного быстрее, чем разбираться на месте.
- **Зафиксируйте версии плагинов**: после обновления ядра не обновляйте сразу все плагины до последних; сначала убедитесь, что ядро нормально запускается, потом обновляйте плагины партиями.
- **Не обновляйте сначала мир**: как только мир открыт более новой версией, откат к старому ядру может не прочитать его. **Сначала добейтесь работы ядра на новой версии и решите, что остаётесь на ней, и только потом трогайте мир.**
- **Двигайтесь партиями**: ядро -> зависимости -> плагины, зависящие от зависимостей -> остальные плагины, после каждой партии запуск и проверка.
- **С прокси так же**: сначала обновите подсерверы, убедитесь, что всё в порядке, потом прокси.

:::warn Условие понижения — «копия до обновления»
После того как новая версия записала данные мира, старая версия может просто отказаться его загружать. **Без полной копии до обновления не обновляйтесь.**
:::

## 4. Другие частые ошибки

### 4.1 UnsupportedClassVersionError (неверная версия Java)

```text
java.lang.UnsupportedClassVersionError: com/example/Plugin has been compiled by a more recent
version of the Java Runtime (class file version 65.0), this version of the Java Runtime only
recognizes class file versions up to 61.0
```

Два числа в скобках — **номера версии файла класса**, а не версии Java. Соответствие:

| Версия файла класса | Соответствующая Java |
| --- | --- |
| 52 | Java 8 |
| 55 | Java 11 |
| 61 | Java 17 |
| 65 | Java 21 |
| 69 | Java 25 |

- **Ошибка у плагина**: плагин скомпилирован под более новую Java, чем ваша среда, смените Java или версию плагина.
- **Ошибка у ядра сервера**: ядро требует Java новее вашей среды.
- Какую Java использовать — по версии игры из таблицы в [Подготовке среды (Windows и Linux)](/tutorials/java/environment), **не ставьте последнюю по ощущению**.
- Правка `-Xmx`, конфигурации и переустановка плагинов не помогут: это не проблема памяти или настроек.

:::note Слишком высокая Java тоже создаёт проблемы
При версии Java выше требуемой такой ошибки обычно нет, но возможны проблемы совместимости части плагинов или модов. **Рекомендуется строго следовать требованию**, конкретно — по официальной документации ядра и плагинов.
:::

### 4.2 Address already in use (порт занят)

```text
[12:00:00 ERROR]: **** FAILED TO BIND TO PORT!
[12:00:00 ERROR]: The exception was: java.net.BindException: Address already in use: bind
[12:00:00 ERROR]: Perhaps a server is already running on that port?
```

Причина в том, что 25565 (или ваш порт) уже занят другим процессом: другой экземпляр сервера, процесс от прошлого запуска, который не завершился, или другая программа.

Windows:

```powershell
netstat -ano | findstr :25565
taskkill /PID <PID> /F
```

Linux:

```bash
sudo ss -tlnp | grep 25565
kill <PID>
```

При запуске нескольких серверов на одной машине каждому экземпляру нужен свой `server-port`. Порядок разбора по портам — см. [Подготовка среды (Windows и Linux)](/tutorials/java/environment).

### 4.3 Выход из-за несогласия с EULA

```text
You need to agree to the EULA in order to run the server. Go to eula.txt for more info.
```

Это не падение, а нормальный отказ сервера запускаться. Поменяйте `eula.txt` в каталоге сервера на `eula=true` и перезапустите. **Делайте так только если вы действительно прочитали и приняли Minecraft EULA**, текст соглашения — на официальной странице.

### 4.4 Ошибки, связанные с памятью

| Ошибка | Смысл | Что делать |
| --- | --- | --- |
| `java.lang.OutOfMemoryError: Java heap space` | Не хватает памяти кучи | Умеренно увеличить `-Xmx`; одновременно проверить дальность прорисовки, число сущностей и утечки в плагинах |
| `java.lang.OutOfMemoryError: GC overhead limit exceeded` | GC тратит массу времени, но память не освобождает | По сути всё та же слишком маленькая куча или утечка, см. выше |
| `Could not reserve enough space for object heap` | Сбой JVM **на этапе запуска**, кучу не удаётся выделить | `-Xmx` больше доступной памяти либо используется 32-битная Java; уменьшите `-Xmx` и перейдите на 64-битную Java |
| `Error occurred during initialization of VM` | Сбой инициализации JVM, обычно из-за параметров или памяти | Проверить разумность `-Xms` / `-Xmx` в параметрах запуска |

- `-Xms` — начальная куча, `-Xmx` — максимальная. Равные значения снижают накладные расходы на расширение кучи во время работы, но **не превышайте физическую память**, оставляйте место операционной системе и другим процессам.
- **Увеличение `-Xmx` не универсальное средство**: если память утекает через плагин или мод, увеличение лишь откладывает падение. Смотрите память и flame graph инструментами вроде **spark**, методы — см. [Оптимизация производительности](/tutorials/java/optimize).
- Рекомендуемое соотношение памяти и игроков — см. [Протокол запуска и рекомендации по конфигурации](/tutorials/java/protocol).

### 4.5 Повреждение сохранений и чанков

Проявление зависит от версии, часто это IO-исключение при загрузке чанка, например (иллюстрация, точные формулировки — по исходному тексту журнала и официальной документации):

```text
[12:00:00 ERROR]: Error loading chunk [12, 34]: java.io.IOException: Region file is corrupted
[12:00:00 ERROR]: Failed to load chunk at 12, 34
```

Принципы обработки:

1. **Не редактируйте файлы в `region/` вручную**, прямая правка с большой вероятностью расширит область повреждения.
2. **Восстанавливайтесь из копии**, это самый надёжный способ, см. [Резервное копирование и восстановление](/tutorials/java/backup).
3. Если повреждён только один чанк и откатывать всё сохранение не хочется, можно удалить или заменить этот чанк сторонними инструментами вроде **MCA Selector**, **NBTExplorer**, **ценой будет исчезновение всего содержимого этого чанка**.
4. Если на одном и том же диске повреждения повторяются, сначала подозревайте железо и файловую систему (состояние диска, журнал ядра), чините железо и только потом говорите о восстановлении.

### 4.6 Падения Ticking entity / Ticking block entity

Заголовок таких падений — `Description: Ticking entity` или `Description: Ticking block entity` (бывает и `Ticking player`), что означает: **сущность или блочная сущность выбросила исключение при тике**, обычно из-за мода или повреждённых данных чанка.

В отчёте о падении указано расположение проблемного объекта (иллюстрация):

```text
Description: Ticking entity

java.lang.NullPointerException: Cannot invoke "net.minecraft.world.entity.Entity.getType()" because "entity" is null
        at com.example.mymod.TickHandler.onTick(TickHandler.java:64) ~[?:?]

-- Entity being ticked --
    Entity Type: minecraft:pig (net.minecraft.world.entity.animal.Pig)
    Entity's Exact location: 123.45, 64.00, -67.89
    Entity's Block location: World: (123,64,-68), Chunk: (at 11,12 in 7,-5; contains blocks 112,0,-80 to 127,255,-65)
```

Для блочных сущностей форма похожая:

```text
Description: Ticking block entity

-- Block entity being ticked --
    Name: minecraft:chest
    Block type: minecraft:chest
    Location: World: (123,64,-68), Chunk: (at 11,12 in 7,-5; ...)
```

**От координат к файлу**:

- Координаты чанка = `floor(x) >> 4`, `floor(z) >> 4`. В примере `x=123` соответствует чанку `7`, `z=-68` — чанку `-5`, что совпадает с `in 7,-5` в отчёте.
- Региональный файл = `r.<floor(чанкX/32)>.<floor(чанкZ/32)>.mca`. В примере чанки `7` и `-5` попадают в `r.0.-1.mca`, что совпадает с полем Region в отчёте.

**Безопасный порядок действий**:

1. **Остановить сервер и полностью скопировать мир**. Этот шаг пропускать нельзя.
2. Открыть соответствующий региональный файл инструментами вроде **MCA Selector**, **NBTExplorer** и **удалить только ту одну сущность или блочную сущность**, так потери минимальны.
3. Только если конкретную сущность найти не удаётся или инструмент не справляется, рассматривать удаление целого чанка. **Удаление чанка уничтожит и постройки, сундуки и все сущности в нём.**
4. После обработки сначала запустить и проверить, что падений больше нет, затем сделать новую копию.
5. Если проблема в сущности мода, вернитесь к разделу 3 и сверьте «версию игры + версию загрузчика + версию мода», **несовпадение версий часто и есть корневая причина**.

:::warn Не меняйте файлы сохранений на работающем сервере
Правка файлов `region/` при работающем сервере вызывает вторичное повреждение. **Остановить сервер, сделать копию, и только потом действовать.**
:::

### 4.7 Ошибки прав и портов в Linux

| Ошибка | Причина | Что делать |
| --- | --- | --- |
| `java.io.FileNotFoundException: ... (Permission denied)` | Неверный владелец каталога сервера (например, когда-то запускали от root) | `sudo chown -R mcserver:mcserver /opt/mcserver` и запускать под выделенным пользователем |
| `java.net.BindException: Permission denied` | Привязка к привилегированному порту ниже 1024 не от root | Использовать порт выше 1024 или при необходимости выдать право привязки (понимая риски) |
| Игроки не подключаются, но в журнале нет ошибок | Брандмауэр или группа безопасности облака не пропускает | Это проблема сетевого уровня, см. [Подготовка среды (Windows и Linux)](/tutorials/java/environment) |

**Не запускайте сервер напрямую от root**: если сервер или плагин будет использован, атакующий получит всю машину. О правах и безопасности — см. [[JAVA] Плагины безопасности](/tutorials/ops/security-java).

## 5. Порядок разбора и чек-лист

### 5.1 Идите в этом порядке

1. **Прочитайте журнал**. Сначала определите, «исключение плагина, сервер жив» это или «сервер уже упал», и решите, смотреть `logs/latest.log` или `crash-reports/`.
2. **Найдите первую ошибку**. Читайте с первой `ERROR` или `Exception`, не гадайте с конца.
3. **Сверьте три версии**. Версия игры, версия ядра или загрузчика, версия Java — сначала исключите базовое несовпадение.
4. **Воспроизведите на чистом тестовом сервере**. То же ядро + только подозрительный плагин + новый мир, чтобы отделить «проблему вашей конфигурации» от «проблемы самого плагина».
5. **Локализуйте делением пополам**. Методом из 2.3 сузьте круг до одного плагина или мода.
6. **Примените исправление**. В порядке «доставить зависимости -> согласовать версии -> заменить на аналог», меняя по одной переменной.
7. **Проверьте**. После перезапуска убедитесь, что ошибки в журнале больше нет, и реально вызовите соответствующую функцию.
8. **Запишите**. Внесите «ошибка + причина + решение» в свои заметки по эксплуатации, чтобы при следующей встрече с той же ошибкой сразу найти ответ.

### 5.2 Чек-лист разбора

| Шаг | Что делать | Критерий |
| --- | --- | --- |
| 1 | Скопировать `logs/latest.log` и свежий файл из `crash-reports/` | Доказательства сохранены, перезапуск их не потеряет |
| 2 | Определить тип исключения | Можете сказать, это исключение плагина или фатальное падение |
| 3 | Найти первое исключение и последний `Caused by` | Получены две строки заголовков |
| 4 | Сверить версию игры, ядра и Java | Все три соответствуют друг другу |
| 5 | Сверить поддерживаемые версии и зависимости плагина | Плагин поддерживает текущее ядро, зависимости на месте |
| 6 | Воспроизвести на чистом тестовом сервере | Стабильно воспроизводится либо доказано, что от вашей конфигурации не зависит |
| 7 | Сузить делением пополам | Локализован один плагин или мод |
| 8 | Исправить и проверить | Ошибки в журнале нет, функции работают |
| 9 | Записать и скопировать | Есть заметка и есть копия для отката |

### 5.3 Что предоставить при обращении за помощью

Прежде чем спрашивать в чате или в issue, подготовьте это. Чем полнее информация, тем вероятнее, что кто-то увидит проблему сразу:

- **Полный фрагмент журнала**: с первой `ERROR` или `Exception` до конца этого исключения, **включая все `Caused by`**. Не обрезайте до трёх строк и не фотографируйте экран телефоном.
- **Отчёт о падении**: если это падение, приложите соответствующий файл из `crash-reports/`, в нём уже есть версии и окружение.
- **Сведения о версиях**: версия игры, имя и номер сборки ядра, вывод `java -version`.
- **Список плагинов или модов**: вывод `/plugins` либо имена и версии файлов в `plugins/`, `mods/`.
- **Что меняли в последнее время**: обновили ядро, поставили новый плагин, изменили такую-то конфигурацию. **Этот пункт часто и есть ответ.**
- **Шаги воспроизведения**: когда падает обязательно, когда нет.
- **Что уже пробовали**: чтобы вас не просили повторить уже исключённые действия.
