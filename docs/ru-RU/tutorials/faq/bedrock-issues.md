Проблемы с запуском сервера Bedrock — «не стартует / не подключается / заходят, но не так» — часто выглядят очень похоже: игрок говорит только «не заходит», а на стороне сервера может быть даже не запущен процесс. Эта статья — расширенная версия [[BE] Частых вопросов](/tutorials/faq/faq-be), она идёт по принципу «сначала классифицировать, потом локализовать» и старается чётко описать критерии каждого шага.
:::tip Как пользоваться статьёй
Сначала посмотрите таблицу классификации в разделе 1, определите, к какому классу относится ваша проблема, и сразу переходите к нужному разделу. В разделе 5 дан полный порядок разбора с нуля; в разделе 6 — что сообщать при обращении за помощью.
:::

## 1. Сначала классификация: не подключается / не стартует / заходит, но странно

Критерий классификации: **работает ли вообще процесс сервера и слушает ли он порт?**

| Явление | К какому классу относится | Какой раздел смотреть |
| --- | --- | --- |
| Окно лаунчера мелькает и закрывается, или командная строка сразу возвращает приглашение | Не стартует | Раздел 2 |
| В консоли сыпятся ошибки, процесс вообще не поднялся | Не стартует | Раздел 2 |
| Процесс работает, консоль в порядке, но игроки не подключаются | Не подключается | Раздел 3 |
| Игроки заходят, но есть лаги, странности с сохранениями, неверные права | Заходят, но странно | Раздел 4 |
| Часть игроков заходит, часть нет | Не подключается | Раздел 3 (сначала проверить версию протокола и платформу клиента) |
| Инструмент проверки портов говорит «доступен», а игроки всё равно не заходят | Не подключается | Раздел 3.2 (чаще всего инструмент проверяет только TCP) |
| Вчера всё работало, сегодня не заходят все | Не подключается | Раздел 3.1 (автообновление клиента сменило протокол) |
| Сервер запускается, но через несколько минут игры сам выходит | Заходят, но странно | Разделы 4.1, 4.2 |
:::note Сначала подтвердите состояние процесса, потом обсуждайте остальное
Пути разбора «не подключается» и «не стартует» совершенно разные. Первый шаг всегда — убедиться, что процесс жив и слушает порт (раздел 5). Пропустив этот шаг, все дальнейшие суждения остаются догадками.
:::

## 2. Сервер не стартует (BDS и сторонние ядра)

### 2.1 BDS: архитектура, библиотеки и требования к системе

BDS — **скомпилированная нативно** программа, а не скрипт, поэтому она требовательна к системе и библиотекам.

| Пункт | Требование | Пояснение |
| --- | --- | --- |
| Архитектура | **x86-64** | Официально предоставляются сборки только для Windows и Linux x86-64; устройства ARM (например, Raspberry Pi) официально не поддерживаются |
| Windows | Windows 10 10.0.15063 и новее или Windows Server 2016 и новее | Дополнительно нужна **библиотека Microsoft Visual C++** (VC++ Redistributable) |
| Linux | Официально поддерживается только **Ubuntu 22.04 и новее** | Другие дистрибутивы x86-64 работают при наличии нужных библиотек, включая **glibc 2.35 или новее** |
| Память | Минимум 4 GB | При более чем 10 игроках обычно нужно больше; на диске рекомендуется оставить 1 GB |

Типичные проявления отсутствия библиотек: в Windows BDS зависит от библиотеки Microsoft Visual C++, **при её отсутствии обычно сразу при запуске сообщается об отсутствии DLL или окно мелькает и закрывается**, в консоли при этом часто ничего нет; в Linux при слишком старой glibc обычно наблюдается **сбой загрузки динамических библиотек** (`error while loading shared libraries` и подобное). Точные требования к библиотекам и версии libc смотрите на **официальной странице загрузки BDS и в release notes**, не копируйте номера версий из сторонних руководств.
:::warn BDS не позволяет указать память, как Java Edition
В Java Edition размер кучи управляется `-Xms` / `-Xmx`, **у BDS соответствующего параметра запуска нет**. Он управляет памятью сам, и вы можете влиять на потребление лишь косвенно: ограничивая размер мира, число сущностей и игроков. Поэтому советы вроде «добавь BDS параметры памяти» бесполезны.
:::

### 2.2 Linux: право на выполнение и рабочий каталог

Две самые частые причины «не стартует» в Linux лежат на уровне действий. **Первая — нет права на выполнение**: извлечённый из архива `bedrock_server` по умолчанию не имеет `+x`:

```bash
chmod +x bedrock_server
```

**Вторая — неверный рабочий каталог**: официальное использование BDS — **запускать его в собственном каталоге** и направлять путь поиска динамических библиотек в текущий каталог:

```bash
cd /opt/bedrock-server
LD_LIBRARY_PATH=. ./bedrock_server
```

**Все данные BDS сохраняются в рабочем каталоге**, и он ожидает, что распакованные начальные файлы лежат именно там. Поэтому: при запуске через systemd или иным способом обязательно задайте `WorkingDirectory`, иначе рабочим каталогом процесса может оказаться `/`; запуск бинарника из другого каталога в лучшем случае создаст в неверном каталоге новый набор конфигурации и мира, в худшем — сразу завершится сбоем из-за отсутствия библиотек в том же каталоге. Учтите также, что `.` в `LD_LIBRARY_PATH=.` означает **текущий рабочий каталог**, а не каталог, где лежит бинарник.
:::tip Первая команда для разбора «не стартует»
Запустите вручную в каталоге сервера `LD_LIBRARY_PATH=. ./bedrock_server` и прочитайте ошибку целиком. Многие проблемы выявляются уже на этом шаге, намного быстрее, чем листать журналы.
:::

### 2.3 Ловушки переименования и путей

Главный исполняемый файл BDS можно переименовать, но **не рекомендуется**. После переименования нужно синхронно изменить все места, где он упоминается: скрипты запуска (`.bat` / `.sh`), ярлыки на рабочем столе, команду запуска, настроенную в панели или демоне, и саму команду `LD_LIBRARY_PATH=. ./bedrock_server` из раздела 2.2. Пропустите любое место — получите «нажал и ничего не произошло» или «файл не найден». Если уже переименовали и не стартует, сначала верните прежнее имя и проверьте, а потом решайте, править ли все места.

Так же легко ошибиться с **самим путём**: каталог сервера рекомендуется размещать по пути только из латинских букв, без пробелов и специальных символов. Пути с кириллицей и другими не-ASCII символами в части панелей и скриптов запуска приводят к сбоям чтения, причём сообщения об ошибках обычно непонятны.

### 2.4 Семейство Nukkit: согласование версии Java и сборки

Семейство Nukkit (Nukkit / PowerNukkitX и др.) — программы на **Java**, нужно проверить два пункта:

- **Достаточно ли новая версия Java**: новые ветки обычно требуют более свежую Java, слишком старая даст при запуске ошибку вроде `UnsupportedClassVersionError`, в тексте которой обычно прямо указана требуемая версия, **ориентируйтесь на официальную документацию этого ядра**.
- **Правильная ли разрядность**: на 64-битной системе нужна 64-битная Java. 32-битная Java упадёт при запуске или в процессе работы из-за предела памяти.

Более скрытая проблема — **несоответствие сборки и версии протокола**: сама сборка ядра запускается, но клиент не подключается или сообщает, что версия сервера устарела. Этот уровень сначала смотрите в [Начале работы со сторонними ядрами Bedrock](/tutorials/bedrock/third-party-setup), там есть полное описание согласования версий.

### 2.5 PocketMine-MP: версия PHP и расширения

PMMP — программа на **PHP**, официальные требования: **64-битный CPU + 64-битная ОС**, памяти от 1 GB; два и более ядра — лишь **рекомендация**, а не жёсткое требование; официально по возможности поддерживаются Windows, Linux и macOS, в принципе подойдёт любая платформа, где работает 64-битный PHP с полным набором расширений.

Две самые частые ловушки: **версия PHP и расширения** — PMMP требует определённой версии PHP и набора расширений, при неверной версии или незагруженном расширении запуск падает с ошибкой, чаще всего это сбой загрузки какого-то расширения PHP (например, `opcache`); **какие именно расширения нужны и какая минимальная версия PHP — по разделу Setup requirements официальной документации PMMP**. **Не используйте попавшийся под руку системный PHP** — PHP из репозитория дистрибутива часто старый и с неполным набором расширений, а в Windows может стоять PHP, оставшийся от другого ПО; PMMP официально предоставляет **готовые сборки PHP для разных систем** (на странице релизов берите файл под свою ОС), распаковываются и работают сразу. **Рекомендуется официально собранный PHP, а не произвольный системный.**
:::warn Сначала убедитесь, какой именно PHP вы вызываете
Выполните `php -v` и убедитесь, что в выводе та версия и та разрядность, которые вы собираетесь использовать. Если в скрипте запуска написано просто `php`, он берёт первый из `PATH`, и это вполне может быть не тот, что вы установили.
:::

### 2.6 Порт занят

Симптом конфликта портов: процесс запускается и сразу выходит, в консоли сообщение о невозможности привязать (bind) порт.

Есть **специфичная для Bedrock ловушка**: параметр `enable-lan-visibility` в `server.properties` по умолчанию включён, его задача — отвечать клиентам, ищущим сервер в локальной сети. При включении **даже если вы изменили `server-port` / `server-portv6` на другие значения, сервер всё равно будет привязываться к стандартным 19132 / 19133**. Поэтому при запуске второго сервера Bedrock на той же машине конфликт возможен даже после смены порта; если обнаружение в локальной сети не нужно, этот параметр можно отключить, чтобы обойти проблему, конкретное поведение — по официальной документации. Учтите также, что допустимый диапазон `server-port` — целое число **1–65535**.

### 2.7 Ошибки в записи server.properties

`server.properties` в Bedrock — **текст из строк `ключ=значение`**, строки, начинающиеся с `#`, являются комментариями. Неверный тип или значение вне диапазона может привести к сбою запуска либо к тому, что параметр будет проигнорирован и «изменение не подействует». Несколько подтверждённых допустимых значений можно сверить напрямую:

```properties
server-port=19132
server-portv6=19133
allow-list=true
gamemode=survival
difficulty=easy
default-player-permission-level=member
tick-distance=4
view-distance=32
max-players=10
compression-algorithm=zlib
```

| Ключ | Допустимые значения / диапазон |
| --- | --- |
| `server-port` / `server-portv6` | Целое число 1–65535 |
| `allow-list` | `true` / `false` |
| `gamemode` | `survival` / `creative` / `adventure` |
| `difficulty` | `peaceful` / `easy` / `normal` / `hard` |
| `default-player-permission-level` | `visitor` / `member` / `operator` |
| `tick-distance` | Целое число 4–12 |
| `view-distance` | Целое число не меньше 5 |
| `max-players` | Положительное целое |
| `compression-algorithm` | `zlib` / `snappy` |
:::warn Перед правкой сделайте копию, правьте в текстовом редакторе
Правьте **простым текстовым редактором** (вроде «Блокнота»), не используйте редакторы, вставляющие форматирование (например, офисные пакеты с форматированным текстом), иначе в файл попадут невидимые символы и разбор сломается. Перед правкой скопируйте `server.properties`. Что именно допускает каждое значение — **по официальной документации**.
:::

## 3. Не подключается (cannot connect)

### 3.1 Несовпадение протокола и версии

Это **самая частая** причина неудачного подключения в Bedrock, и у игроков почти нет возможности что-то сделать самим: магазин приложений обновляет клиент автоматически, и при обновлении клиента меняется протокол. Здесь этот уровень подробно не раскрывается, смотрите [Версии протокола и выбор версии](/tutorials/bedrock/protocol). Главное в двух пунктах: протокол клиента должен **совпадать** с протоколом сервера, иначе не войти; игроки на iOS могут поставить только последнюю версию из магазина, поэтому путь «попросить игроков понизить версию» для iOS закрыт. При несовпадении версий клиента и сервера игрок увидит сообщение вроде «устаревший сервер», **конкретный текст сообщения — по официальной документации**.

### 3.2 UDP и TCP: порты, брандмауэр, группа безопасности

Bedrock **работает по UDP**, это полностью отличается от Java Edition и является главной причиной «проверка портов прошла, а игроки не заходят».

| Пункт | Значение |
| --- | --- |
| Порт IPv4 по умолчанию | **19132 / UDP** |
| Порт IPv6 по умолчанию | **19133 / UDP** |
| Где нужно разрешить | Системный брандмауэр **и** группа безопасности облака, оба места |
| Проброс портов на роутере | Протокол должен быть **UDP**; если доступен только TCP, нужно создать отдельное правило UDP |
:::warn Инструменты, проверяющие только TCP, обманут вас
Многие онлайн-инструменты «проверки портов» по умолчанию проверяют только TCP. Открытый TCP-порт не означает открытый UDP-порт. При проверке портов Bedrock обязательно убедитесь, что проверяется именно **UDP**.
:::

Кроме того, большинство сервисов проброса через промежуточный узел по умолчанию поддерживают только TCP, при выборе уточняйте, поддерживается ли **UDP**. О сценариях кросс-платформы (когда игроки с телефона или Bedrock заходят на Java-сервер или наоборот) — см. [Поддержка мобильных игроков](/tutorials/java/mobile).

### 3.3 CGNAT / нет публичного IPv4 / двойной NAT

Сервер работает нормально, брандмауэр пропускает, а снаружи всё равно не подключиться — проблема часто на стороне оператора.

| Ситуация | Как определить | Что делать |
| --- | --- | --- |
| WAN-порт роутера получил **приватный или общий адрес** (CGNAT) | У вас нет собственного публичного IPv4, пробрасывать порт некуда | Запросить у оператора публичный IP или перейти на туннель / виртуальную локальную сеть с поддержкой UDP |
| **Двойной NAT**: за ONT стоит ещё один роутер | Проброс сделан только на одном устройстве, цепочка рвётся посередине | Проброс должен быть сделан на **том устройстве, которое подключено к интернету напрямую**, и пересылка на следующем хопе выстроена в цепочку |
| Публичный IP динамический | Адрес меняется, игроки не запомнят | Использовать службу динамических доменных имён или туннель |
| Есть только публичный IPv6 | Часть сетей игроков не поддерживает IPv6 | Одновременно убедиться в доступности по IPv4 |

Когда проброс портов невозможен, частая альтернатива — **виртуальная локальная сеть**: сервер и игроки входят в одну виртуальную сеть, и игроки подключаются по IP виртуальной сети. В сообществе обычно используют ZeroTier, Radmin VPN, Hamachi и подобные, конкретная настройка — по их официальной документации.

### 3.4 Обнаружение в локальной сети против подключения по IP

Эти два способа идут разными путями, и симптомы различаются.

| | Обнаружение в локальной сети | Подключение по IP / домену |
| --- | --- | --- |
| Что нужно игроку | Ничего, сервер появится сверху экрана «Игра» | Добавить сервер вручную, указав адрес и порт |
| Предпосылка | Обе стороны в одной локальной сети | Сервер доступен извне (проброс портов или туннель) |
| От чего зависит | `enable-lan-visibility`, доступность UDP 19132/19133 | Публичный IP, брандмауэр, группа безопасности, туннель |

Несколько легко упускаемых моментов: **в Bedrock порт нужно указывать явно**, в отличие от Java Edition он не поддерживает сокращение через SRV-записи, поэтому и поле адреса, и поле порта должны быть заполнены верно; обнаружение в локальной сети зависит от широковещания и многоадресной рассылки и не работает в части виртуальных сетей, сетей контейнеров и сетей с несколькими сегментами, тогда остаётся только подключение по IP; подключение **к самому себе с той же машины** может не удаться из-за loopback или правил брандмауэра, проверка с другого устройства быстро покажет, «сервер недоступен» это или «проблема в самой этой машине».

### 3.5 Консольные платформы (Xbox / PlayStation / Switch)

На консольных платформах **нельзя ввести IP прямо в игре и присоединиться к серверу**. Обычно есть два пути: **свой DNS** (направить разрешение домена на ваш сервер, чтобы консоль подключалась по домену) и **локальная сеть** (консоль и сервер в одной локальной сети, подключение через обнаружение).
:::note Политика платформ меняется и различается
Ограничения на стороне консолей **меняются вместе с политикой платформ и версиями**. По некоторым данным консольные версии в целом больше склоняются к работе только через локальную сеть, причём у Switch выбор уже (возможно, только Realms и официально рекомендованные серверы). **Что именно поддерживает конкретная платформа сейчас — по официальной документации и описанию платформы**, не копируйте старые руководства.
:::

### 3.6 Проверка на стороне клиента

Сначала исключите самые дешёвые варианты, потом трогайте сервер: **формат адреса** — в поле адреса только IP или домен, **порт вводится в поле порта**, если вписать `ip:port` целиком в поле адреса, в части версий разбор не удастся; **порт** по умолчанию 19132, если сервер менял порт, игрок тоже должен поменять; **одна ли версия** — клиент Bedrock **не может** заходить напрямую на сервер Java Edition (и наоборот), для кросс-платформы нужны дополнительные решения, см. [Поддержка мобильных игроков](/tutorials/java/mobile); **версия клиента должна совпадать с версией сервера**, Bedrock не поддерживает подключение старого клиента к новому серверу. В конце **попробуйте с другого устройства и из другой сети** — это сразу покажет, проблема в сервере, в сети игрока или в его устройстве.

### 3.7 Особенности сторонних ядер

Сторонние ядра **не обязательно реализуют все особенности протокола и весь игровой контент** официального сервера, поэтому «тот же клиент на официальном сервере работает, а на моём нет» — нормальное явление, не обязательно ошибка конфигурации. На примере PocketMine-MP официальная документация прямо указывает: PMMP **не** реализует все игровые механики Minecraft, потому что разработчики занимаются этим в свободное время и не успевают за скоростью официальных обновлений; на момент написания отсутствуют **мобы, редстоун, вагонетки и измерения**.

Второй важный момент — **согласование сборки ядра и версии протокола**: версия, которую ядро сообщает клиенту, должна приниматься клиентом, иначе игрок увидит сообщение вроде «версия сервера устарела». Официальный FAQ PMMP предлагает такое решение: выполнить в консоли сервера команду `version`, посмотреть поддерживаемую текущим ядром версию Minecraft и по ней выбрать более новую сборку ядра; там же указано, что **более новые патч-версии иногда (но не всегда) совместимы без обновления ядра**.

## 4. Заходят, но странно (works but behaves oddly)

### 4.1 Лаги и память

**Первый критерий лагов — одноядерная производительность.** Вычисления мобов в BDS выполняются в одном потоке, поэтому плавность зависит в основном от одноядерной производительности, и чем больше карта, тем сильнее лаги; об этом есть в [Сервере BDS](/tutorials/bedrock/bds).

| Что можно подкрутить | Пояснение |
| --- | --- |
| Уменьшить `tick-distance` | Допустимый диапазон 4–12, по умолчанию 4. Чем больше, тем больше чанков в вычислениях |
| Уменьшить `view-distance` | Должно быть не меньше 5, по умолчанию 32. В основном влияет на дальность рассылки |
| Уменьшить размер ферм сущностей и мобов | Сущности — основная нагрузка однопоточных вычислений |
| Взять машину с более сильным одним ядром | Самое прямое, но и самое дорогое |
| `max-threads` | В Bedrock есть этот параметр (максимум потоков), но он **не устраняет узкое место одного потока**, не надейтесь решить лаги им |

О ядрах на PHP: официальная документация PMMP прямо говорит, что они «печально известны» плохим использованием нескольких ядер; если вы покупаете машину под PMMP, **следует выбирать высокую частоту, а не число ядер**.

**О постоянном росте памяти**: у BDS есть известная проблема медленного роста памяти. Ключевое предупреждение —
:::warn Не очищайте память принудительно
Принудительная очистка памяти приводит к тому, что у игроков при скачивании текстурпака или аддона **застревает индикатор прогресса**, и **восстановить можно только перезапуском сервера**. Правильный подход — запланировать окно регулярного перезапуска, а не «увидел высокую память и почистил».
:::

### 4.2 Проблемы чанков и данных мира

Данные мира BDS находятся в каталоге **`worlds/`**, по подкаталогу на мир. Есть одно очень важное поведение:

> При запуске сервер ищет в `worlds/` каталог **с тем же именем, что `level-name` в `server.properties`**. Нашёл — использует его; **не нашёл — создаёт новый мир**.

Это значит, что **ошибка в одну букву в `level-name` не вызывает ошибку, а тихо создаёт новый мир** — игрок видит «мои сохранения пропали». Поэтому, обнаружив «сохранения изменились», первым делом сверьте `level-name` и имена каталогов в `worlds/`.

| Явление | Возможная причина | Что делать |
| --- | --- | --- |
| Мир не загружается / при запуске ошибки про мир | Сохранение повреждено или последнее сохранение было прервано | **Прекратить повторные запуски**, восстановиться из копии |
| После смены ядра мир не читается | Совместимость сохранений сторонних ядер хуже, чем у официального BDS | Вернуть прежнее ядро или мигрировать по документации ядра |
| Импортированный мир не действует | Имя каталога не совпадает с `level-name` | Переименовать каталог мира в значение `level-name` |
| Сохранения потеряны целиком | Скопирована только часть файлов | Копировать **весь каталог** `worlds/` |

Полный порядок восстановления из копии — см. [Резервное копирование и восстановление](/tutorials/java/backup).
:::tip Перед копированием или резервным копированием корректно остановите сервер
Выполните в консоли `stop` и копируйте `worlds/` только после реального выхода процесса. Копирование в момент, когда процесс ещё пишет файлы, с большой вероятностью даст сохранение, «выглядящее целым, но повреждённое».
:::

### 4.3 Аддоны и ресурспаки

Две предпосылки: **пакет должен быть в формате Bedrock** — датапаки и ресурспаки Java Edition и аддоны Bedrock — две разные вещи, они не взаимозаменяемы; **пакет должен быть правильно размещён и зарегистрирован** — просто скопировать файлы недостаточно, сервер его не включит. Проверенные каталоги и способ регистрации:

| Тип | Каталог |
| --- | --- |
| Поведенческий пакет (Behavior Pack) | `development_behavior_packs` |
| Ресурспак (Resource Pack) | `development_resource_packs` |

Чтобы включить пакет в мире, нужно создать в **рабочем каталоге этого мира** соответствующий файл списка и записать в него UUID и версию пакета; UUID берётся из собственного `manifest.json` пакета:

```json
[
    {
        "pack_id": "33556fcf-d192-4d5f-96a0-29357702af7b",
        "version": [ 1, 0, 0 ]
    }
]
```

При этом: поведенческие пакеты записываются в `world_behavior_packs.json`, ресурспаки — в `world_resource_packs.json`; при конфликте нескольких пакетов **приоритет у того, что стоит выше**.

Прочее важное: **`texturepack-required=true`** заставляет клиент скачать ресурспак сервера, и после включения клиентские ресурспаки, включённые самим игроком (включая пакеты маркетплейса), перестают действовать; **пакеты из маркетплейса (Marketplace) нельзя применить к серверу**; в корне сервера есть также **`valid_known_packs.json`** — это поддерживаемый сервером **список известных пакетов**, по нему сервер выполняет проверку, его точный формат и порядок ведения — **по официальной документации**, в повседневной работе достаточно схемы «положить в каталог + записать world_*_packs.json»; если **клиент застревает на скачивании ресурспака**, помимо проблем самого пакета это может быть связано с состоянием памяти сервера (см. 4.1), и тогда перезапуск сервера часто помогает.

Для PMMP есть ещё одна официально известная проблема: **при использовании больших ресурспаков возникают проблемы с подключением** (официальный пример — пакеты больше 1 MB). Официально предложенный способ разбора — убрать большой пакет и попробовать снова; ещё один возможно работающий обход — постепенно уменьшать `network.max-mtu-size` в `pocketmine.yml` (например, уменьшать на 100 и проверять), но официально указано, что это лишь **обход**, снижающий эффективность использования полосы, и корневую причину всё равно нужно найти.

### 4.4 Права и белый список

Права и белый список в BDS — **два независимых файла** с разными полями, их легко перепутать. **Администраторы (OP) находятся в `permissions.json`**, запись состоит из `xuid` и `permission`:

```json
[
    {
        "permission": "operator",
        "xuid": "451298348"
    }
]
```

- У `permission` допустимо только три значения: **`operator` / `member` / `visitor`**.
- **`online-mode` должен быть включён**, потому что XUID требует онлайн-проверки аккаунта.
- Если файл изменён на работающем сервере, изменения вступят в силу после **`permission reload`**; `permission list` показывает текущие права.
- Для новых игроков, которых нет в списке, действует настройка `default-player-permission-level`. Кроме правки файла, права игрока можно **менять прямо в игре**.

**Белый список находится в `allowlist.json`**, поля записи:

| Поле | Смысл |
| --- | --- |
| `name` | **Игровое имя / ник (gamertag)** игрока, должно совпадать полностью |
| `xuid` | XUID игрока; **если указан `name`, это поле можно опустить** |
| `ignoresPlayerLimit` | При `true` игрок может войти, даже когда сервер заполнен |

Несколько важных особенностей: если указан только `name`, **XUID дописывается автоматически, когда подключается игрок с этим именем**, то есть при ошибке в имени этот человек не войдёт никогда, и автоматически это не исправится; **белый список действует только при включённом `online-mode`**, после отключения проверки лицензии игроки могут зайти, используя имя из белого списка, и белый список становится фикцией; после **смены gamertag** старая запись перестаёт совпадать и её нужно обновить; если файл правят вручную на работающем сервере, нужна соответствующая команда reload, чтобы изменения вступили в силу.

| Явление | Возможная причина | Что делать |
| --- | --- | --- |
| Тот, кто должен быть OP, не OP | Запись не попала в `permissions.json` или попала, но не сделан reload | Добавить запись и сделать reload либо выставить права прямо в игре |
| Добавили в `permissions.json`, но не действует | `online-mode` выключен, XUID не проверяется | Включить `online-mode` |
| Человек из белого списка не заходит | `name` не полностью совпадает с реальным gamertag (регистр, пробелы, смена имени) | Сверить точное имя или указать XUID напрямую |
| Заходят все | Белый список не включён или `online-mode` выключен | Проверить `allow-list` и `online-mode` |
:::note Имена полей — по официальной документации
Приведённые имена полей и поведение взяты из официального описания. **В разных версиях поля и значения по умолчанию могут меняться**, фактически ориентируйтесь на официальную документацию BDS (и прилагаемый к пакету `bedrock_server_how_to.html`).
:::

### 4.5 Отличия поведения от Java Edition

Многие «баги», о которых сообщают игроки, на самом деле **различия между двумя версиями**: механика редстоуна, правила спавна мобов и другое отличаются. Здесь этот уровень не раскрывается, смотрите [JAVA против Bedrock](/wiki/editions).

## 5. Порядок разбора

Идите в этом порядке, каждый шаг отсекает половину вариантов. **Не пропускайте шаги**.

1. **Убедитесь, что процесс сервера действительно работает.** Живо ли окно консоли, есть ли процесс в списке процессов.
2. **Убедитесь, что он слушает порт.** Команды для Linux и Windows ниже.
3. **Убедитесь в порте и протоколе.** Верный ли номер порта, разрешён ли именно **UDP** (по умолчанию 19132, для IPv6 — 19133).
4. **Убедитесь в версии клиента.** Версия клиента должна совпадать с версией сервера, см. [Версии протокола и выбор версии](/tutorials/bedrock/protocol).
5. **Убедитесь в сетевом пути.** Локальная сеть / публичный IP / туннель — пути разные; нет ли CGNAT или двойного NAT.
6. **Смотрите консоль и журнал сервера.** Исходный текст ошибки ценнее любых догадок. Запуск и ошибки BDS печатаются в консоли.
7. **Проверьте права и белый список.** Игрока выкинуло или он вообще не подключился? При выкидывании причина обычно видна в консоли.
8. **Проверьте целостность мира и аддонов.** Совпадает ли `level-name` с именем каталога в `worlds/`; размещены ли пакеты в правильных каталогах и зарегистрированы ли.

Команды для шага 2: в Linux `ss -ulnp | grep 19132` (`-u` — только UDP); в Windows `netstat -ano | findstr 19132` (`-a` — все соединения и прослушивания, `-n` — без разрешения имён, `-o` — показывать номер процесса); в PowerShell нагляднее `Get-NetUDPEndpoint -LocalPort 19132`.

```bash
ss -ulnp | grep 19132
```

```bat
netstat -ano | findstr 19132
```

**Таблица соответствия явлений:**

| Явление | Что проверить сначала | Частая причина |
| --- | --- | --- |
| Процесса нет | Исходный текст ошибки в консоли | Нет библиотек, неверная версия Java / PHP, порт занят, ошибка в конфигурации |
| Процесс есть, порт не слушается | Есть ли в журнале запуска сбой bind | Порт занят, `enable-lan-visibility` занимает 19132/19133 |
| Порт слушается, с самой машины подключается, снаружи нет | Доступность из интернета | Группа безопасности / брандмауэр не пропускает UDP, CGNAT, двойной NAT |
| Проверка портов прошла, но игроки не заходят | Инструмент проверял TCP или UDP | Разрешён только TCP |
| Сообщение об устаревшей версии сервера | Версии клиента и сервера | Несовпадение протокола; сборка стороннего ядра слишком старая |
| Заходят, но сразу выкидывает | Есть ли в консоли причина кика | Белый список, права, лимит игроков |
| Заходят, но очень лагает | Загрузка одного ядра, `tick-distance`, число сущностей | Узкое место одного ядра, слишком большая карта |
| Сохранения «исчезли» | `level-name` и имена каталогов в `worlds/` | Ошибка в `level-name`, сервер создал новый мир |
| Аддоны не действуют | Тип пакета и каталог размещения | Неверный каталог, не записан world_*_packs.json |

## 6. Что предоставить при обращении за помощью

Дайте всё ниже сразу — это сэкономит несколько раундов переписки:

| Что предоставить | Зачем нужно |
| --- | --- |
| **Ядро сервера и версия сборки** | Номер версии BDS либо имя и номер сборки ядра Nukkit / PMMP. Пути разбора у разных ядер разные |
| **Версия игры / версия протокола** | Какая версия у клиента и какая у сервера — первый пункт разбора в Bedrock |
| **ОС и архитектура** | Windows или Linux, дистрибутив и версия, 64-битность, x86-64 |
| **Полный исходный текст ошибки из консоли** | **Не пересказывайте и не присылайте половину**. Ключевые слова в исходном тексте прямо указывают на проблему |
| **Что меняли в последнее время** | Обновили ядро? Поменяли порт? Добавили аддон? Изменили `server.properties`? |
| **Работало ли раньше** | «Никогда не работало» и «вчера всё было хорошо» — два совершенно разных пути разбора |
| **Что уже пробовали** | Чтобы не повторять советы; и видно, какие направления уже исключены |
| **Состояние сети** | Локальная сеть или интернет, есть ли публичный IP, какой туннель, как настроен проброс портов |
:::tip Как давать исходный текст ошибки
Просто скопируйте вывод консоли текстом или приложите файл журнала. **Фотографии, скриншоты и только последняя строка** замедляют разбор. Если вывод длинный, сохраните несколько строк до и после ошибки, а не одну фразу.
:::
