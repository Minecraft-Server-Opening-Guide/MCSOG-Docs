Официальный **BDS** — самый надёжный вариант для Bedrock, но **сам по себе он не поддерживает плагины**. Эта статья объясняет его структуру каталогов и то, как добавить возможности плагинов через загрузчики от сообщества.

## 1. Структура каталогов

После распаковки BDS представляет собой «зелёный» каталог — достаточно знать следующие элементы:

| Файл / каталог | Назначение | Можно ли трогать |
| --- | --- | --- |
| `bedrock_server.exe` | **Исполняемый файл сервера** (в Linux без `.exe`) | Переименовать можно, но **не рекомендуется** — после переименования придётся синхронно править путь запуска в скриптах и панелях, легко ошибиться |
| `server.properties` | Конфигурация сервера (порт, сложность, режим и т. п.) | Меняют часто |
| `allowlist.json` | Список **белого списка** (управляется здесь после включения белого списка в `server.properties`) | Можно менять |
| `permissions.json` | Данные **администраторов (OP)** (UUID, имя, права) | Можно менять |
| `valid_known_packs.json` | Список известных дополнительных паков (паки поведения / паки ресурсов), по нему сервер выполняет проверку | Обычно трогать не нужно |
| `worlds/` | **Сохранения миров** (по подкаталогу на мир) | Только целиком в резервную копию |
| `bedrock_server.pdb` | Файл базы данных программы для отладки | Не трогать |
| `bedrock_server_how_to.html` | Официальная инструкция | Можно читать |
| `release-notes.txt` | Список изменений версий | Можно читать |

### Что лежит в каталоге мира

В `worlds/<имя мира>/`:

| Файл / каталог | Содержимое |
| --- | --- |
| `db/` | **Данные сохранения** (файлы базы данных мира, самый большой объём) |
| `level.dat` | Основные настройки и свойства мира (игровые правила, время, погода и т. п.) |
| `level.dat_old` | Настройки сохранения предыдущей версии (используются при обновлении или резервном копировании) |
| `level_name.txt` | Название мира |

:::warn Для резервной копии берите `worlds/`
Все сохранения BDS находятся в `worlds/` — **копируйте каталог целиком**. Не копируйте только `db/`, иначе настройки потеряются.
:::

## 2. Плагины для BDS: три основных загрузчика

В официальном BDS нет системы плагинов, поэтому сообщество сделало загрузчики. Сейчас основных три:

### LeviLamina (также LLL / LLv3) — **рекомендуется больше всего**

- Автор: LiteLDev (предшественник — **LiteLoaderBDS**)
- Позиционирование: лёгкий, модульный, многофункциональный загрузчик плагинов для BDS
- **Степень рекомендации: очень рекомендуется** — лучшая экосистема плагинов, продолжение пика эпохи LiteLoader
- Поддерживаемые версии: 1.20.61 – 1.21.3 (обновляется)

### EndStone — есть потенциал

- Автор: EndStoneMC
- Позиционирование: даёт **дружелюбный API в духе Bukkit**, плагины можно писать на **C++ или Python**
- **Степень рекомендации: скорее рекомендуется** — сейчас экосистема плагинов очень мала, но в сообществе есть голоса за развитие, в дальнейшем возможен паритет с LeviLamina
- Поддерживаемые версии: 1.20.71 – 1.21.2 (обновляется)

### BDSX — старый и стабильный

- Позиционирование: модификация BDS с поддержкой **Node.js**, основана на официальном BDS, сохраняет все ванильные возможности и поддерживает хуки функций и сетевые пакеты
- **Степень рекомендации: довольно рекомендуется** — плагинов не так много, зато пользователей немало, автор поддерживает проект с 2019 года
- Поддерживаемые версии: 1.12 – последняя (обновляется)

> Кроме этих трёх официальный продукт предлагает **скриптовый загрузчик** (на основе официального скриптового API): возможностей меньше, чем у сторонних загрузчиков, зато он официально поддерживается.

### Как выбрать

| Ваша ситуация | Рекомендация |
| --- | --- |
| Нужны готовые плагины, приоритет — экосистема | **LeviLamina** |
| Знаете C++ / Python, хотите писать сами | **EndStone** |
| Знакомы с Node.js / нужны хуки нижнего уровня | **BDSX** |
| Нужны только официальные возможности, без сторонних решений | Официальный скриптовый загрузчик |

:::warn Загрузчик жёстко привязан к версии игры
Загрузчик поддерживает только **определённый диапазон версий**. **Сначала убедитесь, что версия вашего сервера есть в списке поддерживаемых**, и только потом устанавливайте, иначе загрузка не удастся или сервер вообще не запустится. Перед обновлением версии игры тоже сначала проверьте, обновился ли загрузчик.
:::

## 3. Две известные проблемы BDS

1. **Узкое место одного ядра**: обсчёт сущностей однопоточный → плавность зависит от **производительности одного ядра**, и чем больше карта, тем сильнее лаги.
2. **Медленный рост памяти**: потребление постепенно растёт. Учтите: **не стоит принудительно освобождать память** — это приводит к зависанию полосы загрузки у игроков, скачивающих паки ресурсов/аддоны, и **помогает только перезапуск сервера**.
