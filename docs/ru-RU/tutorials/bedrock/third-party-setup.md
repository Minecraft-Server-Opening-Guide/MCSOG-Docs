Статья [Сторонние ядра (Nukkit / PNX / PMMP)](/tutorials/bedrock/third-party) отвечает на вопрос «что выбрать». Эта статья о том, «как заставить это работать после выбора»: что подготовить, как выглядит каталог, как написать скрипт запуска, куда класть плагины — и о самом частом провале: **сборка ядра не совпадает по версии с протоколом Bedrock**.

## 1. Перед началом: подтвердите три вещи

| Что подтвердить | Описание |
| --- | --- |
| **Семейство ядра** | Семейство Nukkit — программа на **Java**, PocketMine-MP — на **PHP**. Ошибётесь с семейством — всю среду выполнения придётся переделывать |
| **Среда выполнения** | Для семейства Nukkit ставьте **Java**, для PMMP — **PHP**. Одно другое не заменяет |
| **Согласование версий** | Сборка ядра должна **соответствовать версии протокола Bedrock, к которому вы подключаетесь**, иначе клиент просто не подключится |

### Среда Java (семейство Nukkit)

Семейство Nukkit, как и серверы Java Edition, — программа на Java, ставить её можно по той же логике, что и для Java Edition, см. [Подготовка среды (Windows и Linux)](/tutorials/java/environment).

Два важных момента:

- **Версия должна быть достаточной**: новые ветки обычно требуют более свежую Java (часто Java 17 и выше); слишком старая версия сразу приведёт к сбою запуска, и в тексте ошибки обычно прямо указано требование.
- **Разрядность должна совпадать**: 64-битной системе — 64-битная Java. 32-битная версия упадёт при запуске или в процессе работы из-за предела памяти.

### Среда PHP (PocketMine-MP)

PMMP нужен **PHP**, а не Java.

:::tip Берите PHP из сборки PMMP, не собирайте окружение сами
На сайте PHP предлагается **чистая версия**, в которой по умолчанию нет нужных PMMP расширений; дописывать зависимости по одной очень утомительно, а при нескольких версиях легко запутаться. **Рекомендуется сразу скачать официальную сборку среды PHP для разных систем** (в её GitHub Releases возьмите файл под вашу ОС) — распаковали и работаете.
:::

:::warn Не используйте PHP из системы
В репозиториях дистрибутивов Linux версия PHP часто устаревшая, а на Windows может стоять PHP, оставшийся от других программ. Сначала проверьте вывод `php -v` и убедитесь, что при запуске сервера вы используете **именно ту версию, которую планировали**.
:::

## 2. Структура каталогов: семейство Nukkit vs PocketMine-MP

### Семейство Nukkit

После первого запуска корневой каталог выглядит примерно так (в разных ветках есть небольшие отличия):

| Файл / каталог | Назначение |
| --- | --- |
| Что-то вроде `nukkit-1.0-SNAPSHOT.jar` | **Сам исполняемый файл ядра**, запускается именно он |
| `start.bat` / `start.sh` / `start.command` | Скрипты запуска для Windows / Linux / macOS соответственно |
| `server.properties` | Основной файл конфигурации: имя сервера, порт, максимум игроков, игровой режим и т. п. |
| `permissions.yml` | Определение прав |
| `ops.txt` | Список администраторов (OP) |
| `whitelist.txt` | Список белого списка (действует после включения белого списка в `server.properties`) |
| `banned-players.txt` / `banned-ips.txt` | Заблокированные игроки и IP |
| `rcon_password.txt` | Пароль удалённого управления RCON |
| `worlds/` | **Общий каталог сохранений миров**, по подкаталогу на мир |
| `plugins/` | **Каталог плагинов**, сюда кладут `.jar` |
| `logs/` | Журналы работы |

Внутри каталога мира `worlds/<имя мира>/`:

| Файл / каталог | Содержимое |
| --- | --- |
| `level.dat` | Основные настройки мира |
| `region/` | **Данные чанков** (рельеф, постройки, самый большой объём) |
| `entities/` | Данные сущностей |

:::warn Для резервной копии берите `worlds/`
Как и в BDS, сохранения Bedrock — это **единое целое**. При резервном копировании копируйте весь `worlds/` целиком, не выбирайте только `region/`.
:::

### PocketMine-MP

Логика каталогов PMMP похожа, но форма файлов другая:

| Файл / каталог | Назначение |
| --- | --- |
| `PocketMine-MP.phar` | **Сам исполняемый файл ядра** (`.phar` — формат упаковки PHP) |
| Среда выполнения PHP | Лаунчер и исполняемый файл `php`; при официальной сборке лежат в том же каталоге |
| `start.bat` / `start.sh` | Скрипты запуска |
| `server.properties` | Основной файл конфигурации |
| `pocketmine.yml` | Собственная конфигурация PMMP |
| `plugins/` | **Каталог плагинов**, сюда кладут `.phar` |
| `worlds/` | Общий каталог сохранений миров |
| `players/` | Данные игроков |
| `logs/` | Журналы работы |

### Сравнение двух семейств

| | Семейство Nukkit | PocketMine-MP |
| --- | --- | --- |
| Файл ядра | `.jar` | `.phar` |
| Среда выполнения | Java | PHP |
| Расширение плагинов | `.jar` | `.phar` |
| Каталог плагинов | `plugins/` | `plugins/` |
| Каталог миров | `worlds/` | `worlds/` |
| Основная конфигурация | `server.properties` | `server.properties` |
| Список администраторов | `ops.txt` | Управляется конфигурацией ядра и командами |
| Внутренняя структура мира | `level.dat` + `region/` + `entities/` | `level.dat` + `region/` + `entities/` |

:::note Общая ловушка: в пути не должно быть кириллицы и пробелов
Каким бы ни было ядро, каталог сервера лучше размещать по пути **только из латинских символов, без пробелов**. Кириллица в пути на части веток и панелей приводит к невозможности прочитать мир или плагины, а ошибки при этом обычно малопонятные.
:::

## 3. Запуск сервера

### Семейство Nukkit

Минимально рабочая команда запуска — одна строка `java -jar`:

```bat
@echo off
java -Xms1G -Xmx4G -jar nukkit-1.0-SNAPSHOT.jar
pause
```

Эквивалентный вариант для Linux / macOS:

```sh
#!/bin/sh
java -Xms1G -Xmx4G -jar nukkit-1.0-SNAPSHOT.jar
```

Пояснения:

- `-Xms` — начальный размер кучи, `-Xmx` — максимальный; **оба лучше задать одинаковыми**, чтобы во время работы не происходило повторного расширения.
- `-Xmx` не должен превышать физическую память машины, иначе система начнёт использовать раздел подкачки и станет только хуже.
- В Windows добавьте `pause` в конец `.bat`, чтобы после падения окно не закрылось сразу и вы успели увидеть ошибку.

### PocketMine-MP

```bat
@echo off
php PocketMine-MP.phar
pause
```

Для Linux / macOS:

```sh
#!/bin/sh
./bin/php7/bin/php PocketMine-MP.phar
```

Пояснения:

- Конкретный путь зависит от того, используете ли вы официально собранный PHP или собственную установку. **Сначала убедитесь через `php -v`, что нужный интерпретатор вызывается**, и только потом прописывайте его в скрипт.
- Предел памяти задаётся не параметрами командной строки, а в `pocketmine.yml` и `server.properties`.

:::tip На что смотреть при первом запуске
При первом запуске создаются файлы конфигурации и мир. После старта обратите внимание на две вещи: **нет ли ошибок в консоли** и **появились ли в каталоге `plugins/` и `worlds/`**. Если каталоги не создались, значит ядро не запустилось — не спешите ставить плагины.
:::

:::warn Не отдавайте всю память сразу
Пока на новом сервере никого нет, задайте `-Xmx` поменьше (например, 2G) и увеличивайте, когда придут игроки. Если сразу отдать предел физической памяти, система и ядро начнут бороться за память.
:::

## 4. Куда класть плагины и как их загружать

1. Скачайте с страницы релиза плагина файл нужной версии: для семейства Nukkit — `.jar`, для PMMP — `.phar`.
2. Положите его в `plugins/` в корне сервера.
3. **Перезапустите сервер**.
4. Посмотрите вывод консоли и убедитесь, что плагин загрузился и ошибок нет.
5. Некоторые плагины после первой загрузки создают собственный каталог конфигурации `plugins/<plugin-name>/`; измените конфигурацию и перезапустите ещё раз.

О перезагрузке:

- Большинство плагинов поддерживают команду перезагрузки, но **перезагрузка — это не перезапуск**. Если вы изменили конфигурацию ядра, сменили версию плагина или плагины регистрируют события друг у друга, перезагрузка часто оставляет старое состояние: получается «изменил, а не работает» или прямая ошибка.
- Вывод: **конфигурацию можно перезагружать, а установку/удаление/замену плагинов — только перезапуском**.

:::warn Не подсовывайте плагины для Java Edition
`.jar` семейства Nukkit и `.jar` Java Edition (Paper / Spigot) — две совершенно разные вещи, **они не взаимозаменяемы**. При скачивании с сайта плагинов сначала проверьте, указано ли Nukkit / PNX или Paper; при ошибке ядро обычно выдаёт лишь «недопустимый файл плагина».
:::

## 5. Самый частый провал: согласование версий

Здесь Bedrock гораздо строже Java Edition, поэтому разберём отдельно.

Клиент Bedrock **обновляется автоматически**, и игрок не может, как в Java Edition, остаться на старой версии. Поэтому:

- Ваша сборка ядра должна **поддерживать текущую версию протокола Bedrock**, иначе игрок увидит сообщение вроде «слишком старый сервер» и просто не подключится.
- Даже если версия ядра верна, плагины тоже должны соответствовать: плагины идут за API ядра, и **после обновления ядра старые плагины могут сразу перестать работать**.
- Поэтому обновление стороннего ядра — **комплексное**: ядро + плагины + конфигурация меняются вместе, нельзя заменить только одно.

Порядок поиска причины, если не подключается:

| Симптом | Что проверить первым |
| --- | --- |
| Сообщение о слишком старой версии сервера | Поддерживает ли сборка ядра текущий протокол Bedrock |
| Клиент зависает на «Подключение» | Открыт ли порт, совпадает ли порт в `server.properties` с пробросом |
| Войти можно, но плагины не реагируют | Загрузились ли плагины, совпадает ли версия с ядром |
| Сразу после входа выбрасывает | Включён ли белый список, нет ли записи в `banned-*` |

:::tip Перед обновлением сделайте резервную копию
**Совместимость сохранений у сторонних ядер хуже, чем у официального BDS**. Перед сменой ядра или обновлением мажорной версии скопируйте весь `worlds/` и конфигурацию из `plugins/`, см. [Резервное копирование и восстановление](/tutorials/java/backup).
:::

## 6. Чек-лист начала работы

- [ ] Среда выполнения установлена и вызывается из командной строки (`java -version` / `php -v`)
- [ ] Сборка ядра соответствует целевой версии протокола Bedrock
- [ ] Путь к каталогу состоит только из латинских символов, без пробелов
- [ ] Параметры памяти в скрипте запуска разумны
- [ ] При первом запуске созданы `plugins/` и `worlds/`, в консоли нет ошибок
- [ ] Расширение плагинов соответствует семейству ядра
- [ ] `worlds/` включён в план резервного копирования
