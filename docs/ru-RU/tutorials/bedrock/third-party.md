Официальный BDS стабилен, но плохо расширяется. Нужны плагины, многоядерность, кастомизация — значит, нужно стороннее ядро. Эта статья объясняет **путь к работе** с тремя основными сторонними ядрами.

## 1. Семейство Nukkit

Nukkit — это «Bukkit для Bedrock»: **написан на Java**, имеет родную систему плагинов, прост в настройке. От него пошло множество веток, и на практике **выбирайте активную ветку**:

| Ветка | Описание |
| --- | --- |
| **Nukkit (оригинал)** | Самый ранний upstream, уже неактивен, для новых проектов не рекомендуется |
| **PowerNukkitX (PNX)** | Современная основная ветка, **поддерживает новейший протокол + многоядерную оптимизацию**, первый выбор |
| **NukkitX** | Историческая ветка |
| **NukkitMot** | Историческая ветка |
| **PM1E** | Историческая ветка, связанная с PocketMine (в сообществе спорят о её истории) |
| **PNX** | Сокращение от PowerNukkitX |

**Подготовка**: семейство Nukkit — это Java-программа, **нужна установленная Java** (как и для Java Edition, см. раздел про Java в «Подготовке окружения (Windows и Linux)»).

**Начало работы**: скачайте jar ядра → положите в каталог → напишите скрипт запуска (`java -jar <core-name>.jar`) → при первом запуске сгенерируются файлы конфигурации → ставьте плагины в `plugins/`.

### Почему стоит выбрать PowerNukkitX

- **Многоядерная оптимизация** — главное преимущество перед BDS, где вычисления в основном упираются в одно ядро;
- **Поддержка новейшего протокола Bedrock**, не нужно долго ждать;
- **Высота мира 384 блока**, встроенный генератор рельефа **Terra**;
- **Полностью открытый исходный код, открытый API**, плагины можно писать на Java / Kotlin / Scala / Python / JavaScript / Lua;
- **Совместимость с массой плагинов экосистемы Nukkit**.

Цена: много плагинов и параметров конфигурации, **у новичков кривая обучения довольно крутая**; темп разработки зависит от изменений в команде upstream.

## 2. PocketMine-MP (PMMP)

Сервер Bedrock, написанный на **PHP**, с **самой большой экосистемой плагинов**.

**Подготовка**: нужна **среда выполнения PHP** (не Java). Устанавливайте подходящую версию PHP по официальной документации и настройте нужные расширения.

**Начало работы**: скачайте PMMP (обычно файл `.phar`) → запустите через PHP (`php PocketMine-MP.phar`) → сгенерируются конфигурация и каталоги → плагины кладите в `plugins/`.

**Плюсы**: очень много плагинов, кроссплатформенность, **плагины можно писать, если знаете PHP**, активное сообщество, высокая степень кастомизации.

**Минусы**: **узкое место по производительности под высокой нагрузкой** (управление памятью и эффективность CPU); обновления запаздывают; при большом числе плагинов стабильность падает; PHP как интерпретируемый язык **заметнее расходует ресурсы**.

:::tip Выбрать семейство Nukkit или PMMP?
- Вы **знакомы с Java** и хотите **лучшую производительность** → **PowerNukkitX**
- Вы **знакомы с PHP** и хотите **максимум готовых плагинов** → **PocketMine-MP**
- Не знакомы ни с тем, ни с другим → сначала поднимите **BDS**, а потом думайте о сторонних решениях
:::

## 3. Другие серверы

Кроме перечисленных, в сообществе есть несколько нишевых ядер под конкретные задачи:

| Ядро | Позиционирование |
| --- | --- |
| **Allay** | Сервер Bedrock, разработанный сообществом |
| **Dragonfly** | Сервер Bedrock на языке Go, ориентирован на производительность |
| **MCPEServer** | Ранний сервер Bedrock |
| **WaterDogPE** | **Прокси** (аналог Velocity / BungeeCord в Java Edition) для связи нескольких дочерних серверов |

> У нишевых ядер **экосистема плагинов и документация обычно очень скудные**, и с проблемами труднее найти помощь. Без явной причины **новичкам их выбирать не стоит**.

### WaterDogPE: нужен только при нескольких дочерних серверах

Как и в Java Edition, в Bedrock есть **прокси**: сам он не держит мир, а только переправляет игроков на дочерние серверы. Подходит для структуры «лобби + выживач + мини-игры». **Для одного сервера он не нужен** — лишний слой это лишняя точка отказа.

## 4. Общие рекомендации

1. **Согласование версий**: версии ядра, протокола и плагинов должны совпадать — в Bedrock это гораздо строже, чем в Java Edition.
2. **Сначала малое, потом большое**: сначала поднимите минимально рабочий сервер, потом постепенно добавляйте плагины.
3. **Смотрите на активность**: предпочитайте ядра и плагины, которые **обновлялись недавно**; те, что давно не обновлялись, на новой версии обязательно упадут.
4. **Резервная копия прежде всего**: совместимость сохранений у сторонних ядер хуже, чем у официального, поэтому **перед обновлением или сменой ядра обязательно сделайте резервную копию** (см. «Резервное копирование и восстановление»).
