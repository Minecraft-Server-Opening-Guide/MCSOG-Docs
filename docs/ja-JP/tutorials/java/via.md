プレイヤーが入れず、「バージョンが合いません」あるいは「クライアントが古すぎます」と表示されるのは、サーバー構築時によくある相談の 1 つです。原因は単純です：サーバーとクライアントは同じプロトコルの異なるバージョンで話しており、かみ合いません。バージョン間互換プラグインがやることは、その間で通訳を務めることです。

本記事では Via シリーズがそれぞれどの方向を担当し、どこに入れ、どれがどれに依存し、そしてできないことは何かを整理します。前提知識は [プラグイン入門](/tutorials/java/plugins) を参照。

## 1. なぜプレイヤーが入れないのか

Minecraft の Java 版のクライアントとサーバーは、1 つのバイナリプロトコルで通信します。ゲームのバージョンごとにこのプロトコルが変更されます：新しいパケットの追加、フィールド順の変更、数値の意味の変更などです。プロトコルのバージョンが合わないとハンドシェイクの段階で失敗し、プレイヤーには通常バージョン不一致のメッセージが表示されます。

サーバーは自分自身のバージョン（および少数の互換バージョン）のクライアントしか受け付けません。したがって：

- サーバーが 1.20.4 で、プレイヤーが 1.21 のクライアント：入れない。
- サーバーが 1.21 で、プレイヤーが 1.8 のクライアント：同じく入れない。

バージョン間互換プラグインの動き方は、サーバー側でプレイヤーのパケットを受け取り、サーバーが理解できる形に翻訳し、サーバーの応答をプレイヤーのプロトコルバージョンに翻訳して返す、というものです。**プレイヤーのクライアントには何も入れる必要がありません。**

:::warn バージョン間互換は万能ではない
翻訳するのはプロトコルであり、遊びの中身ではありません。バージョンの隔たりが大きいほど一致できるものが減り、体験の低下がはっきり現れます。詳細は第 5 節。
:::

## 2. Via 三種の役割

Via シリーズは 1 つのファミリーで、3 つのプラグインがそれぞれ別の方向を担当します。方向の覚え方：**「上向き」はより新しいクライアントを入れ、「下向き」はより古いクライアントを入れる。**

| プラグイン | 方向 | 役割 | 依存 |
| --- | --- | --- | --- |
| **ViaVersion** | 上方向の互換 | サーバーより新しいクライアントを入れる | なし。中核 |
| **ViaBackwards** | 下方向の互換 | サーバーより古いクライアントを入れる | ViaVersion が必要 |
| **ViaRewind** | さらに古いバージョンへの下方向互換 | 1.7.x と 1.8.x のクライアントをサポート | ViaVersion が必要。通常は ViaBackwards と一緒に入れる |

対応範囲の例：

- サーバー 1.9.x で ViaVersion のみ：1.9.x から最新版までのクライアントを許可。
- サーバー 1.21.x で ViaVersion + ViaBackwards：1.9.x から 1.20.x までのクライアントを許可。
- さらに ViaRewind を追加：1.7.x と 1.8.x までカバー。

3 つを重ねると、プラグイン版の Via はおおよそ 1.7 から最新版までをカバーします。

### ダウンロード元

| プラグイン | 配布ページ |
| --- | --- |
| ViaVersion | SpigotMC リソース 19254、Hangar、Modrinth、GitHub |
| ViaBackwards | SpigotMC リソース 27448、Hangar、Modrinth、GitHub |
| ViaRewind | SpigotMC リソース 52109、Hangar、Modrinth、GitHub |

公式のビルドサイトは `ci.viaversion.com` で、最新のビルドが必要なときはここから取得します。

:::note Java 8 のサポート
新しいバージョンの Via シリーズは Java 8 のサポートを終了しているため、非常に古いサーバーではそのまま使えません。1.8 から 1.21 までのサーバーで使いたい場合は、ビルドサイトから Java 8 専用のブランチのビルドを取得する必要があります。
:::

:::tip バージョンを揃える
ViaVersion と ViaBackwards を同時に入れるときは、できるだけ同じ時期のバージョンを選んでください。プロキシを更新したあとも、Via シリーズをまとめて最新に上げるのを忘れないでください。そうしないと「バージョン間互換を入れたのにバージョン非対応と言われる」ことが起きます。プロキシを使わない場合でも、少なくとも月 1 回は更新することをおすすめします。
:::

## 3. どこに入れるか：サーバーかプロキシか

Via シリーズは BungeeCord、Velocity、各種の Minecraft サーバーに導入できますが、入れる場所によって効果と落とし穴が変わります。

| 導入場所 | 利点 | 代償 |
| --- | --- | --- |
| バックエンドのサーバー | バックエンドはプレイヤーの**実際のクライアントバージョン**を受け取るので、チート対策やパケット系のプラグインが正常に動く | バックエンドごとに 1 セット入れる必要があり、設定も個別に維持する |
| プロキシ | 1 回入れるだけでよく、プレイヤーはどのバックエンドに入る前にも翻訳が済む | バックエンドのサーバーが見るプレイヤーのバージョンは**プロキシのバージョン**で、プレイヤーのクライアントの実際のバージョンではない |

チート対策や BOT 対策のようにパケットを大量に処理するプラグインを使っている場合、Via をプロキシに入れると互換性の問題を起こしやすいので注意が必要です。逆にバックエンドが 1 つだけの場合や、プレイヤーがサーバーを選ぶ前に翻訳を済ませたい場合は、プロキシに入れるほうが手間が少なくて済みます。

:::warn バージョン間互換と MOD 系
バージョン間互換の手法は MOD サーバーには向きません。MOD はプロトコルとレジストリの中身を変更し、バージョン間互換プラグインはそうした独自部分を翻訳できません。混ぜて使うと多くの問題が起きます。
:::

## 4. 導入順序と相互関係

3 つのプラグインの関係は段階的な依存です：

1. **まず ViaVersion を入れる**。中核であり、これ単体で上方向の互換性が得られます。
2. **下方向の互換が必要なら ViaBackwards を追加**。新しいバージョンのプロトコルを古いバージョンが理解できる形に戻します。
3. **1.7 と 1.8 のサポートが必要なら ViaRewind を追加**。完全な互換性を発揮するには ViaRewind Legacy Support と組み合わせる必要があります。

読み込み順は、ViaVersion を先に、ViaBackwards と ViaRewind を後にすればよく、通常はサーバーが依存関係に従って自動で処理するため手動で介入する必要はありません。入れたらサーバーを再起動し、コンソールで 3 つとも読み込みに成功したことを確認します。

## 5. できること、できないこと

ここが最も誤解を生む部分です：**Via はプロトコルを翻訳するのであって、コンテンツを追加するのではありません。**

| プレイヤーが遭遇する現象 | 原因 |
| --- | --- |
| 新しいバージョンのクライアントで古いサーバーに入り、新しいバージョンのアイテムの機能が使えない | サーバーにそのアイテムのロジックがそもそもなく、材質の近い古いバージョンのアイテムで代替表示するしかない |
| 古いバージョンのクライアントで新しいバージョンのアイテムの材質が見えない | クライアントに対応するモデルとテクスチャのリソースがない。公式プラグインは対応しない。1.16 以上には回避手段があるが公式の機能ではない |
| 1.17 未満のクライアントで y=0 未満のブロックが見えない | 古いクライアントのプロトコルと描画が負の高さに対応していない。公式に修正しないと明言されている |
| 入ったあとの挙動がおかしい：押し戻される、動作が同期しない、UI がずれる | バージョンの隔たりが大きすぎて、双方で一致できる概念が少なすぎる |
| 送信パケットが多すぎると言われてキックされる | 両側の pps 制限に触れている。下記参照 |

隔たりが大きいほど体験の低下もはっきりします。古いバージョンのプレイヤーにも十分な体験を提供できる見込みがない限り、「全バージョン対応」を盲目的に目指さないでください。

### よくある設定項目

| 設定項目 | 用途 |
| --- | --- |
| `serverside-blockconnections` | ブロックの材質や接続テクスチャの表示がおかしいとき、`true` にして試す |
| `max-pps` | パケット送信が多すぎてキックされるときに調整。Paper 分岐なら `-1` にして、Paper 自身の pps 制限を別に調整する |
| `fix-1_13-face-player` | 1.12 のプレイヤー向けに 1.13 のスキンパケットを変換する。追加のキャッシュが必要 |
| `handle-pings-as-inv-acknowledgements` | 1.17 未満のクライアントにインベントリ確認パケットを ping の代わりに送る。チート対策との互換性に役立つ |
| `replace-adventure` | ViaRewind のオプション。1.9 のパーティクルを 1.8 以下の近似パーティクルに置き換えるかを制御する |

:::warn pps 制限をそのまま無効にしない
パケット制限を高くするのは正常なプレイヤーが誤ってキックされないようにするためですが、完全に無効にすると悪意あるプレイヤーがパケット攻撃でサーバーを落とす隙を与えます。「正常なプレイヤーが触れない」水準までにしてください。
:::

## 6. 単体版：ViaProxy

サーバーコアすら変更しにくい場合には、単体の方案もあります：**ViaProxy**。独立したプロキシプログラムで、任意のクライアントバージョンから任意のサーバーバージョンへ接続でき、サーバー側にプラグインを入れる必要はありません。

対応範囲はプラグイン版よりはるかに広く、遠い昔の Alpha、Beta、Classic バージョン、エイプリルフールのスナップショット、戦闘テストのスナップショットを含み、Geyser 経由で統合版のプレイヤーを接続させることもできます。ダウンロードは ViaVersion の GitHub Releases と公式ビルドサイトにあります。

:::note いつ使うか
現代のクライアントを 10 年前の古いサーバーに入れたいとき、あるいは特定のバージョンの互換性を一時的に検証したいとき、ViaProxy はサーバーを改造するよりはるかに手間が少なくて済みます。ただし独立したプロセスであり、転送の層が 1 つ増えるということは、保守とトラブル対応の箇所も 1 つ増えるということです。
:::

## 7. トラブル対応の早見表

| 現象 | まず確認すること |
| --- | --- |
| 入れたのにバージョン非対応と表示される | Via シリーズが最新か；プロキシを更新したときに Via も同期して更新したか |
| 一部のプレイヤーだけ入れない | そのプレイヤーのクライアントバージョンが現在のプラグインの対応範囲を超えていないか |
| 材質やテクスチャの表示がおかしい | `serverside-blockconnections`；古いバージョンで新しい材質が見えないのは想定内の挙動 |
| プレイヤーがキックされ、パケットが多いと言われる | `max-pps` と Paper の pps 制限 |
| チート対策が誤検知する、挙動がおかしい | Via がプロキシに入っていないか；バックエンドが受け取るのはプレイヤーの実際のバージョンではなくプロキシのバージョン |
| 古いバージョンのプレイヤーが y=0 未満で激しく押し戻される | 既知の制限。修正されない |
