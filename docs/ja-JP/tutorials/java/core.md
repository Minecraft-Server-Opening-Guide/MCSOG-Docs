環境の準備ができたら、次に決めるのは**どのサーバーコアを使うか**です。コアは 3 つのことを決めます：**性能の上限**、**プラグインや MOD を入れられるか**、そして**レッドストーンなどのバニラ挙動が一致するか**です。

間違えても起動はできますが、お金を無駄にする（マルチコア CPU でシングルスレッドのコアを動かす）か、労力を無駄にする（レッドストーン技術で Paper を使う）ことになります。

## 1. まず 3 種類のコアを切り分ける

| 種類 | 代表 | プラグイン | MOD | 説明 |
| --- | --- | --- | --- | --- |
| **バニラ** | Vanilla | 不可 | 不可 | 公式サーバー。挙動が最も標準的だが、最適化は一切ない |
| **プラグイン系** | Spigot → Paper → Purpur / Leaves / Leaf / Folia | 可 | 不可 | Bukkit 系の一本道で、エコシステムが最大 |
| **MOD 系** | Fabric / Forge / NeoForge | ブリッジが必要 | 可 | MOD を読み込む。MOD パック向け |

> もう 1 つ**プロキシ**（Velocity / BungeeCord）があります。自分ではワールドを動かさず、プレイヤーを複数のサブサーバーへ転送するだけで、「複数サーバーの相互接続」が必要なときに使います。

この 3 種類のうち、レッドストーン技術のサーバーが選ぶのは**MOD 系（Fabric）**の道です。レッドストーン技術のサーバーを立てる前に、この一連のチュートリアルに一度目を通しておく価値があります：

- [\[レッドストーン技術編\]Carpet とそのアドオン](/tutorials/java/sd-carpet)：ルールシステム、4 つの主要アドオン、クラッシュ防止ルール。
- [\[レッドストーン技術編\]共有スケマティック](/tutorials/java/sd-schematic)：Syncmatica で投影と設置を全員に同期する。
- [\[レッドストーン技術編\]最適化 MOD](/tutorials/java/sd-optimize)：安心して入れられるもの、タイミングを変えてしまうもの。
- [\[レッドストーン技術編\]セーブデータの保護](/tutorials/java/sd-backup)：バックアップ手順、Ledger、遠隔地バックアップ。

## 2. ハードウェアで選ぶ：ここが最も間違えやすい

**Minecraft のメインスレッドはシングルスレッドです。** エンティティ、チャンク、レッドストーン、プラグインのロジックはほぼ**1 つのコア**に集中します。つまりコア数が多い＝速い、ではなく、**シングルコアのクロックが鍵**です。

| あなたのマシン | おすすめ | 理由 |
| --- | --- | --- |
| **シングルコア性能が高い**（4〜8 コア、3.5GHz 以上） | **Paper / Purpur / Leaf** | これらのコアはシングルスレッドでできる最適化を出し切っており、シングルコアが強いほど効果が大きい |
| **コアは多いがクロックが低い**（16 コア以上、2.5GHz 未満） | **Folia** | シングルコアが弱点で、Paper ではコアの大半を無駄にする。Folia ならマルチコアを使い切れる |
| 迷う、手間をかけたくない | **Paper** | 最も安定し、情報が最も多く、プラグイン互換性も最良 |

### マルチコア向けの Folia とは

Folia は Paper 公式のフォークで、サーバーに**リージョン単位のマルチスレッド（regionised multithreading）**を導入します。ワールドを複数のリージョンに分割し、各リージョンが**並列**に tick を実行するため、マルチコアを本当に活用できます。

代償もはっきりしています：

- **プラグイン互換性が低い**：多くのプラグインが Folia に未対応で、入れるとそのままエラーになったり挙動がおかしくなったりします。
- **Paper と挙動が異なる**：リージョンをまたぐやり取り（レッドストーン、テレポート、エンティティのリージョン移動）のルールが違います。
- **プレイヤーが分散していて、マシンのシングルコアが弱くコア数が多い**場面に向き、レッドストーン技術には向きません。

### シングルコアが強ければ Paper 系

Paper とその下流（Purpur、Leaf、Leaves）はすべて**シングルスレッド最適化**の路線です。メインスレッドの最適化が行き届いており、シングルコアのクロックが高いほど快適になります。

- **Paper**：基準となる選択肢で、エコシステムが最大。
- **Purpur**：Paper + 大量の設定可能なゲームプレイスイッチ。細かく調整したい人向け。
- **Leaf**：Paper のフォークで、**性能・バニラの仕組み・安定性のバランス**を取る（公式の位置づけ）。
- **Leaves**：Paper のフォークだが方向は逆で、**壊されたバニラの特性を専門に修復**します。次の節を参照。

## 3. レッドストーン技術（テクニカル）ではどう選ぶか

レッドストーン技術とは、レッドストーンの装置、モブトラップ、TNT 複製、正確なブロックとエンティティの挙動を指します。**バニラの挙動の一致が必須**なので：

- **Fabric** が該当します —— 最適化 MOD を入れなければバニラに最も近く、レッドストーン技術サーバーの主流の選択です。
- **Leaves** も該当します —— Paper のフォークですが、**Paper に壊されたバニラの特性を専門に修復**する（公式の位置づけ：*repairing broken vanilla properties*）ため、Paper のエコシステムを保ちながらバニラの挙動を取り戻せます。

:::warn レッドストーン技術で Paper / Purpur を使わない
Paper 系は性能のためにバニラの挙動の一部（レッドストーンのタイミング、TNT 複製、スポーンとエンティティのルールなど）を変更しており、**これらの仕組みに依存する装置が動かなくなります**。レッドストーン技術サーバーでは **Fabric** か **Leaves** を使ってください。
:::

## 4. 主要コアの早見表

| コア | 種類 | ひとこと | 向いている用途 |
| --- | --- | --- | --- |
| **Vanilla** | バニラ | 公式サーバー、最適化なし | 純粋な体験、バニラ挙動の検証 |
| **Spigot** | プラグイン系 | Paper の上流、古いプラグインと互換 | 互換性を優先する古いサーバー |
| **Paper** | プラグイン系 | エコシステム最大、最も安定した基準 | ほとんどのサバイバルサーバー、プラグインサーバー |
| **Purpur** | プラグイン系 | Paper + 大量のゲームプレイスイッチ | ゲームプレイを細かく調整したい |
| **Leaf** | プラグイン系 | 性能とバニラの仕組みのバランス | Paper を使いたいがバニラ挙動の変更は少なくしたい |
| **Leaves** | プラグイン系 | バニラ特性の修復 | **レッドストーン技術 + プラグインも使いたい** |
| **Folia** | マルチコア系 | リージョン単位のマルチスレッドでマルチコアを使い切る | **コアが多くクロックが低い**、プラグインの制限を受け入れられる |
| **Fabric** | MOD 系 | 軽量でバニラに近い | **レッドストーン技術**、軽量な MOD 構成 |
| **Forge** | MOD 系 | 老舗で MOD パックが最多 | 大規模な科技系 MOD パック |
| **NeoForge** | MOD 系 | Forge コミュニティのフォーク、新バージョンの主力 | 1.20.2 以降の MOD サーバー |
| **Velocity** | プロキシ | 転送のみでワールドは動かさない | 複数サブサーバーの相互接続、クロスサーバー |

> 表の「性能」に関する記述は相対的な参考です。実際の挙動はバージョン、プラグイン／MOD の数、ハードウェアによって変わります。

## 6. 次のステップ

コアを決めたら、そのコアの公式チャネルから該当バージョンのサーバー jar をダウンロードし、「環境の準備」で作った `survival` ディレクトリに置いて、**起動スクリプトを書いて動かします**：

> **当サイトはこれらのコアのダウンロード入口を収録しています** —— **[リソースダウンロード · サーバーコア](/downloads/core)** を開くと、コア名ごとにすべてのビルドバージョン（Vanilla、Paper、Folia、Velocity、Purpur、Leaf、Leaves、Fabric、NeoForge、Forge、Spigot、BungeeCord および統合版 BDS）が並んでいます。「ダウンロード」ボタンを押し、案内に従ってログインしてください。収録しているのは公式およびコミュニティ由来のダウンロードリンクで、**当サイトはファイルを一切保存していません**。

**→ [サーバーの起動](/tutorials/java/start)** —— 起動スクリプト、EULA への同意、起動成功の判断、自動再起動

- **Paper / Purpur / Leaf / Leaves / Folia**：公式ダウンロードページから jar を取得
- **Fabric / Forge / NeoForge**：対応するローダーのサーバーインストーラーを先に導入（新しい Forge / NeoForge は**起動スクリプトを自動生成**します）
- **バニラ Vanilla**：公式サーバー jar

起動前にもう一度確認してください：**Java のバージョンと対象 MC バージョンが一致しているか**、**25565 が開放されているか**。
