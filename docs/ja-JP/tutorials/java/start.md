前提条件はそろっています：**Java を入れて、ポートを開放し、ディレクトリを作り、コアも選んでダウンロード済み**。この記事ではサーバーを実際に動かします。

:::note 新しい Forge と NeoForge はこの記事を飛ばせます
新しい **Forge** と **NeoForge** は公式の**インストーラー**で導入すると、サーバーディレクトリに**起動スクリプトが自動生成**されます（`run.bat` / `run.sh`）。それを使う場合はそのスクリプトを実行するだけで、起動スクリプトを自分で書く必要はありません。
:::

## 1. 起動スクリプトを書く

ダウンロードしたサーバーコア（`.jar`）を配置ディレクトリに置きます。例えば：

```
C:\mcserver\survival\        （Linux 下对应 /opt/mcserver/survival/）
├── paper-1.21.4.jar         ← 你下载的核心
└── （其余文件首次启动后自动生成）
```

### Windows：`start.bat`

1. このディレクトリに**テキストドキュメント**を新規作成し、ファイル名を `start.bat` に変えます（拡張子を `.txt` から `.bat` に）。
2. 右クリック → テキストエディタで開き、次の内容を書いて保存します：

```bat
@echo off
cd /d "%~dp0"
java -Xms2G -Xmx2G -jar 核心名.jar --nogui
pause
```

`核心名.jar` は実際のファイル名（例：`paper-1.21.4.jar`）に置き換えてください。

- `cd /d "%~dp0"` で作業ディレクトリをスクリプトのあるフォルダに固定し、ダブルクリック時にコアファイルが見つからない事態を防ぎます。
- `--nogui` はサーバー内蔵の GUI ウィンドウを開かず、出力をすべてコマンドラインに出す指定です（`nogui` は古い別名で、同じ意味）。
- `pause` はサーバー終了後にウィンドウが**すぐ閉じない**ようにして、エラーを確認できるようにします。詳しくは後述の「応用」を参照。

### Linux：`start.sh`

```bash
#!/bin/sh
cd "$(dirname "$0")"
exec java -Xms2G -Xmx2G -jar 核心名.jar --nogui
```

実行権限を与えてから実行します：

```bash
chmod +x start.sh
./start.sh
```

## 2. 初回起動：ダウンロードを待ち、EULA に同意する

**初回起動では動作に必要なファイルを先にダウンロードします**。コマンドラインに `Downloading mojang_x.x.x.jar` のような出力が出ますが、これは正常です。**ダウンロードが終わるまで気長に待って**ください（国内の回線で止まり続ける場合は、ネットワークの高速化手段を自分で用意する必要があります）。

ダウンロードが終わってもサーバーは**そのまま起動せず**、次のように表示されます：

```
You need to agree to the EULA in order to run the server. Go to eula.txt for more info.
```

このとき、ディレクトリに**自動生成された `eula.txt`** をテキストエディタで開き、

```
eula=false
```

を

```
eula=true
```

に変更します。

保存したら**起動スクリプトをもう一度実行**します。この操作は [Minecraft EULA](https://aka.ms/MinecraftEULA) を読み同意したことを示します。

:::warn 変更しないと起動しない
`eula=false` のままだと、サーバーは**起動直後に終了**します。ここが初心者の最も多いつまずきどころです。
:::

## 3. 起動成功の見分け方

コマンドラインに次の行が出れば、サーバーは**正常に起動**しています：

```
Done (6.554s)! For help, type "help"
```

括弧内の秒数はマシンによって異なります。この時点で：

- **同じ PC** からは `localhost:25565` で参加できます；
- 他の人は**あなたのグローバル IP**（またはドメイン）に既定のポート `25565` を付けて参加できます；
- コンソールで `stop` を入力すると**安全に停止**できます（**ウィンドウを直接閉じない**でください。セーブデータが壊れやすくなります）。

## 4. 応用：3 つの実用テクニック

### 1. `pause` を入れて、クラッシュ時にログを見られるようにする

Windows の `.bat` をダブルクリックで実行していると、サーバーがクラッシュしたときウィンドウが**一瞬で消えて**何も見えません。スクリプトの**最終行**に `pause` を追加します：

```bat
java -Xms2G -Xmx2G -jar 核心名.jar --nogui
pause
```

これでサーバー終了後もウィンドウが止まり、エラー内容を確認できます（Linux での同等の方法は、スクリプトの末尾に `read -n 1 -p "按任意键继续..."` を追加することです）。

### 2. ワイルドカードを使って、コアのバージョンを変えてもスクリプトを直さない

コアを更新するたびにスクリプト内のファイル名を変えるのは面倒です。**ワイルドカード**で一致させられます：

```bash
java -jar *.jar
java -jar paper-*.jar
java -jar leaf-*.jar
```

:::warn ワイルドカードは Windows の .bat では効かない
これは**実測で確認した**差異です。**Linux / macOS のシェルはワイルドカードを展開**しますが、**Windows の cmd は展開しません**。書いた `*.jar` がそのまま Java に渡され、Java はそのファイルを見つけられずエラーになります。

Windows では `for` ループで同じ効果を得ます：

```bat
@echo off
cd /d "%~dp0"
for %%f in (paper-*.jar) do (
  java -Xms2G -Xmx2G -jar "%%f" --nogui
  goto :done
)
:done
pause
```

`paper-*.jar` を自分のコアの接頭辞（`leaf-*.jar` など）に変えれば、バージョンを更新してもスクリプトを直す必要はありません。
:::

### 3. クラッシュ後の自動再起動

**Windows**（`start.bat`）：

```bat
@echo off
cd /d "%~dp0"
:start
java -Xmx4G -Xms1G -jar server.jar nogui
echo 服务器崩溃，3 秒后重启...
timeout /t 3
goto start
```

**Linux**（`start.sh`）：

```bash
#!/bin/bash
cd "$(dirname "$0")"
while true; do
    java -Xmx4G -Xms1G -jar server.jar nogui
    echo "服务器已关闭，3 秒后重启..."
    sleep 3
done
```

:::warn 自動再起動の前に考えておくこと
自動再起動は**無人で運用する長期サーバー**に向いています。ただしサーバーが**設定ミス**（Java のバージョン違い、ポートの競合など）で起動に失敗している場合、**3 秒ごとに再起動してログを埋め尽くし**、本当のエラーを覆い隠してしまいます。**最初のデバッグでは自動再起動を使わず**、まず手動で通してください。
:::

:::tip Linux の長期運用には systemd がおすすめ
上記の `while` ループは SSH が切れると終了させられます。**起動時の自動起動、クラッシュ時の自動再起動、SSH を抜けても停止しない**ようにするには systemd での管理が適しています。「環境の準備（Windows と Linux）」の第 5 ステップを参照してください。
:::
