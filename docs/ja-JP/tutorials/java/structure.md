サーバーを動かすと、ディレクトリの中にファイルやフォルダがたくさん現れます。**どれを触ってよく、どれに絶対触れてはいけないか**を知ることが、以後のすべての操作（プラグイン導入、バックアップ、移行）の基礎になります。

以下ではプラグイン系サーバー（Paper / Purpur など）を例にします。

## 1. フォルダ

| フォルダ | 役割 | 触ってよいか |
| --- | --- | --- |
| `plugins/` | プラグインを置く場所 | よく触る |
| `world/` | **メインワールド**のデータ | まとめてバックアップするだけ。手で編集しない |
| `world_nether/` | ネザーのデータ | 同上 |
| `world_the_end/` | エンドのデータ | 同上 |
| `logs/` | 実行ログ。問題の切り分けはここ | 古いものは削除可 |
| `crash-reports/` | クラッシュレポート。エラーが出たらまずここ | 古いものは削除可 |
| `config/` | Paper 系のコア設定（`paper-world-defaults.yml` など） | 変更前にバックアップ |
| `libraries/` `versions/` `cache/` | 依存ライブラリとキャッシュ。**自動生成** | 触らない |
| `mods/` | **MOD サーバー**（Fabric / Forge）とハイブリッドサーバーにのみ存在 | よく触る |

## 2. ルート直下の主要ファイル

| ファイル | 役割 |
| --- | --- |
| `server.properties` | **最も基本的なサーバー設定**（ポート、正規アカウント認証、描画距離など） |
| `eula.txt` | 規約への同意ファイル。`eula=true` が必須 |
| `コア名.jar` | サーバーコア本体 |
| `ops.json` | OP（管理者）のリスト |
| `whitelist.json` | ホワイトリストのリスト |
| `banned-players.json` / `banned-ips.json` | BAN リスト |
| `usercache.json` | プレイヤー名と UUID のキャッシュ |
| `bukkit.yml` / `spigot.yml` | Bukkit / Spigot 層の設定（Paper 系にもある） |
| `purpur.yml` / `paper.yml` | 各コア固有の設定（そのコアにした場合のみ） |
| `commands.yml` | コマンドの別名とブロックの対応表 |
| `permissions.yml` | 既定の権限定義 |

## 3. ワールドフォルダの中身

`world/` の中身こそが実体のセーブデータです。**バックアップでは `world` を丸ごと取ります**：

| サブディレクトリ | 内容 |
| --- | --- |
| `region/` | **チャンクデータ**（ブロックと地形はここ。サイズが最大） |
| `playerdata/` | プレイヤーのインベントリ、位置、体力 |
| `entities/` | エンティティのデータ（ドロップ品、モブ、村人の取引など） |
| `poi/` | 関心点（村人の作業台、ベッドなど） |
| `data/` | ワールド全体のデータ（マップ、スコアボードなど） |
| `datapacks/` | データパック |
| `advancements/` `stats/` | 進捗と統計 |

:::warn ワールドのファイルを手で編集しない
`region/` の中のファイルを直接書き換えると、**セーブデータが壊れる**可能性が非常に高いです。ワールドを変更したい場合は `WorldEdit` のようなプラグインを使うか、先にサーバーを停止してから操作してください。
:::

## 4. この構成からわかる 3 つのこと

1. **バックアップで何を取るか**：`world*` の 3 つのワールドフォルダ + `plugins/` 内の設定 + `server.properties`。それ以外の多くは自動的に再生成できます。詳しくは「バックアップと復元」を参照。
2. **移行のしかた**：サーバーディレクトリ全体を新しいマシンへコピーし、同じバージョンの Java を入れるだけです。パスに日本語や空白を含めないでください。
3. **切り分けはどこから見るか**：まず `logs/latest.log`、クラッシュしたら `crash-reports/`。
