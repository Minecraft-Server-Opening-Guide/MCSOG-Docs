MCDReforged（略称 **MCDR**）は、サーバー界隈で非常によく使われている**サーバーマネージャー**です。サーバーコアを置き換えるのではなく、**コアの外側を包みます**：MCDR がコアのプロセスを起動・管理し、コンソール出力を読み取ることで、**サーバー本体を変更せずに**機能を拡張します。

## 1. 何を解決するのか

バニラ / Paper のサーバーで拡張できるのは「プラグイン」だけですが、MCDR が提供するのは**もう 1 つの層**の能力です：

| 能力 | 説明 |
| --- | --- |
| **プラグインエコシステム** | **Python** でプラグインを書けるため、Java プラグインでは扱いにくいこと（クロスサーバー転送、外部 API との連携、運用の自動化）ができます |
| **イベント駆動** | サーバーの出力を解析してイベントを配信します（プレイヤーの入退室、チャット、死亡、コマンド……）。プラグインは購読するだけです |
| **ホットリロード** | プラグインは通常リロードでき、サーバー全体を再起動する必要はありません |
| **権限システム** | プレイヤー単位／グループ単位の権限管理を内蔵し、`!!` プレフィックスのコマンドと組み合わせて使います |
| **ウォッチドッグ** | コアがクラッシュすると自動で再起動できます |
| **クロスサーバー** | 1 つの MCDR で複数のサーバーインスタンスを管理できます |

## 2. どのように動くのか

MCDR は起動すると**サーバープロセスを管理下に置きます**：サーバーのコンソール出力を読み取ってイベントに解析する一方、チャット欄で入力した `!!xxx` コマンドを横取りしてプラグインに渡します。バニラのサーバーには渡しません。

したがって：

- サーバー**本体**はもとのコアのままで、挙動は変わりません；
- 層が 1 つ増えるため、**トラブル調査ではログを 1 層多く見る**必要があります（MCDR 自身のログ + サーバーのログ）。

## 3. インストール

MCDR は **Python 3** で書かれており、Python と pip が必要です：

| MCDR のバージョン | 必要な Python |
| --- | --- |
| < 2.10 | ≥ 3.6 |
| ≥ 2.10 | ≥ 3.8 |
| ≥ 2.15 | **≥ 3.9** |

最新版を入れるなら **pip** でインストールします：

```bash
pip install mcdreforged
```

:::warn ソースの zip をダウンロードして実行しない
ネット上の多くのチュートリアルは GitHub から圧縮ファイルをダウンロードして解凍するよう案内していますが、**それは古い方法です**。MCDR は 1.0（2021 年初頭）以降、ソースからのインストールを廃止しています。開発者で何をしているか分かっている場合を除き、pip でインストールしてください。
:::

## 4. 起動の流れ

1. **初期化**：初期化コマンドを 1 回実行すると、MCDR が自身の設定ファイルとディレクトリ構成を生成します。
2. **設定**：MCDR の設定に**サーバーの起動コマンド**と**作業ディレクトリ**を記入します（「サーバーの起動」で起動スクリプトがやっていたことを、MCDR に任せる形です）。
3. **起動**：MCDR を実行すると、サーバーを立ち上げてコンソールを引き継ぎます。
4. **サーバーの種類の指定**：MCDR は**サーバーハンドラ**でさまざまな種類のコア（バニラ / Paper 系 / MOD 系など）に適応します。間違えるとイベントの解析がおかしくなります。

:::tip コマンドラインのサブコマンドは公式ドキュメントに従う
MCDR のコマンドラインインターフェース（グローバル引数、サブコマンド）はバージョン間で調整されています。**具体的な書き方は公式 CLI ドキュメントと照らし合わせ**、古いチュートリアルをそのまま真似しないでください。
:::

## 5. コマンドと権限

MCDR のコマンドはすべて `!!` プレフィックスです（ゲーム内のチャット欄に入力します）：

| コマンド | 役割 |
| --- | --- |
| `!!MCDR` | メインコマンド。MCDR 自体を管理します（状態、プラグイン、リロード、権限など） |
| `!!help` | 登録済みコマンドのヘルプを表示 |

- コマンドの実行権限は MCDR の**権限システム**で制御され、プレイヤー単位または権限グループ単位で付与できます。
- 権限のないプレイヤーが実行すると拒否のメッセージが返るだけで、サーバー本体には影響しません。

## 6. プラグイン

- プラグインは MCDR の `plugins/` ディレクトリに入れ、`!!MCDR` の関連サブコマンドで読み込み／リロードします。
- 公式の**プラグインリポジトリ**があり、既成のプラグインを探せます。自分で書くこともできます（単一ファイル、複数ファイル、フォルダ型などの形式があります）。
- プラグイン開発の中心は**メタデータ + イベントリスナー + コマンドツリー**です：プラグイン情報を宣言し、関心のあるイベントを登録し、独自の `!!` コマンドを組み立てます。

## 7. いつ MCDR を使うべきか

**向いている**：運用の自動化（定時再起動、クラッシュ時の起動、バックアップとの連携）をしたい、サーバーの状態を外部プラットフォーム（QQ グループ、Discord、Web サイト）に連携したい、Python プラグインで独自のロジックを書きたい。

**必須ではない**：小規模なプラグインサーバーを立てるだけで、コア付属のプラグイン + systemd による管理で足りる場合。**層が増えれば維持コストも増えます**。使うために使うのはやめましょう。
