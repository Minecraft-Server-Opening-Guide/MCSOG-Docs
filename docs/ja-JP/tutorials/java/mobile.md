多くのプレイヤーは**スマホ / タブレット / コンソール**でしか Minecraft を遊んでおらず、それは**統合版**です。既定では統合版のプレイヤーは**Java 版のサーバーに入れません** —— 2 つのバージョンはプロトコルがまったく異なります。

**Geyser** を使えばこの道がつながり、あなたの Java サーバーにもスマホのプレイヤーが参加できるようになります。

## 1. Geyser は一方通行（まずここを理解する）

Geyser の公式 FAQ に明確に書かれています：

> **Geyser で Java のプレイヤーを自分の統合版サーバーに接続できますか？**
> **いいえ。これは統合版のプレイヤーを Java サーバーに接続するための変換ツールであり、逆はできません。**

したがって：

| 方向 | 可否 | 方法 |
| --- | --- | --- |
| 統合版のプレイヤー → **Java サーバー** | 可能 | **Geyser**（+ Floodgate） |
| Java のプレイヤー → 統合版サーバー | 公式な方法はない | 存在しない |

**Geyser は Java サーバー側に入れます**。統合版の公式サーバー（BDS）には **Geyser を入れられません**。

## 2. どこに、どう入れるか

Geyser には複数の形態があり、Java サーバーの種類で選びます：

- **プラグイン形態**：Spigot / Paper / Purpur などのプラグイン系（最も一般的）
- **プロキシ形態**：Velocity / BungeeCord（クロスサーバー構成ではプロキシ側に入れる）
- **MOD 形態**：Fabric / NeoForge
- **単体形態（standalone）**：上記のプラットフォームに依存せず単独で動作

入れたらサーバーを再起動します。Geyser が自身の設定ファイルを生成します。

## 3. 要点：UDP ポートを開ける

ここが最も見落としやすい手順です：

| ポート | プロトコル | 用途 |
| --- | --- | --- |
| `25565` | **TCP** | Java のプレイヤーの接続 |
| `19132` | **UDP** | **統合版のプレイヤーの接続（Geyser が待ち受け）** |
| `19133` | UDP | 統合版の IPv6 既定ポート |

:::warn TCP だけ開けるのがスマホのプレイヤーがつながらない最大の原因
クラウドサーバーのセキュリティグループと OS のファイアウォールの**両方**で **UDP 19132** を許可してください。TCP 25565 だけ許可して「スマホからなぜつながらないのか」と悩む人が後を絶ちません。
:::

スマホのプレイヤーは「サーバーを追加」で、**アドレス = あなたの IP またはドメイン、ポート = 19132** と入力します。

## 4. Floodgate：スマホのプレイヤーに Java アカウントを不要にする

既定では Java サーバーは正規アカウント認証が有効で、統合版のプレイヤーは**Java アカウントを持たない**ため門前払いされます。

**Floodgate** はこれを解決します：統合版のプレイヤーが **Xbox アカウントでそのまま入れる**ようになり、Java 版を購入する必要はありません。

ポイント：

- Floodgate は通常 Geyser とセットで導入します；
- 統合版のプレイヤーの名前には**プレフィックス**（既定は `.`）が付き、Java のプレイヤーと区別されます；
- そのため**ホワイトリスト、BAN、コマンド**で名前を書くときはこのプレフィックスに注意し、必要なら引用符で囲みます；
- Floodgate のアカウント連携機能で、統合版のアカウントを既存の Java アカウントに関連付けることもできます。

## 5. 既知の制限（プレイヤーに事前に伝える）

- **コンソール機には制限がある**：Xbox / PlayStation / Switch のプレイヤーは**IP を直接入力して参加できません**。通常は**カスタム DNS** か**LAN** 経由での接続になります。
- **遠距離での表示異常**：統合版のクライアントは 32 ビット、Java は 64 ビットで、遠くまで移動すると奇妙な位置や描画の問題が出ることがあります（コミュニティに非公式の緩和策があります）。
- **一部のプラグインは非対応**：Geyser は Java クライアントを模擬するため大半のプラグインは使えますが、ログインやプロトコルに深く介入する少数のプラグインは競合します。
- **リソースパックは形式変換が必要**：Java のリソースパックは統合版では読めないため、統合版の形式に変換してから Geyser に渡します。
- **MOD サーバーには制限がある**：クライアントに MOD の導入を求めるサーバーでは、Geyser もそれを持ち込めません（「バニラのクライアントで入れるものだけが Geyser でも入れる」）。

## 6. クロスプレイを有効にするか

**有効にするとよい**：プレイヤーの獲得元を広げたい、サーバーにスマホのプレイヤー層がいる、遊びがサバイバル／建築寄り（精密なレッドストーンに敏感でない）。

**慎重に**：**レッドストーン技術サーバー**。統合版と Java 版ではレッドストーンの挙動がもともと異なり、クロスプレイのプレイヤーが見る仕組みが一致しないため、トラブルになりやすいです。
