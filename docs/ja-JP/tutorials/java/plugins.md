プラグインは**プラグイン系**（Paper / Purpur / Spigot など）の最大の価値です：クライアントを変更せず、プレイヤーに何も入れてもらわずに、サーバーへ機能を追加できます。

## 1. まずプラグインと MOD を切り分ける

| | プラグイン | MOD |
| --- | --- | --- |
| 入れる場所 | サーバーの `plugins/` | クライアント + サーバーの `mods/` |
| プレイヤー側に導入が必要か | **不要** | 通常は必要 |
| 使う対象 | プラグイン系のコア | MOD 系のコア（Fabric / Forge / NeoForge） |
| 混在できるか | **できない**：プラグイン系は MOD を読み込めず、MOD 系はプラグインを読み込めない（ハイブリッドコアやブリッジを使う場合を除く） |

## 2. プラグイン導入の標準手順

1. プラグインの `.jar` ファイルをダウンロードします。
2. サーバーのルートディレクトリにある `plugins/` フォルダに入れます。
3. **サーバーを再起動します**（多くのプラグインは初回のホットロードに対応していません）。
4. コンソールを見ます：プラグインは起動時に通常自分の名前とバージョンを出力し、エラーもここに出ます。
5. `plugins` コマンドで状態を確認します（下記）。

### `plugins` で読み込み状態を判断する

```
plugins          （短縮形は pl）
```

- **緑**：読み込み済み（注意：あくまで**今回読み込めた**という意味で、実行時にエラーが出ないことまでは保証しません）
- **赤**：読み込み失敗（サーバーは認識したが読み込めなかった。コンソールでエラーを確認）
- **まったく出ない**：サーバーがプラグインとして**認識していない** → ファイルが本当に `plugins/` にあるか、拡張子が `.jar` か、コアの種類を間違えていないか（MOD をプラグインとして入れたなど）を確認

## 3. 前提プラグイン（依存関係）

多くのプラグインは自分では何もせず共通機能だけを提供します。**先にそれを入れないと**、目的のプラグインは読み込みに失敗します：

| 前提 | 提供するもの |
| --- | --- |
| **Vault** | 経済 / 権限 / チャットの統一インターフェース。多数のプラグインが依存 |
| **PlaceholderAPI**（PAPI） | 変数プレースホルダー（プレイヤーの残高、オンライン人数の表示など）。プラグイン間で値を取り合う共通手段 |
| **ProtocolLib** | 低レベルなプロトコル操作の機能。多くの高度なプラグインの前提 |
| **LuckPerms** | 権限管理。誰がどのコマンドを使えるかを細かく制御 |

## 4. 設定ファイルと YAML

プラグインの設定はほぼ `plugins/<plugin-name>/` の下にあり、よくあるのは `config.yml` です。YAML を書くときにつまずきやすい点：

- **インデントはスペースのみ。タブは使えない**（YAML のエラーの最大の原因）。
- コロンの後ろにはスペースが 1 つ必要。例：`enabled: true`。
- 階層はインデントで表し、同じ階層のインデントは揃える。

:::warn 文字化け
設定ファイルに日本語を書いて文字化けする場合、ほとんどは**ファイルの文字コードが UTF-8 ではない**ためです（Windows のメモ帳で名前を付けて保存すると ANSI/GBK になりがちです）。VS Code などのエディタで **UTF-8** として保存し直してください。
:::

### カラーコード

サーバーのテキスト（MOTD、チャット、プラグインのメッセージ）では `&` + 英字で色とスタイルを表します。例：

```
&a緑  &c赤  &l太字  &o斜体  &rリセット
```

対応範囲はサーバーのバージョンとプラグインによります。

## 5. 設定を変えたあと反映させる方法

| 方法 | 説明 |
| --- | --- |
| `/<plugin-name> reload` または `/プラグインの短縮名 reload` | 多くのプラグインが対応。**第一候補**（例：`/tab reload`） |
| サーバーを再起動 | 最も確実だが、ホットリロード非対応のプラグインはこれしかない |
| `/reload`（バニラのコマンド） | **非推奨**。プラグインの状態が壊れやすい |

## 6. 用途別にプラグインを選ぶ

| 用途 | よく使われるもの |
| --- | --- |
| 権限 | LuckPerms |
| 基本機能（ホーム、テレポート、キット） | EssentialsX、CMI |
| **荒らし対策とロールバック** | CoreProtect（ブロックの記録を調べ、事故のときに誰がやったか分かる） |
| 領域保護 | Residence、Dominion、GriefDefender |
| ワールド編集 | WorldEdit、WorldGuard（領域保護） |
| マルチワールド | Multiverse-Core |
| チャットの書式 | TrChat、Carbon |
| メニュー / GUI | DeluxeMenus、TrMenu |
| MOTD とサーバーリスト | MiniMOTD |
| スキン（オフラインモードでは必須） | SkinsRestorer |
| ログイン（オフラインモード） | AuthMe、LibreLogin |
| バージョン間の互換 | ViaVersion + ViaBackwards |
| プラグインのホット管理 | PlugManX |

よくある導入初期の組み合わせ：**LuckPerms + EssentialsX + CoreProtect + WorldEdit/WorldGuard + Vault + PlaceholderAPI**。あとは遊びに合わせて追加します。

## 7. セキュリティ：プラグインにも「毒」がある

プラグインは**サーバーの権限で動く第三者製のコード**であり、間違えて入れると結果は深刻です：

- **信頼できる配布元からのみダウンロードする**：公式の配布チャネル（SpigotMC、Modrinth、Hangar など）か作者のリポジトリ。フォーラムやグループのファイル共有で転がっている jar は最も危険です。
- **バックドアに注意**：正常なプラグインを再パッケージし、任意のコマンド実行、特定プレイヤーへの OP 付与、ファイルのアップロードなどのコードを仕込む例があります。
- **メンテナンス状況に注意**：長期間更新されず作者が離れたプラグインは、新しいバージョンでサーバーごと落ちることがあります。
- **迷ったらまずテストサーバーで試す**：出所の怪しいプラグインを本番サーバーに直接入れないでください。

:::tip 問題が起きたらまずプラグインを疑う
サーバーが突然重くなったり奇妙なエラーが出たら、**直近に入れたプラグインをまず無効化**し、1 つずつ有効化して特定してください。ログを読むよりずっと速いです。
:::
