サーバーを立てる前に、2 つのことを先に決めなければなりません：**プロトコル上その立て方が許されるか**、そして**マシンが耐えられるか**です。この 2 つがはっきりしないまま環境やコアを入れるのは、時間とお金の無駄です。
:::note この記事が扱うこと
① 公式プロトコルが個人のサーバー運営に引く境界；② 最低構成と推奨構成；③ CPU がメモリより重要な理由。
:::

## 1. 公式プロトコル：できること、できないこと

Java 版のサーバーは起動時に [Minecraft エンドユーザーライセンス契約（EULA）](https://aka.ms/MinecraftEULA) への同意が必要です。方法は簡単です：初回起動で `eula.txt` が生成されるので、`eula=false` を `eula=true` に変更します。**変更しないと起動直後に終了します。**

| 事項 | 説明 |
| --- | --- |
| プライベートサーバー | 自由に構築でき、友人同士のマルチプレイに制限はありません |
| サーバー本体の再配布 | 公式のサーバー jar を**再配布してはいけません**。公式またはコアの公式チャネルからダウンロードするのみです |
| 課金 | サーバーに課金することはできますが、ゲーム本体や公平性に影響するバニラのゲーム内容を売ることはできません。詳細は各コアとプラットフォームの公式規約に従います |
| 公式名義の使用 | プレイヤーに自分のサーバーが Mojang 公式運営だと**誤解させてはいけません** |
| 正規アカウント認証 | `server.properties` の `online-mode=true` が既定値で、正規アカウントを検証します |
:::warn オフラインモードについて
`online-mode=false`（いわゆるオフラインサーバー）は参入の敷居を下げますが、同時にアカウントの保護を失います：誰でも任意の ID を騙って入れて、正規のスキンや UUID の紐付けも使えません。**リスクを完全に理解しており、サーバーを外部に公開しない場合にのみ使ってください。**
:::

## 2. 推奨構成

### 最低構成（1〜3 人、小規模サーバーの試運転）

| 項目 | 要件 | 説明 |
| --- | --- | --- |
| CPU | **2 コア**（3GHz 以上のシングルコア高周波を推奨） | シングルコア性能を見る。コア数ではない |
| メモリ | **4GB**（システム 1GB + MC 3GB） | システム用の余裕を必ず残す |
| ストレージ | **20GB SSD** | HDD では読み込みが非常に遅い |
| ネットワーク | 上り帯域**最低 10Mbps** | ボトルネックは上り。下りが大きくても意味がない |

### 推奨構成（10 人以内、安定した長期運営）

| 項目 | 要件 | 説明 |
| --- | --- | --- |
| CPU | **4 コア** | シングルコアの周波数を優先 |
| メモリ | **8GB**（MC に 6GB 割り当て） | 残りはシステムとキャッシュへ |
| ストレージ | **50GB SSD** | セーブデータ、バックアップ、ログが増える |
| ネットワーク | 上り帯域 **30Mbps+** | 人数が多くプラグインを入れるほど余裕が必要 |

### レッドストーン技術サーバーの構成（装置とワールドイーターを動かす）

| 項目 | 要件 | 説明 |
| --- | --- | --- |
| CPU | **8 コア**（4.5GHz 以上のシングルコア高周波を推奨） | ワールドイーター、ゲートカッティング、大型装置はほぼ 1 つのコアに集中する。コア数は主にサブサーバーとバックグラウンド用の余裕 |
| メモリ | **16〜32GB** | 複数のサブサーバーを動かすことを考慮：各サブサーバーに個別にメモリを割り当て、システムとキャッシュの余裕も残す |
| ストレージ | **120GB+** | バックアップを考慮：装置が動き出せば、セーブデータとバックアップの増加速度は通常のサバイバルサーバーよりはるかに速い |
| ネットワーク | 上り帯域 **100Mbps+** | 投影の同期、多人数の同画面、大量のエンティティのパケットが上りを通る。余裕を十分に |

### CPU がメモリより重要な理由

**Minecraft のサーバーは、メモリよりも CPU のシングルコア性能をはるかに強く要求します。** メインスレッドはエンティティ、チャンク、レッドストーン、プラグインのロジックを直列に処理し、それらはほぼ**1 つのコア**に集中します —— コアがいくら多くても、メインスレッドは 1 つだけです。

そのため次のようなことが起きます：**2 コア 4GB でもシングルコアが 3.5GHz のマシンのほうが、8 コア 2GB のマシンより実際に快適です。** 前者はシングルコアが強くメインスレッドが詰まらず、後者はコアは多くても周波数が低くメモリも足りないため、同じように TPS が落ちます。

マシンを選ぶときの優先順位：

1. **シングルコアの周波数**（高いほどよい。3.5GHz 以上で体感が明らかに良くなる）
2. **メモリ容量**（足りればよい。不足すると OOM や頻繁な GC が起きる）
3. **ストレージの種類**（SSD は必須。チャンクの読み込みとセーブデータの書き込みに影響する）
4. **コア数**（プラグインサーバー、多重起動、プロキシでのみより多くのコアが必要）
:::tip メモリは多ければよいわけではない
MC に割り当てる `-Xmx` が大きすぎると 2 つの副作用があります：① 1 回の GC 停止が長くなり、周期的なラグとして現れる；② システムの空きメモリが圧迫され、かえって遅くなる。**10 人以内なら 4〜6GB で通常は十分**で、残りはシステムに残します。
:::

### そのほか体験に影響する要素

- **ストレージの IO**：ワールドが大きいほど、走り回る頻度が高いほど IO の負荷が増します。SSD は「起動が速い」だけでなく、走り回るときのラグに直接影響します。
- **上り帯域**：家庭用回線は通常、上りが下りよりはるかに小さいです。サーバーを立てる前に、プランの「500M」ではなく**上り**がどれだけあるかを確認してください。
- **ネットワーク遅延**：プレイヤーとサーバーの物理的な距離が基礎的な遅延を決めます。国内のプレイヤーなら国内のデータセンターのサーバーが最も快適です。
- **常時稼働できるか**：家庭用 PC はスリープや停電で落ちます。長期運営するならクラウドサーバーや専用ホストのほうが適しています。

## 3. 次にやること

1. **OS を選ぶ**：[OS の選択](/tutorials/java/os) を参照 —— 長期運営なら Linux を優先。身内と遊ぶだけなら Windows でも十分
2. **環境を整える**：[環境準備（Windows と Linux）](/tutorials/java/environment) を参照 —— Java を正しく入れ、ポートを開放し、ディレクトリを作る
3. **コアを選ぶ**：[サーバーコア比較](/wiki/compare#mcsog-h-%E6%A0%B8%E5%BF%83%E5%AF%B9%E7%85%A7) を参照 —— 初めてなら通常は Paper をそのまま選ぶ
:::note まとめ
プロトコルへの同意が済み、**シングルコアの周波数をコア数とメモリより優先**し、SSD と上り帯域が要件を満たしていれば —— この 3 点が揃えば、そのマシンで安定してサーバーを運営できます。
:::
