プラグインを `plugins/` に入れただけでは導入は終わりません。サーバーが「使いやすいかどうか」を実際に決めるのは、そのあとの数十個の `config.yml` です。設定が正しければ機能になり、空白 1 つを間違えればその段落ごと読めなくなることがあります。

本記事は 3 つを扱います：**YAML の書き方、カラーコードの使い方、文字化けを出さないエンコーディング**。最後に設定変更の定型手順を示します。

## 1. プラグイン設定の置き場所

ほとんどのプラグインは自分のファイルを `plugins/プラグイン名/` の下に置きます。よくある種類：

| ファイル / ディレクトリ | 役割 |
| --- | --- |
| `config.yml` | メイン設定。ほぼすべてのプラグインにある |
| `messages.yml`、`lang/` | 表示テキスト。ここを変えると文言の変更や日本語化になる |
| `menus/`、`kits.yml` など | モジュール別の設定。プラグインが起動時に生成する |
| `data/`、`playerdata/`、`*.db` | プラグイン自身が管理する実行データ |

:::warn データファイルを手で編集しない
`data/`、`playerdata/`、`*.db` のような内容は、プラグインが実行時に自分で書き込むものです。手で編集すると、軽ければ上書きされ、ひどければプレイヤーデータがずれます。変えるのは設定だけにし、データには触れないでください。
:::

## 2. YAML の 3 つの鉄則

「設定が読めない」の 9 割は、次の 3 つに由来します。

### インデントはスペースのみ。タブは使えない

YAML はインデントにタブ文字を使えないと明確に定めています。しかもタブはエディタ上ではスペース数個とまったく同じに見え、目視ではほとんど見つけられません：

```yaml
# 正しい：スペースを使う
options:
    enable: true

# 誤り：この行の先頭はタブ
options:
	enable: true
```

多くのエディタはタブを矢印や点線で表示し、VS Code なら右下に `Tab Size` とインデント方式が出ます。**すでにタブが混ざっている設定を 1 つずつ手で消さないでください**。エディタの「インデントをスペースに変換」機能で一括処理します。

### コロンの後ろには必ずスペースが必要

```yaml
enabled: true      # 正しい：コロンの後にスペース 1 つ
enabled:true       # 誤り：行全体が 1 つの文字列として扱われる
```

`key:value` は YAML ではキーと値の組ではなく、ただの文字列です。プラグインは `enabled` というキーを読めないため既定値に戻り、現れ方としては「確かに変えたのに効かない」になります。

### 同じ階層のインデントは揃える

```yaml
options:
    enable: true
    check: false
    drop-block: true
    other:
        money: 10
        welcome: "ようこそ"
guide:
    show: true
```

`options` と `guide` は同じ階層、`enable`、`check`、`drop-block` と `other` は同じ階層、そして `other` の下の `money` はさらに 1 層下です。同じ階層では**キーの重複が許されません**：

```yaml
options:
  enable: true
  enable: false     # 誤り：同階層でキーが重複
  check: false
```

YAML に対応したエディタはこの書き方を赤く表示します。エディタが黙っていても、プラグインが読むときにエラーになります。

## 3. オブジェクト、配列、ネスト

YAML の基本構造は 2 つだけです：**キーと値の組（オブジェクト）** と **リスト（配列）**。残りはそれらを入れ子にした結果です。

### オブジェクト

```yaml
options:
  enable: true
  check: false
  money: 10
```

インライン形式でも書け、短い設定に向きます：

```yaml
options: {enable: true, check: false}
```

### リスト

`-` で始まる行がリストを作り、要素は順に並びます：

```yaml
worlds:
  - world
  - world_nether
  - world_the_end
```

インライン形式：

```yaml
worlds: [world, world_nether, world_the_end]
```

### リストの中にオブジェクトを置く

プラグイン設定で最もよく現れ、最も書き間違えやすい構造です —— **各要素の最初のキーは `-` の後ろに続き、同じ要素の他のキーはそれに揃えます**：

```yaml
kits:
  - name: starter
    price: 0
    items:
      - STONE_SWORD
      - BREAD
  - name: vip
    price: 500
    items:
      - DIAMOND_SWORD
```

`name` と `price`、`items` は同じ要素の 3 つのキーなのでインデントを揃え、`- STONE_SWORD` はさらに `items` の 1 層下になります。

### 値の型

プラグイン設定でよくある値はいくつかの種類があり、書き方に注意が必要です：

```yaml
boolean: true          # true / false。大文字小文字は区別しない
integer: 10
float: 3.14
text: "hello"          # 特殊文字を含むときは引用符で囲む
null_value: ~          # ~ は空値を表す
```

:::tip いつ引用符が必須になるか
値に `: `、`#`、`{`、`}`、`[`、`]`、`&`、`*`、`!`、`|`、`>` などの記号が含まれる場合、または値がそれらで始まる場合は、一重引用符か二重引用符で囲むのが最も確実です。たとえば `&aこんにちは` のようなカラーコード付きテキストは、`"&aこんにちは"` と書けば誤解析されません。
:::

## 4. よくある YAML のエラーと原因

| 現象 | 実際の原因 | 対処 |
| --- | --- | --- |
| プラグイン起動時に `while parsing`、`mapping values are not allowed here` | コロンの後にスペースがない、または値に引用符なしの `: ` がある | スペースを補う、または値を引用符で囲む |
| `found character '\t' that cannot start any token` | インデントにタブが混ざっている | インデントをスペースに一括変換 |
| `duplicate key` | 同じ階層に同じキーを 2 つ書いている | 余分なほうを削除 |
| 設定を変えたのに効果がない | キー名の綴り違い、階層の誤り、またはそもそもそのファイルを読んでいない | プラグインの既定設定と項目ごとに照合 |
| あるリスト項目だけ効かない | リスト項目内のキーのインデントが揃っていない | 同じ要素のキーを左揃えにする |
| ファイル全体が読めず、1 行目でエラー | ファイルに BOM が付いている、またはエンコーディングが UTF-8 でない | UTF-8（BOM なし）で保存し直す |
| `expected <block end>` が出る | どこかの行のインデントが足りない／多い | 階層ごとにインデント幅を確認 |

:::tip エディタに検査させる
VS Code に YAML 拡張を入れ、Notepad++ で `.yml` を開けば、インデントと構文の問題をリアルタイムに示してくれます。**保存する前に赤い波線がないか見る**ほうが、あとからログを漁るよりずっと速いです。
:::

## 5. 色と書式のコード

サーバーのテキスト（MOTD、チャット、プラグインのメッセージ、メニュー名）は**書式コード**で色を付けます。バニラはセクション記号 `§` を使いますが、多くのプラグインは利便性のため設定に `&` を直接書けるようにし、プラグイン側で変換します。

### 色

```
&0 黒 &1 濃い青 &2 濃い緑 &3 濃い水色
&4 濃い赤 &5 濃い紫 &6 金 &7 灰
&8 濃い灰 &9 青 &a 緑 &b 水色
&c 赤 &d ピンク &e 黄 &f 白
```

### 書式

```
&l 太字     &o 斜体     &n 下線   &m 取り消し線
&k ランダム文字 &r リセット
```

組み合わせて使えます。例：

```yaml
prefix: "&8[&aサーバー&8] &r"
message: "&aようこそ &e%player_name% &aサーバーへお戻りください"
warning: "&c&l警告&r &7ここには建築しないでください"
```

`&r` は**それ以降**の書式だけを消すので、ある文章を既定のスタイルに戻したいときはその位置に `&r` を書きます。

### いくつかの制限

- **`&` は万能ではない**：プラグイン側が変換する必要があります。一部の場所（バニラの `server.properties` の `motd`、一部のバニラコマンド）は本物の `§` しか受け付けず、`&` はそのまま表示されます。
- **色は 16 種類だけ**：`&` コードは旧来の仕組みで、トゥルーカラーはありません。グラデーションや正確な色値が必要なら、後述の MiniMessage を使います。
- **`§` が入力できないとき**：通常のクライアントではこの記号を直接入力できないので、`Alt` を押しながらテンキーで `167` を入力するか、コピー＆ペーストします。
- **対応するコードの範囲はプラグイン次第**：同じ `&l` でも、あるプラグインではメニュータイトルで効き、別の場所では無視されます。

### MiniMessage（知っておけば十分）

Adventure ライブラリを基にした MiniMessage はタグでスタイルを記述し、トゥルーカラー、グラデーション、ホバーとクリックのイベントに対応します：

```xml
<yellow>こんにちは <blue><bold>世界</bold></blue>!</yellow>
<gradient:#f6d365:#fda085>グラデーション文字</gradient>
<rainbow>虹色の文字</rainbow>
```

注意すべきは：**プラットフォームが標準対応していることは、プラグインが対応していることを意味しません**。Paper とその派生コアは Adventure を内蔵しているので、Paper 向けに開発されたプラグインはたいてい MiniMessage を使えます。一方 Bukkit 向けに開発されたプラグイン（EssentialsX など）は既定では対応しておらず、そのライブラリを自分で取り込んでいる場合（PlaceholderAPI など）を除きます。

:::note 無理に当てはめない
他人が MiniMessage を使って良い結果を出していても、あなたのプラグインがそれを受け付けるとは限りません。書く前にプラグインのドキュメントを確認し、`&` コード対応か、MiniMessage タグ対応か、両方かを確かめてください。
:::

## 6. ファイルのエンコーディングと文字化け

設定に日本語を書いたら `???`、`鍑虹幇`、`æ¬¢è¿` のように表示されるのは、ほぼすべて**エンコーディングの不一致**であり、プラグインが日本語に対応していないわけではありません。

| 現象 | 原因 |
| --- | --- |
| 日本語が疑問符や四角になる | ファイルが ANSI / GBK で保存され、サーバーは UTF-8 として読んでいる |
| 日本語が奇妙な記号の列になる | ファイルは UTF-8 だが、GBK として読まれている（またはその逆） |
| 1 行目のキー名が読めない | ファイル先頭に BOM が付いており、一部のパーサーが BOM をキー名の一部として扱う |

対処：

1. VS Code、Notepad++ などのエディタでファイルを開く。
2. 保存時に **UTF-8** を選ぶ（VS Code なら右下のエンコーディングから `Save with Encoding`）。
3. BOM が付かないことを確認する。Windows のメモ帳は古いバージョンで既定が「UTF-8（BOM 付き）」で、これが最もよくある落とし穴です。
4. 保存後にプラグインをリロードし、コンソールとゲーム内のテキストを確認する。

:::warn まずメモ帳で保存し直すのは危険な操作
Windows のメモ帳で `.yml` を開いて何気なく Ctrl+S すると、正常だった UTF-8 のファイルが ANSI に変わることがよくあります。**最初から YAML とエンコーディングの表示に対応したエディタを使い**、変更前にバックアップを取ってください。
:::

## 7. 安全に設定を変える：定型手順

この順で進めれば、問題が起きる確率はかなり下がります。

1. **まずバックアップ**。`config.yml` を `config.yml.bak` として複製しておけば、壊してもすぐ戻せます。
2. **できれば停止中か低負荷の時間帯に変更する**。一部のプラグインは終了時に自分のメモリ状態をファイルへ書き戻すため、稼働中に変えた内容が上書きされることがあります。
3. **YAML 対応のエディタを使い**、既存のコメントと構造を残す。ついでにファイル全体を整形しないこと。
4. **1 回に 1 か所だけ変え**、変えたらすぐ検証する。20 行を一度に変えると、問題が出たときにどの行か分かりません。
5. **リロードする**。プラグイン自身のコマンドを優先します：

| 方法 | 説明 |
| --- | --- |
| `/プラグイン名 reload` | 多くのプラグインが対応。**第一候補**（例：`/tab reload`、`/papi reload`） |
| サーバーを再起動 | 最も確実。ホットリロード非対応のプラグインはこれしかない |
| `/reload`（バニラのコマンド） | **非推奨**。プラグインの状態が壊れやすい |

6. **コンソールと `logs/latest.log` を見る**。設定の解析失敗は通常、読み込み時にファイル名と行番号を出します。行番号をたどればほぼ一目で分かります。
7. **迷ったらまずテストサーバーで試す**。プラグイン設定の変更はプラグインの導入より安全ですが、それでもセーブデータやプレイヤーデータに影響しうるものです。

:::tip エラーの行番号の使い方
ログに `config.yml: 42` のような表示が出たら、**42 行目だけを見ないでください**。YAML の解析エラーは、前の行のインデントや閉じ忘れた引用符が原因であることがよくあります。2、3 行上まで見てください。
:::

## 8. 早見表

| 問題 | まず確認すること |
| --- | --- |
| 設定が反映されない | キー名の綴り、階層の位置、reload を実行したか |
| プラグイン起動時に解析エラー | コロン後のスペース、タブのインデント、同階層のキー重複 |
| 日本語が文字化けする | ファイルが UTF-8（BOM なし）か |
| カラーコードがそのまま表示される | その場所が `&` に対応しているか、MiniMessage タグが必要か |
| 変更したのに元に戻る | プラグインが停止時に設定を書き戻していないか |
