サーバーを公開すると、必ず 2 種類の問題に直面します：**誰かが壊す・盗む**こと、そして**誰かがチートクライアントを使う**ことです。この 2 つは別の手段で対処する必要があります。

## 1. まず 2 層の防御を切り分ける

| 層 | 目的 | 手段 | 優先度 |
| --- | --- | --- | --- |
| **記録とロールバック** | 事故が起きたときに調べられ、元に戻せる | CoreProtect / Prism などの記録プラグイン | **必須** |
| **リアルタイムのチート対策** | その場でチート行為を止める | チート対策プラグイン（移動・戦闘・パケット送信を検知） | 加点要素 |
| **権限と監査** | 「管理者による濫用」を防ぐ | 権限グループ + 操作の記録 | 必須 |
| **入場のハードル** | トラブルの発生源を減らす | ホワイトリスト / 入場審査 | 規模による |

**順序が重要です**：まず「記録とロールバック」を整え、そのうえでチート対策を考えます。**記録がなければ「誰がやったのか」すら分からない**からです。また、チート対策をどれだけ強化しても取りこぼしは出ます。

## 2. 記録とロールバック（荒らし対策）

この種のプラグインの仕組みは、**ブロック・コンテナ・エンティティ・コマンドなどの操作をすべてデータベースに記録する**ことです。記録があれば、あとから次のことができます：

- あるブロックが**誰にいつ**破壊・設置されたかを調べる；
- あるプレイヤーが**最近何をしたか**を調べる；
- 時間やプレイヤー単位で**まとめてロールバック**する（壊された範囲を元通りにする）；
- コンテナ（チェスト）の出し入れの記録を調べ、窃盗かどうかを判断する。

おすすめの構成：

- **CoreProtect**：最も普及しているブロック記録プラグインです。付属の検索コマンドとロールバックコマンドを組み合わせて使います。
- **InvSee** 系のプラグインを組み合わせてプレイヤーのインベントリを確認する（盗品の調査）こともできます。
- **Prism** などは同種の代替手段です。

:::tip 記録プラグインは早めに入れる
記録できるのは**導入したあと**の出来事だけです。壊されてから入れたのでは、それ以前のことは一切調べられません。
:::

## 3. リアルタイムのチート対策

主流なのは**サーバー側のチート対策プラグイン**で、プレイヤーのパケット送信の挙動を解析して異常（速度超過の移動、テレポート、攻撃距離の超過、自動照準など）を判定します。代表的なものに Grim、Matrix、Vulcan、Spartan などがあります。

選定と設定のときの注意点：

- **まず記録モードで動かす**：ほとんどのチート対策は「記録だけして処罰しない」モードを備えています。**しばらく観察してから**処罰を有効にしてください。
- **誤検知は見逃し以上にプレイヤーを傷つける**：正常なプレイヤーがキックされ、押し戻され、さらには BAN されれば、そのまま離れていき低評価が残ります。**多少の見逃しを許容しても、大規模な誤検知は避ける**べきです。
- **オフラインモードではチート対策の意味が限られる**：ID を変えればやり直せるため、アカウント BAN の抑止力は大きく下がります。
- **クライアント側のチート対策**：専用クライアントの導入を求めて検証するサーバーも少数あります。防御力は高いですが**ハードルが非常に高く**、競技向けの閉鎖的なサーバーに向いています。
- **プラグインの競合**：チート対策プラグインはプロトコルに深く介入するため、一部のプラグイン（とくに移動・戦闘のロジックを変更するもの）と競合しやすくなります。**導入後はログを観察**してください。

## 4. 権限と内部の管理

外部を防いでも、内部の失敗も同じくらい致命的です：

- **OP を気軽に渡さない**：バニラの OP は権限が非常に強いです。権限プラグイン（LuckPerms）で**パーミッションノード**ごとに細かく許可するほうが、OP を渡すよりはるかに安全です。
- **管理操作は記録を残す**：誰が BAN したか、誰がアイテムを渡したか、誰がワールドを変更したかは、すべて追跡できるべきです。
- **1 人による独裁を避ける**：管理権限が 1 人に集中していると、その人に問題が起きたり離脱したりした時点でサーバーは非常に苦しくなります。
- **定期的に監査する**：OP の一覧、権限グループ、ホワイトリストに、いるべきでない人がいないか確認します。

## 5. ハードルを前倒しする

「事後の処理」より手間がかからないのは、**トラブルをそもそも入れない**ことです：

- **ホワイトリスト / 入場審査**：小規模で質の高いサーバーでよく使われ、荒らしやチートの大半を防げます。
- **ルールを明示する**：禁止事項と処罰の方法をはっきり書いておけば、対応するときに筋が通ります。
- **新規プレイヤーの観察期間**：新しいアカウントには一部の権限を制限し（たとえば当面は特定のコンテナを使えないようにする）、一度きりの破壊のリスクを下げます。

## 6. 現実的な結論

**100% チートを止められる対策は存在せず**、100% 荒らしを防げる保護もありません。だからこそ本当に頼れるのは、次の 3 つの組み合わせです：

```
記録プラグインを早めに入れる（調べられる・戻せる）
   + チート対策を慎重に設定する（誤検知を出さない）
   + 定期的に遠隔地へバックアップする（最悪の場合は全体をロールバック）
```

この 3 つのうち、**バックアップが最後の砦**です（「バックアップと復元」を参照）。
