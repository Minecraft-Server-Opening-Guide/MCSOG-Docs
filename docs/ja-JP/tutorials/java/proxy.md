サーバーが「1 台」から「一群」（ロビー + サバイバル + ミニゲーム…）になったら、**プロキシ**で入り口を統一します。

## 1. プロキシの役割

プロキシは**自力でワールドを動かしません**。やることは 1 つだけ：**プレイヤーの接続を受け取り、バックエンドのサブサーバーへ転送する**ことです。

```
プレイヤー → プロキシ（Velocity / BungeeCord）
              ├→ ロビーサーバー
              ├→ サバイバルサーバー
              └→ ミニゲームサーバー
```

利点：

- **入り口の統一**：プレイヤーはアドレスを 1 つ覚えるだけで済み、サブサーバーを切り替えても切断・再接続が不要です。
- **アカウント認証の統一**：正規アカウント認証をプロキシ側で 1 回だけ行い、バックエンドはすべてオフラインモードにします（内部で信頼）。
- **保守が楽**：サブサーバーを増やすときはプロキシの設定に 1 行登録するだけで、プレイヤーには何も感じさせません。
- **リソースの分離**：ロビー、ログインサーバー、ミニゲームをそれぞれ独立に再起動でき、他のサーバーに影響しません。

## 2. どれを選ぶか

| プロキシ | 説明 |
| --- | --- |
| **Velocity** | 現代的な方式で、**性能がよく活発**。新規プロジェクトはこれを優先。モダンフォワーディング（modern forwarding）に対応し、認証情報を鍵で安全に受け渡す |
| **BungeeCord** | 老舗の方式。エコシステムが成熟し情報も非常に多い。多くの古いチュートリアルがこれ前提。既存の古いサーバーを保守する場合に |

> 考え方は同じで、違いは設定の細部と転送の仕組みです。**新規構築なら Velocity をおすすめします**。

## 3. 構築の要点

### 1. プロキシ

- プロキシの jar をダウンロードし、専用のディレクトリに置いて起動スクリプトから実行します。
- 設定に**サブサーバーの一覧**（名前 + 内部アドレス + ポート）を登録します。
- 正規アカウント認証は**プロキシ側だけで有効**にします：プロキシは `online-mode=true`、サブサーバーは必ず `online-mode=false`。

### 2. サブサーバー

サブサーバーはプロキシに「信頼を委ねる」、つまり**プロキシからの接続だけを受け入れる**必要があります：

- **Velocity**：**モダンフォワーディング**を使い、プロキシとサブサーバーに同じ `forwarding.secret` を設定し、サブサーバー側で対応する転送モードを有効にします。
- **BungeeCord**：サブサーバーの設定で `bungeecord: true` を有効にし（Spigot 系）、サブサーバー自身の正規アカウント認証を無効にします。

### 3. 重要なセキュリティポイント

:::warn 転送用の鍵はサーバーの鍵そのもの
サブサーバーがプロキシの転送を信頼した時点で、**鍵を知っている人は誰でも任意のプレイヤーになりすまして入れる**ようになります。したがって：

- `forwarding.secret` は**漏らさない・公開リポジトリにコミットしない**；
- サブサーバーのポートは**インターネットに直接公開しない**。プロキシのあるマシンからのアクセスだけを許可します（ファイアウォールで送信元を制限）。
:::

## 4. 注意事項

- **プラグインは置き場所を区別する**：プロキシ側に入れるもの（クロスサーバーチャット、全体権限）と、サブサーバー側に必ず入れるものがあります。置き場所を間違えると「コマンドは存在するのに反応しない」状態になります。
- **プロキシで 1 ホップ増える**：プレイヤーの遅延はわずかに増えます。通常は無視できますが、経路が悪いと増幅されます。
- **MOD サーバーは混在させにくい**：プロキシの転送は MOD サーバーへの対応が限定的で、MOD サーバーのクロスサーバーには通常専用の方式が必要です。
- **インベントリ／データの同期**：サーバーをまたぐ際のプレイヤーのインベントリや位置は、プロキシとサブサーバーが協調して扱います。**サブサーバー間で同じワールドフォルダを共有しないでください**。
- **プロキシを「性能最適化」と考えない**：性能は上がりません。あくまで**構造**としての入り口の統一です。単一サーバーには不要です。

## 5. いつプロキシを導入すべきか

**導入すべき**：複数のゲームプレイ区分があり、入り口を統一したい、プレイヤーがサーバー間を自由に移動する、ロビーやログインサーバーを用意したい。

**導入すべきでない**：サーバーが 1 台だけ。**層が増えるほど故障点も増えます**。小規模サーバーにプロキシを入れるのは純粋に維持コストの増加です。
