サーバーの日常管理で行き来するのは、結局このあたりのコマンドです。**サーバーのコンソールで実行するときは `/` を付けません**が、ゲーム内のチャット欄では `/` が必要です。

## 1. 起動・停止と保存

| コマンド | 効果 |
| --- | --- |
| `stop` | サーバーを**安全に停止**（先に保存して終了）。**停止は必ずこれ。ウィンドウを直接閉じない** |
| `save-all` | すべてのワールドデータを即座に保存 |
| `save-off` / `save-on` | 自動保存の停止／再開（**バックアップの前**に停止し、書き込み途中のセーブデータを控えないようにする） |
| `reload` | データパックと一部の設定を再読み込み。**慎重に**：プラグインの状態が壊れることがある。プラグイン自身の `reload` で済むなら使わない |
| `restart` | サーバーを再起動（一部のコアのみ対応） |

:::tip 停止の標準手順
`save-all` → `save-off` → バックアップ → `stop`。ウィンドウを直接閉じると、セーブデータの破損やデータの巻き戻りが起きます。
:::

## 2. プレイヤー管理

| コマンド | 効果 |
| --- | --- |
| `list` | **現在オンライン**のプレイヤーを一覧 |
| `kick <プレイヤー> [理由]` | プレイヤーをキック。**その人はまた入り直せます** |
| `ban <プレイヤー> [理由]` | プレイヤーを BAN。**解除しない限り入れない** |
| `pardon <プレイヤー>` | プレイヤーの BAN を解除（古いバージョンでは `unban` の場合がある） |
| `ban-ip <IP>` | IP 単位で BAN（**その IP の全員が入れなくなる**。慎重に） |
| `pardon-ip <IP>` | IP の BAN を解除 |
| `op <プレイヤー>` | OP（管理者）権限を付与 |
| `deop <プレイヤー>` | OP を剥奪 |

### ホワイトリスト

```
whitelist on                  开启白名单
whitelist add <玩家>          添加
whitelist remove <玩家>       移除
whitelist list                查看名单
whitelist reload              从 whitelist.json 重新读取
```

コマンドで変更するとリストは `whitelist.json` に書き込まれます。**このファイルを直接編集した**場合は、`whitelist reload` を実行して反映させてください。

## 3. プラグインと切り分け

| コマンド | 効果 |
| --- | --- |
| `plugins`（短縮 `pl`） | プラグインを一覧。**緑 = 読み込み済み**、**赤 = 読み込み失敗**（コンソールでエラーを確認） |
| `version <プラグイン>` | プラグインのバージョンを表示 |
| `help` | ヘルプ |

あるプラグインが**赤にもならない**場合、サーバーがそれをプラグインとして認識していません。通常はファイルが `plugins/` に入っていない、拡張子が違う、コアの種類が合っていない、のいずれかです。

### プレイヤーにプラグイン一覧を見せたくない

`plugins`、`version`、`help` の 3 つのコマンドは既定で権限が開放されており、誰でも実行できます。無効にしたい場合は次のパーミッションノードを `false` にします：

```
bukkit.command.plugins
bukkit.command.version
bukkit.command.help
```

:::warn コマンドを無効にしても隠しきれるわけではない
一部のチートクライアントは **Tab 補完**の応答から、導入済みのプラグインを推測できます。本当に気にするなら、PluginHide のような非表示系プラグインを別途入れて対応する必要があります。
:::

## 4. ゲーム内でよく使う管理コマンド

| コマンド | 効果 |
| --- | --- |
| `gamemode <モード> [プレイヤー]` | ゲームモードを切り替え |
| `tp <プレイヤー> <目標>` | テレポート |
| `give <プレイヤー> <アイテム> [数量]` | アイテムを渡す |
| `time set day` / `weather clear` | 時刻／天気の調整 |
| `difficulty <難易度>` | 難易度の変更 |
| `gamerule <ルール> <値>` | ゲームルールの変更 |
| `say <内容>` | サーバーの立場で放送 |
| `whitelist` / `op` など | 同上（ゲーム内では OP が必要） |

## 5. 権限と Tab 補完

- バニラサーバーは **OP レベル**で権限を制御します。権限プラグイン（LuckPerms など）を入れると、**パーミッションノード + 権限グループ**による細かい制御に変わり、OP を渡すよりずっと安全です。
- **Tab 補完**はコマンドと引数を補完してくれ、「このコマンドが存在するか」を確かめる最速の方法です。プレイヤー側もこれを使って、サーバーにどのプラグインが入っているかを知ることができます（上記参照）。
