ここまでの記事は「サーバーが起動するか」「荒らしを防げるか」の話でした。この記事では別の種類のプラグインを扱います。ゲームプレイのルールは変えないものの、プレイヤーが**目にする画面**を直接左右するものです——チャット欄、チェストのメニュー、サーバーリストに並ぶ 2 行のテキスト、そして拠点上空に浮かぶホログラムです。

この種のプラグインは設定を間違えてもサーバーが落ちることはなく、ただ「見た目がおかしい」だけなので、最も見過ごされがちです。しかし、プレイヤーがサーバーに入って最初に触れるものこそ、これらなのです。

## 1. チャットプラグイン：見た目だけではない

チャットプラグインの役割は、**プレイヤーが送ったチャットを引き取り**、ルールに従って組み立て直してからブロードキャストすることです。

最も分かりやすい機能は書式で、メッセージに接頭辞・接尾辞・称号を付けたり、プレーンテキストを色付きの内容に置き換えたりできます。しかしチャットプラグインを**管理ツール**にしているのは、次のような機能です：

| 機能 | 解決する問題 |
| --- | --- |
| 複数チャンネル | 通常・全体・個人・管理チャンネルを分離。管理者の発言を一般プレイヤーと区別できる |
| 不適切語句のフィルタ | 暴言や宣伝を自動で遮断。**チャットに限らず**、看板や金床の命名など入力口もまとめて対象になる |
| チャットのクールダウン | 発言間隔を制限し、連投を防ぐ |
| メンション通知（@） | 名指しされたときに効果音やタイトルで通知し、見落としを防ぐ |
| 個人チャットの監視 | 管理者が監視モードを切り替え、個人チャットでの嫌がらせや取引トラブルを調査できる |
| 色の権限 | 誰がどの色コードを使えるかを権限で制御し、全員が使える「レインボー連投」を防ぐ |
| アイテム表示 | チャットで手持ちのアイテム、インベントリ、果てはエンダーチェストまで表示でき、取引や質問の説明を大幅に省ける |
| 変数のサポート | PlaceholderAPI と連携すると、チャットに残高やオンライン人数などのリアルタイムデータを表示できる |

**チャットプラグインはサーバーで最も安上がりな審査手段です**。これがなければ画面を人が見張るしかありませんが、あればルールは設定によって実行されます。

### 主なチャットプラグインの比較

| プラグイン | 位置づけ | 注目すべき点 |
| --- | --- | --- |
| **TrChat** | 最も機能が揃った高機能チャットシステム | 複数チャンネル、クラウドの不適切語句辞書、アイテム表示、@ メンション、クロスサーバー（Bukkit / BungeeCord / Velocity）、正規表現置換、PlaceholderAPI。バージョンは 1.8 から最新まで対応 |
| **Carbon** | モダンな設計のチャットプラグイン | 構造が明快で拡張性が高い。「機能の積み上げ」ではなく「きれいな実装」を求める場面に向く |
| **InteractiveChat** | チャットの**拡張**で、通常は他の書式プラグインと併用 | 核となるのはインタラクション：`[item]`、`[inv]`、`[ender]` などのキーワード、カスタムのホバーとクリック、プレイヤー名のインタラクション、クロスサーバー通知、RGB カラー |
| **HuskChat** | クロスサーバーチャット | 開発は終了しており、新しいプロジェクトでは第一候補にしない |

:::tip まず何が欲しいかを決める
チャットに「接頭辞と色」が欲しいだけなら、**基本プラグイン**（EssentialsX / CMI など）で実現できます。チャットプラグインを別途入れる必要があるのは、**複数チャンネル**、**内容のフィルタ**、**クロスサーバー**の 3 つが必要な場合です。
:::

:::warn 前提を忘れずに
チャットプラグインはほぼすべて変数を使います。書式に「残高」「オンライン人数」などを書きたい場合は、先に **PlaceholderAPI** を入れ、対応する拡張を導入してください。そうしないとプレースホルダーがそのまま文字列として表示されます。詳しくは [プラグインの前提と依存関係](/tutorials/java/plugin-deps) を参照。
:::

## 2. メニュープラグイン：コマンドをチェスト画面にする

メニュープラグイン（GUI メニュー、チェストメニューとも呼ばれます）がやることは、**設定ファイルでチェスト画面を記述する**ことです。各スロットが 1 つのアイコンで、クリックすると 1 つのアクションが実行されます。

これが解決するのは非常に現実的な問題——プレイヤーはコマンドを覚えられない、ということです。新規プレイヤーに `/warp shop` や `/kit starter` を暗記させるより、チェストを渡してアイコンをクリックしてもらうほうがよいのです。

典型的な用途：

- **サーバーのナビゲーション**：メインメニューからショップ、テレポート、イベント、ルールへ
- **ショップと交換**：物々交換、代金を引いてから配布、購入数の制限
- **ギフトとデイリーログイン**：権限やクールダウンに応じてアイテムを配布
- **プレイヤー情報パネル**：自分の統計、残高、称号を表示

### メニュープラグインの比較

NitWikit はメニュープラグインを機能の強さで一列に並べています：**ChestCommands < DeluxeMenus < TrMenu**。

| プラグイン | 強さ | 説明 |
| --- | --- | --- |
| **ChestCommands** | 入門レベル | 歴史が非常に古く、基本的に 1.7 / 1.8 の古いサーバー向け。新しいバージョンでは機能が明らかに不足する |
| **DeluxeMenus** | 主力レベル | 設定駆動でドキュメントも充実。ほとんどのサーバーにとっての「これで足りる」選択 |
| **TrMenu** | 高機能 | 機能も性能も強力で、条件判定、サブアイコン、Kether スクリプトに対応。v2 は更新停止のため、**コミュニティが保守する v3** を使う |
| **Invero** | 見た目重視 | スクロールウィンドウ、フレーム単位のアニメーション、インタラクティブスロットなどを提供し、「バニラのチェストに見えない」画面を作るのに向く |

:::note ビジュアルエディタについて
メニュープラグインにビジュアルエディタは**ありません**し、必要もありません。テキストエディタでドキュメントに従って設定ファイルを書けば十分です。いわゆる「メニューエディタ」は、YAML を生成する補助ツールか、あるいは理解できない設定を埋め込むだけのものです。
:::

:::tip メニュープラグインは変数と権限に依存する
メニュー内の「残高を表示」「VIP にのみ表示」といった効果は、**PlaceholderAPI** と権限プラグインに支えられています。メニュープラグインを入れる前にこの 2 つの土台を整えてください。そうしないと、メニューは開けど中身がすべて死んでいます。
:::

## 3. MOTD：サーバーリストでの第一印象

プレイヤーがまだサーバーに入る前、最初に見るのは**マルチプレイのサーバーリスト**にあるあなたのサーバーの 1 行です。アイコン、名前、2 行の説明、オンライン人数。これらをまとめて **MOTD** と呼びます。

バニラの `server.properties` では 2 行のプレーンテキストしか書けず、色も限られます。MOTD プラグインが補うのはまさにこの部分です：

- **グラデーションと色付きの文字**、および太字・斜体などのスタイル
- **複数行の内容**と自動ローテーション
- **ランダムローテーション**：リストを更新するたびに違う MOTD を表示し、告知を順番に出せる
- **オンライン人数の偽装**：リスト上の数字を別の値として表示する
- **条件による表示**：プレイヤーや状態に応じて違う内容を見せる

| プラグイン | 説明 |
| --- | --- |
| **MiniMOTD** | 対応範囲の広い MOTD プラグイン。Bukkit / Spigot / Paper 系とプロキシのどちらでも使え、ランダムローテーションがよく使われる機能 |

:::warn 名前だけ変えて終わりにしない
MOTD は**プレイヤーが「このサーバーはまだ生きているか」を判断する最速の根拠**です。2 行が空、あるいは「名称未設定のサーバー」、人数が 0 と表示されるサーバーは、中身がどれだけ良くてもクリックされることはほとんどありません。10 分かけて分かりやすい MOTD（**サーバーの種類 + 特徴 + 連絡先**）を書くことは、費用対効果の最も高い改善の 1 つです。
:::

## 4. ホログラム：任意の飾り

ホログラム（浮遊文字）とは、ある位置に固定され、常にプレイヤーの方を向く浮遊テキストです。表示用のエンティティやアイテムを含むこともあります。

これは**あれば嬉しい**類のもので、よくある使い方：

- 拠点のスポーン地点での歓迎メッセージとルールの要約
- ショップの看板に直接価格を表示し、看板を 1 枚省く
- ランキング、イベントのカウントダウン
- テレポート地点やランドマークの表示

| プラグイン | 説明 |
| --- | --- |
| **DecentHolograms** | 軽量だが機能は十分。設定項目が多く、ダメージ表示や回復表示などの任意機能もある。**現在の第一候補** |
| **HolographicDisplays** | 老舗のホログラムプラグイン。リポジトリはアーカイブ済みで新しいコミットはない。古いサーバーではまだ使われているかもしれないが、新規プロジェクトでは DecentHolograms を選ぶべき |

:::note 一部の制限はゲーム自体に由来する
ホログラムのいくつかの「難点」はプラグインの問題ではなく、Minecraft の制限です。テキストは**常にプレイヤーの方を向き**、文字サイズとフォントを個別に調整できません。一部のエンティティ（浮遊アイテムのアイコンなど）は自ら回転し上下に浮遊し、音まで出します。プラグイン側では解決できず、リソースパックによるカスタムフォントなどの回避策しかありません。
:::

## 5. 入れる前に順序を決める

これらのプラグインには依存関係があるため、次の順序で入れることをおすすめします：

1. **前提**：PlaceholderAPI、権限プラグイン、経済プラグイン（[プラグインの前提と依存関係](/tutorials/java/plugin-deps) を参照）
2. **基本プラグイン**：メニューから呼ばれる warp や kit などのコマンドを提供
3. **チャットプラグイン**：チャットの書式を決め、変数の位置を確保する
4. **メニュープラグイン**：コマンドを画面として包む
5. **MOTD プラグイン**：最後に対外的な見せ方を調整
6. **ホログラム**：ワールドとショップの位置が決まってから。そうしないと 1 回変えるたびに 1 回移すことになる

:::tip 一度に 1 つだけ入れる
これらのプラグインはどれもプレイヤーに見えるテキストを変えます。3 つ同時に入れてから調整すると、どのプラグインが出力しているのか分からなくなります。1 つ入れて、再起動して、効果を見てから次を入れてください。
:::
