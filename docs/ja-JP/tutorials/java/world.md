サーバーの「ワールド」は、サーバーのディレクトリにある `world` フォルダだけではありません。地形を変えたい、ある区域を保護したい、ロビーと資源ワールドを同時に動かしたい —— そうなると**ワールド管理**系のプラグインが必要になります。これらはたいてい一緒に導入され、たいてい一緒に問題を起こします。

## 1. ワールド管理に含まれるもの

| 需要 | 代表的なプラグイン | ひとこと説明 |
| --- | --- | --- |
| 地形と建築の編集 | WorldEdit / FastAsyncWorldEdit | 選択ツールでブロックを一括変更し、建築をコピー＆ペーストする |
| 区域の保護とワールドルールの設定 | WorldGuard | 特定の区域を特定の人だけが触れるようにする |
| 複数ワールドの同時運用 | Multiverse-Core | ワールドの作成・削除・インポート、ワールド間テレポートの管理 |

この 3 つはかみ合っています：WorldGuard は WorldEdit（または FAWE）に依存し、WorldEdit の選択コマンドが区域保護の土台になります。そのため通常は 1 セットで入れ、1 つだけ選んで入れることはしません。

## 2. WorldEdit の基礎

WorldEdit は通称「木の斧」で、ほぼすべての建築と管理作業の出発点です。中心となる概念は 2 つだけ：**まず選択し、それから操作する**。

### 選択

```
//wand              選択ツールを取得（既定は木の斧）
//pos1  //pos2      現在位置を 1 つ目 / 2 つ目の角に設定
//hpos1 //hpos2     照準が指すブロックを角に設定
//expand 10 up      選択範囲をある方向へ指定ブロック数だけ拡張
//size              選択範囲のサイズとブロック総数を表示
//limit 100000      1 回の操作あたりのブロック上限を自分に設定
```

ブロックを左クリックして 1 つ目の角、右クリックして 2 つ目の角を選ぶのが最も一般的な方法です。`//pos1` / `//pos2` は正確に立ち位置を指定したいときに便利です。

### よく使う編集コマンド

```
//set stone                 選択範囲をすべて石に置き換える
//replace dirt grass        選択範囲内の土だけを草ブロックに置き換える
//walls stone               選択範囲の四壁だけを埋める（壁を作るのに便利）
//copy  //paste             選択範囲をコピー / 現在位置に貼り付け
//undo  //redo              元に戻す / やり直す
```

### 建築の保存と貼り付け（schematic）

```
//schem save 建築名         現在の選択範囲をファイルに保存
//schem load 建築名         保存済みのファイルを読み込む
//paste                     現在位置に貼り付ける
```

ファイルは通常 `plugins/WorldEdit/schematics/` の下に置かれ、FAWE では `plugins/FastAsyncWorldEdit/schematics/` になります。コマンドの書き方がバージョンで変わる点に注意：7.x は `//schem`、それより前のバージョンは `//schematic` です。

:::tip 作業前にまず //size
`//size` はその選択範囲にブロックがいくつあるかを教えてくれます。先に一目見てから実行する習慣をつければ、「うっかりマップ全体を石に変えた」という事故のほとんどを避けられます。
:::

## 3. WorldEdit がサーバーを重くする理由

バニラの WorldEdit のブロック変更は**メインスレッドで実行**されます。つまり 1 回の `//set` の間、サーバーは他のことを処理する余力がほとんどありません：

- 選択範囲が少し大きいだけで数十万、場合によっては百万単位のブロックになり、各ブロックでライトの再計算、ブロック更新、チャンクのマークが必要になる；
- メインスレッドが長時間埋まり、全プレイヤーが一緒に重くなり切断され、ひどいときはウォッチドッグが発動してサーバーごと落ちる；
- メモリと CPU の負荷も同時に跳ね上がり、描画距離が大きいほど、オンライン人数が多いほど悪化する；
- 最もよくある引き金は**選択範囲を確認せずに実行すること**、あるいは選択範囲をマップ全体に広げてしまうこと。

有効な防御策：

- `//limit` で 1 回の操作あたりのブロック上限を自分に設定する；
- 実行前に毎回 `//size` で規模を確認する；
- 大きな作業は小さなブロック単位の操作に分割する；
- プレイヤーへの WorldEdit 権限は必要に応じて与え、既定で開放しない；
- 本当に広範囲の作業は FAWE に切り替える。

## 4. FastAsyncWorldEdit（FAWE）

**FastAsyncWorldEdit は WorldEdit の非同期最適化版**で、ブロックの変更をメインスレッドから非同期スレッドへ移して分割処理するため、サーバーが長時間止まるのを避けられます。

- WorldEdit のインターフェースを実装しているため、**通常は WorldEdit をそのまま置き換えられます**：WorldEdit を FAWE に替えても、WorldEdit に依存するプラグインはおおむね正常に動きます。
- 独自の設定もあり、プレイヤー 1 人あたりの 1 回の操作のブロック数を制限できるので、バニラよりプレイヤーへの開放に向いています。

**FAWE を使う場面**

- 広範囲の地形改造、schematic の一括貼り付け；
- 複数の管理者が同時に作業する；
- サーバー自体のプレイヤーが多く、メインスレッドが埋まるのを許容できない。

**バニラの WorldEdit でも足りる場面**

- たまに小範囲の変更をするだけ；
- 一部のプラグインが FAWE と互換性の問題を抱えており、サーバーがそれに依存している。

:::note 二者択一ではない
FAWE と WorldEdit は同じ位置を占める 2 つの選択肢で、2 つ同時に入れないでください。FAWE を入れれば WorldEdit の能力があるのと同じで、WorldGuard も正常に認識します。
:::

## 5. WorldGuard：区域を保護する

WorldGuard は管理側の区域保護プラグインで、**前提は WorldEdit または FastAsyncWorldEdit** です。すべての機能が既定で無効で、必要なものを有効にします。

主に 2 つのことをします。

**区域保護**

- 指定した区域内でプレイヤーがブロックを設置・破壊するのを防ぐ；
- 特定のプレイヤーだけが区域内で建築できるようにする；
- 区域内で PvP、TNT、モブのダメージなどを無効化する。

**ワールドルールの調整**

- クリーパーやウィザーによるブロック破壊、落下ダメージなどを防ぐ；
- 延焼、溶岩による引火、凍結、エンダーマンによるブロックの持ち去りなどの仕組みを止める；
- 特定のアイテムやブロックをブラックリストに入れる、あるいは使用時に管理者へ警告を出す；
- ゲームの仕組みを悪用したアイテム増殖の抜け穴を防ぐ；
- 「すべての延焼を即座に止める」といった実用的なコマンドを提供する。

典型的な使い方は、スポーン地点、ショップ街、イベント会場にそれぞれ区域を引き、資源ワールドには別のルールを設定する形です。区域保護の考え方と領地プラグインとの違いは [領地と保護](/tutorials/java/protection) を参照。

## 6. Multiverse：複数ワールドの同時運用

Multiverse-Core は知名度の高い老舗のマルチワールドプラグインで、**ワールド（ディメンション）の作成・削除・インポート**に使います。よくあるワールドの分け方は：ロビー 1 つ、サバイバルのメインワールド 1 つ、再生可能な資源ワールド 1 つ、クリエイティブワールド 1 つ。

本体はワールド管理だけを行い、具体的な機能は拡張プラグインで補います：

| 拡張 | 役割 |
| --- | --- |
| **Multiverse-NetherPortals** | プレイヤーが建てたネザーゲートを指定したワールドへつなぐ |
| **Multiverse-Portals** | 指定した場所へテレポートするポータルを作る |
| **Multiverse-Inventories** | ワールドごとにプレイヤーのインベントリを分離する |
| **Multiverse-SignPortals** | 看板でテレポート地点を作る |

いくつかの実用的な細部：

- **既定のワールドの生成を禁止する**：メインワールドは無効にできません。ネザーは `server.properties` の `allow-nether` を `false` に、エンドは `bukkit.yml` の `settings.allow-end` を `false` にします。これは通常、サーバーをロビーやミニゲーム専用にして余分なディメンションが不要な場合に行います。
- **ワールド名の形式がポータルの帰属を決める**：`plugins/Multiverse-Core/config.yml` に `world-name-format` があり、既定ではネザーとエンドを `%overworld%_nether` と `%overworld%_the_end` と命名します。この形式を変えたり、名前が合わないワールドを作ったりすると、それらとメインワールドの間のネザーゲート・エンドポータルの関連が切れ、ポータルが起動しても送ってもらえません。
- **ダウンロード元**：GitHub 上のバージョンは SpigotMC で入手できるものより新しいので、新機能が欲しいなら GitHub と Hangar を優先してください。
- **クラッシュの脆弱性**：初期のバージョンには特殊文字で `PatternSyntaxException` を引き起こしサーバーが落ちる問題がありました。**Multiverse-Core 4.3.1 で修正済み**なので最新版を使ってください。どうしても更新できない場合、コミュニティが対応する修正パッチを提供していました。

## 7. マルチワールドのよくある落とし穴

| 落とし穴 | 現象 | 対処 |
| --- | --- | --- |
| インベントリとゲームモード | ワールドを変えるとインベントリ、経験値、ゲームモードがついてくる、あるいは分離したいのに分離されない | **Multiverse-Inventories** でワールドごとにインベントリを分離する；各ワールドのゲームモードはワールド設定で個別に設定する |
| ポータルが勝手につながる | ネザーに建てたゲートがプレイヤーを別のワールドへ送る | **Multiverse-NetherPortals** で行き先のワールドを明示し、`world-name-format` を確認する |
| 日本語のワールド名が文字化け | ワールド名がコマンドやメッセージで文字化けする | ワールド名は必ず英字にする；日本語で表示したい場合は `worlds.yml` で `alias` の別名を設定する |
| ワールドが多すぎる | メモリとディスクの使用量が増え、起動が遅くなる | 本当に必要なワールドだけ残す；使わないワールドはバックアップしてから外す。ずっと残しておかない |
| 特殊文字でサーバーが落ちる | 特定の入力でサーバーがそのまま落ちる | 4.3.1 以上に更新する |
| スポーン地点がおかしい | 新規プレイヤーが初回に入ったとき妙な位置に落ちる | ワールドごとにスポーン地点を設定する。メインワールドのスポーン地点だけに頼らない |
| ワールドの権限 | プレイヤーが入るべきでないワールドに自由に出入りできる | 権限ノードで各ワールドへの入場を制御する。クリエイティブワールドとイベントワールドは特に制限する |

:::warn 別名は改名ではない
`alias` はプラグインの表示にしか影響せず、ワールドのフォルダ名とコマンドで使う名前は依然として英字です。日本語名にしたいときは別名を変えてください。ワールド名を直接変えると、セーブ済みのデータが対応するワールドを見つけられなくなります。
:::

## 8. おすすめの組み合わせ

| 需要 | 選択 |
| --- | --- |
| 小範囲の地形と建築の編集 | WorldEdit |
| 広範囲の作業、一括貼り付け | FastAsyncWorldEdit（WorldEdit を置き換え） |
| スポーン地点、ショップ、イベント会場の保護 | WorldGuard（必要なら WorldGuard Extra Flags で flag を補う） |
| ロビー / 資源ワールド / クリエイティブワールド | Multiverse-Core。必要に応じて拡張を追加 |
| 事故のときに調べられ、ロールバックできる | CoreProtect などの記録プラグイン |

入れたあとにまず 3 つのことをします：スポーン地点を WorldGuard の区域に入れる、資源ワールドのルールを決める、各ワールドのインベントリとゲームモードの方針が想定どおりか確認する。この 3 つをやらないと、マルチワールドは面倒を増やすだけです。
