公式の BDS は安定していますが拡張しにくいです。プラグインが欲しい、マルチコアが欲しい、カスタマイズしたいなら、サードパーティのコアを使うことになります。本記事では 3 つの主要なサードパーティコアの**導入までの道筋**を整理します。

## 1. Nukkit 系

Nukkit は「統合版の Bukkit」です：**Java で書かれ**、ネイティブのプラグインシステムを持ち、設定も簡単。そこから多くの分岐が生まれており、実際に使うときは**活発な分岐を優先**してください：

| 分岐 | 説明 |
| --- | --- |
| **Nukkit（オリジナル）** | 最も早い上流。すでに活発ではなく、新規プロジェクトには勧めない |
| **PowerNukkitX（PNX）** | 現代の主力分岐。**最新プロトコル対応 + マルチコア最適化**で、第一候補 |
| **NukkitX** | 歴史的な分岐 |
| **NukkitMot** | 歴史的な分岐 |
| **PM1E** | PocketMine に関係する歴史的な分岐（その来歴にはコミュニティで議論がある） |
| **PNX** | PowerNukkitX の略称 |

**準備**：Nukkit 系は Java のプログラムなので、**Java の導入が必要**です（Java 版と同様。「環境準備（Windows と Linux）」の Java の節を参照）。

**導入**：コアの jar をダウンロード → ディレクトリに入れる → 起動スクリプトを書く（`java -jar <core-name>.jar`）→ 初回起動で設定ファイルが生成される → プラグインを `plugins/` に入れる。

### PowerNukkitX が選ぶ価値のある理由

- **マルチコア最適化** —— BDS に対する最大の利点で、BDS の演算はほぼシングルコアに載る；
- **最新の統合版プロトコルに対応**し、長く待たなくてよい；
- **384 ブロックのワールド高さ**、**Terra** 地形生成器を内蔵；
- **完全オープンソース、API 公開**。Java / Kotlin / Scala / Python / JavaScript / Lua でプラグインが書ける；
- **Nukkit エコシステムの多数のプラグインと互換**。

代償：プラグインも設定項目も多く、**初心者には学習曲線が急**。開発の勢いは上流チームの異動に影響されます。

## 2. PocketMine-MP（PMMP）

**PHP** で書かれた統合版サーバーで、**プラグインのエコシステムが最も大きい**。

**準備**：**PHP の実行環境**が必要です（Java ではない）。公式ドキュメントに従って対応する PHP のバージョンを入れ、関連する拡張を設定することを勧めます。

**導入**：PMMP をダウンロード（通常は `.phar` ファイル）→ PHP で起動（`php PocketMine-MP.phar`）→ 設定とディレクトリが生成される → プラグインは `plugins/` へ。

**利点**：プラグインが非常に多く、クロスプラットフォームで、**PHP が書ければプラグインが書ける**。コミュニティも活発で、カスタマイズの自由度が高い。

**欠点**：**高負荷時に性能のボトルネック**がある（メモリ管理と CPU 効率）。更新が遅れがち。プラグインを入れすぎると安定性が下がる。PHP はインタプリタ言語なので**リソース消費がより目立つ**。

:::tip Nukkit 系か PMMP か？
- **Java に詳しく**、**より良い性能**が欲しい → **PowerNukkitX**
- **PHP に詳しく**、**既成プラグインの多さ**が欲しい → **PocketMine-MP**
- どちらも詳しくない → まず **BDS** で動かし、それからサードパーティを検討
:::

## 3. そのほかのサーバー

上記以外にも、コミュニティには小規模・特定用途のコアがあります：

| コア | 位置づけ |
| --- | --- |
| **Allay** | コミュニティが開発する統合版サーバー |
| **Dragonfly** | Go 言語で書かれた統合版サーバー。性能志向 |
| **MCPEServer** | 初期の統合版サーバー |
| **WaterDogPE** | **プロキシ**（Java 版の Velocity / BungeeCord に相当）。複数サブサーバーの相互接続に使う |

> 小規模コアは**プラグインのエコシステムとドキュメントが薄い**ことが多く、問題が起きたときに頼りにくいです。明確な理由がない限り、**初心者には勧めません**。

### WaterDogPE：複数サブサーバーでのみ必要

Java 版と同じく、統合版にも**プロキシ**があります：自分ではワールドを動かさず、プレイヤーをバックエンドのサブサーバーへ転送するだけです。「ロビー + サバイバル + ミニゲーム」のような複数サーバー構成に向きます。**単一サーバーには不要**で、層が増えれば故障点も増えます。

## 4. 共通の提案

1. **バージョンを揃える**：コア、プロトコル、プラグインの 3 つのバージョンを揃える必要があり、統合版はこの点で Java 版よりずっと厳格です。
2. **小さく始めて大きくする**：まず最小限の使えるサーバーを動かし、それから段階的にプラグインを足す。
3. **活発さを見る**：**最近も更新されている**コアとプラグインを優先する。長期間更新されていないものは新バージョンで必ず落ちます。
4. **バックアップ優先**：サードパーティコアのセーブデータ互換性は公式に劣るため、**アップグレードやコア変更の前に必ずバックアップ**（「バックアップと復元」を参照）。
