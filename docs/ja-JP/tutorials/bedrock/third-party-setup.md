[サードパーティコア（Nukkit / PNX / PMMP）](/tutorials/bedrock/third-party) の記事は「どれを選ぶか」でした。本記事は「選んだあとどう動かすか」です：何を用意するか、ディレクトリはどうなっているか、起動スクリプトの書き方、プラグインの置き場所、そして最も失敗しやすい手順 —— **コアのビルドと統合版のプロトコルバージョンが合わない**こと。

## 1. 着手前に確認する 3 つのこと

| 確認すること | 説明 |
| --- | --- |
| **コアの系統** | Nukkit 系は **Java** のプログラム、PocketMine-MP は **PHP** のプログラム。系統を間違えると、後ろの実行環境をすべてやり直しになる |
| **実行環境** | Nukkit 系は **Java**、PMMP は **PHP**。互いに代替できない |
| **バージョンの整合** | コアのビルドが**接続する統合版のプロトコルバージョンと合っている**必要がある。合わないとクライアントはそのまま接続できない |

### Java 環境（Nukkit 系）

Nukkit 系は Java 版サーバーと同じく Java のプログラムなので、Java 版と同じ考え方で入れれば十分です。[環境準備（Windows と Linux）](/tutorials/java/environment) を参照。

2 つの要点：

- **バージョンが十分であること**：新しい分岐は通常より新しい Java を要求します（多くは Java 17 以上）。古すぎると起動に失敗し、エラーメッセージに要求が書かれているのが普通です。
- **ビット数を合わせること**：64 ビットの OS には 64 ビットの Java。32 ビットを入れるとメモリ上限のため起動時や実行中に落ちます。

### PHP 環境（PocketMine-MP）

PMMP に必要なのは **PHP** で、Java ではありません。

:::tip PMMP が同梱する PHP を使い、環境を自分で組み立てない
PHP 公式サイトが提供するのは**素の PHP** で、PMMP が必要とする拡張は既定では入っていません。依存を 1 つずつ足すのは非常に面倒で、バージョンが増えるほど混乱しがちです。**PMMP 公式が各 OS 向けにパッケージした PHP ランタイムをそのままダウンロードする**ことを勧めます（GitHub Releases で自分の OS 向けのファイルを取る）。解凍すればすぐ使えます。
:::

:::warn OS 標準の PHP を使わない
Linux ディストリビューションのリポジトリにある PHP は古いことが多く、Windows でも他のソフトが入れた PHP が残っていることがあります。まず `php -v` の出力を確認し、サーバーを起動するときに**使うつもりのあれ**が呼ばれていることを確かめてください。
:::

## 2. ディレクトリ構成：Nukkit 系 vs PocketMine-MP

### Nukkit 系

初回起動後、ルートディレクトリはおおよそ次のようになります（分岐によって多少異なります）：

| ファイル / ディレクトリ | 役割 |
| --- | --- |
| `nukkit-1.0-SNAPSHOT.jar` の類 | **コアプログラム本体**。これを起動する |
| `start.bat` / `start.sh` / `start.command` | 起動スクリプト。それぞれ Windows / Linux / macOS に対応 |
| `server.properties` | 主要な設定ファイル：サーバー名、ポート、最大人数、ゲームモードなど |
| `permissions.yml` | 権限の定義 |
| `ops.txt` | 管理者（OP）の名簿 |
| `whitelist.txt` | ホワイトリストの名簿（`server.properties` でホワイトリストを有効にしたあと有効） |
| `banned-players.txt` / `banned-ips.txt` | BAN されたプレイヤーと IP |
| `rcon_password.txt` | RCON 遠隔コンソールのパスワード |
| `worlds/` | **ワールドのセーブデータの総ディレクトリ**。ワールドごとに 1 つのサブフォルダ |
| `plugins/` | **プラグインディレクトリ**。`.jar` を置く |
| `logs/` | 実行ログ |

ワールドディレクトリ `worlds/<ワールド名>/` の中身：

| ファイル / ディレクトリ | 内容 |
| --- | --- |
| `level.dat` | ワールドの基本設定 |
| `region/` | **チャンクデータ**（地形、建築。最も容量が大きい） |
| `entities/` | エンティティのデータ |

:::warn セーブデータは `worlds/` ごと
BDS と同じく、統合版のセーブデータは**まとまり**です。バックアップでは `worlds/` 全体をコピーし、`region/` だけを選ばないでください。
:::

### PocketMine-MP

PMMP のディレクトリも考え方は似ていますが、ファイルの形態が違います：

| ファイル / ディレクトリ | 役割 |
| --- | --- |
| `PocketMine-MP.phar` | **コアプログラム本体**（`.phar` は PHP のパッケージ形式） |
| PHP ランタイム | ランチャーと `php` 実行ファイル。公式のパッケージ版なら同じディレクトリにある |
| `start.bat` / `start.sh` | 起動スクリプト |
| `server.properties` | 主要な設定ファイル |
| `pocketmine.yml` | PMMP 自身の設定 |
| `plugins/` | **プラグインディレクトリ**。`.phar` を置く |
| `worlds/` | ワールドのセーブデータの総ディレクトリ |
| `players/` | プレイヤーデータ |
| `logs/` | 実行ログ |

### 両者の対照

| | Nukkit 系 | PocketMine-MP |
| --- | --- | --- |
| コアのファイル | `.jar` | `.phar` |
| 実行環境 | Java | PHP |
| プラグインの拡張子 | `.jar` | `.phar` |
| プラグインディレクトリ | `plugins/` | `plugins/` |
| ワールドディレクトリ | `worlds/` | `worlds/` |
| 主な設定 | `server.properties` | `server.properties` |
| 管理者名簿 | `ops.txt` | コアの設定とコマンドで管理 |
| ワールドの内部構造 | `level.dat` + `region/` + `entities/` | `level.dat` + `region/` + `entities/` |

:::note 共通の落とし穴：パスに日本語や空白を入れない
どのコアでも、サーバーのディレクトリは**英数字のみ、空白なし**のパスに置くことを勧めます。日本語のパスは一部の分岐やパネルでワールドやプラグインの読み込みに失敗し、エラーも分かりにくいことが多いです。
:::

## 3. サーバーを起動する

### Nukkit 系

最小限の起動コマンドは `java -jar` の 1 行です：

```bat
@echo off
java -Xms1G -Xmx4G -jar nukkit-1.0-SNAPSHOT.jar
pause
```

Linux / macOS での等価な書き方：

```sh
#!/bin/sh
java -Xms1G -Xmx4G -jar nukkit-1.0-SNAPSHOT.jar
```

説明：

- `-Xms` は初期ヒープ、`-Xmx` は最大ヒープ。**両方を同じ値にする**ことを勧めます。実行中に何度も拡張しなくて済みます。
- `-Xmx` はマシンの物理メモリを超えないこと。超えると OS がスワップを使い始め、かえって重くなります。
- Windows では `.bat` の末尾に `pause` を付けると、落ちたあともウィンドウがすぐ消えず、エラーを見る機会が得られます。

### PocketMine-MP

```bat
@echo off
php PocketMine-MP.phar
pause
```

Linux / macOS：

```sh
#!/bin/sh
./bin/php7/bin/php PocketMine-MP.phar
```

説明：

- 具体的なパスは、公式パッケージの PHP を使うか自分で入れた環境かで変わります。**まず `php -v` で呼べることを確認**してからスクリプトに書いてください。
- メモリ上限はコマンドライン引数ではなく、`pocketmine.yml` と `server.properties` で設定します。

:::tip 初回起動で見るもの
初回起動で設定ファイルとワールドが生成されます。起動後に 2 点に注意：**コンソールにエラーがないか**、そして**ディレクトリに本当に `plugins/` と `worlds/` が増えたか**。生成されていなければコアが動いていないので、プラグインを入れる前に確認してください。
:::

:::warn メモリを一度に満額にしない
新しいサーバーはまだ誰もいないので、まず `-Xmx` を小さめ（2G など）にし、人が増えてから調整します。最初から物理メモリの上限まで与えると、OS とコアがメモリを取り合います。
:::

## 4. プラグインはどこに置き、どう読み込むか

1. プラグインの配布ページから対応バージョンのファイルをダウンロード：Nukkit 系は `.jar`、PMMP は `.phar`。
2. サーバーのルートディレクトリの `plugins/` に入れる。
3. **サーバーを再起動する**。
4. コンソールの出力を見て、プラグインが読み込まれ、エラーがないことを確認する。
5. 一部のプラグインは初回読み込み後に自分の設定ディレクトリ `plugins/プラグイン名/` を生成するので、設定を変えたらもう一度再起動します。

リロードについて：

- 多くのプラグインはリロードのコマンドに対応していますが、**リロードは再起動ではありません**。コアの設定を変えた、プラグインのバージョンを替えた、プラグイン同士がイベントを登録し合っている、といった場合、リロードは古い状態を残しがちで、「変えたのに効かない」どころかエラーになることもあります。
- 結論：**設定の変更はリロードでよいが、プラグインの追加・削除・入れ替えは必ず再起動**。

:::warn Java 版のプラグインを持ち込まない
Nukkit 系の `.jar` と Java 版（Paper / Spigot）の `.jar` はまったく別物で、**互換性はありません**。プラグイン配布サイトからダウンロードするときは、Nukkit / PNX 向けか Paper 向けかを先に確認してください。間違えると通常は「無効なプラグインファイル」とだけ出ます。
:::

## 5. 最も失敗しやすい手順：バージョンの整合

ここは統合版が Java 版よりずっと厳しい部分なので、独立して扱います。

統合版のクライアントは**自動更新**され、プレイヤーは Java 版のように古いバージョンに留まることができません。したがって：

- コアのビルドが**現在の統合版のプロトコルバージョンに対応**している必要があります。そうでないとプレイヤーには「サーバーが古すぎる」といった表示が出て、そのまま接続できません。
- コアのバージョンが合っても、プラグインも合う必要があります：プラグインはコアの API に追随するので、**コアを上げた瞬間に古いプラグインが使えなくなる**ことがあります。
- そのためサードパーティコアの更新は**一式**です：コア + プラグイン + 設定をまとめて替え、1 つだけ替えることはできません。

接続できないときの切り分け順：

| 現象 | まず確認すること |
| --- | --- |
| サーバーのバージョンが古いと表示される | コアのビルドが現在の統合版プロトコルに対応しているか |
| クライアントが「接続中」で止まる | ポートが開いているか、`server.properties` のポートと転送が一致しているか |
| 入れるがプラグインが反応しない | プラグインが読み込まれているか、バージョンがコアに合っているか |
| 入った直後にキックされる | ホワイトリストが有効か、`banned-*` に記録されていないか |

:::tip アップグレード前にバックアップ
サードパーティコアの**セーブデータ互換性は公式 BDS に劣ります**。コアを替える、メジャーバージョンを上げる前に、`worlds/` 全体と `plugins/` の設定をバックアップしてください。[バックアップと復元](/tutorials/java/backup) を参照。
:::

## 6. 導入チェックリスト

- [ ] 実行環境を入れ、コマンドラインから呼べる（`java -version` / `php -v`）
- [ ] コアのビルドが対象の統合版プロトコルバージョンと一致している
- [ ] ディレクトリのパスが英数字のみ、空白なし
- [ ] 起動スクリプトのメモリ引数が妥当
- [ ] 初回起動で `plugins/` と `worlds/` が生成され、コンソールにエラーがない
- [ ] プラグインの拡張子がコアの系統と一致している
- [ ] `worlds/` をバックアップ計画に含めた
