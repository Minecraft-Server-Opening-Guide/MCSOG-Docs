公式の **BDS** は統合版で最も安定した選択ですが、**それ自体はプラグインに対応していません**。本記事ではそのディレクトリ構成と、コミュニティのローダーでプラグイン機能を補う方法を整理します。

## 1. ディレクトリ構成

BDS は解凍すると「ポータブル」なディレクトリ一式になります。以下を押さえれば十分です：

| ファイル / ディレクトリ | 役割 | 触ってよいか |
| --- | --- | --- |
| `bedrock_server.exe` | **サーバーの起動プログラム**（Linux では `.exe` なし） | 改名はできるが**勧めない** —— 改名すると起動スクリプトやパネルの起動パスも同期して変える必要があり、間違えやすい |
| `server.properties` | サーバー設定（ポート、難易度、モードなど） | よく変更する |
| `allowlist.json` | **ホワイトリスト**の名簿（`server.properties` でホワイトリストを有効にしたあとここで管理） | 変更可 |
| `permissions.json` | **管理者（OP）**のデータ（UUID、名前、権限） | 変更可 |
| `valid_known_packs.json` | 既知のアドオンパックの一覧（ビヘイビアパック / リソースパック）。サーバーはこれで検証する | 通常は触らない |
| `worlds/` | **ワールドのセーブデータ**（ワールドごとに 1 つのサブフォルダ） | まとめてバックアップするだけ |
| `bedrock_server.pdb` | デバッグ用のプログラムデータベースファイル | 触らない |
| `bedrock_server_how_to.html` | 公式の使用説明 | 読むだけ |
| `release-notes.txt` | バージョンの更新履歴 | 読むだけ |

### ワールドフォルダの中身

`worlds/<ワールド名>/` の下：

| ファイル / ディレクトリ | 内容 |
| --- | --- |
| `db/` | **セーブデータ**（ワールドのデータベースファイル。最も容量が大きい） |
| `level.dat` | ワールドの基本設定と属性（ゲームルール、時刻、天気など） |
| `level.dat_old` | 旧版のセーブデータ設定（更新やバックアップで使う） |
| `level_name.txt` | ワールド名 |

:::warn バックアップは `worlds/` ごと
BDS のセーブデータはすべて `worlds/` にあります。**ディレクトリごとバックアップ**してください。`db/` だけをコピーすると設定が失われます。
:::

## 2. BDS にプラグインを足す：3 つの主要ローダー

公式の BDS にはプラグインの仕組みがないため、コミュニティがローダーを作って補っています。現在の主流は 3 つです：

### LeviLamina（別名 LLL / LLv3）—— **最も推奨**

- 作者：LiteLDev（前身は **LiteLoaderBDS**）
- 位置づけ：軽量、モジュール式、多機能な BDS プラグインローダー
- **推奨度：非常に推奨** —— プラグインのエコシステムが最もよく、LiteLoader 時代の最盛期を引き継いでいる
- 対応バージョン：1.20.61 – 1.21.3（更新継続中）

### EndStone —— 伸びしろあり

- 作者：EndStoneMC
- 位置づけ：**Bukkit に似た親しみやすい API** を提供し、**C++ または Python** でプラグインを書ける
- **推奨度：やや推奨** —— 現在プラグインのエコシステムは非常に少ないが、コミュニティから開発参加の声があり、今後 LeviLamina に追いつく可能性がある
- 対応バージョン：1.20.71 – 1.21.2（更新継続中）

### BDSX —— 老舗で安定

- 位置づけ：**Node.js** に対応した BDS の改造版。公式 BDS を基に、バニラの全機能を保ちつつ、関数のフックとネットワークパケットに対応
- **推奨度：比較的推奨** —— 国内のプラグインは多くないが利用者は少なくなく、作者は 2019 年から今まで維持している
- 対応バージョン：1.12 – 最新（更新継続中）

> この 3 つ以外に、公式も**スクリプトローダー**（公式のスクリプト API ベース）を提供しています。サードパーティのローダーより能力は弱いですが、公式サポートという利点があります。

### 選び方

| あなたの状況 | 提案 |
| --- | --- |
| 既成のプラグインが欲しい、エコシステム優先 | **LeviLamina** |
| C++ / Python が書けて、自分で書きたい | **EndStone** |
| Node.js に詳しい／低レベルをフックしたい | **BDSX** |
| 公式の能力だけを使い、サードパーティを足さない | 公式のスクリプトローダー |

:::warn ローダーはゲームバージョンと強く結び付く
ローダーは**特定のバージョン帯**しか対応しません。**自分のサーバーのバージョンが対応リストにあることを確認してから**入れてください。そうしないと読み込みに失敗し、起動すらしないことがあります。ゲームバージョンを上げる前にも、ローダーが追随済みか確認してください。
:::

## 3. BDS の既知の落とし穴 2 つ

1. **シングルコアのボトルネック**：モブの演算がシングルスレッド → 快適さは**シングルコア性能**次第で、マップが大きいほど重くなります。
2. **メモリがゆっくり増える**：使用量が徐々に増えます。**無理にメモリを解放しない**こと —— プレイヤーがリソースパック／Addon をダウンロードするときの進行バーが止まり、**サーバーの再起動でしか解決できなくなります**。
