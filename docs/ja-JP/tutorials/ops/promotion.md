ここまでは「サーバーが動くかどうか」の話でした。この記事のテーマは別のことです。**サーバーが動いたとして、プレイヤーはなぜその存在を知り、なぜ残るのか**。

これは非技術の記事です。[[JAVA] 運用管理](/tutorials/ops/management-java) とは補完関係にあります。あちらはサーバー開設に何が必要か、チームをどう分担するか、資金とプレイヤーをどう管理するかを扱い、こちらはそのうち **宣伝による集客**と**コミュニティ運営**の 2 点だけに焦点を当てます。コマンド、設定、プラグインの選定には触れません。プラグインの一覧が必要なときは [プラグイン入門](/tutorials/java/plugins) と [よく使う前提プラグイン](/tutorials/java/plugin-deps) を参照してください。

:::note まず期待値を正す
宣伝は「投稿を 1 本出せば終わり」の作業ではなく、**数か月続く、コンテンツに駆動される**日々の仕事です。「宣伝スレを 1 回出せば数十人が常駐する」と期待しているなら、この記事は期待を裏切ります。しかし早く裏切られるほど、サーバーは長く生き残ります。
:::

## 1. 「開設すれば人が来る」は嘘

多くの新しいサーバー主のメンタルモデルはこうです。サーバーを起動し、インターネットから接続でき、IP を公開すれば、プレイヤーは自然に来る。現実はこうです。**あなたを見つける義務のある人は誰もいません**。

あなたが直面しているのは典型的な**コールドスタート問題**で、しかも負のフィードバックループを伴います。

1. サーバーのオンライン人数が 0 人。
2. プレイヤーはサーバーリストサイトやグループで「0/20」を見て、まず「このサーバーはもう終わっている」と判断して素通りする。
3. 誰もクリックしないので、リストサイトからの露出はさらに下がる。
4. 結果、依然として 0 人。

このループで最も重要な点は、**「0 人在線」それ自体が離脱のシグナル**だということです。プレイヤーは最初の 1 人になりたくないのではなく、誰も維持していないように見える場所に時間を賭けたくないのです。だから宣伝の本当の目標は「発信すること」ではなく、**誰かが見に来たその瞬間に、残る価値があるように見せること**です。

受け入れるべき事実がいくつかあります。

| よくある考え | 現実 |
| --- | --- |
| サーバーが面白ければ自然に人が来る | 面白さはリテンションの必要条件であり、露出の十分条件ではない。あなたを知らなければ、面白いかどうかを評価できない |
| 技術があるからサーバーを開ける | 技術が解決するのは「動く」ことだけ。宣伝と運営は別の技能 |
| まず開いて、人が増えてから宣伝を考える | 人が増えてから考えても、たいていその時は来ない。宣伝素材は開設前に用意する |
| 金を払って広告枠を買えば十分 | 広告枠はクリックを買えるが、リテンションは買えない。初日の体験が悪ければ、流入が多いほど早く死ぬ |

:::warn 他人のグループで広告を連投しない
**自分と無関係な QQ グループ、Discord サーバー、掲示板、フォーラムでサーバーの IP を繰り返し貼ることは、最も早く追放・ブロック・名指しされる方法のひとつ**であり、しかもサーバーの評判を巻き込みます。プレイヤーは「あちこちで連投しているサーバー」を覚え、その反感をあなた自身に向けます。他人のコミュニティで宣伝したいなら、まずグループのルールを読み、管理者の同意を得て、まずは会話を楽しむ人になってください。**ルールが許すチャンネルだけがチャンネルであり、許さないチャンネルは迷惑行為です。**
:::

## 2. サーバーとは何かを一文で定義する

宣伝文を書く前に、まずこの空欄を埋めてください。

```
これは ______（誰）が遊ぶための ______（どんな遊び方）のサーバーで、
同種のサーバーと比べた違いは ______ です。
```

3 つの空欄にはすべて**具体的**な内容を入れる必要があります。埋められないなら、ポジショニングがまだ固まっていないということで、その状態での宣伝は「固まっていないこと」をより多くの人に見せるだけです。

### 2.1 よくあるポジショニングの類型

| ポジショニング | 対象となる層 | このポジショニングが強制する決定 |
| --- | --- | --- |
| レッドストーン技術（生電）/ 技術サーバー | レッドストーン、モブトラップ、メカニズム研究を好むプレイヤー | バニラのメカニズムをプラグインで壊せない。TPS とチャンク読み込みに極めて敏感 |
| バニラサバイバルサーバー | 1 つのワールドを長期で運営したいプレイヤー | ワールドを頻繁にリセットできない。経済と領地システムは控えめに |
| ミニゲームサーバー | いつでも 1 試合遊びたいプレイヤー | 安定した対戦人数とマッチングのリズムが必要。ロビーの体験がすべてを決める |
| RP / ロールプレイサーバー | 物語を演じ、設定を作りたいプレイヤー | シナリオ、審査、運営の人手が必要で、投入は一般のサーバーよりはるかに大きい |
| 統合版（基岩版）/ クロスプラットフォームサーバー | スマートフォン、コンソールのプレイヤー | バージョンとクロスプラットフォームの方式が使えるプラグインの範囲を決める |
| MOD サーバー | MOD パックを遊びたいプレイヤー | クライアントにも同じ MOD が必要。宣伝には MOD パックとバージョンを明記する |

### 2.2 ポジショニングがないと人が来ない理由

- **プレイヤーは 3 秒で判断します**。彼が見ているのはあなたのワールドではなく、1 行のタイトルです。曖昧なタイトルはタイトルがないのと同じです。
- **ポジショニングがなければ、宣伝は形容詞の羅列になります**。「面白い、刺激的、特典が多い、課金不要」といった言葉は、誰にとっても情報になりません。
- **集めた人が互いに衝突します**。静かに拠点を作りたいプレイヤーと、いつでも戦いたいプレイヤーを同じ場所に置けば、双方が不満を持ち、双方が去ります。
- **運営に取捨の基準がなくなります**。誰かが PVP を足そうと言い、別の誰かが技術系 MOD を足そうと言う。判断の根拠がなければ、最後は「何でも少しずつある」中途半端なものになります。

:::tip ポジショニングは取捨のリスト
ポジショニングを書くときは、「私たちがやらないこと」も書いてください。たとえば「PVP 競技はやらない」「課金による強さは売らない」「メインワールドはリセットしない」。**一部のプレイヤーを明確に断ることが、別のプレイヤーを安心させる前提です。**
:::

## 3. 中国語圏の MC プレイヤーは実際どこにいるか

以下は**カテゴリ**ごとの説明で、具体的なサイト名は挙げません。理由は単純です。**こうしたプラットフォームは盛衰し、改版し、ルールを変えます**。今日有効なチャンネルが、来年には閉鎖されているか宣伝禁止になっているかもしれません。本当に必要なのは「どの種類の場所で人を探すか」と「その場所に入る前に何を確認するか」です。

| カテゴリ | 典型的な形 | 向いていること | 投稿前に必ず確認すること |
| --- | --- | --- | --- |
| 総合フォーラム / コミュニティ系 | MCBBS に代表されるプレイヤーフォーラム。サーバー板と募集板を含む | 長文の宣伝、運営や建築家の募集 | まだ運営中か、サーバー宣伝が許可されているか、どの板に出すか、書式テンプレートの有無 |
| 動画・コラム系 | Bilibili などの動画、コラム、動態 | 実際の遊びを見せ、「このサーバーは誰かが真面目に作っている」印象を与える | 概要欄やコメント欄に IP を書けるか、商業宣伝と見なされるか、注記が必要か |
| 掲示板系 | MC 関連の各種掲示板 | 小範囲への到達、質問形式の交流 | 板のルールで宣伝が禁止されていないか、集中スレのみ許可されていないか |
| インスタントメッセージ系 | QQ グループ、Discord サーバー | 長期的な付き合い、イベント通知、サポート | グループのルール、外部リンクの可否、事前に管理者と話せるか |
| サーバーリスト / ナビサイト系 | 当サイトを含むサーバーリストとナビサイト | 受け身の流入。バージョンと遊び方で絞り込まれて見つかる | 掲載条件、タグの規定、相互リンクの要否、上位表示が有料か |
| 知人 / 配信者 / 学校コミュニティ | 友人、同級生、小規模配信者の視聴者層 | 最初の数人の実プレイヤー | 相手の意向。当然のように宣伝してくれると決めつけない |

実践的な原則がいくつかあります。

- **まず潜ってから話す**。どのコミュニティに入っても、普段どう交流しているか、管理者はどんな態度か、広告を出して処理された人がいるかを見てください。
- **1 本ごとに手を入れる**。同じ宣伝文を全プラットフォームに貼ると、たいてい体裁で失敗します（画像が切れる、レイアウトが崩れる、リンクが飲み込まれる）。
- **チャンネルごとの効果を記録する**。同じチャンネルで 3 回出しても有効な入室が一度もないなら、頻度を上げるのではなく、そのチャンネルを捨てるべきです。
- **人気を偽装しない**。偽のプレイヤー、オンライン数の水増し、クリックの購入は、短期的にはリストサイトの並びを騙せますが、長期的には必ず見抜かれ、「あのサーバーはデータを盛っている」というレッテルは剥がせません。

## 4. 合格するサーバー宣伝スレに含めるべきもの

宣伝スレの役割は「あなたのサーバーがどれほど良いか説明する」ことではなく、**プレイヤーが 10 秒で 4 つの問いに答えられるようにする**ことです。これは何か？自分に向いているか？今遊べるか？どう入るか？

| 要素 | 必ず必要な理由 | よくある誤り |
| --- | --- | --- |
| 一文のポジショニング | プレイヤーが読み続けるかを決める | 「最高のサーバー」とだけ書く |
| 対応バージョン | クライアントのバージョンが合わないと入れない | 「全バージョン」と書き、実際は 1〜2 個だけ |
| 正規アカウント認証 / オフライン | 入れるか、入りたいと思えるかを決める | 書かない、または曖昧にする |
| 遊び方の特徴 | 他との違いを説明する | プラグイン名を何十個も並べ、プレイヤーには分からない |
| ハードウェアと安定性の説明 | プレイヤーはラグと突然の閉鎖を気にする | 「絶対にラグらない」と吹き、入った瞬間にフレーム落ち |
| 参加方法 | 入室のハードルを下げる | グループ番号だけで、IP もドメインもない |
| スクリーンショットや動画 | 「本当に誰かが遊んでいる」ことを示せる唯一のもの | クリエイティブモードで撮った宣伝画像。入室時の落差が大きい |
| 規約へのリンク | 合わない人を事前に除く | 規約がグループ内にしかなく、新規に見えない |
| 連絡先 | 問題が起きたときに連絡できる | 長期間見ていないメールアドレスを載せる |
| 稼働時間と開設日 | 「新しいサーバーか、いつ人が多いか」を判断できる | 書かず、プレイヤーは幽霊サーバーだと思う |

### 4.1 穴埋めテンプレート

```
【サーバー名】______
【一文のポジショニング】これは ______ が遊ぶための ______ サーバーで、違いは ______ です
【対応バージョン】Java ______ バージョン。統合版（基岩版）の対応：______
【アカウント要件】正規アカウント認証 / オフライン（混合ログイン対応なら明記）
【遊び方の特徴】1. ______  2. ______  3. ______
【ハードウェアと安定性】設置場所：______；通常のオンライン最大：______；直近 1 か月の可用性：______
【参加方法】IP またはドメイン：______；ポート：______；グループ参加方法：______
【開設日】______（新サーバーは「新サーバー」と正直に書く。古いサーバーのふりをしない）
【規約】______（リンク）
【連絡先】______
【スクリーンショットや動画】______
```

### 4.2 よくある減点項目

- 全体に実際のゲーム画面が 1 枚もなく、サーバーのロゴと宣伝画像だけ。
- 「史上最高」「絶対にラグらない」「永久に閉鎖しない」といった検証できない約束を使う。
- プラグインの一覧を遊び方の紹介として、何十個もの名前を書く。
- レイアウトが凝りすぎて IP が読めない。
- 連絡先は載せたが、3 日間 1 通も返さない。

## 5. 動画とショート動画の戦略

動画は**現在もっとも費用対効果の高い見せ方**です。なぜなら 3 つのことを同時に証明できるからです。本当に誰かが遊んでいる、画面がどんな見た目か、サーバーがラグらない。

### 5.1 30 秒のフック

最初の 3 秒で視聴者がスクロールを続けるかが決まります。効果的な冒頭は、たいていオープニングではなく画面の結果を直接見せます。

- 視覚的インパクトの強い場面を直接見せる（大型建築、レッドストーン装置の稼働、イベントの混戦）。
- 「これは何か、なぜ見る価値があるか」を一文で示す。たとえば「全サーバー初の自動仕分け機が完成した夜」。
- 5 秒を超えるロゴアニメーションや、「〇〇サーバー宣伝映像」といったタイトルカードを入れない。

### 5.2 ロゴではなく実際の遊びを見せる

視聴者はやらせと実機を見分けられます。**カメラはプレイヤー視点の連続したプレイに置いてください**。採掘、拠点作り、取引、モブとの戦闘、イベント参加。サーバーの最も魅力的な点が「コミュニティの雰囲気」なら、チャット欄のやり取り、一緒に家を建てる過程、イベント開始前の集合を撮ってください。

### 5.3 安定した TPS が宣伝効果に影響する理由

**ラグは動画に映ります**。エンティティの痙攣、ブロックの跳ね返り、プレイヤーの瞬間移動、ブロック破壊の遅延、ドロップアイテムの堆積。視聴者は TPS が何かを知らなくても、「このサーバーは重い」と必ず感じます。

だから宣伝動画を撮る前に、サーバーの状態を確認してください。

- 録画の時間帯はバックアップ、マップ描画、大規模なワールド生成を避ける。
- [spark でサーバー性能を分析する](/tutorials/ops/spark) で TPS と MSPT が正常か確認し、重い時間帯に無理に録らない。
- 撮ったら自分で一度見返し、エンティティの動きとブロックの相互作用が滑らかか重点的に確認する。
- どうしても性能上の弱点があるなら、撮影範囲を狭めるほうがよく、編集で隠さない。

:::tip 素材は一度きりの投資で、再利用できる
1 回の録画から、30 秒のショート動画、3 分の長い動画、数枚のスクリーンショット、イベントの振り返りを切り出せます。**素材をどこで再利用するかを先に決めてから、何を撮るかを決める**ほうが、毎回その場で素材を探すよりずっと楽です。
:::

## 6. サーバーリストサイトとナビサイトへの投稿

リストサイトの価値は**受け身の流入**にあります。プレイヤーがバージョン、遊び方、オンライン人数で絞り込むときにあなたに遭遇するかもしれません。爆発的な成長はありませんが、「長期的にぶら下がっている」基礎的な露出になります。

典型的な掲載条件（サイトによって差が大きいので、投稿前に 1 条ずつ確認してください）：

| 条件 | 説明 |
| --- | --- |
| 正確なバージョンと遊び方のタグ | バージョンを間違えると、入ってみたら入れず、そのまま離脱され、低評価も付き得る |
| IP / ドメインとポート | プレイヤーが直接接続できるアドレスであること。グループ番号だけでは不可 |
| 正規アカウント認証 / オフラインの説明 | リストサイトの絞り込み条件に対応する |
| スクリーンショット | 通常は実際のゲーム内スクリーンショットが求められる |
| 紹介文 | 文字数上限があり、一文のポジショニングが試される |
| 掲載条件 | 相互リンクを求めるもの、最低オンライン人数を求めるもの、有料の上位表示があるもの |
| 情報の維持 | バージョン更新や IP 変更の後は自分から直す。さもないとプレイヤーは接続できない |

明確にすべき点が 2 つあります。

- **上位表示と広告枠は流入を買えるが、リテンションは買えません。** 金を払って人を呼び込んでも、初日の体験が悪ければ人は去り、しかも金が尽きれば流入は途切れます。
- **並び順は多くの場合、オンライン人数やクリック率と関係します。** つまり「宣伝」と「リテンション」は同じことの裏表です。人を引き止められなければ、順位は自然に下がります。

## 7. コミュニティ運営

宣伝は「来る」を解決し、運営は「残る」を解決します。運営のないサーバーでは、宣伝の効果は日単位で減衰します。

### 7.1 規約

- **少なく、明確に**。実行できる 10 条は、誰も覚えていない 50 条より優れています。
- **公開され、見える場所に**。規約はプレイヤーが誰かに聞かなくても見られる場所に置きます。[コミュニティ規範](/rules) を参照してください。
- **処分に段階を**。注意、警告、一時制限、永久 BAN。各段階の発動条件を明記します。
- **運営自身も規約を守る**。権限の濫用という指摘が一度でも出ると、どんなチートよりもプレイヤーの信頼を傷つけます。

### 7.2 初心者ガイドと初日の体験

新規プレイヤーが入室してからの最初の 5 分が、次の 5 分があるかどうかを決めます。設計目標は 1 つだけです。**10 分以内に何か 1 つを成し遂げさせる**。

- スポーン地点には明確な視覚的導線を。看板、ランドマークの建築、NPC、掲示で「どちらへ行き、まず何をするか」を伝えます。
- 最短の成長ルートを用意する。たとえば「まず初心者用ツールを受け取り、A 地区で採掘し、スポーンに戻ってクエストを納品し、最後に最初の資金を得る」。
- 初心者特典はあってよいですが、**経済を壊さないでください**。金と物資を与えすぎるのは、新人にゲーム前半を丸ごと飛ばさせることであり、成長を味わえなくすることでもあります。
- スポーン地点に看板とテレポートメニューを詰め込まない。情報過多は情報がないのと同じです。

### 7.3 新規プレイヤーの受け入れ

- **人が直接挨拶する**ほうが、自動の歓迎メッセージより百倍有効です。全体チャットで新人の名前を呼ぶ人がいれば、残る確率は明らかに上がります。
- 「当番」という考え方を導入する。少なくともある時間帯には質問に答えられる人を確保します。
- ボットによる連投の歓迎は使わない。それは新人に「ここには誰もいない」と感じさせるだけです。

### 7.4 イベントとスケジュール

- **固定のスケジュール**はランダムな開催より優れます。たとえば「毎週土曜 20:00 建築コンテスト」「毎週日曜 21:00 宝探し」。プレイヤーが予定を立てられます。
- 事前に告知し、開始 10 分前にもう一度リマインドします。
- イベントの規模は人手に合わせる。やると約束して実行できないイベントは、開催しないより傷つけます。
- イベントの記録（スクリーンショット、ハイライト、結果の告知）を残す。それは宣伝素材であり、コミュニティの記憶でもあります。

### 7.5 フィードバックの窓口

- 明確なフィードバック窓口は**1 つだけ**にし、5 つのグループで別々に叫ばせない。
- 処理結果を公開する。受領済み、修正済み、修正しない（理由も説明）。プレイヤーは拒否されることより、返事がないことを恐れます。

## 8. リテンション：プレイヤーが最初の 10 分で去る理由

離脱の大半は**入室後の最初の 10 分**に起こり、しかも理由はたいてい「遊び方が足りない」ことではありません。

| 離脱の理由 | プレイヤーの実感 | どう変えられるか |
| --- | --- | --- |
| スポーン地点が分からない | 「何をすればいいか分からない」 | 明確な案内と最短の成長ルート |
| ラグ、切断 | 「このサーバーはもうすぐ閉じるのでは」 | まず性能を解決し、それから宣伝 |
| 誰も話していない | 「ここは人がいない、死んだサーバーだ」 | 人が直接迎える、当番を確保する |
| 目標が見つからない | 「家を建てて、それから？」 | 明確な成長と目標の体系 |
| 古参に圧倒される | 「永遠に追いつけない」 | 資源格差を抑え、略奪を制限する |
| 規約が不明確で処分された | 「訳も分からず BAN された」 | 規約を公開し、処分を記録に残す |
| いつ閉じるか分からない | 「時間を投資したくない」 | 開設計画と安定性を公開する |
| 課金の強さ | 「金を払わないと遊べない」 | 次を参照 |

### 8.1 pay-to-win をやらない

課金で売ってよいのは**外見、利便性、支援者の表示**であり、**強さ**は売れません。理由は道徳的な説教ではなく、それがリテンションを直接壊すからです。

- 課金で強くなれると、無課金のプレイヤーは「このサーバーは自分のためのものではない」と判断し、去るのが合理的な選択になります。
- プレイヤーが「金で何でも解決できる」と信じた瞬間、あなたの遊び方の設計はすべて意味を失います。
- 信頼が壊れると修復は極めて難しく、しかもサーバーの評判はプレイヤーコミュニティで非常に速く広がります。

### 8.2 成長の道筋を見えるようにする

プレイヤーが「次に何をするか」を自分で答えられる道筋を示してください。短期目標（今日できる）、中期目標（今週できる）、長期目標（今月、あるいはそれ以上）。道筋は複雑でなくてよいですが、**プレイヤーが見られる場所に書く**必要があります。

## 9. コミュニティレベルでの管理と紛争処理

技術面の防破壊は [アンチチートと荒らし対策](/tutorials/java/anticheat) と [[JAVA] セキュリティプラグイン](/tutorials/ops/security-java) を参照してください。ここで扱うのは**人と人との間**の部分です。

- **処理は記録に残す**。BAN、ロールバック、処分はすべて記録を残し、「権限の濫用」という指摘を避けます。記録プラグインが証拠を提供できます。
- **手順を固定する**。個別の注意、公開の警告、一時的な処分、永久の処分と、段階を踏みます。段階を飛ばした処分は紛争を招きます。
- **感情のままに決めない**。プレイヤーがあなたを罵倒したことと、そのプレイヤーが規約に違反したかは別の問題です。
- **係争は公開で処理する**。ルール上の根拠と処理結果を公開するほうが、グループで 100 往復論争するより有効です。
- **チームの内部にも規約が必要**。運営が自分の友人に便宜を図ってはいけません。これはコミュニティが崩壊する最もよくある原因です。

チームの分担、資金、プレイヤー管理についての詳しい議論は [[JAVA] 運用管理](/tutorials/ops/management-java) を参照してください。

## 10. 追う価値のあるデータ

複雑なデータ基盤は不要で、表が 1 枚あれば十分です。**傾向を見て、単点を見ないでください。**

| 指標 | どう理解するか | 説明 |
| --- | --- | --- |
| 翌日リテンション | 今日来た新人が、明日も来るか | 初日の体験を最もよく反映する指標 |
| 7 日リテンション | 1 週間後もいるか | 成長ルートとコミュニティの雰囲気を反映する |
| 最大同時接続数 | 1 日のうち同時接続が最も多い人数 | サーバーの容量とリストサイトの並びの両方がこれを見る |
| 平均プレイ時間 | プレイヤーが 1 回入ってどれくらいいるか | 短く頻繁ならコンテンツ不足。長く安定なら定着している |
| 初日離脱率 | 入室後すぐに抜ける割合 | スポーン地点とガイドと合わせて見る |
| 流入元 | プレイヤーがどこで知ったか | 次にどこへ力を注ぐかを決める |
| チャットの活発さ | 何人が話しているか | 静かなサーバーは死んだサーバーに見える |

注意点が 2 つあります。

- **小標本を過度に解釈しない。** 1 日に 5 人来て 3 人が去ったとしても、それは何の結論にもなりません。少なくとも 2 週間の傾向を見てください。
- **データは行動に対応づけられる必要があります。** リテンションが悪いならスポーン地点とガイドを見るのであって、広告を何本も増やすのではありません。**宣伝が拡大するのは体験であり、体験を補うものではありません。**

## 11. ローンチ週のチェックリスト

開設の 1 週間前から開設後の 1 週間まで、次の表で 1 項目ずつ確認してください。

- [ ] 一文のポジショニングを書き終え、それで合わないプレイヤーを除ける
- [ ] 対応バージョン、正規アカウント認証 / オフライン、クロスプラットフォームの可否を確定し、すべての文面に書いた
- [ ] サーバーが開設前に十分な時間、連続して安定稼働し、頻繁なクラッシュがない
- [ ] 性能を確認済み（TPS、MSPT、メモリ、ディスク書き込み）。録画の時間帯はバックアップと描画を避けた
- [ ] スポーン地点に明確な案内があり、新規が 10 分以内に何か 1 つ成し遂げられる
- [ ] 規約が成文化され、公開アクセスできる
- [ ] 開設時間帯に質問へ答えられる実在の人が少なくとも 1 人いる
- [ ] 宣伝スレの素材が揃っている。ポジショニング、バージョン、アカウント要件、遊び方の特徴、安定性の説明、参加方法、スクリーンショットや動画、規約リンク、連絡先
- [ ] 目標チャンネルのルールを 1 つずつ確認し、必要なら管理者の同意を得た
- [ ] サーバーリスト / ナビサイトの情報を提出し、誤りがないことを確認した
- [ ] 30 秒の動画を少なくとも 1 本、または実際のスクリーンショットを 1 組用意した
- [ ] イベントのスケジュールを決め、開設前に公表した
- [ ] フィードバック窓口が 1 つだけで、誰かが見ている
- [ ] 課金コンテンツの一覧を確認した。外見と利便性だけを売り、強さは売らない
- [ ] データ記録表を作り、毎週決まった時間に 1 回振り返ると決めた
