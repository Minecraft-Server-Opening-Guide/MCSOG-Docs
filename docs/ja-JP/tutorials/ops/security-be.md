統合版のセキュリティモデルは Java 版と**違います**：正規アカウント認証は **Xbox Live** を通り、公式サーバーの BDS には**プラグインの仕組みがありません**。そこで本記事は 2 部に分けます：**BDS 標準の仕組み**（確実で必ず使う）と、**サードパーティコアのプラグイン体系**（柔軟だが自分で負担する）です。

## 1. BDS 標準の 3 つの仕組み（まずこれを使いこなす）

### 1. ホワイトリスト：`allowlist.json`

- `server.properties` でホワイトリストを有効にすると、名簿自体はサーバーディレクトリの **`allowlist.json`** で管理されます。
- これは統合版で**最も効果的な**敷居です：統合版のプレイヤー層は流動性が高く、サブアカウントのコストが低いので、**面倒を門の外で止める**ほうが事後の BAN よりはるかに楽です。
- 名簿を変更したら、公式の説明に従ってサーバーに再読み込みさせる（または再起動する）と反映されます。

### 2. 管理者権限：`permissions.json`

- BDS の管理者（OP）と権限は **`permissions.json`** で定義されます（プレイヤーの UUID、名前、権限項目を含む）。
- 提案：**本当に必要な人にだけ**与え、人の異動があったら速やかに回収してください。

### 3. 正規アカウント認証：`online-mode`

- BDS の `server.properties` には `online-mode` のスイッチがあります：有効にするとプレイヤーは **Xbox Live アカウントの検証**を通る必要があります。
- **公開サーバーでは無効化を勧めません**：無効にすると誰でも他人のゲーム名を騙って入れ、BAN も名前を変えれば回避できます。

:::warn 統合版には「Java 版のような成熟したログインプラグインのエコシステム」がない
Java 版のオフラインサーバーは AuthMe のようなプラグインでパスワードの扉を足せますが、統合版には**同等の地位と普及度を持つ公式／コミュニティの方案がありません**。だから統合版の正しい姿勢は：**正規アカウント認証を維持し + ホワイトリストを敷居にする**ことであり、「ログインプラグインを入れれば安全」と期待することではありません。
:::

## 2. サードパーティコアのプラグイン体系

BDS 自体にはプラグインを入れられず、拡張するにはコアを替えるかコミュニティのローダーを足すしかありません（「BDS サーバー」と「サードパーティコア」を参照）：

| 路線 | 説明 |
| --- | --- |
| **BDS + コミュニティローダー** | LeviLamina / EndStone / BDSX がプラグイン機能を提供し、ログイン、権限、管理などが作れます |
| **Nukkit 系**（PowerNukkitX を含む） | Java で書かれ、ネイティブのプラグインシステムを持つ。エコシステムは Java 版のプラグイン系と発想が近い |
| **PocketMine-MP** | PHP で書かれ、プラグイン数が最も多い。ログイン、権限、管理などのカテゴリが揃う |

:::warn 本記事は具体的なサードパーティプラグインを名指ししない
統合版のサードパーティプラグインは**エコシステムが分散し、命名が乱雑で、活発さの差が極端**であり、長期的に確認できる公式の出所を持たないものが多くあります。更新停止や出所不明のプラグインを勧めないため、本記事は**路線とカテゴリだけ**を説明します。具体的なプラグインは、その公式プラットフォームで「最終更新 + ダウンロード数 + オープンソースか」を自分で見極めてください。
:::

### プラグイン選びの 4 つのチェック

1. **まだ更新されているか**：統合版のプロトコルは数バージョンごとに変わるので、更新停止したプラグインは新バージョンで必ず落ちます。
2. **出所は公式か**：作者のリポジトリか公式のプラグイン配布サイトを優先し、二次転載の圧縮ファイルを避けます。
3. **オープンソースか／監査できるか**：セキュリティ系（ログイン、権限）はとくに実装が見えるものを。
4. **自分のコアのバージョンと合うか**：ローダーもプラグインもバージョン帯に強く縛られます（「BDS サーバー」を参照）。

## 3. クロスプレイ（Geyser / Floodgate）で生まれるセキュリティ上の注意

Geyser で統合版のプレイヤーを Java サーバーに入れるなら、セキュリティ面で追加の注意が必要です：

- **Floodgate のプレイヤー名にはプレフィックスが付きます**（既定は `.`）。**ホワイトリスト、BAN、コマンドで名前を書くときはこれを付ける**こと。付けないと見逃しや誤判定になります。
- Floodgate は統合版のプレイヤーを**Java アカウントなしで**入れるようにするので、検証の扉を 1 つ緩めるのと同じです。**必ずホワイトリストか審査と組み合わせて**ください。
- Geyser は **Java サーバー側**に入れます。逆（Java のプレイヤーが統合版サーバーに入る）には**公式の方案がありません**。

## 4. 共通の原則（Java 版と同じ）

1. **敷居を前に置く**：ホワイトリスト / 入場審査で破壊とチートの大部分を防げます。
2. **ルールは短く**：統合版のプレイヤーはスマホ中心なので、ルールは率直で実行可能に。
3. **管理は記録を残す**：誰が誰を BAN したか、誰が権限を動かしたかは、すべて追跡できるように。
4. **バックアップが最後の防衛線**：「バックアップと復元」を参照 —— BDS のセーブデータはすべて `worlds/` にあり、ディレクトリごとバックアップする必要があります。
5. **無理にメモリを解放しない**：BDS のメモリはゆっくり増えていきますが、無理に解放するとプレイヤーのリソースパック／Addon のダウンロードが止まり、再起動でしか解決できなくなります（「BDS サーバー」を参照）。
