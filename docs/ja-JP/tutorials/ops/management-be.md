統合版の運用管理は Java 版と**根本の考え方は同じ**ですが（[JAVA] 運用管理を参照）、プレイヤー層とクライアントの形態から、**個別に考える必要がある**点がいくつかあります。本記事はその違いだけを扱います。

## 1. 統合版のプレイヤー層の 3 つの特徴

| 特徴 | 運営への影響 |
| --- | --- |
| **スマホの比率が高い** | 年齢の幅が広く、**低年齢のプレイヤーが多い**。ルールはより率直に書き、サポートはより辛抱強く |
| **クライアントのバージョンを制御できない** | アプリストアが自動更新 → **プロトコルが変わると入れなくなる**（「プロトコルのバージョンとバージョン選択」を参照） |
| **プラットフォームが分散** | Android / iOS / Windows / コンソール。**プラットフォームごとに問題が違う** |

## 2. プレイヤー管理：Java 版以上に「入場の敷居」が必要

統合版のプレイヤーは流動性が高く、サブアカウントのコストが低い（とくに Android）。だから**事後の対処は非常に苦しい**：

- **ホワイトリスト / 入場審査**：強く推奨します。統合版には Java 版ほど成熟したチート対策のエコシステムがないので、**面倒を門の外で止める**ほうが事後の BAN よりはるかに有効です；
- **ルールは短く**：スマホのプレイヤーは長文を読みません。ルールは数条の明確な禁止事項で十分；
- **告知は画像で**：統合版のチャット欄は狭いので、重要な告知は画像にしてグループへ流すほうが効果的；
- **管理はオンラインで**：低年齢のプレイヤーは揉め事が多く、**同じ時間帯に誰かが待機している**ことが定着の鍵です。

## 3. クライアントの配布：統合版特有の面倒

Java 版はプレイヤーが公式ランチャーを使えば済みますが、統合版では**クライアントのインストーラーを配布**しなければならないことがよくあります：

- **Android**：`.apk` を配布できますが、**出所の合法性**に注意（クラック版を流さないこと）；
- **Windows**：`.appx` / `.msix` のインストールは初心者には難しく、**図解付きのチュートリアルが必要**；
- **iOS**：**指定したバージョンをインストールできず**、ストアの最新版しか使えない → **これは回避できない厳格な制限**（下記）。

:::warn iOS のプレイヤーは「バージョン追随者」
古いバージョンに固定した時点で、**iOS のプレイヤーは全員入れなくなります**。だから iOS 層を明確に諦めるのでなければ、**サーバーを最新版に追随させる**のが唯一現実的な選択です。
:::

## 4. プラットフォームの違いと技術サポート

| プラットフォーム | よくある問題 |
| --- | --- |
| **Android** | 一部のバージョンで**深刻なラグ**（コミュニティでも長期的に解決策なし）。インストーラーの出所が乱雑 |
| **iOS** | 最新版しか入れられない。ダウングレード不可 |
| **Windows** | RenderDragon の実装後、**従来のシェーダーが使えない**（1.18.30 以降）。appx のインストールが難しい |
| **コンソール（Xbox/PS/Switch）** | **IP を直接入力して参加できない**。通常は**カスタム DNS か LAN** 経由での接続のみ |

⇒ サポートの負荷が大きいので、**プラットフォーム別の図解チュートリアル**を事前に用意し、繰り返しの問い合わせを減らすことを勧めます。

## 5. 資金とチーム

Java 版と同じ（[JAVA] 運用管理を参照）。統合版の特徴を 2 点補足します：

- **リソース消費がより少ない**：同じプレイヤー数なら、統合版のハードウェア要件は通常 Java 版より低く、**小規模ならより安く済みます**；
- **ただしコアの選択がコストに影響する**：BDS はシングルコアが厳しい → より多くのプレイヤーを望むなら**より強いシングルコアに替える**必要があるかもしれません。サードパーティのコア（PowerNukkitX など）はマルチコアを使えますが、プラグインと安定性は自分で負担します。

## 6. 時間：依然として最大の敷居

この点は Java 版とまったく同じで、しかも統合版では**より深刻**です：

- プレイヤーはスマホ中心 → **オンライン時間がより細切れ**で、問題がいつでも出てくる；
- プラットフォームの違いが多い → 同じ問題を 4 種類のクライアントで切り分ける必要がある；
- 低年齢のプレイヤーが多い → 揉め事の調停に取られる時間が増える。

**まず自分が毎週どれだけの時間を安定して投じられるかを正直に見積もって**から、規模を決めてください。

## 7. チェックリスト

- [ ] ルールを書いた（短く、率直で、実行可能）
- [ ] ホワイトリスト / 入場審査を有効にした
- [ ] プラットフォーム別の図解チュートリアルを用意した（Android / iOS / Windows / コンソール）
- [ ] 同じ時間帯に管理がオンラインにいる
- [ ] サーバーのバージョン方針を決めた（最新版への追随を推奨。そうしないと iOS のプレイヤーを失う）
- [ ] 自動バックアップを有効にした（「バックアップと復元」を参照）
- [ ] プレイヤーの交流の場（グループ）を作り、誰かが維持している
