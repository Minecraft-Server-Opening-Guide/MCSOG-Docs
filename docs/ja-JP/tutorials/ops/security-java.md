サーバーを公開した瞬間から、セキュリティは 3 層に分かれます：**誰が誰か**（身元）、**事故が起きたとき調べられるか**（記録とロールバック）、**誰が何をできるか**（権限）。この 3 層にはそれぞれ成熟したプラグインがあり、以下では**公式リポジトリで確認できる**ものだけを紹介します。

## 1. 身元認証：AuthMe

**AuthMeReloaded** は Bukkit / Spigot 系の身元認証プラグインです（作者自身の位置づけも「Bukkit/Spigot API 向けの認証プラグイン」）。

- リポジトリ：<https://github.com/AuthMe/AuthMeReloaded>
- **いつ必要か**：**オフラインモード**（`online-mode=false`）のときだけ必要です。正規サーバーではアカウントは Mojang が検証するので、追加のログインは不要です。
- **何を解決するか**：オフラインモードでは「ID が誰にでも騙れる」ため、AuthMe は**登録 + パスワードログイン**で ID とパスワードを結び付け、騙る者は入れません。
- **解決できないこと**：オフラインモードの根本問題（BAN しても ID を変えれば回避できる、スキンと UUID を紐付けられない）は残ります。**公開サーバーでは正規アカウント認証を有効にすることを勧めます**。

:::warn オフラインモードの代償はログインプラグインを入れても消えない
ログインプラグインは「オフラインモードに扉を 1 つ足す」だけで、オフラインサーバーを正規サーバーにするわけではありません。アカウントの安全性、スキン、BAN の実効性はどれも割引されたままです。
:::

## 2. 記録とロールバック：CoreProtect

**CoreProtect** はデータ記録と破壊対策のツールです（公式の位置づけ：*blazing fast data logging and anti-griefing tool*）。

- リポジトリ：<https://github.com/PlayPro/CoreProtect>
- **何を記録するか**：ブロックの設置／破壊、コンテナの出し入れ、エンティティやコマンドなどの操作をデータベースに書き込みます。
- **何ができるか**：「この土地を誰がいつ壊したか」を調べる、あるプレイヤーが最近何をしたかを調べる、時間やプレイヤー単位で**一括ロールバック**して壊された区域を元に戻す。
- **なぜ第一優先なのか**：記録がなければ「誰がやったか」すら分からず、BAN もロールバックも始まりません。

:::tip 早く入れるほどよい
CoreProtect は**入れたあと**の出来事しか記録できません。壊されてから入れたのでは、それ以前は一切調べられません。
:::

## 3. 権限：LuckPerms

**LuckPerms** は Minecraft サーバーの権限プラグインです（公式の位置づけ：*A permissions plugin for Minecraft servers.*）。

- リポジトリ：<https://github.com/LuckPerms/LuckPerms>
- **何を解決するか**：バニラは「OP を与えるかどうか」しかなく、OP の権限は非常に強い。LuckPerms は**権限グループ + 権限ノード**で細かく制御し、誰がどのコマンドを使えるか、どのブロックに触れるかを個別に設定できます。
- **セキュリティ上の意味**：「管理者」を複数の役割（サポート、建築、イベント進行）に分け、**それぞれが必要な分の権限だけ**を持たせ、1 人が全権を得て事故を起こすのを避けます。
- **併せて行う習慣**：権限グループと OP 名簿を定期的に棚卸しする。

## 4. チート対策：Grim

**Grim** は**オープンソース、非同期マルチスレッド、予測型**のチート対策です（作者の位置づけには対応バージョン範囲 1.8–1.21 も記されており、詳細はリポジトリの現在の説明を優先）。

- リポジトリ：<https://github.com/GrimAnticheat/Grim>
- **考え方**：プレイヤーが実際に違反するのを待つのではなく、**本来あるべき位置／状態を予測**し、そこからの逸脱を判定します。そのため従来の「パケット改変」系のチートに敏感です。
- **オープンソースの利点**：判定ロジックを調べ、監査できる。ブラックボックスを盲信しなくて済みます。

:::warn チート対策の誤検知は見逃し以上にプレイヤーを傷つける
どのチート対策でも、**まず「記録だけで処罰しない」モードでしばらく観察**し、誤爆がないと確認してから処罰を有効にしてください。正常なプレイヤーがキックされ、押し戻され、さらには BAN されれば、そのまま離れていきます。
:::

## 5. 知名度ではなくカテゴリで選ぶ

| カテゴリ | 代表 | 優先度 |
| --- | --- | --- |
| **記録とロールバック** | CoreProtect | 必須（第一優先） |
| **権限** | LuckPerms | 必須 |
| **身元認証** | AuthMe（オフラインモードでのみ必要） | オフラインサーバーでは必須、正規サーバーでは不要 |
| **チート対策** | Grim など | 加点要素。慎重な設定が必要 |
| **入場の敷居** | ホワイトリスト / 入場審査 | 小規模で高品質なサーバーには強く推奨 |

## 6. 共通の原則

1. **公式チャネルからのみダウンロード**：プラグインはサーバーの権限で動く第三者製のコードで、フォーラムやグループのファイル共有で転がっている jar は最も危険です（バックドアを仕込まれている可能性）。
2. **まずテストサーバーで試す**：出所の怪しいプラグインを本番サーバーに直接入れないでください。
3. **権限は最小限に**：OP を渡さずに済むなら渡さず、権限ノードで代替します。
4. **バックアップが最後の防衛線**：チート対策も記録も「最悪の事態」は止められません。遠隔地バックアップは依然として省けません（「バックアップと復元」を参照）。
5. **管理操作は記録を残す**：誰が誰を BAN したか、誰が何を与えたかは、すべて追跡できるべきです。「管理による権限濫用」という指摘を避けます。
