## まずエディションを決める

- **Java 版**：Windows / macOS / Linux 向けの公式 Java エディションで、サーバーコアの選択肢が最も多い（Paper、Purpur、Fabric、Forge、Velocity）。
- **統合版**：スマートフォン、家庭用ゲーム機、Windows 向けのエディションで、公式サーバーは BDS、コミュニティ製は Nukkit、PocketMine-MP などがある。

2 つのエディションは Geyser + Floodgate で相互接続でき、統合版のプレイヤーが Java 版サーバーへ直接接続できます。

## おすすめの読む順番
:::step 実行環境を確認する
まず「Java 版のサーバー構築 → JDK とバージョンの対応」で Java のバージョンを確認し、そのうえでサーバーコアを決めます。
:::
:::step サーバーをデプロイする
「Linux で Paper サーバーを構築する」または「BDS 公式サーバーのデプロイ」に沿って、初回起動までを一通り動かします。
:::
:::step 基本設定を終える
「server.properties の詳細」と「ポート、ファイアウォール、トンネル（内網貫通）」を読んで、プレイヤーが接続できるようにします。
:::
:::step 長期的に運用する
「バックアップとロールバック」を設定し、「TPS / MSPT による調査」でラグの原因を特定できるようにします。
:::
:::note
リソースのダウンロードにはログインが必要です。当サイトは掲載とリンクのみを行い、リソースの著作権はすべて原作者に帰属します。
:::

### つまずきやすい 3 つの罠

1. **更新前にバックアップしていない**：コア、プラグイン、MCDR を更新する前にバックアップを取り、そのバックアップが**本当に復元できる**ことを確認してください。[バックアップと復元](/tutorials/java/backup) と [サーバー・プラグイン・MCDR の更新と保守](/tutorials/ops/updates) を参照。
2. **ホワイトリストと正規アカウント認証を設定しないままアドレスを公開した**：`online-mode` とホワイトリストが未設定のまま IP を公開するのは、サーバーを他人に明け渡すのと同じです。[サーバーの設定](/tutorials/java/config) と [ネットワークセキュリティの基礎](/tutorials/ops/network-security) を参照。
3. **新しいコアでテストせずにワールドをそのまま更新した**：ワールドを新しいバージョンで一度開いてしまうと、旧バージョンへ戻すのは困難です。必ずコピーでテストしてから、本番のセーブデータを触ってください。[サーバー・プラグイン・MCDR の更新と保守](/tutorials/ops/updates) と [Java 版のよくあるエラーとクラッシュの調査](/tutorials/faq/errors) を参照。

### 統合版サーバーだけ立てたい場合

Java 版のプラグイン関連チュートリアルは飛ばして、次の順で進めれば十分です：

1. [統合版サーバーの種類](/tutorials/bedrock/type) —— まず BDS とサードパーティコアの違いを把握します。
2. [統合版のサーバーコアの選択](/tutorials/bedrock/cores) —— 使うコアを決めます。
3. [BDS サーバー](/tutorials/bedrock/bds) または [統合版サードパーティコアの導入](/tutorials/bedrock/third-party-setup) —— 選んだコアでデプロイします。
4. [外部から接続できる環境へのデプロイ](/tutorials/java/deploy) —— 外部から接続できるようにします（ネットワーク部分は共通です）。
5. [統合版サーバーの動作不良の調査](/tutorials/faq/bedrock-issues)、[[BE] よくある質問](/tutorials/faq/faq-be) —— 問題が起きたらまずこの 2 本を。
6. [バックアップと復元](/tutorials/java/backup) —— どのエディションでもバックアップは必須です。
