このページでは 3 種類のコマンドをまとめて引けるようにしています：**Java 版のサーバーコマンド**、**統合版（BDS とサードパーティコア）のコマンド**、そして**サーバーの外側に被せる管理レイヤー**（MCDR、パネルのコンソール、RCON）です。

表の「権限」列は**バニラの既定値**です。Java 版は OP レベル、統合版はオペレーターの立場と「チート」スイッチで決まります。権限プラグイン（LuckPerms など）を入れると、実際の権限はパーミッションノードで決まり、バニラより広くなることも厳しくなることもあります。

> コマンドが使えるかどうか、権限レベルがいくつかは、**ゲームのバージョンとコアの種類によって変わります**。同じ名前のコマンドが別のコアには存在しないことも、コアによって書き換えられていることもあります。コマンドを実行する前に、実際に動かしているサーバーとゲームのバージョンの公式ドキュメントを確認してください。

:::note まず覚える 3 つのこと
- **コンソールでは通常 `/` を付けません**が、ゲーム内のチャット欄では `/` が必須です。
- **コンソールの立場は最高権限**です。ゲーム内では OP かそれに対応するパーミッションノードがあるかどうか次第です。
- **Java 版と統合版は別々のコマンド体系**です。名前が同じでも挙動が同じとは限らず、`save-all` には統合版に対応するものがありません。
:::

## 1. 表を読む前の 3 つのルール

| ルール | 説明 |
| --- | --- |
| バージョン依存 | コマンドはバージョンごとに追加・削除されます（`/tick` のような新しいコマンドは新しいバージョンにしか存在しません）。古いチュートリアルの書き方がそのまま使えるとは限りません |
| コア依存 | `plugins`、`version`、`tps`、`restart` などは**バニラのコマンドではなく**、Spigot / Paper 系のコアが提供するものです。バニラサーバーにはありません |
| プラグイン依存 | 権限プラグインを入れるとバニラのパーミッションノードが書き換えられ、コマンドエイリアスのプラグインを入れるとコマンド名が置き換わることがあります |

あるコマンドが存在するかを確かめる最短の方法は、**ゲーム内で `/` を入力して Tab 補完の一覧を見る**か、コンソールで最初の数文字を入力して補完を見ることです。補完に出てこなければ、そのコアはコマンドを登録していません。

## 2. Java 版：ライフサイクルとセーブデータ

| コマンド | 効果 | 権限 | 備考 |
| --- | --- | --- | --- |
| `stop` | サーバーを安全に終了する：先に保存してから終了 | OP 4 / コンソール | **停止はこれだけ**。ウィンドウを直接閉じたりプロセスを kill したりしない |
| `save-all` | すべてのワールドデータを即座に保存 | OP 4 / コンソール | 引数 `flush` で強制的にディスクへ書き出せる |
| `save-off` | 自動保存を停止 | OP 4 / コンソール | バックアップの前に停止し、書き込み途中のセーブデータを控えないようにする |
| `save-on` | 自動保存を再開 | OP 4 / コンソール | バックアップが終わったら戻すのを忘れずに |
| `reload` | 有効なデータパック内のデータを再読み込み | OP 2（バージョンによって異なる場合あり） | **再起動でもサーバー設定の再読み込みでもありません**。下の警告を参照 |
| `restart` | サーバーを再起動 | コア次第 | Spigot / Paper 系が提供。バニラにはこのコマンドがない |

標準の停止手順は `save-all` → `save-off` → バックアップ → `stop` です。プロセスがすでに終了している場合は `save-on` は不要です。

:::warn `/reload` は「全部再読み込み」ではなく、プラグインを壊すこともある
Java 版の `/reload` は**現在有効なデータパック内のデータ**だけを再読み込みします。次のことは**しません**：

- `server.properties` の再読み込み（ポートや難易度などの設定は再起動しないと反映されません）；
- サーバープロセスの再起動、およびプラグインのコードの再読み込み；
- プラグインが登録した内容をきれいな状態に戻すこと。

逆に、**プラグインの状態を壊す**ことがあります。スコアボード、リスナー、キャッシュ、登録済みコマンドが中途半端な状態で残り、「再読み込みしたら一部の機能がおかしくなった」という症状になります。プラグイン自身の `/プラグイン名 reload`、`/datapack enable`、`/datapack disable` で解決できるなら、バニラの `/reload` は使わないでください。変更が大きい、影響が説明できない場合は、メンテナンス時間を取って再起動してください。

統合版の同名コマンドは範囲がさらに狭く（ビヘイビアパック内の関数とスクリプトを再読み込み）、両エディションの `reload` はどちらも「サーバー設定を更新するボタン」では**ありません**。
:::

## 3. Java 版：プレイヤー、BAN、ホワイトリスト

| コマンド | 効果 | 権限 | 備考 |
| --- | --- | --- | --- |
| `list` | 現在オンラインのプレイヤーを一覧 | 全員 | 「サーバーに誰かいる？」の定番コマンド |
| `kick <プレイヤー> [理由]` | プレイヤーをキック | OP 3 / コンソール | キックされた人は**また入り直せます** |
| `ban <プレイヤー> [理由]` | プレイヤーを BAN | OP 3 / コンソール | 解除しない限り入れない |
| `pardon <プレイヤー>` | プレイヤーの BAN を解除 | OP 3 / コンソール | かなり古いバージョンでは `unban` という名前でした |
| `ban-ip <IP>` | IP 単位で BAN | OP 3 / コンソール | **その IP の全員が入れなくなります**。慎重に |
| `pardon-ip <IP>` | IP の BAN を解除 | OP 3 / コンソール | 解除前に、この IP が今誰のものか確認する |
| `banlist [ips\|players]` | BAN リストを表示 | OP 3 / コンソール | 引数を省略するとプレイヤー一覧 |
| `op <プレイヤー>` | 管理者権限を付与 | OP 3 / コンソール | 必要な人にだけ。OP はパーミッションノードよりずっと大雑把 |
| `deop <プレイヤー>` | 管理者権限を剥奪 | OP 3 / コンソール | 権限プラグイン環境でも OP は権限グループを回避できる場合がある |
| `whitelist on` | ホワイトリストを有効化 | OP 3 / コンソール | 有効化する前に自分を追加しておく |
| `whitelist add <プレイヤー>` | ホワイトリストに追加 | OP 3 / コンソール | `whitelist.json` に書き込まれる |
| `whitelist remove <プレイヤー>` | ホワイトリストから削除 | OP 3 / コンソール | 反映後、その人の次の接続は拒否される |
| `whitelist list` | ホワイトリストを表示 | OP 3 / コンソール | `whitelist.json` の内容と一致する |
| `whitelist reload` | ファイルからホワイトリストを再読み込み | OP 3 / コンソール | **`whitelist.json` を手で編集したら必ず実行** |

ホワイトリストのファイルは `whitelist.json` で、BAN と OP のリストはそれぞれ `banned-players.json`、`banned-ips.json`、`ops.json` にあります。コマンドで変更すると即座にファイルへ書き込まれますが、ファイルを手で編集した場合は対応する reload か再起動が必要です。

## 4. Java 版：ワールド、時間、ゲームルール

| コマンド | 効果 | 権限 | 備考 |
| --- | --- | --- | --- |
| `tp <プレイヤー> <目標>` | プレイヤーをテレポート | OP 2 / コンソール | 正式名は `teleport`。コンソールから実行するときは 2 つの引数を両方書く |
| `gamemode <モード> [プレイヤー]` | ゲームモードを切り替え | OP 2 / コンソール | 値は `survival` / `creative` / `adventure` / `spectator` |
| `gamerule <ルール> <値>` | ゲームルールを変更 | OP 2 / コンソール | ルール名はバージョンごとに増減する。**Tab 補完で確認** |
| `time set day` | 時刻を設定 | OP 2 / コンソール | `noon` / `night` / `midnight` や具体的な数値も使える |
| `time add <数量>` | 時刻を進める | OP 2 / コンソール | 昼夜の仕組みを調べるときは `set` より便利 |
| `weather clear` | 天気を設定 | OP 2 / コンソール | 値は `clear` / `rain` / `thunder`。継続時間を付けられる |
| `difficulty <難易度>` | 難易度を設定 | OP 2 / コンソール | 値は `peaceful` / `easy` / `normal` / `hard` |
| `give <プレイヤー> <アイテム> [数量]` | アイテムを渡す | OP 2 / コンソール | アイテム ID とコンポーネントの構文はバージョンで変わる |
| `seed` | ワールドのシードを表示 | OP 2 / コンソール | セーブデータに紐づくため、ワールドを変えると値も変わる |
| `say <内容>` | サーバーの立場で全体に放送 | OP 2 / コンソール | プレイヤーにはサーバーメッセージの形式で表示される |
| `tell <プレイヤー> <内容>` | 個人メッセージ | 全員 | 別名 `msg` / `w` |
| `datapack list` | データパックを一覧 | OP 2 / コンソール | `/reload` と組み合わせて使う |

`gamerule` は最も誤用されやすいコマンドです。**同じ名前のルールでも Java 版と統合版で意味が違うことがあり、バージョン間で改名・分割されることもあります**。変更する前に補完リストでルールの存在を確認し、変更後はログとプレイヤーの反応を観察してください。

## 5. Java 版：状態と切り分け

| コマンド | 効果 | 権限 | 備考 |
| --- | --- | --- | --- |
| `tps` | TPS を表示 | OP | **バニラのコマンドではありません**。Spigot / Paper 系に標準搭載。spark を入れていると spark に引き継がれる場合がある |
| `mspt` | 1 tick あたりの処理時間を表示 | OP | Paper 系が提供。TPS と併せて見ると意味がある |
| `spark tps` | spark で TPS を表示 | OP | spark のコマンドツリーはコア標準のコマンドより細かい |
| `spark profiler start` | パフォーマンスのサンプリングを開始 | OP | 既定では結果がアップロードされて URL が返る。データ流出のリスクに注意 |
| `spark profiler stop` | サンプリングを終了して結果を見る | OP | アップロードせずに止めたいときは `spark profiler cancel` |
| `plugins` | プラグインを一覧 | OP / パーミッションノード | 別名 `pl`。緑が読み込み済み、赤が読み込み失敗 |
| `version <プラグイン>` | プラグインのバージョンを表示 | OP / パーミッションノード | 不具合報告の際に必ず聞かれる |
| `help` | コマンドのヘルプを表示 | 全員 | ページ単位で表示。`/help <コマンド>` で 1 件だけ見られる |

バニラサーバーには `tps`、`mspt`、`plugins`、`version` は**ありません**。バニラで性能を見るにはログと外部ツールしかなく、これが「コアを変えたら新しいコマンドが増えた」と言われる理由です。性能の切り分けの完全な手順は [spark でサーバーのパフォーマンスを分析する](/tutorials/ops/spark) を参照してください。

:::tip パーミッションノードでコマンドの可視性も変えられる
`plugins`、`version`、`help` のパーミッションノードは既定で全員に開放されています。無効にしたい場合は `bukkit.command.plugins`、`bukkit.command.version`、`bukkit.command.help` を `false` にします。ただし**コマンドを無効にしても隠しきれるとは限りません**。一部のクライアントは Tab 補完の応答から導入済みのプラグインを推測できます。
:::

## 6. 統合版：同じコマンドは BDS でどうなるか

統合版（BDS とサードパーティコア）には独自のコマンド体系があります。**使えるかどうかは 2 つの条件に左右されます**：オペレーターの立場があるか、サーバーでチートが有効かどうかです。

| コマンド | 効果 | 権限 | 備考 |
| --- | --- | --- | --- |
| `stop` | サーバーを安全に終了 | コンソール | Java 版と同名同義。最も覚えておくべき 1 本 |
| `save hold` | 書き込みを一時停止し、ファイルの一貫性を保つ | コンソール | 統合版のバックアップの第一歩 |
| `save query` | 現在バックアップすべきファイルを一覧 | コンソール | 出力されたリストに従ってコピーする |
| `save resume` | 書き込みを再開 | コンソール | コピーが終わったら実行 |
| `whitelist on` / `off` | ホワイトリストの有効・無効 | オペレーター | 対応するファイルは `allowlist.json` |
| `whitelist add` / `remove` / `list` / `reload` | ホワイトリストの管理 | オペレーター | ファイルを手で編集したら reload が必要 |
| `op` / `deop` | 管理者権限の付与 / 剥奪 | オペレーター | 結果は `permissions.json` に書き込まれる |
| `permission list` | 現在の権限を表示 | オペレーター | `permissions.json` に対応 |
| `permission reload` | 権限ファイルを再読み込み | オペレーター | `permissions.json` を手で編集したあとに実行 |
| `kick <プレイヤー> [理由]` | プレイヤーをキック | オペレーター | 意味は Java 版と同じ |
| `ban` / `pardon` | プレイヤーの BAN / 解除 | オペレーター | プレイヤー（gamertag / XUID）単位で BAN。**IP 単位の BAN に相当するコマンドはない** |
| `tp` / `teleport` | テレポート | オペレーター | 構文は Java 版に近いが完全に同じではない |
| `gamemode` | ゲームモードを切り替え | オペレーター | 値は Java 版と同様 |
| `gamerule` | ゲームルールを変更 | オペレーター | ルールの集合は Java 版と**異なり**、同名ルールの意味も違うことがある |
| `time set` / `time add` | 時刻の設定 / 進行 | オペレーター | 統合版では `daylock` のようなコマンドで時刻を固定できる |
| `weather clear` / `rain` / `thunder` | 天気を設定 | オペレーター | ほかに `toggledownfall` もある |
| `difficulty` | 難易度を設定 | オペレーター | Java 版と同名 |
| `list` | オンラインのプレイヤーを一覧 | オペレーター | 一部のバージョンでは一般プレイヤーにも開放。補完を基準に |

表の中には**新しいバージョンで追加されたコマンド**もあります（`ban` / `pardon` などは特に顕著）。古い統合版サーバーでは補完リストにそもそも出てこないことがあります。**あるコマンドが自分のバージョンに存在するかを判断する唯一確実な方法は、Tab 補完と公式ドキュメントを見ること**です。他所のバージョン番号をそのまま書き写さないでください。

BDS の設定にはコマンドと直接関係する項目があります：`server.properties` の `allow-cheats` です。これが無効だと、ゲーム内のコマンドが制限されます。既定値はローカルで生成された `server.properties` を基準にし、変更したらサーバーの再起動が必要です。**統合版で「コマンドが使えない」の多くは、チートスイッチかオペレーターの立場が原因で、コマンドの書き間違いではありません。**

統合版のバックアップ手順は Java 版とまったく異なり、そのまま使えます：

```text
save hold
save query
# 按 query 输出的清单复制文件（worlds/ 要整体拷走）
save resume
```

## 7. 統合版にない（または意味が違う）コマンド

| Java 版のコマンド | 統合版の状況 | 説明 |
| --- | --- | --- |
| `save-all` | 存在しない | `save hold` / `save query` / `save resume` を使う |
| `save-off` / `save-on` | 存在しない | 統合版に「自動保存を止める」この 1 対のスイッチはない |
| `ban-ip` / `pardon-ip` | 存在しない | 統合版はプレイヤー単位で BAN。IP 単位の BAN コマンドはない |
| `plugins` / `version <プラグイン>` | 存在しない | 統合版のコアに統一的なプラグイン一覧コマンドはない。コンソール出力を見る |
| `tps` / `mspt` | 存在しない | 統合版に TPS コマンドはない。性能はログと外部からの観測で判断する |
| `reload` | 存在するが**意味が違う** | 統合版が再読み込みするのはビヘイビアパック内の関数とスクリプト。**`server.properties` は再読み込みせず**、再起動でもない |
| `gamerule` | 存在するが**ルール集合が違う** | 同名ルールでも両エディションで意味が違うことがある。バージョンをまたいで写すとつまずく |
| `difficulty` / `time` / `weather` | 存在する | このあたりは両エディションにあり、構文も近い |

:::warn 「統合版に /reload はない」という言い方は分けて考える
コミュニティでよく言われる「統合版に `/reload` はない」は、実際には**サーバー設定を再読み込みできる reload がない**という意味です。この点は正しく、統合版で `server.properties` を変えた場合はサーバーの再起動しかありません（コンソールから正常に `stop` して起動し直してください。プロセスは kill しないこと）。

ただし統合版にも `reload` という名前のコマンドは確かにあり、その作用範囲はビヘイビアパック内の関数とスクリプトです。**Java 版のデータパック再読み込みとは別物**で、サーバーが設定ファイルを読み直すこともありません。両エディションとも `reload` を「万能リフレッシュキー」として使わないでください。使える範囲と挙動はバージョンで変わるため、公式ドキュメントを基準にしてください。
:::

## 8. 管理レイヤー：MCDR の `!!MCDR` サブコマンド

MCDReforged（MCDR）は**サーバーの外側に被せる**マネージャーです。コアのプロセスを托管し、コンソール出力を解析し、`!!` 接頭辞のコマンド群を提供します。このコマンド群は**ゲームのコマンドではなく**、MCDR 自身が処理し、サーバーへは渡されません。

| コマンド | 効果 | 権限 | 備考 |
| --- | --- | --- | --- |
| `!!MCDR` | メインコマンド。使えるサブコマンドを一覧 | MCDR の権限システムで制御 | 接頭辞 `!!` は設定で変更できる |
| `!!MCDR status` | MCDR の状態を表示 | MCDR 権限 | 「マネージャーは生きているか」の切り分け |
| `!!MCDR reload config` | MCDR の設定を再読み込み | MCDR 権限 | `!!MCDR r cfg` のような短縮形がある |
| `!!MCDR reload plugin` | プラグインを再読み込み | MCDR 権限 | 設定の再読み込みとは別 |
| `!!MCDR reload permission` | 権限データを再読み込み | MCDR 権限 | 権限ファイルを編集したあとに使う |
| `!!MCDR reload all` | すべて再読み込み | MCDR 権限 | 問題が起きたらまずこれ |
| `!!MCDR plugin list` | 読み込み済みのプラグインを一覧 | MCDR 権限 | Java 版の `/plugins` とは別物 |
| `!!MCDR plugin load <プラグイン>` | プラグインを読み込む | MCDR 権限 | 引数はプラグインの id |
| `!!MCDR plugin reload <プラグイン>` | 1 つのプラグインを再読み込み | MCDR 権限 | 全体の再起動より軽い |
| `!!MCDR plugin unload <プラグイン>` | プラグインをアンロード | MCDR 権限 | アンロードはファイル削除ではない |
| `!!MCDR plugin install <プラグイン>` | 公式リポジトリからプラグインを導入 | MCDR 権限 | 例：`!!MCDR plugin install ndpr` |
| `!!MCDR permission list` | 権限を表示 | MCDR 権限 | プレイヤーと権限グループ単位で表示 |
| `!!MCDR permission set` | 権限を設定 | MCDR 権限 | 構文は公式ドキュメントを基準に |
| `!!MCDR permission remove` | 権限を削除 | MCDR 権限 | |
| `!!MCDR checkupdate` | MCDR の更新を確認 | MCDR 権限 | 自動確認の有無は設定項目で決まる |

:::warn MCDR のサブコマンドはバージョンで変わる
MCDR のサブコマンドと短縮形はバージョン間で調整されます（`!!MCDR reload config` のような短縮形はとくに覚え間違えやすい）。**具体的な書き方は MCDR の公式ドキュメントと、手元の `!!MCDR` が出力するヘルプを基準にしてください**。また MCDR の権限は独自の体系で、ゲーム内の OP レベルとは関係ありません。プレイヤーがチャット欄から実行できる `!!` コマンドは、MCDR の権限設定次第です。
:::

## 9. 管理レイヤー：パネルのコンソールと RCON

パネル（MCSManager、Pterodactyl など）の Web コンソールは、本質的には**遠隔の標準入力**です。入力した内容はそのままサーバープロセスへ送られ、マシンの前に座ってコンソールを叩くのと変わりません。

| 経路 | `/` が必要か | 権限 | 備考 |
| --- | --- | --- | --- |
| ローカルのコンソール | 通常は不要 | 最高権限 | バニラのコンソールは OP レベルの制限を受けない |
| パネルの Web コンソール | 多くのパネルはどちらも受け付ける | 最高権限 | 先頭の `/` を自動で外すパネルもある。パネルの挙動を基準に |
| RCON | 通常は不要 | 最高権限 | `server.properties` で有効化しパスワードを設定する必要がある |
| ゲーム内のチャット欄 | `/` が必須 | OP レベルまたはパーミッションノード | ホワイトリスト、BAN、権限プラグインの影響を受ける |

実務的な 3 つの提案：

1. **停止は必ず `stop`（統合版も同じ）**。パネルで「プロセスを終了」を押さないでください。強制終了はデータの消失やセーブデータの破損につながります。
2. **RCON をインターネットへ公開しない**。認証なしで「任意のコマンド」を実行できる経路なので、ループバックか内部ネットワークのアドレスにだけ待ち受け、パスワードは長く一意にしてください。
3. **パネルのコンソールで実行するコマンドは最高権限に等しい**。協力者にパネルのアカウントを渡す前に、この点をよく考えてください。

## 10. コンソール vs ゲーム内：差異の一覧

| 差異 | コンソール / RCON | ゲーム内のチャット欄 |
| --- | --- | --- |
| 先頭のスラッシュ | 通常は不要 | 必須 |
| 権限の出どころ | プロセスの立場。最高権限に等しい | OP レベルまたはパーミッションノード |
| 実行者のコンテキスト | **実行者がいない**：`@s`、相対座標、対象を指定しない `tp` は使えない | 実行者がいるため、セレクタと相対座標が使える |
| 出力の行き先 | ターミナルとログファイル | チャット欄とアクションバー |
| Tab 補完 | 通常はある。一部のパネルにはない | ある |
| 文字コード | Windows コンソールのコードページが違うと日本語が文字化けする | 通常は問題ない |
| プレイヤーからの可視性 | 何を入力したかはプレイヤーに見えない | 一部のコマンドはプレイヤーへ放送される |

最も典型的な失敗は「コンソールで `/tp ~ ~10 ~` を実行する」ことです。コンソールには位置がないため必ず失敗します。コンソールからテレポート系のコマンドを実行するときは、**プレイヤーと目標の両方を明示**してください。

## 11. 権限はどこから来るか

| 体系 | 対象 | 制御方法 |
| --- | --- | --- |
| OP レベル | Java 版のバニラ | `/op` で 4 まで付与。レベル 1〜4 が異なるコマンド群に対応し、パーミッションノードで細分化もできる |
| パーミッションノード | Java 版のプラグインサーバー | 権限プラグイン（LuckPerms など）がノードと権限グループで割り当てる。OP を渡すより安全 |
| オペレーター + チートスイッチ | 統合版 | `permissions.json` が誰をオペレーターにするかを決め、`server.properties` の `allow-cheats` がコマンドの可用性を決める |
| MCDR 権限 | MCDR を入れたサーバー | MCDR 独自の権限システム。プレイヤーと権限グループ単位で `!!` コマンドを制御 |

**権限付与の原則**：1 つのコマンドの権限だけ渡せるなら、OP 全体は渡さない。期限付きの権限を渡せるなら、永久の権限は渡さない。OP は「サーバー全体」を信頼する行為で、最小限の委譲はパーミッションノードのほうです。

## 12. そのまま使える組み合わせ

メンテナンス前の標準手順（Java 版）：

```text
say 服务器将在 5 分钟后进入维护
save-all
save-off
# 此时在外部打包世界目录与插件目录
stop
```

ホワイトリストをゼロから使える状態にする（Java 版）：

```text
whitelist add 你的ID
whitelist on
whitelist list
```

統合版のバックアップと復元：

```text
save hold
save query
# 复制 query 列出的文件，worlds/ 整体拷走
save resume
```

「プレイヤーが入れない」ときに最初に叩くもの：

```text
list
whitelist list
banlist players
plugins
```

## 13. よくある誤用

| 誤用 | 結果 | 正しい方法 |
| --- | --- | --- |
| ウィンドウを閉じる、または「プロセスを終了」を押す | セーブデータが破損したり巻き戻ったりする | コンソールで `stop` |
| `/reload` を再起動代わりに使う | プラグインの状態が壊れ、設定も反映されない | プラグイン自身の reload。必要なら再起動 |
| バックアップ前に `save-off` しない | 書き込み途中のセーブデータを控えてしまう | 先に `save-all`、次に `save-off` |
| コンソールで `~` の相対座標を使う | コマンドがそのまま失敗する | プレイヤーと座標を明示する |
| RCON のポートをインターネットに開ける | サーバーをスキャナに明け渡すのと同じ | ループバックか内部ネットワークのみで待ち受け、強力なパスワードを設定 |
| `whitelist.json` を編集して reload しない | 変更が反映されない | `whitelist reload` を実行 |
| 統合版の `gamerule` 名を Java 版で使う | ルールが存在しないか意味が違う | Tab 補完でルール名を確認 |
| 統合版に `save-all` があると思い込む | コマンドが存在しない | `save hold` / `save query` / `save resume` を使う |
