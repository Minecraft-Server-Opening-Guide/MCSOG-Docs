服务器一公开，安全就分三层：**谁是谁**（身份）、**出事了能不能查**（记录与回滚）、**谁能干什么**（权限）。这三层各有成熟插件，下面只介绍**有官方仓库可查**的几个。

## 一、身份验证：AuthMe

**AuthMeReloaded** 是 Bukkit / Spigot 系的身份验证插件（作者自己的定位就是"面向 Bukkit/Spigot API 的验证插件"）。

- 仓库：<https://github.com/AuthMe/AuthMeReloaded>
- **什么时候需要它**：只有**离线模式**（`online-mode=false`）才需要。正版服里账号由 Mojang 校验，不需要额外登录。
- **它解决什么**：离线模式下"ID 可以被任何人冒用"，AuthMe 用**注册 + 密码登录**把 ID 和密码绑定起来，冒用者进不去。
- **它解决不了什么**：离线模式的根本问题（封禁可换 ID 绕过、皮肤与 UUID 无法绑定）依旧存在。**公开服仍建议开正版验证**。

:::warn 离线模式的代价不会因为装了登录插件而消失
登录插件只是"给离线模式补一道门"，不是把离线服变成正版服。账号安全、皮肤、封禁效力都还是打折的。
:::

## 二、记录与回滚：CoreProtect

**CoreProtect** 是数据记录与防破坏工具（官方定位：*blazing fast data logging and anti-griefing tool*）。

- 仓库：<https://github.com/PlayPro/CoreProtect>
- **它记录什么**：方块放置/破坏、容器存取、实体与指令等操作，写进数据库。
- **它能做什么**：查"这块地是谁在什么时候拆的"、查某个玩家最近干了什么、按时间或按玩家**批量回滚**，把被破坏的区域恢复原状。
- **为什么它是第一优先级**：没有记录，你连"是谁干的"都不知道，封禁和回滚都无从谈起。

:::tip 越早装越好
CoreProtect 只能记录**装上之后**发生的事。等被破坏了才装，之前的一概查不到。
:::

## 三、权限：LuckPerms

**LuckPerms** 是 Minecraft 服务器的权限插件（官方定位：*A permissions plugin for Minecraft servers.*）。

- 仓库：<https://github.com/LuckPerms/LuckPerms>
- **它解决什么**：原版只有"给不给 OP"，而 OP 权限极大。LuckPerms 用**权限组 + 权限节点**做精细控制，谁能用哪条指令、能碰哪些方块，都能单独配。
- **安全意义**：把"管理员"拆成多个角色（客服、建筑师、活动主持），**每个人只拿到自己需要的那点权限**，避免一个人拿到全权后出事。
- **配套习惯**：定期审查权限组与 OP 名单。

## 四、反作弊：Grim

**Grim** 是一个**开源、异步多线程、预测式**的反作弊（作者定位里还标注了支持的版本范围 1.8–1.21，具体以仓库当前说明为准）。

- 仓库：<https://github.com/GrimAnticheat/Grim>
- **思路**：不等玩家真的违规，而是**预测**玩家本应在什么位置/状态，偏离即判定，因此对传统"改包"类作弊较敏感。
- **开源的好处**：判定逻辑可查、可审，不必盲信黑盒。

:::warn 反作弊的误判比漏判更伤玩家
无论用哪个反作弊，**先跑"只记录不处罚"模式观察一段时间**，确认没有误伤再开处罚。正常玩家被踢、被回弹甚至被封，会直接流失。
:::

## 五、按类别选，而不是按名气选

| 类别 | 代表 | 优先级 |
| --- | --- | --- |
| **记录与回滚** | CoreProtect | 必备（第一优先级） |
| **权限** | LuckPerms | 必备 |
| **身份验证** | AuthMe（仅离线模式需要） | 离线服必备，正版服不需要 |
| **反作弊** | Grim 一类 | 加分项，需谨慎配置 |
| **进服门槛** | 白名单 / 进服审核 | 小规模高质量服强烈建议 |

## 六、通用原则

1. **只从官方渠道下载**：插件是以服务端权限运行的第三方代码，论坛、群文件里转手的 jar 风险最高（可能被塞后门）。
2. **先在测试服试**：别在主力服直接装来路不明的插件。
3. **权限最小化**：能不给 OP 就不给，用权限节点替代。
4. **备份是最后防线**：反作弊与记录都拦不住"最坏情况"，异地备份仍然不可省（见「备份与恢复」）。
5. **管理操作要留痕**：谁封了谁、谁给了什么，都应可查，避免"管理滥用权限"的指控。
