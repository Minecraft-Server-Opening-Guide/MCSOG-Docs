基岩版的安全模型和 Java 版**不一样**：正版验证走 **Xbox Live**，官方服务端 BDS **没有插件系统**。所以这一篇分两部分：**BDS 自带的机制**（可靠、必用）与**第三方核心的插件体系**（灵活、但要自己承担）。

## 一、BDS 自带的三个机制（先用好它们）

### 1. 白名单：`allowlist.json`

- 在 `server.properties` 里开启白名单后，名单本身由服务端目录下的 **`allowlist.json`** 管理。
- 这是基岩版**最有效**的一道门槛：基岩版玩家群体流动大、小号成本低，**把麻烦挡在门外**远比事后封禁省事。
- 修改名单后按官方说明让服务端重新读取（或重启）使其生效。

### 2. 管理员权限：`permissions.json`

- BDS 的管理员（OP）与权限定义在 **`permissions.json`**（含玩家 UUID、名称与权限项）。
- 建议：**只给确实需要的人**，并在人员变动后及时回收。

### 3. 正版验证：`online-mode`

- BDS 的 `server.properties` 有 `online-mode` 开关：开启时玩家需通过 **Xbox Live 账号验证**。
- **公开服不建议关闭**：关闭后任何人都能冒用他人游戏名进入，封禁也可换个名字绕过。

:::warn 基岩版没有"Java 那样成熟的登录插件生态"
Java 版离线服可以靠 AuthMe 这类插件补一道密码门；基岩版**没有同等地位、同等普及的官方/社区方案**。所以基岩版的正确姿势是：**保持正版验证 + 用白名单做门槛**，而不是指望"装个登录插件就安全了"。
:::

## 二、第三方核心的插件体系

BDS 本身不能装插件，要扩展只能换核心或加社区加载器（见「BDS 服务端」与「第三方核心」）：

| 路线 | 说明 |
| --- | --- |
| **BDS + 社区加载器** | LeviLamina / EndStone / BDSX 提供插件能力，可做登录、权限、管理等 |
| **Nukkit 系**（含 PowerNukkitX） | Java 编写、有原生插件系统，生态与 Java 版插件端思路相近 |
| **PocketMine-MP** | PHP 编写，插件数量最多，登录、权限、管理等类别都有 |

:::warn 本篇不点名具体第三方插件
基岩版第三方插件的**生态分散、命名混乱、活跃度差异极大**，很多插件缺乏可长期核实的官方来源。为避免推荐到已经停更或来源不明的插件，本篇**只说明路线与类别**，具体插件请在其官方平台按"最近更新时间 + 下载量 + 是否开源"自行甄别。
:::

### 选插件时的四个检查

1. **是否还在更新**：基岩版协议每隔若干版本就变，停更的插件遇到新版必崩。
2. **来源是否官方**：优先作者仓库或官方插件平台，避免二手转发的压缩包。
3. **是否开源 / 可审**：安全类插件（登录、权限）尤其要看得到实现。
4. **是否与你的核心版本匹配**：加载器与插件都强绑定版本区间（见「BDS 服务端」）。

## 三、跨端（Geyser / Floodgate）带来的安全注意点

如果你用 Geyser 让基岩版玩家进 Java 服，安全上要额外注意：

- **Floodgate 玩家名会带前缀**（默认 `.`），**白名单、封禁、指令里写名字时要带上它**，否则会漏判或误判。
- Floodgate 让基岩版玩家**无需 Java 账号**即可进入，等于放宽了一道验证，**必须配合白名单或审核**。
- Geyser 装在 **Java 服一侧**，反向（Java 玩家进基岩版服）**没有官方方案**。

## 四、通用原则（与 Java 版一致）

1. **门槛前置**：白名单 / 进服审核能挡掉绝大部分破坏与作弊。
2. **规则写短**：基岩版玩家以手机为主，规则要直白、可执行。
3. **管理留痕**：谁封了谁、谁动了权限，都要可查。
4. **备份是最后防线**：见「备份与恢复」——注意 BDS 的存档全在 `worlds/`，要整个目录备。
5. **别强行清内存**：BDS 内存会缓慢增长，强行清理会导致玩家下载材质包/Addon 卡条，只能重启解决（见「BDS 服务端」）。
