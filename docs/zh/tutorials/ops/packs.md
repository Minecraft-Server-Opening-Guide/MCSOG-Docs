"资源包"和"数据包"名字很像，作用却完全相反：**资源包改的是玩家看到和听到的东西，数据包改的是游戏本身的行为**。搞混这两个概念，就会出现"我装了材质包为什么合成表没变"或者"数据包为什么改不了贴图"这类问题。

本篇讲 Java 版的资源包与数据包：两者能做什么、怎么装、服务端怎么下发资源包、格式不兼容怎么排查。基岩版是另一套机制（资源包 + 行为包 + 附加包），见 [基岩版第三方核心上手](/tutorials/bedrock/third-party-setup)。

## 1. 两者是什么

| 维度 | 资源包（Resource Pack） | 数据包（Datapack） |
| --- | --- | --- |
| 作用位置 | **客户端**：贴图、模型、音效、语言文件、字体、GUI | **服务端 / 存档**：配方、战利品表、进度、函数、结构、标签 |
| 谁能看到效果 | 只有装了（或被下发）该包的玩家 | 所有玩家（数据在世界/服务端上，与客户端无关） |
| 装在哪 | 客户端 `resourcepacks/`，或由服务端下发 | 存档目录下的 `datapacks/` |
| 服务端能不能强制 | 可以下发并强制（`require-resource-pack`） | 不需要下发，本来就存在服务端 |
| 会不会改变玩法 | **不会**。改变的是外观与声音 | **会**。可以改配方、掉落、世界生成、执行命令 |
| 能不能跑代码 | **不能**。只有素材与配置文件 | **能**。函数里是一串命令，等价于服务端执行命令 |
| 典型用途 | 材质、UI、音效、汉化、字体、模型 | 自定义配方、掉落、成就、小游戏逻辑、世界生成 |
| 与版本的关系 | `pack.mcmeta` 里的格式号必须匹配客户端版本 | `pack.mcmeta` 里的格式号必须匹配服务端版本 |

一句话记忆：**资源包是"换皮"，数据包是"换规则"。**

### 目录结构对照

```text
资源包/
  pack.mcmeta                 <- 必需，标识这是一个包
  pack.png                    <- 可选，选择界面里的图标
  assets/
    <命名空间>/
      textures/               <- .png 贴图
      models/                 <- .json 模型
      sounds/                 <- .ogg 音效
      lang/                   <- <语言代码>.json 翻译
      font/  blockstates/  gui/ ...

数据包/
  pack.mcmeta                 <- 必需
  pack.png                    <- 可选
  data/
    <命名空间>/
      function/               <- .mcfunction 命令函数
      recipe/                 <- .json 配方
      loot_table/             <- .json 战利品表
      advancement/            <- .json 进度
      structure/              <- .nbt 结构
      tags/                   <- 标签（例如 function/tick.json）
      predicate/  item_modifier/  worldgen/ ...
```

`pack.mcmeta` 是**唯一必需的文件**，游戏正是靠它来判断一个目录或 zip 是不是"包"。

## 2. 各自做不到什么

| 想做的事 | 资源包 | 数据包 |
| --- | --- | --- |
| 换方块贴图、换音效、改字体与语言 | 可以 | **不行**（数据包不碰客户端素材） |
| 加一条合成配方、改掉落物 | **不行** | 可以 |
| 改游戏逻辑、加小游戏规则、定时执行命令 | **不行**（不能执行代码） | 可以 |
| 加一个新方块 / 新物品 | **不行**（只能改现有内容的素材） | **不行**（这需要模组） |
| 让所有玩家都看到同样效果 | 需要下发资源包，玩家仍可能拒绝 | 天然对所有玩家生效 |
| 改变服务器性能 | 几乎不影响服务端 | **会影响**：函数每 tick 执行就可能拖慢服务端 |

:::note 为什么"数据包加不了新方块"
数据包能定义配方、掉落、进度、世界生成等**数据**，但方块与物品的注册是硬编码在游戏里的。想在服务端加真正的新方块/新物品，需要模组（或基岩版的行为包）。**看到"数据包添加新矿物"的教程，多半是借用了已有方块的外观与材质。**
:::

## 3. 服务端怎么给 Java 客户端下发资源包

原版服务端通过 `server.properties` 里的几个键把资源包**推给**客户端。**键名必须一字不差**（这是最常见的失败原因之一）：

```properties
resource-pack=https://cdn.example.com/packs/survival-2026-10-04.zip
resource-pack-sha1=<40 位小写十六进制 SHA-1>
require-resource-pack=false
resource-pack-prompt={"text":"本服使用自定义材质包，建议启用。","color":"yellow"}
```

| 键名 | 类型 | 默认值 | 含义 |
| --- | --- | --- | --- |
| `resource-pack` | 字符串（URL） | 空 | 资源包的下载地址。留空表示不下发任何资源包；玩家进服时可以选择是否下载。**包的大小上限为 250 MiB** |
| `resource-pack-sha1` | 字符串 | 空 | 资源包的 SHA-1，**小写十六进制**。用于客户端校验完整性，**强烈建议填** |
| `require-resource-pack` | 布尔 | `false` | 为 `true` 时，**玩家拒绝使用资源包会被踢出服务器** |
| `resource-pack-prompt` | 字符串 | 空 | 在强制资源包时显示的自定义提示文本。使用聊天组件（JSON 文本）语法，可以多行；留空则显示默认提示 |
| `resource-pack-id` | UUID | 空 | 可选，给这个资源包一个标识；**较新版本才有这个键**，旧版本写了不生效 |

### 必须知道的几个细节

- **必须是客户端能直接下载到的 HTTPS 地址。** 实践中原版客户端只接受 HTTPS 链接，明文 HTTP 或证书有问题的地址会导致下载失败（客户端侧的校验随版本变化，以官方文档为准）。
- **下载成功或失败只记录在客户端日志里，服务端看不到。** 所以"服务端没报错"不代表玩家拿到了包——排查时一定要去看客户端的 `logs/latest.log`。
- 服务端**不会**替你托管这个文件。你需要把它放到能被公网访问的地方（对象存储、CDN、Nginx 静态目录等），并确认**没有防盗链、没有鉴权、没有重定向到 HTML 页面**。
- 服务端启动时会重写 `server.properties`：它会补上缺失的键、把无效值改回默认值，并**转义某些特殊字符**（例如 `:`）。所以手写 `resource-pack-prompt` 的 JSON 是可行的，但不要因为文件里出现了反斜杠就以为写错了。
- 改了这些键**必须重启服务端**才生效（`server.properties` 不会被 `/reload` 重新读取）。

:::warn 强制资源包是一把双刃剑
`require-resource-pack=true` 会让**拒绝下载的玩家直接进不来**。如果资源包托管在你自己带宽有限的小机器上，一次更新就可能让全服玩家同时下载、把带宽打满，甚至被误判为"服务器进不去"。**强制之前先确认托管端的带宽与可用性，并保留随时关掉强制的能力。**
:::

## 4. 正确计算 SHA-1

哈希必须是**文件内容**的 SHA-1，小写十六进制，共 40 个字符。

```bash
# Linux / macOS
sha1sum survival-2026-10-04.zip
```

```powershell
# Windows PowerShell：Get-FileHash 默认输出大写，转成小写再填
(Get-FileHash -Algorithm SHA1 .\survival-2026-10-04.zip).Hash.ToLower()
```

### 哈希错了会怎样

| 情况 | 后果 |
| --- | --- |
| 哈希与实际文件不符 | 客户端下载后校验失败，**资源包不会被应用**；失败只出现在客户端日志里，服务端毫无感知 |
| 哈希不是 40 位十六进制字符串 | 按协议文档说明，客户端不会用它做校验，**白白浪费一次下载带宽** |
| 服务端启动时提示 `Invalid sha1 for resource-pack-sha1` | 配置里的这个值与实际包不一致（或格式不合法），控制台会出现黄色提示 |
| 换了包但没更新哈希 | 玩家反复下载、反复失败；旧玩家可能还留着旧包 |

:::tip 三个最容易踩的坑
1. **重新打包会改变哈希**：即使文件内容一样，重新压缩（时间戳、压缩级别不同）也会得到不同的 zip，哈希随之变化。**保留你算过哈希的那个 zip 原件，不要重新压。**
2. **上传过程中可能被改动**：某些平台会自动压缩、加水印或改写内容，上传后要**重新下载一次**并校验哈希是否与本地一致。
3. **大小写**：填 `ABC...` 可能不被识别为合法哈希，统一用小写。
:::

## 5. 数据包放哪、怎么装

数据包放在**存档目录**下的 `datapacks/` 里。服务端的存档目录由 `server.properties` 的 `level-name` 决定（默认是 `world`）：

```text
/opt/mcserver/
  server.properties          <- level-name=world
  world/
    datapacks/
      my-tweaks/             <- 目录形式的数据包
      economy.zip            <- zip 形式的数据包
    level.dat
    region/
```

安装步骤：

1. 下载数据包（本站收录的在 [数据包下载](/downloads/datapacks)），确认它是 **`.zip` 或目录**。
2. 把它放进 `<level-name>/datapacks/`。**zip 里必须直接就是 `pack.mcmeta`，不能多套一层文件夹**——从文件夹右键压缩时最容易多出一层。
3. 如果服务端正在运行：执行 `/reload`，或用 `/datapack enable <名字>` 启用（部分内容必须重启，见第 6 节）。
4. 验证是否加载成功：

```text
/datapack list             列出全部数据包
/datapack list enabled     只列出已启用的
/datapack list available   只列出可用但未启用的
```

输出里应当能看到你的包名（zip 形式会显示为 `file/<文件名>`）。列表里鼠标悬停可以看到 `pack.mcmeta` 里写的 `description`。

### 启用、禁用与顺序

```text
/datapack enable <名字>
/datapack disable <名字>
/datapack enable <名字> first        放到最低优先级
/datapack enable <名字> last         放到最高优先级
/datapack enable <名字> before <已有包>
/datapack enable <名字> after  <已有包>
```

- **顺序很重要**：同名文件**后加载的包覆盖先加载的包**；标签文件默认会合并，除非写了 `"replace": true`。
- 权限等级：`list` / `enable` / `disable` 需要权限等级 2；`create` 需要等级 4。
- 启用的包列表保存在**存档**里（`level.dat`），所以**换存档、回档会一起改变启用了哪些数据包**。

:::note 服务端和单人存档的路径不一样
单人游戏的存档在 `.minecraft/saves/<存档名>/datapacks/`；服务端在**工作目录下**的 `<level-name>/datapacks/`。放错位置是"数据包不生效"的最常见原因。
:::

## 6. `/reload` 到底重载了什么

`/reload` 在 Java 版里的作用是**重新加载当前已启用数据包中的数据**。它**不是**万能的，也不等于重启：

| 内容 | `/reload` 是否生效 |
| --- | --- |
| 注册表标签（tags） | 会重新加载 |
| 战利品表（loot table） | 会重新加载 |
| 配方（recipe） | 会重新加载 |
| 进度（advancement） | 会重新加载 |
| 物品修饰器、谓词 | 会重新加载 |
| 函数（function，`.mcfunction`） | 会重新加载 |
| 结构模板（structure） | 会重新加载 |
| 使用动态注册表 / 实验性内容的部分（例如维度、生物群系、世界生成、附魔等，具体范围随版本变化） | **不会**，必须重启服务端（单人则退出并重新进入世界） |
| `server.properties` 等核心配置 | **不会**，必须重启 |
| 服务端进程、插件状态 | **不会**，而且可能被 `/reload` 弄乱 |

两个必须记住的行为：

1. **数据包里有非法数据时，改动不会被应用**，游戏会继续使用之前的数据。所以"我 `/reload` 了但没变化"有时是包本身写错了，而不是重载没生效。
2. **在插件服上慎用 `/reload`。** 它可能让插件状态错乱（例如计分板、监听器、缓存）。能用 `/datapack enable` / `/datapack disable` 或干脆重启解决时，优先选后者。

## 7. 包格式：`pack.mcmeta` 与 `pack_format`

`pack.mcmeta` 是包的元数据文件，资源包与数据包都用它，但**两者要求的格式号不同**。

```json
{
  "pack": {
    "pack_format": <该版本要求的整数>,
    "description": "示例数据包"
  }
}
```

:::warn 上面的 `<该版本要求的整数>` 是占位符，不是可以直接用的 JSON
**不要照抄任何教程里的格式号**，包括本篇。`pack_format` 的数值随每个 Minecraft 版本变化，资源包与数据包各有一套；填错就会得到"格式不兼容"的提示，包不会被加载。
:::

### 怎么查你这个版本要填多少

| 途径 | 说明 |
| --- | --- |
| 官方文档 / Minecraft Wiki 的包格式表 | 表中按版本列出资源包与数据包各自的格式号，**以它为准** |
| 你所用服务端核心的文档 | 部分核心会在文档里注明当前版本对应的格式 |
| 游戏给出的提示 | 加载失败时的提示通常会同时给出"包声明的格式"与"当前版本期望的格式"（具体文案随版本变化） |
| 从当前版本的官方包反推 | 直接看官方资源包/内置数据包里的 `pack.mcmeta` 写了什么 |

### 与版本有关的其他字段

`pack.mcmeta` 不止 `pack_format` 一个字段，而且**字段本身也在随版本演进**：

| 字段 | 作用 | 注意 |
| --- | --- | --- |
| `pack.pack_format` | 该包的主要格式号 | 在较新版本中已变为可选；旧版本必需 |
| `pack.supported_formats` | 声明一个格式区间（如 `[42, 45]`） | 1.20.2 引入；**在更新的版本中已被移除**，只在需要兼容旧版本时保留 |
| `pack.min_format` / `pack.max_format` | 新版本引入的最小/最大支持格式（可带次版本号） | 取代了 `supported_formats` 的角色 |
| `pack.description` | 悬停时显示的文字，支持文本组件 | 资源包与数据包都用 |
| `pack.filter` | 过滤掉优先级更低的包中的文件（正则） | 1.19 引入 |
| `pack.overlays` | 按版本区间叠加子目录 | 1.20.2 引入 |
| `features.enabled` | 启用实验性功能标志 | 需要对应的实验性开关 |

**字段的名称、是否必需、以及格式号的取值都以官方文档为准**，不要以本篇或任何第三方教程为准。

## 8. 性能与安全

### 数据包是"服务端代码"

函数里是一串**由服务端执行**的命令，因此：

- **只安装你信任来源的数据包。** 一个函数可以做任何命令能做的事：给物品、传送、改世界、清空容器、甚至把玩家丢进虚空。
- 安装前**打开 zip 看一眼**：`data/<命名空间>/function/` 里有没有你不想执行的命令；`pack.mcmeta` 里的 `description` 与实际内容是否相符。
- 函数的权限等级由 `server.properties` 的 `function-permission-level` 决定（默认 2），这决定了函数能执行到多"高级"的命令。

### 每 tick 执行的函数会拖慢服务端

- 被 `minecraft:tick` 函数标签引用的函数**每 tick（每秒 20 次）执行一次**。一次遍历几百个实体、或每 tick 放置/破坏方块，都会稳定地吃掉 MSPT。
- 被 `minecraft:load` 引用的函数只在（重）加载时执行一次，代价小得多。
- 用 `/schedule`、`execute if` 之类的机制做"轮询"时，要算清楚**每秒实际执行多少次**。
- 出现卡顿先量化再改：见 [性能分析 spark](/tutorials/ops/spark)。

```text
# 判断一个包有没有每 tick 的入口：看它有没有这个文件
data/<命名空间>/tags/function/tick.json
```

### 资源包的注意事项

- 资源包在客户端执行的是**素材替换**，不能执行代码，所以"安全"层面风险低；但**下载与存储成本**是真实的：包上限 250 MiB，玩家每次更新都要重下。
- 大包会显著拉长玩家进服时间，弱网玩家可能直接放弃。**能用几 MB 解决的，不要上几十 MB。**
- 资源包可以替换任何贴图，因此**也可能被用来误导玩家**（例如把普通矿石画成钻石矿）。多人服里这属于公平性问题，不只是技术问题。
- 服务端下发资源包**不等于**玩家一定用它：除非 `require-resource-pack=true`，玩家可以拒绝；玩家自己的客户端资源包顺序也可能覆盖你下发的包。

## 9. 排查表

| 现象 | 常见原因 | 怎么查 |
| --- | --- | --- |
| 资源包完全没下发 | `resource-pack` 为空或写错；URL 不可访问；改完没重启服务端 | 检查 `server.properties` 的键名拼写与 URL；用浏览器/`curl -I` 确认能直接下载到 zip |
| 玩家进服时提示下载失败 | 非 HTTPS、证书无效、需要鉴权、被防盗链、返回的是 HTML 而不是 zip | **看客户端日志**（服务端不会记录下载失败） |
| 哈希校验失败、包反复重下 | `resource-pack-sha1` 与实际文件不符；重新打包过却没更新哈希；哈希写成大写或长度不对 | 用第 4 节的方法重新计算，确认下载到的是同一个文件 |
| 服务端控制台出现 `Invalid sha1 for resource-pack-sha1` | 该键的值与实际包不一致或格式不合法 | 重新计算并更新；不确定就先留空（会失去校验） |
| 玩家拒绝后进不去 | `require-resource-pack=true` | 改成 `false` 并重启；或先修好下载问题再强制 |
| 贴图没变化 | 包内路径或命名空间写错；`pack.mcmeta` 缺失或格式号不对；被更高优先级的包覆盖；玩家自己的客户端包覆盖了它 | 确认 `assets/<命名空间>/textures/...` 路径正确；把包放在资源包列表最上方；用原版客户端单独测试 |
| 只对部分玩家生效 | 玩家拒绝了下载，或用了自己的资源包 | 需要全服一致就开 `require-resource-pack`，并先解决托管带宽 |
| 数据包没出现在 `/datapack list` 里 | 放错目录（应在 `<level-name>/datapacks/`）；zip 里多套了一层文件夹；不是 `.zip` 也不是目录 | 确认 `pack.mcmeta` 就在包的根目录；用 `unzip -l` 看结构 |
| 数据包出现了但没效果 | 未启用；函数没被 `tick` / `load` 标签引用；命名空间或路径写错；属于必须重启才生效的内容 | `/datapack list enabled` 确认已启用；`/reload` 后看日志报错；必要时重启 |
| 提示"格式不兼容" | `pack_format` 与当前版本不符（资源包与数据包格式号不同，别用错） | 按第 7 节查官方格式表；更新到正确格式号 |
| `/reload` 后配置没变 | 该内容属于必须重启的部分；或包里有非法数据导致改动被整体丢弃 | 看服务端日志有没有加载错误；直接重启验证 |
| 装了数据包之后明显卡顿 | 有函数挂在 `minecraft:tick` 上且每 tick 开销大 | 检查 `tags/function/tick.json`；用 [spark](/tutorials/ops/spark) 定位 |

## 10. 小结

- **资源包换外观，数据包换规则**；一个在客户端，一个在服务端。
- **服务端下发资源包靠 `server.properties` 的四个键**：`resource-pack`、`resource-pack-sha1`、`require-resource-pack`、`resource-pack-prompt`（较新版本还有 `resource-pack-id`），改完要重启。
- **哈希必须与实际文件一致且为小写 40 位十六进制**；算完不要重新打包，上传后要重新校验。
- **数据包放在 `<level-name>/datapacks/`**，用 `/datapack list` 验证；`/reload` 只重载一部分内容，动态注册表与核心配置必须重启。
- **格式号随版本变化**，一律查官方表格，别照抄教程。
- **数据包是服务端代码**：只装可信来源；挂在 `tick` 上的函数会一直消耗性能。
