前面讲的是"服务器能不能跑起来"。这一篇讲的是另一件事：**服务器跑起来了，玩家凭什么知道它存在，又凭什么留下来**。

这是一篇非技术文档。它和 [[JAVA] 经营管理](/tutorials/ops/management-java) 是配套关系：那一篇讲开服需要什么、团队怎么分工、资金与玩家管理怎么做；这一篇只聚焦其中两块——**宣传引流**和**社群运营**。它不涉及任何命令、配置或插件选型；需要插件清单时看 [插件入门](/tutorials/java/plugins) 与 [常用前置插件](/tutorials/java/plugin-deps)。

:::note 先摆正预期
宣传不是一个"发一条帖子就完事"的动作，而是一件**持续几个月、由内容驱动**的日常工作。如果你期待"发一次宣传帖就有几十人常驻"，那这篇会让你失望——但失望得越早，服务器活得越久。
:::

## 1. "开服了就有人来"是假的

很多新服主的心智模型是：我把服务端跑起来，公网能连上，把 IP 发出去，玩家自然就会来。现实是：**没有人有义务发现你**。

你面对的是典型的**冷启动问题**，而且它自带一个负反馈循环：

1. 你的服务器在线 0 人；
2. 玩家在服务器列表站或群里看到"0/20"，第一反应是"这个服已经死了"，直接跳过；
3. 因为没人点进来，列表站给你的曝光更低；
4. 于是你依然 0 人。

这个循环里最关键的一点是：**"0 人在线"本身就是一个劝退信号**。玩家不是不愿意当第一个，而是不愿意把时间押在一个看起来没人维护的地方。所以宣传的真正目标不是"发出去"，而是**在有人来看的那一刻，让服务器看起来值得留下**。

几个必须接受的事实：

| 常见想法 | 现实 |
| --- | --- |
| 服务器好玩，玩家自然会来 | 好玩是留存的必要条件，不是曝光的充分条件。没人知道你，就没人能评价你好不好玩 |
| 我有技术，所以我能开服 | 技术只解决"能跑"。宣传和运营是另外两门手艺 |
| 先开着，等人多了再想宣传 | 等人多了再想，通常等不到。宣传素材要在开服前就准备好 |
| 花钱买广告位就够了 | 广告位能买到点击，买不到留存。首日体验差，流量越大死得越快 |

:::warn 不要在别人的群里刷广告
**在与你无关的 QQ 群、Discord 服务器、贴吧、论坛里反复粘贴服务器 IP，是最快被踢、被拉黑、被公开点名的方式之一**，而且会连累你的服务器名声——玩家会记住"那个到处刷屏的服"，并把这份反感迁移到你身上。想进别人的社群宣传，先看群规、先征得管理员同意、先做一个愿意聊天的人。**规则允许的渠道才叫渠道，不允许的渠道叫骚扰。**
:::

## 2. 用一句话定义你的服务器是什么

在写任何宣传文案之前，先完成这个填空：

```
这是一个给 ______（谁）玩的 ______（什么玩法）服务器，
和同类服务器相比，它的差别是 ______。
```

三个空都必须填出**具体**的东西。填不出来，说明定位还没想清楚，此时做宣传只是把"没想清楚"放大给更多人看。

### 2.1 常见的定位类型

| 定位 | 面向的人群 | 这个定位会强制你做的决定 |
| --- | --- | --- |
| 生电 / 技术服 | 喜欢红石、刷怪塔、机制研究的玩家 | 原版机制不能被插件改坏；对 TPS 与区块加载极敏感 |
| 原版生存服 | 想长期经营一个世界的玩家 | 世界不能频繁重置；经济与领地系统要克制 |
| 小游戏服 | 想随时玩一局的玩家 | 需要稳定的对局人数与匹配节奏；大厅体验决定一切 |
| RP / 角色扮演服 | 想演故事、做设定的玩家 | 需要剧本、审核与管理人力，投入远高于普通服 |
| 基岩版 / 跨端服 | 手机、主机玩家 | 版本与跨端方案决定可用插件范围 |
| 模组服 | 想玩整合包的玩家 | 客户端要装同样的模组；宣传必须写清整合包与版本 |

### 2.2 为什么没有定位就没人来

- **玩家在 3 秒内做判断**。他看到的不是你的世界，而是一行标题。定位模糊的标题等于没有标题。
- **没有定位，宣传只能堆形容词**。"好玩、刺激、福利多、不氪金"这些词对所有人都不构成信息。
- **招来的人会互相冲突**。想安静建家的玩家和想随时开打的玩家放在一起，两边都不满意，两边都走。
- **运营没有取舍标准**。有人提议加 PVP、有人提议加科技模组，你没有判断依据，最后加成"什么都有一点"的四不像。

:::tip 定位是一份取舍清单
写定位的时候，把"我们不做什么"也写下来。例如"不做 PVP 竞技""不做付费强度""不重置主世界"。**明确拒绝掉一部分玩家，是让另一部分玩家安心的前提。**
:::

## 3. 中文 MC 玩家实际在哪里

下面按**类别**描述，不点名具体站点。原因很简单：**这类平台会兴衰、会改版、会换规则**，今天有效的渠道明年可能已经关闭或禁止宣传。你真正需要掌握的是"去哪一类地方找人"和"进这类地方之前先确认什么"。

| 类别 | 典型形态 | 适合做什么 | 发帖前必须先确认 |
| --- | --- | --- | --- |
| 综合论坛 / 社区类 | 以 MCBBS 为代表的玩家论坛，含服务器版块与招人版块 | 长文宣传、招管理、招建筑师 | 是否仍在运营、是否允许服务器宣传、发在哪个版块、是否有格式模板 |
| 视频与专栏类 | Bilibili 等平台的视频、专栏、动态 | 展示真实玩法、建立"这服有人在认真做"的印象 | 是否允许在简介或评论区留 IP、是否算商业推广、是否需要标注 |
| 贴吧类 | 各类 MC 相关贴吧 | 小范围触达、提问式互动 | 吧规是否禁止宣传、是否只允许集中楼 |
| 即时通讯社群类 | QQ 群、Discord 服务器 | 长期陪伴、活动通知、客服 | 群规、是否允许外链、能否先和管理员沟通 |
| 服务器列表 / 导航站类 | 包括本站在内的服务器列表与导航站 | 被动流量、按版本与玩法被筛选到 | 收录要求、标签规范、是否需要互链、置顶是否收费 |
| 熟人 / 主播 / 校园社群 | 朋友、同学、小主播的观众群 | 最早期的那几个真实玩家 | 对方的意愿；不要默认别人会帮你推 |

几条实操原则：

- **先潜水，再说话**。进任何一个社群，先看它平时怎么交流、管理员什么态度、有没有人因为发广告被处理。
- **一稿一改**。同一篇宣传稿直接粘贴到所有平台，通常会在格式上翻车（图片挂了、排版乱了、链接被吞）。
- **记录渠道效果**。同一个渠道发过三次都没带来任何一次有效进服，就该放弃它，而不是加大频率。
- **不要伪造人气**。挂假人、刷在线数、买点击，短期能骗过列表站的排序，长期一定会被玩家发现，而"这服刷数据"的标签洗不掉。

## 4. 一份合格的服务器宣传帖应该包含什么

宣传帖的任务不是"描述你的服务器有多好"，而是**让玩家在 10 秒内回答四个问题**：这是什么？适合我吗？现在能玩吗？怎么进？

| 要素 | 为什么必须有 | 常见错误 |
| --- | --- | --- |
| 一句话定位 | 决定玩家是否继续往下看 | 只写"最好的服务器" |
| 支持的版本 | 玩家客户端版本不匹配就进不来 | 写"全版本"，实际只支持一两个 |
| 正版 / 离线 | 决定玩家能不能进、以及是否愿意进 | 不写，或者含糊其辞 |
| 玩法特色 | 说明和别人的差别 | 罗列几十个插件名，玩家看不懂 |
| 硬件与稳定性说明 | 玩家关心卡不卡、会不会突然关服 | 吹"永不卡顿"，进服就掉帧 |
| 加入方式 | 降低进入门槛 | 只有群号，没有 IP 或域名 |
| 截图或视频 | 唯一能证明"真的有人在玩"的东西 | 用创造模式摆拍的宣传图，进服落差巨大 |
| 规则链接 | 提前筛掉不合适的人 | 规则只写在群里，新人看不到 |
| 联系方式 | 出事能找到人 | 留一个长期不看的邮箱 |
| 在线时间与开服时间 | 让玩家判断"是不是新服、什么时候人多" | 不写，玩家以为是僵尸服 |

### 4.1 填空模板

```
【服务器名称】______
【一句话定位】这是一个给 ______ 玩的 ______ 服务器，差别是 ______
【支持版本】Java ______ 版本；是否支持基岩版：______
【账号要求】正版 / 离线（如支持混合登录请写清）
【玩法特色】1. ______  2. ______  3. ______
【硬件与稳定性】托管位置：______；日常在线峰值：______；近一个月可用性：______
【加入方式】IP 或域名：______；端口：______；加群方式：______
【开服时间】______（新服请直接写"新服"，不要装作老服）
【规则】______（链接）
【联系方式】______
【截图或视频】______
```

### 4.2 常见减分项

- 全篇没有一张真实游戏截图，只有服务器 logo 和宣传图。
- 用"史上最好""绝对不卡""永不关服"这类无法验证的承诺。
- 把插件列表当成玩法介绍，写了几十个插件名。
- 版式花哨到看不清 IP。
- 留了联系方式，但三天不回一条消息。

## 5. 视频与短视频策略

视频是**目前性价比最高的展示方式**，因为它同时证明了三件事：真的有人在玩、画面长什么样、服务器卡不卡。

### 5.1 三十秒钩子

前 3 秒决定观众是否划走。有效的开头通常直接给画面结果，而不是给片头：

- 直接展示一个视觉冲击强的场景（大型建筑、红石机器运转、活动混战）。
- 用一句话说明"这是什么、为什么值得看"，例如"这是全服第一台自动分类机建成的那一晚"。
- 不要放 5 秒以上的 logo 动画、不要放"某某服务器宣传片"的标题卡。

### 5.2 展示真实玩法，而不是 logo

观众能分辨摆拍和实机。**把镜头放在玩家视角的连续游玩上**：挖矿、建家、交易、打怪、参加活动。如果服务器最吸引人的地方是"社区氛围"，就拍聊天栏里的互动、一起盖房子的过程、活动开始前的集合。

### 5.3 为什么稳定 TPS 会影响你的宣传效果

**卡顿在视频里是看得见的**：实体抽搐、方块回弹、玩家瞬移、方块破坏延迟、掉落物堆积。观众未必知道 TPS 是什么，但一定能感觉到"这服卡"。

所以拍宣传片之前，先确认服务器状态：

- 录制时段避开备份、地图渲染、大规模世界生成。
- 用 [用 spark 分析服务器性能](/tutorials/ops/spark) 确认 TPS 与 MSPT 正常，不要在卡顿期硬录。
- 拍完自己回看一遍，重点看实体移动和方块交互是否顺滑。
- 如果确实有性能短板，宁可缩小拍摄范围，也不要用剪辑掩盖。

:::tip 素材是一次性投入，可以复用
一次录制可以剪出：一条 30 秒短视频、一条 3 分钟长视频、若干张截图、一段活动回顾。**先想好素材要复用在哪里，再决定拍什么**，比每次临时找素材省力得多。
:::

## 6. 服务器列表站与导航站的投稿

列表站的价值在于**被动流量**：玩家按版本、玩法、在线人数筛选时可能撞见你。它不会带来爆发式增长，但它是"长期挂在那里"的基础曝光。

典型收录要求（不同站点差异很大，投稿前逐条核对）：

| 要求 | 说明 |
| --- | --- |
| 准确的版本与玩法标签 | 标错版本会让玩家进来发现进不去，直接流失并可能被差评 |
| IP / 域名与端口 | 必须是玩家能直接连的地址，不能只给一个群号 |
| 正版 / 离线说明 | 与列表站的筛选条件对应 |
| 截图 | 通常要求真实游戏内截图 |
| 简介文案 | 有字数上限，考验你的一句话定位 |
| 收录条件 | 有的要求互链、有的要求达到最低在线人数、有的有置顶付费位 |
| 信息维护 | 版本更新、IP 变更后要主动改，否则玩家连不上 |

需要说清楚的两点：

- **置顶和广告位买得到流量，买不到留存。** 花钱把人引进来，首日体验差，人还是走，而且钱花完了流量就断了。
- **排序往往和在线人数、点击率有关。** 这意味着"宣传"和"留存"是同一件事的两面：留不住人，排名会自己掉下去。

## 7. 社群运营

宣传解决"来"，运营解决"留"。一个没有运营的服务器，宣传效果会以天为单位衰减。

### 7.1 规则

- **少而清楚**。十条能执行的规则，好过五十条没人记得的规则。
- **公开可见**。规则要在玩家不需要问人就能看到的地方，参考 [社区规范](/rules)。
- **处罚有梯度**。提醒、警告、临时限制、永久封禁，每一级都要写清楚触发条件。
- **管理自己也要守规则**。管理滥用权限的指控一旦出现，比任何作弊都更伤玩家信任。

### 7.2 新手引导与首日体验

新玩家进服的第一个五分钟，决定他会不会有第二个五分钟。设计目标只有一个：**让他在 10 分钟内做成一件事**。

- 出生点要有明确的视觉引导：路牌、地标建筑、NPC 或告示，告诉他"往哪走、先做什么"。
- 提供一条最短的成长路径：例如"先领新手工具，再去 A 区挖矿，回到出生点交任务，最后拿到第一笔启动资金"。
- 新手福利可以有，但**不要破坏经济**。给太多钱和物资，等于让新人跳过整个游戏前期，也让他体会不到成长。
- 不要在出生点堆满告示牌和传送菜单，信息过载等于没有信息。

### 7.3 迎新

- **真人打招呼**比自动欢迎语有用一百倍。有人在公屏叫出新人的名字，他留下来的概率会明显提高。
- 安排一个"值班"概念：至少保证某个时段有人能回答问题。
- 不要用机器人刷屏式欢迎，那只会让新人觉得这里没人。

### 7.4 活动与排期

- **固定排期**优于随机办活动。例如"每周六 20:00 建筑赛""每周日 21:00 寻宝"，玩家可以形成预期。
- 提前公告，并在活动开始前 10 分钟再提醒一次。
- 活动规模要匹配你的人力。承诺了做不到的活动，比不办活动更伤。
- 保留活动记录（截图、集锦、结果公告），它们既是宣传素材，也是社群记忆。

### 7.5 反馈渠道

- 只留**一个**明确的反馈入口，不要让玩家在五个群里分别喊话。
- 公开处理结果：已收到、已修、不修（并说明原因）。玩家不怕被拒绝，怕的是没有回音。

## 8. 留存：玩家为什么在最初 10 分钟离开

绝大多数流失发生在**进服后的前十分钟**，而且原因通常和"玩法不够多"无关。

| 流失原因 | 玩家的真实感受 | 可以怎么改 |
| --- | --- | --- |
| 出生点看不懂 | "我不知道该干什么" | 明确指引与最短成长路径 |
| 卡顿、掉线 | "这服是不是快关了" | 先解决性能，再谈宣传 |
| 没有人说话 | "这里没人，是死服" | 真人迎新、保证有人值班 |
| 找不到目标 | "盖个房子然后呢" | 清晰的成长与目标体系 |
| 被老玩家碾压 | "我永远追不上" | 控制资源差距、限制掠夺 |
| 规则不清被处罚 | "莫名其妙就被封了" | 规则公开、处罚留痕 |
| 感觉随时会关服 | "不想投入时间" | 公开开服计划与稳定性说明 |
| 付费强度 | "不花钱玩不下去" | 见下 |

### 8.1 不要做 pay-to-win

付费可以卖**外观、便利、支持者标识**，不能卖**强度**。原因不是道德说教，而是它直接摧毁留存：

- 付费变强会让免费玩家认定"这服不是给我做的"，离开是理性选择。
- 一旦玩家相信"钱能解决一切"，你的所有玩法设计都失去意义。
- 信任破裂后极难修复，而服务器口碑在玩家社群里传播得非常快。

### 8.2 成长路径要看得见

给玩家一条能自己回答"下一步做什么"的路径：短期目标（今天能完成）、中期目标（这周能完成）、长期目标（这个月甚至更久）。路径不需要复杂，但必须**写在玩家能看到的地方**。

## 9. 社区层面的管理与冲突处理

技术上的防破坏见 [反作弊与防破坏](/tutorials/java/anticheat) 与 [[JAVA] 安全插件](/tutorials/ops/security-java)；这里讲的是**人和人之间**的部分。

- **处理要留痕**。封禁、回档、处罚都留下记录，避免"管理滥用权限"的指控。记录插件能提供证据。
- **流程固定下来**：私下提醒、公开警告、临时处罚、永久处罚，逐级递进。跳级处罚会引发争议。
- **不在情绪里做决定**。玩家辱骂你，和他是否违反规则是两件事。
- **争议公开处理**。把规则依据和处理结果公开，比在群里吵一百句更有用。
- **团队内部也要有规则**。管理不能给自己的朋友开绿灯；这是社群崩坏最常见的原因。

更多关于团队分工、资金与玩家管理的讨论，见 [[JAVA] 经营管理](/tutorials/ops/management-java)。

## 10. 值得盯的数据

不需要复杂的数据平台，一张表就够。**看趋势，不要看单点。**

| 指标 | 怎么理解 | 说明 |
| --- | --- | --- |
| 次日留存 | 今天来的新人，明天还来吗 | 最能反映首日体验的指标 |
| 7 日留存 | 一周后还在吗 | 反映成长路径与社群氛围 |
| 峰值在线人数 | 一天里同时在线最多多少人 | 服务器承载与列表站排序都看它 |
| 平均在线时长 | 玩家一次进来待多久 | 短而频繁说明内容不足；长而稳定说明有粘性 |
| 首日流失率 | 进服后很快退出的比例 | 配合出生点与引导一起看 |
| 渠道来源 | 玩家从哪知道你的 | 决定下次把精力放在哪 |
| 聊天活跃度 | 有多少人在说话 | 沉默的服务器看起来像死服 |

两点提醒：

- **小样本不要过度解读。** 一天来了 5 个人，走了 3 个，这不构成任何结论。至少看两周趋势。
- **数据要能对应到动作。** 留存差就去看出生点和引导，不是去多发几条广告。**宣传放大的是体验，不是弥补体验。**

## 11. 上线周清单

开服前一周到开服后一周，按下表逐项确认。

- [ ] 一句话定位已经写好，并且能用它筛掉不合适的玩家
- [ ] 支持版本、正版 / 离线、是否跨端已经确定并写进所有文案
- [ ] 服务器在开服前连续稳定运行了足够长时间，没有频繁崩溃
- [ ] 性能已确认（TPS、MSPT、内存、磁盘写入），录屏时段避开了备份与渲染
- [ ] 出生点有明确指引，新人在 10 分钟内能做成一件事
- [ ] 规则已成文并可公开访问
- [ ] 至少有一位真人能在开服时段值班答疑
- [ ] 宣传帖素材齐备：定位、版本、账号要求、玩法特色、稳定性说明、加入方式、截图或视频、规则链接、联系方式
- [ ] 目标渠道已逐个确认规则，并取得管理员同意（如需要）
- [ ] 服务器列表 / 导航站的信息已提交并核对无误
- [ ] 至少一条 30 秒视频或一组真实截图已准备好
- [ ] 活动排期已定，并在开服前公布
- [ ] 反馈入口唯一且有人看
- [ ] 付费内容清单已检查：只卖外观与便利，不卖强度
- [ ] 数据记录表已建好，约定好每周固定时间复盘一次
