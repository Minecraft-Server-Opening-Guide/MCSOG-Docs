"服务器卡"是最常见的问题，但**优化是有优先级的**。按下面的顺序做，性价比最高；顺序反了，容易花大力气收效甚微。

## 一、优先级顺序

```
1. 硬件（单核性能）        ← 收益最大，花钱也最多
2. 服务端配置（视距/模拟距离）  ← 几乎免费，立竿见影
3. 核心选择（Paper 系 vs 原版）
4. 插件/模组质量（劣质插件是重灾区）
5. JVM 参数
```

**先说结论**：如果你的机器单核很弱，**换配置和调参数都救不回来**，因为主线程只有一个。

## 二、配置优化（性价比最高）

### 视距与模拟距离

| 选项 | 影响 |
| --- | --- |
| `view-distance` | 玩家能看多远。调低省 CPU 与带宽，代价是远处发雾 |
| `simulation-distance` | 多远的区块还在**真实运算**（刷怪、红石、作物）。**调低它比调低视距省得多，且不影响观感** |

对多数小服，把 `simulation-distance` 从 10 降到 6 左右就能明显缓解卡顿。

### Spigot 层的实体控制

`spigot.yml` 里有几组与实体相关的关键项（不同版本名称略有差异）：

- **实体激活范围**：控制生物在多远才被 tick，调小能省大量 CPU。
- **刷怪范围**：控制刷怪的距离。
- **实体/物品合并半径**：调大能减少实体数量（如掉落物、经验球），**但会改变原版行为**（生电慎用）。
- **每 tick 最大实体 tick 数**：给实体运算设上限，防止爆量卡服。

### Paper 层的世界配置

`config/paper-world-defaults.yml` 里可调：实体碰撞上限、自动保存的区块数、区块卸载延迟等。

:::warn 优化与"原版行为"是此消彼长的
上面很多开关**默认值就是被优化过的**，调得越激进，离原版越远。**生电服请反过来——把影响原版行为的项调回原版**（见「生电与红石」）。
:::

## 三、先找到"卡在哪"，再动手

**不要凭感觉优化**。先测量：

| 工具 | 用途 |
| --- | --- |
| **spark** | 目前最主流的性能分析插件/命令，能生成火焰图，直接指出哪个插件/实体/区块在吃 CPU |
| `/tps` 类命令 | 看当前 TPS（低于 20 就是掉刻了） |
| **timings**（旧版 Paper） | 老版本上的性能报告 |

用 spark 跑一段时间的采样，**看火焰图里最宽的那条**，再针对性处理。常见元凶：

- 某个劣质插件在循环里做重活；
- 大量实体堆积（刷怪塔没做好收集、掉落物没清理）；
- 漏斗/红石装置过多（漏斗是经典的性能杀手）；
- 玩家跑图导致大量新区块生成（见下）。

## 四、世界预生成

**玩家边跑图边生成新区块**是卡顿的重要来源：新区块生成是 CPU 密集操作，会让 TPS 瞬间掉下去。

解决办法是**预生成**：用 `Chunky` 一类插件提前把一定范围的地图生成好。玩家再到那片区域时，只是加载已有区块，不触发生成。

对**长期开放的生存服**，预生成几乎是必做项。

## 五、JVM 参数

- **内存**：`-Xmx` 给足但别过量（过大反而让 GC 停顿变长）。专用机器上可让 `-Xms` 与 `-Xmx` 相等，减少堆伸缩。
- **GC 参数**：社区有成熟的推荐组合（如 **Aikar's Flags**），在 Paper 官方文档里有专门的启动参数生成工具与说明。**不要盲目抄网上互相矛盾的"玄学参数"**。
- 参数只在**内存/GC 层面**有帮助，**救不了单核瓶颈**。

## 六、其他实用手段

- **定期清理实体**：给掉落物、经验球设置合理存活时间；有插件可做定时清理。
- **限制 TNT / 高频红石**：对公开服，限制爆炸与高频红石能显著减少恶意卡服。
- **限制跑图**：用世界边界（world border）约束活动范围，避免无限生成。
- **定期重启**：不是"优化"，但能清掉部分插件内存泄漏，作为**临时缓解**手段可用（治标不治本）。
- **升级硬件**：如果 spark 显示 CPU 被主线程吃满且配置已调优，那就是**该换单核更强的机器**了。

## 七、优化的底线

```
优化不能以牺牲"原版行为"为代价 —— 除非你明确不需要原版行为
```

对生电服：**宁可卡一点，也要保证机器能工作**。
对普通生存服：**可以适度激进**，优先保证在线体验。

## 结语

到这里，Java 版开服的完整链路就走完了：

```
协议与配置 → 操作系统 → 环境准备 → 服务端选择 → 开启服务端
   → 服务端结构 → 配置服务端 → 部署 → 常用指令
   → MCDR → 插件 → 生电
   → 经营管理 → 跨服端 → 手机玩家 → 备份 → 反作弊 → 性能优化
```

需要回顾某一环，随时从左侧目录回到对应章节。核心选型的逐项对照见 [服务端核心对比](/wiki/compare#mcsog-h-%E6%A0%B8%E5%BF%83%E5%AF%B9%E7%85%A7)。
