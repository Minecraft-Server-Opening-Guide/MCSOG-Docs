玩家进不来，提示"版本不兼容"或者"过旧的客户端"，是开服时最常见的求助之一。原因很简单：服务端和客户端说的是同一套协议的不同版本，双方对不上话。跨版本插件做的事，就是在中间当翻译。

这一篇讲清楚 Via 系列各自负责什么方向、装在哪里、谁依赖谁，以及它们做不到什么。前置知识见 [插件入门](/tutorials/java/plugins)。

## 1. 为什么玩家进不来

Minecraft 的 Java 版客户端和服务端通过一套二进制协议通信。每个游戏版本都会改动这套协议：加了新数据包、改了字段顺序、换了数值含义。协议版本对不上，握手阶段就会失败，玩家看到的通常是一句版本不匹配的提示。

服务端只认自己那个版本（以及少量兼容版本）的客户端。于是：

- 服务端是 1.20.4，玩家用 1.21 客户端：进不来。
- 服务端是 1.21，玩家用 1.8 客户端：同样进不来。

跨版本插件的工作方式，是在服务端这一侧接收玩家的数据包，把它们翻译成服务端能理解的形式，再把服务端的回应翻译回玩家的协议版本。**玩家客户端不需要装任何东西。**

:::warn 跨版本不是万能方案
它翻译的是协议，不是玩法。跨的版本越大，能对上的东西越少，体验下降越明显，详见第 5 节。
:::

## 2. Via 三件套各管什么

Via 系列是一个家族，三个插件分别负责不同的方向。方向记法：**"向上"指让更新的客户端进来，"向下"指让更旧的客户端进来。**

| 插件 | 方向 | 作用 | 依赖 |
| --- | --- | --- | --- |
| **ViaVersion** | 向上兼容 | 让比服务端更新的客户端进服 | 无，是核心 |
| **ViaBackwards** | 向下兼容 | 让比服务端更旧的客户端进服 | 需要 ViaVersion |
| **ViaRewind** | 向下兼容更老的版本 | 支持 1.7.x 与 1.8.x 客户端 | 需要 ViaVersion，通常与 ViaBackwards 一起装 |

举例说明覆盖范围：

- 服务端 1.9.x，只装 ViaVersion：允许 1.9.x 到最新版的客户端进服。
- 服务端 1.21.x，装上 ViaVersion + ViaBackwards：允许 1.9.x 到 1.20.x 的客户端进服。
- 再加上 ViaRewind：覆盖到 1.7.x 与 1.8.x。

三者叠加后，插件版 Via 大致覆盖 1.7 到最新版这一整段。

### 下载渠道

| 插件 | 发布页 |
| --- | --- |
| ViaVersion | SpigotMC 资源 19254、Hangar、Modrinth、GitHub |
| ViaBackwards | SpigotMC 资源 27448、Hangar、Modrinth、GitHub |
| ViaRewind | SpigotMC 资源 52109、Hangar、Modrinth、GitHub |

官方构建站是 `ci.viaversion.com`，需要最新构建时从这里取。

:::note Java 8 支持
新版本的 Via 系列已经去掉了对 Java 8 的支持，因此在很老的服务端上无法直接使用。如果你要让 1.8 到 1.21 的服务端都能用，需要从构建站上取专门的 Java 8 分支版本。
:::

:::tip 版本要对齐
同时安装 ViaVersion 与 ViaBackwards 时，尽量选同一时期的版本。更新过代理端之后，也要记得把 Via 系列一起升到最新，否则会出现"装了跨版本却仍然提示版本不支持"的情况。即使不用代理端，也建议至少每月更新一次。
:::

## 3. 装在哪里：服务端还是代理端

Via 系列在 BungeeCord、Velocity 和各种 Minecraft 服务端上都能装，但装的位置不同，效果和坑也不同。

| 安装位置 | 优点 | 代价 |
| --- | --- | --- |
| 后端服务端 | 后端拿到的是玩家**真实的客户端版本**，反作弊与数据包类插件工作正常 | 每台后端都要装一套，配置要各自维护 |
| 代理端 | 只需装一次，玩家在进入任何后端之前就完成翻译 | 后端服务端看到的玩家版本是**代理端的版本**，不是玩家客户端的真实版本 |

如果你用了反作弊、反假人这类对数据包做大量处理的插件，把 Via 装在代理端容易引起兼容性问题，需要谨慎。反过来，如果你只有一个后端，或者希望玩家在选服之前就完成翻译，装在代理端会更省事。

:::warn 跨版本与模组端
跨版本方案不适合模组服。模组会改动协议与注册表内容，跨版本插件无法翻译这些自定义部分，混在一起用会出很多问题。
:::

## 4. 安装顺序与相互关系

三个插件的关系是层层依赖的：

1. **先装 ViaVersion**。它是核心，单独装它就已经具备向上兼容能力。
2. **需要向下兼容时再加 ViaBackwards**。它把新版本协议回退成旧版本能理解的形式。
3. **需要支持 1.7 与 1.8 时再加 ViaRewind**。它需要配合 ViaRewind Legacy Support 才能发挥完整的兼容能力。

加载顺序上，让 ViaVersion 先加载、ViaBackwards 与 ViaRewind 后加载即可，通常由服务端按依赖关系自动处理，不需要手动干预。装完后重启服务端，在控制台确认三个插件都加载成功。

## 5. 能做到什么、做不到什么

这是最容易产生误解的部分：**Via 翻译协议，不添加内容。**

| 玩家会遇到的现象 | 原因 |
| --- | --- |
| 高版本客户端进低版本服务端，用不了高版本物品的功能 | 服务端根本没有这些物品的逻辑，只能用材质相近的低版本物品代替显示 |
| 低版本客户端看不到高版本物品的材质 | 客户端没有对应的模型与贴图资源，官方插件不处理；1.16 以上有绕过手段，但不是官方能力 |
| 1.17 以下的客户端看不到 y=0 以下的方块 | 旧客户端的协议与渲染不支持负高度，官方明确表示不会修复 |
| 进服后行为怪怪的：回弹、动作不同步、界面错位 | 跨的版本太大，双方能对上的概念太少 |
| 提示发送数据包过多被踢出 | 触发了两侧的 pps 限制，见下 |

跨版本越大，体验下降越明显。除非你有能力让低版本玩家也获得不错的体验，否则不要盲目追求"全版本通吃"。

### 常见配置项

| 配置项 | 用途 |
| --- | --- |
| `serverside-blockconnections` | 方块材质或连接纹理显示不对时，改为 `true` 试试 |
| `max-pps` | 玩家因发送数据包过多被踢出时调整；使用 Paper 分支时可直接设为 `-1`，再单独调整 Paper 自身的 pps 限制 |
| `fix-1_13-face-player` | 为 1.12 玩家转换 1.13 的皮肤数据包，需要额外的缓存 |
| `handle-pings-as-inv-acknowledgements` | 对 1.17 以下客户端发送物品栏确认数据包来替代 ping，对反作弊兼容性有帮助 |
| `replace-adventure` | ViaRewind 的选项，控制 1.9 的粒子是否被替换为 1.8 及更低版本的近似粒子 |

:::warn 不要直接关掉 pps 限制
把数据包限制调高是为了让正常玩家不被误踢，但完全禁用会让恶意玩家有机会用数据包攻击卡服。调到"正常玩家不会触发"的水平即可。
:::

## 6. 独立版：ViaProxy

如果你连服务端核心都不方便改，还有一个独立方案：**ViaProxy**。它是一个独立的代理程序，支持任意客户端版本连接任意服务端版本，不需要在服务端里装插件。

它的覆盖范围比插件版宽得多，包括远古的 Alpha、Beta 与 Classic 版本、愚人节快照、战斗测试快照，甚至可以通过 Geyser 让基岩版玩家接入。下载在 ViaVersion 的 GitHub Releases 与官方构建站上。

:::note 什么时候用它
当你想让现代客户端进入十年前的旧服务端，或者只想临时验证某个版本的兼容性，ViaProxy 比改造服务端省事得多。但它是独立进程，多了一层转发，也意味着多一处要维护和排障的地方。
:::

## 7. 排障速查

| 现象 | 先查什么 |
| --- | --- |
| 装完仍提示版本不支持 | Via 系列是否为最新；代理端升级后是否同步升级了 Via |
| 部分玩家进不来，其他人正常 | 这些玩家的客户端版本是否超出了当前插件的覆盖范围 |
| 材质或纹理显示异常 | `serverside-blockconnections`；低版本看不到高版本材质属于预期行为 |
| 玩家被踢，提示数据包过多 | `max-pps` 与 Paper 的 pps 限制 |
| 反作弊误报或行为异常 | Via 是否装在代理端；后端拿到的是代理端版本而非玩家真实版本 |
| 低版本玩家在 y=0 以下疯狂回弹 | 已知限制，不会修复 |
