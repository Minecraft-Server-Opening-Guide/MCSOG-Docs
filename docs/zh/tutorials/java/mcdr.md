MCDReforged（简称 **MCDR**）是开服圈里非常流行的一个**服务端管理器**。它不替代你的服务端核心，而是**包在核心外面**：由它来启动和管理核心进程，读取控制台输出，从而在**不改动服务端本体**的前提下扩展功能。

## 一、它解决什么问题

原版 / Paper 服务端能扩展的只有"插件"，而 MCDR 提供的是**另一层**能力：

| 能力 | 说明 |
| --- | --- |
| **插件生态** | 用 **Python** 写插件，能做很多 Java 插件不方便做的事（跨服转发、外部 API 对接、自动化运维） |
| **事件驱动** | 解析服务端输出并分发事件（玩家进出、聊天、死亡、指令……），插件订阅即可 |
| **热重载** | 插件通常能重载，不必重启整个服务端 |
| **权限系统** | 自带一套按玩家/按群的权限控制，配合 `!!` 前缀指令使用 |
| **看门狗** | 核心崩溃后可自动重启 |
| **跨服** | 一套 MCDR 可以管理多个服务端实例 |

## 二、它是怎么工作的

MCDR 启动后会**托管服务端进程**：它把服务端的控制台输出读进来解析成事件，同时把你在聊天框里输入的 `!!xxx` 指令拦下来交给插件处理，而不是丢给原版服务端。

所以：

- 服务端**本身**还是原来的核心，行为不变；
- 你多了一层"外壳"，**故障排查时要多看一层日志**（MCDR 自己的日志 + 服务端日志）。

## 三、安装

MCDR 用 **Python 3** 编写，依赖 Python 与 pip：

| MCDR 版本 | 需要的 Python |
| --- | --- |
| < 2.10 | ≥ 3.6 |
| ≥ 2.10 | ≥ 3.8 |
| ≥ 2.15 | **≥ 3.9** |

装最新版就用 **pip** 安装：

```bash
pip install mcdreforged
```

:::warn 不要下载源码 zip 来运行
网上不少教程让你去 GitHub 下载压缩包解压使用——**那是过时做法**。MCDR 从 1.0（2021 年初）起就不再以源码方式安装。除非你是开发者且清楚在做什么，否则请用 pip 安装。
:::

## 四、启动流程

1. **初始化**：执行一次初始化命令，MCDR 会生成自己的配置文件与目录结构。
2. **配置**：在 MCDR 的配置里填好**服务端的启动命令**与**工作目录**（也就是「开启服务端」里那个启动脚本干的事，现在交给 MCDR 来做）。
3. **启动**：运行 MCDR，它会拉起服务端，并接管控制台。
4. **确认服务端类型**：MCDR 通过**服务端处理器**适配不同类型的核心（原版 / Paper 系 / 模组端等），选错会导致事件解析异常。

:::tip 命令行子命令以官方文档为准
MCDR 的命令行接口（全局参数、子命令）在各版本间有调整，**具体写法请对照官方 CLI 文档**，不要照抄旧教程。
:::

## 五、指令与权限

MCDR 的指令统一用 `!!` 前缀（在游戏内聊天框输入即可）：

| 指令 | 作用 |
| --- | --- |
| `!!MCDR` | 主命令，管理 MCDR 自身（状态、插件、重载、权限等） |
| `!!help` | 查看已注册的指令帮助 |

- 指令的执行权限由 MCDR 的**权限系统**控制，可按玩家或权限组授予。
- 未授权的玩家执行会收到拒绝提示，不会影响到服务端本体。

## 六、插件

- 插件放进 MCDR 的 `plugins/` 目录，通过 `!!MCDR` 相关子命令加载 / 重载。
- 官方有一个**插件仓库**，可以在里面找现成插件；也可以自己写（单文件插件、多文件插件、文件夹插件等几种形式）。
- 插件开发的核心是**元数据 + 事件监听 + 命令树**：声明插件信息，注册感兴趣的事件，构建自己的 `!!` 指令。

## 七、什么时候该用 MCDR

**适合**：想要自动化运维（定时重启、崩溃拉起、备份联动）、想把服务端状态对接到外部平台（QQ 群、Discord、网站）、或需要写 Python 插件做定制逻辑。

**不一定需要**：只是开个小型插件服，用核心自带的插件 + systemd 托管就够了。**多一层就多一层维护成本**，别为了用而用。
