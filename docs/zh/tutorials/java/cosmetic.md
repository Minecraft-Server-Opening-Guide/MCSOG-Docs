前面几篇讲的是"服务器能不能跑起来"和"能不能防住破坏"。这一篇讲的是另一类插件：它们不改玩法规则，但直接决定玩家**看到的界面**——聊天框、箱子菜单、服务器列表里的那两行字，以及主城上空飘着的浮空字。

这类插件装错了通常不会崩服，只是"看起来不对劲"，所以最容易被忽视。但它们恰好是玩家进入服务器后最先接触的东西。

## 一、聊天插件：不只是好看

聊天插件的作用是**接管玩家发出的聊天信息**，再按规则重新组装后广播出去。

最直观的能力是格式：给消息加上前缀、后缀、称号，或者把纯文本换成带颜色的内容。但真正让聊天插件成为**管理工具**的，是下面这几类功能：

| 能力 | 解决什么问题 |
| --- | --- |
| 多频道 | 常规、全局、私聊、管理频道分开；管理员说话可以和普通玩家区分 |
| 敏感词过滤 | 自动拦截脏话与广告，**不限于聊天**，木牌、铁砧命名等输入口一并覆盖 |
| 聊天冷却 | 限制发言间隔，防刷屏 |
| 提及提醒（@） | 玩家被点名时用音效、标题提醒，避免漏看 |
| 私聊监听 | 管理员可切换监听模式，排查私聊中的骚扰与交易纠纷 |
| 颜色权限 | 谁能用哪种颜色代码由权限控制，而不是人人可用的"彩虹刷屏" |
| 物品展示 | 在聊天里展示手中物品、背包甚至末影箱，交易和求助时省掉大量描述 |
| 变量支持 | 接入 PlaceholderAPI 后，聊天里可显示余额、在线人数等实时数据 |

**聊天插件是服务器里最便宜的审核手段**。没有它，你只能靠人盯着屏幕；有了它，规则由配置执行。

### 常见聊天插件对比

| 插件 | 定位 | 值得注意的地方 |
| --- | --- | --- |
| **TrChat** | 功能最全的高级聊天系统 | 多频道、云端敏感词库、物品展示、@ 提及、跨服（Bukkit / BungeeCord / Velocity）、正则替换、PlaceholderAPI；版本覆盖 1.8 到最新 |
| **Carbon** | 设计现代的聊天插件 | 结构清晰、可扩展性好，适合想要"干净实现"而不是"功能堆叠"的场景 |
| **InteractiveChat** | 聊天**增强**，通常配合别的格式插件使用 | 核心是交互：`[item]`、`[inv]`、`[ender]` 等关键词、自定义悬停与点击、玩家名交互、跨服提醒、RGB 颜色 |
| **HuskChat** | 跨服聊天 | 已停止开发，新项目不建议作为首选 |
:::tip 先想清楚要什么
如果你只是想让聊天"有前缀、有颜色"，其实**基础插件**（EssentialsX / CMI 一类）就能做到，不必额外装聊天插件。真正需要独立聊天插件的是这三种需求：**多频道**、**内容过滤**、**跨服**。
:::
:::warn 前置别忘了
聊天插件几乎都会用到变量。要在格式里写"余额""在线人数"这类内容，先装 **PlaceholderAPI** 并安装对应扩展，否则占位符会原样显示成一段文字。详见 [插件前置与依赖](/tutorials/java/plugin-deps)。
:::

## 二、菜单插件：把指令变成箱子界面

菜单插件（也叫 GUI 菜单、箱子菜单）做的事情是：**用配置文件描述一个箱子界面**，里面的每个格子是一个图标，点一下执行一条动作。

它解决的问题很实际——玩家记不住指令。与其让新人背 `/warp shop`、`/kit starter`，不如给他一个箱子，点图标就行。

典型用途：

- **服务器导航**：主菜单点进商店、传送、活动、规则
- **商店与兑换**：以物易物、扣钱发货、限购
- **礼包与签到**：按权限或冷却发放物品
- **玩家信息面板**：显示自己的统计、余额、称号

### 菜单插件对比

NitWikit 把菜单插件按功能强弱排成一条线：**ChestCommands < DeluxeMenus < TrMenu**。

| 插件 | 强度 | 说明 |
| --- | --- | --- |
| **ChestCommands** | 入门级 | 年代很早，基本只适合 1.7 / 1.8 的老服务端；在高版本上功能明显不够用 |
| **DeluxeMenus** | 主力级 | 配置驱动、文档完善，绝大多数服务器的"够用"选择 |
| **TrMenu** | 高阶 | 功能与性能都很强，支持条件判断、子图标、Kether 脚本；v2 已停更，**用社区维护的 v3** |
| **Invero** | 视觉向 | 提供滚动窗口、逐帧动画、交互槽等效果，适合做"看起来不像原版箱子"的界面 |
:::note 关于可视化编辑器
菜单插件**没有**可视化编辑器，也不需要。用文本编辑器照着文档写配置文件就行。所谓"菜单编辑器"要么是生成 YAML 的辅助工具，要么会给你埋下看不懂的配置。
:::
:::tip 菜单插件依赖变量与权限
菜单里的"显示余额""仅 VIP 可见"这类效果，靠的是 **PlaceholderAPI** 和权限插件。装菜单插件前先把这两个基础打好，否则菜单能打开但内容全是死的。
:::

## 三、MOTD：服务器列表里的第一印象

玩家还没进服，先看到的是**多人游戏列表**里你服务器的那一条：图标、名称、两行描述文字、在线人数。这几样合起来就是 **MOTD**。

原版 `server.properties` 只能写两行纯文本，颜色也受限。MOTD 插件补上的正是这部分：

- **渐变与彩色文字**，以及粗体、斜体等样式
- **多行内容**与自动轮换
- **随机轮换**：每次刷新列表显示不同的一条 MOTD，用来轮流展示公告
- **伪造在线人数**：让列表里的数字显示成别的值
- **按条件显示**：不同玩家、不同状态看到不同内容

| 插件 | 说明 |
| --- | --- |
| **MiniMOTD** | 支持范围广的 MOTD 插件，Bukkit / Spigot / Paper 系与代理端都能用，随机轮换是它的常见用法 |
:::warn 不要只改名称
MOTD 是**玩家判断"这个服还活着吗"的最快依据**。两行空着、写着"未命名服务器"、或者人数显示为 0 的服，即使内容做得再好，也很少有人点进去。花十分钟写一条清楚的 MOTD（**服务器类型 + 特色 + 联系方式**）是性价比最高的改动之一。
:::

## 四、全息图：可选的点缀

全息图（浮空字）指的是固定在某个位置、始终朝向玩家的悬浮文本，也可以包含展示用的实体和物品。

它属于**锦上添花**的一类，常见用法：

- 主城出生点的欢迎语与规则摘要
- 商店招牌上直接标价，省掉一个告示牌
- 排行榜、活动倒计时
- 传送点与地标的标注

| 插件 | 说明 |
| --- | --- |
| **DecentHolograms** | 轻量但功能完整，配置项多，另有伤害显示、回血显示等可选特性；**当前首选** |
| **HolographicDisplays** | 老牌全息图插件，仓库已归档、不再有新提交；旧服可能还在用，新项目建议直接选 DecentHolograms |
:::note 有些限制来自游戏本身
全息图的几个"毛病"不是插件的问题，而是 Minecraft 的限制：文本**始终朝向玩家**，无法单独调整字号与字体；部分实体（例如浮空物品图标）会自行旋转与上下浮动，还会发出声音。插件层面解决不了，只能用资源包做自定义字体等绕行方案。
:::

## 五、装之前先排个顺序

这几类插件之间有依赖关系，建议按下面的顺序装：

1. **前置**：PlaceholderAPI、权限插件、经济插件（见 [插件前置与依赖](/tutorials/java/plugin-deps)）
2. **基础插件**：提供 warp、kit 这些被菜单调用的指令
3. **聊天插件**：确定聊天格式，并留出变量位置
4. **菜单插件**：把指令包装成界面
5. **MOTD 插件**：最后调整对外展示
6. **全息图**：等世界和商店位置定下来再做，否则改一次搬一次
:::tip 一次只装一个
这类插件都会改玩家可见的文本。同时装三个再调试，你分不清是哪个插件在输出。装一个、重启、看效果，再装下一个。
:::
