服务端能在本机跑通，只是第一步。**让别人也能连上**，才叫真正开服。这一步的难点几乎全在网络，不在 Minecraft 本身。

## 一、三条路线，先选一条

| 方案 | 适合 | 优点 | 代价 |
| --- | --- | --- | --- |
| **云服务器** | 想长期 24 小时在线 | 有公网 IP、稳定、不怕停电断网 | 要花钱，配置越好越贵 |
| **自家电脑 + 公网 IP** | 家里有公网 IPv4 | 不额外花钱，性能可控 | 电费/噪音/断电断网，且**多数家宽没有公网 IPv4** |
| **内网穿透（frp 等）** | 家里没有公网 IP | 不用换宽带也能开 | 多一层转发，延迟与稳定性取决于穿透服务 |

:::warn 先确认你有没有公网 IPv4
IPv4 地址稀缺，**很多家庭宽带拿到的是运营商大内网地址**，此时无论怎么配路由器端口映射都没用。判断方法：路由器 WAN 口 IP 与"我的公网 IP"查询结果**不一致**，就说明没有公网 IPv4。

没有公网时的选择：向运营商申请（部分地区免费、部分收费、部分不给）、改用云服务器、或用内网穿透。
:::

## 二、云服务器路线

1. **买机器**：按「开服协议与配置推荐」选，重点看**单核频率**；系统选 Ubuntu / Debian 的 Server 版。
2. **装环境**：按「环境准备（Windows 与 Linux）」装对应版本 Java、建专用用户、建目录。
3. **放行端口**：安全组放行 `TCP 25565`，系统防火墙（ufw / firewalld）也要放行，**两处都要**。
4. **上传服务端**：用 SFTP 或 `scp` 把整个服务端目录传上去。
5. **启动并常驻**：用 systemd 托管，做到开机自启、崩溃重启（见「环境准备」第五步）。
6. **验证**：从**另一台机器**连 `你的公网IP:25565`。

## 三、自家电脑路线

1. **申请/确认公网 IPv4**（见上）。
2. **路由器端口映射**：把外网 `25565` 转发到内网那台机器的 `25565`（TCP）。
3. **固定内网 IP**：给这台机器在路由器里绑定静态 IP，避免重启后 IP 变了映射失效。
4. **系统防火墙**放行 `25565`。
5. **保证不掉线**：电源选项设为**从不睡眠**，并考虑断电与断网风险。

## 四、内网穿透路线（frp）

原理：你在**有公网 IP 的机器**（frps 服务端）上开一个端口，把流量转发回你家内网机器（frpc 客户端）。常见做法是租一台最便宜的云服务器当 frps。

```ini
# frps.ini（放在有公网的服务器上）
[common]
bind_port = 7000
```

```ini
# frpc.ini（放在你家内网机器上）
[common]
server_addr = 你的公网服务器IP
server_port = 7000

[minecraft]
type = tcp
local_ip = 127.0.0.1
local_port = 25565
remote_port = 25565
```

启动顺序：先跑 `frps`，再跑 `frpc`，之后玩家连**公网服务器的 IP:25565** 即可。

:::tip 也可以用现成的穿透服务
不想自己维护节点，可以用商用的内网穿透服务，省事但通常有流量/带宽限制，且**质量参差**——选择时先看是否支持 **TCP**（UDP 通常要额外付费，基岩版或跨端才需要）。
:::

## 五、域名（可选但推荐）

有域名后玩家不用记 IP：

- **A 记录**：`mc.你的域名.com` → 服务器公网 IPv4。
- **SRV 记录**：想省掉玩家输入端口，可用 SRV 把 `_minecraft._tcp` 指向你的实际端口。这样玩家只填域名就能进。

注意：**国内服务器解析域名通常需要备案**，海外服务器则不需要。

## DNS 与 SRV 记录

上一节说到「有域名后玩家不用记 IP」，真正落地靠的是 DNS 记录。这一节把开服会用到的记录类型、SRV 的准确写法和排查方法一次讲清楚。

### 开服会用到的几种记录

| 记录类型 | 作用 | 例子 | 注意事项 |
| --- | --- | --- | --- |
| `A` | 域名 → IPv4 地址 | `mc.example.com` → `203.0.113.10` | 最基础的一条；同一个名字可以有多条 A 记录 |
| `AAAA` | 域名 → IPv6 地址 | `mc.example.com` → `2001:db8::10` | 服务器有 IPv6 时才需要；玩家用 IPv6 连不上先查这里 |
| `CNAME` | 别名，指向另一个域名 | `mc.example.com` → `node1.example.net` | **同一个名字上不能与其他记录共存**：有了 CNAME 就不能再有 A / AAAA / TXT 等；根域名通常也不允许 |
| `SRV` | 声明某项服务在哪个主机、哪个端口 | `_minecraft._tcp.example.com` | Java 版专用，见下文 |
| `TXT` | 文本记录，常用于验证与声明 | `_acme-challenge.example.com` 的验证值 | 域名所有权验证、邮件配置常用；对开服本身不直接影响 |

**TTL** 是每条记录的缓存时间，单位秒，决定「改完记录之后全世界要多久才看到新值」。日常可以设大一些（如 `3600`）；**计划迁移前先把 TTL 调小**（如 `300`），等旧 TTL 过期后再切换，出问题时才能快速切回。迁移的完整流程见 [服务器迁移](/tutorials/ops/server-migration)。

### SRV 记录是干什么的

Minecraft 的默认端口是 `25565`。如果服务跑在别的端口，或者根本在另一台机器上，玩家就得输入 `mc.example.com:25566` 这种带端口的地址。**SRV 记录就是用来省掉端口的**：它告诉客户端「这个域名对应的 Minecraft 服务其实在哪个主机、哪个端口」，玩家只填域名就能进。

Java 版的 SRV 查询名称是固定的 `_minecraft._tcp.<你的域名>`。写在区域文件里长这样：

```dns
; 玩家输入 mc.example.com，服务实际跑在 node1.example.com 的 25566 端口
_minecraft._tcp.example.com.  3600  IN  SRV  10 5 25566 node1.example.com.
node1.example.com.            3600  IN  A    203.0.113.10
```

四个数值字段的含义：

| 字段 | 示例 | 含义 |
| --- | --- | --- |
| `priority` | `10` | 优先级，**数值最小者优先**；只有优先级相同的记录之间才会互相分担 |
| `weight` | `5` | 权重，仅在优先级相同时生效，按比例分配，数值越大被选中的概率越高 |
| `port` | `25566` | **服务真正监听的端口**，不是 25565 |
| `target` | `node1.example.com.` | 服务真正所在的主机名，它**必须自己能被解析** |

关于 `target` 有两条硬性要求：它必须是主机名，且通常应指向一条 `A` / `AAAA` 记录；不要让它指向一条 CNAME，更不要让 CNAME 再指向 CNAME。

:::warn target 不能写成 IP 字面量
把 `target` 填成 IP（例如 `SRV 10 5 25566 203.0.113.10.`）在协议上是**无效**的，客户端不会使用这条记录，即使某些面板允许你把它填进去。正确做法是给目标主机建一条 `A` / `AAAA` 记录，再让 `target` 指向那个主机名。
:::

:::warn 最常见的错误：target 末尾漏了点
在多数 DNS 服务商的控制台里，`target` 必须写成**带末尾点**的完整域名（`node1.example.com.`）。漏掉这个点，控制台会把它当成「相对于当前区域」的名字，于是变成 `node1.example.com.example.com.`——记录等于白写，而且**不会有任何报错**。
:::

### 基岩版不支持 SRV

这一点必须说清楚：

- **Java 版客户端会查询 `_minecraft._tcp` 的 SRV 记录**，所以 Java 玩家只填域名就能进。
- **基岩版客户端不使用 SRV 记录**。基岩版玩家必须输入 `主机:端口`（例如 `mc.example.com:19132`），或者用一个直接解析到正确地址、端口也一致的域名。

所以 SRV 是 **Java 版专属的便利**。服务器同时服务两个版本时，别指望一条 SRV 解决所有玩家——基岩版那边该写端口还是要写。

### 怎么验证记录真的生效了

```bash
# 查 SRV 记录（Linux / macOS）
dig +short SRV _minecraft._tcp.example.com

# 查 SRV 记录（Windows 或没装 dig 的机器）
nslookup -type=SRV _minecraft._tcp.example.com

# 查 A 记录
dig +short A example.com
```

- `dig +short SRV` 正常会返回 `10 5 25566 node1.example.com.` 这样的四段内容；返回空说明记录没生效、名字写错，或者你查的不是权威服务器。
- 再用 `dig +short A node1.example.com` 确认 **target 本身能解析**——这一步最容易被漏掉。
- 最后做**客户端实测**：在游戏里添加服务器，只填域名，看客户端能不能自己补上端口并连上。

DNS 修改不是立刻生效的，要等旧 TTL 过期。排查时可以先用 `dig @ns1.example.com ...` 直接问权威服务器，确认记录已经写对，再等缓存过期。**SRV 写错最阴的地方在于「不报错」**：客户端只会表现为连不上，而不会提示你 SRV 有问题。

### 常见故障对照表

| 现象 | 原因 | 检查方法 |
| --- | --- | --- |
| 用 IP 能连，用域名连不上 | SRV 的 `target` 解析不了，或 `port` 填错 | `dig +short SRV _minecraft._tcp.你的域名`，再 `dig +short A` 查 target |
| 能连上，但进的是另一个服务器 | 记录是旧的，或改完还没等 TTL 过期 | 对比 `dig` 结果与实际 IP / 端口；必要时先降 TTL 再改 |
| 基岩版玩家用短地址进不来 | 基岩版不支持 SRV | 让玩家改填 `主机:端口`，或另备一条直连域名 |
| 记录加了但毫无变化 | TTL 还没过期，或改错了区域（比如改的是 `example.com`，玩家查的却是 `mc.example.com`） | 直接查权威服务器；确认记录加在正确的 zone 下 |
| 域名解析正常但连不上 | DNS 没问题，是防火墙或安全组没放行 | 从外部机器用 `telnet 域名 端口` 或 `nc -vz 域名 端口` 测试 |

### 代理与面板的额外记录

- 前面挂了 **Velocity / BungeeCord 代理**时，SRV 的 `target` 应该指向**代理**的地址，`port` 填代理的监听端口，而不是某个后端子服。
- 用了**面板**（MCSManager、Pterodactyl 等）时，面板的访问地址是另一回事：它通常需要独立的子域名（如 `panel.example.com`）配合反向代理，**与游戏用的 SRV 记录互不影响**，不要混在同一条记录里。
- 部分服务商或机房还会要求额外的验证记录（`TXT`、`CNAME`），按他们给的说明加即可。

## 六、上线前的安全检查清单

- [ ] `online-mode` 保持 `true`（除非明确知道风险）
- [ ] 控制台/RCON 端口（如 `25575`）**绝不暴露到公网**
- [ ] Linux 下**不要用 root 跑服务端**，用专用用户
- [ ] 已配置白名单或进服审核（公开前先小范围测试）
- [ ] 已开启**自动备份**（见「备份与恢复」）
- [ ] 已装**防破坏/记录类插件**（见「插件」与「反作弊」）
- [ ] 已用外部机器验证过端口可达
