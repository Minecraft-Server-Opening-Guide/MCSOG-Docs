反作弊在普通生存服上是加分项，在生电服上却常常是负收益。原因不是"反作弊不好用"，而是**生电玩家的正常玩法本身就会持续触发反作弊判定**。

还有一个更直接的事实：官方 Carpet 自己就提供了 `antiCheatDisabled` 这条规则（作用是防止玩家因移动过快被回拉）。官方在规则系统里给出这个开关，说明生电服真正需要的是**关掉原版那套针对快速移动的回拉检测**，而不是再加一层判定。

这篇只谈结论与替代方案：为什么冲突、误判从哪来、以及不加反作弊的话你该做什么。[反作弊与防破坏](/tutorials/java/anticheat) 讲的是通用的两层防护与配置方法，本篇不重复那些内容。

## 一、官方给的反向信号

先把最有说服力的一条事实摆出来。

| 规则 | 含义 |
| --- | --- |
| `antiCheatDisabled` | 关掉它，玩家因移动过快被回拉的现象就不再发生 |

这条规则值得逐句读：

- 它处理的是"**移动过快被回拉**"这一件事，也就是原版针对快速移动的检测。这里说的"检测"指原版自身的行为，不是第三方反作弊。
- 它的存在说明：**生电服真正需要的是关掉原版这一层回拉检测**，而不是在它之上再加一层判定。

## 二、正常玩法为什么会触发判定

生电玩家的日常操作，在判定逻辑眼里几乎全是异常信号：

| 生电玩法 | 在判定逻辑眼里像什么 |
| --- | --- |
| 高速移动（鞘翅、冰道、矿车、活塞弹射一类位移手段） | 超速移动、位置不连续 |
| 大量实体（刷怪塔、TNT 阵列、掉落物与经验球堆积） | 异常实体行为与异常密度 |
| 机器与自动化（飞行器、连发装置、无人值守的长时运行） | 高频、重复、与人手操作不一致的动作 |

关键在"持续"两个字：这不是偶尔撞上一次判定，而是**玩法本身长期贴着判定的边界走**。结果是两类损失：

1. **误判直接打断机器与测试**：被回拉、被取消动作、被踢出，一次测试可能就白跑了。
2. **误判不可复现**：机器坏掉的原因通常很难查，如果还叠加一层会随机干预移动与操作的判定，排查成本会成倍上升。

:::warn 本篇不讨论任何具体判定阈值
不同反作弊的实现与阈值各不相同，这里不列举、不比较，也不点评任何具体产品。要判断的是**逻辑上的冲突**：一套以"人类正常操作"为基准的判定，遇上以"突破人类操作上限"为目标的玩法，冲突是必然的。
:::

## 三、装在哪一侧，代价是什么

反作弊通常要求装在**插件端或优化端**上。问题在于，优化端本身就会改原版行为，而这两件事与生电目标直接冲突：

| 冲突点 | 说明 |
| --- | --- |
| 平台冲突 | 反作弊主要面向插件端生态，而生电工具链（Carpet 及其附属包）在 Fabric 上 |
| 行为冲突 | 优化端的默认配置本身就偏离原版行为，机器可能不工作或产出不稳定 |
| 目标冲突 | 反作弊要"限制异常"，生电要"利用异常"，两者的方向相反 |

核心选型与优化端的取舍，见 [服务端选择](/tutorials/java/core)；插件端为什么要逐项调回原版行为，见 [生电与红石](/tutorials/java/redstone)。本篇只给一句结论：**方向相反的组件，装上去只会互相抵消。**

## 四、不加反作弊，那装什么

反过来问更有用：**你到底想防什么？**把这个问题拆开，每一类都有比反作弊更稳的手段：

| 想防的事 | 该用的手段 | 说明 |
| --- | --- | --- |
| 陌生人乱来 | 白名单与权限 | 把门槛放在进服之前，比事后判定便宜得多 |
| 破坏与偷窃 | `ledger` 记录与回溯 | 它是服务端侧的记录 mod，对标插件端的 CoreProtect |
| 最坏情况 | 定期与异地备份 | 出事能整体回档，这是最后一道防线 |
| 人肉盾构机、自动破基岩一类 | `playerOperationLimiter` | 每 gt 玩家可以放置 2 个方块，秒破 1 个方块，这两个操作每 gt 只能做一种，用于防人肉盾构机和玩家自动破基岩 mod |

几点补充：

- **白名单与权限**：生电服通常是熟人圈子，把"谁能进来"控制住，比在服内做实时判定有效得多。权限分开配置的思路见 [领地与保护](/tutorials/java/protection)。
- **记录与回溯**：`ledger`（对标插件端的 CoreProtect）属于记录类工具，它不做实时拦截，但**能回答"是谁、什么时候、动了什么"**。没有记录，你连处理依据都没有。
- **备份**：定期备份与异地备份解决的是"前面都失效了"的情况，完整的策略与恢复流程见 [存档保护](/tutorials/java/sd-backup)。
- **`playerOperationLimiter`**：请注意它是**服务端侧的限制手段**，作用在服务端自身，不需要玩家装任何东西。它限制的是每 gt 的放置与破坏操作，针对的是自动化滥用，而不是给正常玩家打分。它属于某个 Carpet 附属项目提供的规则，**装之前先按你的游戏版本与 mod 组合确认可用**。

## 五、该怎么做：一张正向清单

与其反复论证"不要装反作弊"，不如直接照着做：

1. **先进服门槛**：白名单或进服审核，把来源控制住。
2. **再做权限分级**：普通玩家、技术组、管理权限分开，不轻易给 OP；谁能动机器、谁能用高风险操作，事先写清楚。
3. **装记录工具**：`ledger` 一类记录 mod 越早装越好，它只记录装上之后发生的事。
4. **配好备份**：定期备份加异地备份，并**实际演练一次恢复流程**——没验证过的备份不算备份。
5. **用服务端侧限制替代实时判定**：例如 `playerOperationLimiter` 这种在服务端自身生效、不依赖玩家客户端的手段。
6. **规则写明白**：允许什么、禁止什么、怎么处理，写在玩家看得到的地方。
7. **需要原版回拉检测时，用 `antiCheatDisabled` 关掉它**：这是官方规则系统给出的开关，比装第三方组件更可控，也更容易向玩家解释。

## 六、本篇的底线

```
1. 官方自己就提供 antiCheatDisabled —— 生电服要的是关掉原版回拉，不是再加一层
2. 生电的正常玩法会持续触发判定，误判是必然的，不是偶发
3. 反作弊要装在插件端/优化端，与生电目标方向相反
4. 替代方案：白名单与权限 + ledger 记录 + 定期异地备份 + 服务端侧限制
```
