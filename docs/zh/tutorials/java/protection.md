服务器一旦对公众开放，几乎必然会遇到同一类麻烦：**有人拆别人的建筑、有人翻别人的箱子、有人守在出生点追杀新人**。这些事靠事后讲道理很难收场，需要在规则和技术两个层面同时设防。本文只讲技术层面的**领地与保护**。

## 1. 为什么需要领地保护

公开服里最常见的问题可以归成三类：

| 问题类型 | 典型表现 | 保护插件的作用 | 记录插件的作用 |
| --- | --- | --- | --- |
| 破坏 | 拆建筑、烧森林、倒岩浆、铲平别人的农田 | 拦住非成员对方块的改动 | 查出是谁做的、把区域回滚 |
| 偷窃 | 翻箱子、拿熔炉和漏斗里的物品、牵走牲畜 | 禁止非成员打开容器与取用实体 | 查容器的存取记录 |
| 纠纷 | 抢怪、堵门、在别人家门口 PvP | 在区域内禁用 PvP 与部分交互 | 还原现场，作为处罚依据 |
:::note 保护是预防，记录是追溯
两者解决的不是同一个问题。保护插件负责**让破坏根本发生不了**，记录插件负责**事后查清并恢复**。真正稳妥的服务器两样都会装，原因见第 5 节。
:::

## 2. 两条路线：玩家自助圈地与管理端划区

领地类插件可以分成思路完全不同的两类。先分清这个，后面选插件才不会乱：

| | 玩家自助圈地 | 管理端区域保护 |
| --- | --- | --- |
| 谁划线 | **玩家自己**，用指令或工具圈 | **管理员**，用选区工具划 |
| 典型插件 | Residence、Dominion、GriefDefender | WorldGuard |
| 玩家要学指令吗 | 要，而且要理解圈地规则 | 基本不用 |
| 保护粒度 | 按玩家、按领地 | 按区域、按世界 |
| 适合的场景 | 生存服、允许自由建家的服 | 出生点、商店、活动场地、公共设施 |
| 管理成本 | 低，玩家自己管自己 | 高，每个区域都要管理员维护 |

**自助圈地是给每个玩家一把锁，管理端划区是给公共区域装围栏**。两者并不冲突，规模大一点的服务器通常同时使用。

## 3. 玩家自助领地插件

### Residence

老牌领地插件，开发历史超过十三年，最初由 bekvon 维护，后来由 Zrips 团队接手，并转为**开源付费**的运营模式。

- **前置**：需要 CMIlib 才能运行。
- **版本**：支持 1.8 以上的服务端，覆盖面很广。
- **安全**：为避免被已知漏洞利用，**不要使用 5.1.4.2 以下的版本**。
- 免费版本仍可从 SpigotMC 或 Zrips 官网获取。

它最大的优势是**知名度**：大量服务器用过，玩家对它的指令逻辑比较熟悉，老玩家上手成本低；生态兼容性也经过长期验证，与其他插件冲突的概率相对小。

### Dominion

由国内开发者开发的**完全开源、免费**的领地插件，从一开始就面向高版本设计。

- **版本要求**：仅支持 1.20.1 及以上（Bukkit / Spigot / Paper / Folia），**1.20 以下的服务端用不了**。
- **运行环境**：需要 Java 21。
- 虽然兼容 Spigot，但作者强烈建议使用 Paper 或其分支核心（如 Purpur）以获得更好的性能体验。
- 支持导入 Residence 的绝大部分数据，迁移成本较低。
- 项目目前仍标记为 beta，因此版本更新非常频繁：好处是问题修得快，代价是升级节奏也快。

### GriefDefender

同样是一款领地保护插件，提供英文与中文文档。需要注意的是，它的**开源代码停留在 2021 年**，此后没有继续公开，长期维护状态需要自行评估。

## 4. 管理端区域保护：WorldGuard

WorldGuard 的定位与上面三个不同：它不面向玩家自助圈地，而是让**管理员划定区域并设定规则**。

- **前置**：必须安装 WorldEdit 或 FastAsyncWorldEdit。
- **默认状态**：所有功能默认关闭，只启用你真正需要的那部分。

它能做的事大致分成两类。

**区域保护**

- 阻止玩家在指定区域内放置与破坏方块；
- 只允许特定的人在某个区域内建造；
- 在区域内禁用 PvP、TNT、怪物伤害等功能。

**世界规则调整**

- 阻止爬行者与凋灵造成的方块破坏，以及坠落伤害等；
- 关闭火焰蔓延、岩浆引燃、结冰、末影人搬走方块等机制；
- 把某些物品或方块加入黑名单，使其无法使用；
- 在使用特定物品或方块时向管理员发出警告；
- 防范一些利用游戏机制的刷物品漏洞；
- 提供"立即停止所有火焰蔓延"一类的实用管理指令。

WorldGuard 是**运营方的工具**，不是玩家的工具。它适合用在出生点、商店街、活动场地，以及需要统一规则的世界，例如资源世界禁止 PvP、禁止放置方块。

## 5. 领地与记录回溯插件的关系

不少人以为装了领地插件就不用管记录了，这是个常见误解：

- **领地只保护被圈起来的地方**。荒野、公共区域、还没圈地的空地都没有保护。
- **领地保护不了内部作案**。如果玩家把权限给了不靠谱的队友，或者把领地共享出去，插件不会阻止对方搬空箱子。
- **领地插件通常不提供回滚**。它拦得住的行为拦住了，没拦住的（爆炸、领地外的破坏、权限误配）依然需要记录插件来恢复。

所以标准组合是：**领地插件负责预防，CoreProtect 一类的记录插件负责追溯与回滚**。两者的分工与配置细节见 [反作弊与防破坏](/tutorials/java/anticheat)。
:::warn 记录插件要早装
它只能记录**安装之后**发生的事。等被破坏了才装，之前的记录一概没有。
:::

## 6. 对比表

| 插件 | 谁圈地 | 上手难度 | 版本要求 | 典型用途 |
| --- | --- | --- | --- | --- |
| **Residence** | 玩家自助 | 低，老牌且教程多 | 1.8+ | 生存服自由建家；玩家基数大的老服 |
| **Dominion** | 玩家自助 | 低到中 | 1.20.1+，需 Java 21 | 新开的高版本生存服，希望用开源方案 |
| **GriefDefender** | 玩家自助 | 中 | 视版本而定 | 需要较细权限分级的领地管理 |
| **WorldGuard** | 管理员 | 中到高，要学选区与 flag | 跟随 WorldEdit / FAWE | 出生点、商店、活动场地、世界级规则 |

## 7. 怎么选

可以按下面的顺序判断：

1. **服务端版本在 1.20.1 以上吗？**
   - 是：Residence 与 Dominion 都可以考虑。想要开源、更新活跃就选 Dominion；想要玩家熟悉、兼容性稳妥就选 Residence。
   - 否：Dominion 直接排除，在 Residence 与 GriefDefender 之间挑。
2. **玩家以老玩家为主还是新人为主？**
   - 老玩家多：Residence 的既有认知能省下大量答疑成本。
   - 全新玩家群体：Dominion 的指令设计更贴近高版本的使用习惯。
3. **需要给公共区域定规则吗？**
   - 需要：无论选了哪个领地插件，都再装一个 WorldGuard。
4. **有跨版本或特殊核心需求吗？**
   - 有：优先选兼容面更广、资料更全的方案，并先在测试服验证。
:::tip 不要同时装两个自助领地插件
Residence、Dominion、GriefDefender 解决的是同一个问题。同时装两个，玩家会不知道该用哪个，两个插件的选区逻辑还容易互相干扰。**选一个就好**；WorldGuard 属于另一层，可以和它们并存。
:::

## 8. 落地时的常见坑

- **圈地额度没限制**：给玩家的领地大小与数量要配好，否则一个人能把出生点周围全圈走。多数插件支持按权限组给不同额度。
- **权限节点没配**：领地插件的指令都要权限节点控制。没配好，要么玩家用不了，要么人人都是管理员。
- **领地重叠与相邻**：先确认插件对重叠、紧贴的领地如何处理，并把结论写进服务器规则。
- **领地传送被滥用**：领地传送是常见功能，但要限制频率与冷却，防止被当成免费的跨图交通。
- **只在主世界生效**：很多领地插件的保护是按世界配置的。开了多世界之后，记得检查资源世界、创造世界是否也有保护，或者是否**故意**不设保护——资源世界通常就是让人随便挖的。
