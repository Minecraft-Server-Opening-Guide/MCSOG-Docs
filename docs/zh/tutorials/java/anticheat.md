服务器一公开，就会遇到两类问题：**有人破坏/偷东西**，以及**有人用作弊客户端**。这两类要用不同的手段应对。

## 一、先分清两层防护

| 层次 | 目标 | 手段 | 优先级 |
| --- | --- | --- | --- |
| **记录与回溯** | 出事能查、能回滚 | CoreProtect / Prism 一类记录插件 |  **必备** |
| **实时反作弊** | 当场拦住作弊行为 | 反作弊插件（检测移动、战斗、发包） | 加分项 |
| **权限与审计** | 防"管理滥用" | 权限组 + 操作留痕 |  必备 |
| **进服门槛** | 减少麻烦来源 | 白名单 / 进服审核 | 视规模 |

**顺序很重要**：先把"记录与回溯"做好，再考虑反作弊。因为**没有记录，你连"是谁干的"都不知道**；而反作弊再强也有漏网的。

## 二、记录与回溯（防破坏）

这类插件的原理是**把方块、容器、实体、指令等操作全部记进数据库**，之后可以：

- 查某个方块**被谁在什么时候**破坏/放置过；
- 查某个玩家**最近都干了什么**；
- 按时间或按玩家**批量回滚**（把被破坏的区域恢复原状）；
- 查容器（箱子）的存取记录，判断是否偷窃。

推荐做法：

- **CoreProtect**：最主流的方块记录插件，配合它的查询指令与回滚指令使用。
- 也可以搭配 **InvSee** 类插件查看玩家背包（排查赃物）。
- **Prism** 一类是同类替代方案。

:::tip 记录插件要早装
它只能记录**装上之后**发生的事。等被破坏了才装，之前的事一概查不到。
:::

## 三、实时反作弊

主流方案是**服务端反作弊插件**，通过分析玩家发包行为判断异常（如超速移动、瞬移、攻击距离超限、自动瞄准等）。常见的有 Grim、Matrix、Vulcan、Spartan 一类。

选择与配置时注意：

- **先跑记录模式**：绝大多数反作弊支持"只记录不处罚"，**先观察一段时间**再开启处罚。
- **误判比漏判更伤玩家**：正常玩家被踢、被回弹、甚至被封，会直接流失并留下差评。**宁可漏一点，也不要大规模误伤**。
- **离线模式下反作弊意义有限**：换个 ID 就能重来，账号封禁的威慑力大打折扣。
- **客户端反作弊**：少数服务器要求玩家安装专用客户端做校验，防护更强但**门槛极高**，适合竞技向的封闭服务器。
- **插件冲突**：反作弊插件对协议的介入较深，和某些插件（尤其是修改移动/战斗逻辑的）容易冲突，**装完要观察日志**。

## 四、权限与内部管理

外部防住了，内部翻车同样致命：

- **不要随便给 OP**：原版 OP 权限极大。用权限插件（LuckPerms）按**权限节点**精细授权，比给 OP 安全得多。
- **管理操作要留痕**：谁执行了封禁、谁给了物品、谁改了世界，都应可查。
- **避免单人独裁**：管理权限集中在一个人手上，一旦此人出问题或跑路，服务器会很被动。
- **定期审查**：检查 OP 名单、权限组、白名单是否有不该在的人。

## 五、把门槛前置

比"事后处理"更省事的是**少让麻烦进来**：

- **白名单 / 进服审核**：小规模、高质量服务器常用；能挡掉绝大部分破坏与作弊。
- **规则明确**：写清楚禁止事项与处罚方式，处理时才站得住脚。
- **新玩家观察期**：新号限制部分权限（如暂时不能使用某些容器），降低一次性破坏的风险。

## 六、一个现实结论

**没有任何反作弊能 100% 拦住作弊**，也没有任何保护能 100% 防住破坏。所以真正可靠的是三件事的组合：

```
早装记录插件（能查、能回滚）
   + 谨慎配置反作弊（别误伤）
   + 定期异地备份（最坏情况能整体回档）
```

这三件里，**备份是最后一道防线**（见「备份与恢复」）。
