**备份是开服里唯一不能省的事。** 硬件会坏、服务商会跑路、玩家会破坏、插件会写坏存档——真出事了，别的都能重来，存档没了就是真的没了。

## 一、要备份什么

| 必要性 | 内容 |
| --- | --- |
| 必须 | `world/`、`world_nether/`、`world_the_end/`（**存档本体，最重要**） |
| 必须 | `plugins/`（插件本体与配置）、`mods/`（模组端） |
| 必须 | `server.properties`、`ops.json`、`whitelist.json`、`banned-*.json` |
| 必须 | 核心自己的配置（`bukkit.yml` / `spigot.yml` / `paper-*.yml` / 对应核心的 yml） |
| 可选 | `logs/`、`crash-reports/`（可选，排查问题有用） |
| 不必 | `libraries/`、`versions/`、`cache/`（可自动重建，不用备） |

## 二、最重要的原则：备份要"一致"

**不要在服务器正在写存档时直接复制**——可能拷到写了一半的区块文件，恢复后存档损坏。

正确姿势（两种）：

**方式 A：热备份（不停服）**

```
save-all        先把数据刷到磁盘
save-off        关闭自动保存（避免备份过程中继续写入）
（此时执行复制/打包）
save-on         备份完恢复自动保存
```

**方式 B：停服备份（最稳）**

```
stop            安全关服
（复制/打包整个目录）
（重新启动）
```

:::tip 定时备份脚本建议用方式 A
配合定时任务，在低峰期执行"`save-all` → `save-off` → 打包 → `save-on`"，玩家几乎无感。
:::

## 三、自动化

**Linux（cron）**：写一个备份脚本（打包 + 按日期命名 + 清理旧包），用 `crontab -e` 定时执行。

**Windows（任务计划程序）**：把启动脚本改造成"备份脚本"，在任务计划里设置每天固定时间运行。

**插件方案**：也有专门的备份插件，能按间隔自动备份并保留若干份历史，省去自己写脚本。**注意**：插件备份同样要保证一致性，且**备份文件别放在同一块盘上**。

## 四、保留策略

- **多留几个版本**：只留最新一份，遇到"存档已经坏了但还没发现"时就没救了。建议保留**若干天每日 + 若干周每周**。
- **注意磁盘**：世界文件会持续增长，**定期清理旧备份**，别把盘写满（盘满会导致服务端写存档失败，后果严重）。
- **异地一份**：本机磁盘坏了，本地备份也一起没了。

:::warn 服务商会跑路，机房会出事
把全部数据只放在一台你租来的机器上，是把命交给别人。**至少定期把备份下载到自己的电脑或另一处存储**。
:::

## 五、恢复（回档）流程

1. **停服**（务必先 `stop`）。
2. **把当前存档改名留底**（例如 `world_broken_20261004`），**不要直接删**——万一新备份也有问题还能回退。
3. 解压备份，把 `world*` 放回服务端目录。
4. 启动服务端，检查日志有无存档相关报错。
5. 让玩家确认关键建筑与物品是否正常。

## 六、最后一个提醒

> **没有验证过恢复的备份，不算备份。**

定期（比如每月一次）拿一份备份**在测试环境里真的恢复一遍**。很多人是在真出事那天才发现：备份脚本早就因为权限/路径问题失败了，或者打包出来的文件是空的。
