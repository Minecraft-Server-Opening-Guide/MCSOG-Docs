官方 **BDS** 是基岩版最稳的选择，但它**本身不支持插件**。这一篇讲清它的目录结构，以及怎么用社区加载器补上插件能力。

## 一、目录结构

BDS 解压后就是一套"绿色"目录，认识这几个就够：

| 文件 / 目录 | 作用 | 能不能动 |
| --- | --- | --- |
| `bedrock_server.exe` | **服务端启动程序**（Linux 下无 `.exe`） | 可以改名，但**不建议**——改名后启动脚本/面板里的启动路径都要同步改，容易出错 |
| `server.properties` | 服务器配置（端口、难度、模式等） | 常改 |
| `allowlist.json` | **白名单**名单（`server.properties` 里开白名单后在此管理） | 可改 |
| `permissions.json` | **管理员（OP）**数据（UUID、名称、权限） | 可改 |
| `valid_known_packs.json` | 已知附加包列表（行为包 / 资源包），服务器据此校验 |  一般不用动 |
| `worlds/` | **世界存档**（每个世界一个子文件夹） | 只整体备份 |
| `bedrock_server.pdb` | 调试用程序数据库文件 | 别动 |
| `bedrock_server_how_to.html` | 官方使用说明 |  可读 |
| `release-notes.txt` | 版本更新日志 |  可读 |

### 世界文件夹里有什么

`worlds/<世界名>/` 下：

| 文件 / 目录 | 内容 |
| --- | --- |
| `db/` | **存档数据**（世界的数据库文件，体积最大） |
| `level.dat` | 世界基本设置与属性（游戏规则、时间、天气等） |
| `level.dat_old` | 旧版存档设定（更新或备份时使用） |
| `level_name.txt` | 世界名称 |

:::warn 备份就备 `worlds/`
BDS 的存档全在 `worlds/` 里，**整个目录一起备份**。别只拷 `db/`，否则设置会丢。
:::

## 二、给 BDS 加插件：三个主流加载器

官方 BDS 没有插件系统，社区做了加载器来补。目前主流三个：

### LeviLamina（别名 LLL / LLv3）——**最推荐**

- 作者：LiteLDev（前身就是 **LiteLoaderBDS**）
- 定位：轻量、模块化、多功能的 BDS 插件加载器
- **推荐度：非常推荐** —— 插件生态最好，延续了 LiteLoader 时代的巅峰
- 支持版本：1.20.61 – 1.21.3（保持更新）

### EndStone —— 有潜力

- 作者：EndStoneMC
- 定位：提供**类似 Bukkit 的友好 API**，可用 **C++ 或 Python** 写插件
- **推荐度：比较推荐** —— 目前插件生态极少，但社区有参与开发的声音，后续可能追平 LeviLamina
- 支持版本：1.20.71 – 1.21.2（保持更新）

### BDSX —— 老牌稳定

- 定位：支持 **Node.js** 的 BDS 修改版，基于官方 BDS，保留原版全部特性，并支持 Hook 函数与网络数据包
- **推荐度：较为推荐** —— 国内插件不算多，但用户不少，作者从 2019 年维护至今
- 支持版本：1.12 – 最新（保持更新）

> 除这三个外，官方也提供**脚本加载器**（基于官方脚本 API），能力比第三方加载器弱，但胜在官方支持。

### 怎么选

| 你的情况 | 建议 |
| --- | --- |
| 想要现成插件、生态优先 | **LeviLamina** |
| 会 C++ / Python，想自己写 | **EndStone** |
| 熟悉 Node.js / 需要 Hook 底层 | **BDSX** |
| 只想用官方能力、不加第三方 | 官方脚本加载器 |

:::warn 加载器与游戏版本强绑定
加载器只支持**特定版本区间**。**先确认你的服务端版本在支持列表里**再装，否则会加载失败甚至起不来。升级游戏版本前也要先确认加载器是否已跟进。
:::

## 三、BDS 的两个已知坑

1. **单核瓶颈**：生物运算单线程 → 流畅度取决于**单核性能**，地图越大越卡。
2. **内存缓慢增长**：占用会慢慢涨。注意 **不要强行清理内存**——会导致玩家下载材质包/Addon 时进度条卡住，**只能重启服务端**解决。
