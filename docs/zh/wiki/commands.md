这一页把三类指令放在一起查：**Java 版服务端指令**、**基岩版（BDS 与第三方核心）指令**、以及**套在服务端外面的管理层**（MCDR、面板控制台、RCON）。

表里的「权限」一列写的是**原版默认**：Java 版按 OP 等级，基岩版按操作员身份与「作弊」开关。装了权限插件（如 LuckPerms）之后，实际权限由权限节点决定，可能比原版更宽也可能更严。

> 指令是否可用、权限等级是多少，**随游戏版本与核心类型变化**：同一个名字在不同核心上可能不存在，也可能被核心改写。下指令前请以你实际运行的服务端与游戏版本的官方文档为准。

:::note 三句话先记住
- **控制台里通常不用打 `/`**，游戏内聊天框里必须打 `/`。
- **控制台身份等于最高权限**，游戏内要看你有没有 OP 或对应权限节点。
- **Java 版与基岩版是两套指令集**：名字相同不代表行为相同，`save-all` 在基岩版根本没有对应物。
:::

## 1. 读表之前：三条规则

| 规则 | 说明 |
| --- | --- |
| 版本相关 | 指令会随版本增删（例如 `/tick` 一类新指令只存在于较新版本），老教程里的写法不一定还能用 |
| 核心相关 | `plugins`、`version`、`tps`、`restart` 这类指令**不是原版指令**，是 Spigot / Paper 系核心提供的；原版服务端没有 |
| 插件相关 | 装了权限插件后，原版权限节点可以被改写；装了命令别名插件后，指令名可能被替换 |

判断一条指令到底存不存在，最快的办法是**在游戏内输入 `/` 后看 Tab 补全列表**，或在控制台输入前几个字母看补全。补全里没有，就是这条核心没注册它。

## 2. Java 版：生命周期与存档

| 指令 | 作用 | 权限 | 备注 |
| --- | --- | --- | --- |
| `stop` | 安全关闭服务端：先保存再退出 | OP 4 / 控制台 | **关服只用它**，不要直接叉窗口或杀进程 |
| `save-all` | 立即保存全部世界数据 | OP 4 / 控制台 | 可加参数 `flush` 强制写入磁盘 |
| `save-off` | 关闭自动保存 | OP 4 / 控制台 | 备份前先关，避免备份到写了一半的存档 |
| `save-on` | 恢复自动保存 | OP 4 / 控制台 | 备份结束后记得开回来 |
| `reload` | 重载已启用数据包中的数据 | OP 2（版本间可能不同） | **不是重启，也不是重载服务端配置**，见下方警告 |
| `restart` | 重启服务端 | 视核心而定 | Spigot / Paper 系提供；原版没有这条指令 |

标准关服顺序是 `save-all` → `save-off` → 备份 → `stop`。进程已经退出时不需要再 `save-on`。

:::warn `/reload` 不是"全部重载"，还可能弄坏插件
Java 版的 `/reload` 只重载**当前已启用数据包里的数据**。它**不会**：

- 重新读取 `server.properties`（改端口、改难度这类配置必须重启才生效）；
- 重启服务端进程，也不会重载插件代码；
- 让插件的注册内容回到干净状态。

反过来，它**可能**让插件状态错乱：计分板、监听器、缓存、注册过的命令都可能残留成半新半旧的样子，症状是"重载完某些功能就怪了"。能用插件自己的 `/插件名 reload`、`/datapack enable`、`/datapack disable` 解决的，就别用原版 `/reload`；改动大或说不清影响时，直接挑维护窗口重启。

基岩版的同名指令范围更窄（重载行为包中的函数与脚本），两版的 `reload` 都**不是**"刷新服务端配置"的按钮。
:::

## 3. Java 版：玩家、封禁与白名单

| 指令 | 作用 | 权限 | 备注 |
| --- | --- | --- | --- |
| `list` | 列出当前在线玩家 | 所有人 | 最常用的"服里有人吗"指令 |
| `kick <玩家> [原因]` | 踢出玩家 | OP 3 / 控制台 | 被踢的人**还能重新进** |
| `ban <玩家> [原因]` | 封禁玩家 | OP 3 / 控制台 | 不解封就进不来 |
| `pardon <玩家>` | 解封玩家 | OP 3 / 控制台 | 很老的版本里这条叫 `unban` |
| `ban-ip <IP>` | 按 IP 封禁 | OP 3 / 控制台 | **该 IP 下所有人都进不来**，慎用 |
| `pardon-ip <IP>` | 解封 IP | OP 3 / 控制台 | 解封前先确认这个 IP 现在归谁 |
| `banlist [ips\|players]` | 查看封禁列表 | OP 3 / 控制台 | 不写参数时列出玩家 |
| `op <玩家>` | 授予管理员 | OP 3 / 控制台 | 只给需要的人；给 OP 比给权限节点粗放得多 |
| `deop <玩家>` | 撤销管理员 | OP 3 / 控制台 | 权限插件环境下 OP 仍可能绕过权限组 |
| `whitelist on` | 开启白名单 | OP 3 / 控制台 | 开启前先把自己加进去 |
| `whitelist add <玩家>` | 加入白名单 | OP 3 / 控制台 | 写入 `whitelist.json` |
| `whitelist remove <玩家>` | 移出白名单 | OP 3 / 控制台 | 生效后对方下次连接被拒 |
| `whitelist list` | 查看白名单 | OP 3 / 控制台 | 与 `whitelist.json` 内容一致 |
| `whitelist reload` | 从文件重新读取白名单 | OP 3 / 控制台 | **手工改过 `whitelist.json` 后必须执行它** |

白名单相关文件是 `whitelist.json`，封禁与 OP 名单分别在 `banned-players.json`、`banned-ips.json`、`ops.json`。用指令改会立即写文件；手工改文件则需要对应的 reload 或重启。

## 4. Java 版：世界、时间与游戏规则

| 指令 | 作用 | 权限 | 备注 |
| --- | --- | --- | --- |
| `tp <玩家> <目标>` | 传送玩家 | OP 2 / 控制台 | 完整写法是 `teleport`；控制台执行时两个参数都要写 |
| `gamemode <模式> [玩家]` | 切换游戏模式 | OP 2 / 控制台 | 取值 `survival` / `creative` / `adventure` / `spectator` |
| `gamerule <规则> <值>` | 修改游戏规则 | OP 2 / 控制台 | 规则名随版本增删，**用 Tab 补全确认** |
| `time set day` | 设置时间 | OP 2 / 控制台 | 也可用 `noon` / `night` / `midnight` 或具体数值 |
| `time add <数量>` | 推进时间 | OP 2 / 控制台 | 调试昼夜机制时比 `set` 好用 |
| `weather clear` | 设置天气 | OP 2 / 控制台 | 取值 `clear` / `rain` / `thunder`，可带持续时间 |
| `difficulty <难度>` | 设置难度 | OP 2 / 控制台 | 取值 `peaceful` / `easy` / `normal` / `hard` |
| `give <玩家> <物品> [数量]` | 给予物品 | OP 2 / 控制台 | 物品 ID 与组件语法随版本变化 |
| `seed` | 显示世界种子 | OP 2 / 控制台 | 与存档绑定，换世界后数值不同 |
| `say <内容>` | 以服务端身份广播 | OP 2 / 控制台 | 玩家看到的是服务器消息样式 |
| `tell <玩家> <内容>` | 私聊 | 所有人 | 别名 `msg` / `w` |
| `datapack list` | 列出数据包 | OP 2 / 控制台 | 与 `/reload` 搭配使用 |

`gamerule` 是最容易被误用的一条：**同名规则在 Java 版与基岩版可能含义不同，在不同版本之间也可能被改名或拆分**。改之前先在补全列表里确认规则存在，改完观察日志与玩家反馈。

## 5. Java 版：状态与排查

| 指令 | 作用 | 权限 | 备注 |
| --- | --- | --- | --- |
| `tps` | 查看 TPS | OP | **不是原版指令**：Spigot / Paper 系自带；装了 spark 时可能被 spark 接管 |
| `mspt` | 查看每刻耗时 | OP | Paper 系提供；与 TPS 一起看更有意义 |
| `spark tps` | 用 spark 查看 TPS | OP | spark 的命令树比核心自带指令更细 |
| `spark profiler start` | 开始性能采样 | OP | 结果默认会上传并给出链接，注意数据外泄风险 |
| `spark profiler stop` | 结束采样并查看结果 | OP | 只想停下不上传，用 `spark profiler cancel` |
| `plugins` | 列出插件 | OP / 权限节点 | 别名 `pl`；绿色为已加载，红色为加载失败 |
| `version <插件>` | 查看插件版本 | OP / 权限节点 | 报 bug 时对方一定会问这个 |
| `help` | 查看指令帮助 | 所有人 | 分页查看，`/help <指令>` 可看单条 |

原版服务端**没有** `tps`、`mspt`、`plugins`、`version` 这几条。原版想看性能只能靠日志与外部工具，这也是很多人"换了核心就有新指令"的原因。性能排查的完整流程见 [用 spark 分析服务器性能](/tutorials/ops/spark)。

:::tip 权限节点也能改指令可见性
`plugins`、`version`、`help` 的权限节点默认对所有人开放。想关掉，把 `bukkit.command.plugins`、`bukkit.command.version`、`bukkit.command.help` 设为 `false`。但**关掉指令不等于藏得住**：部分客户端能通过 Tab 补全的响应推断出已装插件。
:::

## 6. 基岩版：同一批指令在 BDS 上是什么样

基岩版（BDS 与第三方核心）有自己的一套指令。**可用性同时受两件事影响**：你是否有操作员身份，以及服务端是否开启了作弊。

| 指令 | 作用 | 权限 | 备注 |
| --- | --- | --- | --- |
| `stop` | 安全关闭服务端 | 控制台 | 与 Java 版同名同义，是最该记住的一条 |
| `save hold` | 暂停写入并保持文件一致 | 控制台 | 基岩版的备份第一步 |
| `save query` | 列出当前需要备份的文件 | 控制台 | 按它给出的清单复制 |
| `save resume` | 恢复写入 | 控制台 | 复制完成后执行 |
| `whitelist on` / `off` | 开关白名单 | 操作员 | 对应文件是 `allowlist.json` |
| `whitelist add` / `remove` / `list` / `reload` | 维护白名单 | 操作员 | 手工改文件后要 reload |
| `op` / `deop` | 授予 / 撤销管理员 | 操作员 | 结果写入 `permissions.json` |
| `permission list` | 查看当前权限 | 操作员 | 与 `permissions.json` 对应 |
| `permission reload` | 重新读取权限文件 | 操作员 | 手工改过 `permissions.json` 后执行 |
| `kick <玩家> [原因]` | 踢出玩家 | 操作员 | 与 Java 版含义相同 |
| `ban` / `pardon` | 封禁 / 解封玩家 | 操作员 | 按玩家（gamertag / XUID）封禁，**没有按 IP 封禁的等价指令** |
| `tp` / `teleport` | 传送 | 操作员 | 语法与 Java 版接近但不完全相同 |
| `gamemode` | 切换游戏模式 | 操作员 | 取值与 Java 版类似 |
| `gamerule` | 修改游戏规则 | 操作员 | 规则集合与 Java 版**不同**，同名规则含义也可能不同 |
| `time set` / `time add` | 设置 / 推进时间 | 操作员 | 基岩版也可用 `daylock` 一类指令锁时间 |
| `weather clear` / `rain` / `thunder` | 设置天气 | 操作员 | 另有 `toggledownfall` |
| `difficulty` | 设置难度 | 操作员 | 与 Java 版同名 |
| `list` | 列出在线玩家 | 操作员 | 部分版本对普通玩家开放，以补全为准 |

表中有一部分指令是**较新版本才加入的**（`ban` / `pardon` 这类尤其明显），在较旧的基岩版服务端上，补全列表里可能根本没有它们。**判断某条指令在你的版本上存不存在，唯一可靠的办法是看 Tab 补全与官方文档**，不要照抄别处的版本号。

BDS 的配置里有一项与指令直接相关：`server.properties` 中的 `allow-cheats`。它关闭时，游戏内的指令会受到限制；默认值以你本地生成的 `server.properties` 为准，改完必须重启服务端才生效。**基岩版的很多"指令用不了"，根因是作弊开关或操作员身份，不是指令写错了。**

基岩版的备份流程与 Java 版完全不同，可以直接照抄：

```text
save hold
save query
# 按 query 输出的清单复制文件（worlds/ 要整体拷走）
save resume
```

## 7. 基岩版没有（或语义不同）的指令

| Java 版指令 | 基岩版情况 | 说明 |
| --- | --- | --- |
| `save-all` | 不存在 | 用 `save hold` / `save query` / `save resume` |
| `save-off` / `save-on` | 不存在 | 基岩版没有"关闭自动保存"这一对开关 |
| `ban-ip` / `pardon-ip` | 不存在 | 基岩版按玩家封禁，没有按 IP 封禁的指令 |
| `plugins` / `version <插件>` | 不存在 | 基岩版核心没有统一的插件列表指令，看控制台输出 |
| `tps` / `mspt` | 不存在 | 基岩版没有 TPS 指令；性能只能从日志与外部观测判断 |
| `reload` | 存在但**语义不同** | 基岩版重载的是行为包里的函数与脚本，**不重载 `server.properties`**，也不是重启 |
| `gamerule` | 存在但**规则集不同** | 同名规则在两版可能含义不同，跨版本照抄会踩坑 |
| `difficulty` / `time` / `weather` | 存在 | 这几条两版都有，语法接近 |

:::warn "基岩版没有 /reload" 这个说法要拆开看
社区里常说的"基岩版没有 `/reload`"，指的其实是**没有能重载服务端配置的 reload**——这一点是对的：基岩版改了 `server.properties` 只能重启服务端（用控制台正常 `stop` 再启动，别杀进程）。

但基岩版确实有一条名为 `reload` 的指令，它的作用范围是行为包中的函数与脚本，**和 Java 版重载数据包不是同一件事**，也不会让服务端重新读取配置文件。两版都别把 `reload` 当"万能刷新键"用；具体可用范围与行为随版本变化，以官方文档为准。
:::

## 8. 管理层：MCDR 的 `!!MCDR` 子命令

MCDReforged（MCDR）是**包在服务端外面**的管理器：它托管核心进程、解析控制台输出，并提供一套 `!!` 前缀的指令。这套指令**不是游戏指令**，由 MCDR 自己处理，不会传给服务端。

| 指令 | 作用 | 权限 | 备注 |
| --- | --- | --- | --- |
| `!!MCDR` | 主命令，列出可用子命令 | 由 MCDR 权限系统控制 | 前缀 `!!` 可在配置里改 |
| `!!MCDR status` | 查看 MCDR 状态 | MCDR 权限 | 排查"管理器还活着吗" |
| `!!MCDR reload config` | 重载 MCDR 配置 | MCDR 权限 | 有缩写形式，如 `!!MCDR r cfg` |
| `!!MCDR reload plugin` | 重载插件 | MCDR 权限 | 与重载配置分开 |
| `!!MCDR reload permission` | 重载权限数据 | MCDR 权限 | 改完权限文件后用 |
| `!!MCDR reload all` | 重载全部 | MCDR 权限 | 出问题时优先用它 |
| `!!MCDR plugin list` | 列出已加载插件 | MCDR 权限 | 与 Java 版 `/plugins` 是两回事 |
| `!!MCDR plugin load <插件>` | 加载插件 | MCDR 权限 | 参数是插件 id |
| `!!MCDR plugin reload <插件>` | 重载单个插件 | MCDR 权限 | 比整体重启轻 |
| `!!MCDR plugin unload <插件>` | 卸载插件 | MCDR 权限 | 卸载不等于删除文件 |
| `!!MCDR plugin install <插件>` | 从官方仓库安装插件 | MCDR 权限 | 示例：`!!MCDR plugin install ndpr` |
| `!!MCDR permission list` | 查看权限 | MCDR 权限 | 按玩家与权限组查看 |
| `!!MCDR permission set` | 设置权限 | MCDR 权限 | 语法以官方文档为准 |
| `!!MCDR permission remove` | 移除权限 | MCDR 权限 | |
| `!!MCDR checkupdate` | 检查 MCDR 更新 | MCDR 权限 | 是否自动检查由配置项决定 |

:::warn MCDR 子命令随版本变化
MCDR 的子命令与缩写形式在版本之间会调整（`!!MCDR reload config` 这类缩写尤其容易记错），**具体写法以 MCDR 官方文档与你机器上 `!!MCDR` 输出的帮助为准**。另外，MCDR 的权限是它自己的一套，和游戏内 OP 等级无关；玩家在聊天框里能执行哪些 `!!` 指令，取决于 MCDR 的权限配置。
:::

## 9. 管理层：面板控制台与 RCON

面板（如 MCSManager、Pterodactyl）的网页控制台本质上是一个**远程标准输入**：你敲的内容会被原样送进服务端进程，和你坐在机器前敲控制台没有区别。

| 渠道 | 要不要打 `/` | 权限 | 备注 |
| --- | --- | --- | --- |
| 本机控制台 | 通常不需要 | 最高权限 | 原版控制台不受 OP 等级限制 |
| 面板网页控制台 | 多数面板两种都能接受 | 最高权限 | 有的面板会自动去掉前导 `/`，以面板行为为准 |
| RCON | 通常不需要 | 最高权限 | 需在 `server.properties` 里开启并设置口令 |
| 游戏内聊天框 | 必须打 `/` | 按 OP 等级或权限节点 | 受白名单、封禁、权限插件影响 |

三条实践建议：

1. **停服永远用 `stop`（基岩版同样）**，不要在面板上点"终止进程"。强行终止可能丢数据或损坏存档。
2. **RCON 不要暴露到公网**。它是一条免登录的"执行任意指令"通道，只监听回环或内网地址，口令要长且唯一。
3. **面板控制台里执行的指令等同于最高权限**，给协管面板账号之前先想清楚这一点。

## 10. 控制台 vs 游戏内：差异清单

| 差异 | 控制台 / RCON | 游戏内聊天框 |
| --- | --- | --- |
| 前导斜杠 | 通常不用写 | 必须写 |
| 权限来源 | 进程身份，等于最高权限 | OP 等级或权限节点 |
| 执行者上下文 | **没有执行者**：`@s`、相对坐标、不指定目标的 `tp` 都不能用 | 有执行者，可用选择器与相对坐标 |
| 输出去向 | 终端与日志文件 | 聊天框与动作栏 |
| Tab 补全 | 通常有；部分面板没有 | 有 |
| 字符编码 | Windows 控制台代码页不对时中文会乱码 | 一般正常 |
| 玩家可见性 | 玩家看不到你敲了什么 | 部分指令会对玩家广播 |

最典型的坑是"控制台里执行 `/tp ~ ~10 ~`"——控制台没有位置，这条一定失败。控制台执行传送类指令时，**玩家与目标都要显式写出来**。

## 11. 权限从哪来

| 体系 | 适用 | 怎么控制 |
| --- | --- | --- |
| OP 等级 | Java 版原版 | `/op` 给到 4 级；等级 1 到 4 对应不同指令组，可用权限节点细化 |
| 权限节点 | Java 版插件服 | 权限插件（如 LuckPerms）按节点与权限组分配，比给 OP 安全 |
| 操作员 + 作弊开关 | 基岩版 | `permissions.json` 决定谁是操作员；`server.properties` 的 `allow-cheats` 决定指令可用性 |
| MCDR 权限 | 装了 MCDR 的服 | MCDR 自己的权限系统，按玩家与权限组控制 `!!` 指令 |

**给权限的原则**：能只给一条指令的权限，就不要给整个 OP；能给限时权限，就不要给永久权限。OP 是"整台服务器"级别的信任，权限节点才是最小授权。

## 12. 可以直接抄的组合

维护前的标准流程（Java 版）：

```text
say 服务器将在 5 分钟后进入维护
save-all
save-off
# 此时在外部打包世界目录与插件目录
stop
```

白名单从零到可用（Java 版）：

```text
whitelist add 你的ID
whitelist on
whitelist list
```

基岩版备份与恢复：

```text
save hold
save query
# 复制 query 列出的文件，worlds/ 整体拷走
save resume
```

排查"玩家进不来"时最先敲的几条：

```text
list
whitelist list
banlist players
plugins
```

## 13. 常见误用

| 误用 | 后果 | 正确做法 |
| --- | --- | --- |
| 直接关窗口或点"终止进程" | 存档可能损坏或回滚 | 控制台执行 `stop` |
| 用 `/reload` 当重启 | 插件状态错乱、配置不生效 | 用插件自己的 reload；必要时重启 |
| 备份前不 `save-off` | 备份到写入一半的存档 | 先 `save-all` 再 `save-off` |
| 在控制台用 `~` 相对坐标 | 指令直接失败 | 显式写出玩家与坐标 |
| 把 RCON 端口开到公网 | 等于把服务器交给扫描器 | 只监听回环或内网，配强口令 |
| 改完 `whitelist.json` 不 reload | 改动不生效 | 执行 `whitelist reload` |
| 用基岩版的 `gamerule` 名去 Java 版 | 规则不存在或含义不同 | 用 Tab 补全确认规则名 |
| 以为基岩版有 `save-all` | 指令不存在 | 用 `save hold` / `save query` / `save resume` |
